# Monster Tamer — 캐릭터 스프라이트 제작 가이드

게임은 **스프라이트가 없으면 절차적으로 캐릭터를 그리고**, 파일이 있으면 그 파일을 우선 사용한다.
즉 아래 규칙대로 파일만 떨궈두면 코드 수정 없이 교체된다.

## 1. 현재 렌더링 방식 (배경)

| 계층 | 방식 |
|---|---|
| 이전(v5) | `DEX[id].emoji` 이모지 1글자를 `fillText` — 얼굴만 크게 보이는 한계 |
| 현재(v6) | `drawCreature()` 절차 생성 — 타입 팔레트 + 체형(round/tall/serpent/quad/wing/blob) + 부위(뿔·귀·날개·꼬리·지느러미)를 종족 ID 해시로 결정 |
| 오버라이드 | `sprites/{speciesId}.png` 존재 시 그 이미지로 대체 (없으면 절차 생성 유지) |

`speciesId` 는 `m{계열번호}_{단계}` 형식이다 (예: `m0_0` = 0번 계열 1단계, `m0_2` = 최종 진화형).
계열/단계와 종족명 대응은 게임 내 **📖 도감 탭**에서 확인할 수 있고, 콘솔에서 아래로 전체 목록을 덤프할 수 있다.

```js
// 브라우저 콘솔에서 실행 — id, 이름, 타입, 단계, 종족값 목록
Object.entries(DEX).map(([id, d]) => `${id}\t${d.name}\t${d.type}\t${d.stage}\t${d.hp+d.atk+d.def+d.spc+d.spd}`).join('\n')
```

## 2. 만들어야 하는 파일

```
portal-fe/public/games/monster-tamer/
├── sprites/
│   ├── m0_0.png      # 필수 아님 — 있으면 절차 생성 대체
│   ├── m0_1.png
│   ├── m0_2.png
│   ├── ...           # 총 102종 (34계열 × 3단계)
│   └── shiny/        # 선택 — 이로치 전용. 없으면 본 스프라이트에 색조 필터
│       └── m0_0.png
└── sprites/manifest.json   # 선택 — 파일이 있는 종만 명시하면 404 요청이 사라짐
```

### manifest.json (권장)

없으면 게임이 모든 종에 대해 PNG 로드를 시도하고 실패 시 절차 생성으로 폴백한다(동작엔 문제없지만 404 로그가 남는다).

```json
{ "sprites": ["m0_0", "m0_1", "m0_2"], "shiny": ["m0_0"] }
```

## 3. 이미지 규격

| 항목 | 값 |
|---|---|
| 크기 | **96 × 96 px** (배틀에서 2배 확대, 메뉴에서 축소) |
| 포맷 | PNG, 알파 투명 배경 |
| 여백 | 캐릭터가 캔버스의 80% 이내, 하단 기준선에 발이 닿게 |
| 방향 | **정면~3/4 측면**, 화면 오른쪽을 바라보게 통일 (적은 자동 반전) |
| 스타일 | 픽셀아트 권장(도트 크기 2px 단위). 외곽선 1~2px 어두운 톤 |

## 4. 캐릭터별 특성 (디자인 입력값)

각 종의 아래 값이 이미 결정되어 있으니 그림도 여기에 맞추면 게임과 일관된다.

| 속성 | 의미 | 디자인 반영 예 |
|---|---|---|
| `type` | 15타입 중 하나 | 주 색상 — 불꽃=주황/적, 물=청, 풀=녹, 전기=황, 얼음=하늘, 격투=적갈, 독=자주, 땅=황토, 비행=연보라, 에스퍼=분홍, 벌레=연두, 바위=회갈, 고스트=남보라, 드래곤=보라, 노말=회베이지 |
| `stage` | 0 기본 / 1 중간 / 2 최종 | 단계가 오를수록 **덩치·장식(뿔/날개/갈기) 증가**, 눈매 날카롭게 |
| `hp/atk/def/spc/spd` | 종족값 배분 | ATK↑ 발톱·엄니, DEF↑ 갑각·등껍질, SPD↑ 날렵한 실루엣·유선형, SPC↑ 보석·오라 장식 |
| `flying` | 비행 여부 | 날개 필수 (비전서 하늘날기 습득 가능 종) |
| `family` | 같은 계열 3종 | **실루엣 계승** — 같은 계열은 색·특징을 유지한 채 성장한 형태 |

### 계열 단위로 작업하는 것을 권장

`m7_0 → m7_1 → m7_2` 세 장을 한 세트로 그리면 진화 연출이 자연스럽다.

## 5. 절차 생성 결과를 참고 이미지로 뽑기

콘솔에서 아래를 실행하면 현재 절차 스프라이트를 PNG data URL 로 얻을 수 있다 — 이걸 밑그림으로 삼으면 색/실루엣 톤을 맞추기 쉽다.

```js
spriteDataUrl('m0_0', false)   // 콘솔에 뜬 data:image/png;base64,... 를 새 탭에서 열기
```

## 6. 적용 확인

파일을 넣고 portal-fe 를 재배포하면 즉시 반영된다.

```bash
scripts/image-import.sh --image commerce/portal-fe:latest
kubectl -n commerce rollout restart deployment portal-fe
```
