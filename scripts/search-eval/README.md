# 관광지 검색 품질 평가 — 판정 세트와 3구성 nDCG@10

`hybrid-search-local-embedding`(ADR-0090) 의 품질 근거다. 이 폴더는 **측정 기록**이고, 스크립트와 판정 세트는
CronJob 이 ConfigMap 으로 싣도록 `k8s/base/search-batch/eval/` 에 있다.

| `k8s/base/search-batch/eval/judgments-attractions-2026-09-13.json` | 이전 세트 — 쿼리 48개(ko 24 · en 24), 2,141건. 풀링은 세 구성의 top-10 합집합 |
| `k8s/base/search-batch/eval/live-eval.py` | A. BM25 · B. 하이브리드(RRF) · C. 하이브리드 + 쿼리 언더스탠딩(라이브 API) 의 nDCG@10 + 회귀 판정 |
| `k8s/base/search-batch/cronjob-eval.yaml` | 매일 KST 07:30(재색인 뒤) 실행. C 가 기준선 − 0.03 아래면 Job Failed |
| `results/<날짜>.json` | 남길 값이 있던 실행의 결과 |

## 돌리는 법

```bash
ssh msa-oci 'sudo kubectl -n commerce create job --from=cronjob/search-eval search-eval-manual'
ssh msa-oci 'sudo kubectl -n commerce logs job/search-eval-manual'     # 표와 판정 줄
```

기준선은 CronJob env(`EVAL_BASELINE_KO/EN`)다. 의도해서 순위를 바꾼 변경 뒤에는 새 값을 재고 env 를 같이 고친다.

`조용 · 한 · 하 · ᆫ` 이 되어 「한미옥」·「정온한」이 「조용한 사찰」 1위로 올라왔고(A .269→0), 「해운대해수욕장」의
분해가 「해수욕장」과 달라져 A .599→.069. 동의어 규칙도 `mixed` 로는 같은 자리 토큰 때문에 해석이 실패한다.
**`캠핑장` · `글램핑장` 은 통째 한 토큰으로** 둔다 — `캠핑 장` 으로 쪼개 넣으면 `discard` 에서 흔한 `장` 만 남아 A .280→.117.
스팟체크 20건은 정밀도가 뚜렷이 올랐다 — 「올리브영」이 영금정·영광정을, 「마라도」가 말도를, 「대부도」가 모현동 부도를 더 이상 내지 않는다.

## 함정

- **판정 세트는 그것을 만든 시스템에만 공정하다.** 새 구성(예: 1-bit 양자화)이 top-10 에 새 문서를 올리면 그 문서는
  등급이 없어 0 으로 계산된다. 큰 변경 뒤엔 풀링을 다시 하고 등급을 더한 뒤 비교한다.
- 매일 도는 `search-eval-daily` CronJob 은 이 세트를 쓰지 않는다 — ADR-0050 의 상품 검색 기준선 잡이고
  `analytics.search_judgments` 가 비어 매일 건너뛴다(2026-09-21 확인). 관광지 평가는 이 폴더의 스크립트다.
- **NO_ANSWER 는 `intent` 로 nDCG 평균·클릭 계수 짝 비교에서 뺀다** — `ndcg()` 의 `None` 에 맡기면 국내 대체지가
  등급 1 을 받은 질의가 숫자를 내서 평균에 섞인다. 정답 없는 질의는 빈 정답 통과율(`totalElements == 0` 비율)로 본다.
- **`seed:` NATURAL 문구는 질의 벡터 사전에 미리 들어 있어 점수가 후하다** — NATURAL 은 `seed:` 와 나머지를 따로 본다.
- **등급만 바뀌어도 새 날짜 파일을 만든다** — 같은 파일 이름으로 등급을 고치면 기준선이 무엇으로 잰 값인지 잃는다.
  세트 파일·CronJob 명령의 파일 이름·`EVAL_BASELINE_KO/EN` 은 한 커밋에 넣는다.
- C(라이브)−B(색인 직접) 델타를 전부 쿼리 언더스탠딩 탓으로 읽지 않는다 — 앱 질의 모양·인덱스 드리프트가 섞인다.
