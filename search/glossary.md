## 1. Bounded Context Overview

Search BC는 **OpenSearch 기반 읽기 전용 검색 모델 서비스**. CDC + Kafka 로 product BC 변경을 비동기 인덱싱. 상품 검색 결과는 OpenSearch `_score` + Bandit posterior 의 reranking 으로 최종 랭킹. 관광지 검색은 키워드 레그와 벡터 레그를 RRF 로 합치는 하이브리드다(3-2절, ADR-0090). multi-armed bandit (Thompson sampling) 으로 노출·클릭 피드백 기반 적응 학습. 무중단 리인덱스는 alias swap.

## 2. Aggregates & Entities

### ProductDocument
**Type.** Aggregate (data class — 검색 인덱스의 비정규화 표현)
**Definition.** Product 의 검색 인덱스 표현. product BC 의 권위 모델을 CDC/Kafka 로 동기화한 **읽기 모델**. OpenSearch 문서 단위로 인덱스됨.
**Lifecycle.** `product.item.created` 수신 시 생성 → `product.item.updated` 수신 시 갱신 → `analytics.score.updated` 수신 시 score 필드 갱신
**Invariants.**
- OpenSearch 측 권위 (이중 권위 아님 — product BC가 카탈로그 SSOT)
- `popularityScore / ctr / cvr / scoreUpdatedAt` 는 analytics BC 에서 주입된 외부 score 필드
- `categoryId` 는 nullable — 미분류 상품 허용
- `status: String` (enum 아님) — product BC의 ProductStatus 와 다른 표현 (Flagged: enum 동기화 검토)
**Avoid.** Product (product BC의 권위 모델과 혼동 금지), ProductIndex (port 이름과 충돌)
**Code.** `com.kgd.search.domain.product.model.ProductDocument`

### BanditState
**Type.** Aggregate (data class)
**Definition.** 특정 BanditKey 의 현재 학습 상태. 누적 노출·클릭 수와 마지막 갱신 시각.
**Lifecycle.** `empty(key)` 또는 신규 ImpressionEvent 수신 시 생성 → 노출/클릭 누적 → time decay 가능
**Invariants.**
- `clicks >= 0` — 음수 클릭 금지
- **`impressions >= clicks`** — 클릭이 노출보다 많을 수 없음 (논리적 invariant)
- `ageDays(now)` — lastUpdatedAt 기준 경과일 (time decay 가중치 산정에 활용)
**Code.** `com.kgd.search.domain.bandit.model.BanditState`

## 3. Value Objects

### ScoredProductDocument
**Type.** Value Object (data class)
**Definition.** ProductDocument + OpenSearch `_score`(`esScore`). reranker 입력.
**Code.** `com.kgd.search.domain.product.model.ScoredProductDocument`

### BanditKey
**Type.** Value Object (data class)
**Definition.** Bandit 학습 단위 식별자 — `(categoryId, productId)` 결합.
**Invariants.**
- `categoryId.isNotBlank() ?: DEFAULT_CATEGORY` ("_default_") — 빈 카테고리는 기본값으로 폴백
- `redisField()` → "categoryId:productId" 문자열 (Redis key 표현)
**Code.** `com.kgd.search.domain.bandit.model.BanditKey`

### BanditPosterior
**Type.** Value Object (data class — Beta 분포 파라미터)
**Definition.** 베이지안 사후 분포. Beta(α, β) — α=클릭, β=노출-클릭 (사전분포 + 관측 누적).
**Invariants.**
- `alpha > 0.0`, `beta > 0.0` — Beta 분포 파라미터 양수 강제
- `mean() = alpha / (alpha + beta)` — 분포 평균
**Code.** `com.kgd.search.domain.bandit.model.BanditPosterior`

### ImpressionEvent / ClickEvent
**Type.** Value Object (data class)
**Definition.** 검색 결과 노출·클릭 단일 이벤트.
**Payload.** `searchId + key + position + userId?(nullable) + occurredAt`
**Code.** `com.kgd.search.domain.bandit.model.{ImpressionEvent, ClickEvent}`

## 3-1. 관광지 문서 용어 (ADR-0103, 2026-09-30 · 행사·숙박·여행코스 ADR-0104, 2026-10-02)

| 용어 | 정의 | 피할 말 · 비고 |
|---|---|---|
| **속성 패싯** | 관광지 문서에 재색인 때 계산해 싣는 파생 속성(휴무·주차·반려동물·신용카드·유모차 대여·무료 입장)과, 그것으로 거르는 목록 필터·건수. 값은 긍정·부정·`UNKNOWN` 이고 `UNKNOWN` 을 부정으로 바꾸지 않는다. 건수는 `facets=true` 일 때만 센다. 목록에서 「행사」를 고르면 화면이 칩·속성 조건·건수 요청을 모두 뺀다(관광지 축이라 행사에는 전부 0) | 「태그」와 다르다 — 원천에 없는 추출값이다. 코드: `search:domain` 속성 파서 |
| **`petPolicy`** | 반려동물 동반 정책 — `ALLOWED`(전 구역) · `PARTIAL`(일부 구역) · `UNKNOWN`. place `petAcmpyType` 원문을 대응 표로 정규화한다. 운영 원문에 「불가」가 없어 부정 값이 없다 | 영문 문서는 원천이 없어 늘 `UNKNOWN` |
| **`uniqueClickers14d`** | 최근 14일 관광지 상세를 클릭한 고유 이용자 수(`anonymous` 제외, KST 날짜). analytics `attraction_popularity_daily.unique_clickers` 를 `uniqMerge` 로 합친 값 | 원시 클릭 수 아님. `visitor_id` 가 클라이언트 값이라 조작을 막지 못한다 |
| **`clickBoost`** | `uniqueClickers14d` 로 만든 순위 계수(상한·최소 표본). 검색어 있는 키워드 레그 점수에만 곱한다. 스위치 `search.attraction.click-boost.enabled` 기본 꺼짐 | `popularityScore`(정보 충실도)와 다른 값이다 |
| **서버 렌더(관광지)** | place 호스트의 관광지 상세 요청을 search:app 이 받아 portal-fe 셸에 메타·JSON-LD·본문을 넣어 내는 것. 표지 `X-Render: ssr`(폴백은 `shell-fallback`·`proxy-fallback`) | 「프리렌더」 아님 — 빌드 때 찍는 파일은 지역 페이지뿐이다 |
| **비슷한 곳** | 관광지마다 오프라인 도구(`tools/embed`)가 임베딩으로 고른 유사 관광지 목록. place `attraction_similar` 에 적재하고 재색인이 문서에 싣는다 | 「주변 명소」(반경 검색)와 다르다 — 거리와 무관하다 |
| **주변 명소** | 관광지 상세에서 화면이 검색 API 반경 검색으로 그리는 가까운 관광지 절(6곳, 자기 자신과 「같은 분류 가까운 곳」 제외). 서버 렌더 본문에는 없다 | 「근처 관광지」「주변 관광지」로 쓰지 않는다 — 사전·코드(`nearby`) 표기가 「주변 명소」다. 「근처 행사」「근처 숙소」는 따로 있는 절이다 |
| **유효 시작일 · 유효 종료일** | 행사 원천 시작일 S · 종료일 E 를 정규화한 기간. S≤E → (S,E) · S 만 → (S,S) · E 만 → (E,E) · S>E 나 둘 다 없음 → 날짜 없음. 재색인이 `EventSchedule` 로 계산해 `eventStartEffective`·`eventEndEffective`(`date`)로 싣고, 범위 질의는 이 둘만 본다 | 원천 날짜 아님 — 원천 값은 place 컬럼에 그대로 남는다. 코드: `search:domain` `EventSchedule` (ADR-0104) |
| **행사 상태** | 유효 기간과 KST 오늘로 판정하는 넷: `ONGOING`(시작일 ≤ 오늘 ≤ 종료일, 당일 포함) · `UPCOMING`(시작일 > 오늘) · `ENDED`(종료일 < 오늘) · `UNKNOWN`(날짜 없음). 저장하지 않고 조회·렌더 시점에 계산한다. 오늘은 호출자가 `Clock` 으로 넘긴다 | 「진행 상태 컬럼」은 없다. `UNKNOWN` 은 모든 행사 필터·근처 행사·행사 sitemap 에서 빠진다. 화면 문구: 「진행 중」「D-n 시작」「종료된 행사」 / 「Ongoing」「Starts in n days」「Ended」 |
| **`eventStatus`** | 검색 API 의 행사 필터 값 다섯: `ONGOING` · `WEEKEND` · `UPCOMING` · `THIS_MONTH` · `NOT_ENDED`(진행 중 ∪ 예정). 조건은 「행사가 아니거나 범위 안」이라 행사 아닌 문서는 영향받지 않는다. 그 밖의 값은 무시한다 | 상태(넷)와 필터(다섯)는 다르다 — `WEEKEND`·`THIS_MONTH`·`NOT_ENDED` 는 상태가 아니라 범위다 |
| **이번 주말** | `eventStatus=WEEKEND`. 기간이 [max(오늘, 이번 주 토), 이번 주 일]과 겹치는 행사. 주는 월~일이고 오늘을 포함한다 — 일요일이면 그날 하루, 월~금이면 토·일 둘 | 「다가오는 주말」 아님 — 일요일에 다음 주말로 넘어가지 않는다 |
| **이번 달** | `eventStatus=THIS_MONTH`. 기간이 [오늘, KST 이번 달 말일]과 겹치는 행사. 지역 허브 「이번 달 행사」(최대 8건, `sort=eventStart`)가 쓴다 | 달의 1일부터가 아니다 — 이미 끝난 행사는 들지 않는다 |
| **만료 noindex** | 행사 페이지는 종료 뒤에도 200 + 「종료된 행사」로 남고, 유효 종료일 + 31일 ≤ 오늘(KST)부터 `noindex, follow` 다. robots 판정 전체는 「개요 없음 OR 만료」. 정본은 서버 렌더, `useSeo` 가 같은 판정을 따른다 | 404·410 아님. 행사 sitemap 은 「종료 + 30일 ≥ 오늘」까지만 싣는다 — 두 경계가 같은 날을 가른다 |
| **코스 구성** | 여행코스(유형 25)를 이루는 지점 목록. 재색인이 place `infoRaw`(`detailInfo2`)를 순수 함수로 풀어 순서 · 원천 contentId · 이름 · 같은 언어 관광지 id 를 색인하지 않는 객체 `courseStops` 로 싣는다. 순서는 `subnum` 수 값 오름차순 | 매칭 안 된 지점은 이름만 있고 링크가 없다. 국문 전용 — 영문 서비스에 코스 유형이 없다 |
| **근처 행사** | 관광지 상세 절. 반경 20km · `NOT_ENDED` · `sort=eventStart` · 최대 6건, 거리·기간 표시. 화면이 검색 API 로 그리고 0건이면 절이 없다. 노출 기록 섹션 `NEARBY_EVENTS` | 서버 렌더 본문에 없다(관광지당 조회 한 번 규칙) |
| **근처 숙소** | 관광지 상세 절. `category=stay`(레포츠 캠핑장 포함) · 반경 5km · 거리순 · 최대 6건. 기존 「주변 편의시설」의 숙박 몫을 옮긴 것이라 편의시설 절에는 숙박이 없다. 노출 기록 섹션 `NEARBY_STAYS` | 「숙박 유형(32·80)」과 범위가 다르다 — 원문 키 절·딥링크 제외만 유형 기준이다 |
| **`festival` · `course`** | 파생 분류 `category` 의 새 값. 유형 코드가 먼저 정한다: 행사(국 15 · 영 85) → `festival`, 여행코스(국 25) → `course`, 숙박(32 · 80) → `stay`. `SIGHT_CATEGORIES`(관광 분류)에 들지 않아 지역 드릴다운 건수에 섞이지 않는다 | 행사의 신분류 `EV` 를 `culture` 로 접던 규칙은 유형 코드가 앞서 막는다. 화면 칩: 「행사」, 국문 전용 「여행코스」 |
| **방문 요약** | 상세 첫 화면의 일곱 칸 — 요금·이용시간·쉬는 날·주차·반려동물·무장애·확인 상태(영문 Admission·Hours·Closed·Parking·Pets·Accessibility·Data status). 행사·숙박·코스가 아닌 유형에만 붙고, 겹치는 이용 안내 행·배지를 대신한다. 값이 없으면 「정보 없음」/「Not provided」. FE `placeAttributes.ts` `visitSummary(attraction, lang)` 가 만들고 서버 렌더는 `<dl data-place-section="visit-summary">` 로 같은 칸·문구를 낸다(`VisitSummaryParityTest` 가 골든 대조) | 「방문 정보 요약」/「At a glance」는 행사·숙박·코스의 배지 절 제목이고(FE 탭 이름은 「방문 정보」) 방문 요약과 다르다 |
| **확인 상태** | 방문 요약의 마지막 칸. 「출처: {표시명} · 원천 갱신일: YYYY-MM-DD · 수집일: 정보 없음」(영문 「Source: … · Source updated: … · Collected: Not provided」). 출처는 색인 `source`, 갱신일은 원천 수정일(`modifiedAt`)의 날짜. 값이 없어도 칸은 늘 낸다 | 바닥 출처 줄(출처표시 의무 문구)과 별개다 — 그 줄은 그대로 남는다. 수집일은 아직 값이 없어 늘 「정보 없음」 |
| **배지 줄** | 방문 요약에 칸이 없는 배지 — 신용카드(가능/불가)·유모차 대여(있음/없음)·「많이 클릭한 곳」 — 를 「 · 」로 이은 한 줄. `UNKNOWN` 은 넣지 않고, 항목이 없으면 내지 않는다. 서버 렌더는 방문 요약 바로 뒤 `<p data-place-section="visit-badges">` | 정기휴무·주차·반려동물은 해당 칸 첫 줄로 갔고, 입장 무료/유료는 요금 칸과 같은 정보라 배지로 내지 않는다. 행사·숙박·코스의 배지 절과 다르다 |
| **행동 줄** | 제목 아래(전화 줄 다음), 방문 요약 앞 줄. FE 는 길찾기(구글맵 링크)와 문의 전화, 서버 렌더는 전화만(`<p data-place-section="actions">`). 전화는 `infoCenter` 원문, 비면 `tel` — 원문을 글로 보이고 첫 번호만 `tel:` 링크(`attractionPhone`). `tel` 을 쓸 때는 제목 아래 전화 줄을 빼 한 번만 낸다 | 모든 유형에 붙는다(행사·숙박·코스 포함 — 방문 요약과 다른 점). 서버 렌더에 지도 URL 규칙 사본을 두지 않는다 |
| **`feeText`** | 요금 평문 — 파생 색인 필드(`text`, `index: false`). 규칙 원본은 search:domain `AttractionFee.text(useFee, info)` 하나다: place `use_fee` 가 우선이고, 비면 반복정보(`infoRaw`)의 입장료·관람료·이용요금 행. 재색인이 한 번 계산하고 방문 요약 요금 칸·서버 렌더·입장 무료 판정(`attrAdmission`)이 모두 이 값만 읽는다 | 이미 `sourceText` 를 거친 평문이다 — 다시 거치면 디코드된 「<어린이>」가 태그로 지워진다. 출력은 이스케이프만 한다. 원천 `useFee`·`infoRaw` 는 그대로 남는다 |
| **속성 랜딩** | 속성 하나 × 시군구 하나의 목록 페이지 — `place.1989v.com/regions/{시군구 5자리}/{attr}`(영문 `/en/…`), attr 은 `parking`·`pet`·`barrier-free`·`free`. 결과가 하한(`PLACE_LANDING_MIN_RESULTS` 10) 이상인 조합만 스크립트(`select-place-landings.mjs`)가 골라 `portal-fe/src/content/place-landings.json` 에 커밋하고, 빌드·화면은 그 목록만 읽는다. 목록 밖 주소는 404 | SEARCH trigger 값 `landing`(허브 진입 뒤 첫 질의)과 다르다 — 속성 랜딩에서 온 질의는 payload `landing: "{code5}/{attr}"` 로 가른다. 속성 칩 조작은 주소를 만들지 않는다 |
| **편집 페이지(guide)** | 사람이 고르고 쓴 큐레이션 글 — `place.1989v.com/guides/{slug}`(국문만). 원본 `portal-fe/src/content/guides/{slug}.md`, 머리말 `status`(`draft`·`published`)·`reviewedBy`·`reviewedAt`·`attractionIds`. 본문의 관광지 카드는 `<div data-guide-card="{id}"></div>` 표지를 빌드·화면이 검색 API 로 채운다. `draft` 는 `noindex` + 「검수 전 초안」 띠, 검수자 없이 `published` 면 빌드 실패 | 블로그 글이 아니다(blog 호스트·DB 원본 아님). 기각된 태그 랜딩과도 다르다 — 사람이 고른 선별이라 색인 스위치를 따르지 않고 자기 `status` 가 스위치다 |
| **프리셋** | 속성 랜딩이 허브 화면(`PlacePage`)에 넘기는 초기 조건 — 시도·시군구(3자리 `code.slice(2)`)·속성 칩 하나·은퇴 여부·SEO 입력. `useState` 초기값으로만 넣는다(effect·`selectRegion` 으로 넣으면 trigger 가 `initial`/`region` 으로 덮인다) | 사용자가 고른 필터 상태(허브 복원 `restore`)와 다르다 |
| **색인 스위치** | 속성 랜딩의 색인 여부를 정하는 상수 `PLACE_LANDINGS_INDEXABLE`(`portal-fe/src/seo/copy.mjs`, **기본 `false`**). 꺼져 있으면 랜딩은 200 이되 프리렌더·화면 모두 `noindex, follow`, sitemap·llms 에서 빠진다. 환경 변수가 아니라 상수라 켜는 일이 커밋 한 줄로 남는다 | 켜는 커밋은 ADR-0062 개정 수용과 같아야 하고, 켜는 것은 사용자다. 편집 페이지에는 걸리지 않는다. 관광지 짝 스위치(`search.alternate-pairs.enabled`)와 다른 스위치다 |

## 3-2. 하이브리드 검색 용어 (ADR-0090 · ADR-0065 · ADR-0095)

정의는 `portal-fe/src/content/search-architecture.md` §2·§4 와 같다. 값이 바뀌면 그 문서의 §4 표가 먼저 바뀐다.

| 용어 | 정의 | 피할 말 · 비고 |
|---|---|---|
| **하이브리드** | 관광지 검색에서 키워드 레그와 벡터 레그를 hybrid 질의 하나로 보내고, 검색 파이프라인이 RRF 로 순위를 합치는 방식. 쿼리 벡터가 없으면 키워드 레그만, 잔여 검색어가 비면 벡터 레그만 탄다. 스위치 `search.attraction-hybrid.enabled` | 상품 검색의 Bandit reranking 과 다르다. 통합 검색의 관광지 외 6종은 `unified` 색인 BM25 라 하이브리드가 아니다 |
| **키워드 레그** | hybrid 질의의 BM25 쪽. 점수 = BM25 × 관광·상업 분류 가중치 × 완결성 가중치 × clickBoost. 쿼리 언더스탠딩의 잔여 검색어와 패싯 필터가 여기 걸린다 | 「BM25 레그」와 같은 말. 가중치는 융합 **전**, 이 레그 안에서만 곱한다 |
| **벡터 레그** | hybrid 질의의 k-NN 쪽. 쿼리 벡터와 문서 `embedding` 의 코사인 근접, 1비트 양자화 근사 후 원본 벡터로 재채점. 필터는 키워드 레그의 bool 그대로(검색어 일치 포함) + `embeddingModel` 스탬프 | 분류 가중치·완결성·clickBoost 를 곱하지 않는다. 스탬프가 다른 문서는 이 레그에서 빠지고 키워드 레그로만 올라온다 |
| **RRF** | Reciprocal Rank Fusion. 두 레그의 순위로 `1/(60+rank)` 를 더해 합친다(rank_constant 60). 점수 정규화가 필요 없다. 앱이 기동 때 검색 파이프라인을 PUT 으로 만든다 | 동점이 실제로 생기고 하이브리드 경로엔 정렬을 걸 수 없어 동점 순서는 보장되지 않는다 |
| **쿼리 벡터 캐시** | 쿼리를 벡터로 바꾸는 세 층 — 프로세스 Caffeine 캐시 → MySQL `query_vector` 표(원천) → `search-embed` 사이드카 인코딩. 인코딩한 값은 즉시 표에 쓴다. 키는 `(model_ref, QueryNormalizer 결과)` | OpenSearch `query_vectors` 인덱스는 2026-09-08 에 없어졌다. 「질의 사전」은 옛 이름. 인코딩까지 실패한 쿼리만 Redis ZSET `search:qmiss:{modelRef}` 에 센다 |
| **쿼리 언더스탠딩** | 검색어에서 의도어를 떼어 잔여 검색어·패싯 필터·타입 의도·상업 의도로 나누는 단계(`QueryIntent`). 키워드 레그에만 건다. 자동완성은 거치지 않는다 | 벡터 레그 입력은 의도어를 떼지 않은 (오타 교정된) 검색어다 |
| **분류 사전** | place 분류 코드표(`lclsSystmCode2`)의 이름 → 코드 사전(`CategoryLexiconUseCase`). 쿼리 언더스탠딩이 패싯 필터를 만들 때 쓴다. 그 언어의 attractions 문서가 1건 이상인 코드만 담고 10분마다 갱신한다 | 「질의 사전」(쿼리 벡터 캐시의 옛 이름)과 다르다. 구현 `search/app/src/main/kotlin/com/kgd/search/application/attraction/service/CategoryLexiconService.kt` |
| **오타 교정(`correctedKeyword`)** | 검색 필드 어디에도 일치하는 문서가 0건인 두 글자 이상 단어를 자모 편집거리 2 안의 `titleJamo.spell` 제안으로 고치는 단계. 교정된 검색어는 두 레그에 모두 쓰고, 응답 `correctedKeyword` 로 함께 낸다. 허브 화면은 결과가 0건이어도 교정 안내를 보인다 | 제목에만 없는 단어는 고치지 않는다. `exact=true` 면 건너뛰고 `correctedKeyword` 는 null |
| **원래 검색어 검색(`exact`)** | 관광지 검색 요청 파라미터 `exact=true`. 오타 교정을 건너뛰고 친 검색어 그대로 찾는다. 교정 안내의 「원래 검색어로 검색」 링크가 싣는다. 화면은 누른 순간의 검색어(`exactFor`)를 들고 있다가 지금 검색어와 같을 때만 싣는다 | 검색어가 바뀌면 저절로 풀린다. 쿼리 언더스탠딩은 그대로 건다 |
| **잔여 검색어** | 쿼리 언더스탠딩이 의도어를 떼고 남긴 검색어(`Understood.residual`). 키워드 레그와 통합 검색 6종의 `unified` 질의에 쓴다. 의도어만으로 된 질의면 비고, 그때 관광지는 벡터 레그만, `unified` 는 matchAll + 인기도순이다 | 「정제 검색어」로 쓰지 않는다 |
| **상업 의도** | 질의가 상점·시장을 직접 가리킨다는 판정(`Understood.commerceIntent`). 필터가 아니라 랭킹 스위치라, 켜지면 키워드 레그에서 분류 가중치·완결성·clickBoost 를 빼고 BM25 그대로 채점한다. 음식어가 하나라도 있으면 상업 의도로 치지 않는다 | 「쇼핑 필터」 아님 — 결과를 거르지 않는다 |
| **타입 의도** | 통합 검색에서 대상 타입을 가리키는 의도어(`Understood.type`, 예: 블로그·게임). 요청 `type` 이 없을 때 이것이 대상 타입을 정하고, 묶음 순서의 첫째가 된다. 없으면 `ALL_TYPES` 7종 전부 | 관광지의 `contentTypeId` 패싯과 다르다 |
| **분류 가중치** | 키워드 레그 안에서 파생 분류 `category` 가 관광 분류(`nature`·`history`·`culture`·`leisure`)면 `3.0`, 상업 분류(`shopping`·`food`)면 `0.35` 를 곱한다. 상업 의도면 빠진다. 관광지 제안(자동완성)에도 건다 | 「카테고리 부스트」로 쓰지 않는다. 벡터 레그에는 없다 |
| **완결성 가중치** | 키워드 레그에 곱하는 `ln1p(popularityScore)`. `popularityScore` 는 문서 정보 충실도이고 필드가 없으면 1.0. `unified` 색인에서는 ln1p 를 BM25 에 **더한다**(0 이면 곱이 점수를 지운다) | 「인기도」라는 필드 이름과 달리 방문·클릭 수가 아니다 — 그건 clickBoost |
| **clickBoost** | 위 3-1절 `clickBoost` 와 같다. 키워드 레그에만 곱하고 상한 1.3, 운영 기본 꺼짐 | — |
| **판정 세트** | 쿼리 × 관광지 id 등급(0~3) 목록. CronJob `search-eval` 이 매일 BM25 · 하이브리드 · 하이브리드 + 쿼리 언더스탠딩 세 구성의 nDCG@10 을 재고, 마지막 구성이 기준선 − 0.03 아래면 실패한다. 현재 파일 `k8s/base/search-batch/eval/judgments-attractions-2026-10-11.json`(v3, 228쿼리). 항목마다 질의 의도 유형·출처(`evidence`)·등급 출처(`graded_by`)를 갖고, 매일 평가가 의도별 표를 함께 낸다 | 풀링으로 만든 세트라 그것을 만든 구성에만 공정하다 — 새 모델을 비교하기 전에 후보의 top-10 을 합쳐 다시 채점한다. 등급만 바뀌어도 새 날짜 파일로 만든다 |
| **질의 의도 유형** | 판정 세트 질의의 `intent` 여덟 값 — `NO_ANSWER` · `TYPO` · `ALIAS` · `CONDITION` · `NATURAL` · `NAME` · `REGION_TYPE` · `CATEGORY`. 질의 문자열만 보고 정하고, 둘 이상에 걸리면 앞쪽이 이긴다. 정의는 `scripts/search-eval/README.md` 「판정 세트 v3」 | 쿼리 언더스탠딩의 「타입 의도」·「상업 의도」와 다르다 — 이것은 평가용 라벨이고 검색 경로는 읽지 않는다 |
| **빈 정답 질의(`NO_ANSWER`)** | 색인에 정답이 없음을 원천 집계로 확인한 판정 세트 질의(국외 지명 · 그 지역에 없는 분류 · 무의미 입력). 올바른 응답은 0건이다. nDCG 평균과 클릭 계수 짝 비교에서 `intent` 로 뺀다 | 등급 1(국내 대체지)이 있어도 nDCG 에 넣지 않는다. 등급 2 이상이 나오면 정답이 있는 것이라 유형을 옮긴다 |
| **0건율** | 판정 세트에서 `NO_ANSWER` 를 뺀 질의 중 라이브 응답 `totalElements == 0` 인 비율. 의도별로 낸다 | 운영 트래픽의 0건 검색 비율이 아니다 — 판정 세트 기준 값이다. 보고값이고 게이트가 아니다 |
| **빈 정답 통과율** | `NO_ANSWER` 질의 중 라이브 응답 `totalElements == 0` 인 비율. 높을수록 좋다 | 보고값이고 게이트가 아니다. 0 근처에 붙어 있을 때는 같은 행의 「top-10 중 등급 0 비율」이 움직임을 보인다 |

## 7. Ports

### Outbound

#### ProductSearchPort
**Definition.** OpenSearch 검색 추상화. `search(keyword, Pageable) → Page<ProductDocument>` + `searchScored` (esScore 동봉, reranker 입력용).
**KDoc 인용.** "ES `_score` 를 동봉해 반환. application 레이어의 reranker (e.g. ThompsonReranker) 가 esScore 를 hybrid 계산에 사용한다."
**Adapter.** `ProductSearchAdapter` (OpenSearch 클라이언트)

#### ProductIndexPort
**Definition.** OpenSearch 인덱싱 추상화 — `indexProduct(doc)`, `bulkIndex(docs)`.
**Adapter.** `ProductSearchAdapter` 또는 별도 indexing adapter

#### BanditStatePort
**Definition.** BanditState 조회 (Redis). `fetch(key)`, `fetchBatch(keys)`.
**Adapter.** `BanditStateRedisAdapter`

#### BanditEventPort
**Definition.** Bandit 학습 이벤트 발행. `recordImpression(event)`, `recordClick(event)`.
**Adapter.** `BanditEventKafkaAdapter`
