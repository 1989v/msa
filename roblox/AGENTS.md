# 로블록스 게임 개발 — 지속 작업 원칙

사용자가 2026-10-28 반복 교정하고 메모리에 남기라고 요청한 원칙이다.

작업 전에 [로블록스 이식 원칙](../docs/research/2026-10-26-roblox-development/README.md#0-이식-원칙--무엇을-보존하고-무엇을-새로-만드는가-2026-10-28-사용자-확정)을 읽는다. **게임의 핵심 재미와 구성은 보존하고, 조작·화면·카메라·배경·에셋·물리·규모는 로블록스에 자연스럽게 새로 설계한다.**

- 기본 이동·점프·터치 스틱·게임패드·카메라·아바타를 우선 활용한다. 기본 동작을 웹 버튼/고정 키 안내/커스텀 카메라로 다시 만드는 것을 기본값으로 삼지 않는다.
- 원본의 점프 클릭 버튼·C/X/Z 안내·모바일웹 HUD를 옮기지 않는다. 게임 전용 상호작용이 필요할 때만 적절한 ProximityPrompt·Tool·입력 액션을 추가한다.
- 배경/에셋은 Terrain·재질·Lighting·Atmosphere·Clouds·모듈형 Model·적합하고 출처가 확인된 에셋으로 실제 공간을 구성한다. 단색 발판 수를 늘리고 구간 이름만 붙이는 것으로 풍부한 월드라고 하지 않는다.
- 원작 규칙/수치/좌표는 게임 의도를 이해하는 자료다. 엔진과 조작에 맞춘 조정은 허용하되 보존한 재미와 각색한 부분을 기록한다. 게임별로 별도 승인된 경제/밸런스 계약은 따른다.
- 원본과 같은 좌표/개수, 코드 검사 수, AI 시안을 게임 경험 검증으로 대신하지 않는다. 실제 플레이·화면·기기 입력을 확인하지 못했다면 미검증으로 명시한다.
- 구현은 지정 모델 `gpt-6.1-sol` 담당자 한 명에게 위임한다. 다른 로블록스 게임·웹 원작·다른 작업자의 변경을 건드리지 않는다.
- 컴퓨터 사용의 기존 거절을 다른 도구로 우회하지 않는다. 플랫폼 로그인·업로드·구매·공개는 별도 승인 범위를 따른다.
