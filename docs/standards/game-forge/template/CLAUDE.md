# {{NAME}} — game-forge 하네스

**이 폴더가 세계의 전부다.** 바깥의 코드·에셋·관습을 참고하지 않는다. 목표의 원본은 `BRIEF.md`.
사용자는 세션 중에 답하지 않는다 — 기획·조작·기술·연출의 결정은 네가 한다.

## 루프

구현 → 실행(`forge/play.mjs`) → 관찰(스크린샷을 Read 로) → 디버깅 → 개선 → 재검증(`forge/gate.mjs`).
계획·설계·코드 초안·첫 실행 성공에서 멈추지 않는다. "동작한다" 는 출발점이지 목표가 아니다.

## 완성의 정의 — Stop 훅이 이 순서로 대조한다

1. `node forge/gate.mjs` **전체 실행**이 PASS. 축 17개, 문턱은 `forge/thresholds.json` — **하한**이지 목표가 아니다
2. 게이트가 만든 **스크린샷을 전부 Read 로 보고** `verifications/visual-review.md` 를 쓴다 — 게이트 실행 *이후에*, 한 장에 한 줄(파일명 · 보이는 것 · 결함)
3. 봉인(`forge/.seal`)이 유지된다. 게이트·문턱을 고쳤으면 `node forge/seal.mjs --reason "<왜>"` — 사유는 `verifications/seal-log.md` 에 남아 사용자가 본다

셋이 아니면 세션은 끝나지 않는다. **문턱을 낮추지 말고 게임을 고쳐라.**
사용자 없이는 정말 못 나가는 것(외부 키 등)만 `verifications/BLOCKED.md` 에 적고 멈춘다. 그 외의 모든 결정은 네 몫이다.

## 증거 규칙

- **"고쳤다" 는 값으로 판정한다** — 게이트 리포트의 `measured` 가 달라진 것. 코드를 바꿨다는 사실은 근거가 아니다
- **재기 전에 재는 대상이 최신인지** — 게이트는 `sourceHash` 로 이를 강제한다. 옛 리포트로 "확인했다" 고 하지 않는다
- 스크린샷은 파일로 남기고 Read 로 본다. **base64 를 대화로 흘리지 않는다**(한 장에 수만 토큰이 증발한다)
- 수치가 전부 초록이어도 그림을 본다 — 「있어야 할 것이 없음」은 수치가 못 잰다
- 검증용 크롬은 도구가 켜고 끈다. 직접 띄우지 않는다

## 기술 계약

- 순수 HTML5 Canvas(2D 또는 WebGL) + 바닐라 JS. **빌드 0 · 외부 라이브러리 0 · 다운로드 에셋 0.** `index.html` 을 열면 실행
- `window.__forge` — `forge/step-api.md`. **이것이 없으면 검증도 완성도 없다.** 첫 실행 가능 시점에 가장 먼저 붙인다
- 입력은 이벤트에서 **상태만 기록**하고 판정은 `step` 안에서. 난수는 시드 RNG 하나(`reset(seed)`). `alert/prompt/confirm` 금지
- 에셋: `assets/STYLE.md` 가 스타일 바이블. 프로바이더는 `BRIEF.md` 가 정한다(기본 `procedural` — 코드 드로잉 + WebAudio 합성)
- 모바일: **세로·가로 둘 다.** 캔버스 `touch-action: none`. 조작은 `controls().touch` 로 선언하고 게이트가 실제 터치로 누른다
- 한국어 UI. 게임 용어는 한국 통용("스테이지 N", "N면" 금지)

## 품질 순서 (BRIEF 의 4축)

정확성·안정 프레임 → **장르 특유의 판단과 보상**(손맛) → 캐릭터·소리·화면의 완성도 → 콘텐츠 양.
**첫 판부터 어렵다** — 가만히 있으면 죽고, 난타로는 못 깬다(게이트가 봇으로 잰다). 무음은 미완성, 정적인 화면은 미완성.
장식과 기능 개수로 품질을 대신하지 않는다. 쉬운 MVP 에 스스로 상한을 두지 않는다.

## 리듬

- 30분 안에 조작되는 코어 루프 + `__forge` → 게이트 1회(**빨간불이 정상**) → 축별로 초록을 늘린다
- 의미 있는 단위마다 `git commit`. `progress.md` 갱신 — **산출물 경로 · 다음 할 일 · 막힌 것 · 함정** 넷. 컴팩션 뒤 SessionStart 훅이 이 파일을 읽는다
- `node forge/gate.mjs --only HIT,MOBILE` 로 한 축만 빨리 돌 수 있다. 완성 판정은 전체 실행만 인정된다

## 실측 함정 (이전 제작에서 실제로 난 것)

- 120Hz 화면: `keydown` 에서 직접 판정 → edge-trigger 입력 유실. `step` 안에서 소비
- `ctx.filter = 'blur()'` 매 프레임 → 33fps. 오프스크린 캔버스에 미리 그려 캐시
- `undefined <= 0 === false` — 초기화 안 된 hp 가 불사
- 논리 px 로 재면 전부 통과처럼 보인다 — 폰에서 캐릭터가 11 CSS px 였다. 게이트는 CSS px 로 잰다
- 가로 캔버스를 세로 폰에 레터박스 → 조작 불가. 레이아웃은 방향별로
- WebAudio 는 첫 사용자 입력 뒤 `resume()` 해야 소리가 난다. 게이트는 제스처 없이 켜 주지만 실기기는 아니다
- 보스 스폰 시점의 `undefined` 참조는 그 스테이지에 가야 터진다 — `warp` 로 모든 스테이지를 직접 밟는다
- **렌더가 시뮬레이션 RNG 를 소비하면 결정론이 깨진다** — 흔들림·파티클 지터가 `rnd()` 를 쓰자 rAF 횟수에 따라 봇 결과가 달라졌다(같은 seed 인데 한 번은 통과, 한 번은 클리어). 시각 지터는 별도 RNG 로
- 광역기 + 겹쳐 서는 적 = 난타로 클리어된다. 적은 플레이어 둘레의 자기 슬롯으로 가게 하고, 광역 피해는 대상 수만큼 곱해진다는 것을 잊지 않는다
