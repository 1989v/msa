# 게임 지형 생성 표준

이 문서는 특정 엔진에 의존하지 않는 높이장 기반 오픈월드 생성 절차다. 구현 예시는 WINDWAKE이며, 다른 게임은 이동 속도·점프 높이·카메라 크기에 맞춰 수치를 다시 검증한다. 같은 시드의 예쁜 지형을 만드는 것보다 **보이는 땅, 밟는 땅, 배치 기준이 일치하는 것**을 먼저 보장한다.

## 좌표와 재현성

- 길이 단위는 미터, +Y는 위, +Z는 북쪽이다. 청크 위치는 `floor(x / chunkSize)`로 구한다. 음수를 0 방향으로 버림하지 않는다.
- 새 게임의 저장 계약에는 세계 시드와 생성 버전을 함께 기록한다. 현재 WINDWAKE는 저장에 시드를 기록하고 생성 버전은 코드의 `WORLD_GENERATION.version`으로 관리하는 기존 형식이다. 기본 세계 시드는 `18092026`, 외곽 지형 생성 버전은 2, 청크는 60m다. 이번 이주는 이전 슬롯의 ID 의미를 유지한다. 향후 여러 생성 버전의 세계를 병존시킬 때는 저장에도 생성 버전을 추가하고 버전별 로더를 둔다.
- 지형, 장식, 적 무리의 난수 스트림을 분리한다. 새 장식을 추가했다고 기존 적의 좌표나 종류가 바뀌면 안 된다. 영속 ID를 다른 생물에 재사용하지 않는다.
- 기존 슬롯의 난수 소비와 과거 배치 거절 조건을 유지한 뒤, 새 지형에서 위험한 슬롯만 억제한다. 억제된 ID의 처치 기록도 저장에서 제거하지 않는다. 새 슬롯에는 버전별 이름 공간을 사용한다.

## 생성 순서

1. **이동 계약부터 정한다.** 기본 걷기·경사 이동·점프·활강으로 연결할 목적지와 복귀 경로를 먼저 배치한다. 도로를 가장 짧은 직선으로만 연결하지 말고 고갯길·능선·계곡 우회로를 함께 둔다.
2. **큰 지형을 만든다.** 연속 보간한 격자 잡음에 여러 주파수의 잡음을 더한다. fBm은 옥타브마다 주파수를 늘리고 진폭을 줄이는 방식이다. 높이의 전체 규모와 물 높이를 먼저 조정한 뒤 세부를 넣는다. [The Book of Shaders의 fBm 설명](https://thebookofshaders.com/13/)을 참고한다.
3. **능선·골짜기를 더한다.** `1 - abs(noise)`를 제곱한 능선 항과 완만한 장주기 항을 조합한다. 바이옴 강도는 거리 가중치로 혼합한다. 바이옴 경계에서 진폭을 즉시 바꾸지 않는다. WINDWAKE는 정규화한 4옥타브 fBm, 기본 주기 145m, 주파수 배율 2, 진폭 배율 0.46을 사용한다. 큰 항 진폭은 39m, 능선 항은 26m, 작은 항은 2.2m다. 실제 높이는 바이옴 계수와 보호 마스크를 적용한 결과다.
4. **보호 영역을 적용한다.** 시작 퍼즐, 마을 바닥, 입구, 보스 전투 바닥, 주요 이동로를 고정한다. 마스크 경계는 연속 보간한다. 경로 높이는 검증된 양 끝점 높이 사이에서 보간하고, 넓은 어깨를 통해 주변 지형에 연결한다. 높이를 먼저 바꾼 뒤 건물의 기초만 덮는 방식은 피한다.
5. **최종 격자 정점을 확정한다.** 렌더링과 충돌이 같은 최종 표본을 사용하도록 한다. 이동·카메라·스폰·저장 복원 모두 이 API를 호출한다.
6. **배치를 마지막에 한다.** 최종 지면에서 물·기울기·구조물·휴식 영역·입구 접근로를 검사한다. 바이옴별 2~3마리의 혼합 무리와 도로 옆 무리를 배치하되, 출현 직후 접촉 피해가 발생하지 않는 거리를 런타임에서도 검사한다.

## 보호 영역과 접근

WINDWAKE는 기존 중심부 퍼즐의 분석적 높이 함수를 유지한다. 중심부 240×240m 영역의 마지막 3m 띠에서는 충돌도 외곽 삼각형으로 부드럽게 전환하여 경계의 비정점 위치에 높이 단차가 생기지 않게 한다. 외곽 도로의 중심 8m는 고정 높이를 따르고, 34m까지 완만하게 주변 지형과 섞는다. 마을은 반경 31m, 입구는 10m, 등대는 10m, 보스는 28m의 평탄한 내부 영역을 갖는다. 각 영역 바깥에는 별도의 완충 구간이 있다. 주요 경로가 교차하면 높이와 경사를 재검증한다.

휴식 장소와 입구의 적 금지 반경은 장식 금지 반경과 다르다. 특히 던전 입장에 근처 적 검사가 있으면 **스폰 위치뿐 아니라 추격 거리**도 고려한다. WINDWAKE의 입구 주변 42m는 외곽 적 생성에서 제외한다. 기존 난수 호환용 거절 함수는 변경하지 않고 최종 출현 단계에서 적용한다.

## 메시와 충돌 계약

외곽은 월드 원점에 맞춘 3m 정사각 격자를 사용한다. 각 셀의 정점을 `a=(0,0)`, `b=(1,0)`, `c=(1,1)`, `d=(0,1)`로 정의하고 삼각형은 `a,d,c`와 `a,c,b`다. 렌더링이 이 대각선을 쓰면 충돌도 동일한 두 삼각형의 선형 보간을 쓴다. 쌍선형 보간이나 원본 잡음 함수로 충돌 높이를 다시 계산하지 않는다.

`terrain.mjs`의 `triangleHeight()`와 `createHeightfield()`가 재사용 가능한 기준 구현이다. 평탄면은 `a + (b-a)*u + (c-a)*v` 형태로 계산하여 같은 높이를 정확히 유지한다. 정점은 전역 좌표를 키로 캐시하며, 청크 경계에서 별도 난수를 사용하지 않는다.

기존 퍼즐 지형처럼 분석적 충돌을 유지하는 예외는 따로 측정한다. WINDWAKE 중심부는 1.5m 렌더링 격자로 정밀도를 높이며, 외곽과 만나는 중간 정점은 외곽 3m 변을 따라 연결한다. 이 예외를 외곽 전체로 확장하지 않는다.

높이장은 한 X/Z에 하나의 Y만 표현한다. 동굴·돌출 바위·다리 밑·겹치는 층은 별도 구조물과 충돌 표면이 필요하다. [GPU Gems 3의 절차적 복합 지형 장](https://developer.nvidia.com/gpugems/gpugems3/part-i-geometry/chapter-1-generating-complex-procedural-terrains-using-gpu)은 밀도장 기반의 다른 표현을 다룬다. 그 방식 전체를 단순 높이장 예제에 구현했다고 표현하지 않는다.

## 배치와 성능 한도

- 정점 캐시 상한 32,768개, 데이터 청크 상한 96개. 지도 표본 조회는 지형 표본만 계산하며 청크 메시나 적을 생성하지 않는다.
- 렌더러 청크 상한 64개, 프레임당 청크 생성 2개 이하, 정적 삼각형 120,000개 미만. 반복 이동 후 GPU 버퍼를 모두 해제할 수 있어야 한다.
- 외곽 적 후보는 청크당 기존 2슬롯 + 새 9슬롯이다. 최대 32×32 청크이므로 외곽 후보 11,264개 + 유한한 수작업 적을 포함해 ID 예산 12,288개 이하다. 인스턴스 적은 별도 저장 영역을 사용한다. 실제 동시 활성 적은 64개 이하로 제한한다.
- 후보 수와 실제 활성 수는 다르다. 지역 방문 순서와 저장된 처치 기록을 바꿔도 생존·보스·습격을 위한 우선 수용이 가능해야 한다. 구체적인 프레임 시간은 실제 브라우저/장비에서 따로 보고한다.

## 출시 전 정량 게이트

| 대상 | 기준 |
|---|---|
| 외곽 셀 내부 | 렌더 삼각형과 충돌 높이 차이 ≤0.02m |
| 외곽 청크 이음새 | 양쪽 높이 차이 ≤0.001m, 음수 좌표 포함 |
| 기존 중심부 예외 | 분석적 지면과 정밀 메시 차이 ≤0.12m |
| 주요 연결 경로 | 1m 간격 높이 변화/수평 거리 ≤0.8, 물·충돌 장애물 없음 |
| 바이옴 높낮이 | 180m 창 8개 중 6개 이상에서 고저 차 ≥18m; 보호 패드 밖도 측정 |
| 실제 이동 | 연결된 걷기 구간에서 상승 ≥15m 후 다시 하강, 낙하 복구 사용 금지 |
| 적 배치 | 물·급경사·구조물·거점·입구 제외, 실제 이동 중 만난 위협과 지역별 수 보고 |
| 결정성/영속성 | 역순 청크 조회·캐시 퇴거·저장 복원 후 ID 의미 유지, 4,096개 초과 처치 보존 |
| 성능 | 위 캐시·메시·활성 적 상한, 실제 Chrome 프레임 시간 및 콘솔 검사 |

검증 명령은 `node --test windwake/tests/terrain.test.mjs windwake/tests/world.test.mjs`다. 수치 테스트와 렌더러 가짜 GL 테스트는 실기 화면·완전한 플레이 경로의 대체물이 아니다. 연결된 시작점부터 목적지까지의 통합 경로, 카메라 회전, 점프/활강, 브라우저 이미지와 콘솔을 별도로 확인한다.

## 참고 영상과 적용 범위

사용자 영상은 [「마인크래프트에서 자연 환경을 자동 생성하는 방법?」 — 저세상개발자](https://www.youtube.com/shorts/3W1tKXhbiEk)다. 이번 조사에서는 제목·작성자·설명을 확인했으며, 자막 응답은 비어 있었고 영상 자체를 검증된 시청 자료로 확보하지 못했다. 설명에 Alan Zucconi의 Minecraft World Generation 튜토리얼이 나열되어 있다는 사실까지만 확인했다. 따라서 영상의 발언·단계·구현 방식을 추정하거나 전사한 것으로 인용하지 않는다.

위 표준의 잡음·다중 옥타브·표면 표현 설명은 위의 공개 기술 자료와 실제 구현/테스트에 근거한다. Skybound 인계에서는 렌더/충돌 삼각형 공유, 연결된 실제 이동 검증, 복수 이동 방법이라는 원칙만 채택한다. 해당 엔진·의존성·미확인 물리 구조를 가져오지 않는다.
