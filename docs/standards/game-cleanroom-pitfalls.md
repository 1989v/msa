# 게임 클린룸 — 실측 함정 목록

<!-- source: docs/standards/game-cleanroom-pipeline.md -->

`game-cleanroom-pipeline.md` 에서 갈라 나온 파일. **검증 단계에 들어갈 때 읽는다.**
앞선 제작에서 실제로 터진 것만 적는다 — 추측한 위험은 여기 오지 않는다.

## 판정 트리거 — 증상으로 찾는다

증상만 보고는 엉뚱한 곳을 파기 쉽다. 아래 표는 **증상 → 진짜 원인 → 잡았어야 할 게이트** 다.

| 증상 | 진짜 원인 | 잡았어야 할 게이트 |
|---|---|---|
| 모바일에서 화면이 작다 | 캔버스가 flex/grid 아이템이다 (카메라 문제가 아니다) | G5-2 |
| 캐릭터가 손톱만 하다 | 비율로만 재고 CSS px 을 안 쟀다 | G1-2 · G5-2 |
| 가상패드가 영영 안 뜬다 | 상시 HUD 에 `.panel` 을 썼다 | G5-4 |
| 게임 스케일과 화면 맞춤이 서로 싸운다 | `data-fit="0"` 누락 | G5 |
| 랭킹이 붙었다는데 점수가 안 올라간다 | 배선만 하고 호출이 없다 | 통합 검증 |
| 규격이 지켜지지 않는다 | 문서에만 있고 정적 검사에 없다 | lint |
| 폰이 뜨겁다 | 픽셀 수 × 포스트 패스 × MSAA 가 곱해진다 | G7 |

**문서에만 적힌 규격은 8% 준수율로 수렴한다. 게이트에 없는 축은 지켜지지 않는다.**

### G5 하네스 첫 시험 — 통과했고, 그 과정에서 셋이 드러났다 (2026-08-25)

G5 개편이 실제로 작동하는지 보려고 클린룸 세션에 세로 액션(`neon-drifter`)을 맡겼다.
**게이트를 첫 시도에 통과했다** — `lint --strict` 경고 0, 주인공 세로 43.3 · 가로 32.4 CSS px,
두 방향 콘솔 0. 하네스는 먹혔다. 다만 세 가지가 걸렸고 전부 **프롬프트에 없던 것**이다.

**1. `touch.js` 는 캔버스가 블록 흐름일 것을 전제한다 — flex 로 두면 계속 줄어든다**

세션이 `body { display:flex; align-items:center }` 로 두자 캔버스가 flex 로 먼저 줄고,
줄어든 값을 `fitCanvas` 가 다시 재서 **390×520 이어야 할 것이 334×446 → 306×409 로 반복 축소**됐다.
`display:block` + `canvas { margin:0 auto }` 로 바꾸자 정확히 390×520 이 나왔다.

- **증상이 "모바일에서 화면이 작다" 라 카메라·해상도 문제로 오진하기 딱 좋다.** 원인은 CSS 한 줄이다
- 게임에 알려야 할 규약: **캔버스를 flex/grid 아이템으로 두지 마라.** `data-fit="0"` 을 쓰지 않는
  게임은 블록 흐름 + `margin:0 auto` 가 전제다

**2. 세로 게임을 가로에서 재면 하한이 깨진다 — 기준 방향을 정하는 것이 규칙보다 먼저다**

3:4 세로 캔버스를 844×390 에 넣으면 배율이 0.270 으로 고정되고, 탄 지름이 **12~13 CSS px**
(하한 16)로 내려간다. 세션은 하한을 맞추려 게임 좌표에서 탄을 키우면 **세로에서 화면 폭의
1/18 짜리 탄**이 되어 세로 플레이가 망가진다고 판단하고 **세로를 기준으로 삼았다.** 옳은 판단이다.

- **G5-2 의 하한표는 "그 게임의 기준 방향"에서 재는 것**이다. 두 방향 모두에서 전 항목을
  만족시키라는 뜻이 아니다 — 세로 게임은 세로가, 가로 전용은 가로가 기준이다
- 기준 방향은 `orientation` 시드와 같아야 한다. 이 게임은 `PORTRAIT` 로 남겼다
- 대신 **못 맞춘 축을 숨기지 말고 적는다** — 세션은 "가로에서 탄이 하한 아래" 를 그대로 적고
  식별 폭을 빛무리로 보완했다고 밝혔다. 이게 올바른 보고다

**3. 클린룸은 `lib/` 를 못 봐서 API 를 "안 부른다" — 조용히 빠진다**

세션이 런타임에서 `PlatformAdapter` 에 `init`/`runEnd` 만 있는 것을 확인하고도,
**인자 모양을 몰라 `runEnd` 를 부르지 않았다.** 대신 자체 이벤트를 쏘고 통합 세션에 넘겼다.
정직한 처리지만 결과는 **랭킹이 안 붙은 게임**이고, 이건 2026-08-24 의 rank.js 누락 4종과
같은 자리에서 같은 모양으로 다시 나온 결함이다.

- **마스터 프롬프트에 `runEnd({score, detail, board})` 시그니처를 적어라.** 클린룸 하드 룰이
  `lib/` 열람을 금지하는 한, 세션이 알 방법이 없다 — 금지해 놓고 알기를 기대하면 안 된다
- 통합 절차의 "요청 본문 확인" 이 이걸 잡는 마지막 그물이다. 그물이 하나뿐이면 언젠가 샌다


### 모바일 결함이 50여 종에 한결같이 남은 이유 — 게이트가 데스크톱 전용이었다 (2026-08-24)

"모바일에서 캐릭터가 크고 맵이 확대돼 못 즐긴다"가 **5회 이상 반복 지적**됐다. 게임마다
고쳐도 신작에서 또 나왔다. 원인은 개별 실수가 아니라 **이 표준의 구조**였다:

- 완성의 정의(품질 게이트 · 검증 프로토콜)가 **100% 데스크톱**이었다 — KeyboardEvent 디스패치,
  데스크톱 스크린샷, 죽은 입력 감사(키보드). 모바일은 "완성 선언 **뒤**" 통합 절차에만 있었다
- 클린룸 세션이 받는 마스터 프롬프트에 모바일이 **한 줄도 없었고**, `SKILL.md` 에도 **0회**였다.
  즉 세션은 **구조적으로** 모바일을 못 보고 완성 선언을 했다
- G5(모바일은 기본값이다)는 **4줄짜리 선언**이었고 수치도 절차도 없었다 — 지킬 수 없는 규칙이다
- **교훈: 게이트에 없는 축은 지켜지지 않는다.** "중요하다"고 문서에 적는 것과
  "미달이면 완성이 아니다"로 판정에 넣는 것은 완전히 다른 일이다

### G1 을 통과했는데 모바일에서 손톱만 하다 — 비율은 기기를 모른다 (2026-08-24)

G1 의 비율(주인공 높이 / 화면 높이)은 **기기 무관**이다. 그런데 2560×1440 가로 캔버스를
390px 폭 세로 화면에 레터박스하면 **390 × 219 CSS px** 가 되고, G1 을 통과한 1/19 캐릭터는
실제로 **11 CSS px** 다.

- **비율 통과와 기기 공간 통과는 별개의 게이트다** (G5-2). 논리 좌표로 재면 둘 다 통과처럼 보인다
- 이건 "그려지는 픽셀로 재라"(coin-corgi 함정)의 **한 단계 아래** 층이다 —
  그려지는 픽셀도 캔버스 좌표계이지 화면 좌표계가 아니다
- 16:9 이상 가로 캔버스 게임은 세로에서 **자동 실패**로 취급하고 셋 중 하나를 고르게 했다

### 게임 자체 스케일과 `fitCanvas` 가 서로 싸운다 — `data-fit="0"` 누락 (2026-08-24)

`lib/touch.js` 의 `fitCanvas` 와 게임 자체 리사이즈가 **둘 다 `canvas.style.width` 를 쓰면**
서로 덮어쓴다. `docs/conventions/game-input-standard.md` 가 "둘 중 하나만 쓴다"고 금지한 사례인데,
**인피니티 타워가 현재 이 상태다** — `touch.js` 를 `data-fit="0"` 없이 싣고 `js/20-main.js` 가
직접 `canvas.style.width/height` 를 쓴다. (올바른 예: `deadline` 은 `data-fit="0"` 을 붙였다)

- 게임이 스케일을 직접 관리하면 **반드시 `data-fit="0"`** 을 붙인다
- 증상이 "가끔 레이아웃이 튄다" 라 눈으로는 잘 안 잡힌다 — 정적 검사로 잡는 편이 싸다
  (`scripts/lint-game-mobile.py` W2)

### 규격을 정해도 지켜지지 않는다 — 3-part 한글 라벨 4/48 (2026-08-24)

가상패드 액션 라벨은 `code:아이콘:라벨` 3-part 한글이 표준인데, `touch.js` 를 실은 48종 중
**4종만** 지키고 있다(`abyssal-crown` `aero-vendetta` `deadline` `serpent-legion`).
인피니티 타워는 아직 `KeyZ:⚔,KeyX:✦,…` 로 아이콘만 있다.

- 아이콘만 있으면 **무슨 버튼인지 아무도 모른다** — 특히 5개가 나란히 있을 때
- **문서에만 적힌 규격은 8% 준수율로 수렴한다.** 정적 검사로 옮겨야 한다
  (`scripts/lint-game-mobile.py` W1)

### 배선해 놓고 아무도 안 읽는 필드 — `orientation` (2026-08-24)

카탈로그에 `Orientation.LANDSCAPE|PORTRAIT|BOTH` 가 있고 도메인 → DTO → `gameApi.ts` 까지
**끝까지 배선돼 있는데 FE 에서 아무도 읽지 않는다.** 가로 전용 게임도 세로로 열리고,
사용자가 `⛶ 크게` 를 직접 눌러야만 가로가 된다.

- 값을 채우는 것과 쓰는 것은 다르다. **소비자 없는 필드는 시드만 정확해지고 화면은 그대로다**
- `GameDetailPage.tsx` 는 이미 `screen.orientation.lock('landscape')` 를 할 줄 안다 —
  없는 건 "이 게임이 가로 전용인지" 를 묻는 한 줄뿐이다


### 랭킹이 붙었다고 적혀 있는데 점수가 한 건도 안 올라간 게임 4종 (2026-08-24)

`platform.js` 만 싣고 **`rank.js` 를 안 실은** 게임이 넷 있었다 — 잿불 원정대 · 랜덤 타워
디펜스 · 인피니티 타워 · 랜덤 카드 디펜스. 넷 다 카탈로그에 `sdk_integrated=1` 과
`leaderboard` 태그가 붙은 채 배포됐고, **단 한 건도 제출되지 않았다.**

- 원인은 두 겹이다. ① 통합 때 스크립트 한 줄이 빠졌다 ② `platform.js` 의 `runEnd` 가
  `if (!window.GameRank) return;` 로 **조용히 넘어갔다**. ②가 없었으면 첫 판에서 들켰다
- **조용한 무시가 진짜 범인이다.** 없어야 할 것이 없을 때는 소리를 내라 —
  지금은 `console.error` 로 "rank.js 를 platform.js 앞에 넣어야 한다"고 외친다
- **검증 절차가 없던 것도 원인이다.** "배선했다"를 눈으로 확인하는 단계가 통합 절차에
  없었다. 지금은 요청 본문 확인이 필수 항목이다
- 같은 층위의 교훈: **카탈로그 플래그는 약속이다.** `sdk_integrated=1` 은 "랭킹이 있다"는
  약속이고, 켜놓고 안 되면 안 켠 것보다 나쁘다 (`supports_mobile` 과 같은 성질)

### dev 훅으로 만든 런은 점수가 0 이라 "제출 0건"이 배선 문제로 안 보인다 (2026-08-24)

`dev.scene('over')` 류는 판을 열자마자 죽이므로 점수가 0 이고, `GameRank.submit` 은
`score > 0` 이 아니면 **아무 일도 하지 않는다**. 그래서 제출이 0건인데, 이게 배선 문제인지
0점 런인지 구분되지 않는다.

- 랭킹 검증은 **점수가 실제로 쌓인 런**으로 하라 — 웨이브를 건너뛰거나(`dev.jumpWave`),
  진짜 한 판을 끝까지 두거나, 월드의 점수 필드를 채운 뒤 결과 씬으로 보낸다
- 실측: 그어서 막기 세 유형을 방어 없이 그대로 두면 10~13초에 끝나고 점수 97~168 이 남는다.
  이 정도면 실제 완주로 검증하는 게 가장 싸다

### 있지도 않은 필드로 모드를 갈랐다 (2026-08-24)

인피니티 타워의 런 종료 보고가 `G.mode === 'tower'` 로 모드를 판정했는데 **`G` 에 `mode`
필드가 없었다.** 항상 `undefined !== 'tower'` 라 등반 판이 전부 「방어전」으로 보고됐다.
모드는 `world.mission.mode` 에 있었다.

- 랭킹이 아예 안 붙어 있어서(위 함정) **몇 주 동안 아무 증상이 없었다** — 함정 둘이
  겹치면 하나가 다른 하나를 가린다
- JS 는 없는 필드를 조용히 `undefined` 로 돌려준다. **분기의 근거가 되는 필드는 값이
  실제로 뭐가 찍히는지 한 번은 찍어 보라** — 타입이 잡아 주지 않는다
- 캐시도 같이 물렸다. 고친 뒤 재확인이 옛 결과를 보여줘 "안 고쳐졌다"로 읽혔다 —
  CDP 검증에서는 `Network.setCacheDisabled` 를 켜라

- 120Hz 디스플레이: 고정스텝이 0회 도는 렌더 프레임에서 edge-trigger 입력을 비우면 입력 유실
- **"렉 걸린 느낌"의 진범은 대개 히트스톱이 아니라 프레임 페이싱이다** — 고정 1/60 누적
  방식은 120Hz 에서 **렌더 프레임의 절반이 0스텝**으로 돌아 개체가 두 프레임에 한 번만
  움직인다(미세 스터터). **클램프된 가변 스텝**(프레임당 1~4 서브스텝, 서브스텝 ≤20ms)으로
  바꿔 렌더 프레임마다 반드시 시뮬한다. 무겁다는 피드백이 오면 히트스톱부터 줄이지 말고
  **여기부터 계측**하라 (ashen-warband 실측)
- 공격 시작에서 속도를 통째로 죽이면(`vx *= 0.25` 류) 걷다 치는 순간 끊기고, **공중에도
  같은 감속을 걸면 점프 궤적이 끊긴다** — 감속은 지상에만, 공중 관성은 100% 보존
- 잡기가 약공을 가로채면 연타가 막힌다 — 근접만으로 잡기로 새면 실측 입력의 절반이
  유실된다(24회 중 12회). 잡기는 **콤보 미시작 + 적 방향 입력 유지**일 때만 성립시켜라
- **공중 저글이 "안 되는" 원인은 저글 로직이 아니라 판정·넉백이다** (실측 원인 2개):
  ①투사체/공격의 **세로 판정 밴드가 좁아**(±30px) 뜬 적을 통과한다 → ±90~110px 로 확대
  ②**런처 넉백이 적을 사거리 밖으로 밀어낸다** → 런처만 넉백을 대폭 낮추고(200→50)
  **저글 자석**(뜬 적을 공격자 앞 ~105px·같은 깊이로 흡인)을 넣는다.
  추가로 저글 중 중력 ~0.46배 + 피격마다 재상승(감쇠 0.85) + **상승 상한**(너무 높이 뜨면
  후속타 사거리를 벗어난다). 근접 가로채기 기술이 체인을 먹지 않는지도 확인
- `ctx.filter = 'blur()'` 는 프레임을 죽인다 (33fps 실측) — 그라디언트/스트로크로 대체
- `undefined <= 0` 는 false — 타이머류는 0 으로 명시 초기화하고 부정형(`!(x > 0)`) 비교
- 커맨드 입력은 **입력 당시 facing** 을 히스토리에 함께 기록 (도중 돌아서면 의미 반전)

  통째로 놓친다** — 0.24초 약공이 "무반응" 으로 나온다. **누르는 동안 40~50ms 간격으로 폴링**하라.
  ②**긴 세션의 후반 블록에서 CDP 입력이 씹힌다** — 마지막 7칸이 전부 실패로 나왔는데, **블록 순서를
  바꾸자 실패가 순서를 따라 이동**해 씬·키가 아닌 위치 의존(하네스 드리프트)으로 판명됐다.
  **블록마다 프로세스를 분리**해 재측정하라. 두 경우 모두 그대로 믿었으면 **멀쩡한 코드를 뜯을
  뻔했다.** 대량 실패가 한꺼번에 나오면 코드보다 측정을 먼저 의심하고, 격리 재현 → 누적 상태
  배제 → **순서 바꾸기** 3단계로 확인하라

## 통합 절차 (완료 보고 후 — 메인/통합 세션 몫)

> [!important] **모바일 가상패드 배선은 통합의 필수 항목이다** (2026-08-20 신설)
> 클린룸 하드 룰이 `lib/` 열람을 금지하므로 **클린룸 게임은 구조적으로 PC 전용으로 나온다** —
> 만든 세션은 공용 가상패드의 존재조차 모른다. 실제로 클린룸 게임 **6종이 전부
> `supports_mobile=0`** 으로 배포됐다(2026-08-20 적발). 통합 시 반드시:
>
> 1. **배선** — `<script src="../lib/touch.js" data-actions="Code:아이콘:라벨,…">`
>    (필요 시 `data-dirkeys="wasd"` · `data-stick` · `data-fit`).
>    **순서가 곧 자리다** — 1번째=주공격(코너 대형), 2번째=점프/결정, 3번째=대시/특수,
>    4·5번째=보조. 라벨은 한글 1~3자 필수. **Esc 가 일시정지/뒤로로 동작하면
>    `data-pause="1"`(시스템 ⏸ 버튼)도 켠다** → `docs/conventions/game-input-standard.md`
> 2. **터치 에뮬레이션 실측** — `#vt-root` 생성 · 버튼 개수 · **조이스틱 드래그로 실제 이동**까지.
>    **패드가 뜨는 것과 조작이 먹히는 것은 다른 문제다**
> 3. 통과한 뒤에만 `supports_mobile = 1` 로 시드한다 — 이 플래그는 "모바일에서 할 만하다"는
>    약속이고, 켜놓고 안 되면 안 켠 것보다 나쁘다
>
> **실측 함정 2종**
> - `touch.js` 는 **보이는 `.panel` 이 있으면 패드를 숨긴다**(메뉴 위에 버튼이 겹치는 것을
>   막는 규약). 게임이 **플레이 화면에도 `.panel` 클래스를 쓰면 패드가 영원히 안 뜬다** —
>   클래스 이름 충돌을 확인하라
> - **합성 터치는 `click` 을 만들지 않는다.** DOM 버튼 메뉴는 터치로 넘어가지 않으므로,
>   메뉴 통과는 `click()` 으로, 패드 검증은 실제 터치 이벤트로 **나눠서** 테스트하라

1. **스모크 테스트**: 직접 열어 콘솔 에러 0·부팅·기본 조작 확인
   + **IP 스캔**: 서빙 파일에서 타사 게임 명칭 grep, `DESIGN.md` 를 `docs/specs/`
   로 이동 — **이때 문서 첫 줄에 인용 표기를 붙여라**:
   `<!-- source: portal-fe/public/games/<slug>/ -->`
   (없으면 Docs Health 의 L4-01 이 감점한다. 게임 문서가 쌓이면서 실제로 CI 가 빨개졌다)(벤치마크 서술은 서빙 경로에 남기지 않는다 — 2026-08-15 전수 점검 정책)
2. **platform.js 배선** (`portal-fe/public/games/lib/platform.js`):
   - index.html 게임 스크립트 앞에:
     ```html
     <script src="../lib/rank.js"></script>
     <script src="../lib/platform.js"></script>
     <script>PlatformAdapter.init({ slug: '<slug>', title: '<한글명>', saveKeys: ['<localStorage 키…>'] });</script>
     ```
   - 게임의 런/스테이지 종료 지점에 한 줄:
     `window.PlatformAdapter && PlatformAdapter.runEnd({ score, detail })`
   - 서버 세이브는 어댑터가 localStorage 가로채기로 자동 동기화
   - **모드가 둘 이상이면 보드를 나눈다** (V59). 같은 게임인데 재는 자가 다르면 —
     「그어서 막기」의 물/돌/벌, 「인피니티 타워」의 방어전(14분)/등반(층당 60~90초),
     「랜덤 카드 디펜스」의 혼자/협동/대전 — 한 표에 합치면 순위표가 실력이 아니라
     **점수가 잘 나오는 모드를 고른 사람** 순위가 된다:
     ```html
     PlatformAdapter.init({ …, boards: [{ key: 'leak', name: '물 막기', nameEn: 'Water' }, …] });
     ```
     `runEnd({ score, detail, board: '<키>' })` 로 어느 모드였는지 실어 보내고,
     **같은 키를 시드 마이그레이션의 `game.score_boards` 에도 넣는다** — 게임 안 탭은 위
     선언이 그리지만, 사이트(게임 밖 상세 페이지)는 iframe 안 선언을 읽을 수 없어
     카탈로그를 본다. 두 곳의 키가 어긋나면 **기록은 쌓이는데 사이트 탭에만 안 보인다**
   - ★ **배선했다고 끝이 아니다 — 한 판을 실제로 끝내 요청 본문을 눈으로 확인한다.**
     `fetch` 를 가로채 `POST /api/v1/games/<slug>/scores` 의 body 를 찍어 보고,
     `score > 0` 이고 `board` 가 그 모드 키인지 본다 (아래 실측 함정 참조)
   - ★ **정적 검사를 통과시킨다 — `python3 scripts/lint-game-mobile.py <slug> --strict`.**
     rank.js 순서·viewport·3부 한글 라벨·`data-fit` 충돌·가로 캔버스·조작 방식 선언을 잡는다.
     신작은 **경고 0** 이어야 한다(기존 게임의 소급은 후속 작업 큐라 기본 실행에서는 통과한다).
     같은 검사가 `.claude/hooks/game-mobile-check.sh` 로 게임 파일을 고칠 때마다 자동으로 돈다
3. **썸네일**: 전투 실플레이 320×180 캡처 → `thumbs/shots/<slug>.png`
   (반드시 업로드 서버 방식 — base64 를 대화로 통과시키지 않는다)
3-b. **SNS 공유 카드 (OG) — 필수**
   > 목록 썸네일 320×180 을 og:image 로 쓰면 안 된다. 큰 카드 최소치(600×315)에 한참
   > 못 미쳐 카카오톡·슬랙·X·페이스북에서 뭉개진 카드가 나온다.
   - **1200×630 전용 카드**를 `thumbs/og/<slug>.png` 로 만든다 — 실플레이 화면을
     16:9 로 잘라 넣고 하단 그라디언트 위에 **게임 한글명 + 한 줄 소개 + 브랜드**를 얹는다
   - 프리렌더가 이 파일의 존재를 보고 자동으로 큰 카드로 승격한다
     (`socialImage()` → `game.ogImageUrl`, 없으면 썸네일 + `summary` 로 폴백)
   - **게임 자체 `index.html` 에도 OG 를 넣는다** — 누군가 iframe URL 을 직접 공유해도
     카드가 나오게. 단 `og:url` 과 `<link rel=canonical>` 은 **포털의 게임 상세**
     (`https://game.1989v.com/games/<slug>`)를 가리켜 공유 지표가 한 URL 로 모이게 한다
   - 확인 항목: og:title / og:description / og:url / og:image(+secure_url·type·width·
     height·alt) / twitter:card=summary_large_image / canonical
4. **V시드**: `game/feature/src/main/resources/gamedb/migration/V{next}__seed_<slug>.sql`
   - V30 을 템플릿으로. 태그는 V25 생존 슬러그만 매핑(roguelike/leaderboard 등),
     장르는 genre 컬럼. title_en/description_en 필수(SEO). supports_mobile 은 키보드 전용이면 0
   - `./gradlew :game:feature:test --tests '*GameSchemaIntegrationSpec*' --rerun-tasks` 로 실 MySQL 검증
5. **game/CLAUDE.md** 정적 자산 표에 행 추가
6. **msa-games 푸시 + 본체 포인터 범프** — 서브모듈에서 커밋·푸시 후 msa 에서
   `git add portal-fe/public/games` (포인터) → 시드·문서와 함께 커밋
7. 커밋 → 푸시 → 배포 확인 → **portal-fe 재빌드**(`gh workflow run images -f services=portal-fe`)
   — 프리렌더/사이트맵은 빌드 시점 API 를 읽으므로 백엔드 반영 후 한 번 더 돌아야 잡힌다
