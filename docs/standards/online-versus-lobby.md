# 온라인 대전 게임 공통 로비 표준 — 기준은 아레나 (2026-09-15)

> **적용**: 사람과 붙는 온라인 대전 게임 전부. 방 만들기·참여·대기실·공유·이탈·결과 복귀는 **게임마다 다시
> 설계하지 않는다** — 이 문서가 정한 흐름과 문구를 그대로 구현한다. 기준선은 `arena`(AMP ARENA)의 로비이고,
> 여기에 적힌 것이 아레나와 다르면 **이 문서가 이긴다**(아레나도 뒤에 맞춘다).
>
> **클린룸 세션이 읽어도 되는 문서**다 — 온라인 대전 게임의 클린룸 마스터 프롬프트는 파이프라인 문서 셋에
> 이 문서를 더해 넷을 넘긴다. 아레나 폴더는 여전히 열지 않는다(이 문서가 그 대신이다).
>
> 근거: 사용자 결정(2026-09-15, 「사태」 확장 착수) — "온라인 대전 게임일 때 항상 동일하게 구현하도록
> 표준을 아레나 정도로 잡는다".

## 0. 한 줄

**빠른 대전 · 코드 방 · 공개 방 목록 · 코드 입장 · 초대 링크 — 다섯 진입로가 한 대기실로 모이고,
대기실에서 좌석·팀·병과(또는 스타일)·준비를 정하며, 방장이 시작하거나 30초가 시작한다.**

## 1. 화면 흐름

```
타이틀(닉네임) ─┬─ 연습(봇)                      → 매치 → 결과 → 타이틀
               └─ 온라인 ──┬─ 빠른 대전            → 대기실(자동 30초) → 매치 → 결과 → 로비(온라인 화면)
                           ├─ 코드 방 만들기        → 대기실(방장 시작) → 매치 → 결과 → 같은 대기실(한 판 더)
                           ├─ 코드로 입장 / 초대 링크 → 그 대기실
                           └─ 공개 방 목록에서 선택  → 그 대기실
```

- **닉네임**은 타이틀에서 정하고 `localStorage`(`game_nickname` — 플랫폼 순위표와 같은 키)에 둔다. 최대 16자.
  릴레이가 `MAX_NICK_LENGTH=16` 으로 자르므로 화면도 16 에서 막는다.
- **온라인 화면(로비)** 한 장에 진입로 넷이 모두 있다 — 빠른 대전(큰 버튼) · 코드 방 만들기(「공개 방으로」 체크 +
  만들기) · 코드로 입장(6자 입력) · 공개 방 목록(새로고침 버튼, 최대 20). 관전으로 참가 체크박스는 대전 인원이
  3 이상인 게임에만 둔다.
- **매치 중 입장은 없다**(릴레이 `ROOM_STARTED`). 결과 뒤 코드 방은 같은 대기실로 돌아오고(준비 상태 초기화),
  빠른 대전은 방을 나가 로비로 돌아온다.

## 2. 대기실

| 요소 | 규칙 |
|---|---|
| 좌석 | 릴레이가 준 `seats` 만큼 칸을 그린다. 빈 칸은 「빈 자리 → 봇」(봇이 채우는 게임) 또는 「빈 자리」. 닉네임 + 그 사람의 선택(병과·스킨·스타일 등)이 칸 안에 보인다 |
| 팀 | 팀전 게임은 좌석 번호로 갈라 **칸 테두리 색**으로만 팀을 표시한다(홍 `#A2231D` / 청 `#2B4B63`). 방장이 팀 배정을 바꿀 수 있으면 그 규칙을 게임 문서에 적는다 |
| 내 선택 | 병과·스킨(또는 스타일·악세서리)은 **대기실에서 고르고 매치 중 교체 불가**. 선택은 `move` 로 방에 방송해 남의 칸에도 보인다 |
| 방장 | **가장 낮은 점유 좌석**. 방장은 항상 「준비」로 친다. 방장이 나가면 다음 낮은 좌석이 방장이 된다 |
| 준비 | 방장·관전자 아닌 사람은 「준비 / 준비 해제」 토글. 시작 버튼에 `준비 N/M` 이 붙는다 |
| 시작 | 코드 방: 방장의 「게임 시작 · N명 (+ 봇 K)」. **준비 안 한 사람이 있으면 한 번은 막고 알리고, 그래도 누르면 시작한다**(AFK 로 방이 잠기면 안 된다). 빠른 대전: 「N초 뒤 자동 시작」 카운트다운(릴레이 30초), 가득 차면 즉시 |
| 코드 | 코드 방 헤더에 6자 코드(자간 넓게) + **「코드 복사」** + **「초대 링크 복사」**(§4) |
| 채팅 | 대기실 채팅 한 줄(120자, Enter 전송, `move` 의 `d.t='c'`). 시스템 줄(입장·퇴장·방장 승계)도 같은 로그에 |
| 나가기 | 「로비로」— `leave` 를 보내고 방을 비운다 |

## 3. 참여

- **빠른 대전**: `join{room:null, private:false}`. 릴레이가 같은 게임의 대기 방에 넣거나 새로 만든다. 3석 이상 방은 30초 뒤 인원 무관 시작(빈 좌석은 호스트 클라이언트가 봇으로 채운다).
- **코드 방 만들기**: `join{room:null, private:true, manualStart:true, listed:<공개 여부>}`. 응답 `joined` 의 `room` 이 코드, `token` 이 좌석 토큰(재접속용).
- **코드로 입장**: `join{room:<6자>, private:true}`. 입력은 대문자로 정규화, 혼동 문자(0/O·1/I)가 없는 알파벳이라 안내에 적는다.
- **공개 방 목록**: `{"t":"rooms"}` → `{"t":"rooms","rooms":[{code,n,cap,host}]}` (최대 20, 요청한 사람에게만). 행을 누르면 코드로 입장. 3초 안에 응답이 없으면 빈 목록으로 취급.
- **초대 링크**: §4.
- 오류 문구는 고정한다 — `ROOM_NOT_FOUND` 「그 코드의 방이 없습니다」 · `ROOM_FULL` 「방이 가득 찼습니다」 · `ROOM_STARTED` 「이미 시작한 방입니다」 · `ROOM_LIMIT` 「대전 서버가 붐빕니다. 잠시 뒤 다시」 · `ALREADY_JOINED` 「이미 방에 있습니다」 · `NOT_HOST` 「방장만 시작할 수 있습니다」 · `RATE_LIMIT` 「메시지가 너무 많아 끊겼습니다」 · `TOO_LARGE` 「메시지가 너무 커서 끊겼습니다」.

## 4. 공유 — 코드와 링크

- **코드 복사**: `navigator.clipboard.writeText(code)` → 토스트 「코드를 복사했습니다」. 실패하면 코드를 토스트로 보여 준다.
- **초대 링크**: `https://game.1989v.com/games/<slug>?room=<CODE>` — 게임 카탈로그 상세 주소에 `room` 하나. 「초대 링크 복사」 버튼 + 모바일에서 `navigator.share` 가 있으면 공유 시트(`{title:'<게임 이름> 초대', text:'코드 <CODE>', url}`).
- **링크로 들어오면**: 게임이 뜰 때 `?room=` 이 있으면 닉네임 확인 뒤 **바로 그 코드로 입장**(코드 입력 화면을 건너뛴다). 카탈로그 상세(IFRAME 호스트)는 `room` 을 iframe 주소로 그대로 넘긴다.
  (아레나에는 아직 링크가 없다 — 이 항목은 표준이 아레나보다 앞선 부분이고, 아레나도 맞춘다.)

## 5. 릴레이 프로토콜 (서버 변경 없이 쓰는 것 — `/ws/games/<slug>`)

raw WebSocket + JSON 한 줄. 릴레이는 `d` 를 열어보지 않는다(무권위). 규칙·봇·승계는 전부 클라이언트 몫.

| 방향 | 메시지 |
|---|---|
| C→S | `join{room, nick, seats(2~20), private?, manualStart?, listed?, spectate?}` · `move{d, to?}` · `start{cfg?}`(방장, manualStart 방) · `done`(라운드 끝, manualStart 방) · `rooms` · `leave` · `ping` |
| S→C | `joined{room, seat, seats, token?}` · `seat{seat, nick}`(3석↑ 입장 알림) · `start{seed, players[], round?, cfg?, token?}` · `move{seat, d}` · `left{seat}`(3석↑) / `opponentLeft`(2석) · `roundEnded{round}` · `rooms{rooms[]}` · `error{code}` · `ping`/`pong` |

- **상한**: 메시지 4,096자 · 초당 40개 — 넘으면 릴레이가 끊는다. 클라이언트가 먼저 센다(길이·빈도 카운터).
- **유휴**: 60초 무메시지면 릴레이가 `ping` 을 보낸다 → `pong` 으로 답한다. 90초면 끊긴다. 클라이언트는 20초마다 `ping` 을 보내 둔다.
- **시작**: 빠른 대전은 릴레이가 `start` 를 낸다(가득 차거나 30초). 코드 방은 방장이 `start` 를 보내면 릴레이가 시드를 뽑아 `cfg` 와 **한 메시지로** 돌려준다 — 시드를 방장이 정하지 못하게 하려는 것이므로 시드는 반드시 릴레이 것을 쓴다.
- **`players`** 는 좌석 수만큼의 닉네임 배열, 빈 좌석은 빈 문자열 → 호스트 클라이언트가 봇으로 채운다.
- **`to`**: 특정 좌석에게만 보내는 `move`(호스트 권위 게임의 게스트 의도). 락스텝 게임은 방 전체 방송이라 안 쓴다.
- **라운드**: 코드 방은 매치가 끝나면 방장이 `done` → `roundEnded{round}` 가 전원에게 → 같은 대기실. 다음 `start` 는 `round` 가 1 오른다.
- **방장 승계**: `left{seat}` 를 받으면 남은 가장 낮은 좌석이 방장. 게임 규칙(호스트 권위/락스텝)에 따라 상태 이전이 필요한지가 다르다 — 그 게임의 PRD 가 정한다.
- **관전**: `spectate:true` 로 들어오면 좌석 없이(`seat:-1`) 방송만 받는다. 대전 인원 3 이상인 게임만 UI 를 둔다.
- **2석 방은 「legacy」 프로토콜이다** — `seat` 입장 알림·30초 마감이 없고 이탈은 `opponentLeft` 로 온다(3석↑는 `left{seat}`). 그래서 **입장 직후 `move{d:{t:'hi', nick, pick}}` 로 스스로를 알린다**(아레나의 hi 핸드셰이크) — 대기실은 `seat` 가 아니라 `hi` 로 남의 칸을 채우면 2석·N석에서 같은 코드가 된다. `seats` 는 그 게임의 실제 최대 인원으로 만든다.

## 5-1. 동기화 모델 — 장르로 고른다

결정의 원본은 ADR-0088(last-one)이다. 거기서 한 게임에 내린 판정을 모든 온라인 게임의 기본값으로 쓴다. PRD 는 아래 표와 다른 쪽을 고를 때만 이유를 적는다.

| 모델 | 언제 | 오가는 것 | 반드시 둘 장치 |
|---|---|---|---|
| **결정적 락스텝** | 턴제 · 2~4인 · 유닛이 많아 상태를 보낼 수 없는 RTS | 입력만 방 전체에 방송 | 시드는 릴레이 것 하나. 시뮬은 시드 RNG 하나와 고정 dt로 돌고 렌더용 난수(흔들림·파티클)는 따로 둔다. **1초마다 상태 해시를 주고받고, 어긋나면 판을 멈추고 알린다** — 조용히 계속하면 두 사람이 서로 다른 판을 끝까지 한다 |
| **호스트 권위** | 실시간 · 5인 이상 · 모바일 | 게스트 → 호스트 의도(`to`), 호스트 → 전원 스냅샷 10Hz | **게스트는 자기 캐릭터를 입력 즉시 예측해 그리고**, 스냅샷이 오면 보정한다(차이가 작으면 몇 프레임 보간, 크면 맞춘다). 남의 개체는 스냅샷 사이를 보간한다. 스냅샷 왕복을 기다렸다 움직이면 지연이 그대로 손에 느껴진다 |
| 서버 권위 | 쓰지 않는다 | — | 무료 티어 노드 하나에서 동시 2~3판이 상한이고 규칙을 JVM 에 한 벌 더 짜야 한다(ADR-0088 C안) |

- 락스텝은 한 명의 지연이 전원의 입력 지연이 된다 — 인원이 늘면 호스트 권위로 간다(ADR-0088 B안 탈락 사유).
- **어느 쪽도 치트를 막지 않는다.** 릴레이는 내용을 보지 않고, 호스트 권위에서는 방장 클라이언트가 판정을 갖는다. 순위표는 신뢰 기반이다(ADR-0084) — 막지 않는다고 적어 둔 것이지 빠뜨린 것이 아니다.

## 6. 개발 릴레이 (클린룸 E2E 용)

클린룸 세션은 운영 릴레이에 붙지 않는다. 위 §5 표대로 동작하는 **Node 개발 릴레이**(`tools/dev-relay.mjs`, `ws` 의존 없이 Node 22 내장으로)를 게임 폴더에 두고, E2E 가 스스로 띄운다 — 두 탭(또는 헤드리스 페이지 둘)이 코드 방을 만들고 들어가 한 판을 끝까지 돌리는 것이 온라인 게이트다. 개발 릴레이는 §5 의 상한·유휴·오류 코드까지 흉내 낸다(느슨하게 만들면 운영에서만 끊긴다).

## 7. 완성 판정 (온라인 게이트)

| 항목 | 기준 |
|---|---|
| 진입로 다섯 | 빠른 대전 · 코드 방 · 코드 입장 · 공개 방 목록 · 초대 링크가 전부 같은 대기실에 닿는다 (E2E) |
| 대기실 | 좌석·팀·선택·준비·방장 시작·30초 자동·채팅·코드/링크 복사가 §2 문구 그대로 |
| 이탈·승계 | 방장 탭을 닫으면 2초 안에 다음 좌석이 방장이고 판이 이어진다 (E2E, `left` 기준) |
| 상한 | 한 판 동안 좌석당 메시지 ≤ 40/s · ≤ 4,096자 — 계측해 보고에 적는다 |
| 결과 복귀 | 코드 방 → 같은 대기실(준비 초기화), 빠른 대전 → 로비 |
| 모바일 | 대기실·로비가 세로 390×844·가로 844×390 에서 탭만으로 전부 된다, 누름 대상 ≥44px |
| 동기화 | 락스텝: E2E 가 한 탭의 시뮬 상태를 일부러 바꾸면 **2초 안에 양쪽이 어긋남을 알린다**(주입 없이 한 판을 끝까지 돌리면 경보 0). 호스트 권위: 릴레이에 지연 200ms 를 넣은 E2E 에서 게스트 입력 **다음 프레임**에 게스트 화면의 자기 캐릭터가 움직인다 |
| 순위표 | 사람과 붙은 판은 `board:'online'`, 봇 연습은 `'practice'` — 시드의 `score_boards` 와 글자 그대로 같아야 한다 |

## 8. 기준선 대조 — 아레나에 있는 것 / 이 표준이 더한 것

| 항목 | 아레나 | 이 표준 |
|---|---|---|
| 빠른 대전 · 코드 방 · 코드 입장 · 공개 방 목록 · 준비 · 방장 강행 · 채팅 · 관전 · 코드 복사 | 있음 | 그대로 |
| 초대 링크(`?room=`) · `navigator.share` | 없음 | **추가** — 아레나도 맞춘다 |
| 오류 문구 8종 | 있음 | 고정 문구로 승격 |
| 개발 릴레이 | `tools/e2e-*` 가 띄움 | 게임마다 `tools/dev-relay.mjs` 로 통일 |
