# 공개 콘텐츠의 한영 검색 발견성

사용자 요청(2026-10-15): 원하는 검색어와 실제 서비스 콘텐츠가 연결되도록 설계하고, 영어 검색도 지원한다. 게임 한 페이지의 키워드를 모든 서비스에 복제하는 규칙이 아니라, **공개 콘텐츠마다 검색 의도와 페이지를 연결하는 작업 방식**을 공통으로 적용한다.

## 페이지를 만들거나 고칠 때

1. 먼저 사용자 목적과 대표 URL을 정한다. 페이지마다 한국어·영어 목표 표현, 실제 제공 기능, 색인 여부, 콘텐츠 원본과 갱신일을 기록한다. 검색량 자료가 없으면 우선순위는 검색 의도 적합성에 따른 판단이라고 밝힌다.
2. 주 검색 의도를 title·주요 제목·소개·사용법·관련 링크에 자연스럽게 반영한다. 브랜드명만으로 기능 검색을 대신하지 않는다. 키워드를 반복하거나 관련 없는 인기 검색어·도박 기능·효과를 덧붙이지 않는다. `meta keywords` 추가를 해결책으로 삼지 않는다.
3. 검색용 메타, 초기 HTTP HTML, 실제 화면, 구조화 데이터는 같은 검증된 콘텐츠 원본을 쓴다. iframe/canvas 속 기능과 API 카탈로그만 바꾸고 공개 소개를 옛 상태로 남기지 않는다. 크롤러에게만 다른 본문을 주거나 화면 마운트 후 사라지는 허위 소개를 쓰지 않는다.
4. 영어는 title만 번역하지 않는다. 주요 소개·사용법·관련 링크도 영어로 제공한다. 직역보다 그 언어에서 실제 기능을 찾는 표현을 사용하고, 제공하지 않는 서비스로 오해할 용어는 문맥으로 바로잡는다. 검증 없이 번역을 완료했다고 쓰지 않는다.
5. 언어별 안정된 URL과 self-canonical을 제공한다. 번역된 페이지끼리 양방향 hreflang을 연결하고 실제 콘텐츠 언어를 `html lang`과 맞춘다. 한국어 canonical로 영어를 모두 합치거나, 없는 번역 URL을 hreflang에 넣지 않는다. 언어 전환은 실제 링크로 제공하며 위치·브라우저 언어로 강제 이동하지 않는다.
6. 공개 대표 페이지를 sitemap·관련 허브·탐색 링크에 연결한다. 내부 링크는 실행 가능한 `<a href>`로 제공한다. 동일 내용을 키워드만 바꿔 여러 주소로 양산하지 않는다. lastmod는 의미 있는 실제 콘텐츠 편집일이며 배포할 때마다 자동 갱신하지 않는다.
7. 공개 소개와 사적 상태를 구분한다. 게임 방·참가자·계정·관리·초대 코드·개인 검색 결과는 소개 페이지를 색인한다고 함께 공개하지 않는다. 기존 noindex의 목적부터 확인한다. `noindex`는 접근 제어 수단이 아니다.
8. JSON-LD는 화면에서 확인할 수 있는 사실만 표현한다. 허위 평점·리뷰·FAQ·검색 결과 모양을 만들지 않는다. 구조화 데이터 추가만으로 순위나 리치 결과를 보장하지 않는다.

## 제목과 소개의 고유성

- `무료 온라인 플레이`·`Play Free Online` 같은 사실에 맞는 수식어 자체를 SEO 오류나 제재 사유로 단정하지 않는다. 다만 모든 상세에 긴 공통 문구를 붙이기보다, 실제 이름과 종류·차이를 앞세운다. 무료 여부와 설치 없이 실행되는 조건은 허브·소개에서 명확하게 설명한다.
- 동명 게임은 소스로 확인한 장르나 플레이 차이로 구분하고, 동명 관광지는 확인된 지역을 함께 쓴다. 메타만 다른 상품처럼 꾸미지 말고 주요 제목·소개와 의미를 맞춘다. 이미 이름에 포함된 지역을 기계적으로 중복하지 않는다.
- 게임 소개의 목표·조작법·팁은 해당 게임의 현재 코드나 실제 설명을 근거로 작성한다. 장르만 보고 키보드·터치 지원이나 승리 조건을 추정하지 않는다. 영어도 같은 확인된 사실을 사용한다. 글자 수를 늘리기 위한 일반 설명을 각 페이지에 반복하지 않는다.
- 옛 경로와 중복 호스트는 대표 주소로 서버 영구 리다이렉트를 검토한다. canonical만 선언한 HTTP 200이나 JS 이동과 구분하고 언어·쿼리·실제 자산·비공개 화면 정책을 확인한다.
- 관광지의 언어별 원천 ID는 서로 다를 수 있다. 기존 검증된 일대일 매칭을 사용하고, 지역·유사한 이름만으로 번역 관계를 만들지 않는다. 연결 확대보다 오연결 방지를 우선하며 연결 불가 사유를 보고한다.

## 서비스별 적용 방향

| 콘텐츠 | 대표 검색 의도와 보강할 실제 내용 |
| --- | --- |
| 게임·추첨 | 게임 종류, 용도, 규칙, 조작, 기기 지원. 게임명·기능과 현재 코스·모드·초대를 일치시킨다. |
| 관광지·지역 | 장소 이름과 실제 지역·주소·접근·운영 정보. 데이터 근거와 갱신 상태를 명시하고, 확인되지 않은 시설이나 이용 조건을 만들지 않는다. |
| 블로그·가이드 | 글에서 해결하는 질문, 직접 다룬 내용과 근거, 실제 편집일. 요약만 바꾸고 오래된 본문을 유지하지 않는다. |
| 랭킹·리더보드 | 무엇을 어떤 기준·기간으로 정렬했는지와 실제 데이터. 점수나 추천 근거를 부풀리지 않는다. |
| 상품·혜택 | 실제 상품·제공처·조건·유효성·제휴 고지. 빈 카테고리·만료 조건·얇은 중복 페이지의 색인 여부를 검토한다. |
| 기술 사전·포트폴리오 | 개념·구현 문제·실제 결과·증거 링크. 과장된 성능·경험·번역만 있는 빈 페이지를 만들지 않는다. |
| 로그인·관리·개인 기록·내부 API | 공개 검색 유입 대상인지부터 판단한다. 검색 최적화를 이유로 사적 화면을 색인하지 않는다. |

이번 적용은 랜덤레이스와 구슬 레이스부터 시작한다. 다른 기존 콘텐츠의 일괄 교정이나 순위 검증을 완료했다는 뜻은 아니다. 이후 각 서비스의 공개 콘텐츠 수정·추가 시 이 기준으로 적용 범위를 기록하고, 기존 서비스 점검은 위 표의 공개 대표 페이지부터 진행한다.

## 완료 판단과 배포 후 확인

- HTTP 200·HTML title/description/본문·canonical·lang·양방향 hreflang·robots/noindex·사이트맵을 초기 응답에서 확인한다. SPA의 JS 실행 후 head만 확인하고 완료하지 않는다.
- 실제 화면과 초기 HTML이 같은 최신 소개를 사용하는지, 다른 콘텐츠의 fallback과 비공개 화면이 유지되는지 focused test로 검증한다. 소개만 바뀐 작업에 무관한 게임 물리 전수검사를 반복하지 않는다.
- 서버 HTTP 검사와 실제 브라우저 검증은 구분해 기록한다. 브라우저 검증은 사용자 승인이 있는 범위에서만 한다.
- 배포 확인, 검색엔진 수집, 색인, 검색어 노출, 클릭/전환을 서로 다른 단계로 보고한다. `site:` 검색이나 한 번의 첫 페이지 미발견만으로 전체 미색인·노출 0을 단정하지 않는다.
- 계정 접근이 가능할 때 Google Search Console·네이버 서치어드바이저에서 sitemap 제출 상태와 대표 URL 수집/색인을 검사한다. 실제 수행한 제출과 미수행 작업을 구분한다.
- 노출/클릭/평균순위는 검색어 묶음·목표 URL·언어/국가·기기별로 동일 기간을 비교한다. 영어 번역을 배포했다는 이유만으로 영어 유입이 생겼다고 보고하지 않는다. 순위 상승·색인 완료 시점을 보장하지 않는다.

## 랜덤레이스 적용 사례

한국어 `핀볼 추첨`, `핀볼 내기`는 구슬 레이스 상세를, `내기 게임`은 랜덤레이스 허브를 대표로 한다. `핀볼게임/핀볼 게임`, `핀볼`은 일반 플리퍼 게임·게임기 등의 검색 의도도 섞이므로 실제 추첨 방식과 사용법을 설명한다. 영문은 `pinball random picker`, `pinball raffle`, `pinball draw`, `online pinball game`, `friendly bets`, `party decision games`를 용도에 맞춰 쓴다. `betting`은 친구끼리 커피 살 사람을 정하는 문맥이며 현금 베팅·배당 서비스로 홍보하지 않는다.

구체적인 변경·미완료 계정 작업은 [구현 계획](../plans/2026-10-15-multilingual-game-discovery.md)과 해당 작업의 검증 기록에 남긴다.
