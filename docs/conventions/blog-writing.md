# 블로그 글 작성 규칙

`blog.1989v.com` 에 올리는 글의 문체·구조 기준. 검증은 `scripts/lint-blog-post.py` 가 한다.

## 1. 목적

블로그 글은 **정보 전달물**이지 에세이도 작업 일지도 아니다. 읽는 사람은 답을 찾으러 왔고, 대개
검색 결과에서 바로 들어와 필요한 줄만 보고 나간다. 스크롤 없이 답이 잡히는 밀도가 먼저다.

읽는 사람이 이미 아는 것을 설명하는 문장, 독자의 생각을 대신 서술하는 문장, 던졌다가 스스로 답하는
질문은 전부 답에 도달하는 시간을 늘린다.

## 1.1 무엇을 담고 무엇을 빼나 (필수)

**담는 것 — 그것이 무엇이고 어떻게 쓰는가.**

| 담는다 | 예 |
|---|---|
| 결과물의 동작 | 강조색은 페이지에서 가장 많이 쓰인 유채색이다 |
| 쓰는 법 | 코드 블록, 명령, 설정 |
| 규칙과 한계 | id 에 하이픈은 못 쓴다 |
| 주장을 받치는 실측값 | 대비 15/255, gzip 16.6 KB |

**빼는 것 — 어떻게 그렇게 됐는가.**

| 뺀다 | 왜 |
|---|---|
| 판올림 이력 (`0.3.2 에서는…`) | 릴리스 노트의 몫이다 |
| 시도와 실패 (`처음에는 …했는데 무너졌다`) | 커밋 메시지의 몫이다 |
| 의사결정 서술 (`…하기로 했다`, `고민 끝에`) | ADR 의 몫이다 |
| 작업 경위 (`재 봤다`, `검토했다`) | 옵시디언 작업 노트의 몫이다 |

옵시디언 노트를 그대로 옮기면 이 네 가지가 딸려 온다. **소개 글에 배경과 판단이 들어가면
독자는 기능을 알러 왔다가 남의 일지를 읽는다.**

설계 이유가 정보로서 필요할 때는 **결과 문장 뒤 한 줄**로 붙인다. 서사로 풀지 않는다.

- 나쁨: `첫 판은 링크 색을 봤다. 그게 무너져서 채도로 바꿨더니 장식 점이 이겼다. 그래서 사용량으로 골랐다.`
- 좋음: `강조색은 가장 많이 쓰인 유채색이다. 채도로 고르면 3px 장식 점이 페이지를 지배하는 색을 이긴다.`

## 2. 문체

**필수**

| 규칙 | 이유 |
|---|---|
| 한 문장 100자 이하 | 긴 문장은 조건이 여러 개 붙어 있다는 뜻이다. 쪼개면 표가 된다 |
| 한 문단 3문장 이하 (리드는 2문장) | 문단이 길면 스캔이 안 된다 |
| 산문에 물음표 금지 | 자문자답은 답을 한 박자 늦춘다. 질문은 h2 제목으로 |
| 1인칭·권유형 금지 | `필자` · `저는` · `살펴보자` · `정리해 보자` |
| 수사 도입어 금지 | `사실은` · `흥미롭게도` · `말하자면` · `한마디로` · `결론부터 말하면` |
| 독자의 생각 대신 서술 금지 | `먼저 떠오른다` · `헛짚기 쉽다` — 독자가 뭘 생각했는지는 알 수 없다 |
| 감상 표현 금지 | `놀랍게도` · `아쉽게도` · `다행히` |
| **기술 용어는 굳어진 표기로** | `질의 이해` 아니라 `쿼리 언더스탠딩`, `재순위` 아니라 `리랭킹`. 번역어는 검색이 안 된다 |

**권장**

- 평균 문장 60자 이하.
- 값·조건·비교는 산문 대신 **표**로. 절차는 **번호 목록**으로.
- 산문 줄이 전체 내용 줄의 55% 를 넘으면 옮길 것이 남아 있다는 신호다.
- 단정형(`~다`)으로 끝낸다. 추측이면 `(추정)` 을 붙이고, 안 붙일 거면 쓰지 않는다.

### 2.0.1 기술 용어 표기

**현업에서 영어로 말하는 용어는 발음대로 적는다.** 직접 번역한 조어는 쓰지 않는다 —
읽는 사람이 아는 말과 글의 말이 달라지고, 그 용어로 더 찾아볼 수도 없다.

| 쓰지 않는다 | 쓴다 |
|---|---|
| 질의 이해 | 쿼리 언더스탠딩 |
| 질의 (= query) | 쿼리 |
| 재순위 | 리랭킹 · 리랭커 |
| 희소 / 밀집 검색 | 스파스 / 덴스 검색 |
| 불용어 | 스톱워드 |

**한국어가 이미 업계 표준인 말은 그대로 둔다** — 색인 · 형태소 분석기 · 사전 · 융합 · 임베딩.
판단 기준은 「현업에서 말할 때 어느 쪽으로 발음하나」다. 확신이 안 서면 번역하지 말고 원어를 병기한다.

## 2.1 제목

**검색어가 되는 관용 용어를 앞에, 이 글만의 훅을 뒤에.** 아무도 제품 이름이나 우리끼리의 말로
검색하지 않는다.

| 나쁨 | 좋음 | 왜 |
|---|---|---|
| `fencesvg — 마크다운 펜스를 …` | `mermaid 없이 마크다운 다이어그램 그리기 — … (fencesvg)` | fencesvg 는 검색어가 아니고 mermaid 는 검색어다 |
| `JVM 논힙 메모리가 …` | `힙은 정상인데 컨테이너가 OOMKilled 될 때 — … MALLOC_ARENA_MAX` | 논힙은 비표준어, OOMKilled·MALLOC_ARENA_MAX 는 사람이 치는 말이다 |
| `세션 계측 표시 — 설정 키가 …` | `Claude Code statusLine 으로 … — showMessageTimestamps 가 안 켜지는 이유` | 공식 설정 키 이름이 곧 검색어다 |

**slug 은 바꾸지 않는다.** URL 이라 바꾸면 색인과 기존 링크가 끊긴다. 제목·요약만 고친다.

## 3. 구조

1. **리드 2문장 이하** — 무엇을 다루는 글인지 + 기준 버전/시점.
   frontmatter 의 `summary` 는 **카드와 글 상단에 인용문 스타일로 같이** 나간다. 본문에 요약을
   또 적지 않는다 — 한 글에 요약은 하나고, `summary` 가 그것이다.
2. **요약 표** — 결론을 먼저. 목차가 아니라 답을 담는다. **첫 h2 앞에 와야 한다(F8).**
3. **본문** — h2 하나가 하나의 답. 코드·표·목록이 골격이고 산문은 접착제다.
   **코드 이야기면 코드 블록을 낸다** — 설명 문단 세 개보다 여덟 줄짜리 블록이 빠르다.
   블록에는 언어를 표시한다(` ```ts `). `<pre><code>` 로 렌더되고 가로 스크롤이 걸린다.
4. **검증** — 재현 명령과 실측값. 안 재본 것은 쓰지 않는다.

버전·날짜에 의존하는 값은 **기준을 본문에 밝힌다** (`v2.1.241 기준`). frontmatter 의 날짜는 발행일이지
데이터 시점이 아니다.

**목차를 본문에 적지 않는다.** 화면이 h2·h3 에서 접힌 목차를 만들고, 제목마다 그 절을 가리키는
링크를 단다. 손으로 적은 목록은 제목을 고칠 때마다 어긋나고, 자동 목차와 나란히 두 벌이 된다.
공유용 절 주소도 화면이 준다 — 제목 옆 `#` 이 `…/posts/{slug}#{제목}` 을 복사한다.

## 4. 검증 (`scripts/lint-blog-post.py`)

발행 전 초안을 통과시킨다. **본문의 원본은 DB 라서 빌드가 잡을 수 없다** — DB 에 넣기 전 이 단계가
유일한 게이트다.

```bash
scripts/lint-blog-post.py draft.md            # FAIL 있으면 exit 1
scripts/lint-blog-post.py draft.md --strict   # WARN 도 실패로
```

| 코드 | 검사 |
|---|---|
| F1 | front-matter 4필드 + DB 컬럼 상한 (title 200 / slug 80 / summary 300) + slug 형식 |
| F2 | 한 문장 100자 이하 |
| F3 | 한 문단 3문장 이하 |
| F4 | 리드 문단 2문장 이하 |
| F5 | 산문에 물음표 없음 |
| F6 | 금칙 표현 없음 (§2 표) |
| F7 | 이력·의사결정 서술 없음 (§1.1 표) |
| F8 | 첫 h2 앞에 요약 표(또는 항목 2개 이상 목록) |
| W1 | 평균 문장 60자 이하 |
| W2 | 산문 줄 비율 55% 이하 |
| W3 | h2 구간당 산문 8문장 이하 |
| W4 | h2 구간마다 표·코드·목록 중 하나 (산문만 6줄 넘으면 경고) |

코드 블록 · 표 · 인용 · 목록은 산문에서 제외한다. 규칙은 산문에만 건다.
줄 첫머리가 태그인 **raw HTML 블록(다이어그램 SVG)도 제외**한다 — 빈 줄에서 끝난다.
그림 아래 캡션 줄은 산문이라 규칙이 그대로 걸린다 → `blog-diagram.md`.

## 5. 초안 형식

lint 가 읽는 front-matter 는 DB 컬럼과 1:1 이다. 그대로 `blog_post` 에 넣는다.

```markdown
---
title: Claude Code 세션에 시각과 남은 사용량 표시하기
slug: claude-code-session-timestamp-and-usage
category: /harness
summary: 한 화면에 결론이 담기는 두세 문장. 검색 결과의 설명문으로도 쓰인다.
---

본문 …
```

`category` 는 `blog_category.path` 다. 없는 path 를 쓰면 INSERT 가 FK 로 막힌다.

## 6. DB 에 넣을 때

한글은 **hex 로 넣는다.**

```sql
INSERT INTO blog_post (..., title, body) VALUES (..., CONVERT(0x<hex> USING utf8mb4), ...)
```

`oci-mysql` 경유 접속의 클라이언트 charset 이 latin1 이라, 한글을 리터럴로 넣으면 조용히
이중 인코딩된다 (2026-08-24 실제 발생). 값은 들어가고 에러도 없으며, 목록 API 응답에서야 깨져 보인다.

## 6.1 본문에서 쓸 수 있는 표현 수단

산문·표·코드 말고도 렌더가 받는 것이 있다. sanitizer 는 `<style>` 태그만 지우고
`class` · `style` · `data-*` · `<span>` · `<div>` · `<details>` · `<kbd>` · `<mark>` ·
인라인 `<svg>` 는 통과시킨다 (`portal-fe/src/pages/blog/markdown.ts`).

| 수단 | 문법 | 쓰임 |
|---|---|---|
| 콜아웃 5종 | `> [!NOTE]` `[!TIP]` `[!IMPORTANT]` `[!WARNING]` `[!CAUTION]` | 함정·전제·경고. 제목은 표식 뒤에 적는다 |
| 상태 알약 | `<span class="pill p-green">안전</span>` | 표 안의 판정값. `p-green` · `p-amber` · `p-red` · 클래스 없으면 회색 |
| 코드 블록 | ` ```bash ` 처럼 **언어를 적는다** | 하이라이트 + 오른쪽 위 언어 라벨 |
| 다이어그램 | ` ```mermaid ` 펜스 + `%% caption:` | `fencesvg` 가 그린다 → `blog-diagram.md` |
| 접기 | `<details><summary>…` | 곁가지. 본문 흐름에서 뺄 것 |

좁은 화면(≤48rem)에서 **3열 이상 표는 셀을 접지 않고 옆으로 민다.** 그대로 두면 열 셋이 351px 을
두고 경쟁해 브라우저가 열을 min-content 까지 짓누르고, 짧은 라벨이 세 줄로 쪼개진다. 표 오른쪽 위의
`펴서 보기` 를 누르면 그 표만 행 단위 블록으로 펴진다 — 열 이름은 렌더러가 칸마다 `data-label` 로
박아 둔다(CSS 는 다른 칸의 글자를 못 읽는다).

**한 열을 아래로 훑는 표는 기본(표 모양)이, 한 행 안의 값을 한 덩어리로 봐야 하는 표는 편 쪽이
빠르다** — 어느 쪽이 필요한지는 글이 아니라 읽는 사람이 안다. 두 열짜리 표는 이미 라벨:값 모양이라
대상이 아니다.

**함정 서술은 산문 대신 콜아웃으로 낸다.** 평문 문단에 섞으면 스캔에서 묻히고, 콜아웃은
인용 줄로 세어져 W2(산문 비율)도 같이 내려간다.

**코드 블록에는 언어를 적는다.** 등록된 언어는 `bash` · `json` · `python` · `typescript` ·
`javascript` · `yaml` · `markdown` · `java` · `css` · `sql` · `kotlin` 이고, 약칭(`ts` · `py` ·
`sh` · `yml` · `md` · `kt` · `jsx` · `tsx`)은 자동으로 정규화된다. **없는 언어를 적어도 글은 안 깨진다**
— 하이라이트 없이 평문으로 나간다. 자주 쓰게 되면 `portal-fe/src/pages/blog/highlight.ts` 에 한 줄
추가한다(쓰지도 않는 190여 개 언어를 통째로 싣지 않으려고 목록을 손으로 관리한다).

코드 판은 **라이트 정경에서도 어둡다.** 한지 위의 먹이고, 본문과 재료가 갈려야 코드가 코드로
읽힌다. 판이 늘 어두우므로 구문 색은 한 벌이면 되고, 색은 브랜드 4색(소나무·황토·연지·청자)에서
섞어 낸다 — 코드 전용 원색을 새로 만들지 않는다.

**알약은 판정값에만 쓴다.** 안전/주의/위험처럼 셋을 나란히 놓는 열이 대상이고, 강조하고
싶은 낱말에 쓰면 지면이 알록달록해져 정작 판정이 안 보인다.

## 7. 본문 세로 리듬 (렌더)

문체가 아무리 촘촘해도 블록이 붙어 있으면 읽기가 막힌다. 본문 스타일은
`portal-fe/src/pages/blog/Blog.css` 의 `.blog-body` 이고, 간격은 **20px 하나로 통일**한다.

| 대상 | 값 | 토큰 |
|---|---|---|
| 산문 열 | **52rem (832px)** | `--blog-column` — 한글 59자/줄 |
| 표 · 코드 블록 (넓은 화면) | **64rem (1024px)** | 산문 열 밖으로 나간다 |
| 본문 | 1.02rem / 1.75 | |
| **h2** | **1.9rem** (본문의 1.86배) + 아래 괘선 | |
| h3 | 1.3rem | |
| 코드 블록 | 0.84em (13.7px) / 1.6 · 먹판 + 황토 좌선 | 본문과 크기·재료가 갈려야 코드로 읽힌다 |
| 인라인 코드 | 0.88em + `--ko-surface-2` 면 | 글꼴만 바꾸면 산문에 묻힌다 |
| 문단 · 표 · 코드 블록 · 목록 · 인용 · 콜아웃 | 20px | `--ko-space-5` |
| **h2 위 (절 경계)** | **128px** | `calc(var(--ko-space-16) * 2)` |
| h2 아래 (제목 → 본문) | 16px | `--ko-space-4` |
| h3 위 | 40px | `--ko-space-10` |
| h4 위 | 32px | `--ko-space-8` |
| 목록 항목 사이 | 4px | `--ko-space-1` |

**제목은 위를 크게, 아래를 작게 둔다.** 위아래가 비슷하면 제목이 어느 절에 속하는지 흐려진다.
h2 위 128px 은 본문 블록 간격(20px)의 여섯 배라, 스크롤 중에도 절이 바뀐 것이 눈에 걸린다.

> [!warning] 새 블록 요소는 margin 을 직접 적어야 한다
> 전역 리셋이 `* { margin: 0 }` 이라 **UA 기본 여백이 하나도 오지 않는다.**
> `.blog-body` 에 규칙이 없는 요소는 앞뒤 문단에 그대로 달라붙는다.
> 실제로 **표와 코드 블록이 위아래 `0px`** 이었고, 표 바로 뒤 문단과의 실간격도 `0px` 였다.

값을 바꾸면 계산값으로 확인한다. 눈으로 봤다는 근거로 쓰지 않는다
(`docs/standards/fe-visual-verification.md`).

```js
getComputedStyle(document.querySelector('.blog-body table')).marginTop
```
