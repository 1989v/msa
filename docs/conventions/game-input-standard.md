# 게임 입력 표준 (플랫폼 공통)

> 모든 캔버스 게임은 같은 버튼 문법을 쓴다. 구현체는 `portal-fe/public/games/lib/keys.js`
> (`GameKeys`) — 손잡이 선택은 `localStorage('game_input_layout')` 로 **전 게임 공유**되고,
> 좌하단 배지로 언제든 전환한다. (2026-08-15 사용자 피드백로 제정)

## 표준 레이아웃 (좌/우 손잡이 2종 고정)

| 액션 | 오른손잡이(기본) | 왼손잡이 |
|---|---|---|
| 이동 | 방향키 | WASD |
| 액션1 — 주공격 / (메뉴 보조결정) | C | L |
| 액션2 — 점프 / **메뉴 결정** | X | K |
| 액션3 — 대시/특수 | Z | J |
| 보조1/보조2 — 무기 전환 등 | A / S | U / I |
| **일시정지/메뉴** | Enter (공통) | Enter (공통) |
| **뒤로/취소** | Esc (공통) | Esc (공통) |

> 2026-08-16 재배치: 공격/점프/대시 = C/X/Z (왼손 L/K/J) — 물리 키 집합은 유지, 시맨틱만
> 재배치라 레거시 remap 프로필은 무수정 자동 추종.

- 메뉴/일시정지 키는 레이아웃과 무관하게 모든 게임에서 동일하다 (Enter/Esc).
- 게임 내 도움말·힌트 문구는 `GameKeys.labels()` 로 현재 레이아웃의 키 이름을 표기한다.
- 2인: 온라인 2P(릴레이) 게임은 각자 기기에서 위 표준을 그대로 쓴다. 로컬 동시 2인 게임을
  만들 경우 P1=왼손 레이아웃 고정, P2=오른손 레이아웃 고정.

## 적용 방법

- **신규/개편 게임**: `<script src="../lib/keys.js">` 로드 후 `GameKeys.keys()` 로 물리 키를
  받아 자체 입력 매핑을 구성하고 `GameKeys.onChange()` 로 전환에 반응한다.
  레퍼런스: `nova-strike/js/input.js`.
- **레거시 게임(코드 무수정)**: `GameKeys.remap({ left:'ArrowLeft', a1:'Space', pause:'KeyP', ... })`
  — 표준 키 입력을 게임이 원래 듣는 키로 변환 재디스패치한다. 게임별 remap 프로필 한 줄만
  추가하면 된다.
- 모바일(`lib/touch.js`)은 KeyboardEvent 를 합성하므로 remap/매핑 위에 자동으로 얹힌다.
- **`data-stick="off"` 는 게임이 터치 입력을 자체로 가진 경우에만 쓴다** — 캔버스 히트테스트나
  스와이프가 있어야 한다. 입력이 keydown 뿐인 게임에서 끄면 터치 기기에서 시작만 되고 조작이
  안 된다. 끄기 전에 해당 게임에 `click`/`touch*`/`pointerdown` 핸들러가 실제로 있는지 확인한다.
- 조이스틱 베이스는 **쉬는 동안에도 반투명하게 보인다**. 짚어야 나타나는 방식은 조작부가 있다는
  사실 자체를 숨겨 "화면 아래가 그냥 비어 있다"로 읽힌다.

## 가상패드 액션 버튼 표준 (2026-08-24 제정 — 사용자 피드백)

> 구현체: `lib/touch.js` `placeActions()`. 이전의 "4개 이상 부채꼴" 배치는 폐기 —
> 반경·각도가 버튼 수를 따라 변해 게임마다 자리가 달랐고, 곡선 위의 버튼은 엄지가
> 자리를 외울 수 없었다.

### 고정 슬롯 — 전 게임 동일

```
        [보조1][보조2]
        [액션2]
   [액션3][주액션]      ← 우하단 코너 앵커
```

| 슬롯 | 크기 | data-actions 순번 | 용도 |
|---|---|---|---|
| 주 액션 | 76px · 코너 | **1번째** | 가장 자주 누르는 것(주공격). 밝은 테두리로 구분 |
| 액션2 | 62px · 주액션 위 | 2번째 | 점프/결정 |
| 액션3 | 62px · 주액션 왼쪽 | 3번째 | 대시/특수 |
| 보조1·2 | 54px · 윗줄 왼쪽 | 4·5번째 | 무기 전환 등 저빈도 |

- **`data-actions` 순서가 곧 자리다.** 키보드 표준(액션1=C/액션2=X/액션3=Z/보조=A·S)과 같은
  의미 순서로 적는다 — 어느 게임을 열어도 주공격은 코너에, 점프는 그 위에 있다.
- **버튼 상한 5개.** 6개가 필요하면 배치가 아니라 조작 설계를 다시 한다.

### 라벨 — 아이콘만으로는 안 읽힌다

- 문법: `code:아이콘:라벨` (예: `KeyZ:⚔:공격`). 라벨은 **한글 1~3자**, 아이콘 아래 작게 표기된다.
- 신규/개편 게임은 라벨 필수. `⚔✦🔮` 만 있는 버튼은 첫 판에서 도박이 된다.
- 2부 문법(`code:아이콘`)은 하위 호환으로 유지되지만 게임을 손댈 때 3부로 올린다.

## 화면비 — 캔버스는 절대 늘리지 않는다

- 캔버스 스케일은 **비율 유지 + 레터박스**만 허용. `width:100%;height:100%` 류 스트레치
  금지 — **전체화면(호스트가 가로 잠금을 건다)에서 비율이 깨지는 게임의 공통 원인**이다.
- 게임이 직접 스케일하면 `min(availW/cw, availH/ch)` 한 배율로 양축을 같이 줄인다.
  `touch.js` 의 `fitCanvas` 가 이 규칙의 구현체다 — 게임 자체 스케일 코드와 fitCanvas 가
  **각자 style.width 를 쓰면 서로 싸운다. 둘 중 하나만 쓴다** (자체 스케일을 쓰면
  `data-fit="0"` + `GameTouch.on('layout')` 로 패드 높이를 반영).
- 방향(orientation)을 가정하지 않는다 — 매 layout 에서 `v.w > v.h` 를 다시 읽는다.

## 모바일 편의성 체크리스트 (게임 통합·개편 시 전수 확인)

- [ ] 메뉴·결과·선택지의 모든 상호작용이 **DOM 버튼 탭**으로 가능하다 (키보드 전용 진입 금지)
- [ ] 플레이 중 상시 노출되는 HUD 에 `.panel` 클래스가 없다 (있으면 패드가 영영 숨는다)
- [ ] 세로↔가로 회전 시 레이아웃이 스스로 복구된다 (`GameTouch.on('layout')`)
- [ ] 캔버스 좌표 상호작용(건설 배치·조준 등)은 **터치 탭/드래그**로도 같은 일이 된다
- [ ] 텍스트 입력은 DOM input 으로 받는다 (캔버스 가짜 입력창 금지)
- [ ] 랭킹은 `lib/rank.js` 공통 레이어만 쓴다 — **게임 자체 이니셜/닉네임 입력 UI 금지**
  (aero-vendetta 실측: 아케이드식 3자 이니셜 입력이 공통 닉네임 랭킹과 이중이 됐다)

## 모바일 화면 배치 (기기 크기 무관 규칙)

| 상황 | 게임 화면 | 조작부 |
|---|---|---|
| 세로 (일반 폰) | 폭 100%, 세로는 비율이 정한다. **위로 붙인다** | 화면 하단 |
| 가로 | 남는 쪽 기준으로 최대 — 보통 높이 100% | 화면 하단에 오버레이 |
| 폴드 내부(정사각에 가까움) | 세로와 같은 규칙 — 폭 100%, 상단 | 화면 하단 |

- 판정은 `v.w > v.h` (가로) 하나뿐이다. **기기 이름이나 폭 구간으로 분기하지 않는다** — 폴드는
  펴면 673×841, 접으면 344×882 로 둘 다 세로 규칙이 그대로 맞는다.
- 세로에서 캔버스를 가운데 두지 않는다. 캔버스는 폭에 묶여 있어(세로는 비율이 정한다) 가운데
  정렬하면 위아래 양쪽에 빈 띠가 생긴다. 위로 붙이면 죽는 공간이 캔버스와 조작부 사이 한 곳으로
  모이고, 가로에서는 캔버스가 그만큼 더 커진다.
- 조작부는 **보이는 뷰포트** 기준으로 놓인다. iframe 안에서는 주소창의 존재를 알 수 없으므로
  호스트(`useStageFit`)가 상자 높이를 재서 준다. **`innerHeight` 와 `visualViewport.height`
  중 작은 쪽**을 쓴다 — 어느 한 값도 혼자서는 보이는 높이가 아니다. 갤럭시 S23 울트라 실측:
  삼성인터넷 30 은 `visualViewport` 가 크롬을 반영하지 않아 화면 전체(882)를 돌려주고
  `innerHeight`(702)가 맞다. 카톡 WebView·크롬 안드로이드는 반대다.
- **`.panel` 은 메뉴/결과 오버레이 전용 클래스다.** `touch.js` 가 이 클래스를 "메뉴 열림"으로
  읽어 조작부를 숨긴다. 상시 표시되는 HUD 카드에 쓰면 조작부가 영영 안 나온다 (deadline 사례).
  카드 표면 스타일이 필요하면 다른 이름을 쓰고, 진짜 메뉴에는 `.panel` 을 붙인다.
- **게임이 캔버스를 직접 스케일하면** 가용 높이에서 `--vt-pad-h` 를 빼고, `GameTouch.on('layout')`
  로 다시 맞춘다. 안 그러면 조작부 띠와 겹치거나(nova-strike) 화면 밖으로 나간다.
