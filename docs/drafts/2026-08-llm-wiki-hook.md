Claude Code 의 `Stop` 훅으로 세션 기록을 LLM Wiki 에 강제하는 구조다. v2.1.246 · 2026-08-26 로컬 실측 기준.

| 문제 | 해법 |
|---|---|
| 부르는 걸 잊으면 세션이 통째로 사라진다 | 프롬프트에 의도, `Stop` 훅에 강제를 나눠 얹는다 |
| "세션 종료" 이벤트가 없다 | 매 턴 도는 `Stop` 에서 종료를 **추론**한다 |
| 사용량이 훅 payload 에 없다 | `statusLine` 이 캐시 파일로 흘려 주고 훅이 읽는다 |
| 마일스톤마다 새 문서가 생긴다 | transcript 에서 **실존하는** 위키 경로만 인정해 재사용한다 |
| 통과가 곧 침묵이라 죽어도 모른다 | 게이트마다 판정 로그를 남긴다 |

## 프롬프트만으로는 새는 구멍이 있다

`CLAUDE.md` 에 "세션 끝나면 위키에 정리해라"를 넣는 것만으로는 두 경우를 못 잡는다.

- 세션이 조용히 닫히면(창 닫기 · `/clear` · 컨텍스트 소진) 그 규칙을 읽을 턴이 없다.
- 규칙은 모델 판단에 걸려 있어 긴 세션 끝에서 가장 먼저 탈락한다.

훅이 트리거를 감지해 `decision:"block"` 을 내보내면 모델은 그 턴에서 멈추지 못한다. 프롬프트가 지워져도 훅이 남고, 훅이 죽어도 프롬프트가 남는다.

## 쓸 수 있는 이벤트는 Stop 하나다

| 이벤트 | 시점 | 사용 가능 |
|---|---|---|
| `Stop` | 매 턴 응답이 끝날 때 | 가능. 종료 여부를 추론해야 한다 |
| `SessionEnd` | 세션이 실제로 닫힐 때 | 불가. 그 시점엔 모델을 더 움직일 수 없다 |

`SessionEnd` 에서 헤드리스 에이전트를 새로 띄우는 길도 있다. 감독 없이 쓰고 커밋하는 비용이 든다.

## 트리거는 넷으로 나눈다

| 종류 | 판정 근거 | 사용량 게이트 |
|---|---|---|
| `closing` | 미처리 구간의 마지막 실제 사용자 발화가 마무리 어휘와 일치 | 없음 |
| `milestone` | 미처리 구간에 PR 생성·머지 · 티켓 상태 전이 · 배포 실행 흔적 | 없음 |
| `first` | 그 세션의 첫 `Stop`. 목표·범위·제약으로 뼈대를 만든다 | 90% 미만 |
| `periodic` | 이후 N턴마다 + 실제 파일 수정·커밋이 있었을 때 | 90% 미만 |

앞의 둘은 저빈도이자 마지막 기회라 사용량과 무관하게 돌린다. 뒤의 둘은 편의라서 한도에 양보한다.

"마지막 사용자 발화"는 transcript(JSONL)를 역순으로 훑어 뽑는다. `type=="user"` 중 `isMeta != true` 이고 텍스트 블록이 빈 게 아닌 첫 항목이다. 두 조건이 없으면 도구 결과나 슬래시 커맨드 주입문이 사용자 발화로 잡힌다.

## 사용량은 statusLine 에만 온다

남은 한도(`rate_limits`)는 훅 payload 에 없다. `statusLine` 이 stdin 으로 받는 값이 유일한 경로다. 이미 그 값을 쓰던 상태줄 스크립트가 파일로 흘려 주고, 훅이 읽는다.

```bash
u5=$(j '.rate_limits.five_hour.used_percentage // empty')
u7=$(j '.rate_limits.seven_day.used_percentage // empty')
if [ -n "$u5$u7" ]; then
  printf '%.0f\n' "$(printf '%s\n%s\n' "${u5:-0}" "${u7:-0}" | sort -g | tail -1)" \
    > "${TMPDIR:-/tmp}/claude-usage.pct"
fi
```

설계상 중요한 지점은 셋이다.

- 키가 없으면 아무것도 쓰지 않는다. 비구독 과금이나 첫 응답 전에는 `rate_limits` 가 통째로 빠진다.
- 그때 `0` 을 쓰면 사용량 0% 와 구분되지 않는다. 값이 없으면 훅은 모름으로 다뤄 통과시킨다.
- 캐시는 `refreshInterval` 만큼 낡는다. 게이트가 90% 라는 굵은 경계라 감수한다.

## 한 업무에 문서 하나를 유지한다

마일스톤마다 새 페이지가 생기면 위키가 파편으로 덮인다. 훅이 문서를 지목해서 넘긴다.

1. transcript 전체에서 볼트 위키 경로 패턴을 긁는다. 도구 인자든 셸 커맨드 문자열이든 걸린다.
2. `index.md` · `log.md` · `overview.md` 는 제외한다. 매번 갱신되는 파일이라 본문 페이지가 아니다.
3. 최신순으로 훑어 **실제로 존재하는 첫 파일**만 인정한다.
4. 있으면 그 절대경로를 `reason` 에 실어 "새로 만들지 말고 여기에 이어 써라"로 바꿔 보낸다.

3번이 핵심이다. 경로는 언급만 되고 만들어지지 않는 일이 흔하다. 존재 확인을 빼면 유령 경로를 기존 문서로 오인한다.

## 재발동은 세 겹으로 막는다

- `stop_hook_active` 가 참이면 즉시 빠진다. 훅이 깨운 턴에서 다시 깨우는 것을 막는 1차 차단이다.
- 세션별 오프셋에 "여기까지 처리했다"를 남기고, **발동할 때만** 전진시킨다. 같은 트리거로 두 번 돌지 않는다.
- 작업 증거를 셀 때 볼트 경로가 든 줄은 제외한다. 기록 작업 자체가 실제 작업으로 잡혀 스스로를 부르는 것을 막는다.

## 침묵이 정상인 장치에는 판정 로그가 필요하다

이 훅은 대부분의 턴에서 아무 일도 하지 않고 빠진다. 그래서 **작동 불능과 조건 미충족 통과가 겉보기에 같다.**

게이트마다 `skip: <이유>` 와 `FIRE[<종류>]` 를 남긴다. 그래야 로그가 비었을 때 그것을 미호출로 읽을 수 있다.

`hooks.Stop` 은 배열이고 여러 훅이 공존한다. 등록은 대입이 아니라 append 로 한다.

```bash
# 대입은 같은 이벤트에 붙어 있던 다른 훅을 지운다
jq '.hooks.Stop += [{"matcher":"","hooks":[{"type":"command","command":"~/.claude/hooks/session-wiki-log.sh"}]}]'   ~/.claude/settings.json > /tmp/s.json && mv /tmp/s.json ~/.claude/settings.json
```

## 검증

훅은 stdin 으로 JSON 을 받는다. 합성 payload 로 게이트별 동작을 확인한다.

```bash
echo '{"session_id":"T1","transcript_path":"/tmp/a.jsonl","cwd":"/repo","stop_hook_active":false}' \
  | ~/.claude/hooks/session-wiki-log.sh
```

실제 세션 셋에서 찍힌 판정 로그다. 대상 밖 저장소 차단, 조건 미충족 통과, 사용량 보류, 실제 발동이 모두 관측됐다.

```
16:50:00 | 8df6712e | skip: 대상 저장소 아님
16:51:19 | 6b76566e | skip: 트리거 없음 (304~316줄, usage=91%)
16:55:11 | dd3470a6 | skip: usage 91% >= 90% → first 보류
16:56:59 | dd3470a6 | FIRE[periodic]: 51턴 경과 + 실제 작업 있음 | usage=84%
```

`dd3470a6` 세션은 첫 턴에 사용량 91% 로 보류됐다가, 84% 로 떨어진 뒤 `periodic` 으로 잡혔다. 게이트가 의도대로 동작한 실사례다.
