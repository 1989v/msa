# K-관광 화면 구성 상세안

> 2026-10-07 · 검토용 디자인 제안. [HTML 스켈레톤](exploration-prototype.html) · [성장 분석 보고서](report.html)
> 실제 관광지 정보·지도·재고를 제공하는 화면이 아니다. 시안의 사진 영역·추천 문구·조건·결과 수·가격은 구조 검토용 예시이며 실서비스 데이터와 구분한다.

## 1. 화면 구성의 중심 결정

**검색과 지도는 하나의 결과 집합을 보여주고, 관광지 상세는 방문 결정을 돕는다.** 최초 방문자는 추천/지역에서 시작할 수 있고 목적지가 있는 사람은 검색으로 바로 진입한다. 저장은 이 두 흐름을 다시 연결한다.

대상 가설은 국내 자유여행자, 특히 주말·당일 여행지를 고르는 사람이다. 영문 서비스 확장에서도 정보 순서는 유지하되 교통·현지명·예약 안내를 보강한다. 디자인의 승인 대상은 정보 순서·화면 비율·상호작용이며, 운영 기능 변경은 별도다.

| 화면 | 들어오는 이유 | 가장 먼저 보여줄 내용 | 주요 행동 |
|---|---|---|---|
| 탐색 시작 | 아직 갈 곳을 못 정함 | 지역/관광지 검색, 최근/추천 지역, 조건별 작은 묶음 | 검색하거나 지역 선택 |
| 검색 결과 | 목적지·조건으로 후보 비교 | 현재 지역·검색어·적용 필터·결과 수, 카드와 지도 | 후보 확인·저장 |
| 필터 | 결과를 실제 제약에 맞게 줄임 | 요금/이동/동반/접근성, 선택 초안과 예상 결과 | 적용 또는 취소 |
| 상세 | 이 장소에 갈지 결정 | 사진·한 줄 이유·방문 핵심 정보·출처 | 저장·길찾기·공식 확인 |
| 저장한 후보 | 후보를 비교하거나 동행자에게 전달 | 후보 목록·개수·공통 지도·메모 | 순서 조정·공유 |

탐색 흐름:

```text
탐색 시작 ─검색/지역─> 검색 결과 ─장소 선택─> 관광지 상세
                         │  ↑                 │
                         └필터 적용/취소       ├길찾기/공식 정보
                         │                    │
                         └──── 저장 ──────────┘
                                  ↓
                            저장한 후보 ─공유─> 동행자 열람
```

Google에서 상세로 바로 들어오는 사람에게도 지역 경로와 ‘주변 탐색’으로 다음 행동을 제공한다. 검색을 거쳐야만 상세를 이해할 수 있게 만들지 않는다.

## 2. 레이아웃 대안과 선택 이유

| 대안 | 장점 | 부담 | 결정 |
|---|---|---|---|
| 큰 지도 + 좁은 목록 | 위치 관계가 잘 보임 | 카드 정보가 줄어 비교하기 어려움 | 위치 우선 사용자용 지도 모드로 제공 |
| 사진 카드 그리드 + 별도 지도 | 첫 방문의 발견·사진 탐색에 적합 | 목록과 위치를 오가야 함 | 탐색 시작/편집 콘텐츠에 사용 |
| 읽을 수 있는 목록 + 병렬 지도 | 조건 비교와 동선 파악을 동시에 수행 | 작은 화면에서 양쪽이 좁아짐 | **데스크톱 검색 기본** |
| 모바일 목록 + 지도 전환 | 작은 화면에서도 한 작업에 집중 | 전환 시 상태 복원이 중요 | **모바일 검색 기본** |

### 데스크톱

- 1200px 이상: 검색 결과 영역을 목록 약 46%, 지도 약 54%로 배치한다. 목록 최소 폭 420px, 실제 콘텐츠 폭에 맞춰 조정한다.
- 상단: 브랜드/탐색/저장 → 검색 → 지역/핵심 필터/정렬. 첫 카드까지 큰 홍보 히어로나 반복 설명을 넣지 않는다.
- 결과 목록은 자연스러운 페이지 스크롤, 지도는 해당 결과 영역 안에서 sticky. 페이지·목록·지도에 각각 세로 스크롤을 만드는 삼중 스크롤은 피한다.
- 지도 모드에서는 목록 대신 선택 카드 1개와 결과 수를 유지한다. 목록 모드에서는 비교 폭을 확보한다.
- 상세는 읽기 본문 약 2/3, 방문 요약/행동 약 1/3의 보조 열. 첫 화면에 요금·휴무·길찾기가 오게 한다.

### 태블릿과 모바일

- 768~1199px: 목록/지도 전환을 기본으로 두고 좁은 병렬 배치를 강제하지 않는다.
- 767px 이하: 한 열 목록, 검색·선택 조건 요약, ‘필터’와 ‘지도 보기’의 명확한 진입.
- 지도 모드: 지도 아래 선택 카드 시트. ‘목록으로’는 언제나 찾을 수 있게 두고 지도의 두 손가락 제스처와 페이지 스크롤을 혼동하지 않게 한다.
- 필터는 바텀시트 또는 전체 화면 다이얼로그. 제목·닫기·적용 버튼은 고정, 항목만 스크롤한다. 취소는 원래 조건을 보존한다.
- 상세의 하단 행동은 저장/길찾기. 본문 마지막 요소를 가리지 않도록 하단 공간·safe area를 둔다.
- 뒤로 가면 검색어·적용 필터·선택 장소·목록 스크롤 위치를 복원한다.

HTML의 ‘휴대폰 폭’은 좁은 실제 레이아웃을 검토하는 프레임이다. 실제 iOS/Android 브라우저와 키보드·지도 제스처 검증을 대체하지 않는다.

## 3. 검색창·자동완성·검색 결과

### 입력과 자동완성

1. 빈 입력: 최근 검색은 개인 기기에 저장한 경우만, 시작 지역은 편집 추천으로 구분한다.
2. 입력 중: 지역/관광지/테마를 유형 라벨과 함께 보여준다. 같은 이름이면 지역을 병기한다.
3. Enter 또는 검색 버튼: 목록에 표시한 제안을 고르지 않았다면 입력 문자열로 검색한다.
4. 제안 선택: 지역은 지역 범위 검색, 관광지는 선택된 결과 또는 상세, 테마는 근거가 있는 필터/편집 컬렉션으로 이동한다.
5. 한글 입력 조합 중에는 Enter로 검색을 확정하지 않는다. combobox의 방향키·Escape·Enter 동작과 스크린리더 안내를 제공한다.

시안은 제한된 예시 데이터만 검색한다. 자연어를 이해하거나 실제 검색 API를 부르는 것처럼 표현하지 않는다.

### 결과의 정보 순서

`서울 · 궁궐` → 적용 조건 칩 → 결과 N곳/정렬 → 카드와 지도. 카테고리·시설·지도 오버레이를 같은 줄의 동일한 버튼처럼 섞지 않는다. ‘주변 음식점 표시’는 관광지 결과의 필터와 별도 그룹이다.

정렬은 관련도·가까운 순처럼 근거를 설명할 수 있는 항목부터. ‘가까운 순’에는 기준 위치가 필요하고, 정렬이 바뀌면 목록 순서와 지도 번호가 함께 갱신된다. 클릭 수를 별점으로 바꾸지 않는다.

### 필터 구조

| 그룹 | 예시 | 정확성/상태 규칙 |
|---|---|---|
| 여행 성격 | 자연·역사·문화 | 한 단계로 시작, 긴 하위 분류는 펼침 |
| 비용 | 무료입장 | 주차/특별전 유료 여부는 상세 설명 |
| 이동 | 주차 가능 | 주차 가능과 무료 주차 구분 |
| 동반 | 반려동물 허용/일부 구역 | 부분 허용 조건을 표시 |
| 접근성 | 휠체어·엘리베이터·화장실 | 시설 하나로 전체 접근 가능을 단정하지 않음 |
| 운영 정보 | 정기휴무 기준 | ‘지금 영업 중’과 구분 |

필터는 초안 상태에서 수정하다 ‘N곳 보기’로 한 번에 적용한다. 취소·Escape·닫기는 적용하지 않는다. 선택 초기화는 초안을 지우고, 실제 결과 변경은 적용 시점에 한다. 정보가 없는 장소는 ‘불가’로 취급하지 않는다는 설명을 유지한다.

여행 성격 그룹 안에서는 OR(역사 또는 문화), 서로 다른 시설/조건 그룹은 AND(무료이면서 주차 가능)로 결합한다. 그룹 구분과 선택 결과를 함께 표시해 사용자가 뜻하지 않게 0건을 만들지 않도록 한다.

## 4. 카드 3종 — 장소·주변 후보·예약 상품

### 관광지 결과 카드

```text
┌사진 영역 4:3┐  경복궁                    [저장]
│            │  서울 종로구 · 역사
└────────────┘  이 장소를 고를 이유 한 줄
                 [확인된 속성] [확인된 속성]
                 정보 출처/확인 상태       [상세 보기]
```

- 제목 1~2줄, 추천 이유 최대 2줄. 200자 역사 설명을 카드에 넣지 않는다.
- 좌측 사진 + 우측 정보의 가로형은 검색 결과, 사진 상단형은 발견 컬렉션에 사용한다.
- 외곽 전체를 링크로 감싼 뒤 내부에 버튼을 중첩하지 않는다. 제목/상세 링크와 저장/지도 선택을 별도 의미 요소로 둔다.
- ‘지도에서 선택’과 ‘상세 보기’를 구분한다. hover만으로 핵심 내용을 공개하지 않는다.
- 가격 정보가 없을 때 ‘무료’를 추정하지 않는다. 사진 없음은 조용한 대체 이미지로 처리한다.

### 지도 선택/주변 카드

사진 작은 영역 + 제목 + 현재 선택 상태 + 상세/저장만 넣는다. 이 카드에서 모든 방문 정보를 반복하지 않는다. 거리라면 ‘직선거리’를 명시하고 도보 시간과 혼용하지 않는다.

### 예약 상품 카드

| 요소 | 관광지 정보 카드 | 예약 상품 카드 |
|---|---|---|
| 대상 | 장소 그 자체 | 입장권·투어·체험의 구매 옵션 |
| 제목 | 장소명 | 판매하는 경험/옵션 이름 |
| 주요 정보 | 위치·추천 이유·방문 조건 | 제공업체·포함사항·소요시간·조건 |
| 금액 | 입장료 정보·미확인 상태 | 인원/옵션/날짜 기준 가격 및 조회 시점 |
| 행동 | 상세·저장·지도 | 외부 판매처에서 옵션 확인 |
| 검증 | 공식 방문 정보·원천 데이터 | 실제 제휴 상품·가격·재고·취소 조건 |

**예약 상품 카드는 상세의 별도 구역에 둔다.** 관광지 결과 사이에 광고/예약 상품을 같은 모양으로 섞지 않는다. 현재 단순 상품 검색 링크만 있다면 ‘관련 상품 검색’으로 표현한다. 시안에는 구조 예시 가격/조건을 표시하되 실제 구매 링크·예약 확정 기능은 두지 않는다.

## 5. 지도와 목록의 상호작용

- 목록과 핀은 같은 필터 결과를 사용한다. 선택 장소 ID는 한 상태로 공유한다.
- 카드의 지도 선택 → 해당 핀 강조. 핀 선택 → 카드 강조/선택 카드 표시. 상세로 강제 이동하지 않는다.
- 선택이 색에만 의존하지 않도록 번호·윤곽·선택 문구를 함께 사용한다.
- 지도 이동 후 자동 검색은 비용과 사용자의 위치 맥락을 고려해야 한다. 기본 제안은 ‘이 지역에서 다시 검색’ 버튼으로 명시적 적용이다.
- 지도 모형의 범위 재검색은 시안 상태만 변경하며 실제 거리·경로·현재 위치를 계산하지 않는다.
- 목록을 더 불러올 때 이미 선택한 핀/카드를 유지한다. 클러스터는 확대를 유도하고 개별 장소 핀과 구분한다.
- 지도 실패 시 목록·주소·외부 길찾기 경로를 제공한다. 지도가 안 떠도 검색 결과를 잃지 않는다.

## 6. 상세 화면: 정보와 행동의 우선순위

1. 지역 breadcrumb, 장소명, 추천 이유.
2. 대표 사진/갤러리. 첫 화면 전체를 사진 한 장으로 채우지 않는다.
3. 방문 요약: 요금·시간·휴무·주차·동반/접근성·확인 상태.
4. 저장·길찾기·공식 정보. 길찾기는 별도 지도 서비스로 이동한다는 맥락을 제공한다.
5. 왜 가는가/주의할 점 → 긴 소개 → 주변 후보와 지도 → 추가 사진·영상.
6. 관련 예약 상품/외부 링크는 명확히 분리한다.

개요의 역사 설명과 동적 운영 정보의 확인 시각을 합치지 않는다. ‘원천 갱신’, ‘수집’, ‘편집 검수’는 다른 상태다. 정보가 상충하면 최신 공식 안내로 확인할 수 있게 한다.

시안의 요금·시간·휴무는 UI 자리와 표현을 보기 위한 값이다. 현재 경복궁 실제 안내로 사용하지 않는다.

## 7. 저장한 후보·공유

후보를 저장하면 카드·핀·상세의 저장 상태와 헤더 개수가 일치한다. 저장 목록에서 항목 제거, 순서 변경, 간단한 목록 이름을 제공한다. 기본 목록은 개인용이며 사용자가 ‘공유’를 선택하기 전 공개되지 않는다.

시안은 현재 브라우저 세션의 동작을 보여준다. 공유는 미리보기 다이얼로그까지만 제공하고 실제 공개 URL이 생겼다고 알리지 않는다. 실제 제품 구현 시 로그인/기기 간 동기화/공개 범위를 결정해야 한다.

빈 저장 화면은 ‘저장한 곳이 없습니다’와 ‘관광지 탐색’으로 이어진다. 로그인부터 강제하기보다 먼저 고를 수 있게 하는 방향을 검토한다.

## 8. 반드시 설계할 예외 상태

| 상태 | 화면 | 다음 행동 |
|---|---|---|
| 검색 로딩 | 이전 검색 맥락 유지 + 정적인 카드 스켈레톤 | 중복 검색 제어, 완료 안내 |
| 결과 0건 | 적용한 조건과 0건 이유 | 개별 조건 해제·초기화 |
| 네트워크 오류 | 검색어 보존, 오류 메시지 | 다시 시도 |
| 정보 없음 | 빈칸/0원/불가 대신 ‘확인 필요’ | 공식 안내 |
| 지도 실패 | 목록 유지·지도 오류 안내 | 재시도/주소로 확인 |
| 저장 목록 비어 있음 | 간단한 설명 | 탐색 시작 |

로딩 스켈레톤은 실제 콘텐츠의 공간을 예약한다. 이미지/텍스트가 도착했을 때 버튼이 뛰지 않게 하고, 모션은 `prefers-reduced-motion`을 따른다.

## 9. HTML에서 검토할 항목

- 화면 전환: 탐색 시작·검색 결과·상세·저장 목록.
- 데스크톱/휴대폰 폭 전환과 실제 창 크기에 따른 반응형.
- 검색어/추천어 선택, 조건 필터 적용/취소/초기화.
- 지도/목록/병렬 구성, 핀과 카드의 선택 동기화.
- 저장 상태/개수, 상세 진입과 결과로 돌아오기.
- 로딩·0건·오류 상태의 예시 전환.
- 관광지 카드/예약 상품 카드의 정보와 행동 차이.
- 보충 설명은 시안 외부의 ‘설계 설명’으로 분리. 실제 제품 화면에 구현 용어를 넣지 않음.

## 10. 이번 산출물과 다음 단계

이 문서는 부모 세션이 결정한 디자인 방향이며 HTML 구현은 지정된 `gpt-6.1-sol` 에이전트가 맡는다. 산출물은 분석 디렉터리의 독립 파일이며 서비스 소스/배포/API에 연결하지 않는다.

검토 후 목록/지도 비율, 카드 정보 밀도, 모바일 지도 진입, 상세 요약 위치를 선택한다. 그 결정을 바탕으로 운영 소스 버전과 기존 기능을 확인하고 작은 구현 범위를 별도로 확정한다.
