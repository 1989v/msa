# K-관광 성장 분석 — place.1989v.com

> 조사일: 2026-10-07 · 상태: 의사결정용 제안 · 대상: https://place.1989v.com/
> 운영 화면·HTTP 응답·현재 작업 트리·공식 외부 자료를 교차 확인했다. 서비스 구현이나 배포를 변경하는 문서가 아니다.

## 1. 판단: 데이터의 양에서 ‘방문 결정을 돕는 정보’로

**추천 방향은 한국 여행에 특화된 ‘조건별 관광지 발견 + 믿을 수 있는 방문 정보 + 저장·공유’ 서비스다.** 세계 전체 관광지 확장보다, 한국의 몇 개 지역에서 방문 결정을 가장 잘 돕는 경험을 먼저 만든다. 글로벌 사이트는 범위를 그대로 따라갈 대상이 아니라 정보 설계의 벤치마크다.

현재 서비스는 지도 검색만 있는 초기 제품이 아니다. 한·영 정보, 관광지 상세, 지역별 탐색, 무료·주차·반려동물·접근성 필터, 찜, 주변 장소, 행사, 날씨, 영상, 외부 여행 상품 링크까지 있다. **핵심 문제는 기능 부족보다 우선순위·정보 정제·신뢰·검색 유입 후의 행동 연결이다.**

바로 결정할 세 가지:

1. **첫 사용자:** 우선 국내 자유여행자의 ‘주말/당일 여행지 고르기’를 90일 가설로 삼는다. 외국인 대상 서울 핵심 명소는 별도 소규모 실험으로 검증한다. 타깃을 확정한 사용자 답변은 없으므로 이는 제안이다.
2. **첫 상품 가치:** “어디가 유명한가”에 더해 “내 조건에 맞고, 방문 전에 무엇을 확인해야 하는가”를 답한다. 무료·주차·동반 조건이라는 기존 자산을 활용한다.
3. **첫 투자:** 화면 재배치와 신뢰 정보 → 지역·상황별 편집 콘텐츠 → 공유·유통 → 검증된 범위 확대 순서다. 전면 프레임워크 교체와 자체 예약 엔진은 후순위다.

## 2. 조사 범위와 증거의 한계

| 구분 | 확인한 것 | 확인하지 못한 것 |
|---|---|---|
| 운영 UI | 국문/영문 홈, 경복궁 상세의 렌더링 DOM·텍스트·링크, 1440×900 좌표 | 모바일 실제 렌더링, 터치 사용성, 시각적 스크린샷 비교, 로그인 후 찜 완주 |
| HTTP | 홈 2개, 서울 지역 2개, 상세 6개, 없는 상세 1개, robots·사이트맵 | 전 URL 전수검사, Googlebot 실제 수신 응답, 모든 응답 헤더 |
| 검색 | 공식 Google 지침, 공개 검색 보조 조회 | Search Console, GA/자체 집계 대시보드, 실제 검색량·순위·전환율 |
| 코드 | PlacePage·AttractionPage·RegionPage·FavoriteButton·SEO 생성기 등 | 현재 작업 트리와 운영 배포의 동일성 |
| 외부 비교 | 글로벌 6개 서비스의 공식 페이지/도움말, 국내 공식 관광 사이트 | 동일 조건의 전체 예약·회원가입 여정, 유료 트래픽 통계 |

운영 화면에 있는 필터·주변 탐색·행사 등 일부가 현재 로컬 파일보다 확장되어 있었다. 따라서 **운영에서 확인한 기능을 우선**하며, 로컬에 없다는 이유로 운영에도 없다고 판정하지 않았다. 작업 트리는 다른 변경이 다수 있어 분석 산출물만 별도 디렉터리에 작성했다.

스크린샷·모바일 에뮬레이션 도구는 자동 승인 검토에서 거절되었다(`approval policy is never`). 픽셀 단위 시각 검수와 모바일 평가를 완료했다고 주장하지 않는다. 초기 Python 기본 HTTP 클라이언트는 403/1010을 받았으나 일반 브라우저와 curl은 정상 응답했다. 이것만으로 Googlebot 차단을 단정할 수 없다.

증거: [HTTP 기본 표본](evidence/http-audit.json), [상세 후반 표본](evidence/http-tail-sample.json), [사이트맵 항목 집계](evidence/sitemap-counts.json), [운영 UI 관찰 기록](evidence/ui-observations.md). HTTP의 `textChars`는 title 등을 포함한 단순 텍스트 추출 길이이며 본문 품질 점수가 아니다. `xRobots`는 헤더 미수집으로 판정하지 않는다.

## 3. 현재 서비스: 유지할 강점과 실제 마찰

### 이미 있는 강점

- **탐색 기반:** 지도/목록, 지역 드릴다운, 내 주변, 자연·역사·문화·레포츠·행사·코스, 지도 위 음식·쇼핑·숙박.
- **조건 필터:** 무료입장, 주차, 반려동물, 휠체어·엘리베이터·장애인 화장실 등. “정보가 있는 곳만 거릅니다”라는 한계 안내도 있다.
- **방문 보조:** 경복궁 상세에 사진 7장, 이용시간·휴무·요금·주차, 주변 탐색, 지역 날씨·대기질·혼잡도 탭, 영상, 외부 링크가 있다. 탭 존재와 각 데이터 정확성은 다른 문제다.
- **재방문 기반:** 카드 찜과 `/favorites` 진입이 있다. 찜 기능을 새로 만들라는 권고는 부정확하다.
- **검색 기반:** 원본 HTML 본문, 고유 title/description/canonical, 지역 링크, 한·영 허브/지역 hreflang, BreadcrumbList, TouristAttraction, 행사 Event, 분할 사이트맵.

근거: [국문 홈](https://place.1989v.com/), [영문 홈](https://place.1989v.com/en), [경복궁 상세](https://place.1989v.com/attractions/1), [서울 지역](https://place.1989v.com/regions/11).

## 5. UI/UX 개선안

### A. 홈과 검색 결과: ‘모든 옵션’보다 다음 선택을 명확하게

현재 지도 경험을 유지하며 상단을 다음 순서로 재배치한다. 별도 홍보용 홈을 먼저 만들 필요는 없다.

```text
K-관광                    한국어 / English   저장한 곳
어디로 가볼까요? [지역·관광지 검색________________] [검색]
[서울 ▾] [무료] [아이와 함께*] [실내*] [필터 · 2]
서울 · 무료 · 주차 가능             결과 N곳  [정렬 ▾]
데스크톱: 비교하기 쉬운 카드 목록 | 지도
모바일:   목록 기본 + [지도 보기] / 지도에서는 결과 시트
```

`*` 아이 동반/실내는 제안된 새 편집 분류다. 데이터 검증 전에 기능이 있는 것처럼 노출하지 않는다. 지역·분류·시설을 서로 다른 조작 목적에 맞게 묶고, 선택 해제와 전체 초기화는 항상 찾을 수 있게 한다.

**카드 정보 순서:** 사진 → 장소명/동네 → 추천 이유 한 줄 → 확인된 요금/동반/주차 속성 → 저장. 긴 원문은 상세에서 읽게 한다. 확인하지 못한 속성은 생략하거나 ‘정보 확인 필요’로 표시한다. 주소 전체는 상세 또는 복사 액션으로 넘긴다.

**정렬:** 처음에는 관련도·거리 등 검증 가능한 기준만 제공한다. ‘인기’는 노출량 보정·집계 기간·표본 기준을 정한 후 제공한다. 클릭 수를 평점으로 표현하지 않는다. 선택한 지도 범위와 목록 범위를 한 문장으로 표시한다.

**빈 결과:** 실패와 0건을 구분하고, 어떤 조건 때문에 좁아졌는지 보여준다. ‘반려동물 정보가 확인된 곳이 없습니다 → 이 조건 해제’처럼 사용자가 선택해 완화하게 한다. 반경을 몰래 넓히거나 조건을 조용히 무시하지 않는다.

**검색 품질:** `경복궁`, `Gyeongbokgung`, `궁궐`, `제주 무료`, `비 오는 날 서울` 등 30개 평가 질의를 만든다. 지원하지 않는 자연어 조건은 해석했다고 가장하지 않고 사용 가능한 필터로 안내한다. 잘못된 지역·동명이인·별칭·오타·0건을 별도로 평가한다.

### B. 상세: 역사 소개보다 방문 결정을 먼저

```text
서울 > 종로구 > 경복궁
사진 · 장소명 · 한 줄 특징                       [저장] [공유]
방문 전 확인: 요금 | 이용시간 | 휴무 | 주차 | 출처·확인일
[길찾기] [공식 방문 안내]
이런 여행에 적합 / 주의할 점 / 주변에서 함께 볼 곳
소개 더 읽기 → 사진 → 상세 이용 안내 → 날씨/주변/영상
```

- 경복궁의 실제 요금·휴무를 이 문서에서 재검증한 것은 아니다. 화면에 있는 값을 요약할 때도 조건·계절·공휴일 예외를 보존한다.
- 지금 있는 날씨·영상·상품 링크는 보조 정보로 배치한다. 방문 핵심 정보가 아래로 밀리지 않게 한다.
- 데이터의 **원천 수정일, 수집일, 운영자 검수일**을 구분한다. 수집일을 현장 확인일처럼 표시하지 않는다.
- ‘정보 수정 제안’을 도입하면 항목·근거 링크·검토 상태를 수집한다. 초기에 무제한 자유게시판을 운영할 필요는 없다.
- 공식 사이트로 가는 링크와 상품 예약 링크를 구분한다. 단순 검색 딥링크를 확정 예약 가능 상품처럼 표현하지 않는다.

### C. 저장·공유: 기존 찜에서 작은 여행 계획으로

제안 흐름은 `검색 → 후보 3곳 저장 → 목록 이름 설정 → 링크 공유 → 동행자 열람 → 길찾기`다. 게스트 저장은 로컬 브라우저 범위임을 알려주고 로그인 시 계정에 합친다. 공유 목록은 사용자가 명시적으로 공유할 때 생성하며, 기본 공개 SEO 페이지로 만들지 않는다.

첫 버전은 후보 목록과 간단한 메모면 충분하다. 경로 최적화·실시간 협업·AI 일정 자동 생성은 실제 저장/공유 사용을 확인한 다음 결정한다.

### D. 시각·접근성 원칙

사진이 목적지를 설명하고 타이포그래피가 정보 중요도를 드러내도록 한다. 새 브랜드 팔레트를 즉흥적으로 추가하기보다 root `DESIGN.md`의 k-heritage 관련 토큰과 기존 컴포넌트를 우선 사용한다. 지도 위 텍스트, 사진 위 라벨, 버튼 상태의 명도 대비는 실측한다.

모바일 검증 계획: 390px·360px·320px, 목록/지도 전환, 필터 시트 열고 닫기, 뒤로 가기 시 검색 조건·스크롤 복원, 키보드 노출, 느린 네트워크, 지도 실패 폴백. 이미지 대체 텍스트는 장식인지 정보 전달인지 구분하고, 지도 없이도 목록과 주소로 탐색 가능하게 한다. 이번 조사에서 모바일 검증을 수행한 것은 아니다.

## 6. 콘텐츠·데이터 확장 전략

### 단계적으로 넓힐 범위

1. **서울·부산·제주 × 2개 상황, 편집 페이지 6개:** 팀이 실제 검수할 수 있는 지역부터. 콘텐츠 예산이 작으면 서울 2개부터 시작한다.
2. **핵심 상세 30개:** 원문 정제, 방문 요약, 공식 링크, 출처/시각, 사진·언어 품질을 검수한다.
3. **영문 서울 핵심 10개:** 영문 데이터의 현지명·교통·결제·예약 안내를 검증한다. 성공한 한국어 글을 기계번역해 전량 발행하지 않는다.
4. **성공한 조건/지역만 확대:** 검색 노출보다 저장·길찾기·수정 제안 등 실제 사용까지 확인한다.

### 초기 콘텐츠 후보 — 검색량 검증 전 가설

| 페이지 아이디어 | 사용자의 결정 | 필요한 고유 정보 | 연결 |
|---|---|---|---|
| 서울 무료 실내 여행지 | 비/더위에도 예산 내 방문 | 실제 무료 범위, 유료 특별전, 휴관, 위치 | 서울 지역 ↔ 검수된 상세 |

‘부모님과’, ‘무료’, ‘접근 가능’ 등은 제목만 바꿔 만드는 분류가 아니다. **선정 기준을 확인할 수 없으면 발행하지 않는다.** Google은 자체 경험·독창성·충분한 도움을 강조하고, 검색 순위 조작을 목적으로 한 대량 콘텐츠 생성을 문제 삼는다. [유용한 콘텐츠 지침](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [스팸 정책](https://developers.google.com/search/docs/essentials/spam-policies).

### 운영에 필요한 정보

장소별 정규 식별자와 언어별 문서를 구분한다. 필드마다 `값 / 출처 URL / 원천 갱신일 / 수집일 / 검수일 / 상태(확인·미확인·상충)`를 관리하는 설계를 검토한다. 이는 제안이며 현재 스키마를 변경한 것이 아니다.

국·영문 경복궁 ID는 운영에서 `/attractions/1`, `/en/attractions/21`로 다르다. 동일 장소 매칭이 확인된 쌍부터 연결한다. 이름 문자열만으로 자동 통합하면 동명이인·분관을 잘못 합칠 수 있다.

동적 정보는 신선도 정책을 다르게 둔다: 주소·역사, 요금·휴무, 행사 일정, 날씨·혼잡도. 날씨 갱신 성공이 요금 최신성을 보장하지 않는다. 사진·영상·후기를 늘릴 때는 원천별 재사용 조건과 표시 의무를 확인하고, 경쟁 사이트의 후기·평점을 복사해 자체 데이터처럼 만들지 않는다.

## 7. 구글 검색 노출: 새 SEO 설비보다 현재 상태의 측정

### 운영 응답 점검 결과

| 항목 | 직접 확인 | 판단 |
|---|---|---|
| HTTPS 주요 문서 | 홈·지역·상세 표본 200 | 기본 접근 경로 정상 |
| 원본 HTML 본문 | 허브·지역·상세와 후반 ID 표본에 H1·본문 | ‘React라 색인 불가’ 또는 ‘SSR 전면 교체 필요’ 근거 없음 |
| title/canonical | 표본마다 대상 URL에 맞는 값 | 기존 기반 유지, 대량 품질 검사로 확장 |
| hreflang | 홈·서울 지역 ko/en/x-default | 상세는 없음. 언어별 ID 매칭 후 정확한 쌍에만 추가 |
| 구조화 데이터 | CollectionPage/ItemList, TouristDestination, TouristAttraction, BreadcrumbList | 문법 존재와 Google 검색 표시 자격은 별도 |
| 행사 상세 | `/attractions/65811`에 Event | 이미 구현됨. 날짜·상태·장소·지원 지역/언어 조건 검증 필요 |
| 없는 상세 | `/attractions/999999999` 404 + noindex | soft 404라고 진단할 근거 없음 |
| robots | 일반 봇 허용, `/api/` 차단, sitemap 선언 | 핵심 내용은 HTML에 있으나 JS 추가 정보의 렌더 가능성은 URL 검사 필요 |
| sitemap | 6개 하위 파일, 총 **62,607 URL 항목** | 제출 대상 양이다. 고유 관광지 수·색인 수·유입 수가 아님 |

사이트맵 세부: 허브/지역 541 + 상세 20,000 + 20,000 + 20,000 + 1,559 + 행사 507. 언어와 유형이 섞여 있으며 중복 제거 수를 측정한 것은 아니다. 사이트맵이 크다는 사실만으로 저품질·패널티를 판단하지 않는다. [운영 사이트맵](https://place.1989v.com/sitemap.xml).

### 1주차: 색인 진단을 재현 가능하게 만들기

1. Search Console에서 `https://place.1989v.com/` URL-prefix 속성 또는 해당 하위 도메인을 포함하는 DNS 검증 Domain 속성의 소유권/권한을 확인한다. 이미 등록했다면 새로 만들지 않는다.
2. `https://place.1989v.com/sitemap.xml` 제출/최근 읽기/처리 오류를 확인한다.
3. 홈 ko/en, 서울 지역 ko/en, 경복궁 ko/en, 후반 상세, 행사, 의도적 404를 URL 검사한다. **실시간 테스트와 Google에 저장된 색인 상태를 구분**한다.
4. Google 선택 canonical, 마지막 크롤링, 렌더링 HTML, robots/리소스 차단, 발견됨/크롤링됨-현재 색인 안 됨을 URL 유형별로 기록한다.
5. 최근 28일의 페이지·검색어·국가·기기별 노출/클릭을 저장한다. `site:` 공개 검색은 정밀 색인 수 측정에 쓰지 않는다.

사이트맵 제출은 발견을 돕는 신호이고 색인 보장이 아니다. 공개 검색 노출에는 비용을 낼 필요가 없으며, 기본 조건 충족도 크롤링·색인·순위를 보장하지 않는다. [Search Console 시작](https://developers.google.com/search/docs/monitor-debug/search-console-start), [사이트맵 제출](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Search Essentials](https://developers.google.com/search/docs/essentials).

### 페이지 종류별 색인 정책 제안

| 페이지 | 권장 처리 | 이유 |
|---|---|---|
| 검수된 장소 상세 | self-canonical·사이트맵·지역 내부 링크 | 고유명사와 방문 질문에 답함 |
| 지역 허브 | 고유한 소개/추천 이유 보강 후 유지 | 단순 목록 이상으로 지역 의도를 충족 |
| 편집된 상황별 가이드 | 안정적인 URL, 수동 품질 게이트 | 검색 의도에 맞는 독립 콘텐츠 |
| 임의 검색어·지도 좌표·필터 조합 | 원칙적으로 색인 확대 대상에서 제외 | 조합 폭증·중복·빈 결과 관리 |
| 개인 찜/공유 목록 | 기본 비공개 또는 noindex 정책 | 사용자가 공개를 선택한 편집 콘텐츠와 분리 |
| 삭제된 장소 | 대체 장소가 동일한 경우만 적절한 이동, 그 외 404/410 검토 | 모든 삭제를 홈으로 보내지 않음 |
| 일시 API 장애 | 정상 콘텐츠 유지/적절한 장애 응답 | 일시 실패를 영구 noindex로 바꾸지 않음 |

`noindex`를 읽히게 하려면 해당 URL의 크롤링을 막지 않아야 한다. robots 차단과 색인 제거는 다르다. canonical도 모든 필터 페이지를 홈으로 보내는 만능 해법이 아니다. 유사하지 않은 페이지를 한 canonical로 뭉치지 않는다. 현재 URL 동작과 GSC 결과를 확인한 뒤 적용한다. [필터 URL 크롤링 관리](https://developers.google.com/crawling/docs/faceted-navigation), [JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

### 구조화 데이터·다국어·성능

- `TouristAttraction` 존재만으로 관광지 전용 리치 결과나 별점을 보장하지 않는다. Google의 지원 검색 기능과 schema.org 의미 표현을 구분한다. Breadcrumb 및 실제 Event를 해당 기준에 맞게 검증한다. 허구 리뷰를 생성하지 않는다. [지원 기능 목록](https://developers.google.com/search/docs/appearance/structured-data/search-gallery), [Event 지침](https://developers.google.com/search/docs/appearance/structured-data/event).
- 국문과 영문은 각각 self-canonical을 유지한다. 정확한 번역 쌍에만 양방향 hreflang을 선언하고, 영문 전체를 국문 canonical로 합치지 않는다. [언어별 페이지 지침](https://developers.google.com/search/docs/specialty/international/localized-versions).
- 사이트맵 `lastmod`는 실제 중요한 내용 갱신을 반영한다. 빌드할 때 모든 문서의 날짜만 새로 찍지 않는다. 제목의 연도도 실제 갱신과 맞춘다.
- Core Web Vitals 목표는 실제 방문의 75백분위에서 LCP ≤2.5초, INP ≤200ms, CLS ≤0.1이다. 현재 점수는 측정하지 않았다. 모바일/데스크톱과 페이지 종류를 나눠 측정하고 지도·영상 지연 로드, 이미지 크기, 광고 공간 예약을 진단한다. [Web Vitals](https://web.dev/articles/vitals).
- `llms.txt`나 AI 봇 허용을 구글 순위 개선 작업의 대체물로 삼지 않는다. 우선순위는 사용자에게 보이는 내용, 읽을 수 있는 링크, 정확한 응답과 실제 검색 실적이다.

**프레임워크 결정:** 표본에서 원본 HTML이 이미 제공되므로 Next.js 전면 이전을 우선 과제로 제안하지 않는다. 로컬 프리렌더 상한 설정을 운영 전체 커버리지로 오해하지 않는다. 정적 생성/동적 응답 여부보다 배포된 URL의 실제 결과를 검사한다.

## 10. 성과 측정과 수익화

**대표 제품 지표 제안:** 유입 세션 중 ‘유효한 관광지 결정 행동’에 도달한 비율. 방문이 실제로 일어났다고 단정하지 않고, 후보 저장·목록 공유·길찾기 클릭을 행동별로 나눠 본다.

| 지표 | 정의 | 주의 |
|---|---|---|
| 검색→상세 | 결과를 받은 검색 중 상세를 연 검색 비율 | 상위 노출 순위·페이지 종류로 분해 |
| 상세→실행 | 상세 방문 세션 중 저장/공유/길찾기 각 행동 비율 | 중복 클릭 제거, 클릭은 실제 방문 아님 |
| 공유 유효성 | 공유 링크를 연 별도 세션의 상세/저장 행동 | 공유 버튼 클릭과 수신자 사용을 구분 |
| 검색 품질 | 의도별 평가 질의의 적합 결과·0건율 | 단순 전체 평균으로 지역/언어 격차를 숨기지 않음 |
| SEO | 비브랜드 노출·클릭, 유효 페이지 색인, 검색어별 CTR | CTR은 순위·기기·국가·질의 변화와 함께 해석 |
| 콘텐츠 건강 | 필수 정보 확인율, 오래된 정보 비율, 수정 처리 시간 | 없는 정보를 부정값으로 채우지 않음 |
| 재방문 | 저장 이용자의 7일/28일 재방문 | 여행 주기가 길므로 DAU만 최적화하지 않음 |

이벤트 예: `search_submitted`, `filter_applied`, `result_clicked`, `save_completed`, `collection_shared`, `directions_clicked`. 현재 analytics 구현과 이름/중복 방지를 맞춘 후 도입한다. 검색어에는 개인정보가 섞일 수 있으므로 수집 범위·보관 기간을 정하고, 정밀 위치를 필요 이상 남기지 않는다.

초기 광고는 결정 정보의 가독성·레이아웃 안정성을 먼저 검증한다. 제휴 수익은 단순 외부 링크 존재로 발생하지 않는다. 실제 제휴 계약·추적·공시·상품 적합성이 필요하며 수수료율은 이번 조사에서 확인하지 않았다. 수익 계산은 `유효 상세 세션 × 외부 상품 클릭률 × 제휴사 구매전환율 × 확인된 순수수료`로 하고, 추정치를 실적으로 제시하지 않는다.

## 11. 실행 전에 남은 결정

- 국내 여행자 중심인지, 방한 외국인 중심인지. 후자라면 영문 정보 정제·교통/결제 안내·언어 쌍 연결이 P0로 올라간다.
- 실제 Search Console 권한/현황과 28일 유입 데이터. 미색인 원인을 현재 공개 표본만으로 단정할 수 없다.
- 주당 콘텐츠 검수 시간과 처음 집중할 지역. 운영 여력이 30곳을 감당하지 못하면 10곳으로 줄인다.
- 현재 배포된 소스 버전/브랜치. 운영과 로컬 차이를 정리한 뒤 구현 범위를 확정한다.
- 게스트 저장과 공유 공개 범위, 오류 제보 검토 담당자.

**다음 구현의 작은 범위 제안:** ‘홈 필터 압축 + 경복궁 상세 방문 요약 + 영문 카드 정제’의 시안/명세를 먼저 확정한다. 그다음 지정된 Codex 구현 에이전트로 구현·검증하고, 결과를 본 뒤 지역 가이드와 저장·공유로 넓힌다.
