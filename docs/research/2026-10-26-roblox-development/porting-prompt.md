# 기존 게임을 Roblox로 이식하는 프롬프트

아래 블록을 복사해 사용한다. 다른 게임을 옮길 때는 첫 입력 표만 바꾼다. 현재 값은 인피니티 스탭의 승인된 첫 구현 범위다. 게임별 실제 코드와 사용자 선택이 이 템플릿보다 우선한다.

```text
너는 기존 게임을 Roblox로 이식하는 게임 개발 파트너다.
원작의 핵심 재미를 실제 코드로 확인하고, Roblox에서 직접 실행 가능한 작은 구간부터 구현하라.

[이번 게임]
- 이름: 인피니티 스탭 / Infinity Step
- 저장소: /Users/gideok-kwon/IdeaProjects/msa
- 원작 소스: portal-fe/public/games/_src/infinity-step/
- 원작 기획: docs/specs/2026-09-02-infinity-step-prd.md
- Roblox 명세: docs/specs/2026-10-26-roblox-infinity-step/spec.md
- 구현 위치: roblox/infinity-step/
- 첫 범위: 짧은 도시 등반 코스 3구역, 5단 충전 점프, 공중 방향 고정,
  아래 발판까지 추락, 현재/최고 높이, PC·터치 입력, 선택형 부활권
- 부활 위치: 떨어지기 직전 마지막으로 안정적으로 밟았던 발판
- 상품: 반복 구매 가능한 부활권 1개. 가격·상품 ID 미정, 실제 판매 비활성화
- 공개: 로컬 결과물까지. Roblox 공개·상품 생성·실제 결제는 별도 승인 필요

[작업 원칙]
1. 루트와 대상 경로의 AGENTS.md, 관련 명세·결정·디자인 토큰을 먼저 읽어라.
   다른 작업자의 수정과 staging을 보존하라. 원작 소스를 수정하지 마라.
2. 기획·핵심 설계는 부모 세션에서 확정한다. 이 저장소의 모델 분담에 따라
   승인된 구현과 관련 검증은 model="gpt-6.1-sol", fork_turns="none"인
   구현 서브에이전트 한 명에게 명시적으로 위임한다.
   파일 소유권·요구사항·검증 명령을 넘기고, 모델을 쓸 수 없으면 대체하지 말고 알린다.
3. 원작 코드를 다른 엔진에 그대로 붙이는 방식으로 접근하지 마라.
   조작·시뮬레이션·저장·UI·에셋 의존성을 나눈 뒤 Roblox에 맞게 옮겨라.
   보존할 규칙과 Roblox판에서 바꿀 규칙을 짧게 명시한다.
4. 코드가 답하는 사항은 직접 확인하라. 중요한 미결정 사항만 질문한다.
   이미 승인된 범위의 구현 세부사항은 합리적으로 정하고 기록한다.
   범위 확대나 핵심 규칙 변경은 사용자에게 먼저 드러내라.

[원작 분석]
- 진입점과 실제 게임 루프를 찾는다. 기획 문서와 코드가 다르면 차이를 기록한다.
- 이동·충돌·승패·성장·추락의 실제 수치와 저장 형식을 확인한다.
- 원작의 재미를 한 문장으로 설명하고, 첫 구간의 성공 조건을 정한다.
- 이미지·모델·오디오의 라이선스와 Roblox에서 재사용할 수 있는 경로를 확인한다.
- 게임 전체 목록을 한 번에 포팅하지 말고, 이번 게임의 승인된 구간만 구현한다.

[Roblox 설계와 구현]
- Luau를 사용한다. Workspace는 월드, ServerScriptService는 서버 전용 처리,
  ReplicatedStorage는 공유 정의와 통신 객체, StarterPlayerScripts/StarterGui는
  입력·카메라·HUD에 사용한다. 실제 위치는 Roblox의 스크립트 실행 규칙을 따른다.
- 원작의 단위를 Roblox studs/초와 Workspace.Gravity에 맞춰 환산한다.
  발판 배치는 런타임과 같은 점프 상수로 도달 가능성을 검사한다.
- 화면 입력은 클라이언트에서 처리하고, 진행·소모품·부활·결제 확정은 서버가 판단한다.
- RemoteEvent의 타입·유한수·상태·권한·빈도를 검증한다.
  클라이언트가 점프 단계·점수·보유량·텔레포트 좌표를 결정하게 하지 않는다.
- 원작의 핵심 조작을 먼저 완성한다. 이번 게임은 5단 충전 점프와 공중 방향 고정이 핵심이다.
- PC와 터치에서 같은 행동이 가능해야 한다. 터치 이동과 점프 버튼이 겹치지 않게 한다.
- 화면 색·크기·여백은 저장소 DESIGN.md를 참조한 중앙 Theme로 관리한다.
- Studio에서 열 수 있는 .rbxlx 또는 검증된 동등한 프로젝트를 제공한다.
  프로젝트 매핑과 재생성 명령, 편집 가능한 원본 Luau를 함께 남긴다.

[부활권]
- 부활권은 추락 후 사용자가 명시적으로 선택할 때만 소비한다.
  무료로 계속 플레이하거나 처음부터 다시 할 수 있어야 한다.
- 서버가 마지막 안정 착지 발판을 기록하고, 추락 시작 시 복귀 발판 ID를 고정한다.
  아래층 착지가 원래 복귀 지점을 덮어쓰면 안 된다.
- 복귀는 서버가 확인한 해당 발판의 안전한 위치로 한다.
  캐릭터 속도를 초기화하고 발판 내부·허공에 생성하지 않는다.
- 계속하기를 선택하면 같은 추락에서 구매/부활 제안을 반복 생성하지 않는다.
- 사망 후 무료 지상 리스폰에서도 유효한 추락 기록으로 새 선택을 제공할 수 있다.
  이전 캐릭터의 요청으로 새 캐릭터를 뒤늦게 이동시키지 않는다.

[결제와 저장]
- 반복 구매 소모품은 Developer Product로 설계한다.
- 공식 Roblox 문서의 현재 SDK와 정책을 확인한다.
- ProcessReceipt를 서버에서 처리하고 PurchaseId 기준으로 중복 지급을 방지한다.
- 구매는 인벤토리에 1개를 지급하고, 부활 실행은 별도 요청으로 1개를 소비한다.
  구매창 종료 이벤트만으로 지급하거나 구매 완료 즉시 자동 부활시키지 않는다.
- 지급·중복 영수증 표시를 같은 원자적 저장 갱신에 넣는다.
- 소비·전달 대기 기록도 같이 저장해, 차감 직후 끊겨도 다시 차감하지 않고 복구한다.
  전달 완료 기록 중 캐릭터가 교체되는 경우와 여러 서버의 경쟁도 처리한다.
- 저장 실패·취소·늦은 영수증·중복 요청·재접속을 정상 흐름으로 다룬다.
  실패 시 실제 보유량을 기본값으로 덮어쓰지 않는다.
- 가격은 실제 상품 정보에서 조회한다. 상품 ID가 없으면 판매 버튼을 비활성화한다.
- Studio 테스트용 인벤토리와 실제 판매 모드를 명확히 분리한다.

[검증]
- 검증은 실제 구현 모듈을 실행해야 한다. 별도 언어로 규칙을 다시 쓴 모형은 대체 증거가 아니다.
- 단위/컴포넌트 검사: 충전 경계, 도달 가능 코스, 공중 입력 차단, 복귀 발판 유지,
  계속하기, 단일 차감, 중복 영수증, 저장 실패, 전달 전후 접속 종료, 캐릭터 교체.
- 패키징 검사: 모든 Luau 구문 컴파일, 정확한 소스 포함, 올바른 서비스 배치,
  시작 위치·월드 포함, 동일 입력으로 동일 산출물 재생성.
- Studio 검사: 실제 물리·충돌·카메라·모바일 조작·클라이언트/서버 분리·복수 플레이어.
- 실제 상품 검사는 비공개 테스트 경험에서 별도 수행한다.
  CLI 검사만 실행했으면 Studio 플레이나 결제가 검증됐다고 말하지 않는다.
- 브라우저·앱·Studio 등 computer use는 이 저장소의 사전 승인 규칙을 지킨다.
  필요한 경우 앱/사이트·읽기/행동·상태 변경·완료 조건을 명시하고 승인받는다.
  승인이 없으면 소스와 CLI로 할 수 있는 작업을 먼저 완료한다.

[최종 결과]
- 첫 구간의 구현 결과와 실행 파일
- 편집 가능한 소스와 빌드/검증 명령
- 원작 대비 변경 사항과 부활권의 정확한 동작
- 실행한 검증 명령·결과·남은 미검증 항목
- Studio에서 실행하는 짧은 절차
- 실제 공개/판매 전에 사용자가 정해야 할 항목

검증이 끝난 작은 구간을 먼저 보여 주고 다음 구간은 그 피드백을 반영한다.
```
