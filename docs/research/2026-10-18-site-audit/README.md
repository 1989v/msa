# 1989v 공개 사이트 개선 리포트

조사일: 2026-10-18 · 범위: 메인, 게임, 관광 국문·영문, 블로그, IT, 스토어, 혜택, 랭킹.

**먼저 고칠 것은 게임 목록의 누락 가능성, 게임 설명과 인원 표시의 불일치, 초기 HTML과 실제 앱의 콘텐츠 차이입니다.** 새 서비스를 더 늘리기보다, 이미 있는 콘텐츠를 끝까지 찾고 정확히 이해할 수 있게 만드는 개선을 권합니다.

## 조사 방법과 한계

- 사용자가 공개 사이트 브라우저 탐색을 승인했으나, 컴퓨터 사용 도구가 Chrome과 내장 브라우저 모두 `Browser is not available`을 반환했고 브라우저 목록도 비어 있었습니다. 실제 화면·클릭·스크린샷·게임 플레이는 확인하지 못했습니다. 이 문서는 **공개 HTTP 응답·소스 기반 1차 조사**이며 시각적 UX 검수 완료 보고서가 아닙니다.
- 공개 URL 26개를 GET으로 수집했습니다. 응답 원문, 수집 시각, 최종 URL, 상태 코드, 본문 해시를 `evidence/`에 저장했습니다. 별도로 메인 HEAD 요청과 외부 웹 검색을 수행했습니다.
- 운영 HTML과 로컬 소스는 배포 시점이 다를 수 있습니다. 실제로 SearchAction 주소가 서로 달랐습니다. 로컬 코드만으로 확인한 문제는 운영 화면 재현이 필요한 것으로 표시합니다.
- 로그인, 구매, 방 생성, 글 작성, 관리자 기능, 외부 제휴 링크 이동은 수행하지 않았습니다. 운영 코드·설정·데이터는 변경하지 않았습니다.
- 기존 작업 트리에 많은 변경이 있었으며, 본 조사 디렉터리 외의 파일은 수정하지 않았습니다.
- 검색 도구의 `site:1989v.com`, `"1989v.com"`, `site:game.1989v.com` 질의에서 유효한 사이트 결과를 확보하지 못했습니다. **이를 미색인 또는 Google·네이버 검색 순위 하락의 증거로 해석하지 않습니다.** Search Console·서치어드바이저는 확인하지 않았습니다.

근거 표기: **운영 확인**은 HTTP 원문/API에서 확인, **코드 확인**은 현재 로컬 구현에서 확인, **제안**은 사용자 검증 전 가설입니다. P1은 다음 개선 묶음의 우선 항목, P2는 그다음 개선이며 장애 심각도 등급이 아닙니다.

## 1. 게임이 82개인데 기본 목록은 48개에서 끝납니다

대상: https://game.1989v.com/

운영 공개 목록 응답은 `totalElements=82`, `size=48`, `totalPages=2`, `last=false`입니다. 로컬 `GamesPage.tsx`는 `size:48`로 첫 페이지만 요청하고 `page.content`만 저장합니다. 목록 끝에는 더 보기나 다음 페이지가 없습니다. 별도 장르·큐레이션·검색엔진 링크로 나머지 게임에 도달할 가능성은 있으므로 “34개가 완전히 접근 불가”라고 단정하지 않습니다. 다만 기본 목록의 순차 탐색은 끝까지 이어지지 않는 구조입니다.

**개선:** `48 / 82개`와 더 보기 제공 → 추가 로드 후 스크롤 유지 → 상세에서 돌아오면 필터와 읽던 위치 복원. 게임명을 아는 사람을 위한 제목 검색도 후속 후보입니다. Poki는 이름을 찾는 입력과 장르 탐색을 함께 제공합니다. [비교: Poki](https://poki.com/)

완료 기준: 기본 목록에서 82개를 중복 없이 모두 탐색하고, 마지막 페이지에 도달하면 더 보기가 사라짐. 운영 브라우저에서 필터 조합과 뒤로 가기를 재확인해야 합니다.

근거: `evidence/game-catalog-audit.json`, `portal-fe/src/pages/games/GamesPage.tsx:142`, `portal-fe/src/api/gameApi.ts:190`.

## 2. 사태의 소개와 인원 표시가 서로 다릅니다

대상: https://game.1989v.com/games/landslide

운영 초기 본문에는 “빠른 대전·코드 방·초대 링크로 사람과 1대1”이라고 쓰여 있지만 요약은 “1인 / 약 5분 / 모바일 지원”입니다. 로컬 상세 화면은 `playerMode === MULTI`일 때만 “2인 이상”, 나머지는 “1인”으로 표시합니다. 혼자 연습과 온라인 1대1을 모두 지원하는 게임을 단일 값으로 설명하기 어렵습니다.

**개선:** 실제 지원 모드를 확인한 뒤 “혼자 연습 · 온라인 1대1”처럼 표현합니다. 상세 소개, 요약 배지, 필터 조건, 초기 HTML을 동일한 데이터로 생성합니다. 미구현 예고인 “창병·방패병·팀전·아이템은 다음 단계”는 현재 기능 설명과 구분합니다.

완료 기준: 소개·배지·검색 분류가 같은 지원 범위를 설명함. 이번 조사에서는 실제 멀티플레이 작동 여부를 검증하지 않았습니다.

## 3. 블로그 비교표의 구조가 초기 HTML에서 사라집니다

대상: https://blog.1989v.com/posts/opensearch-knn-lucene-vs-faiss-memory

운영 응답에 `| 항목 | lucene | faiss |`와 구분선이 문자열로 남고 `<table>` 요소는 0개입니다. `[!NOTE]`, `[!IMPORTANT]`도 원문 표기가 남습니다. 로컬 브라우저 렌더는 `marked`의 GFM과 별도 확장을 쓰므로 **브라우저 최종 화면도 깨진다고 단정할 수는 없습니다.** 문제는 초기 본문과 최종 본문의 의미 구조가 다르다는 점입니다.

**개선:** 서버 렌더에서도 표·알림·코드 블록을 의미 있는 HTML로 변환합니다. 기존 HTML 정화 정책을 유지하면서 두 렌더 경로의 출력 계약을 맞춥니다. 기술 비교 글의 핵심 표부터 적용하면 효과를 확인하기 쉽습니다.

완료 기준: JS 실행 전후 모두 동일한 열·행의 표를 읽을 수 있고, 알림 제목과 본문이 보존됨. Google은 사전 렌더링이 크롤러에도 유용하며 모든 봇이 JS를 실행하는 것은 아니라고 설명합니다. [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)

## 4. 검색 구조화 데이터가 실제 진입점과 어긋납니다

대상: https://1989v.com/ · https://1989v.com/search?q=Kafka

운영 메인의 `WebSite.potentialAction`은 `/search?q={search_term_string}`를 가리킵니다. 해당 URL은 200이지만 본문이 없는 기본 앱 HTML을 반환합니다. 로컬 라우터에는 `/search`가 없고 `/tech`에 개념 검색 화면이 연결됩니다. 로컬 `copy.mjs` 기본 템플릿은 이미 `/tech?q=…`여서 운영 생성 결과와도 다릅니다. 검토한 `SearchPage.tsx`에서는 URL의 q를 초기 검색에 연결하는 코드를 찾지 못했습니다.

**개선:** 우선 검색 deep link가 필요한지 결정하고, 필요하면 URL의 검색어를 실제 입력·결과와 연결합니다. 생성 HTML과 앱 실행 후 JSON-LD를 대조합니다. 기능을 제공하지 않는다면 SearchAction을 제거하는 것도 적절합니다. 단순히 주소 문자열만 교체하는 것으로 완료 처리하지 않습니다.

완료 기준: 구조화 데이터의 주소를 직접 열면 동일한 검색어와 결과가 나타나거나, 지원하지 않는 검색 동작이 구조화 데이터에서 제거됨.

## 5. 영문 관광 페이지의 마지막 구간까지 번역을 이어갑니다

대상: https://place.1989v.com/en/attractions/13686

운영 본문에 `Village Tourism Siteas 1 of 5 attractions in Gangdong-gu`라는 붙어 있는 표현이 있습니다. 버스 정류장명은 한국어이고 공통 푸터의 “무료 웹게임”, “한국 관광지 검색”, “개인정보처리방침”도 한국어입니다. 고유명사의 원어 병기는 도움이 되지만 내비게이션 자체는 영문 사용자가 이해할 수 있어야 합니다.

**개선:** 문장을 `One of 5 attractions in Gangdong-gu · Village tourism`처럼 분리하고 푸터·상태 메시지의 언어를 통일합니다. 정류장명은 원어를 유지하되 가능한 경우 영문/로마자명과 복사 기능을 제공합니다. 원천 번역이 없는 이름을 임의 번역하지 않습니다.

완료 기준: 영문 대표 상세·빈 상태·오류·푸터를 한 흐름으로 읽을 수 있음. 이번 표본은 영문 허브와 상세 1개로, 전체 영문 페이지의 오류율은 산출하지 않았습니다.

## 6. 메인에 서비스 이용자를 위한 직접 진입점을 둡니다

대상: https://1989v.com/

로컬 히어로는 “서비스를 처음부터 끝까지 만듭니다”와 “지나온 것 보기” CTA로 구성됩니다. 포트폴리오 목적에는 맞지만, 게임이나 관광 서비스를 이용하려는 방문자에게는 경력보다 서비스 진입이 먼저 필요할 수 있습니다. 서비스 본문에는 실제 데이터 카드와 직접 링크가 이미 있으므로 이를 없애기보다 첫 선택을 분명하게 만드는 제안입니다.

**개선안:** 히어로에 `서비스 둘러보기`와 `경력·프로젝트 보기`를 함께 두고, 대표 서비스 2~3개는 용도 중심으로 짧게 소개합니다. 예: “설치 없이 게임 한 판”, “지역별 여행지 찾기”. 경력 데이터가 없을 때 `#portfolio` 대상 없이 CTA만 남지 않도록 fallback도 둡니다.

이는 **전환 개선 가설**이며, 첫 화면 높이·CTA 시인성은 확인하지 못했습니다. 홈페이지가 목적을 설명하고 다음 목적지를 찾게 해야 한다는 NN/g 원칙을 적용한 제안입니다. [NN/g 홈페이지 지침](https://www.nngroup.com/articles/113-design-guidelines-homepage-usability/)

완료 기준: 처음 방문한 사람이 서비스 이용과 운영자 경력 확인을 각각 쉽게 시작함. 클릭률뿐 아니라 목적 페이지 도달률도 측정합니다.

## 7. 필터 상태와 오류 복구를 목록의 기본 기능으로 만듭니다

대상: 게임·메인·블로그·랭킹 목록.

게임의 장르는 URL에 있지만 태그·정렬은 로컬 state입니다. 상세 이동 후 돌아오는 흐름에서 선택이 사라질 가능성이 있습니다. 메인·블로그·랭킹의 일부 오류 분기는 안내 문구만 제공하고 명시적 재시도 버튼은 없습니다. 현재 장애가 발생했다는 뜻은 아닙니다.

**개선:** 목록 선택과 스크롤을 복원하고, 실패 상태에 `다시 불러오기`를 제공합니다. 필터를 query parameter로 저장하더라도 canonical은 기본 목록으로 유지하는 등 상태 복원과 색인 정책을 분리할 수 있습니다. 게임 필터의 선택 상태를 `aria-pressed` 등으로 전달하고 동적 결과/실패 안내를 보조기술에서도 인지하도록 확인합니다. [W3C 상태 메시지 기법](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22.html)

완료 기준: 상세→뒤로 가기 후 같은 목록으로 돌아옴. 실패→재시도가 페이지 전체 새로고침 없이 동작. 키보드와 스크린리더 재검증 필요.

## 8. 준비 중인 랭킹 서비스의 공개 안내를 통일합니다

대상: https://rank.1989v.com/

전시 API에서는 랭킹이 `PREOPEN`입니다. 그러나 다른 사이트의 초기 HTML 푸터에는 일반 “랭킹 리더보드” 링크가 있습니다. 공개 랭킹 API는 정상 200에 빈 배열을 반환했습니다. 따라서 **현재 데이터가 빈 것은 관찰 사실이며 서비스 장애로 분류하지 않습니다.**

**개선:** 준비 중으로 안내할지 공개 목록에서 잠시 제외할지 통일합니다. 링크를 유지한다면 도착 페이지에서 현재 제공 범위와 준비 상태를 명확히 알리고 다른 서비스를 이용할 경로를 둡니다. 데이터가 생긴 뒤 활성화하는 기준도 정의합니다.

완료 기준: 전시 타일·푸터·도착 페이지가 같은 운영 상태를 설명함. 데이터 수집 실패와 아직 개시하지 않은 상태를 구분함.

## 9. 혜택 모음을 ‘링크 목록’에서 ‘선택에 도움이 되는 정보’로 보강합니다

대상: https://deal.1989v.com/

초기 본문은 9개의 상시 이벤트/프로모션 링크 소개로 구성됩니다. “타임딜”, “쿠폰팩”처럼 넓은 혜택 표현이 많아, 방문자가 자신에게 적용되는 조건을 다시 외부 사이트에서 확인해야 합니다. 초기 HTML에는 개별 혜택 이동 링크가 없고 공통 푸터 링크만 있습니다. 로컬 앱은 `/go/{slug}` 카드 링크를 생성하므로 JS 전후 탐색성도 다릅니다.

**개선:** 구체적인 혜택을 확정할 수 없는 항목은 “이벤트 모음”으로 구분합니다. 확인 가능한 항목에는 대상(신규/기존 회원), 최소 구매, 기간, 최종 확인일, 제외 조건을 붙입니다. 조건이 바뀌는 프로모션은 원문 확인을 안내합니다. 초기 HTML에서도 동일한 안전한 이동 링크를 제공합니다. 기존 카드 단위 제휴 고지는 유지합니다.

완료 기준: 사용자가 클릭 전 적용 가능성과 정보 최신성을 판단할 수 있음. 이번에는 외부 제휴 목적지와 실제 할인 조건을 검증하지 않았습니다.

## 10. 관광 상세의 방문 정보는 요약과 원문을 구분합니다

대상: https://place.1989v.com/attractions/1

경복궁 상세는 운영시간·요금·휴무·접근성·가까운 역과 정류장을 갖춰 이미 실용적입니다. 다만 운영시간이 계절별로 붙은 긴 문자열이고, 휴무/주차는 요약과 원문이 연속으로 나와 중복됩니다. “수집일: 정보 없음”도 표시됩니다. 실제 화면의 줄바꿈은 미확인입니다.

**개선:** 계절별 운영시간은 표/목록으로, 휴일은 요약 1줄과 예외 안내로 정돈합니다. 원천 갱신일과 수집일을 구분하고, 수집일을 알 수 없으면 그 한계를 짧게 안내합니다. 확인되지 않은 데이터로 “오늘 영업 중”을 단정하지 않습니다.

후속 콘텐츠 실험으로는 행정구역 목록에 “서울 궁궐 반나절”, “비 오는 날 실내” 같은 짧은 동선을 얹을 수 있습니다. VISITKOREA의 공식 자료도 지역·테마별 코스와 방문 전 운영시간/요금 확인을 함께 안내합니다. [VISITKOREA 지역 여행 자료](https://english.visitkorea.or.kr/public/assets/medical_asset/pdf/eng_seoul_Gyeonggi.pdf)

완료 기준: 중요한 방문 정보를 빨리 찾고, 날짜와 예외 조건의 출처를 확인할 수 있음. 추천 동선은 이동 거리와 개방 조건을 검증한 소수부터 운영.

## 11. 오류 URL은 현재의 클라이언트 보호를 유지하며 초기 응답도 개선합니다

대상: https://1989v.com/audit-nonexistent-20261018

이 임의 URL의 초기 응답은 200이고 robots noindex 메타가 없습니다. 다만 로컬에는 NotFoundPage와 JS로 noindex를 설정하는 구현이 이미 있습니다. Google도 SPA의 대안으로 JS noindex를 안내하므로 **오류 페이지 대책이 전혀 없다고 평가하면 안 됩니다.**

**개선:** 가능하면 알려지지 않은 경로에 실제 404와 복구 링크를 반환합니다. 어려우면 현재 noindex가 운영 렌더 후 정확히 적용되는지 우선 검증합니다. 모든 동적 상세를 404로 만드는 포괄적인 nginx 변경은 피하고 유효한 deep link 보존을 함께 확인합니다. [Google의 SPA soft 404 처리](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics#avoid-soft-404-errors-in-single-page-apps)

완료 기준: 존재하는 deep link는 정상 진입하고, 없는 주소는 명확한 오류 상태와 홈 이동 경로를 제공함.

## 12. 성능은 장식을 제거하기 전에 실측합니다

메인은 서비스·타임라인·오픈소스 조회 외에 관광 최대 80개, 게임 최대 100개 등을 쇼케이스용으로 조회합니다. 화면 아래 콘텐츠도 컴포넌트 마운트 시 조회합니다. 먹 효과와 카드 애니메이션도 있습니다. 이것만으로 느리다고 판정할 수는 없습니다. 터치 기기 별도 처리, 이미지 지연 로딩, 기능별 lazy import 등 최적화도 이미 보입니다.

**개선:** 대표 모바일 기기에서 첫 방문/재방문을 분리해 측정하고, 화면 밖 조회는 필요 시점으로 미루는 실험을 합니다. 서비스 기본 링크는 API 완료 전에도 사용할 수 있게 유지하는 것이 좋습니다.

판정 기준 후보: 실제 사용자 75백분위 LCP ≤2.5초, INP ≤200ms, CLS ≤0.1. 이는 공식 기준이며 **이번 사이트의 측정 결과가 아닙니다.** curl 요청 시간도 화면 로딩 시간으로 해석하지 않았습니다. [web.dev 기준](https://web.dev/articles/defining-core-web-vitals-thresholds)

## 유지할 강점

- 게임 허브·장르·상세, 관광 지역·상세, 블로그 본문에 검색 가능한 초기 HTML이 있습니다. “SPA라서 전면 SSR 전환이 필요하다”는 처방은 과합니다.
- 게임의 설치/회원가입 없는 진입 설명, 장르 링크, 목표·조작법·첫 플레이 팁은 이미 있습니다. 없는 기능으로 취급해 다시 만들 필요가 없습니다.
- 관광 상세는 출처·원천 갱신일·직선거리 주의·접근성 정보를 제공합니다. “가까운 곳”과 “다른 지역의 비슷한 곳”도 연결되어 있습니다.
- 블로그는 실제 기술 판단과 측정 사례를 담고 있어 포트폴리오와 연결하기 좋은 콘텐츠입니다.
- 혜택 카드의 제휴 고지, 랭킹의 데이터 커버리지 안내, 호스트별 메타데이터와 canonical 등 운영 기반이 갖춰져 있습니다.

## 권장 실행 순서와 검증

1. **작은 정확성 수정:** 게임 인원·소개 일치, 영문 오타/푸터, 검색 구조화 데이터 정합성. 기존 운영 데이터와 배포 버전 차이부터 확인합니다.
2. **탐색 완결성:** 게임 82개 끝까지 보기, 목록 상태 복원, 오류 재시도. 새 게임을 추가하는 것보다 기존 게임 발견성을 먼저 개선합니다.
3. **콘텐츠 전달:** 블로그 초기 표 렌더, 관광 방문 정보 정돈, 혜택 조건/확인일, 준비 중 상태 통일.
4. **브라우저 검증 후 실험:** 메인 CTA·모바일 카드 탐색·성능. 방문 목적별 도달률, 목록→상세, 상세→플레이/길찾기를 기준으로 판단합니다. 현재 전환율과 예상 상승률은 산출하지 않았습니다.

브라우저가 연결되면 390px 모바일과 데스크톱에서 메인→서비스, 게임 필터→상세→뒤로 가기, 관광 검색→상세→지도, 영문 전환, 긴 블로그 표를 우선 확인해야 합니다. 게임 실행은 이번에 수행하지 않았고, 멀티플레이 방 생성·위치 권한·로그인은 별도 범위입니다.
