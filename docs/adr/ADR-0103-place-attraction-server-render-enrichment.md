# ADR-0103 — 관광지 상세는 search 가 서버 렌더하고, 인리치먼트는 색인 시점에 한다

- 상태: 채택 (2026-09-30, 제안 2026-09-29)
- 관련: ADR-0062(SEO·프리렌더, §8 상세 선별 프리렌더 · §13 셸 오염), ADR-0072 §6(블로그 서버 렌더),
  ADR-0076(AdSense), ADR-0090(통합 검색), ADR-0095(노출·클릭 원장), ADR-0065/0071(place)
- 스펙: `docs/specs/2026-09-29-place-ssr-enrichment/`

## 맥락

관광지 URL 55,524개가 sitemap 에 있지만 크롤러 첫 응답에 본문이 있는 것은 프리렌더한 6,000개뿐이다
(ADR-0062 §8 의 `PLACE_DETAIL_CAP` — 이미지에 구우므로 용량이 예산). 나머지 약 4만 9천 개는 4,623B 셸,
제목 `1989v`, 문단 0개로 나간다. 2026-08-31 AdSense 반려(「가치가 별로 없는 콘텐츠」)의 주 원인 후보다.

또 페이지 본문이 TourAPI 원문을 옮긴 것이라 다른 곳과 내용이 같다. 원문 이상의 정보가 필요하다.

코드를 보면 상세 화면·검색·(앞으로의) 서버 렌더가 모두 **search 가 가진 관광지 문서 하나**를 읽는다
(`AttractionSearchAdapter.findById`).

## 결정

1. **서버 렌더는 search:app 이 하고, portal-fe nginx 가 앞에 선다.** place 호스트의 `/attractions/{id}`·
   `/en/attractions/{id}` 는 지금처럼 portal-fe 로 들어오고, nginx 가 search 의 `/internal/render/attractions/{id}`(공개 라우트 밖)로
   프록시한다. 404 는 그대로 내고, 시간 초과·5xx·연결 실패면 SPA 셸로 떨어진다. 이렇게 하는 이유:
   - search 는 파드가 하나라 재기동 동안 게이트웨이 경유면 상세 5만 5천 개가 빈 200 이 된다. nginx 폴백은 화면을 살린다.
   - 공개 게이트웨이에 경로가 없으니 Cloudflare 를 거치지 않는 호스트(`rt.1989v.com`)로는 렌더에 닿지 않는다.
   - ingress 를 바꾸지 않는다.
   데이터 주인이 렌더하므로 요청 경로에 서비스 간 호출이 없고 관광지당 ES 조회 한 번이 그대로다.
   셸 계약·캐시·폴백은 블로그(ADR-0072 §6)를 따르되 셸 받기 시간 초과(1초)와 실패 백오프(30초)를 더한다.
   1초는 nginx 읽기 한도(3초)보다 작아야 해서다 — 셸 캐시가 만료된 요청도 서버 렌더로 나간다.
   블로그와 두 번째 사용처라 셸 제공자는 **복사**한다(세 번째가 생기면 공통 모듈로 — Rule of Three).
2. **서버 렌더는 실제 상태 코드를 준다.** 없는 id 는 404. SPA 폴백이 못 해서 `noindex` 로 대신하던 일이다(ADR-0062 §13).
3. **관광지 상세 프리렌더는 운영 확인 뒤 제거한다**(ADR-0062 §8 을 대체). 이미지 약 54MB 감소. 지역 프리렌더는 유지.
4. **속성 추출·지역 집계는 색인 시점에 search:domain 순수 함수가 한다.** 모든 소비자가 search 문서를 읽으므로
   파생값을 place 에 저장하지 않는다. 원천은 place 가 이미 접어 둔 컬럼을 읽는다(유형별 키 매핑을 세 번째로
   복사하지 않는다). 파서를 고치면 다음 재색인이 전량을 다시 계산한다 — 백필이 없다.
5. **유사 관광지는 임베딩과 같은 경로다.** 오프라인 도구가 계산해 place 의 새 표 하나(`attraction_similar`)에
   적재하고, 재색인이 조회한다. 재색인 중 6만 건 kNN 은 무료 노드에서 감당할 수 없다.
6. **클릭 신호는 ADR-0095 §6 대로 집계 표를 직접 읽는다.** §6 은 analytics 가 가진 `attraction_popularity_daily`
   를 공개 읽기 모델로 정했고 소비자에 검색 랭킹이 이미 있다. 원장 스키마의 주인은 analytics 로 남는다.
   신호는 **14일 고유 클릭 방문자 수**(`uniqState`/`uniqMerge`, `anonymous` 제외)다 — 노출은 순위의 결과라 쓰지 않는다.
   원시 건수보다는 낫지만 `visitor_id` 는 클라이언트 값이라 조작을 막지는 못한다. 그래서 작은 가중치로만 쓴다.
   순위 반영(`clickBoost`, 상한·최소 표본)은 스위치를 꺼 둔 채 배포하고, 짝지은 nDCG 가 떨어지지 않을 때만 켠다.
   `popularityScore`(정보 충실도)는 그대로다.

## 대안

- **프리렌더 상한 올리기** — 전량이면 이미지가 수백 MB, 푸시마다 OCIR 월 10GB 를 빠르게 먹는다. 기각.
- **프리렌더를 이미지 밖(오브젝트 스토리지)으로** — 저장·배포 경로가 새로 생기고 데이터가 바뀔 때마다 다시 찍어야 한다. 요청 시 렌더가 더 단순하다.
- **place(content:app)가 렌더** — 블로그와 같은 JVM 이라 셸 제공자를 공유할 수 있지만, 데이터가 search 에 있어 요청마다 서비스 간 호출이 생긴다. 기각.
- **게이트웨이 경유 렌더** — 블로그와 같은 모양이지만 search 재기동 중 빈 200, 우회 호스트 노출 문제가 있다. 기각.
- **analytics 내부 API 로 클릭 신호 제공** — ADR-0095 §6 과 충돌하고 새 네트워크 정책·API 가 는다. 기각.
- **파생 속성을 place 컬럼으로** — 마이그레이션·백필·전체 동기화 보존(`syncFrom ?: existing`) 부담이 생기고, 소비자가 없다. 기각.

## 결과

- 크롤러가 받는 관광지 본문: 6,000 → 55,524 (목표). 응답마다 search 가 한 번 조회한다. 2026-09-27 ingress 48시간 표본에서 메타 크롤러 0건 · Googlebot 6건이었다.
- 네트워크 정책 둘: portal-fe → search(렌더 프록시), search → portal-fe(셸).
- place 에 표 하나(V22), analytics 일 집계 표에 컬럼 하나(ClickHouse V007).
- 관광지 문서 필드가 는다. 필터 대상만 keyword, 나머지는 `index:false` 로 페이지 캐시 부담을 줄인다.

## 운영 결과 (2026-09-30)

수치는 스펙 `verifications/status.md` 의 실측이다.

- **서버 렌더(T19)**: 밖에서 Googlebot UA 로 프리렌더에 없던 `/attractions/5000` 요청 → 200 · `X-Render: ssr` ·
  9,141B · 문단 4개(전: 4,623B · 제목 `1989v` · 문단 0). 없는 id 는 404, 비숫자 id 는 nginx 404,
  `/regions/*` 프리렌더는 그대로, 우회 호스트의 `/internal/**` 는 404.
  search 중단 시 셸 폴백·쿠키 미전달은 스텁 search + 실제 nginx 로만 확인했다(단일 파드 롤링이라 운영에서 끊김 구간이 생기지 않는다).
- **재색인**: 9분 34초~12분 → 5분 1초(키셋 페이징 뒤), 유사 목록 합류 뒤 316초. 색인 크기 283MB → 296.2MB(속성) → 307.2MB(유사 목록).
- **속성 패싯 건수(T22)**: API 건수와 OpenSearch `_count` 가 일치 — 주차 31,605 · 무료 입장 1,127 · 반려동물 9,070 · 주차 선택 시 반려동물 7,189.
- **비슷한 곳(T23)**: 표본 50에서 대분류 일치 86.0% · 소분류 61.2%.
- **클릭 신호(T16)**: 짝 48 · 순서가 바뀐 질의 0 · ΔnDCG +0.0000 → 판정 보류, 스위치는 꺼진 채다. 고유 클릭 방문자가 쌓이면 다시 잰다.
- 관광지 상세 프리렌더는 제거했다(결정 3). 이미지 크기 전후는 배포 뒤에 잰다.

구현 중 바뀐 것:

- **place 목록은 키셋 페이징**(`afterId`·`nextAfterId`). OFFSET 59,000 이 4.9초 걸려 첫 운영 재색인이 14분 멈췄다(키셋 266ms). 배치의 place 클라이언트에 연결 5초·응답 60초 한도. OFFSET 경로는 파이썬 호출자용으로 남는다. place 가 search-batch 보다 먼저 배포돼야 한다.
- **렌더 표지 셋**: `ssr` · `shell-fallback`(search 가 색인 조회에 실패해 셸을 냄) · `proxy-fallback`(nginx 가 5xx·시간 초과·연결 실패로 셸을 냄). 운영 확인이 폴백을 성공으로 세지 않게 한다.
- **상세 응답에 `contentTypeId`·속성·지역**을 싣는다. 하이드레이션이 서버 JSON-LD 를 다시 쓰므로 화면도 서버 렌더와 같은 값을 받아야 한다. 읽기 문서에서 필드를 빠뜨린 사고는 계약 게이트가 아니라 역직렬화 테스트가 잡았다.
- **클릭 집계 날짜는 KST**(`toDate(timestamp, 'Asia/Seoul')`). ClickHouse 가 UTC 라 03:30 KST 에 접는 「어제」에서 KST 마지막 몇 시간이 빠졌다. place-ingest 가 읽는 합계에도 같이 적용된다.
- **`clickBoost` 는 검색어 있는 키워드 레그에만**, 스위치 기본 꺼짐. 벡터 단독·상업 의도·브라우즈 목록·자동완성은 제외.
- **패싯 건수는 opt-in**(`facets=true`). 상세의 주변·편의시설·지도가 같은 API 를 불러 매번 세면 상세 한 번에 집계가 두 번 는다. 목록 첫 쪽만 요청한다.

## 덧붙임 — 행사·숙박·여행코스 (2026-10-02, ADR-0104)

- **유형별 본문**: 행사(일정·상태 문구) · 숙박(입실·퇴실) · 여행코스(코스 구성 순서)는 일반 「이용 안내」 대신 자기 절을 그린다.
  제목·설명·JSON-LD(`Event` · `LodgingBusiness` · `TouristTrip`)도 유형별이고 패리티 테스트가 `copy.mjs` 와 대조한다.
  이름이 이미 「코스」로 끝나는 여행코스는 「여행코스」 접미를 붙이지 않는다(운영에서 「… 코스 여행코스」 중복을 보고 고쳤다).
- **출처 문구**: 새 유형도 같은 「출처: 한국관광공사 TourAPI」 절을 단다. 행사 원문에 주최측 이미지·문구가 섞여도 공공누리 유형은 행마다 원문(`cpyrhtDivCd`)에 남는다.
- **행사 sitemap**: 행사는 정적 sitemap 에서 빠지고, place 호스트 `/sitemap-places-events.xml` 을 이 ADR 의 렌더 프록시 경로로 search 가 요청 시점에 만든다.
  조회 실패는 503 이다 — 빈 200 은 행사 URL 이 전부 사라졌다는 뜻이 된다.

## 개정 — 배포가 옛 해시 자산을 바로 지우지 않는다 (2026-10-04)

- **문제**: portal-fe 이미지에 그 빌드의 `/assets` 만 들어 있어, 배포 순간 옛 해시 파일이 전부 404 가 됐다.
  셸을 5분 캐시하는 search(블로그도 같다)가 그동안 옛 `index-*.js` 를 가리켜 상세의 화면 스크립트가 붙지 않았다
  (2026-10-03 운영 확인, 새 파드에서 옛 번들 404).
  롤링 중 옛 파드와 새 파드가 섞인 구간, 배포 전에 열어 둔 탭이 나중에 받는 청크도 같은 원인이다.
- **결정**:
  - **옛 자산 유지.** 이미지가 최근 10개 릴리스 몫의 해시 자산을 함께 서빙한다(`portal-fe/scripts/retain-assets.mjs`).
  - CI 는 지금 배포된 태그의 이미지에서 `/assets`·릴리스 목록을 꺼내 빌드 컨텍스트에 둔다.
  - 빌드는 최근 목록에 든 파일만 합치고, 이번 목록을 서빙 루트 밖(`/usr/share/nginx/asset-releases`)에 남긴다.
  - 목록으로 자르므로 옛 파일이 끝없이 쌓이지 않는다. 직전 이미지를 못 받으면 경고만 내고 이번 것만으로 빌드한다.
  - **청크 실패 시 한 번 새로고침.** 10개 릴리스보다 오래 열어 둔 탭은 `vite:preloadError` 를 받아 한 번 새로고침한다
    (`shell/staleChunkReload.ts`, 10초 안 재실패는 새로고침하지 않는다).
- **셸 캐시 5분은 그대로 둔다.** 옛 셸이 가리키는 파일이 남아 있으므로 문제가 되지 않는다. 캐시를 줄이는 것은
  깨지는 구간을 좁힐 뿐이고 롤링·열린 탭은 못 막는다.
