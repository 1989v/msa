# ADR-0104: Woodland Haven 공유 월드의 첫 서버 구현

- 상태: 공유 월드 우선 구현 승인(2026-10-18), 공개 베타 연동 승인(2026-10-23, 아래 운영 계약이 로컬 제한을 확장)
- 관련: ADR-0059, ADR-0088, ADR-0102

## 결정
기존 DOM 없는 JavaScript 규칙을 Node 서버가 실행한다. 브라우저는 행동 의도만 제출하며 서버가 거리·충돌·재료·내구도·쿨다운을 판정한다. 기존 호스트 권위 릴레이는 중도 참여와 영구 월드 요구에 맞지 않아 변경하지 않는다. 새 JVM이나 플랫폼 DB 의존은 추가하지 않는다.

첫 실행 대상은 loopback의 단일 프로세스, 최대8명 협동 월드다. HTTP 명령과 SSE 상태 전달을 사용한다. 공유 자원·건물·식물·동물과 개인 위치·가방·도구·탐험을 분리한다. 서버 시간으로 공유 성장을 한 번만 계산하며 개인 메뉴나 탭 숨김이 월드를 멈추지 않는다. 서버 종료 동안의 성장 소급은 이번 범위 밖이다.

서버 전용 디렉터리에 버전 있는 전체 월드 기록을 원자 교체한다. 경제 명령은 저장 성공 뒤에만 성공 응답을 보낸다. 쓰기 실패는 진행 성공으로 표시하지 않는다. 손상된 기록은 조용히 초기화하지 않는다. 같은 데이터 디렉터리를 두 서버가 동시에 쓰지 못하게 한다.

로컬 서버 발급 불투명 게스트 자격으로 재접속을 구분한다. 이 자격은 기존 플랫폼 계정과 다르며 외부 배포 전 ADR-0102 프로필과 연결해야 한다. 서버 디렉터리는 정적 서빙에서 제외한다. Origin/Host, 요청 크기·빈도·동시접속 제한을 둔다. 기존 localStorage 저장을 온라인 월드로 업로드하거나 신뢰하지 않는다.

## 결과 및 제한
게임 규칙 중복 구현 없이 두 클라이언트 경합과 재시작 복원을 검증한다. 파일 저장·단일 프로세스는 첫 로컬 실행 경계이며 공개 운영, 다중 인스턴스, 플랫폼 인증 연동과 DB 영속화는 후속 설계다. PvP와 소유권/약탈 정책은 도입하지 않는다. 기존 싱글플레이 주소와 저장은 유지한다.

2026-10-18 도끼 장착 확장: 개인 상태에 optional `equipped`(null|axe)를 추가한다. 기존 기록은 null로 이행하고 새 기록은 소유한 정상 도끼만 장착 가능하다. equip/공격 내구도는 기존 직렬·원자 저장과 명령 순번 중복 방지를 그대로 사용한다. 플랫폼 DB/서비스 경계 변경 없음.

2026-10-18 건축 회전 확장: 공유 건축물과 build 의도에 optional `rotation`(정수0..3)을 추가한다. 누락된 기존 기록/명령은0으로 해석하며 잘못된 값은 거부한다. 방향은 시각적 바닥 배치에 적용하고 기존 원형 충돌 반경을 유지한다. 기존 직렬 명령/원자 저장/스냅샷 경로를 사용하며 플랫폼 경계는 변경하지 않는다.

2026-10-18 대형 월드/주택 확장: 32000×24000의 정적 결정적 자원과 기존 공간 인덱스/LRU를 사용한다. 기존 자원ID와 좌표는 보존한다. 게임 저장v4는 개인별 탐험 격자 좌표 이행과 compact 탐험 저장/전송을 도입하며 기존 공유record1은 계속 읽는다. 모듈식 주택에는 이동 충돌과 레이어 설치 충돌을 구분하고 문/철거는 오프라인을 포함한 모든 영구 플레이어 위치·귀환점을 보호한다. 서비스 추가/플랫폼DB 변경 없이 기존 로컬 권위 서버의 확장이며 실제8접속/64영구 게스트의 크기·처리 비용을 검증한다.

A 규모 실측에 따른 보완: 최대 자원 변경 상태의8snapshot이16.52MB/직렬화59.3ms이므로 자원의 remaining/regrowAt/forageReadyAt만 수신자 주변 공간 인덱스 범위로 제한한다. 범위 메타데이터를 포함해 전체 월드 저장과 구분한다. 서버의 전체 권위·원자 저장과 경제 명령 순번은 유지한다. 클라이언트는 온라인 snapshot을 오프라인 저장으로 쓰지 않는다.

2026-10-19 건축 재설계1단계: 신규벽/문/창문은floorId+rotation으로바닥40격자의변에앵커한다. 클라이언트미리보기와서버가같은기하를사용하고인접칸의같은변을정규화해중복금지. 저장앵커는참조/좌표/방향을검증하며legacy중앙벽과완성형건물은강제이동/삭제하지않는다. 신규완성형주택/축사생성은비활성화하고fire/chest는생활제작진입으로분리한다. 계단층구조/다종동물/가변사육장은후속확정계약으로추가한다.

2026-10-19 후속 확정: 실제 다층 주택은 level0..2와 상하 floorId 계단 연결로 구현한다. 개인/캠프/건축의 층을 서버가 검증하고 이전 저장은 지상으로 보존(v5). 새로운 종별 포획은 기존 닭 가방 및 사육 기록을 보존하면서 토끼/양 수량과 종별 개체 보존식을 추가한다. 공유record v2에서 기존24 야생 actor를 유지하고 새32개를 결정적으로 추가한다. 크기조절 사육장은 기존 coops의 pen 직사각형 확장으로 저장하며 resize도 기존 원자 명령·순번 경로를 사용한다. 기존 서버/DB 경계를 바꾸지 않는다.

## 2026-10-23 — 승인된 공개 베타 운영 계약
- 사용자 승인: 공유 월드 운영 연동을 설계·구현한 뒤 main 통합·배포. 정적 싱글플레이만 배포하지 않는다.
- 하나의 협동 월드, 동시8명/영구 프로필64명. 만원은 명시 오류로 안내하며 기존 인원을 지우지 않는다.
- 기존 게임 프로필(ADR-0102)이 필수다. 콘텐츠 서비스가 전용30초 일회용 Woodland 접속권을 발급한다. Node는 필수 공유 비밀로 보호한 내부 redeem HTTP API로만 UUID/닉네임을 확인한다. Territory 접속권과 공유하지 않는다.
- POST /api/v1/games/woodland/tickets → ApiResponse<{ticket,expiresAt}>; POST /internal/games/woodland/tickets/redeem ({ticket}, X-Woodland-Bridge) → ApiResponse<{playerId,nickname}>, 잘못된 비밀/만료/재사용401. 공개 gateway는 /internal을 라우팅하지 않는다.
- Node 공개 API namespace /api/v1/games/woodland: POST /join({ticket}), GET /state,/events, POST /input,/command. /join은 Secure HttpOnly SameSite=Strict Path=/api/v1/games/woodland 쿠키를 발급한다. 세션1시간 만료 후 새 접속권으로 재인증한다. 외부 의존 실패503, 인증 실패401; 입력/명령의 기존 원자 저장 및 순번 계약은 유지한다.
- platformPlayerId를 기존24hex 개인ID에 별도 연결한다. 로컬 기록은 읽을 수 있지만 플랫폼 계정으로 자동 귀속하지 않는다. 운영은 새로운 PVC로 시작한다. 명령/상태에 자격증명 해시를 노출하지 않는다.
- Node24 단일 replica/Recreate, RWO PVC의 원자 fsync 저장. 비root·읽기전용root·한정 자원·상태probe·종료드레인. DB 공유/새 스키마 없음. Origin/Host는 명시 운영설정으로 제한하고 forwarded 헤더를 신뢰하지 않는다. SSE heartbeat/버퍼링 해제/timeout 해제.
- 월드 백업은 기존 OCI PAR의 Woodland 전용prefix로만 저장하고7일 보존한다. MySQL 백업은 변경하지 않는다. 별도 데이터 디렉터리 복원 연습을 실행한다. 노드 디스크의 PVC만으로 노드 소실을 복구할 수 없으므로 오프노드 백업 성공을 운영조건으로 둔다.
- 운영기본 진입은 공유 월드. offline=1은 명시 브라우저 싱글플레이, loopback online=1은 기존 로컬 기능을 보존한다.
- 배포 전 Node180개 회귀+운영인증/업스트림HTTP 실패·동시2명·재시작/복원,8접속/64개인 규모, Gradle 관련테스트/구조검증, FE빌드, 독립리뷰를 통과한다. UI도구 승인은 없음.

운영 보존 정정(2026-10-23): 7일 자동 보존은 로컬 백업에 적용한다. 쓰기 전용 PAR의 오프노드 사본은 기본 무기한이며 Woodland prefix 전용 lifecycle 설정 전에는 원격 삭제를 주장하지 않는다.
