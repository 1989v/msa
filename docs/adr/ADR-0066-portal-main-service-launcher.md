# ADR-0066 — 1989v.com 메인은 서비스 런처다

- 상태: 채택 (2026-08-11)
- 관련: ADR-0064(이력서 게이트 — 본 ADR 로 공개 범위 개정), ADR-0059(게임), ADR-0065(K-관광),
  ADR-0063(어드민 단일 호스트), ADR-0062(SEO)

## 맥락

현 메인(`portal-fe/src/pages/SearchPage.tsx`)은 코드 사전 시각화 데모가 되어 있다.
카운터 → 카테고리 칩 → 3D 캐러셀(5종) → 인기 개념 → 퀴즈 순으로 배치돼 있고,
정작 운영 중인 서비스(`place.1989v.com`, `game.1989v.com`, `/shop`)로 가는 길은
GNB 링크 한 줄이다.

한 화면이 서로 다른 두 목적을 동시에 떠안고 있었다.

1. 방문자가 **서비스를 골라 들어가는** 런처
2. 만든 사람의 **기술 역량을 보여주는** 포트폴리오

둘을 같은 스크롤에서 동시에 최적화하려다 양쪽 다 못 하고 있다. 서비스는 묻히고,
포트폴리오는 "할 수 있다"의 나열로 읽힌다.

초기 개편안은 반대 방향이었다 — 메인 전체를 경력 도메인 5종(검색/전시/커머스/인프라/AI)의
드릴다운 탐색기로 만드는 것. 이 안은 **메인을 포트폴리오 쪽으로** 완전히 밀어붙이는 선택이고,
그러면 운영 중인 서비스로 가는 길이 더 멀어진다.

## 결정

**메인은 런처다. 포트폴리오는 하단 섹션 하나로 접는다.**

```
1  브랜드 히어로 — 1989v
2  도메인 타일 그리드 — 활성 / 준비중(딤드)
3  포트폴리오 섹션 — 시간순 타임라인
4  About
5  Footer
```

기존 시각화(3D 그래프·트리맵·히트맵)는 삭제하지 않고 `/tech` 라우트로 옮겨
"IT" 타일이 받는다. 코드는 그대로 두고 진입 맥락만 바꾼다.

**퀴즈는 제거한다.** 시각화 3종은 옮기면 "데이터 시각화 역량의 증거"로 의미가 바뀌지만,
퀴즈는 어디에 두든 같은 신호를 낸다.

### 타일 축은 서비스도 경력도 아니다

타일은 **방문자가 실제로 들어가서 쓸 수 있는 진입점**이다.

| 타일 | 진입 | 상태 |
|---|---|---|
| 한국 관광 검색 | `place.1989v.com` | 활성 |
| 게임 | `game.1989v.com` | 활성 |
| IT | `/tech` | 활성 |
| 커머스 | `/shop` | 활성 — "데모" 명시 |
| 포트폴리오 | `/portfolio` | 활성 |
| 풀필먼트 | — | 준비중(딤드) |

기존 `service` 테이블(`/api/v1/services`)은 재사용하지 않는다. 그쪽은 **백엔드
마이크로서비스 목록**이라 `common`(공유 라이브러리)·`gateway:8080` 같은 항목과
ADR-0019 에서 삭제된 `discovery`(Eureka)가 남아 있고, 정작 `place`·`game` 은 없다.
사용자 진입점과 배포 단위는 다른 축이다.

**퀀트 · 기프티콘 · 에이전트뷰어는 비노출.** 프라이빗 서비스이고 `shell/placeholders.tsx`
껍데기만 있다. 딤드로도 걸지 않는다 — 준비중 타일이 많을수록 "진행 중인 게 많다"가 아니라
"끝맺은 게 없다"로 읽힌다. 딤드는 실제 로드맵인 풀필먼트 하나로 제한한다.

### 타일 목록은 DB 서버 드리븐 + 어드민 CRUD

`portal_tile` 테이블에 두고 admin.1989v.com 에서 관리한다. 서비스가 완성되면
어드민 토글로 딤드를 푼다.

| 컬럼 | 역할 |
|---|---|
| `code` | 식별자 |
| `label` / `tagline` | 타일 문구 |
| `href` | 진입 주소 (외부 호스트 · 내부 라우트 모두) |
| `status` | `LIVE` / `SOON`(딤드) / `HIDDEN`(비노출) |
| `order_no` | 정렬 |

`HIDDEN` 을 삭제 대신 두는 이유는 퀀트·기프티콘처럼 **존재하지만 노출하지 않는** 서비스를
행으로 남겨두기 위해서다. 지웠다가 다시 넣는 것보다 상태 전환이 명확하다.

### 포트폴리오 타임라인의 공개 범위

타임라인은 두 겹이다.

```
회사 재직 기간 = 배경 막대 (회사명 · 기간 · 직무)
개인 프로젝트  = 타임라인 위의 점 (제목 · 기간 · 요약 · 성과지표 · 태그)
```

데이터는 `resume_company` / `resume_project` 를 재사용한다. `resume_project` 는
`company_id NULL = 개인 프로젝트`로 이미 설계돼 있고, 어드민 CRUD(`/api/v1/admin/resume/*`)와
관리 화면(admin-fe `/resume/profile`)이 갖춰져 있다. 별도 포트폴리오 도메인을 세우면
관리 화면을 한 벌 더 만들고 프로젝트를 두 곳에 입력하게 된다.

**불변식: `company_id IS NOT NULL` 인 프로젝트는 어떤 공개 경로로도 나가지 않는다.**

- 공개 조회 쿼리에 `company_id IS NULL` 을 못박는다 (호출부 파라미터가 아니라 쿼리 자체에)
- 공개 응답의 프로젝트 DTO 에 회사 연결 필드를 두지 않는다 — 실수로 채울 필드가 없어야 한다
- 회사에 소속된 프로젝트가 공개 응답에 섞이지 않음을 테스트로 고정한다

## ADR-0064 개정 — 재직 기간·직무는 게이트 밖

ADR-0064 는 경력 전체를 `resume.1989v.com` 의 토큰 게이트 뒤에 두었다. 본 ADR 은
경계선을 **회사 단위에서 서술 깊이로** 옮긴다.

| 정보 | 위치 |
|---|---|
| 회사명 · 재직 기간 · 직무 | **메인 공개** (색인 대상) |
| 그 회사에서 무엇을 했는지 (성과 · 기여 범위 · 상세) | 게이트 뒤 (변경 없음) |
| 실명 · 연락처 | 게이트 뒤 (변경 없음) |

바꾸는 이유는 타임라인이 재직 기간 없이는 읽히지 않기 때문이다. 개인 프로젝트만 점으로
찍으면 "언제부터 개발했는지"가 사라져 11년차라는 사실이 화면에서 증발한다.

게이트가 지키려던 것은 **어느 회사에서 무엇을 했는가**이지 재직 사실 자체가 아니다.
재직 이력은 통상 공개 프로필(링크드인 등)에 있는 수준이고, 이 정도로는 지원본을 대체할 수 없다.
`resume_company.note` 는 자유 서술 필드라 공개 응답에서 제외한다.

## 결과

- 첫 화면에서 운영 중인 서비스가 보인다. 서비스 진입이 GNB 링크 한 줄에서 타일로 승격된다
- 서비스 활성화가 **데이터 변경**이 된다 — 어드민 토글, FE 재배포 없음
- 포트폴리오가 메인에서 사라지지 않고 타임라인으로 압축된다. 상세는 `/portfolio` 가 받는다
- 대신 **타일 하나 추가에 백엔드·어드민·FE 세 곳이 관여한다.** FE 상수 배열이었다면 파일
  하나였다. 무배포 토글의 대가다
- `code-dictionary` 장애 시 메인 타일이 뜨지 않는다. ADR-0064 가 이력서에 대해 감수한 것과
  같은 트레이드오프이고, 같은 파드를 쓰므로 위험이 늘지는 않는다
- 재직 기간·직무가 색인된다. 되돌리려면 색인 제거까지 필요하다 (ADR-0062 의 sitemap·robots 대상)

## 대안

- **FE 상수 배열** — 타일 6~9개이고 `href`·호스트 분기가 이미 `App.tsx` 에 하드코딩돼 있어
  파일 하나로 끝난다. 게다가 풀필먼트를 활성화하려면 그 화면 자체를 만들어 배포해야 하므로
  "무배포 활성화"의 실익이 크지 않다. **DB 를 택한 이유는** 타일 문구·순서·상태가 화면 자체와
  달리 자주 손보게 되는 값이고, 그때마다 FE 배포를 거는 것을 피하고 싶어서다
- **`service` 테이블 확장** — `href`·`status` 컬럼을 붙여 겸용. 마이그레이션 하나로 끝나지만
  배포 단위(`common` 라이브러리, `gateway`)와 사용자 진입점이 한 테이블에 섞인다
- **메인 = 드릴다운 포트폴리오 탐색기** (최초안) — L0 경력 도메인 5종 → L1 결정 서술 →
  L2 케이스 → L3 코드 경로. 포트폴리오로서는 더 강하지만 서비스 진입이 더 멀어진다.
  타임라인 항목 → `/portfolio` 상세로 축소해 흡수했다
- **타임라인에 경력 서술까지 공개** — 메인 하나로 끝나지만 ADR-0064 의 토큰·열람 기록·공개
  토글이 전부 무의미해진다. 제출처별 공개 제어를 포기할 이유가 없다
