# ADR-0112 — 카페 음료명 비교와 파생 식별값

- 상태: 승인된 2026-10-21 카페 2단계 요구사항 구현
- 관련: ADR-0081, ADR-0083, ADR-0093

## 결정

원천 `menu_name`을 유지하고 `drink_name`을 별도 저장한다. 순수 도메인 `DrinkNames.normalize`가 명시적인 경계 온도·사이즈(EX 포함) 표식을 제거하고 공백을 없앤다. 내부 단어를 지우거나 유사어로 치환하지 않는다. `빅`·`빽사이즈`는 상품 의미를 지니므로 남긴다. `디카페인`은 카페인 상태가 이미 별도 변형으로 구분하므로 이름에서 걷어 같은 음료의 변형으로 묶는다. `마키아또·마끼야또·마키아토`는 `마끼아또`로, `라테`는 `라떼`로 표기만 맞춘다(2026-10-21 리뷰 반영). `아이스크림`은 `아이스` 온도 접두사로 처리하지 않는다.

Flyway V4는 Java migration을 Kotlin으로 구현하여 동일 도메인 규칙을 호출해 기존 행을 보강한다. 위치는 ranking 전용 `classpath:rankingdb/migration`이며 원천 열과 기존 자연키를 변경하지 않는다. 신규·bulk 교체도 동일 규칙으로 파생값을 저장한다. 다른 스키마를 읽지 않는다.

이름 검색은 정규화된 이름별 브랜드 수와 원천 행 수를 반환한다. 이름 비교는 해당 이름의 모든 행을 읽어 브랜드별로 묶는다. 기존 페이지 API는 유지한다. 대표는 영양 최솟값이 아니라 공개 판의 결정적 선택이다. 사이즈 미표시/R/Regular/Tall → S/Short → M → L/Large/Grande → 기타 순, 온도 ICE → HOT → 미표시 순, 일반 → 디카페인 순과 원문명·사이즈·안정키로 동률을 해소한다. UI가 선택된 원문명·온도·사이즈·카페인 상태를 밝히고 전체 판 상세 진입을 제공한다. 정렬은 화면에 표시한 대표의 지표를 사용하며, 100ml는 반올림된 응답 농도 대신 원천 성분량/양수 용량을 BigDecimal 교차곱으로 비교한다. 카페인 미공개 상태는 원천 숫자가 있어도 정렬에 사용하지 않는다. 양방향 모두 null을 마지막에 둔다.

주변 기능은 기본 비활성이다. 활성화된 경우 상단 진입에서 준비 상태와 매장 판매 미확인 안내를 열고 선택적인 통합 콜백을 호출한다. 위치 권한·가상 매장·주변 API는 구현하지 않는다.

## 결과와 운영

V4가 기존 DB의 이름을 보강하지만 최신 원천과 컵 용량 파생값을 동기화하기 위한 브랜드별 재적재는 필요하다. 이번 작업은 배포·DB migration 실행·재적재를 수행하지 않는다. 코드딕셔너리 V20에 남아 있는 rank PREOPEN은 새 V32에서 rank만 OPEN으로 바꾼다. 기존 migration은 수정하지 않는다.
