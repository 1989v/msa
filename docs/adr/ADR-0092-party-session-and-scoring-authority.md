# ADR-0092: 파티 세션 — 게임 중립 방 · 아케이드 채점 스택 확장 · 친구 명부

- 상태: Proposed (2026-09-09)
- 관련: 스펙 `docs/specs/2026-09-09-party-session/` · 릴레이 N석 ADR-0088 · 폴드 ADR-0059 ·
  식별 최소화 ADR-0078 · 원장 보존 ADR-0077 · 레이어 표준 ADR-0083

## Context

한자리에 모인 사람들이 초대 링크로 모여 무엇을 할지 정하고 누가 걸렸는지 정하는 자리가 필요하다.
지금은 결정자 게임 셋(구슬 레이스·사다리타기·카드 뽑기)을 **한 기기로 돌려 보며** 쓴다.

기능을 얹으려면 세 가지가 걸린다.

1. **릴레이의 방은 「한 판 = 한 방」으로 굳어 있다.** 파티는 게임을 갈아타며 이어져야 한다.
2. **참여형 게임의 결과를 아무도 재지 않는다.** 릴레이는 페이로드를 열어보지 않는다.
3. **결정자 게임은 「참가자 이름은 이 기기 밖으로 나가지 않는다」를 공개 약속으로 걸어 뒀다.**
   친구 명부를 저장하는 순간 그 약속의 일부가 뒤집힌다.

### 먼저 정정 — 무권위 원칙의 출처

「릴레이는 규칙을 모른다」의 원본은 **`GameRelayRegistry` KDoc 과 `game/CLAUDE.md`** 다.
ADR-0088 이 이것을 「기존 무권위 원칙(ADR-0059)」으로 적었으나 **ADR-0059 본문에 릴레이·무권위는
한 글자도 없다**(폴드 배치 ADR 이다). 이 ADR 이후로는 원칙의 ADR 상 자리를 여기로 둔다.

## Decision

### A. 파티 방은 릴레이를 넓혀 만든다 — 새 엔드포인트를 내지 않는다

방 코드 발급·좌석 배정·속도 제한·유휴 정리가 이미 릴레이에 있고, 파티가 필요로 하는 것과 같다.
넓히는 방식은 **join 옵션 둘**이고 나머지는 그 귀결이다.

| 넓히는 것 | 왜 |
|---|---|
| `private` — 빠른 매칭 대기열 우회 | 대기열이 슬러그당 한 칸이라, 파티는 슬러그가 하나뿐이어서 **두 번째 방장이 첫 방장 방에 앉는다** |
| `manualStart` — 로비 30초 마감·시작 후 잠금 면제 | 지금은 3석 이상 방을 30초 뒤 강제 시작하고 그 뒤 초대 링크를 전부 거절한다 |
| `started` 와 `seed` 를 판 단위로 | 방이 판보다 오래 살아야 하고, 판 2가 판 1의 시드를 물려받으면 **전원이 결과를 미리 안다** |
| 방장 시작 명령 (좌석 0 에서 온 것만) | 위 둘이 기존 시작 경로를 다 막았다 — 명령이 없으면 판이 영영 시작되지 않는다 |
| 시작 신호가 설정을 불투명 값으로 함께 나름 | 시드와 설정이 두 메시지로 갈리면 원자성이 깨진다 (아래 C) |
| `joined` 응답에 좌석 토큰 | 아래 B |
| 관전자를 좌석 없이 받음 · 좌석 조회 포트 | 관전자가 좌석을 먹으면 참가자가 못 들어온다 |

**옵션은 형식이지 규칙이 아니다.** 릴레이가 새로 아는 것은 좌석 번호·메시지 종류·시각뿐이고,
게임 규칙은 여전히 모른다.

### B. 채점은 새 권위 레이어가 아니라 아케이드 스택의 확장이다

서버 채점이 이미 있다 — Tier A 개연성 검사, Tier B 서버 재실행 검증, `jvm + js` 타깃을 갖는
정수 결정적 코어, 시드 쇼핑을 막는 서버 발급 시드. 참여형 게임 2종은 그 위에 얹는다.

**좌석 토큰은 릴레이가 좌석 배정 시점에 그 피어의 소켓으로만 발급한다.** HTTP 가 (방 코드 + 좌석)을
받아 내주면 **자칭 사실에 도장을 찍는 것**이고, 공격자가 전 좌석 토큰을 받아 전원 대신 제출할 수 있다.
서명 대상은 (방 + 방 생성 시각 · 판 · 좌석 · 좌석 점유 세대)이고, 기존 세션 토큰 payload 로는
담기지 않으므로 **새 포트**다.

**권위의 경계를 적어 둔다 — 「서버 채점이므로 위조 불가」가 아니다.** 7초는 서버 시계로 잴 수 있고,
원그리기는 궤적을 서버가 재현할 수 없어 **개연성 검사가 상한**이다. 캐주얼 조작만 막는다.

### C. 결과 권위는 사람에게 두지 않는다 — 문이 넷이다

이 자리가 내기에 쓰이므로 **누구도 결과를 미리 정할 수 없다**가 1급 불변식이다.
방장의 문을 하나 닫는 것으로는 부족했다 — 넷이었다.

| 문 | 닫는 법 |
|---|---|
| 시드를 방장이 뽑는다 | 릴레이가 뽑는다 (이미 `SecureRandom` 으로 하고 있다) |
| 시드를 보고 코스·비율을 고른다 | **원자적 발급** — 시작 명령이 설정을 싣고 오면 릴레이가 그 순간 시드를 뽑아 **설정과 한 메시지로** 뿌린다 |
| 판마다 시드를 물려받는다 | 시드를 판 단위로 |
| 판을 취소·종료해 재추첨한다 | 무효 사유를 셋으로 열거하고(해시 불일치·채점 실패·전원 미제출) **어느 것도 사람이 부르지 않는다**. 종료는 해시가 모이거나 제한 시간으로만 |

**참가자의 문도 함께 닫는다.** 「해시가 다르면 무효」를 그대로 두면 결과가 마음에 안 드는 사람이
**거짓 해시 하나로 재추첨**을 만든다(다시 하면 시드가 새로 뽑히므로). 해시는 채점 서버가 좌석 토큰과
함께 받아 **다수결로 판정**하고, 소수 기기는 이탈로 처리한다.

### D. 동시 관전은 결정적 재생이다 — 화면을 보내지 않는다

이 장르 시뮬은 고정 스텝이고 시뮬 파일에 `Math.random`·`Date.now` 가 없다. 시드와 설정을 한 번
뿌리면 각 기기가 같은 판을 그린다 — 판당 릴레이 트래픽이 **메시지 한 건**이다.

두 곳에서 깨지므로 함께 고친다.

- **엔진 간 동일성** — `Math.sin/cos` 는 ECMAScript 가 정밀도를 규정하지 않아 JSC 와 V8 이 갈리고,
  그 값이 로터·시소의 충돌 기하로 초당 240스텝 들어간다. 카오스라 순위가 바뀐다. 한 방에 아이폰과
  안드로이드가 있는 것이 기본 시나리오다 → **호출부 2곳을 정수 양자화 룩업으로 교체**한다.
- **입력이 결과를 바꾸는 게임**(카드 뽑기) — 시드만으로는 기기마다 다른 판이 된다 →
  **뒤집기 입력을 릴레이로 중계**한다(판당 메시지가 사람 수만큼만 는다).

### E. 친구 명부는 `game_db` 에, 옵트인으로만

별칭은 자유 텍스트라 **실명이 들어올 수 있고, 저장 대상이 제3자**다(친구는 동의한 적이 없다).
그래서 개인정보로 취급한다.

- 기본은 기기 저장(로그인 불필요). 로그인 사용자가 **켰을 때만** 서버에 저장하고, 확인 화면이
  「다른 사람의 이름이 서버에 저장된다」를 그대로 말한다
- `member` 에 두지 않는다 — 식별 최소화를 지키는 서비스에 사용자 입력 이름을 넣지 않는다.
  **위치를 옮긴 것이지 위험을 줄인 것이 아니라는 점**을 함께 적어 둔다
- 보존기간 · 실제로 지우는 호출자 · 방침 문구를 **셋 다** 만든다. 상수만 두고 호출자가 없어
  무기한 누적한 선례가 이미 있다
- **회원 탈퇴 시 함께 파기한다.** 지금 member 는 탈퇴에 상태만 바꾸고 메시징을 쓰지 않아
  `game_db` 가 탈퇴를 알 채널이 없다 — 채널을 만드는 것이 이 결정의 일부다

### F. 명부 규약은 버전을 올리지 않는다

배포된 파서가 버전 불일치에 인계를 **통째로 버린다.** 올리면 새 필드가 무시되는 게 아니라
**참가자 이름을 다시 입력하는 화면**이 뜬다. 확장은 `v:1` 유지 + 선택 필드 가법 추가뿐이다.

### G. 명부 경로는 게이트웨이에서 좁은 라우트로 먼저 잡는다

**개정 2026-09-10.** 처음 붙였을 때 `/api/v1/games/party/rosters` 에 전용 라우트가 없어
`game-catalog`(`/api/v1/games/**`, 필터 없는 공개 경로)로 떨어졌다. 그 경로는 클라이언트가 붙인
`X-User-Id` 를 벗기지 않으므로, 헤더 한 줄이면 **아무 회원의 친구 그룹을 읽고 고치고 지울 수
있었다.** E 가 「제3자의 이름이라 개인정보로 취급한다」고 정해 놓고 그 경로를 열어 둔 셈이다.

같은 함정을 개선 제안 읽기에서 이미 겪었고 해법도 같다 — **좁은 라우트를 캐치올 앞에 세운다.**
`game-party-roster`(USER+)와 `game-party-room`(게스트 허용, 위조 신원 헤더를 벗김) 둘을
`game-catalog` 앞에 둔다. 판 진행 경로가 로그인을 요구하지 않는 이유는 C·E 그대로다 —
초대 링크로 들어온 사람이 참가자이고 신원은 릴레이가 발급한 좌석 토큰이 갖는다.

경계는 문서가 아니라 검사가 지킨다: `GatewayRoutingSpec` 이 무인증 조회와 `X-User-Id` 위조
쓰기를 각각 401 로 고정한다. 라우트를 넣기 전에 이 검사가 실제로 빨간불인 것을 확인했다.

## Alternatives Considered

| 후보 | 판정 | 근거 |
|---|---|---|
| 파티 전용 WebSocket 핸들러 신설 | 탈락 | 코드 발급·좌석·속도 제한·유휴 정리를 통째로 복제한다. 릴레이가 필요로 하는 것과 같은 것을 두 벌 갖게 된다 |
| 방장 화면을 스트리밍(WebRTC/서버 렌더) | 탈락 | 결정적 재생이 같은 결과를 픽셀까지 낸다. 대역·지연·비용이 전부 크고 무료 티어에서 성립하지 않는다 |
| 호스트 권위(방장 기기가 결과를 뿌린다) | 탈락 | 엔진 갈림은 확실히 막지만 「방장이 결과를 정한다」는 의심을 구조적으로 못 없앤다. **내기 자리에서는 그 의심이 기능을 죽인다.** `sin/cos` 교체가 호출부 2곳으로 같은 문제를 더 싸게 푼다 |
| 해시 불일치 시 무조건 판 무효 | 탈락 | 참가자 한 명의 거부권이 된다. 다수결 + 소수 이탈이 SR 의 목적(결과가 갈리는 것을 잡는다)을 지키면서 거부권만 없앤다 |
| 결정자 게임 3종을 정수 결정적 코어로 이식 | 보류 | 근본적이지만 전면 재작성이다. 호출부 2곳 교체로 같은 성질을 얻는다. 참여형 신작을 코어 위에 지을지는 열린 질문으로 남긴다 |
| 친구 명부를 `member` 에 | 탈락 | 식별 최소화 원칙을 지키는 서비스에 사용자 입력 이름을 넣게 된다 |
| 투표를 릴레이 메시지로 | 탈락 | 릴레이가 중계마다 발신 좌석을 박는다 — 전체로 뿌리면 전원이, 방장에게만 보내면 방장이 남의 표를 본다 |
| 투표 1표의 주체를 방문자 식별자로 | 탈락 | 쿠키 파생이라 지우면 새 표가 되고, WS 핸들러가 헤더를 안 읽어 릴레이 경로엔 값이 없으며, 관전자도 값을 갖는다 |
| 참여형을 새 장르로 | 탈락 | 장르는 게임당 하나라 결정자 장르와 배타가 되어 목록의 합집합이 깨진다. 태그 축으로 간다 |
| 앱 안에 포인트·전적 도입 | 탈락 | 현행 게임 설명의 「앱 안에 돈이나 포인트는 없다」를 유지한다. 그것이 규제 영역에 안 들어가는 근거다 |

## Consequences

**얻는 것**

- 새 JVM·새 DB·새 엔드포인트가 없다. 릴레이 옵션 둘과 명령 하나, 그리고 기존 채점 스택의 확장이다
- 관전이 판당 메시지 한 건이다. 무료 티어 제약 안에 그대로 남는다
- 「방장도 결과를 못 고른다」가 문장이 아니라 **강제되는 형태**로 선다 — 문 넷이 각각 검사를 갖는다

**치르는 것**

- 릴레이가 처음으로 방 종류를 갖는다. 규칙은 여전히 모르지만 형식이 늘었다
- `Math.sin/cos` 교체가 **기존 다시보기 코드의 재현성을 한 번 끊는다.** 화면이 그 사실을 안내한다
- 별칭이 서버에 남는 첫 지점이다. 방침·보존기간·탈퇴 파기가 함께 가야 하고, 하나라도 빠지면
  방침이 거짓이 된다
- **N석 릴레이 경로가 운영에서 한 번도 돈 적이 없다.** 배포된 릴레이 게임 셋이 전부 2석으로 돈다 —
  파티가 그 경로의 첫 사용자다
- 방 상한 200이 전역이라 파티가 사용량을 크게 늘린다. 알 수 없는 코드로 방이 만들어지는 현재 동작을
  막지 않으면 한 사람이 **모든 릴레이 게임을 정지**시킬 수 있다

**함께 고쳐야 하는 것**

- 장르 표준의 「참가자 이름은 이 기기 밖으로 나가지 않는다」. 이 기능이 그것을 부분적으로 뒤집는다 —
  표준을 안 고치면 다음 사람이 스펙과 표준 중 어느 쪽을 따를지 알 수 없다
- **`GAME_HMAC_SECRET` 이 클러스터에 주입돼 있지 않다.** 좌석 토큰이 그 위에 얹히므로,
  주입되기 전에는 이 기능의 서명이 공개된 기본값으로 서명된다. **비밀키 미주입 시 기동 실패**를
  요구로 둔다. (지금 아케이드 세션 토큰이 그 상태라는 것은 이 ADR 밖의 별건이다)
