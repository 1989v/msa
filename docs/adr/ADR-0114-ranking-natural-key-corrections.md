# ADR-0114 — 랭킹 수기 교정은 자연키 기반 별도 테이블

- 상태: 채택 (2026-10-21, 사용자 승인 P1)
- 관련: ADR-0077, ADR-0081, ADR-0083, ADR-0093, ADR-0112, ADR-0113
- 계약: `docs/specs/2026-10-21-ranking-admin/plan.md` §3~9 및 `screens.md` S1~S8

## 맥락

카페 bulk는 요청에 포함된 브랜드의 원천 행을 삭제하고 다시 삽입한다. 행 ID는 지속 식별자가
아니며 공식 원천 25필드·raw·notes를 수기 값으로 덮으면 외부 데이터 보존 규칙을 위반한다.
사용자는 계획서 §9의 다섯 권고안을 모두 승인했다. 이 ADR은 구현 전 그 결정을 기록한다.

## 결정

**A안: 기존 CafeDrinkKey v1 자연키를 사용하는 별도 교정 테이블**을 ranking_db에 둔다.
교정은 원천 행 ID의 FK·삭제 cascade와 독립하며 필드별 SET, SET_UNKNOWN, RESET과
baseline·상태·revision·근거를 보관한다. 자연키 구성 요소와 카페인 상태는 P1에서 수정하지 않는다.
브랜드 검증 메타·적재 실행 이력·관리자 감사 및 멱등 operation 결과도 별도 저장한다.
브랜드 검증일은 행별 checkedAt를 변경하지 않는다.

원천과 기본 파생값을 보존하고 별도 `cafe_drink_effective` 테이블에 유효값 투영을 저장한다.
공개 필터·정렬·페이지 처리는 이 DB 투영을 사용하며 요청마다 전체 원천을 읽지 않는다.
ACTIVE 교정만 적용하며 실효 영양과
용량을 정한 뒤 표시 용량·100ml 수치를 도메인에서 재계산한다. 용량 SET은 ADMIN_VERIFIED,
SET_UNKNOWN은 모든 용량 추론을 차단하고 RESET만 원천 추론으로 돌아간다. 목록·상세·필터·정렬·
groups·brands·drink-names·nearby는 동일 유효값을 사용한다. 원천 메뉴명 검색도 유지한다.

bulk와 모든 교정·일괄·되돌리기는 같은 브랜드 잠금을 slug 순으로 획득한다.
rankingTransactionManager의 한 트랜잭션에서 브랜드 원천 교체, 교정 재적용, 필드별 충돌·
ORPHANED 판정, 유효값 투영, generation, SYSTEM 감사, 성공 적재 이력을 확정한다.
실행 시작과 실패 기록은 별도 짧은 트랜잭션으로 남긴다. 15분 초과 RUNNING은 INTERRUPTED로
구분한다. 브랜드별 결과와 부모 실행의 PARTIAL을 분리하며 도입 전 이력을 추정하지 않는다.

baseline 원천·의존값·규칙 버전이 달라지거나 원천이 교정값과 같아지면 CONFLICT로 보존하고
해당 필드는 새 원천을 공개한다. 소멸 키는 ORPHANED, 재등장 키는 재승인 대기로 두며 다른
키에 자동 이전하지 않는다. 충돌 해결은 원천 채택·현재 기준 재승인·새 교정값으로 제한한다.

모든 관리자 API는 기존 ads 신원 검사와 gateway adminConfig의 ROLE_ADMIN 규칙을 따른다.
쓰기에는 서버 신원·시각, 사유·근거, revision/generation, UUID operationId를 요구한다.
멱등 결과 조회는 revision·preview 만료 검사보다 먼저 수행한다. 최대 200키·5분 preview의
일괄 적용과 되돌리기는 전부 성공 또는 전부 취소한다. 감사·결과 저장 실패도 변경을 롤백한다.
되돌리기는 직후 revision과 동일 generation일 때만 새 보상 변경으로 기록하며 원천을 복원하지 않는다.

감사는 **1년** 보관한다. ADR-0077 retention CronJob과 `/privacy` §6은 기존 공통 보존기간
원본을 통해 같은 값을 사용한다. 주유소 스냅샷 30일 보관과 분리한다. 주유소 화면은 읽기 전용이고
지연 진단은 36시간이다. 수집 실행·가격/순위 수정·자연키 이전은 P1에 포함하지 않는다.

## 기각한 대안

- **B: cafe_drink override 컬럼** — delete/insert 경로마다 추출·복원을 보장해야 하며 한 경로만
  누락해도 교정이 사라진다. 소멸 키 보존에는 결국 별도 저장소가 필요하고 원천과 운영 판단의 경계도 흐려진다.
- **C: 원천 JSONL 수정 후 재적재** — 공식 원천과 운영 교정을 섞고 다음 수집 때 유실된다.
  필드별 감사·낙관적 잠금·충돌 재승인·원자적 되돌리기를 제공하기 어렵다.

## 결과와 운영

조회 투영·잠금·충돌 관리 비용을 받아들이는 대신 원천 보존과 재적재 후 교정 추적을 보장한다.
UseCase/Port/Adapter 경계(ADR-0083), 전체 동기화와 부분 수정 분리, DESIGN.md 토큰을 따른다.
구현·검증·리뷰는 현재 워크트리에서 수행하며 배포·운영 DB 변경·커밋·푸시는 별도 작업이다.
