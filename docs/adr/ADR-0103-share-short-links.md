# ADR-0103: 공유용 단축 링크 — apex 접두사 + 도메인별 해석

- 상태: 수용 (2026-10-08 — 스펙 리뷰 3라운드 후 구현)
- 관련: ADR-0064(이력서 게이트), ADR-0069(deal `/go` 리다이렉터), ADR-0072(블로그 글 상세), ADR-0077(원장 보존기간), ADR-0089(비밀 게임), ADR-0093(파드 배분)
- 스펙: `docs/specs/2026-10-08-share-short-links/spec.md`

## 문제

공유 주소가 길다. 이력서 제출처 링크는 `https://resume.1989v.com/?k=<32자 토큰>` 이라 지원서 입력란과 메신저에서 잘린다.
글·게임 주소에는 긴 슬러그가 들어간다. 공유 대상마다 짧은 주소가 필요하다.

## 결정

### 1) 주소는 apex 하나 + 서비스 접두사

`1989v.com/{r|p|g|b}/{code}` 형태이고, `/{접두사}/list` 는 서비스 홈으로 가는 고정 별칭이다.
호스트를 apex 하나로 둔 이유는 두 가지다. 주소가 가장 짧고, 인그레스 규칙이 한 호스트에만 생긴다.
서브도메인마다 열면 호스트와 접두사가 같은 서비스를 두 번 말하게 된다.

### 2) 공개 콘텐츠의 코드는 id 에서 결정한다 — 매핑 테이블 없음

관광지·게임·글의 코드는 숫자 id 에 고정 순열을 적용한 뒤 base62 로 쓴 값이다(6자 이상).
URL 단축기의 일반형인 「코드 → URL 매핑 테이블」을 쓰지 않는다.
- 사용자 요구는 「생성 단계 없이 모든 대상이 단축 주소를 가진다」였다. 결정적 코드는 이 요구를 저장 없이 만족한다.
- 매핑 테이블을 쓰면 대상이 생길 때마다 행을 만들거나 공유 시점에 만들어야 한다. 앞의 방식은 네 도메인의 생성 경로에 훅을 걸어야 하고, 뒤의 방식은 공개 생성 API 를 열어야 한다.
- 순열은 비밀이 아니다. 대상은 원래 공개 주소를 가지므로 코드를 추측해도 새로 노출되는 것이 없다. 비공개 대상은 해석 단계의 공개 판정이 막는다.

### 3) 이력서는 예외 — 무작위 코드를 저장한다

이력서 토큰은 곧 열람 권한이다(ADR-0064). 이력서 코드를 id 에서 계산하면 추측할 수 있게 되고, 그러면 게이트가 무력해진다.
그래서 제출처 링크 행마다 `SecureRandom` 으로 만든 10자 코드(약 59비트)를 저장한다. 폐기한 링크의 코드는 해석에 실패한다.

### 4) 해석은 대상을 가진 도메인이 한다

deal `/go` 와 같은 구조다. 게이트웨이가 `/r/**` 를 atlas(resume)로, `/p` `/g` `/b` 를 content 로 보낸다.
각 도메인은 자기 저장소만 읽고 302 로 응답한다. 응답에는 `no-store` · `noindex` 를 붙인다.
단축 링크 전용 서비스나 모듈은 두지 않는다. 그런 모듈은 네 도메인의 공개 규칙과 슬러그를 알아야 하고, 이는 서비스 간 참조를 금지하는 규칙에 걸린다.
해석에 실패하면 서비스 목록으로 302 한다. 받은 사람이 빈 화면을 보지 않게 하려는 것이다.

### 5) 클릭 원장은 도메인별 테이블

`deal_offer_click` 과 같은 모양의 테이블을 각 도메인 DB 에 하나씩 둔다. IP 는 저장하지 않는다. 크롤러는 기록하지 않는다.
- 누적 수는 별도 집계 테이블에 원자적으로 올린다. 대상 행에 컬럼을 두면 게임 행 실시간 카운터 금지 규칙에 걸린다. 관광지는 일괄 수집이 행 전체를 다시 써서 컬럼이 덮인다.
- **이력서 원장은 링크 id 와 시각만** 남기고 365일 보관한다. ADR-0064 는 이력서 열람에서 리퍼러·UA 를 모으지 않기로 정했고, 보존기간은 `resume_access_log` 와 같다.
- 나머지 원장은 90일이다. 정리는 각 도메인의 보존 러너가 하고, 보존기간은 ADR-0077 표와 `/privacy` §2·§6 에 같은 숫자로 추가한다.
ADR-0095 의 노출·클릭 파이프라인에 싣는 안은 보류했다. 그 파이프라인이 아직 진행 중이라 일정이 묶이기 때문이다.
파이프라인이 운영에 들어가면 그쪽으로 옮기는 것을 다시 검토한다.

## 결과

- 공개 대상의 코드는 저장하지 않으므로 백필·동기화·누락이 없다. 대가로, 대상 id 가 바뀌면(재생성) 코드도 바뀐다.
- 인코딩 순열을 바꾸면 이미 퍼진 단축 주소가 전부 깨진다. **순열 상수는 바꾸지 않는다.**
- 단축 해석 경로 네 곳이 같은 302 응답 모양을 반복한다. 응답 헤더 조립과 주소 조립은 `common` 헬퍼 하나로 묶는다. origin 은 설정값에서만 얻는다(요청 헤더 금지 — 오픈 리다이렉트 방지).
- 해석 파드가 내려가면 게이트웨이의 빈 200 응답이 그대로 나간다. 플랫폼 공통 한계로 감수한다.

## 검증

- 코덱 골든 벡터(순열 고정)·왕복·충돌 없음·거절 단위 테스트. 리다이렉터 302·헤더·실패 시 목록 이동 컨트롤러 unit 테스트.
- 배포 후 apex 단축 주소 4종과 `list` 4종의 `Location` 실측.
