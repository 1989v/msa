# ADR-0072 — 블로그 플랫폼 (blog.1989v.com): 다중 저자 · 계층 카테고리 · 서버 메타 주입

- 상태: 제안 (2026-08-21)
- 관련: ADR-0069(deal — 폴드/서브도메인/어드민 분리 패턴), ADR-0059(game — 폴드),
  ADR-0066(메인 런처·전시 테이블), ADR-0064(resume — 호스트 인식 루트 라우팅),
  ADR-0062(SEO·프리렌더·호스트별 robots), ADR-0063(단일 어드민 호스트),
  ADR-0061(엣지 노출면), ADR-0018(RBAC), ADR-0031(NetworkPolicy)

## 맥락

기술·일상 두 축의 글을 계층 카테고리(예: `기술 > 서버 > 검색`)로 모아 보여주고, 댓글·평점·
좋아요·조회수·공유가 붙는 블로그를 운영하려 한다. 나 혼자 쓰는 공간이 아니라 **여러 저자가
각자의 공간을 갖는** 형태로 확장 가능해야 한다.

제약은 셋이다.

1. **무료 티어 단일 노드** — 신규 상시 파드는 예산 밖이다 (ADR-0069 와 동일 전제).
2. **기존 RBAC 은 3종뿐** — `ROLE_USER / ROLE_SELLER / ROLE_ADMIN`. "블로그를 쓸 수 있는
   사람"이라는 축이 없고, 있더라도 역할 하나로는 **작성자 프로필**(핸들·표시명·소개)을
   담지 못한다. 작성자별 공간(`/authors/{handle}`)이 요구사항이므로 프로필은 어차피 필요하다.
3. **공유가 1급 요구** — 블로그의 유입은 검색과 메신저 공유다. 그런데 현재 플랫폼의 상세
   페이지(관광지 등)는 SPA 전용이라 **OG 카드가 전부 기본 문구**로 나간다. 빌드타임
   프리렌더(게임 패턴)는 새 글이 다음 배포 전까지 비어 보인다 — 공유가 가장 활발한 시점이
   발행 직후라 이 공백이 정확히 최악의 구간에 온다.

## 결정

### 1) 백엔드는 `code-dictionary:app` 에 폴드 — 패키지는 `com.kgd.blog`

`:blog:domain`(순수) + `:blog:feature`(Spring 라이브러리, 비-bootable)를 `code-dictionary:app`
이 흡수한다. ADR-0059/0069 와 같은 폴드 패턴이고, 자원이 생기면 그대로 재분리 가능하다.
신규 bootJar·신규 이미지·신규 상시 파드 0.

`deal` 과 같이 **전용 datasource 를 두지 않는다.** 스키마는 code-dictionary 것을 쓰고
마이그레이션도 스키마 주인 쪽(`code-dictionary/app/.../db/migration/V14__blog.sql`)에 둔다 —
Flyway 히스토리가 하나이므로 버전 수열도 하나여야 한다.

**`DataSourceConfig.entityManagerFactory().packages()` 에 `com.kgd.blog` 을 더한다.** 이 EMF 는
명시 정의라 `@EntityScan` 이 먹지 않는다. 빠뜨리면 "not a managed type" 으로 컨텍스트 로드에서
죽는다 (deal 폴드 때 실제로 겪은 함정).

> (−) 이로써 `code-dictionary:app` 이 개념사전·전시·이력서·게임·딜·블로그 6개 도메인을
> 호스팅한다. ADR-0069 가 남긴 "호스트 앱 개명" 숙제가 한 칸 더 무거워졌다. 개명은 여전히
> 별도 ADR 이다 — 이번 작업에 끼워 넣으면 이미지 태그·Argo·CI 경로 매핑이 동시에 흔들린다.

### 2) 작성 권한은 역할이 아니라 **블로그 프로필**이 갖는다

`ROLE_AUTHOR` 를 전역 Role enum 에 추가하지 않는다. 이유는 두 가지다.

- 역할 하나로는 핸들·표시명·소개를 담지 못해 **어차피 프로필 테이블이 필요**하다. 권한 진실이
  두 군데(JWT 클레임 + 프로필 행)로 갈리면 정지 처리가 토큰 만료 전까지 먹지 않는다.
- 전역 enum 변경은 auth 서비스 마이그레이션 + JWT 재발급 + 역할 부여 UI 를 끌고 온다.
  블로그 하나를 위해 플랫폼 인증 축을 늘릴 근거가 없다.

`blog_profile` 한 테이블이 **독자와 저자를 모두** 담는다. 프로필 테이블을 둘로 쪼개면
(저자용/댓글용) 같은 사람의 표시명이 화면마다 달라진다.

| 컬럼 | 의미 |
|---|---|
| `member_id` | 인증된 신원 (게이트웨이가 검증한 `X-User-Id`). UNIQUE |
| `role` | `READER`(첫 댓글 시 자동 생성) / `AUTHOR` |
| `status` | `PENDING` / `ACTIVE` / `SUSPENDED` |
| `handle` | 작성자 공간 URL 세그먼트. `AUTHOR` 만 보유 (nullable, UNIQUE) |

**작성 가능 = `role=AUTHOR AND status=ACTIVE`.** 게이트웨이는 로그인 여부만 강제하고(ROLE_USER+),
"작성자인가"와 "내 글인가"는 서비스가 판정한다 — 소유권은 엣지가 알 수 없는 정보다.

`ROLE_ADMIN` 은 모든 글을 수정·삭제할 수 있지만 **글을 쓸 때는 자기 프로필 행을 갖는다**
(첫 작성 시 자동 생성). 저자 없는 글이 생기면 작성자 공간·목록·JSON-LD 가 전부 예외 분기를
갖게 된다.

### 3) 카테고리는 인접 리스트 + 물질화 경로, 최대 3단

`(parent_id, slug)` UNIQUE + `path`(`/tech/server/search`) UNIQUE + `depth`. 조회는 `path`
prefix 하나로 서브트리를 긁고, 이동은 부모만 바꾼 뒤 하위 `path` 를 다시 쓴다.

깊이 상한 3단은 도메인에서 강제한다. 요구가 3단이고, 상한이 없으면 어드민에서 실수로 만든
5단 카테고리가 URL·브레드크럼·사이트맵에 그대로 새어 나간다.

### 4) 조회수는 Redis 가 아니라 **중복 방지 원장 테이블**로 센다

`code-dictionary:app` 에는 Redis 의존성이 없다. 조회수 하나를 위해 새 의존성과 커넥션 풀을
붙이지 않는다.

`blog_post_view(post_id, visitor_key, view_date)` UNIQUE 에 INSERT 를 시도하고, **새로 들어간
경우에만** `blog_post.view_count` 를 올린다. 부수 효과로 **날짜별 조회 추이**가 공짜로 남아
작성자 대시보드가 된다 (deal 클릭 로그와 같은 구조). 90일 초과분은 정리한다.

봇 UA 는 세지 않는다. 세는 순간 조회수는 "사람이 읽은 횟수"가 아니게 되고, 그 숫자를 보고
글을 쓰게 되면 판단 자체가 오염된다.

### 5) 좋아요·평점은 익명 허용, 댓글은 로그인 필수

투표 키는 `voter_type(MEMBER|VISITOR)` + `voter_key`(회원 id 또는 게이트웨이 `X-Visitor-Id`).
게임 평점이 쓰는 방식 그대로다. 익명 쓰기 경로에는 게이트웨이 Rate Limiter 를 건다.

댓글만 로그인을 요구한다 — 익명 댓글은 무료 티어 단일 노드에서 가장 큰 운영 리스크이고,
스팸 대응(캡차·모더레이션 큐)을 P1 에 같이 만들어야 한다.

> 평점(5점)과 좋아요(토글)는 축이 겹친다. 블로그에서 별점은 드물고, 두 지표가 같은 방향을
> 가리키면 어느 쪽도 신호가 되지 못한다. **요구대로 둘 다 만들되** 상세 화면에서 좋아요를
> 1차 액션, 평점을 보조로 배치해 서로 경합하지 않게 한다.

### 6) 글 상세·작성자 공간은 **백엔드가 meta 를 주입한 HTML** 로 서빙한다

`blog.<DOMAIN>` 의 `/posts/**` 와 `/authors/**` 만 ingress 에서 gateway 로 보낸다
(deal 의 `/go` 와 같은 방식 — 공유되는 주소라 `/api` 밑에 두지 않는다).

백엔드는 클러스터 내부에서 `http://portal-fe/index.html` 을 받아 **기존 프리렌더와 똑같은
계약**으로 조립한다: `<!--seo:start-->…<!--seo:end-->` 블록을 페이지 메타로 교체하고
`<div id="root">` 에 크롤러용 본문을 넣는다. 자산 해시를 알 필요가 없고, FE 를 배포해도
셸이 자동으로 최신이 된다.

- 셸은 Caffeine 에 5분 캐시하고 **실패 시 마지막 정상본을 계속 쓴다**. 셸을 못 받는 것이
  글이 안 보이는 이유가 되어서는 안 된다.
- 콜드 스타트에 셸도 없으면 메타 + 본문만 있는 최소 HTML 을 낸다. SPA 없이도 읽힌다.
- 서버 렌더는 `commonmark` 로 하되 **raw HTML 을 이스케이프**한다. 이 HTML 은 SPA 가 마운트되면
  교체되는 크롤러용 사본이라, 렌더 결과가 FE(`marked`)와 미세하게 달라도 무방하다.

홈(`/`)과 카테고리(`/c/**`)는 빌드타임 프리렌더로 남긴다 — 목록은 메타가 고정이라 신선도
요구가 없다.

### 7) 화면은 둘로 나뉘고, 에디터는 하나다

- **`admin.1989v.com/blog/*`** — 내 글 작성(기본 작성 경로) + 카테고리 · 저자 승인 · 댓글 모더레이션
- **`blog.<DOMAIN>/studio`** — 외부 저자용. 자기 글만 보이고, 자기 글만 고칠 수 있다

외부 저자에게 백오피스 계정을 열지 않는다 (ADR-0063 단일 어드민 호스트 원칙 유지).

마크다운 에디터는 **두 앱에 각각 둔다.** `@kgd/design-system` 으로 올리는 안을 먼저 검토했으나,
그 패키지는 quant-fe·gifticon-fe 도 쓰는 vendored tarball 이라 `marked`/`dompurify` 를
거기에 넣으면 마크다운을 쓰지 않는 두 FE 까지 그 의존성을 받게 된다. 중복되는 것은 입력
화면(프레젠테이션)뿐이고 **규칙은 전부 서버에 있다** — 슬러그·상태 전이·소유권·본문 검증이
`BlogPostWriteService` 한 곳을 지난다. 반복이 세 번째가 되면 그때 올린다 (Rule of Three).

### 8) 색인은 연다 — deal/resume 과 반대다

블로그는 자체 콘텐츠라 thin 판정 대상이 아니다. 호스트별 `robots.txt` + `sitemap.xml` +
`llms.txt` 를 발행하고, 글 상세에 `Article` + `BreadcrumbList` JSON-LD 를 넣는다.
`DRAFT`·`ARCHIVED` 는 사이트맵에서 빠지고 `noindex` 로 나간다.

전시 타일(`display_service`)에 `blog` 행을 추가해 메인 런처에서 진입한다.

## 결과

- (+) 신규 상시 파드 0, 신규 datasource 0, 신규 이미지 0. ingress host 한 블록 + gateway 라우트
  6줄 + 전시 타일 한 행이 인프라 변경의 전부.
- (+) 발행 즉시 정확한 OG 카드와 색인 가능한 본문. 플랫폼에서 처음으로 상세 페이지의
  공유 카드 공백이 메워진다 — 관광지 상세에도 같은 방식을 적용할 길이 열린다.
- (+) 권한 진실이 한 곳(`blog_profile`)에 있어 정지가 즉시 먹는다. auth 서비스 무변경.
- (−) 이미지 업로드가 없다. 오브젝트 스토리지 클라이언트가 플랫폼에 아직 없어서, P1 은
  **외부 이미지 URL 입력**만 지원한다. 업로드는 스토리지 도입 ADR 이 선행되어야 한다.
- (−) 전문 검색이 없다. OpenSearch 는 이미 있지만 P1 은 카테고리·작성자 탐색만 제공한다.
  글이 쌓이기 전의 색인 파이프라인은 유지비만 든다.
- (−) 댓글 표시명이 회원 서비스의 이름과 별개다(블로그에서 직접 정한다). member 로의
  서비스 간 호출과 NetworkPolicy 확장을 피한 대가이고, 블로그로서는 오히려 통상적이다.
- (−) `code-dictionary:app` 의 도메인 수가 6이 된다. 개명 숙제가 더 미뤄진다.
- 선행 조건(코드 밖): `blog` DNS 레코드(proxied/orange). **Origin 인증서는 불요** —
  `cf-origin-ca-tls` 가 `*.1989v.com` 와일드카드다 (ADR-0061 §5). 반영 전 526 은 인증서가
  아니라 ingress 미동기화로 SNI 가 안 맞는 것이다.
