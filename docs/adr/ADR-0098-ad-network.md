# ADR-0098 — 광고 네트워크: engagement 에 폴드, 과금은 자기 카운터로, game ads 흡수

- 상태: 제안 (2026-09-23) — R2(ads + 게이트웨이) 운영 배포를 확인한 뒤 채택으로 바꾼다
- 관련: ADR-0059 §3(game HOUSE 광고), ADR-0076(AdSense 지면), ADR-0093(파드 재편),
  ADR-0095(노출·클릭 원장), ADR-0083(레이어 표준), ADR-0072(프로필 행 권한),
  ADR-0069(규제 업권), ADR-0077(보존기간), ADR-0078(식별 최소화), ADR-0079(단일 로그인)
- 스펙: `docs/specs/2026-09-23-ad-network/`

## 맥락

AdSense 같은 광고 네트워크를 둔다 — 광고주가 크레딧으로 캠페인을 걸고, 지면에 광고가 나가고,
노출·클릭을 검증해 정산한다. 첫 퍼블리셔는 우리 서브도메인이고, 돈은 가상 크레딧이다.

같은 개념이 이미 세 곳에 흩어져 있다.

| 어디 | 무엇 | 상태 |
|---|---|---|
| game `ads` 모듈 (ADR-0059 §3) | 지면·빈도 정책·보상 원장, HOUSE 배너 | 배너는 게임 목록에 노출 중, 보상형은 FE 호출처 0 |
| portal-fe `AdSlot` (ADR-0076) | AdSense 지면 4곳 | 2곳은 2026-08-31 반려로 꺼짐 |
| deal `/go/{slug}` (ADR-0069) | 클릭 리다이렉트·계측 | 운영 중 |

제약은 OCI 무료 티어다. 상주 JVM 을 늘리지 않는다 (ADR-0093).

## 결정

### 1) 새 파드 없이 `engagement` 에 폴드한다

`:ads:domain` + `:ads:feature`, 스키마 `ads_db`. 호스트는 `engagement` 다.

| 후보 | 판단 |
|---|---|
| **engagement** (채택) | 경매·pCTR·A/B 가 추천·실험과 같은 「순위를 매기고 실험하는」 성격. Redis·Kafka·스케줄링이 이미 있다(스케줄링은 common outbox 자동 구성이 켠다 — 풀만 1 → 4) |
| content | game 이 있어 흡수는 쉽지만 이미 4도메인 22k줄. 한 시크릿이 네 도메인을 멈춘 사고(2026-09-10)의 반경이 더 커진다 |
| 새 파드 | 상주 JVM +1. 무료 티어에서 이 규모에 맞지 않는다 |

대가로 드는 인프라 변경은 넷이다 — engagement 메모리 등급 한 단계(512Mi → 768Mi), 공유 MySQL 의 `ads_db`·계정(기존 볼륨은 place_db 처럼 1회 수동 SQL), 시크릿 `ads-token`(`ADS_TOKEN_SECRET` — oci-arm 은 game-hmac·auth-subject-hash 처럼 `kubectl create secret` 으로 수동 생성, prod-k8s 는 SealedSecret), ads 전용 Redis 연결(타임아웃 250ms — 공용 연결은 Lettuce 기본 60초라 결정 경로가 매달린다). 셋(스키마·계정·시크릿) 중 하나라도 없으면 engagement 가 못 뜨므로 이미지보다 먼저 넣는다.

### 2) 1단계에는 별도 서빙 도메인을 두지 않는다

AdSense 가 광고를 별도 등록 도메인에서 서빙하는 이유는 **광고주 코드를 퍼블리셔 페이지와 격리**하기
위해서다. 1단계 소재는 구조화 필드(이미지·제목·문구·랜딩 URL)만 받고 우리 코드가 그린다 —
격리할 광고주 코드가 없다. 새 Cloudflare 존·인증서를 만들지 않는다.

외부 퍼블리셔를 받거나 HTML 소재를 받는 순간 이 결정은 무효다. 그때는 로그인 쿠키
(`.1989v.com`, ADR-0079)가 실리지 않는 별도 등록 도메인이 **불가피하다**.

### 3) 과금 수치는 ads 가 소유한다

과금의 원천은 ads 의 Redis 카운터 → MySQL 시간별 집계다. analytics ClickHouse 를 읽지 않는다.

- 서비스 간 DB 공유 금지 규칙
- ADR-0095 원장은 아직 제안 상태다 — 돈이 착지 전 파이프라인에 의존하면 안 된다
- 원장이 있어도 「모두에게 같은 사실」을 다루는 분석용이지 정산용이 아니다

검증을 통과한 이벤트의 사본만 `analytics.event.collected` 에 `entity_type=AD` 로 보낸다.
발행 실패가 정산에 영향을 주지 않는다. 이 사본은 권위 원천이 아니므로 Outbox 를 쓰지 않는다 —
`new-domain-checklist.md` §5 에서 의도적으로 벗어난다.

### 4) 과금 노출은 가시 노출이다

렌더만으로 과금하면 스쳐 간 노출까지 광고주가 낸다. 면적 50%·연속 1초(MRC 디스플레이 기준)를
노출로 친다. ADR-0095 의 노출 정의와 같아서, FE 감지 규칙이 하나로 모인다.

### 5) 1차가 경매, eCPM 순위

CPM 입찰과 CPC 입찰을 `입찰가 × pCTR × 1000` 으로 한 척도에 올린다. 승자는 자기 입찰가를 낸다
(AdSense 가 2차가에서 옮겨 온 방식). pCTR 은 베타 사전분포 + 시간별 집계 — 모델 서빙을 두지 않는다.

### 6) 채움 순서: 유료 → AdSense → HOUSE

자체 유료 광고가 없거나 결정 호출이 실패하면 AdSense 지면 ID 가 있는 곳은 AdSense 가 채우고, AdSense 가 unfilled 이거나 ID 가 없으면 HOUSE 가 채운다.
ADR-0076 의 「지면은 코드가 정한다」는 그대로다 — 지면 등록부가 코드의 지면 키를 받아 판다.

### 7) game ads 는 흡수한다

같은 개념(지면·빈도·하우스)이 두 곳에 있으면 수치와 규칙이 갈린다. `/api/v1/ads/**` 를
engagement 로 옮기고, HOUSE 소재는 시스템 광고주의 캠페인이 된다(우선순위는 광고주 종류에서 파생). 보상형은 호출처가
없어 옮기지 않는다. game 의 표는 **새 마이그레이션**으로 지운다(적용된 마이그레이션은 불변).

### 8) 광고주 본인 판정은 결정 시점에 한다

노출 비콘(`sendBeacon`)과 클릭 302 에는 로그인 헤더가 실리지 않는다. 이벤트 단계에서 본인을
가리려 하면 신원이 늘 비어 규칙이 한 번도 동작하지 않는다. Bearer 가 실리는 **결정 호출**에서
본인이면 토큰에 「과금 안 함」을 서명해 넣고, 이벤트 단계는 토큰만 믿는다.

### 9) HOUSE 는 전용 형식·목록 응답·빈도 면제

game 의 HOUSE 소재는 이미지 없는 이모지·앱 안 링크이고 여러 장을 순환한다. 유료 소재 규칙에
끼워 넣으면 「전과 같이」가 깨진다. HOUSE 는 시스템 광고주 소유의 별도 소재 형식으로 두고,
결정 응답이 목록으로 주며, 예산·빈도·원장에서 면제한다.

### 10) 원장은 복식부기, 불균형은 만들 수 없다

거래는 멱등 키가 유일하고, 분개 합이 0 이 아니면 도메인 팩토리가 거래를 만들지 않는다.
검사로 잡는 대신 **쓸 수 없게** 한다. 매일 전체 합 검사는 그 위의 이중 안전장치다.

## 결과

- (+) 상주 JVM 증가 0. 인프라 변경은 메모리 등급·스키마·시크릿·Redis 타임아웃 넷뿐이고 새 파드·도메인·저장소는 없다
- (+) 광고 개념이 한 도메인으로 모인다 — game·AdSense·deal 에 흩어진 규칙 중 둘이 합쳐진다
- (+) 예산을 지키는 것은 Redis 실시간 지출이고 이벤트 수락 단계에서도 상한을 확인하므로, 정산이 늦거나 토큰을 몰아 내도 과다 과금이 되지 않는다
- (−) engagement 배포가 ads 변경에도 트리거된다 (폴드의 공동 배포 대가, ADR-0058 과 같은 수용)
- (−) `ads_db`·계정·`ADS_TOKEN_SECRET` 중 하나라도 없으면 engagement 전체가 못 뜬다. 셋을 이미지보다 먼저 넣는다
- (−) `common` 변경(`CrawlerUserAgents` 이동·`EntityType.AD`)은 전 JVM 이미지를 다시 굽는다. 별도 슬라이스로 먼저 배포한다
- (−) 소재 이미지가 MySQL 에 있다. 수가 커지면 오브젝트 스토리지로 옮긴다 — 포트는 그때 어댑터만 바꾼다
