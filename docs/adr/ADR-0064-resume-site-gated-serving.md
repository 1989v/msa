# ADR-0064 — 이력서 사이트는 DB 서빙 + 토큰 게이트로 공개 범위를 제어한다

- 상태: 채택 (2026-08-10)
- 관련: ADR-0061(엣지 하드닝), ADR-0062(SEO), ADR-0063(어드민 단일 호스트), ADR-0019(K8s 배포 모드)

## 맥락

`resume.1989v.com` 에 경력 이력서를 올린다. 기존 포트폴리오 자산(`docs/portfolio/`,
`PortfolioPage`)과는 성격이 다르다 — 그쪽은 개인 MSA 프로젝트의 기술 상세이고,
이력서는 **실명·연락처·재직사·재직기간이 들어가는 개인정보 문서**다.

여기서 두 가지 제약이 충돌한다.

1. **상시 공개하고 싶지 않다.** 구직 중일 때만 열고, 아닐 때는 닫아야 한다.
   그런데 채용 담당자에게는 로그인 없이 링크 하나로 열려야 한다.
2. **제출처별로 열람 여부를 알고 싶다.** 어느 회사에 낸 링크가 실제로 열렸는지 구분되어야 한다.

초기 콘텐츠는 별도 이력서 볼트(파일 기반)에서 가져오지만, **볼트와 사이트는 같은 문서를 공유하지
않는다.** 볼트는 공고별 지원본을 만드는 작업 공간이고, 사이트는 상시 유지되는 공개본이다.
용도가 다르므로 초기 적재 이후에는 각자 독립적으로 갱신된다.

### 왜 정적 파일이 아닌가

가장 단순한 안은 마크다운을 레포에 커밋하고 빌드타임에 렌더하는 것이다. 그런데
**`1989v/msa` 는 PUBLIC 레포다.** 사이트에 게이트를 걸어도 원문이 GitHub 에서 그대로 읽히면
게이트가 무의미하다. 비공개 서브모듈(`career`)에 두면 유출은 막지만, 문구 한 줄 고치는 데
커밋·푸시·재배포가 필요해진다.

또한 빌드타임 플래그는 공개/비공개 전환에 재배포가 필요하고, 제출처별 토큰을 발급할 수 없다.

## 결정

**콘텐츠를 DB에 마크다운 텍스트로 저장하고, 게이트·토큰 검증·열람 기록을 API 한 곳에서 처리한다.**

```
이력서 볼트(파일) ──최초 1회 복사──▶ DB(markdown, 이후 원본) ──API(게이트)──▶ resume.1989v.com
                                        ▲
                                    어드민에서 편집
```

**적재 이후 사이트 콘텐츠의 원본은 DB다.** 볼트는 초기 데이터 출처였을 뿐이고, 이후 양쪽은
서로를 덮어쓰지 않는다. 사이트 문구를 고칠 일이 생기면 어드민에서 고치면 된다.

- **소유 서비스는 `code-dictionary`** — 이미 포트폴리오 카드를 소유하고 있어 성격이 같고,
  새 서비스를 만들면 무료 티어 단일 노드에 파드가 하나 더 는다
- **호스트는 `resume.1989v.com` 하나 추가하되 파드는 늘리지 않는다.** ingress 에 host 만
  append 하고 기존 `portal-fe` Service 로 라우팅한다 (ADR-0019 자유 티어 제약)
- **공개 상태는 런타임 설정 1건**(`PUBLIC` / `TOKEN_ONLY`)으로 두고 어드민에서 토글한다

### 게이트 규칙

| 공개 상태 | 토큰 없음 | 유효 토큰 | 폐기·미존재 토큰 |
|---|---|---|---|
| `PUBLIC` | 열람 가능 | 열람 가능 | 열람 가능 |
| `TOKEN_ONLY` | **404** | 열람 가능 | **404** |

`TOKEN_ONLY` 에서 403 이 아니라 **404 로 응답한다.** 403 은 "여기 뭔가 있다"를 알려주므로,
포트폴리오 카드의 PRIVATE 처리(존재 여부 은닉)와 같은 기준을 따른다.

콘텐츠 본문은 게이트를 통과해야만 응답에 실린다. 프론트 번들에는 이력서 문장이 들어가지
않으므로 devtools 로도 볼 수 없다.

### 공개 상태 조회는 예외적으로 항상 열어둔다

`1989v.com` 메인이 이력서 진입점을 노출할지 판단하려면 공개 여부를 알아야 한다.
이 엔드포인트는 **불리언 하나만** 반환하고 어떤 개인정보도 싣지 않는다.

### 열람 추적

토큰에 제출처 라벨을 붙여 발급하고, 열람 시 접근 로그를 남긴다.
수집 범위는 **토큰·경로·시각**으로 한정한다. 쿠키 기반 방문자 식별이나 referer/UA 수집은
하지 않는다 — 목적이 "이 회사가 열어봤나"이지 방문자 프로파일링이 아니고, 범위를 좁히면
개인정보 처리 고지 부담도 생기지 않는다.

### 검색 노출은 하지 않는다

resume 호스트는 `noindex` 로 고정하고 sitemap 에 넣지 않는다. 게이트로 닫는 문서를
색인시키는 것은 모순이고, 공개 상태에서도 실명·연락처가 검색결과에 남는 것은 되돌리기 어렵다.
링크는 직접 전달하는 것이 전제이므로 SEO 가 필요 없다.

## 데이터 모델

| 테이블 | 역할 |
|---|---|
| `resume_document` | 문서 1건 = 화면 1장. `slug`, `title`, 마크다운 본문, 종류(MAIN/DETAIL), 정렬순서 |
| `resume_share_link` | 제출처별 토큰. 라벨, 발급/폐기 시각 |
| `resume_access_log` | 열람 기록. 토큰(nullable — 전체공개 상태의 익명 열람), 경로, 시각 |
| `resume_setting` | 공개 상태 1행 |

## 결과

- 공개/비공개 전환이 어드민 토글 1회로 끝난다 (재배포 없음)
- 제출처별 열람 여부를 구분해서 볼 수 있다
- 사이트 콘텐츠를 어드민에서 바로 고칠 수 있다. 볼트를 거치지 않으므로 문구 수정이 가볍다
- 대신 **볼트와 사이트가 시간이 지나면 갈라진다.** 의도한 결과다(용도가 다르다). 다만 경력 사실을
  정정할 일이 생기면 양쪽 모두 손봐야 한다는 뜻이기도 하다 — 한쪽만 고치면 지원본과 공개
  사이트의 서술이 어긋난다
- `code-dictionary` 장애 시 이력서가 뜨지 않는다. 이력서는 상시 트래픽이 없고 링크 전달
  시점에만 열리므로, 파드를 늘리지 않는 대가로 감수한다
- 마크다운 렌더러 의존성이 `portal-fe` 에 추가된다

## 대안

- **빌드타임 정적 렌더 + 환경변수 플래그** — 토글에 재배포 필요, 제출처별 토큰 불가.
  다만 번들에 콘텐츠가 없어 차단은 가장 확실했다
- **ingress basic-auth** — 채용 담당자에게 계정을 알려줘야 해서 링크 하나로 여는 요구와 충돌
- **별도 resume 서비스** — 파드 증설이라 무료 티어 제약에 걸린다
