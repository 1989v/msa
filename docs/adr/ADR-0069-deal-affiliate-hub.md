# ADR-0069 — 혜택 링크 허브 (deal.1989v.com): 큐레이션 + 아웃바운드 리다이렉터

- 상태: 채택 (2026-08-20) — P1 구현 반영 / 개정 (2026-08-22) — 고지 위치
- 관련: ADR-0066(메인 런처·전시 테이블), ADR-0059(게임 — 폴드/서브도메인 패턴),
  ADR-0065(place — host 인식 루트 라우팅), ADR-0062(SEO·robots 호스트 분기),
  ADR-0061(엣지 노출면), ADR-0058(모듈러 모놀리스), ADR-0031(NetworkPolicy)

## 맥락

여행·커머스·구독 등 각 서비스의 혜택 링크를 카테고리별로 모아 보여주고, 그중 제휴 프로그램이
있는 링크는 유입→구매 시 수수료를 받는 페이지를 운영하려 한다.

이 도메인의 제약은 코드보다 **밖**에 있다.

1. **업권 규제** — 의료(의료법 27조 환자 알선 금지)·금융(대출모집인 등록)은 "링크 타고 가서
   결제하면 수수료" 구조 자체가 규제 대상이다. 공개 제휴 프로그램이 없는 이유이기도 하다.
2. **표시 의무** — 공정위 추천·보증 심사지침상 경제적 이해관계 공개는 선택이 아니다.
3. **thin affiliate** — 자체 부가가치 없는 링크 모음은 구글이 색인에서 민다. 수익의 실질 변수는
   페이지 완성도가 아니라 유입 경로다.
4. **약관** — 제휴 링크의 파라미터 재조립·클로킹은 대부분 네트워크가 금지하고, 트래킹 쿠키
   (30~90일)를 깨뜨려 수익 자체를 날린다.

플랫폼 쪽 제약은 이미 정해져 있다. OCI free tier 단일 노드 — **신규 상시 파드는 예산 밖**이다.

## 결정

### 1) 링크는 두 종류다 — 수익 유형이 도메인 축

| `revenue_type` | 정의 | 고지 |
|---|---|---|
| `AFFILIATE` | 제휴 프로그램 발급 트래킹 URL | 해당 카드 안에 고지 한 줄 (아래 개정 참조) |
| `PLAIN` | 제휴 없는 곳의 공개 혜택 페이지 | 없음 |

한 그리드에 섞되 고지로 가른다. 전부 뭉뚱그려 "광고 포함"으로 고지하면 수수료를 받지 않는
링크까지 광고로 읽혀, 고지의 목적(신뢰)과 반대로 간다.

`AFFILIATE` 만 `rel="sponsored nofollow noopener"`, `PLAIN` 은 `sponsored` 없이 `nofollow noopener`.

#### 개정 (2026-08-22) — 고지는 페이지 머리말이 아니라 카드 안으로

첫 제휴 링크(마이리얼트립 마이링크)를 올리면서 원안의 "배지 + 상단 고정 고지"를 접었다.
상단 배너는 **"일부 링크는 제휴 링크입니다"** 라고밖에 말하지 못한다 — 9건 중 1건이 제휴인
지금, 어느 게 그 일부인지 알려주지 못하면서 페이지 전체를 광고로 읽히게 한다. 공정위
「추천·보증 등에 관한 표시·광고 심사지침」이 요구하는 것도 추천이 이루어지는 지점에
**근접한** 표시이므로, 배너는 요건을 채우는 쪽도 아니었다.

바뀐 형태는 제휴 카드 바닥의 메타 줄 한 칸이다 — 남은 기간과 같은 무게로 `제휴 링크 ·
구매 시 수수료를 받습니다`. 배지("제휴")를 없앤 것은 그 두 글자가 경제적 이해관계를
전달하지 못해서다. 지침이 "체험단"·"협찬" 같은 애매한 표현을 지적하는 것과 같은 이유다.

프리렌더 셸에서도 고지를 뺐다. 그 셸에는 오퍼 링크가 없고, 고지는 링크에 붙는다.

### 2) 카테고리는 규제 없는 축만 — 행 자체를 만들지 않는다

여행 / 커머스 / 디지털구독 / 교육 / 생활·통신 5종. 의료·금융은 `HOLD` 로 숨기는 게 아니라
**행을 만들지 않는다.** ADR-0066 이 프라이빗 서비스에 적용한 규칙과 같다 — 전시 테이블에
비전시 행을 심는 것은 모순이고, 노출하지 않기로 한 결정을 데이터로 남길 이유가 없다.

### 3) 아웃바운드는 자체 리다이렉터를 거친다 — 단, 링크는 무변조

```
GET /go/{slug}  →  302 Location: <target_url 원본 그대로>
```

거치는 이유는 두 가지다. 링크가 교체돼도 **이미 공유된 주소가 안 죽고**, 클릭 수를 우리가 센다.
거치지 않는 것 하나 — **URL 을 건드리지 않는다.** 파라미터 재조립·서브ID 주입·iframe 래핑은
네트워크 약관 위반이고 302 가 아니면 트래킹 쿠키가 깨진다.

`/api/v1/deal/go/...` 가 아니라 `/go/...` 인 이유는 공유되는 주소이기 때문이다. ingress 와
gateway 라우팅에 `/go` prefix 한 줄씩이 추가된다 (ADR-0061 이후 gateway 는 specific path 만 받는다).

**클릭 적재 실패가 302 를 막지 않는다.** 리다이렉트가 본질이고 통계는 부수다 — 로그 INSERT 를
try/catch 로 감싸고 실패는 warn 만 남긴다. 이 순서를 뒤집으면 DB 가 흔들릴 때 수익 링크가 죽는다.

만료된 slug 는 404 가 아니라 해당 카테고리 목록으로 302 한다. 프로모션은 끝나도 공유된 링크는
남는다.

### 4) 백엔드는 code-dictionary:app 에 폴드 — 단, 패키지는 `com.kgd.deal`

신규 상시 파드 0 이 최상위 제약이므로 새 bootJar 를 만들지 않는다. `:deal:domain`(순수) +
`:deal:feature`(Spring 라이브러리, 비-bootable)를 `code-dictionary:app` 이 흡수한다 — ADR-0059
게임과 같은 폴드 패턴, 자원이 생기면 그대로 재분리 가능.

`display`·`resume` 처럼 `com.kgd.codedictionary` 하위 패키지로 넣지 않는다. deal 은 개념 사전과
아무 관계가 없고, 잘못된 패키지 이름은 폴드가 풀린 뒤에도 남는다. 모듈 2개의 빌드파일이
그 값을 치른다.

**게임과 달리 전용 datasource 를 만들지 않는다.** game 은 40+ 마이그레이션에 리더보드·세션·
Kafka 를 가진 플랫폼이라 `game_db` 분리가 값을 했지만, deal 은 테이블 3개에 독립 쓰기 경로가
없고 라이프사이클이 `display_service` 와 같다. 두 번째 HikariCP 풀은 실제로 강제하지도 않을
경계를 위해 free-tier 메모리를 쓰는 일이다. 스키마는 code-dictionary 것을 쓰고, 마이그레이션도
스키마 주인 쪽(`code-dictionary/app/.../db/migration`)에 둔다 — Flyway 히스토리가 하나이므로
버전 번호도 하나의 수열이어야 한다.

### 5) 신선도 — 만료일 + 자동 숨김 + 헬스체크 CronJob

죽은 링크 방치가 이런 페이지의 실패 원인 1번이다. 3중으로 막는다.

- `valid_until` 경과 시 공개 API 에서 제외 (화면 로직이 아니라 쿼리에서)
- 어드민 대시보드에 "만료 임박 / 90일 미수정 / 링크 깨짐" 목록
- 주 1회 CronJob 이 HEAD(거부 시 GET Range) 로 점검해 `link_status` 갱신

**HEAD 실패를 곧바로 BROKEN 으로 찍지 않는다.** 403/405/429 는 봇 차단 오탐이 압도적이라
`UNKNOWN` 으로, 404/410 만 `BROKEN` 으로 본다. 오탐이 잦으면 어드민이 경고를 무시하게 되고,
그 순간 이 장치는 없는 것과 같아진다.

CronJob 은 **code-dictionary 이미지를 재사용**한다 (`--spring.main.web-application-type=none`
+ `@Profile("linkcheck") ApplicationRunner`). 새 이미지도 새 상주 파드도 만들지 않는다 —
search-batch 의 `--spring.batch.job.enabled=true` 와 같은 정신.

외부 :443 egress 는 **CronJob 파드에만** 연다 (`app.kubernetes.io/name: deal-linkcheck`).
code-dictionary:app 자체에 열면 상시 노출면이 늘어난다 (ADR-0031 §5.10 화이트리스트 확장).

클릭 로그 90일 정리도 이 CronJob 이 겸한다. 배치 하나를 위해 배치를 또 만들지 않는다.

### 6) FE 는 portal-fe host 라우팅 — P1 은 noindex

`place`/`game`/`resume` 과 동일하게 같은 번들을 `deal.<domain>` 으로 서빙하고 host 로 분기한다.
apex `/deal` 은 프로덕션에서 서브도메인으로 302.

**P1 은 `noindex`였다.** 링크 모음만 있는 상태로 색인에 넣으면 thin affiliate 판정을 자초하고,
그 평가는 사이트 전체에 번진다. 그때까지 유입은 SNS/메신저 공유이므로 OG 카드 품질이 색인보다
중요하다고 봤다.

전시 타일(`display_service`)에 `deal` 행을 추가해 메인 런처에서 진입한다.

#### 개정 (2026-08-24) — 색인을 연다, 대신 방어를 링크 층으로 내린다

서치콘솔이 `deal.1989v.com/` 을 「'NOINDEX' 태그에 의해 제외」로 잡은 것을 계기로 다시 봤다.
**해제한다.** 판단이 바뀐 지점은 하나다 — thin affiliate 를 막는 것은 색인 차단이 아니라
링크에 붙는 표시라는 것. 색인 차단은 그 위험을 **가리기만** 하고 사이트가 얻을 것까지 함께 없앤다.

방어는 세 층으로 남는다. 셋 다 색인 개방과 무관하게 유지된다:

1. **아웃바운드 `rel="sponsored nofollow"`** — `revenueType` 이 판정한다 (§1). 링크 자산이
   흐르지 않는다는 신호가 여기서 끝난다.
2. **`/go/` robots Disallow** — 리다이렉터는 사이트 밖으로 나가는 문일 뿐이다. 제휴 트래킹
   URL 이 색인되면 안 된다. 이 줄은 절대 풀지 않는다.
3. **허브가 카탈로그다** — 오퍼를 이름·제공처·혜택으로 찾는 검색이 붙는다(아래). 링크 목록이
   아니라 "찾을 수 있는 목록"이라는 것이 자체 부가가치의 최소선이다.

**URL 은 허브 하나만 만든다.** 카테고리별·오퍼별 주소를 쪼개고 싶은 유혹이 있지만, 오퍼가
수십 건인 지금 그것은 링크 두세 개짜리 doorway page 가 되어 **열려는 색인을 오히려 깎는다.**
검색은 화면 상태이고 주소를 만들지 않는다 — 질의 조합마다 URL 이 생기면 같은 카탈로그가
무한한 주소로 갈라져 크롤 예산만 태운다. canonical 은 항상 `/` 다.
오퍼가 늘어 분류 하나가 그 자체로 읽을 거리가 될 때 다시 연다.

프리렌더 허브 본문에는 **오퍼를 텍스트로** 적는다 — 링크로 적지 않는다. `rel="sponsored"` 는
React 가 붙이는 것이라 정적 복사본에는 그 표시가 없고, 그러면 고지 없는 제휴 링크를 초기 HTML 로
내보내는 셈이 된다. 텍스트로 두면 무 JS 크롤러(Yeti·GPTBot·ClaudeBot)는 카탈로그를 읽고,
실제 링크는 하이드레이션 뒤의 정상 마크업에만 존재한다.

호스트별 robots/sitemap/llms.txt 는 ADR-0062 의 분기를 그대로 쓴다.

### 7) 검색 — 저장소 질의로 시작한다 (2026-08-24)

`GET /api/v1/deal/search?q=` 가 이름·제공처·혜택·요약을 훑는다. 전시·만료 판정은 목록
(`findAllVisible`)과 **같은 조건**이어야 한다 — 갈리면 목록에 없는 오퍼가 검색으로만 나온다.

**OpenSearch 인덱스를 만들지 않는다.** 오퍼가 9건인 지금 전용 인덱스·리인덱스 잡·CronJob 을
추가하면 단일 노드(OCI 무료)에 샤드와 배치가 늘 뿐 검색 품질은 달라지지 않는다. 응답 모양을
목록과 같은 `List<DealCategorySection>` 으로 맞춰 뒀으므로, 항목이 수백 건을 넘어 형태소·동의어가
필요해지는 시점에 **인터페이스를 그대로 둔 채** 구현만 색인으로 바꾼다.

## 결과

- (+) 신규 상시 파드 0, 신규 datasource 0, 신규 이미지 0. ingress host 한 블록 + gateway 라우트
  2줄 + egress NP 한 줄이 인프라 변경의 전부.
- (+) 리다이렉터가 링크 교체와 클릭 계측을 동시에 해결 — 공유된 주소가 자산으로 남는다.
- (+) 규제 축을 데이터가 아니라 결정으로 잘라내 법적 노출을 0 으로 유지.
- (+) 색인 개방(2026-08-24)에도 신규 인프라 0 — 검색은 기존 datasource 질의, URL 은 허브 한 장.
- (−) 색인을 열었으니 thin 판정 위험을 **오퍼 수로** 갚아야 한다. 9건짜리 허브 한 장으로는
  유입이 붙지 않는다 — 색인 개방은 유입의 조건이지 원인이 아니다. 이 전제를 남겨야
  "열었는데 왜 안 들어오나"를 오독하지 않는다.
- (−) `code-dictionary:app` 이 개념사전·전시·이력서·게임·딜 5개 도메인을 호스팅하게 된다.
  이름과 내용의 괴리가 커졌다 — 호스트 앱 개명은 별도 ADR 로 다룬다.
- (−) 클릭만 세고 전환은 못 센다. 어느 오퍼가 돈이 됐는지는 네트워크 대시보드를 봐야 한다
  (P2 성과 입력 화면까지 수동).
- (−) 수익은 유입에 종속된다. P1 은 수익 검증이 아니라 **유입 실험을 할 수 있는 상태**를 만드는 것이
  목표다. 이 전제를 문서에 남겨야 P1 결과를 "실패"로 오독하지 않는다.
- 선행 조건(코드 밖): 쿠팡 파트너스 사이트 등록 심사, 여행 네트워크 가입, `deal` DNS 레코드
  (proxied). **Origin 인증서 작업은 불요** — `cf-origin-ca-tls` 는 `*.1989v.com` 와일드카드라
  새 서브도메인을 이미 커버한다 (ADR-0061 §5). 반영 전 526 이 뜨는 것은 인증서 문제가 아니라
  ingress 미동기화로 SNI 가 안 맞아 기본 인증서가 나가는 것이다 — 증상이 같아 오진하기 쉽다.
