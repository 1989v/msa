# ADR-0071 — 관광 탐색 IA 개편: 행정구역 드릴다운 + 지도 중심 레이아웃

- 상태: 제안 (2026-08-20)
- 관련: ADR-0065(K-관광 검색), ADR-0070(콘텐츠 보강), ADR-0056(행정 지리·POI),
  ADR-0062(SEO/AEO), ADR-0025(latency budget), ADR-0031(NetworkPolicy)

## 맥락

지금의 `place.1989v.com` 은 **키워드 검색이 축**이다. 그런데 사람이 여행지를 고르는 순서는
그 반대다 — "제주" 나 "강릉" 을 먼저 정하고 그 안에서 고른다. 지역을 먼저 고를 방법이
지금은 광역 셀렉트 박스 하나뿐이고, 시군구로 좁힐 수단이 없다.

### 그런데 시군구로 좁힐 데이터가 없다 — 두 가지 이유

**1. `regions.CITY` 는 시군구가 아니다.** GeoNames 인구밀집지(populated place) 덤프라
흥해읍·왜관읍·탈랑동이 "CITY" 로 섞여 있고, `admin2_code` 는 **296행 전부 NULL** 이다.
경주시·서울특별시 같은 진짜 시군구도 있지만 골라낼 기준이 없다.

**2. `attractions.sigungu_code` 에 두 코드 체계가 섞여 있다.** (2026-08-20 실측)

| 코드 체계 | 행 | (area, sigungu) 쌍 |
|---|---|---|
| 법정동 시군구코드(3자리) | 25,030 | 257 |
| TourAPI 구 sigungucode | 19,874 | 229 |

원인은 수집기의 한 줄이다 — 응답에 구 코드가 있으면 그걸 쓰고, 없으면(무지정 조회의 43%)
법정동 코드로 대체했다. 두 값이 같은 컬럼에 들어가 **시군구가 486개로 보인다.** 실제 229개의
두 배다. 이 컬럼 위에 드릴다운을 올리면 같은 구가 두 번 나온다.

## 결정

### 1) 행정구역의 원본은 정부 오픈데이터다 — GeoNames 도 TourAPI 도 아니다

행정안전부 **법정동코드 전체자료**(행정표준코드관리시스템, 공공누리 제1유형)를 적재해
`admin_regions` 를 만든다. 시도 17 + 시군구 229 가 코드와 함께 확정된다.

GeoNames 를 고치지 않는 이유: GeoNames 의 KR 자료는 애초에 행정구역 체계가 아니라 지명
데이터셋이다. 여기에 시군구를 끼워 넣으면 두 체계가 한 테이블에서 섞여 지금 `sigungu_code` 에
일어난 일이 `regions` 에서 반복된다. **`regions` 는 세계 지명 계층으로 남기고, 한국 행정구역은
따로 둔다.**

TourAPI `areaCode2` 스냅샷을 쓰지 않는 이유: 그 엔드포인트는 발급 화면에서 "미사용(삭제예정)"
이고, 받아봐야 폐기 중인 코드 체계에 다시 묶인다.

### 2) 관광지는 법정동 코드로 지역에 붙는다 — 구 코드는 파생으로 내린다

`attractions` 에 `ldong_regn_cd`(시도 2자리)·`ldong_signgu_cd`(시군구 3자리)를 추가하고
목록을 재동기화한다. TourAPI 신체계가 이미 이 값을 주므로 원천에서 그대로 온다.

기존 `area_code`/`sigungu_code` 는 **지우지 않되 드릴다운의 근거로 쓰지 않는다.** 화면·API 가
쓰는 지역 축은 법정동 코드 하나로 통일한다. 코드 체계가 둘이면 필터 결과가 경로에 따라 달라진다.

**재동기화가 개요를 지우지 않는다** — `Attraction.syncFrom` 이 개요를 보존한다(ADR-0065).
며칠치 수집이 날아가는 경로가 아니라는 것을 확인하고 진행한다.

### 3) 탐색의 기본 축을 지역 드릴다운으로 바꾼다

```
시도(17) ──▶ 시군구(229) ──▶ 관광지 목록
   └─ 좌표가 있으면 현재 위치의 시도가 상단에 온다 (선택은 사용자가)
```

키워드 검색은 없애지 않는다 — 축이 바뀌는 것이지 기능이 빠지는 게 아니다.
상단 검색에 **행정 레벨 필터 + 카테고리 필터**를 함께 둔다.

### 4) 줌은 화면이 아니라 행정 레벨이 정한다

| 레벨 | 줌 | 근거 |
|---|---|---|
| 시도 | 9 | 도 하나가 화면에 들어온다 |
| 시군구 | 12 | 시 경계가 보이면서 개별 마커가 구분된다 |
| 관광지 선택 | 최대 16 | 건물 단위까지 당기면 주변 감각이 사라진다 (ADR-0070 §, 이미 적용) |

경계 폴리곤은 P2 다. 좌표 중심 + 줌 프리셋으로 먼저 하고, 필요하면 그때 경계 데이터를 얹는다 —
경계 GeoJSON 은 용량이 크고 free-tier 에서 전송 비용을 다시 계산해야 한다.

### 5) 목록은 관광지, 편의·식음은 지도 위 토글

좌측 목록에는 관광 분류(nature/history/culture/leisure)만 올린다. 음식·쇼핑은 **지우지 않고
지도 오버레이로** 옮긴다 — "이 지역 카페 보기 / 식당 보기" 토글에 별도 아이콘.

적재의 62% 가 음식·쇼핑이라 한 목록에 섞으면 관광지가 보이지 않는다. 분류 가중치(ADR-0065 P2)로
순위를 눌렀지만, 목록과 지도의 **역할을 나누는 것**이 더 정직한 해법이다.

### 6) Google 은 `place_id` 만 저장한다

지도 링크를 좌표에서 `place_id` 기반으로 바꾼다:
`https://www.google.com/maps/search/?api=1&query={name}&query_place_id={place_id}`

**저장은 `place_id` 하나로 제한한다.** Google Maps Platform 약관은 place ID 를 무기한 캐시할 수
있는 예외로 명시하고, 이름·주소·평점 등 나머지 Places 콘텐츠는 그렇지 않다. 우리가 이미 갖고 있는
이름·좌표는 TourAPI 출처이므로 섞지 않는다.

Places API 는 유료 SKU 다. 59,570건을 한 번에 해석(resolve)하는 것은 free-tier 제약과 충돌하므로
**조회된 관광지부터 온디맨드로** 해석한다 — ADR-0070 이 유튜브에 쓴 큐를 그대로 쓴다.

### 7) 유튜브·블로그는 이미 아이템 단위다 — 상품은 아니다

영상 썸네일 카드와 블로그 글 링크는 ADR-0070 에서 이미 아이템 단위로 구현됐다. 남은 것은 **키**다.

여행 상품(마이리얼트립/클룩/트립닷컴)은 **제휴 API 승인 없이는 아이템 단위가 될 수 없다.**
상품명·가격·이미지를 화면에 올리려면 그 데이터를 받아와야 하고, 공개 API 없이 받아오는 방법은
스크래핑뿐이다 — 약관 위반이고 차단·법적 노출을 free-tier 단일 노드가 계속 부담한다.
승인 전까지는 검색 진입 링크로 남긴다. **이건 코드로 풀 수 있는 문제가 아니다.**

### 8) 레이아웃 — 지도가 센터, 정보는 오버레이가 아니라 영역

```
┌──────────┬────────────────────────────┬───────────┐
│ 목록      │           지도              │  정보     │
│ (접기)    │                            │  패널     │
│          ├────────────────────────────┤           │
│          │  아이템 캐로셀 (유형별 식별) │           │
└──────────┴────────────────────────────┴───────────┘
```

지금은 정보 패널이 지도 위에 떠서 지도를 가린다. 정보를 읽는 동안 지도를 못 보는 구조는
지역 탐색과 맞지 않는다. 좌측 목록은 접어서 지도를 넓힐 수 있다.

캐로셀은 정보 패널 하단이 아니라 **지도 하단**이다 — 아이템은 "이 지역/이 장소에 딸린 것"이지
정보 패널의 부속이 아니다. 영상·블로그·상품을 **유형별로 식별되는 카드**로 구분한다.

### 9) 지역 페이지를 색인 표면으로 추가

`/regions/{시도}` · `/regions/{시도}/{시군구}` 를 고유 URL 로 연다. "제주 가볼 만한 곳" 류의
질의에 착지점이 없으면 관광지 데이터 전체가 색인 밖이다 — `/attractions/:id` 를 만든 것과 같은 이유
(ADR-0062). 구조화 데이터는 `TouristDestination` + `ItemList`.

## 결과

- (+) 시군구 축이 **정부 코드**로 확정돼 필터 결과가 경로에 상관없이 같아진다.
- (+) 목록과 지도의 역할이 갈려 관광지가 음식·쇼핑에 묻히지 않는다.
- (+) 지역 페이지가 색인 표면을 229배로 넓힌다(시군구 수만큼).
- (−) `attractions` 재동기화가 필요하다. 목록은 100건/콜이라 하루면 끝나고 개요는 보존되지만,
  그 사이 지역 필터가 부분적으로만 맞는 구간이 생긴다.
- (−) `sigungu_code` 가 당분간 두 체계를 담은 채 남는다. 신규 코드로 완전히 넘어간 뒤 제거한다 —
  지금 지우면 롤백 경로가 사라진다.
- (−) Places API 는 유료다. 온디맨드로 줄여도 조회량에 비례해 비용이 늘어난다 — 상한을 먼저 정한다.
- (−) 여행 상품은 이 ADR 로 해결되지 않는다. 제휴 승인이 선행 조건이고 코드 밖에 있다.
- 선행 조건(코드 밖): 법정동코드 자료 내려받기, Google Places API 키 + 월 상한,
  YouTube/네이버 키, 여행 제휴 프로그램 가입.
