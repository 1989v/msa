# ADR-0081 — 랭킹 리더보드 플랫폼 (rank.1989v.com): 스냅샷 원장 + 도메인별 수집기

- 상태: 채택 (2026-08-23) — P1 주유소 슬라이스
- 관련: ADR-0069(deal — 폴드/서브도메인/외부링크 패턴), ADR-0059(game — 폴드),
  ADR-0065(place — host 인식 루트 라우팅·지리 SSOT), ADR-0070(외부 :443 수집 CronJob),
  ADR-0074(wishlist — opaque targetKey), ADR-0066(메인 런처·전시 테이블),
  ADR-0062(SEO 호스트 분기), ADR-0061(엣지 노출면), ADR-0025(latency budget)

## 맥락

"아무거로나 순위를 매겨 보여주는 곳"을 만들려 한다 — 지역별 주유소 가격, 지역별 빵집,
생필품 인기. 서로 다른 도메인의 목록을 같은 모양의 리더보드로 서빙한다.

이 도메인의 제약도 코드보다 **밖**에 있다.

1. **순위를 매길 근거가 대부분 없다.** 사람들이 기대하는 "맛집 순위"의 재료(네이버·카카오
   평점)는 공식 API 가 없고 크롤링은 약관 위반이다. Google Places 는 우리 정책상 `place_id`
   외 저장이 금지다(ADR-0065 / `data-sources.md` §7). **라면 판매량 같은 실판매 데이터는
   어느 원천도 공개하지 않는다.**
2. **열려 있는 것은 사실 데이터다.** 오피넷(유가), LOCALDATA(인허가·개폐업), 참가격(실판매가),
   식약처(영양). 전부 무료이거나 이미 우리 파이프라인에 있다.
3. **외부 한도가 서비스 수명을 정한다.** 오피넷 무료 API 는 일일 한도가 공개돼 있지 않고,
   Google Routes 무료분은 월 10,000 콜이다. 사용자 요청 수에 외부 호출을 묶으면
   **인기가 생기는 순간 서비스가 죽는다.**
4. **출처 표시 의무**가 원천마다 붙는다(공공누리·KOGL).

플랫폼 제약은 그대로다 — OCI free tier 단일 노드, **신규 상시 파드는 예산 밖**이다.

## 결정

### 1) 순위는 현재값이 아니라 **스냅샷 원장**이다

`ranking_entry` 를 "현재 순위" 테이블로 두고 매번 덮어쓰면 화면이 만들 수 없는 것이 생긴다 —
**"지난주 대비 ↑3"**. 등락은 랭킹 서비스의 거의 유일한 재방문 동기인데, 그것을 만들려면
이전 시점이 남아 있어야 한다.

```
ranking_board      무엇을 · 무엇으로 · 어느 범위에서 줄세우나 + 출처표기 문자열
ranking_snapshot   시점 (board_id, captured_at, entry_count)
ranking_entry      snapshot_id, rank, subject_key, score, prev_rank, payload_json
```

부수로 **시계열이 공짜로 남는다** — 유가 추이, 개폐업 추이. blog 조회수를 Redis 카운터가 아니라
`blog_post_view` 원장으로 둔 것과 같은 판단이다.

보존기간은 ADR-0077 의 원장 정책을 따른다 — 스냅샷은 등락 계산에 필요한 최근분 외에는
`retention` CronJob 이 정리한다. **방침(`/privacy` §6)에 적은 숫자와 상수가 같아야 한다.**

### 2) 공통은 "줄 세운 결과"까지 — 도메인 지식은 내려보내지 않는다

`ranking_entry` 는 **무엇이 좋은 주유소인지 모른다.** 등수와 점수와 표시용 payload 만 안다.
점수를 만드는 규칙은 도메인별 수집기·점수기에 남는다.

도메인 이질성(브랜드·셀프여부·좌표 / kcal·나트륨 / 인허가일자)은 `payload_json` 이 흡수한다.
이걸 정규 컬럼으로 펴려 하면 **nullable 30개짜리 테이블**이 되고, 도메인 하나 늘 때마다
마이그레이션이 붙는다. 겉이 비슷하다고 합치는 것은 DRY 가 아니다 — DRY 는 지식의 중복을
없애는 것이지 모양의 중복을 없애는 게 아니다.

`subject_key` 는 **opaque 문자열**이다(`gas:{opinet_uni_id}` 꼴). ADR-0074 wishlist 의
targetKey 와 같은 규약이라 찜하기 연동이 스키마 변경 없이 붙는다.

### 3) 수집과 서빙을 분리한다 — 사용자 요청이 외부 API 를 부르지 않는다

주유소 가격은 **하루 1회** CronJob 이 전량 수집해 우리 DB 에 넣는다. 조회도, 경로 탐색도
우리 DB 만 읽는다.

오피넷 갱신 자체가 일 단위라 실시간 호출은 **같은 값을 받으려고 한도를 태우는 일**이다.
`place/ingest` 와 같은 형태 — 외부 `:443` egress 가 열리는 파드를 늘리지 않기 위해
`ranking/ingest` 하나로 모으고, 이후 도메인(LOCALDATA·참가격)도 같은 잡에 job 플래그로 붙인다.

한도 초과(429 / 한도 응답)를 만나면 **그 실행을 즉시 멈춘다.** 부분 적재를 남기면
다음 전체 동기화가 나머지를 지운다.

### 4) 좌표는 수집기가 변환해 적재하고, 원천도 남긴다

오피넷 응답의 `GIS_X_COOR`/`GIS_Y_COOR` 는 **KATEC(TM128)** 이다. WGS84 로 착각하고 그대로
저장하면 값이 십만 단위라 그럴듯한 채로 **지도의 핀만 전부 어긋난다** — 타입 검사도 빌드도
안 잡고, 화면을 열어봐야 안다.

변환은 수집기(Python `pyproj`)에서 한다. 서버가 변환하면 원천 좌표계가 도메인에 새어들고,
골든 좌표 테스트를 붙일 자리도 애매해진다. **원천 KATEC 값은 별도 컬럼으로 보존**한다
(`data-sources.md` §0 ① — 원천 필드는 전부 적재).

### 5) 유료 API 를 부르지 않는다 — 무료 수집분으로 같은 화면을 만든다

오피넷의 `최저가 Top20`·`시군구별 평균가`는 유료다. 그런데 우리는 이미 전국을 수집해 두므로
**같은 결과를 직접 집계할 수 있다.** 유료 경계를 넘지 않는 것이 free-tier 원칙의 연장이다.

### 6) 길찾기는 Google Routes API — 이탈 시간은 근사로 시작한다

| 후보 | 판정 |
|---|---|
| 카카오모빌리티 Directions | **제휴 파트너 전용** — 사전 제휴 계약 필요. 탈락 |
| **Google Routes API** | **채택** — Essentials 월 10,000 콜 무료. GCP 프로젝트와 서버 키 IP 제한 패턴이 이미 있다 |
| TMAP | 폴백 (OQ-9) |

> Directions API 는 Google 이 legacy 로 지정했다. **Routes API** 를 쓴다.

키는 **분리한다** — Maps JS 키는 공개·리퍼러 제한, Routes 키는 서버 호출이라 IP 제한이다.
한 키에 둘을 담으면 어느 제한을 걸어도 한쪽이 죽는다(YouTube·Places 키를 분리한 것과 같은 이유).

**경로 이탈 시간은 P1 에서 근사값**이다. 후보마다 경유지 포함 재호출을 하면 정확하지만
1건당 1콜이라 월 10,000 을 즉시 태운다. 폴리라인 최근접점까지의 거리 기반으로 "약 N분"으로
표기하고, 문구가 근사임을 감춘 채 단정하지 않는다.

키가 없으면 **경로 화면만 비활성, 리더보드는 정상 동작**한다 — `google-places` 잡이 키 없으면
조용히 건너뛰는 것과 같은 성질이다.

### 7) 백엔드는 code-dictionary:app 에 폴드 — 패키지는 `com.kgd.ranking`

`ranking:domain` + `ranking:feature` 라이브러리를 `code-dictionary:app` 에 폴드한다
(ADR-0058 모듈러 모놀리스, ADR-0059/0069/0072 와 같은 형태). 새 상시 파드를 만들지 않는다.

**폴드 시 고칠 곳은 세 군데다** — `scanBasePackages` / EMF `packages` / `EnableJpaRepositories`.
빠뜨리면 기동 실패가 아니라 **조용한 404** 라 배포가 성공한 것처럼 보인다.

### 8) FE 는 portal-fe host 라우팅 — 그리고 **색인 대상이다**

`rank.1989v.com` 은 같은 번들·같은 Service 를 호스트로 분기한다(ADR-0065 place 와 동형).

deal 을 noindex 로 둔 이유는 자체 부가가치 없는 링크 모음이 thin affiliate 로 읽히기
때문이었다. 랭킹은 반대다 — **집계와 등락이 우리가 만든 부가가치**이고, "OO구 최저가 주유소"는
검색 의도가 뚜렷하다. 색인 대상으로 두고 시군구·유종 URL 을 승격한다(ADR-0062).

신규 서브도메인 체크리스트 4단계를 전부 탄다 — ingress host 블록 / `App.tsx` host 분기 +
apex 리다이렉트 / 프리렌더 `_hosts/$host` 키 / **`serviceHref.ts` 의 `SUBDOMAIN_ORIGIN` 한 줄**.
④ 를 빠뜨리면 타일이 apex 경로를 걸고 hover·링크복사·새 탭·크롤러가 전부 apex 에 머문다.

## 결과

**얻는 것**

- 등락·시계열이 스키마에서 나온다 — 별도 집계 파이프라인 없이 재방문 동기가 생긴다
- 도메인을 늘리는 비용이 "수집기 + 점수기" 로 국한된다. 화면·API·찜하기는 재사용
- 외부 한도가 사용자 트래픽과 분리돼 있어 인기가 늘어도 원천이 끊기지 않는다
- 유료 API·제휴 계약 없이 free tier 안에서 완결된다

**비용**

- `payload_json` 은 스키마가 강제하지 않는다 — 도메인별 payload 계약을 테스트로 지켜야 한다
- 스냅샷은 행이 누적된다. 보존 정책(ADR-0077)을 처음부터 붙이지 않으면 free-tier 디스크를 먹는다
- 이탈 시간이 근사라 실제와 어긋날 수 있다 — 화면 문구가 이 불확실성을 감당해야 한다
- 오피넷 무료 한도가 미공개라 **전국 수집이 하루에 들어가는지는 키 발급 후에야 안다**(OQ-3/4)

**후속**

- `data-sources.md` 대장에 오피넷·Google Routes 두 줄 추가 — **코드에만 있고 대장에 없으면 없는 것**
- P2: LOCALDATA(업력·밀도·개폐업 트렌드), 참가격·영양(이미 적재분 재활용)
- P3: 자체 조회수·투표 축, 네이버 데이터랩 트렌드 축
