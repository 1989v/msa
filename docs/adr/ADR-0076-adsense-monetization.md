# ADR-0076 — AdSense 수익화: 지면은 코드가 정하고, 게시자 ID 하나가 전부를 켠다

- 상태: 채택 (2026-08-22) — 사이트 승인 2026-08-22, 광고 단위 4종 연결 2026-08-28 (광고 활성)
- 관련: ADR-0062(SEO·호스트별 정적 자산 분기), ADR-0064(이력서 게이트),
  ADR-0066(메인 런처), ADR-0069(deal — thin affiliate), ADR-0072(블로그),
  ADR-0059(게임 — HOUSE 광고)

## 맥락

운영 중인 6개 호스트(apex·game·place·blog·deal·resume)에 외부 광고를 붙여 수익화하려 한다.

전제 몇 가지가 이미 정해져 있다.

1. **portal-fe 한 벌이 6개 호스트를 서빙한다.** `index.html` 도 nginx 도 하나다. 호스트마다
   다르게 굴려야 하는 것은 전부 `$host` 또는 런타임 hostname 으로 갈라야 한다 (ADR-0062).
2. **resume 는 광고를 실을 수 없다.** 실명·연락처가 든 토큰 게이트 문서다 (ADR-0064).
   같은 이유로 GA 도 빼 뒀다 — 열람을 토큰·경로·시각으로 한정해 놓고 광고망에 열람 맥락을
   넘기면 그 결정이 무의미해진다.
3. **브랜드 면은 여백과 판의 어긋남으로 깊이를 만든다** (DESIGN.md §12). 그림자조차 쓰지
   않는 규율이라, 임의로 삽입된 띠 하나가 규칙을 깬다.
4. **게임은 조작 영역이다.** 플레이 화면에 겹친 광고는 UX 문제이기 이전에 AdSense 정책 위반이다.
5. **개인정보처리방침이 없었다.** AdSense 승인의 형식 요건이면서, 애초에 GA·지도·OAuth 를
   이미 쓰고 있었으므로 광고와 무관하게 있었어야 하는 문서다.

## 결정

### 1) 자동 광고를 쓰지 않는다 — 지면은 코드가 정한다

자동 광고는 구글이 DOM 을 훑어 스스로 자리를 잡는다. 코드가 0 이라는 장점이 있지만
전제 3·4와 정면으로 충돌한다. **`AdSlot` 컴포넌트를 넣은 자리에만 광고가 나간다.**

| | 자동 광고 | `AdSlot` (채택) |
|---|---|---|
| 자리 결정 | 구글 | 코드 |
| 브랜드 면 통제 | 불가 | 가능 |
| 게임 조작 영역 침범 | 가능 | 구조적으로 불가 |
| 초기 작업량 | 스니펫 1개 | 스니펫 + 지면당 1줄 |

지면은 넷이다. 목록·본문이 **끝난 지점**에만 둔다 — 중간에 끼우면 읽던 것을 끊는다.

| 지면 | 위치 | 왜 여기인가 |
|---|---|---|
| `blogPostEnd` | 글 본문 끝, 댓글 위 | 다 읽은 뒤라 방해가 없고, 댓글 위여서 대화 흐름도 자르지 않는다 |
| `gameHubEnd` | 게임 목록 끝 | **게임 프레임(iframe) 안에는 두지 않는다** — 조작 방해이자 정책 위반 |
| `attractionEnd` | 관광지 상세 끝 | 지도와 주변 목록을 다 본 뒤 |
| `dealHubEnd` | 혜택 목록 바깥 | 제휴 고지가 붙은 카드 사이에 끼면 어느 쪽이 광고인지 흐려진다 (ADR-0069) |

메인(`/`)과 `/portfolio` 에는 두지 않는다. 첫인상이 곧 포트폴리오인 면이다.

광고 단위 ID 는 콘솔에서 만들어야 나오므로 승인 전에는 `ADSENSE_SLOTS` 가 전부 빈
문자열이다. **자리는 코드에 박혀 있고 ID 만 비어 있는** 상태이고, 승인 후 네 줄을 채우면
그 순간 전부 켜진다.

콘솔에서 사이트별 자동 광고는 **끈 상태로 유지한다.** 켜는 순간 이 결정이 코드와 무관하게
무력화된다 — 레포만 보고 되돌릴 수 없는 종류의 설정이라 여기 적어 둔다.

로더 스크립트(`adsbygoogle.js`)는 자동·수동이 공용이므로 `index.html` 에 두는 것이 맞다.
자동 광고를 끈다는 것은 스크립트를 빼는 것이 아니라 콘솔 스위치를 끈다는 뜻이다.

### 2) 게시자 ID 하나가 전체를 켜고 끈다

`ADSENSE_CLIENT` 가 빈 문자열이면 — 로더가 조기 반환하고, `AdSlot` 이 `null` 을 그리고,
`ads.txt` 가 아예 생성되지 않는다. 세 곳이 같은 상수 하나를 본다.

승인 전에 스크립트만 먼저 나가면 게시자 없는 요청이 반복돼 심사에 불리하다. 빈 지면이
남으면 심사자가 보는 화면에 깨진 자리가 생긴다. **"아직 없음"이 정상 동작이어야 한다.**

값은 브라우저에 노출되는 공개값이라 GA 측정 ID 와 같이 레포에 그대로 둔다. 빌드 ARG 로
받지 않는 이유는 값이 비밀이 아니고, CI 주입으로 바꾸면 로컬 빌드 산출물과 배포물이
갈려 "왜 로컬에선 광고가 안 뜨지"를 매번 다시 확인해야 하기 때문이다.

`index.html` 은 정적 HTML 이라 `copy.mjs` 를 import 할 수 없어 값의 사본을 갖는다.
테마 판정 스크립트가 `useHeritageSurface` 의 사본을 두는 것과 같은 구조이고, 같은 대가
(두 곳을 함께 고쳐야 함)를 진다.

### 3) `ads.txt` 는 호스트별로 찍는다

`ads.txt` 가 없으면 대부분의 수요처가 입찰을 건너뛰어 실질 수익이 0 에 수렴한다.

서브도메인은 원래 루트 도메인의 `ads.txt` 를 따르지만, 여기서는 5개 호스트에 같은 내용을
찍는다. nginx 가 `/ads.txt` 를 `$host` 로 가르는데(robots·sitemap·llms 와 동일 구조)
서브도메인 키가 없으면 `location /` 폴백이 `index.html` 을 내보내기 때문이다. 그 응답은
파싱 실패가 아니라 **'유효한 판매자 0줄'** 로 읽혀 도메인 전체 입찰이 끊긴다.

resume 에는 찍지 않는다 — 광고를 싣지 않는 호스트다.

로더도 같은 목록을 **허용 목록**으로 쓴다. 제외 목록이면 새로 뜨는 호스트가 로더만
물려받아 `ads.txt` 없이 광고를 내보낸다 — rank 가 2026-08-23 에 그렇게 됐고, 광고
요청은 나가는데 `/ads.txt` 는 404 인 상태로 일주일을 보냈다.

### 4) `/privacy` 는 apex 하나만 둔다

호스트마다 방침을 따로 두면 한 곳만 고쳐진 채로 남는다. 라우트는 호스트를 가리지 않고
열되 canonical 은 apex 를 가리켜, 어느 호스트에서 열어도 색인은 하나로 모인다.

다른 포털 페이지와 같이 **프리렌더 대상**이다. 심사는 크롤러로 확인하는데 초기 HTML 이
비어 있으면 '방침 없음'으로 읽힐 수 있다.

푸터는 전 콘텐츠 화면 공통이므로 링크를 거기 둔다 — 광고를 싣는 모든 화면에서 방침에 닿는다.

### 5) deal 호스트에도 광고를 싣는다 — 다만 위험을 인지한 선택이다

deal 은 제휴 링크 허브라 자체 부가가치가 얇고(ADR-0069), AdSense 는 루트 도메인 단위로
심사한다. **1989v.com 전체가 함께 평가된다.** 승인이 거절되면 이 호스트를 먼저 의심한다.

`X-Robots-Tag: noindex` 는 색인 정책이고 광고 게재와는 별개다 — noindex 페이지에도 광고는
나간다. 둘을 같은 스위치로 묶지 않는다.

## 결과

**켜짐**

- 지면 위치가 코드에 남는다 — 어디에 광고가 있는지 파일에서 읽힌다.
- 게시자 ID 한 줄로 전체 on/off. 승인 전 상태가 깨진 화면을 만들지 않는다.
- 개인정보처리방침이 생겼다. 광고와 무관하게 GA·지도·OAuth 때문에 필요했던 문서다.

**대가**

- 지면을 늘리려면 코드를 고쳐야 한다. 자동 광고의 "일단 깔면 알아서" 를 포기했다.
- 게시자 ID 가 `copy.mjs` 와 `index.html` 두 곳에 있다.
- 광고 단위 ID(`data-ad-slot`)는 콘솔에서 만들어야 나오므로, 지면을 추가할 때마다
  콘솔 작업이 선행된다.

**되돌리기**

`ADSENSE_CLIENT` 를 빈 문자열로 되돌리면 광고·`ads.txt` 가 전부 사라진다. `AdSlot` 호출은
남아 있어도 `null` 을 그리므로 화면이 깨지지 않는다.

## 운영 절차 (승인까지)

1. `/privacy` 배포 — 방침 없이 신청하면 그 사유로 반려된다.
2. adsense.google.com 가입 → 사이트에 `1989v.com` 등록 (루트 하나로 서브도메인 전부 커버).
3. 소유권 확인 — **메타 태그 방식**(`google-adsense-account`, `index.html`)을 쓴다.
   코드 스니펫 방식은 못 쓴다: 로더를 `document.createElement` 로 붙이므로 HTML 소스에
   `<script src>` 태그가 없고, 확인 크롤러가 JS 를 돌리지 않으면 없는 것과 같다.
4. 심사 (며칠~2주). 이 기간에도 `ads.txt` 는 이미 나가 있어야 한다.
5. 승인 후 콘솔에서 광고 단위 생성 → 나온 `data-ad-slot` 값으로 `AdSlot` 배치.
6. 콘솔의 **자동 광고는 끈 채로 둔다** (위 1항).
