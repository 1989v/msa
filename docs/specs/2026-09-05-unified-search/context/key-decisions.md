# key-decisions — 통합 검색

근거와 실측은 `docs/plans/2026-09-05-unified-search-hybrid-embedding.md` §8 에 있다. 여기는 **무엇을 정했는가**만.

| # | 결정 | 근거 | 날짜 |
|---|---|---|---|
| 1 | 임베딩 계산은 **서버 밖**(로컬 GPU·Colab). 서버에 모델 없음, 파드 +0 | 노드 CPU 84%, CPU 추론이 모델을 300M 급으로 묶는다 | 2026-09-05 |
| 2 | 문서 벡터 원본은 **SSOT 서비스의 DB 표**, OpenSearch 는 재색인이 채우는 사본 | 인덱스가 매일 재구축된다 | 2026-09-05 |
| 3 | 질의 벡터는 **사전**(`query_vectors`), 미적중은 BM25 + 미스 로그 | 질의 다양성이 작고 반복된다는 가정 — 적중률로 검증 | 2026-09-05 |
| 4 | 모델 = **`snowflake-arctic-embed-l-v2.0-ko`** (568M · 1024차원 · Apache-2.0) | 판정 세트 nDCG@10 ko 0.7404 / en 0.7773 로 후보 중 최고 | 2026-09-06 |
| 5 | **이미지 임베딩 안 함** | 질의가 텍스트, 사진은 표시용, 공간이 다름 | 2026-09-05 |
| 6 | 벡터는 `_source` 에 **둔다**(응답에서만 제외) | `_source.excludes` 로 빼면 인덱스가 3.4배 커진다(실측 2회) | 2026-09-05 |
| 7 | hybrid 에서 `sort` 타이브레이커 대신 **앱이 페이지 안에서 정렬** | 3.3.0 이 `_score` 와 다른 정렬을 못 섞는다 | 2026-09-05 |
| 8 | 융합 방식·가중치는 **P1 에서 A/B** — RRF 를 기본으로 두되 확정 아님 | 질의별로 방향이 갈린다(`야시장` +0.513 vs `한옥` −0.270) | 2026-09-06 |

## 열린 것

- 차원 512 vs 1024 (메모리는 둘 다 가능, nDCG 차이만 남음)
- 사전 시드에 관광지 제목 6만 건을 넣을지
- 적중률 기대치 80% 가 맞는지 — 운영 첫 주에 판정
