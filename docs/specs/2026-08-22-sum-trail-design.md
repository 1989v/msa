# 합이 딱 (sum-trail) — 설계 문서

> 장르 프리셋: `grid-number-puzzle` (격자 숫자 퍼즐 — 경로 드래그형)
> 표준: `docs/standards/game-cleanroom-pipeline.md`

숫자 카드를 이어 그어 제시된 합을 **정확히** 만든다.
라운드마다 할당량을 채워야 넘어가고, 돌과 자물쇠가 길을 막는다.

---

## 1. 한 줄 요약

**수가 딱 떨어지는 순간이 유일한 정지점이다.** 합이 목표를 넘으면 더 못 잇고,
정확히 맞으면 확인 키 없이 즉시 확정된다. 나머지 설계는 그 순간을 자주 만들기 위해 붙어 있다.

---

## 2. 벤치마크 대비 자평 (6축)

벤치마크 = **모바일 캐주얼 숫자 퍼즐 상위권**의 완성도. 이 장르는 그래픽이 아니라
**훑는 손맛 · 정보 가독성 · 판이 막히지 않는 것**으로 평가된다.

| 축 | 벤치마크 수준 | 합이 딱 | 판정 |
|---|---|---|---|
| ①그래픽 | 단색 타일 + 숫자 | 1080×1440, 카드마다 3톤(deep/face/lift) + 외곽선 + 접지 그림자, 값이 곧 색인 9색 팔레트 | **상회** |
| ②애니메이션 | 즉시 교체 | 사라짐(0.14초) → 가속 낙하(7칸 0.37초) → 착지 팝, 선택 시 확대·순번 배지 | **상회** |
| ③해상도·화면 활용 | 격자가 화면의 60~70% | **격자가 화면 폭의 89.4%**, 셀이 화면 폭의 1/7.8 (프리셋 하한 1/9) | **상회** |
| ④이펙트 밀도 | 사라질 때 반짝 | 파티클 3종 360풀 · 링 · 점수 팝업 · 화면 흔들림 · 플래시 · 해제/파괴 전용 연출 | **상회** |
| ⑤조작감 | 터치 전용 | **포인터 + 키보드 완전 대응**, 되짚기 취소 양쪽 지원, 관용 반경 0.62셀 | **상회** |
| ⑥연출 | 없음 | 라운드 배너 · 테마 3종(3라운드마다 배경/광원/강조색) · **BGM 이 라운드마다 반음 상승** | **상회** |

**못 따라잡은 것**: 없음. 다만 이 벤치마크는 캐주얼 퍼즐의 하한선이므로
"상회" 는 자랑이 아니라 최소 조건 충족으로 읽어야 한다.

---

## 3. 막힌 판을 만들지 않는다 (이 장르의 1급 불변식)

목표를 난수로 뽑으면 **지금 판에서 만들 수 없는 수**가 나올 수 있다. 그 순간 게임은
"풀 수 없는데 시간만 가는" 상태가 되고, 플레이어는 자기 실력을 의심한다.

그래서 목표는 **지금 판에서 실제로 만들 수 있는 합 중에서만** 고른다:

1. `achievableSums(pred)` — 길이 2~6 경로를 제한 깊이 DFS 로 훑어 **만들 수 있는 합 전부**와
   각 합의 **가짓수**를 모은다 (49칸 × 4방향, 최악 5만 경로 — 클리어 때만 돈다)
2. 라운드 범위 안 후보를 우선하고, 가짓수가 너무 많은 합(=너무 쉬운 합)은 하위 15% 를 잘라낸다
3. **리필이 끝날 때마다 다시 검사**한다 — 여기가 막힌 판이 생기는 지점이다.
   못 만들게 됐으면 목표를 바꾸고, 그래도 안 되면 판을 섞는다

**실측**: 봇 30초 연속 플레이 중 idle 상태 **31회 전수 검사 — 풀 수 없는 판 0회, 셔플 0회.**
라운드 8까지 도달하는 동안 한 번도 막히지 않았다.

## 4. 조작 — 포인터가 1급 시민, 키보드도 완전

| | 포인터 | 키보드 |
|---|---|---|
| 시작 | 카드 누르기 | 커서 이동 후 Space |
| 잇기 | 끌기 | 방향키 (경로 끝에 인접한 칸으로) |
| 한 칸 취소 | **직전 칸으로 되짚기** | 직전 칸으로 되짚기 · X/K/Backspace |
| 전체 취소 | 손 떼기 | Esc/P/C/L |
| 확정 | 없음 — 합이 맞는 순간 자동 | 동일 |

- **관용 반경 = 셀 한 변의 0.62배**(85.6px). 셀 반폭(69px)보다 넓어 카드 사이 여백까지
  받아주고, 반대각선(97.6px)보다 좁아 대각선 오선택은 막는다
- 확정 키를 따로 두지 않는다. 모든 카드 값이 1 이상이라 **합이 목표와 같아지는 지점은
  경로당 최대 한 번**이고, 그게 유일한 정지점이다

### 실측 (합성 이벤트 · 실제 리스너 경유)

| 항목 | 결과 |
|---|---|
| 포인터 드래그로 클리어 | ✅ |
| 키보드(Space + 방향키)로 클리어 | ✅ |
| 포인터 되짚기 취소 | ✅ |
| 키보드 되짚기 취소 | ✅ |
| 손 떼면 미완성 경로 취소 | ✅ |
| 터치(pointer:coarse)로 시작·드래그·클리어 | ✅ |

## 5. 격자·카드

- 7×7, 셀 138px, 격자 966×966 = **화면 폭의 89.4%**
- 숫자는 **셀 높이의 55%** (76px)
- **값이 곧 색이다** — 1~9 각각 고유 색. 숫자를 읽기 전에 패턴이 먼저 보여야 훑는 맛이 산다
- 사라짐 0.14초 → 낙하 시작. 낙하 가속 14000px/s² 로 **7칸이 0.37초** (프리셋 상한 0.45초)

### 방해 타일 2종 — 반드시 반격 수단이 있다

| 타일 | 막는 것 | 푸는 법 |
|---|---|---|
| **돌** | 경로가 통과 못 함 | 인접한 칸을 지우면 금이 간다. **2회면 부서진다**(금이 붉게 변해 남은 내구가 보인다) |
| **자물쇠** | 값은 보이지만 못 고름 | 인접한 칸을 한 번만 지우면 풀린다 |

자물쇠는 **숫자를 가리지 않는다** — 자물쇠 아이콘을 우하단 배지로 뺐다.
가운데에 두면 "풀면 얼마가 되는지"를 못 읽어 계획이 불가능해진다.

## 6. 목표 유형 3종

| 유형 | 내용 | 등장 |
|---|---|---|
| 합 | 제시된 수를 정확히 | 라운드 1~ |
| **금지 숫자** | "7 은 못 쓴다" — 해당 값 카드가 X 표시로 잠긴다 | 라운드 4~ (30%) |
| **홀짝** | "짝수만" / "홀수만" | 라운드 6~ (22%) |

제약형 목표는 점수 배율 ×1.3. 세 유형 모두 **해 존재 검사를 같은 제약으로 돌린다** —
제약을 걸어놓고 만들 수 없는 목표를 주면 3장의 불변식이 깨진다.

## 7. 진행·난이도

| 라운드 | 값 범위 | 목표 | 할당량 | 시간 | 방해 |
|---|---|---|---|---|---|
| 1 | 1~4 | 7~13 | 3 | 67초 | — |
| 4 | 1~6 | 12~19 | 5 | 60초 | 돌 2 |
| 6 | 1~8 | 15~24 | 6 | 55초 | 돌 4 · 자물쇠 2 |
| 8 | 1~9 | 18~28 | 7 | 50초 | 돌 5 · 자물쇠 4 |

- **값 범위를 넓히는 것이 가장 강한 상향**이다 — 탐색 공간이 급증한다
- 라운드 1은 목표가 카드 3~4장으로 맞아떨어진다. 손이 경로 그리기를 먼저 배운다
- 3라운드마다 테마가 바뀐다 (심야 서재 / 자정 바다 / 노을 유리) — 배경·광원·강조색·BGM 반음

> [!warning] 봇으로 난이도를 재지 마라
> 이 게임의 봇은 **DFS 로 정답을 즉시 찾는다.** 사람은 눈으로 경로를 더듬는다.
> 1차 곡선(라운드 7 = 47초에 8조합, 목표 ~31)은 봇 기준으로는 여유로웠지만
> 사람에게는 조합당 5.9초로 과했다. 지금 곡선은 봇 측정이 아니라
> "사람이 목표 하나를 눈으로 찾는 데 걸리는 시간" 을 기준으로 잡았다.

## 8. 점수

```
점수 = 목표값 × 12 × (1 + 0.22 × (길이 − 2)) × (제약형이면 1.3) × (1 + 0.18 × 연속)
```

- **긴 경로가 이득**이라 "짧게 여러 번" 대신 "길게 한 번" 을 노리는 선택이 생긴다
- 연속(콤보)은 3.2초 안에 다음 조합을 만들면 이어진다, 최대 ×8
- 라운드 통과 시 남은 시간 × 20 보너스

## 10. 검증 결과

| 항목 | 결과 |
|---|---|
| 콘솔 메시지 | **0** |
| 죽은 입력 감사 | **120칸(4씬 × 30키) 중 0칸 죽음** |
| 방해 타일 스모크 | 돌·자물쇠·금지숫자·홀짝 4/4 |
| 돌 내구 | 인접 클리어 1회 → hp 2→1 (금이 붉게), 2회 → 파괴 |
| 자물쇠 해제 | 인접 클리어 1회로 해제 확인 |
| 돌·자물쇠 선택 거부 | `canAdd` 가 각각 `'stone'` `'lock'` 반환 |
| **막힌 판** | idle 31회 전수 검사 **0회**, 셔플 0회 |
| 입력 6종 | 포인터/키보드 각각 잇기·되짚기·취소 전부 통과 |
| 모바일 | 터치 드래그 클리어 ✅ · 셀 52.6 CSS px · 가로 넘침 없음 · **가상패드 없음**(프리셋대로) |
| fps | 120 |

### 검증에서 잡은 실버그 2종

1. **`setPointerCapture` 예외가 드래그 첫 칸을 통째로 삼켰다.**
   포인터 캡처를 `addCell` 앞에서 호출했는데, 이 API 가 던지면 그 뒤 코드가 전부 건너뛰어져
   **드래그의 첫 카드가 선택되지 않았다.** 캡처는 있으면 좋은 최적화일 뿐이므로
   입력 처리 뒤로 옮기고 try/catch 로 감쌌다.
2. **키보드에서 경로 길이가 1일 때 잇기가 취소로 오인됐다.**
   `inPath()` 는 없는 칸에 `-1` 을 주는데 `path.length - 2` 도 1일 때 `-1` 이라,
   `idx === path.length - 2` 가 참이 되어 **새 칸으로 잇는 대신 마지막 칸을 지웠다.**
   포인터 경로에는 `idx >= 0` 가드가 있었고 키보드 경로에만 없던 비대칭이었다.

두 버그 모두 "포인터로는 되는데 키보드로는 안 된다" / "두 번째 칸부터는 되는데 첫 칸이 안 된다"
라는, **눈으로 보면 되는 것처럼 보이는** 부류다.

## 11. 기술

순수 정적 웹 — HTML + JS + Canvas 2D. **빌드 스텝 없음, 런타임 외부 요청 0.**

```
sum-trail/
  index.html
  js/audio.js   WebAudio 신스 (경로 길이에 따라 음정 상승) + 16스텝 BGM
  js/fx.js      파티클·텍스트·링 풀 / 흔들림 / 플래시
  js/art.js     팔레트 · 테마 3종 · 카드/돌/자물쇠 · 트레일
  js/meta.js    localStorage 메타 진행 (실패해도 게임은 돈다)
  js/game.js    격자 · 경로 · 해 존재 검사 · 라운드 · 중력
  js/main.js    루프 · 씬 · 포인터/키보드 입력 · HUD · 검증 훅(dev.*)
```

### 검증 훅

`dev.scene(name)` · `dev.stats()` · `dev.solve()` · `dev.play()` · `dev.bot(true)` · `dev.smoke()`
— `solve()` 는 게임 내부와 **같은 규칙·같은 제약**으로 DFS 를 돌려 정답 경로를 돌려주고,
봇은 그 경로를 `addCell()` 로 한 칸씩 실제 입력한다 (쿨다운·판정을 우회하지 않는다).

## 12. IP

숫자를 이어 합을 맞추는 메커닉은 장르 문법이다. 다만 국내 판례
(대법원 2019. 6. 27. 선고 2017다212095)는 **규칙의 선택·배열·조합**이 창작적 개성을
갖추면 보호될 수 있다고 보므로, 특정 작품의 규칙 세트·진행 구조·화면 배치를 이식하지 않고
전부 이 프로젝트에서 설계했다 — 목표 유형 3종, 라운드 할당량·제한 시간 구조,
돌/자물쇠와 그 반격 수단, 해 존재 보장 규칙, 점수식이 모두 자체 설계다.
