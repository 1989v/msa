## 공격 자세 — 2026-10-18 사용자 요청

- 사용자가 줍기 모션 확인을 마친 뒤 공격 모션을 요청했다. 기존 원형 효과만 표시하는 공격을 준비→타격→회수의 짧은 맨손 공격 자세로 바꾼다. 무기 아이템/장비 규칙은 새로 도입하지 않는다.
- 공격 직전 사거리 안 가장 가까운 살아 있는 적을 기준으로 방향을 정하고, 적이 없으면 현재 시선을 유지한다. 팔은 고정 길이의 두 마디로 굽혀서 내지르며 대상까지 길어지지 않는다. 상체·머리의 작은 움직임과 전방 짧은 타격 궤적을 맞춘다. 발/허리 연결을 유지하고 북쪽 팔은 몸 뒤에 그린다.
- 성공한 공격(허공 공격 포함)에만 표현을 시작한다. 거부/쿨다운 중에는 새 동작을 만들지 않는다. 도중 움직여도 팔 길이/방향이 깨지지 않으며 채집 동작과 겹쳐 그리지 않는다. 480ms 공격 간격 전에 회수가 끝난다.
- reduced-motion에서는 정적인 공격 자세와 최소 표식만 사용한다. 기존 채집/줍기 모션을 보존한다. 공격 범위·데미지·서버 판정·경제/저장은 바꾸지 않는다. 로컬 플레이어 표현이 이번 범위이며 다른 접속자의 공격 이벤트 동기화는 포함하지 않는다.

## 맨손 보정 및 도끼 장착 — 2026-10-18 사용자 요청

- 사용자가 맨손 모션을 조금 더 다듬고 무기 하나를 장착해 공격 모션까지 확인하도록 요청했다. 기존 도끼를 첫 장착 대상으로 사용한다. 새 검/아이템 종류나 데미지/공격 사거리 조정은 하지 않는다.
- 펀치의 팔꿈치 잠김과 과한 상체 반동을 줄이고, 짧은 준비·타격·회수의 속도 변화를 보정한다. 팔 길이·네 방향/북쪽 가시성·허리/발 연결·reduced-motion을 유지한다.
- 개인 `equipped`는 null 또는 axe. C 도구 창에 도끼 장착/해제와 현재 상태를 표시한다. 보유하고 내구도가 양수인 도끼만 장착 가능하며 장착은 자원/내구도를 소모하지 않는다. 곡괭이 등 다른 장비는 이번 단계에 추가하지 않는다.
- 대기/이동에는 장착 도끼를 손에 표시하며, 공격은 고정 길이 자루를 손에 붙인 준비→내려치기→회수 자세다. 채집 도중에는 기존 채집 표현이 우선하고 종료 후 장착 자세로 돌아간다. 이미 시작한 공격은 이후 장착 변경과 무관하게 당시 장비로 끝난다.
- 승인된 도끼 공격은 허공 공격 포함 내구도1을 소비한다. 거부/쿨다운/명령 재전송은 추가 소모하지 않는다. 내구도가0이 되면 자동 해제하되 마지막 공격은 도끼로 그린다. 채집으로 도끼가 파손돼도 자동 해제한다. 기존 데미지18/반경66/쿨다운480ms는 유지한다.
- 온라인 `equip` 의도는 kind:null|axe만 허용, 소유권/내구도는 서버가 검증한다. 장착은 개인별 저장하고 재접속/서버 재시작 후 복원한다. 예전 v1/v2/v3 및 서버 기록에 equipped가 없으면 맨손으로 이행하며 잘못된 값/미보유 장착은 거부한다. 기존 로컬 저장과 공유 월드 경제 보존·중복 방지를 유지한다.
- 검증은 모델/명령·API 계약/저장 호환/실제 HTTP 장착·공격·중복·복원과 모션/DOM을 포함한다. 실제 Chrome 화면/조작 검증은 별도 명시 승인 후 수행한다. 공개 배포·원격 플레이어 장착/공격 표현 동기화는 이번 범위 밖이다.

- fence는floor없이도40격자의변을따라자유롭게연결한다. roof는새배치시바닥위에정렬. 가구/보관함은실내floor위에정상배치(보관함은바깥배치도가능). 기존중앙wall/door/fence/roof좌표는강제로옮기지않으며legacy로보존.
- 새anchored부품이연결된floor는먼저연결부품을철거해야제거가능. 이전건물/개인캠프보호유지. 저장의floorId는실제floor를참조하고좌표/회전일치·중복변·순서독립검증. 원격명령/저장/중복재전송동일규칙.
- 실제집조립회귀:2×2바닥과외곽벽/문/창문으로방을만들어연결/출입/중복공유변/회전4변/저장순서변경/재시작검증. 하단버튼→분류→부품과C제작경로DOM검증. 예전저장에완성건물/중앙벽이있어도보존.

### 다음 단계 결정
- 계단: 사용자가 실제 2층으로 오르는 계단과 다층 주택으로 확정했다. 아래 2단계 명세를 따른다.
- 동물: 닭보존+토끼/양추가. 실제포획/종별가방/사육/먹이/저장/외형을구분해야하며기존닭보존식이종간뒤섞이지않게이행한다. 구체저장계약은다음단계설계에기록한다.
- 사육공간: 두모서리로직사각영역크기선택/관리에서확장. 기존고정닭장·축사보존. 신규는완성형건물대신크기선택형울타리공간. 개체수보다작게축소하거나자원/건물/사람을침범하지못한다. 상세범위/비용/충돌은다음단계설계.

### 2단계: 실제 계단·다층 주택 (사용자 확정)
- 1~3층(level0..2)을 지원한다. 개인 위치/캠프, 집 부품/가구에 층을 저장하며 이전 기록은 모두1층으로 이행한다. 새 저장v5, v1~4 유지. 바닥의 floorId 앵커는 같은 층을 참조한다. 구조/이동/문/상호작용/철거 보호는 층을 구분한다.
- 건축창과 배치 중 선택층을 명확히 표시한다. 2·3층 바닥은 바로 아래 같은 격자 바닥의 지지가 필요하다. 위층 바닥/계단이 참조하는 바닥 철거는 거부한다. 가구는 선택층 바닥 위에 놓인다. 동물/밭/자연자원/제작 모닥불은 지상 전용, 상층 실내 보관함/침대/등불은 허용한다.
- 계단(나무8돌2)은 아래층 바닥에서 회전방향의 인접 격자에 있는 바로 위층 바닥으로 연결한다. 아래/위 floorId를 저장하고 실제 출입 위치와 통로를 검사한다. R로 오르기/내려가기, 서버가 출발층/거리/도착바닥/도착충돌을 검사한 뒤 층과 위치를 함께 변경한다. 시각적으로 높이 차와 계단 방향을 표시하며 단순 장식 계단으로 끝내지 않는다. 목적지가 막힌 이동은 거부하고 위치/층을 보존한다.
- 위층에서는 바닥 없는 곳으로 걸어 떨어지거나 지상 자원을 채집/적을 공격하지 않는다. 지상 적은 상층 플레이어를 공격하지 않는다. 침대 캠프·귀환·죽음 후 복귀·재접속도 층을 보존한다. 다른 접속자도 층/높이에 맞게 표시한다.
- 층별 높이 투영과 실내 cutaway를 적용해 현재층 캐릭터가 위층 바닥/지붕에 가려지지 않는다. 아래층 물체의 화면상 겹침을 같은 층 상호작용으로 혼동하지 않게 한다. 다른 층 문/계단/철거 대상을 선택하지 않는다.
- 서버 명령은 선택층과 앵커를 검증하며 서버 권위/순번 중복 방지/저장 원자성을 유지한다. API 계약을 갱신한다. 지지 바닥·왕복 계단·막힌 착지·다층 문·다른 층 자원/전투 차단·상층 침대 복귀·오프라인 플레이어 보호·v4이행/재시작을 검증한다.

### 3단계: 토끼·양과 크기 조절 사육 공간
- 기존 야생닭24개 ID/위치를 그대로 두고 야생토끼16/양16을 결정적으로 추가한다. 현재 큰 월드에 여러 무리를 배치하되 시작 지역에서도 각 종을 찾을 수 있게 한다. 닭/토끼/양은 외형·크기·이름이 구별되고 실제 포획·사육할 수 있다. 초기 종 추가만 수행하고 번식/무한 재생은 이번에 추가하지 않는다.
- 포획은 지상50이내, 그물+열매 사용. 닭/토끼는 그물1·열매1, 양은 그물2·열매2가 있어야 성공한다. 서버가 야생ID로 종을 결정한다. 종류별 포획 가방 수량을 보존하고 잘못된 종 지정/중복 포획/재전송의 자원·개체 중복 방지.
- 기존 inventory.captive는 닭을 유지하고 새 captiveRabbit/captiveSheep 수량을 추가한다. 기존 coops.birds 개체는 species가 없으면 chicken. 각 종별 `모든 개인 포획 가방 합계+사육 개체수=해당 종 capturedWildIds 수`를 검증한다. 공유record v2는 옛24마리 wildlife를 위치 그대로 이행하고 새32마리를 추가하며, 새버전은 잘못된 ID/종/개체 수를 거부한다. 개인/공유 마이그레이션은 재실행해도 중복 동물을 만들지 않는다.
- 닭은 기존 달걀 생산 유지. 양은 먹이30이상 시간120초마다 털1(최대3)을 생산하며 수거시섬유1, 토끼는 먹이를 주고 키우는 사육동물로 제공한다. 종별 생산 문구/수거를 구분하고 토끼에 달걀 버튼을 표시하지 않는다. 굶어도 죽지 않는 기존 규칙 유지.
- 신규 사육장은 완성형 건물이 아니라 두 모서리로 영역을 정하는 울타리 공간이다. 40단위 격자, 가로/세로 각각2~8칸. 첫클릭시작→두번째끝/Enter확정, 크기·비용·수용량 미리보기, Esc취소. 둘레울타리/문/사육동물이 선택 크기와 일치하도록 그린다. 별도의 자유 울타리 부품도 계속 배치 가능하다.
- 사육장은 coops 배열의 kind:'pen', width/height를 저장한다. 용량은min(32,칸면적), 닭/토끼1칸·양2칸 사용. 전체 시설16/실제개체128 상한 유지. 비용은wood4*(가로칸+세로칸)+fiber2. 외곽과 내부가 물/자원/건물/밭/다른시설/모든 영구 플레이어·캠프와 충돌하는지 검사한다. 사육장은 지상 전용이다.
- R 관리창에서 크기 변경을 선택한다. 동물·먹이·생산물·ID를 보존하며 확장 비용은 새 둘레 비용의 증가분만 사용한다. 축소는 환급 없이 현재 개체의 사용칸 이상이어야 하고 공간 충돌 검사도 유지한다. legacy 닭장/축사도 이 동작으로 사육 공간으로 전환 가능하지만 자동으로 바꾸거나 동물을 제거하지 않는다. 변경 전 미리보기와 명시확정, 요청재전송 비용1회.
- 넓은 사육장은 전체직사각형을 원형반경으로 다루지 않는다. 설치/재생/바닥재료 제외/충돌/가까운 관리 거리/사육 동물의 위치가 실제 경계를 따른다. 주변 자원 snapshot은 최대320규모 시설과 렌더범위를 포함하고 기존2304 범위의 모서리 검증을 유지한다.
- UI는 하단건축→울타리·마당→사육공간에서 시작, C동물은 종별 포획 준비/부족재료/가방/시설/사육 안내를 제공한다. 완성형shelter/warehouse/barn/fixedcoop 신규생성은 계속 차단한다.

### 2·3단계 설계 리뷰 보강
- 상층 이동·착지·귀환은 캐릭터 반경 전체가 같은 층 바닥으로 지지되어야 한다. 안전 위치 탐색도 같은 층에서 수행하며, 유효한 상층 캠프를 지상으로 조용히 변경하지 않는다. 귀환 공간이 없으면 동작을 거부하고 현재 위치를 보존한다. 재접속은 저장 위치 또는 같은 층의 안전 위치를 사용한다.
- 바닥 철거는 연결 부품·위층 바닥·계단뿐 아니라 해당 바닥 위 가구, 모든 영구 플레이어·캠프도 보호한다. 지지 연결은 배열 순서와 무관하게 검사한다. 같은 층 건축이 기본이며, 바로 다음 층 바닥만 아래층에서 설치할 수 있다. 계단 착지는 같은 층 문·다른 플레이어도 검사한다.
- 공유 record 버전과 개인 저장 버전은 독립적이다. record v1 안에 개인 v5가 있을 수 있다. 동물 확장 개인 저장은 v6으로 올리고 이전 버전에만 새 포획 수량0/기존 새 종 chicken 기본값을 적용한다. 야생24개의 ID·순서·좌표·home 유효성을 먼저 검증한 뒤32개를 한 번만 추가하며 record v2는 정확한56개 ID·종을 요구한다. 종별 보존은 모든 영구 게스트를 합산한다.
- 사육장 모서리는40격자 경계이며 두 경계의 차가 실제 월드 단위 width/height다. x/y는 중심, 좌상단은 중심에서 반크기를 뺀 값이다. 크기 변경은 좌상단을 고정하며 이동 기능으로 사용하지 않는다. 설치/변경은 내부 전체 점유를 검사하고, 이동은 둘레만 막는다. 남쪽 중앙에40너비 출입문을 두어 R로 여닫고 사람 위로 닫지 않는다.
- 기존 닭장은2×2칸, 축사는4×2칸을 초기 전환 미리보기로 제안한다. 사용자가 확정할 때만 전환하며 기존 시설 중심에서 계산한 좌상단을 고정한다. 새 목재 비용에서 기존 닭장12/축사28을 뺀 양수 차액과 새 섬유2를 지불한다. 돌 환급은 없다. pen 철거 환급은 실제 지불한 누적 재료와 현재 크기 비용 중 작은 값의 절반 내림으로 계산해 축소/재확장으로 재료를 생성하지 않는다.
- 양의 생산은 먹이30 이상인 시간만 누적하며120초마다 털1, 최대3에서 누적을 멈춘다.

### 완료·푸시
사용자가 '다 되면 푸시'를 명시 승인했다. 각 단계 구현/기존 저장 보존/회귀/HTTP/빌드/독립 리뷰 후 게임과 해당 문서의 커밋만 원격에 포함한다. 무관한 변경을 함께 게시하지 않는다. UI 도구 사용은 별도 명시 승인 전 하지 않으며 미검증 범위를 보고한다.
