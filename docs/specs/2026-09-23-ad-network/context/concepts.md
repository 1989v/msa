# 광고 네트워크 개념 목록 (AdSense 형)

조사 결과를 개념 단위로 나눈 목록이다. 번호는 대조용이다.
「범위」 열은 확정 범위 기준이다 — ● 1단계 포함 · ○ 모델만 두고 2단계 · × 제외.
확정 범위: 퍼블리셔는 우리 서브도메인 먼저 · 가상 크레딧 원장 · 광고주 셀프서브 콘솔.

## A. 참여자와 시장 구조

| # | 개념 | 설명 | 범위 |
|---|---|---|---|
| A1 | 광고주 (Advertiser) | 돈을 내고 광고를 싣는 쪽. 캠페인을 소유한다 | ● |
| A2 | 퍼블리셔 (Publisher) | 지면을 파는 쪽. 사이트를 소유하고 수익을 받는다 | ● (우리 서브도메인만) |
| A3 | 광고 네트워크 | 둘 사이에서 매칭·경매·과금·정산을 하는 중개자. AdSense·카카오 애드핏·데이블 | ● (우리가 이것) |
| A4 | 구매 쪽 / 판매 쪽 (buy-side / sell-side) | 광고주 도구(Google Ads·DSP)와 퍼블리셔 도구(AdSense·SSP)의 구분. AdSense 는 두 쪽 수수료를 따로 뗀다 | ● (한 시스템이 양쪽) |
| A5 | 애드 익스체인지 · SSP · DSP | 거래소와 그 양쪽 플랫폼. SSP(Supply-Side Platform)는 퍼블리셔 지면을 여러 수요처에 팔고, DSP(Demand-Side Platform)는 광고주 예산으로 여러 거래소에서 산다 | × |
| A6 | RTB (실시간 입찰) · OpenRTB 2.6 | 노출 하나마다 외부 입찰자에게 요청을 보내는 규격 | × (필드 어휘만 차용) |
| A7 | 헤더 비딩 · Prebid.js / Prebid Server | 퍼블리셔 쪽에서 여러 수요처를 동시에 경매하는 방식 | × |
| A8 | 미디에이션 · 워터폴 | 수요처를 우선순위대로 시도하고 못 채우면 다음으로 넘기는 방식. 자체 네트워크 → AdSense 대체 | ○ |
| A9 | 하우스 광고 (HOUSE) | 팔리지 않은 지면에 자기 서비스를 홍보하는 광고. 기존 game ads 모듈 | ● (빈 지면 대체) |
| A10 | DMP (Data Management Platform) | 노출·클릭·행동 로그를 모아 타기팅·분석에 쓰는 데이터 쪽. 광고 플랫폼과 역할을 나눠 갖는 경우가 많다 | ● (역할은 analytics 가 맡는다 — 로그 수집은 analytics, 분석·적용은 광고) |
| A11 | 광고 서버 (Ad Server) | 광고 결정·소재 전달·노출 집계를 하는 시스템. 퍼블리셔 쪽(GAM)과 광고주 쪽이 있고, 네트워크는 둘을 한 몸에 갖는다 | ● (D 영역이 이것) |

| B6 | 랜딩 URL · 클릭 URL | 광고를 누르면 가는 곳. 네트워크 리다이렉터를 거친다 | ● |

| B9 | 입찰가 (bid) · 입찰 전략 | 광고주가 노출 천 회(CPM) 또는 클릭 한 번(CPC)에 낼 최대 금액 | ● |

| B13 | CPT (Cost Per Time) · 보장형 | 구좌를 기간 단위로 사 단독 점유하고, 노출과 관계없이 기간이 지나면 과금. 국내 표준(카카오 비즈보드 CPT·네이버 보장형), 해외는 flat fee·sponsorship 이라 부른다 | ○ |
| B14 | 광고 형식 — 디스플레이 vs 네이티브 | 띠 배너와, 목록 안에 스폰서 항목으로 섞이는 네이티브(인피드). 커머스·목록형 서비스는 네이티브 비중이 크다 | ● (1단계 형식 결정 필요) |
| B15 | 반응형 소재 규격 | 모바일 웹 비중이 크면 고정 크기보다 비율·최소 크기로 받는다 | ● |

|---|---|---|---|

| D7 | 2차가 경매 · GSP | 승자가 차순위 가격을 낸다. 검색광고의 전통 방식 | × (대안으로만 기록) |

| D9 | eCPM 순위 | CPC 광고와 CPM 광고를 비교하려고 `입찰가 × 예상 클릭률 × 1000` 으로 환산 | ● |
| D10 | 예상 클릭률 (pCTR) | 과거 노출·클릭으로 추정한 클릭 확률. 초기에는 사전값 + 베이지안 보정 | ● (단순 모델) |
| D11 | 탐색·활용 (explore/exploit) | 새 광고에도 기회를 주는 밴딧. 레포의 Thompson 밴딧과 같은 계열 | ○ |
| D12 | 페이싱 (pacing) | 예산을 하루에 고르게 쓰도록 요청 일부를 거른다 | ● |
| D13 | 소재 렌더링 · 교차 출처 iframe | 소재를 퍼블리셔 페이지와 분리된 출처에서 그린다. 스크립트·쿠키 격리 | ● |
| D14 | 광고 서빙 도메인 분리 | 로그인 쿠키(`.1989v.com`)가 실리지 않는 별도 등록 도메인. AdSense 의 googlesyndication.com | ● (도메인 결정 필요) |
| D15 | 지연 예산 (latency budget) | 광고 결정 P99 목표. 결정 경로에 외부 호출 금지 | ● |
| D16 | 지연 로딩 | 지면이 화면에 가까워질 때 요청 | ● |
| D17 | 라인아이템 우선순위 | 보장형 계약 → 경매 → 하우스 순으로 채운다 (GAM 의 Sponsorship/Standard/Price priority/House) | ○ |
| D18 | 인벤토리 예측 (avails) | 기간·지면별 팔 수 있는 노출량 추정. 보장형 판매와 카탈로그 예상치의 근거 | ○ |
| D19 | 네이티브 삽입 규칙 · 광고 비중 (ad load) | 목록의 몇 번째에 넣을지, 광고 간 최소 간격, 같은 항목이 오가닉과 광고로 두 번 나오지 않게 중복 제거 | ● |
| D20 | 품질 점수 | 순위를 `입찰가 × 예상 클릭률 × 품질` 로 매겨 싸게 불러도 관련 높은 광고가 이기게 한다 (검색광고 품질지수) | ○ |

## F. 계측

| # | 개념 | 설명 | 범위 |
|---|---|---|---|
| F1 | 요청 · 채움률 (fill rate) | 요청 대비 광고가 채워진 비율 | ● |

| F6 | CTR · eCPM · RPM | 클릭률, 노출 천 회당 수익(광고주 쪽), 페이지 천 회당 수익(퍼블리셔 쪽) | ● |
| F7 | 이벤트 원장 | 원본 이벤트는 analytics(ClickHouse) 가 소유 (ADR-0059) | ● |
| F8 | 중복 제거 | 같은 노출·클릭이 두 번 과금되지 않도록 이벤트 ID 멱등 | ● |
| F9 | 보존기간 | 노출·클릭 원장 90일 (ADR-0077, `/privacy` §6 과 숫자 일치) | ● |
| F10 | OM SDK · VAST · SIMID | 외부 가시성 측정·동영상 광고 규격 | × |
| F11 | 위치 편향 보정 | 아래 위치일수록 클릭률이 낮다. 위치를 빼고 학습하면 pCTR 이 위치 효과를 광고 품질로 오인한다 | ● |
| F12 | 식별 키 | 빈도 제한·중복 제거의 기준. 앱은 광고 식별자(IDFA·GAID/ADID), 웹은 1st-party 쿠키 ID — 우리는 `visitorId`. 행태 타기팅에는 쓰지 않는다 | ● |
