## Goal
place 의 프리렌더·SSR 본문이 있는 화면(JS 없이 보는 크롤러 포함)이 사이트 소개·연락처·개인정보처리방침·데이터 출처와 이어지고, 데이터 출처 페이지가 원천 대장과 같은 목록을 공개한다. 관광지 상세 SSR 이 ETag 를 내고 조건부 요청에 304 로 답한다.

### SR-3 `/about`·`/data-sources` 프리렌더 본문
1. `renderPortalPages`(`prerender-seo.mjs:1596`)는 `/tech/search` 외에 분기가 없다. `/about`·`/data-sources` 분기를 새로 두고, 본문은 export 한 순수 함수 `renderAboutHtml(shell)`·`renderDataSourcesHtml(shell, rows = DATA_SOURCES)`(행을 인자로 받아 이스케이프를 시험할 수 있게 한다, 선례 `renderTechSearchHtml(shell, generated)` :1647)가 만든다.

### SR-4 상세 SSR ETag/304
1. `AttractionPageController.render()` 의 `Page.Found` 분기 `ResponseEntity` 에만 `.eTag(<본문 UTF-8 바이트 SHA-256 hex 앞 16자>)` 를 더한다. 304 판정은 Spring `HttpEntityMethodProcessor` 에 맡긴다(200·GET/HEAD 에서 If-None-Match 평가, 엔티티 헤더 유지 — spring-webmvc 7.0.6 바이트코드로 심판이 확인). `WebRequest` 파라미터는 두지 않는다. 분기 기준은 상태 코드가 아니라 `is Page.Found` 다(Fallback 도 200, `:39`). 404·셸 폴백에는 ETag 를 달지 않는다. Cache-Control 은 지금 그대로(`no-cache, must-revalidate`).
2. 약한 비교: nginx gzip 이 `W/` 를 붙여 돌려보내는 경우를 받아들인다 — `If-None-Match: W/"x"` 도 304 를 테스트로 고정.
3. 테스트(`AttractionPageControllerTest`, 실제 컨트롤러 + 렌더러): 200 응답에 ETag. 첫 응답 헤더에서 읽은 ETag 로 재요청 → 304·본문 0, 304 응답에도 `ETag`·`Cache-Control`·`X-Render` 있음. `W/` 붙은 값도 304. 다른 값 → 200. 같은 id 로 두 번째 조회 문서의 개요만 바꾸고 첫 ETag 를 보내면 200·새 개요·다른 ETag(테스트 안에서 해시를 다시 계산하지 않는다). 같은 id 의 국문·영문 경로는 본문이 같으므로(`AttractionPageService.kt:36` — Found 본문은 문서만으로 그리고 경로 언어를 쓰지 않는다) ETag 도 같다. 언어가 다른 두 문서(`AttractionPageFixtures.doc()` 와 `doc(id = "6001", lang = "en")`)는 ETag 가 다르다. 색인 조회가 예외일 때 정상 ETag 를 보내면 200·셸 본문·ETag 없음, 404 도 같은 모양. 컨트롤러 테스트는 `AttractionPageService` 네 번째 인자에 `Clock.fixed(...)` 를 넘겨 고정 시계로 돈다(위생).
4. 배포 뒤: `curl -s -o /dev/null -D - --compressed https://place.1989v.com/attractions/1` 과 `--compressed` 없는 GET 두 벌로 받은 ETag(`W/` 여부·`Content-Encoding` 기록)를 그대로 `If-None-Match` 에 실어 304 를 본다. origin 직접(`ssh msa-oci` 안에서 portal-fe 서비스)도 같은 두 벌로 재서 Q1 표에 넣는다. origin 304 가 확인되면 S2-8 은 완료로 본다. 측정 결과(origin·공개 주소 두 벌의 ETag, `W/` 여부, `Content-Encoding`, 304 여부)는 계획서 진행 상태 표(`docs/plans/2026-10-08-place-growth-work-plan.md:14`)에 S2-8 행을 더해 결과 요약 칸에 적는다. 공개 주소에서 ETag 가 사라지면 그 사실과 Cloudflare 후속(설정은 사용자 몫)도 같은 칸에 적고, 크롤 통계 304 비율은 「배포 후 관찰」로 같은 칸에 적는다. S2-8 의 lastmod 조건(plan:82 「sitemap 의 lastmod 가 재색인 시각이 아님」)은 S1-9 결과(plan:21 「lastmod = 원천 수정일」)로 이미 충족돼 이 스펙은 lastmod 코드를 바꾸지 않는다.
