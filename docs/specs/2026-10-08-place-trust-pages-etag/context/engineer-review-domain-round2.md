## 4. 새 지적 (모두 비차단, 문장 한 줄씩)

### R2-1. TourAPI 비고를 다는 행이 정해지지 않았다 — 규칙 ②가 지운 정보가 어느 행에도 안 남을 수 있다
- 대장 §1 에 TourAPI 계열 행이 10개다(`data-sources.md:68-77`). 대장은 그중 `:75-77`(축제·숙박·여행코스) 라이선스 칸에 직접 「〃 (행마다 `cpyrhtDivCd`)」를 달아 두었다.
- `spec.md:17` 규칙 ②는 이 괄호를 버린다. `spec.md:15` 는 비고를 「TourAPI 행에」 단다고만 한다. 구현자가 첫 행(`:68` 「관광지」)에만 달면, 대장이 행 단위로 명시한 사실이 정작 그 세 행에서 사라진다.
- 수정안: SR-1.2 를 「원천이 TourAPI 인 행 전부(`:68-77`)의 비고에」로 고친다. 최소한 `:68` 과 `:75-77` 을 명시한다.

### R2-2. 비고 열이 게이트 대조 대상인지 적혀 있지 않다
- `spec.md:15` 는 고지만 「상수라 게이트 대조에서 뺀다」고 하고, 비고는 언급이 없다. `spec.md:17` 의 비교 대상은 데이터·원천·라이선스뿐이다.
- 비고 두 문구는 대장 본문(`:168`, `:261`)이 원본이라 데이터다. 대장 본문이 바뀌어도 페이지가 그대로면 결정 ③(「어긋나면 테스트가 실패」, `spec.md:4`)의 취지에서 빠진다.
- 수정안(둘 중 하나를 SR-1.4 에 적는다):
  - (a) 대기 실시간 측정 비고는 정규화한 대장 본문에 부분 문자열로 있는지 단언한다(`:261` 과 글자째 같다). TourAPI 비고는 요약 문구라 핵심어 「행마다 다르다」·「변경금지」가 `:168` 에 있는지만 본다.
  - (b) 비고도 고지처럼 게이트 밖이라고 명시한다.
- 권고는 (a)다. 두 줄짜리 단언이다.

### R2-3. U2 의 「류」와 규칙 ③의 문자열 조건이 범위가 다르다 (참고)
- `spec.md:6` U2 는 「「포털 표기 미확인 — …」 류」를 비공개로 하지만, `spec.md:17` ③은 「포털 표기 미확인」을 포함하는 괄호만 버린다.
- 실제로 남는 괄호는 `data-sources.md:96` 「Google Maps Platform 약관 (place_id 만 무기한 저장 허용)」 하나다. 이것은 내부 메모가 아니라 약관 조건이라 공개해도 대장과 모순은 없다.
- 수정안: 규칙 ③ 옆에 「`:96` 괄호는 약관 조건이라 남긴다」 한 줄. 지금 규칙대로 구현해도 결과는 같으므로 선택 사항이다.
