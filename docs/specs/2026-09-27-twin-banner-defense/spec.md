# Specification: 쌍성 수비대

## Goal
승인된 `planning/visuals/04-sata-siege-revision.png`의 캐릭터·병기·적·전장을 실제로 움직이는 2인 협동 타워디펜스로 만든다. 사용자의 2026-09-27 최신 승인은 기존 사태 벡터 화풍보다 이 수정 시안을 우선한다.

## User Stories
- 혼자 군사를 소환하고 AI 동료와 성문을 지킨다.
- 다른 기기의 친구와 같은 전장에서 자기 진영을 운영하며 협력한다.
- 그림과 동일한 병사·병기가 준비하고 발사하고 재장전하는 것을 본다.

## Specific Requirements
### SR-1 전장과 경제
1. 고정된 외곽 경로의 적이 공동 성문으로 이동한다. 초기 체력 20, 20웨이브와 5/10/15/20 보스.
2. 각 좌석은 4×4 배치 칸, 초기 군량 240. 소환 비용 50, 처치·웨이브 보상과 제한된 수동 수급으로 회복한다.
3. 자신의 빈 칸에 전원에게 해금된 고정 10종 풀에서 시드 기반 무작위 소환. 별도 편성 선택·잠금·해금 없음. 같은 종류·등급 두 유닛을 합치면 같은 종류의 다음 등급. 등급 상한 4.
4. 빈 칸으로 이동과 다른 유닛 교환. 다른 좌석 수정 불가. 실패·중복 명령은 재화를 소모하지 않는다.
5. 병종 강화와 동료에게 군량 50 지원. 소환/합성/강화/지원은 DOM 버튼과 칸 탭으로 가능.
6. 아군 공격은 자동, 종류마다 사거리·공격주기·공격 방식이 다르다. 투사체 도달 시 피해, 군악수 반경 지원.

### SR-2 무장·병기·적과 모션
1. 초기 10종: 궁수, 포수, 검사, 창병, 방패병, 투석기, 신기전 화차, 총통기, 대형 총통, 군악수.
2. 아트 원본은 승인 이미지. 사태 SVG 재사용 및 사각형/삼각형 개체 폴백 금지. 개별 아틀라스로 분리한 고해상도 래스터 아트 사용.
3. 각 아군 최소 4개 실질적으로 다른 공격 프레임: 대기/준비/발사/회복. 궁수 활 당김, 창 내지름, 검사 베기, 화포 반동, 투석기 팔 회전, 화차 점화/연발, 군악수 북치기.
4. 적 최소 3종(잡병·방패병·중갑병)+보스. 보행 4프레임과 피격/사망 표현. 단순 전체 스프라이트 상하 흔들림만으로 공격·보행을 대신하지 않는다.
5. 공격 방향에 맞춘 좌우 반전, 준비→타격 시점과 투사체/효과 동기화. 합성·승급·피해·죽음은 구별되는 시청각 피드백.
6. 정적 배경에서 아군·적·UI·발사체를 제거한다. 죽은 적이나 가짜 병사가 배경에 남지 않는다. 아트 로딩 실패는 오류·재시도 화면으로 알린다.
7. 별도 에셋 갤러리에서 모든 종류의 프레임을 비교·재생하고 투명도/여백/발 접점을 검사한다.

### SR-3 싱글과 판 흐름
1. 싱글은 나(좌석0)+AI(좌석1). AI는 플레이어와 같은 비용·행동 규칙을 사용한다.
2. 시작→준비→웨이브→보스→승/패→재시작. 첫 판 도움말, 음량/음소거, 싱글 일시정지, 온라인 나가기.
3. 싱글은 네트워크 없이 작동하고 브라우저 저장으로 이어하기. 파손/다른 버전 저장은 안내하고 안전하게 새 판 선택.
4. 20웨이브 정상판과 짧은 검증판을 구분한다. 테스트 속도·무적은 기본 사용자 경험에 켜두지 않는다.

### SR-4 온라인
1. 기존 raw WebSocket `/ws/games/twin-banner-defense` 프로토콜 재사용. 서버/DB 스키마 변경 없음. 실제 2석 hi handshake와 opponentLeft 처리.
2. 빠른 협동, 코드 방, 코드 입장, 공개 방, 초대 링크. 동일 대기실에서 닉네임·준비·채팅·방장 시작. 닉네임 game_nickname, 최대16자, 채팅120자. 받은 닉네임·채팅·방장 이름은 타입·길이를 검증하고 textContent로만 표시. 2석 빠른 협동은 둘이 차면 즉시 시작하며30초 자동 시작 없음.
3. 좌석0 호스트 시뮬레이션, 게스트는 의도 명령만 전송. 신뢰 가능한 relay envelope seat로 발신자 판정, payload seat 무시. 호스트도 중복 seq와 tick/명령 범위를 검증.
4. 제한된 스냅샷·명령 메시지, 메시지당4096자·초당40개 이하. 분할시 타입/순번/시점/크기 검증, 완전한 동일 snapshot 묶음만 적용. 불완전·오래된 묶음은 폐기.
5. 브라우저 두 개에서 일치하는 적·군량·타워·체력·웨이브. 지연 중 게스트는 표시 보간만 하며 자체 피해를 계산하지 않는다.
6. 이탈 시 남은 사람은 최신 확정 상태로 AI 동료와 계속. 호스트 이탈이면 게스트가 그 상태를 승계. 이탈 처리에서 즉시 relay를 닫고 현재판을 오프라인으로 전환. 실제 legacy/manual 방은 중간 입장을 허용하므로 busy hi로 늦은 참여자에게 새 방 안내 후 이탈시키며, 진행 중 또는 AI 계속하기 중 들어오는 새 start는 무조건 무시. 현재판 중간 재접속은 지원하지 않음. 조용한 초기화 금지.
7. 개발용 relay는 같은 프로토콜과 크기/빈도 제한 사용. 실제 relay 기준 모든 연결된 사람이 권위 있는 승패 상태를 확인한 뒤 done을 전송하고, roundEnded를 받아야 준비 초기화. 중복 done은 무해. 코드방 다시하기는 그 뒤 새 seed. 운영 연결은 배포 전 미검증으로 명시.
8. 클라이언트 호스트를 신뢰하는 캐주얼 협동. 경쟁 랭킹·검증된 점수·결제 없음. 임의 relay URL은 loopback 개발 주소 외 허용하지 않음.

### SR-5 화면·입력·성능
1. 1600×900 전장 논리좌표, 가로 기본 전체 경로 보임. 세로는 같은 전장 좌표 유지 + 확대/이동과 4×4 DOM 배치 패드로 작은 타깃 보완. 타깃44 CSS px 이상.
2. 배경과 유닛 비율은 승인 시안 기준. 배치 소유는 색과 원/마름모 표시. 싱글 AI 표기.
3. 로컬 에셋만 사용, DPR 상한2. 모바일45fps/데스크톱60fps 목표, 메뉴·일시정지 렌더 정지 또는20fps 이하. hidden 탭 렌더 정지. 싱글 숨김은 자동 일시정지, 온라인 호스트 숨김은 공유 대기 상태를 전송하고 시뮬을 정지, 복귀시 재개. 프레임 누적시간 최대250ms, 그 이상의 숨김 시간을 되감아 따라잡지 않음. 게스트는 연결 유지 상태와 대기를 표시.
4. 시뮬레이션은 DOM/렌더와 분리. 프레임 시간이 길어도 고정 스텝과 시간 누적을 통해 동일 규칙.
5. 자연스러운 WebAudio 활·포격·충돌·합성·성문 피해 소리와 배경음, 사용자 입력 이후 시작, 음소거 저장.

## Visual Design
승인 이미지가 최상위 시각 기준. 직전 거절된 SVG 구도 비교판은 재사용 금지. 각 그림의 고정 조명을 유지하고 UI는 이미지에 굽지 않는다. 격자 수/길은 승인 그림의 생성 오차를 바로잡는다.

## Existing Code to Leverage
- game relay 프로토콜과 `docs/standards/online-versus-lobby.md`.
- 플랫폼 입력 표준, 공용 키 설정은 통합층에서 연결. cleanroom 구현은 다른 게임 소스 열람 없이 본 명세와 승인 아트로 만든다.
- 구현 위치 `portal-fe/public/games/twin-banner-defense/` (games submodule). 타 게임과 공용 lib 수정 없음.

## Out of Scope
운영 배포·카탈로그 등록·DB migration·랭킹·계정·유료 재화·실제 휴대폰 발열 인증. 승인 시안 품질을 갖춘 플레이 가능한 구현을 먼저 로컬에서 검증한다. 원격 공개는 별도 승인 대상.

## Open Questions
구현 전 미결 없음. 사용자 구현 승인에 따라 싱글 AI·4×4와 가로 기본/세로 배치패드를 구현 기본값으로 선택. 피드백으로 바꿀 수 있다.

## Vocabulary
좌석=한 플레이어의 소유권. 성문=공동 체력/실패 목표. 군량=좌석별 소비 재화. 소환 풀=고정10종. 등급=개별 유닛 합성 성장. 병종 강화=해당 좌석 같은 종류 전체 강화. 지원=두 좌석 사이 군량 이전. Avoid: 등급과 병종 강화의 혼용.
