# 곡선 이동 시안

2026-10-18 사용자 요청: “곡선으로 움직임은 우선 샘플로만 보여줘봐”. 기존 territory-lab을 수정하지 않고 `/games/territory-curve/`에 별도 로컬 조작 시안을 제공한다. 최종 온라인 세계 요구는 기존 spec에 보존하며 이 시안에서는 네트워크·AI·전투를 구현하지 않는다.

## 승인 범위 / 동작

- 연속 x/y 좌표와 heading. 속도 16 world units/s, 최대 회전6πrad/s(1,080°/s), 고정 120Hz 적분. 첫 이동만 입력 방향에 정렬하고 이후 방향 전환은 곡선을 그린다. 최소 회전 반지름은 약0.85 world units이다.
- 데스크탑: 필드를 누르고 있는 동안 포인터 목적지로 조향. 모바일: 최초 누른 지점을 중심으로 드래그하는 가상 조이스틱(48px 링,8px 데드존). 포인터 캡처, 놓기·취소·캡처 손실에 정지.
- WASD/방향키: 각 축에서 마지막으로 누른 키 우선, 두 축은8방향으로 합성. 대각선도 같은 이동 속도. 놓으면 이전에 유지한 키로 복귀하며 모두 놓으면 정지.
- 정지해도 노출된 선은 유지. 일시정지·조작법·초점 상실·숨겨진 탭에서 입력을 비우고 멈춤. 조작법을 닫아도 자동 재개하지 않음.
- 160×160 world-unit 유한 지도. 최초32×32 패치(면적1,024)에서 혼자 시작. 이동 감각 확인을 위해 기존49칸 시작 규칙과 분리한 실험값이다.
- 영역 판정은0.5world-unit 격자(320×320)로 근사. 이동 선분의 supercover 표본으로 대각선 틈·터널링을 방지. 내 영역에 다시 연결할 때 선과 기존 땅을 벽으로 삼은4방향 경계 flood fill로 닫힌 면적을 획득.
- 최근1.2초의 인접 선 표본은 회전 몸체로 허용. 더 오래된 자기 선을 다시 가로지르거나 지도 끝에 닿으면 이번 선만 취소하고 기존 땅을 보존한 채 출발점으로 돌아옴. 사망/공격 규칙은 없음.
- 전체 dynamic viewport를 명시적으로 채우는 캔버스와 부유 HUD. 지연 보간 없는 직접 카메라 추적, 격자선 없는 연결된 땅, 외곽 경계, 둥근 연속 선, 방향을 표시하는 원형 플레이어. 상단에 로컬 조작 시안, 시작 화면에 혼자 조작하는 곡선 시안 표기 및 기존 시안 링크.
- 색상은 root DESIGN.md §12 heritage arcade 토큰의 격리된 매핑. 새 의존성·저장·서버 변경 없음.

## 반응 지연 피드백 반영

사용자 피드백: “곡선도 좋은데 약간 반응이 딜레이가 있는거 빼고는? 곡선으로 변경시에도 플레이에 부하가 더 없다면 곡선으로 진행하면 좋을듯”.

- 원인: 기존2.8rad/s(약160°/s) 제한으로90° 방향 전환에68단계/약567ms가 필요했다. 또한 카메라에100ms 시정수의 지수 보간이 있어 이동 자체와 별개로 화면 추적이 뒤처졌다. 이벤트 처리에 의도적인 대기시간은 없었다.
- 수정:1,080°/s 제한으로90°전환을10단계/83.3ms에 완료. 목표 방향의 변화는 다음120Hz단계부터 반영. 카메라는 실제 위치에 바로 맞추며 위치 보간을 제거했다. 반대방향180°는20단계/166.7ms로 여전히 연속 회전한다.
- 시뮬레이션 적분 간격은8.3ms이며 입력은 다음 rAF에서 읽어 반영한다. 따라서60Hz에서는 프레임 직후 입력이 약16.7ms,30Hz에서는 약33.3ms 후에 처리될 수 있다. 실제 입력→화면 지연은 rAF 주기·기기·브라우저 측정 전에는 보장할 수 없다.
- 입력을 비운 뒤 물리적으로 누른 키의 자동반복 이벤트가 들어와도 다시 움직이지 않는다. 새로 누르는 동작이 있어야 재개된다. 모든 키를 놓으면 다음 단계부터 위치가 변하지 않는다.

### 판단과 검증 한계

곡선의 각도 계산과120Hz 갱신은 기준선보다 CPU를 더 쓰지만,100인원에서도 순수 이동+sweep p50약0.92ms/모의1초로 이 장치의 합성 측정에서는 작다. 따라서 곡선 이동을 채택할 근거는 있으나 “추가 부하 없음”은 입증되지 않았다. 곡선 좌표/시각적 곡면과 영역 판정 격자 해상도는 독립 선택이므로 온라인은 우선1단위 판정을 권장한다. 현재 비교에서720/1 캡처는 원래4.51ms→시안7.08ms이고,0.5는28.89ms와4배 셀 수가 필요하다. 이 시안 자체는 사용자가 체험한0.5격자를 유지했다.

렌더링·실제 입력 전달·AI30명 공격 탐색·선 충돌/동시획득·네트워크·서버 지연·저사양 모바일·온라인 무제한 수용량은 이 합성 측정에 포함하지 않는다. 원래30AI게임 전체와 솔로 시안 전체를 비교한 결과가 아니다. 캡처는 동기식 전역 flood fill이며 여러 명이 동시에 닫으면 비용이 누적된다. 최종 온라인은 같은 인원/규칙/렌더링을 갖춘 구현에서 재측정하고 캡처 작업 예산 또는 분할 처리를 검토해야 한다.
