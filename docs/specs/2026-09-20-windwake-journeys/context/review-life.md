# Domain and usecase review

Verdict: **SHIP with the resolutions below incorporated in journey-contract.md**.

Reviewed spec.md, context/key-decisions.md, previous Frontiers life contracts, current progression.mjs, village.mjs, frontier-ui.mjs, sim.mjs save/interaction code, and the hns domain/usecase seed/checklists previously loaded in this team session.

1. **Quest readiness and claims need separate facts.** Spec requirement2 permits prior completion and insists on physical return. Existing durable chest/trial/boss records already support proof (`windwake/sim.mjs:199`, `:396`, `:442`); no new unbounded kill counter is needed. Resolution:16known quest IDs with status0/1/2 (unaccepted/accepted/claimed); readiness derived from recognized world or dungeon proof. Second quest requires first claimed; costs validated and charged only when physically claiming from the matching guide.
2. **Town UI cannot grant distant services.** Current home domain independently validates range (`windwake/village.mjs:76`) and menu actions can otherwise remain visible after movement. Resolution: townAction validates playing mode, outdoor scene, known NPC membership, role, ≤4.2m horizontal/≤2.5m vertical, action eligibility and cost. Panels explain distance. Relic equip and quest tracking are separate location-independent commands; equip still rejects nearby combat or active raid.
3. **Alliances and relics must have one canonical source.** Requirement5 promises functional effects, while current modifiers contain only learned skills (`windwake/progression.mjs:76`). Resolution: owned relics are a unique8-ID set, equipped has exactly2distinct owned IDs, alliance membership derives from claimed regional quests. Apply immutable catalog modifiers with explicit combined caps; home flask/tower benefits derive from alliance count and do not stack per interaction.
4. **Indoor scene isolation includes home domain actions.** Existing villageAction accepts any playing state and only checks world coordinates (`windwake/village.mjs:76`). Local dungeon coordinates could accidentally overlap home. Resolution: reject every villageAction when expedition.active is set, and keep village ticking disabled indoors in root orchestration.
5. **Migration must initialize new fields explicitly.** validateAdventure reconstructs only its known fields (`windwake/progression.mjs:84`); export/load currently serializes v2 adventure/village (`windwake/sim.mjs:419`). Resolution: independent s.journey initialized/validated by root v3 save orchestration; old v1/v2 get empty journey without changing legacy progression. No NPC coordinates, collision shapes or arbitrary effect values are deserialized.
6. **Regional trades must avoid a profitable exchange cycle.** Requirement5 asks distinct useful services. Resolution: wood↔stone exchanges use4→3 in either direction; consumables have no sell-back, seed exchanges feed time-based crops, and the observatory sells a finite skill-point respec rather than repeatable XP. Invalid/full inventory/reset-with-no-skills rejects before charging.

Usecase acceptance: fresh visit→first local quest→real prerequisite→return claim→regional quest→dungeon/outdoor boss→return alliance; precompleted objective accepted later; repeated claim, wrong guide, distant panel, dungeon coordinates, unaffordable trade, duplicate equip, forged quest ordering, capped bonuses, and old-save defaults. NPC guide/merchant/keeper roles remain recognizable through text as well as visual symbols.
