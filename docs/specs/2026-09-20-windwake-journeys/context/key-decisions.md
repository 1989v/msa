# Integration contracts

Primary owns sim.mjs, main.mjs, index.html/style.css, save orchestration, publishing and browser integration. World worker owns world.mjs/render.mjs and world tests. Life worker owns new settlements.mjs, journey-ui.mjs, relic data, progression/village modifier integration and domain tests. Dungeon worker owns new dungeons.mjs and dungeon domain/natural-route tests. Workers are not alone and must not revert others.

world.mjs exports TOWNS (8) and DUNGEON_ENTRANCES (4), also LANDMARKS kinds town/dungeon. Town record: {id:'town-'+biomeId,biomeId,name,x,y,z,radius:28,waypointId,service,description,npcs:[{id,name,role,x,y,z}]}. Town center offset to side of existing waypoint; keep waypoint road and NPC approaches clear. Entrances IDs dungeon-sunfields,dungeon-canyon,dungeon-mistwood,dungeon-alpine, distinct authored approach roads. world owns finite geometry/clearing and keeps old exports compatible.

New local dungeon context is s.expedition.active, null outdoors or {id,...progress}. Pure dungeons.mjs imports world metadata, never sim/render/browser. It exports DUNGEONS catalog and initExpedition(), validateExpedition(raw), dungeonFloor(s,x,z), dungeonSolids(s,x,z,r), dungeonBounds(s), dungeonInteraction(s), dungeonAction(s,action,payload,hooks), tickDungeon(s,dt,hooks), enterDungeon(s,id,hooks), leaveDungeon(s,hooks), dungeonObjective(s). Dungeon worker finalizes exact progress/actor contracts before implementation. Use local coordinates within ±150, floor≥0 on safe paths, pit floor−12. No overworld spatial function when active. All walls/doors have actual matching solids; renderer consumes same geometry. Dungeon clear/reward marker is separate from adventure.bosses/worldDefeated.

Primary supplies hooks for spawning bounded enemies, hitting, XP, relic grants, effects/toasts, and enter/leave scene clearing/restoration. Runtime world actors are parked only in transient fieldState and excluded from durable saves; village/crops/raids cannot run in dungeon coordinates. Save active progress uses validated dungeon ID and bounded puzzle/kill IDs, not raw geometry. Reload/death reenter at safe dungeon entry with recorded clear facts; loss cannot award or reset treasures. Dungeon bosses must use family AI and dungeonId, never legacy bossId/ending path. Every collision, projectile, ray and camera uses same scene floor/solids.

Settlement domain: initJourney(), validateJourney(raw), townInteraction(s), townAction(s,action,payload), journeyObjective(s), grantRelic(s,id), plus catalogexports. s.journey stores known town visits, accepted/claimed quest stages, relic ownership, equipped2slots, trackedquest, alliance benefits. Domain functions independently validate mode, scene, NPC distance, eligibility and costs. No UI-only checks. Effects combine with existing progression.modifiers using explicit caps. Life worker finalizes exact catalog/contracts before edits. No network/backend changes.

Existing same-game deployment is authorized. Shared user dirty/staged files are untouched; use scoped commits and isolated release worktree. Only publisher allowlisted runtime files go public. Newly added modules must be in publisher and deployed verifier allowlists. No Higgsfield or external assets.
