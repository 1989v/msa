## 1. 먼저 고쳐야 하는 것 — 지역 코드가 섞여 있다

드릴다운을 지금 데이터 위에 올릴 수 없다. 실측(2026-08-20):

```
attractions.sigungu_code (ko 44,904건)
  법정동 시군구코드(3자리)   25,030행 → 257쌍
  TourAPI 구 sigungucode     19,874행 → 229쌍
  ────────────────────────────────────
  합계                                486쌍   (실제 시군구는 229개)
```

수집기가 "구 코드가 있으면 쓰고 없으면 법정동 코드" 로 대체해 온 결과다. 같은 구가 두 번
나타난다. `regions.CITY` 도 대안이 아니다 — GeoNames 인구밀집지 덤프라 흥해읍·왜관읍이 섞여
있고 `admin2_code` 가 296행 전부 NULL 이다.

### 해결

1. **`admin_regions`** 신설 — 행정안전부 법정동코드 전체자료(공공누리 제1유형).
   시도 17 + 시군구 229. 폐지 항목 제외.
2. **`attractions.ldong_regn_cd` / `ldong_signgu_cd`** 추가 — TourAPI 신체계가 주는 값 그대로.
3. 목록 재동기화(`--job=sync`). 100건/콜이라 하루면 끝나고 **개요는 보존된다**(`syncFrom`).
4. 화면·API 의 지역 축은 법정동 코드로 통일. `area_code`/`sigungu_code` 는 남기되 쓰지 않는다.

```
admin_regions
  code        VARCHAR(5) PK    -- 시도 2자리(11) / 시군구 5자리(11110)
  parent_code VARCHAR(5) NULL  -- 시군구 → 시도
  level       VARCHAR(10)      -- SIDO / SIGUNGU
  name        VARCHAR(60)      -- 서울특별시 / 종로구
  name_en     VARCHAR(80) NULL
  latitude / longitude DOUBLE NULL   -- 지도 중심 (§2)
```

`name_en` 은 영문 화면용이다. **법정동 자료에 영문 컬럼이 없다**(2026-08-20 확인 — 컬럼은
법정동코드/법정동명/폐지여부 뿐이고 페이지에 영문 전환도 없다). 로마자 변환 규칙으로 만들지
않는다 — `서울특별시 → Seoul` 같은 관례를 규칙이 못 잡는다.

대신 **이미 가진 데이터에서 뽑는다** (추가 API 호출 0):

| 레벨 | 원천 | 근거 |
|---|---|---|
| 시도 (17) | 상수 `SIDO_EN` | 원천이 깨졌다 — `Jeonnam-Gwangju Special Metropolitan City` 568건이 전남·광주를 뭉갠다 |
| 시군구 (229) | 영문 관광지 주소의 최빈값 | 품질이 좋다. 4,000건 표본에서 추출 실패 0.5%, 노이즈 0.7% |

주소에서 어느 칸을 볼지는 **법정동 한글명의 단어 수**가 정한다. `종로구`(1단어)는 뒤에서 둘째,
`전주시 완산구`(2단어)는 한 칸 더 앞을 함께 본다 — 시 아래 자치구가 있으면 위치가 밀린다.

**최빈값이 못 고치는 것**: 원천이 일관되게 틀린 값(인천 서구 137건 전부 `Seohae-gu`, 맞는 표기는
`Seo-gu`). 잡이 결과를 시도별로 찍으므로 첫 실행 후 한 번 훑는다. 229개를 손으로 적는 것보다
뽑고 검수하는 쪽이 오류가 적다.

영문명이 비면 화면은 `name`(한글)을 그대로 쓴다 — 없는 번역을 지어내지 않는다.

## 2. 지역 드릴다운

```
GET /api/places/admin-regions?level=SIDO&lang=ko
GET /api/places/admin-regions?level=SIGUNGU&parent=11&lang=ko
    → { regions: [ { code, parentCode, level, name, nameEn, latitude, longitude, attractionCount } ] }
```

**search 가 아니라 place 다.** place 가 행정구역과 관광지를 둘 다 갖고 있어 교차 서비스 호출도
색인 변경도 필요 없다. 시도 건수는 시군구 건수의 합으로 **한 번의 group by** 에서 같이 만든다 —
레벨마다 따로 세면 합이 안 맞는 순간이 생기고 화면에서 알아채기 어렵다.

`lang` 을 주지 않으면 `attractionCount` 가 `null` 이다. 0(세어봤고 없음)과 구분해야 한다.

- `attractionCount` 는 관광 분류만 센다 — 음식·쇼핑까지 세면 "제주 12,000곳" 같은 수가 나와
  기대와 어긋난다.
- 현재 위치가 있으면 그 좌표가 속한 시도를 **상단에 올린다**. 자동 선택하지 않는다 —
  위치가 곧 목적지는 아니다.
- 위치→시도 판정은 경계 폴리곤 없이 `admin_regions` 중심 좌표 최근접으로 한다. 경계가 필요할
  만큼 정밀한 판단이 아니다.

| 레벨 | 줌 |

| SIDO | 9 |

## 3. 목록과 지도의 역할 분리

- 좌측 목록: 관광 분류(nature/history/culture/leisure)만
- 지도 오버레이 토글: `카페·식당 보기` / `쇼핑 보기` — 별도 아이콘, 목록에는 안 올린다
- 토글은 현재 지도 bounds 안에서만 조회한다. 시군구 전체 식당을 다 찍으면 지도가 마커로 덮인다

## 4. Google `place_id`

```
GET /api/places/attractions/{id}/links → deepLinks 에 GOOGLE_MAPS 추가
  place_id 있음: https://www.google.com/maps/search/?api=1&query={name}&query_place_id={id}
  없음:          https://www.google.com/maps/search/?api=1&query={lat},{lng}   (현재 동작)
```

- **저장은 `place_id` 하나뿐이다.** Google Maps Platform 약관이 무기한 캐시를 허용하는 유일한
  필드다. 이름·주소·평점은 받아도 저장하지 않는다.
- 해석은 ADR-0070 의 온디맨드 큐를 그대로 쓴다 (`AttractionLinkSource.GOOGLE_PLACE` 추가).
  전량 해석은 유료 SKU 라 free-tier 제약과 충돌한다.
- **월 상한을 코드에 박는다.** 예산 초과 시 조용히 좌표 링크로 떨어진다 — 링크가 깨지지 않는다.

## 5·6. 아이템 단위 콘텐츠

- 유튜브 영상 카드 · 네이버 블로그 글: **구현 완료**(ADR-0070). `YOUTUBE_API_KEY`,
  `NAVER_CLIENT_ID/SECRET` 만 넣으면 동작한다.
- 여행 상품: **제휴 API 승인이 선행 조건.** 상품명·가격·이미지를 화면에 올리려면 그 데이터를
  받아와야 하고, 공개 API 없이 받는 방법은 스크래핑뿐이라 약관 위반이다.
  Klook·Trip.com 은 제휴 프로그램에 상품 API 가 있고, 마이리얼트립은 공개 프로그램이 확인되지
  않았다. 승인 전에는 검색 진입 링크로 남는다.

## 7·8. 레이아웃

```
┌────────────┬─────────────────────────────┬──────────────┐
│ 목록        │            지도              │  정보 패널    │
│ (접기/펼치기)│                             │  (오버레이 X) │
│            ├─────────────────────────────┤              │
│            │  아이템 캐로셀 (유형별 식별)   │              │
└────────────┴─────────────────────────────┴──────────────┘
```

- 정보 패널이 지도를 가리지 않는다. 지역 탐색은 지도를 보면서 읽는 행위다.
- 캐로셀은 **지도 하단**. 아이템은 장소에 딸린 것이지 정보 패널의 부속이 아니다.
- 유형 식별: 영상(썸네일 16:9 + 재생 표시) / 블로그(텍스트 카드) / 상품(가격 자리) —
  색이 아니라 **형태**로 가른다. 색만으로 가르면 색각 이상에서 구분이 사라진다.
- 좁은 화면(<900px): 목록 접힘이 기본, 캐로셀은 지도 아래로 흐른다.

### SEO / AEO (ADR-0062 연장)

- `/regions/{시도}` · `/regions/{시도}/{시군구}` 고유 URL + 프리렌더
- 구조화 데이터 `TouristDestination` + `ItemList`
- 지역 페이지는 `noindex` 가 아니다 — "제주 가볼 만한 곳" 류 질의의 착지점이 필요하다

## 9. 검색 필터

```
GET /api/search/attractions?sidoCode=11&sigunguCode=11110&category=history&keyword=...
```

`areaCode` 파라미터는 남기되 신규 축과 병행하지 않는다 — 둘 다 받으면 어느 쪽이 이기는지
호출자가 알 수 없다. 신규 축으로 넘어간 뒤 제거한다.

## 10. 하지 않는 것

- 행정구역 **경계 폴리곤** — P2. GeoJSON 용량과 free-tier 전송 비용을 먼저 계산한다.
- `regions`(GeoNames) 를 시군구 체계로 개조 — 지명 데이터셋을 행정구역으로 쓰면 지금
  `sigungu_code` 에 일어난 일이 반복된다.
- 상품 데이터 **크롤링** — 약관 위반.
- Places API 로 이름·주소·평점 저장 — 약관 위반(`place_id` 만 예외).

## 11. 미결 (OQ)

| ID | 질문 | 막는 것 | 해소 |
|---|---|---|---|
| OQ-1 | 법정동 자료의 시군구 229 와 TourAPI `lDongSignguCd` 가 100% 대응하는가 | 드릴다운 정확도 | 재동기화 후 미매칭 건수 집계 |
| OQ-2 | 세종시(단층제)·제주(행정시) 같은 예외 처리 | 계층 표시 | 자료 적재 후 확인 |
| OQ-3 | Places API 월 비용 상한 | §4 착수 | SKU 단가 × 예상 조회량 |
| OQ-4 | 여행 제휴 프로그램 가입 가능 여부 | §6 전체 | 사용자 확인 |

## 12. 검증

- 재동기화 후 `ldong_signgu_cd` 미매칭 0 건 (OQ-1)
- 드릴다운 합계 = 시도별 관광지 수 합 (누락 없음)
- 지도 링크: `place_id` 있는 것과 없는 것 모두 열린다 (폴백이 죽지 않는다)
- 레이아웃: CDP 4조합 + 좁은 화면 — `docs/standards/fe-visual-verification.md`
- 지역 페이지 프리렌더 산출물에 `_hosts/$host` 키 적용 확인 (ADR-0062 함정)
