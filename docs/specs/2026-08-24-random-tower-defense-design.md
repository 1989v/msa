# 랜덤 타워 디펜스 (random-tower-defense) — 설계 문서

> 무작위 소환 웨이브 디펜스. 뽑고 · 겹치고 · 막는다.
> 순수 정적 웹(HTML + JS + Canvas 2D). 빌드 스텝 없음, 런타임 외부 요청 0.

---

## 1. 장르와 지향

한국 커스텀맵 상위권의 절반을 차지하는 **랜덤/운빨 디펜스 계열**을 웹으로 옮긴 것이다.
장르 골격은 이렇게 정의했다.

| 장르 요소 | 이 게임에서의 구현 |
|---|---|
| 매 라운드 자원으로 유닛을 **무작위로 뽑는다** | 금화로 소환. 단, 독립 확률이 아니라 **10장짜리 주머니**를 섞어 뽑는다 |
| 같은 유닛을 **겹쳐 상위 등급**으로 | 같은 지킴이 3기 → 한 등급 위 무작위 |
| **조합표**로 지정 유닛 산출 | 8종. 조합 전용 지킴이 8기는 조합표로만 나온다 |
| 정해진 **경로를 도는 적 웨이브** | 레인마다 5단 뱀형 경로(34칸). 떠도는눈는 경로를 무시하고 직선 하강 |
| 못 막으면 **누적 패배** | 방벽 26 공유. 0 이 되면 종료 |
| **개인 구역 + 협동** | 소환사 슬롯 1~4, 각자 레인. 우두머리(보스)는 공유 |

**IP**: 세계관 · 지킴이 · 어둠벌레 · 우두머리 · 등급명은 전부 창작이다.
서빙 파일(코드 · 주석 · UI 문구 · 메타태그)에 타사 게임/애니/상표/실존 인물 명칭 **0건**
(자동 스캔으로 확인).

## 2. 최우선 제약 — 이탈 내성

### 2-1. 한 판 10~15분
기본 20판 20 웨이브. **자동 플레이 실측 11.3~15.5분** (4회 평균 13.2분).
긴 40판(40 웨이브, 약 25분)은 원작 길이를 원하는 사람을 위한 선택지다.

### 2-2. 슬롯 배열 + 런타임 승계
플레이어는 배열(`sim.slots[]`)이고 각 슬롯은 `kind: 'human' | 'ai'` 를 **판 도중 언제든** 바꾼다.

- 전환 수단: 레인 머리의 「사람 / AI 대행 중」 버튼(탭·클릭) · `Shift + 1~4`
- 승계 즉시 `RTD.AI` 가 그 슬롯의 의도를 밀어넣는다 — 계속 뽑고, 배치하고, 합성하고,
  보스 예고를 읽어 정답 스킬까지 쓴다
- **표시**: 레인 머리 배지가 보라로 바뀌고 맥동한다 · 소환사 아바타가 보라로 물들고
  이름표가 「AI 대행 중」 이 된다 · 커서 색이 바뀐다 · 기록 패널에 전환이 남는다
- 복귀하면 그 자리에서 사람이 다시 맡는다. **판은 멈추지 않는다**

### 2-3. 네트워크 계층 없음 · 권위 1곳 · 의도 분리
- 시뮬레이션은 `RTD.Sim` 하나뿐이고 **모든 입력은 의도(intent)** 로만 들어간다:
  `cursor · cursorTo · confirm · summon · merge · sell · upgrade · skill · kind`
- 사람 입력(키보드/포인터)과 AI 컨트롤러는 **같은 큐**에 같은 모양의 의도를 넣는다.
  릴레이가 붙으면 원격 슬롯의 의도를 이 큐에 얹기만 하면 된다
- 표현(소리·이펙트)은 `sim.events` 큐로 흘려보내고 시뮬 자신은 아무것도 그리지 않는다.
  좌표는 전부 **칸 단위**라 해상도·레이아웃과 독립이다
- 슬롯별 난수는 시드에서 파생된 독립 스트림(`U.rng`)이다

### 2-4. 혼자 나가도 판이 성립
슬롯 수는 1~4 어느 값이든 완주 가능(1슬롯 완주 회귀 통과). 우두머리 체력은 슬롯 수에
비례하고, 일반 웨이브 체력은 `0.92 + 0.08 × 인원`으로 완만히 오른다 — 인원이 늘어도
난이도가 반토막 나지 않는다.

## 3. 시스템

### 3-1. 등급 (6단계)

| 등급 | 이름 | 색 | 종수 | 기준 가치 | 획득 |
|---|---|---|---|---|---|
| Ⅰ | 파편 | 회색 | 8 | 20 | 소환 |
| Ⅱ | 문양 | 초록 | 7 | 62 | 소환 · 합성 |
| Ⅲ | 인장 | 청색 | 8 (조합 2) | 190 | 소환 · 합성 · 조합 |
| Ⅳ | 성흔 | 보라 | 6 (조합 2) | 580 | 소환 · 합성 · 조합 |
| Ⅴ | 왕관 | 금색 | 5 (조합 2) | 1,750 | 합성 · 조합 **(소환 불가)** |
| Ⅵ | 천공 | 무지개 | 3 (조합 2) | 5,200 | 합성 · 조합 **(소환 불가)** |

**구역당 보유 상한**: Ⅴ(전설) 18기 · Ⅵ(신화) 7기. **20판을 넘기면 열 판마다 한 단계씩 풀린다** — 긴 40판에서 화력이 상한에 막혀 멈추면 후반이 통째로 무너진다. 상한이 없으면 후반에 최상위가 판을 뒤덮어
성장 곡선이 무너진다(실측: 상한 없이 12웨이브에 Ⅵ 도배 → 이후 전 구간 무피격).
상한 덕분에 "무엇을 남기고 무엇을 팔 것인가" 가 후반의 판단이 된다.

### 3-2. 소환 주머니 — 시드 운 제거 (★ 핵심 설계)

절차 뽑기를 **독립 확률로 굴리지 않는다.**

1. 소환 등급별로 **구성이 고정된 10장 주머니**를 만든다
   (Lv1 = Ⅰ7·Ⅱ3 / Lv3 = Ⅰ3·Ⅱ5·Ⅲ2 / Lv5 = Ⅱ4·Ⅲ4·Ⅳ2)
2. 각 등급 몫은 **서로 다른 종류를 `ceil(n/2)` 개만** 고르고 나머지는 그것들로 채운다
   → 한 주머니 안에서 **같은 지킴이가 반드시 겹친다**. "겹칠 것이 하나도 안 나오는 판"이
   구조적으로 불가능하다
3. 그 위에 **천장**: Ⅲ 이상이 14회 안에 반드시 나온다
4. **첫 주머니는 두 번째 장 안에 Ⅱ 이상이 오게 고정**한다 —
   개시 4장이 전부 Ⅰ 이면 1웨이브가 운으로 갈린다(실측: 같은 편성에서 0누출 / 9누출)

| 소환 등급 | 비용 | 강화 비용 | 주머니 구성 (Ⅰ/Ⅱ/Ⅲ/Ⅳ) |
|---|---|---|---|
| Lv1 | 22 | 180 | 7 / 3 / 0 / 0 |
| Lv2 | 38 | 420 | 5 / 4 / 1 / 0 |
| Lv3 | 70 | 900 | 3 / 5 / 2 / 0 |
| Lv4 | 130 | 1,900 | 1 / 5 / 3 / 1 |
| Lv5 | 240 | — | 0 / 4 / 4 / 2 |

> **소환 비용이 등급을 따라 오르는 이유**: 비용을 고정하면 판매 환급(가치의 60%)이
> 소환 비용을 넘어 **무한 금화**가 된다. Lv5 주머니 한 장의 기대 가치는 217, 고정 비용
> 22 로는 뽑아서 파는 것만으로 이득이다. 실측에서 판매 수입이 처치 수입의 4.5배까지
> 부풀었다. 등급별 비용을 두면 어떤 등급에서도 환급 < 투입이 성립한다.

### 3-3. 조합표 (8종)

| 산출 | 재료 | 등급 |
|---|---|---|
| 불꽃폭풍 | 화염술사 + 전류술사 + 불씨 | Ⅲ |
| 서리사슬 | 빙결술사 + 진흙손 + 서릿날 | Ⅲ |
| 황금저울 | 광부 ×2 + 부적술사 | Ⅳ |
| 저주못 | 역병사제 + 저격눈 + 망치꾼 | Ⅳ |
| 천리안 | 불꽃창 + 얼음감옥 + 번개술사 | Ⅴ |
| 불꽃대장간 | 황금저울 + 부적술사 + 화산심장 | Ⅴ |
| 별을삼킨자 | 잿빛태양 + 천둥왕좌 + 얼음지옥 | Ⅵ |
| 봉인석 | 천리안 + 불꽃대장간 + 절대영도 | Ⅵ |

마지막 둘은 앞 조합의 산출물을 재료로 쓴다 — **2단 조합 트리**다.
「합성」 한 번이면 조합표가 있을 때 조합을 우선하고, 없으면 같은 것 3기를 겹친다.
우측 패널이 "지금 만들 수 있는 조합" 을 항상 띄운다.

### 3-4. 공격 계열 (11종)
단일 · 폭발 · 관통 · 연쇄 · 광선 · 저격 · 파동 · 장판 · 포격 · 지원(오라) · 수급(금화)

부가 효과: 둔화 · 정지 · 화상 · 중독(전파) · 방어 감소 · 넉백 · 처형 · 감전

### 3-5. 소환사 스킬 (슬롯마다 독립)

| 스킬 | 효과 | 재사용 | 언제 쓰나 |
|---|---|---|---|
| 공격 강화 | 8초간 내 레인 공격력 +60% | 45초 | 보스가 굳거나 회복할 때 |
| 적 멈춤 | 내 레인 어둠벌레 전부 2.4초 정지 | 60초 | 돌진 · 위상이동 예고 |
| 무료 뽑기 | 무료 소환 3회 + 그 3회 등급 +1 | 75초 | 침묵 · 역행으로 판이 무너졌을 때 |

### 3-6. 월드 · 카메라 · 미니맵

한 화면에 다 들어오는 판이 아니다. 지도를 보며 카메라를 옮겨 다닌다.

| 항목 | 값 | 가드레일 G1 기준 |
|---|---|---|
| 월드 | **11,520 × 11,520 px = 288 × 288 타일** (72×72 칸, 1칸 = 4타일 = 160px) | 128 타일 이상 (권장 192) ✓ |
| 한 화면이 보는 면적 | **8.49% / 4.16% / 2.12%** (줌 3단 전부) | 10% 이하 (권장 5%) ✓ |
| 지킴이 **실제 렌더 높이** | **1/18.4** (47px / 화면 863px) | 전략·디펜스 1/16~1/24 ✓ |
| 적 실제 렌더 높이 | **1/22.7** | ✓ |
| 구역 | 소환사마다 1개(네 귀퉁이) + **중앙 공유 방벽** | 4~8 ✓ |
| 동시 개체 | 웨이브 진행 중 100~250, 스트레스 실측 **531** | 100+ (권장 200~300) ✓ |

**회로가 맵을 크게 돈다** — 맵 가장자리 등장 → 접근로 → 내 구역 뱀형 회로(7단 × 14칸) →
탈출로 → **중앙 방벽**. 네 구역의 출구가 전부 가운데로 모이므로 누가 흘리든 같은 곳이 깎인다.
회로 길이 **143.5칸**(단일 화면 시절 34칸의 4.2배), 배치 칸 **78**(20의 3.9배).
비행 적은 회로를 무시하고 가장자리에서 중앙까지 **대각선으로 가로지른다** — 지대가 유리해도
비행은 그 이득을 못 받는다.

**카메라**: 끌기 · 휠 · `+`/`-` · 상단 버튼으로 3단 줌 · 미니맵 탭 점프 · `[` `]` 구역 전환 시
자동 이동 · `H` 내 구역으로 · 모바일 **핀치 줌**. 포커스 구역을 부드럽게 따라가고, 사용자가
직접 옮기면 추종을 멈춘다.

**미니맵**: 전체 월드 · 4구역 · 회로 · 적 점 · 우두머리 위치 · 카메라 사각형 ·
**누출 경보(그 구역 테두리가 붉게)**. 탭하면 그 지점으로 점프한다.
협동에서 **다른 소환사의 화면을 크게 보여주지 않는다** — 왼쪽 목록(금화·칸·적 수)과
미니맵 표식이면 충분하다.

**컬링**: 화면 밖 개체는 그리지 않고 시뮬은 전부 돈다. 지형 눈금도 보이는 사각형만 그린다.

> **밸런스를 옮긴 방법** — 적 속도를 **회로 길이에 비례해 자동 보정**(`lane.len / 34`)해서
> 한 바퀴 도는 시간을 그대로 유지했고, 경제·체력·팀화력 기준만 4배로 옮겼다.
> **전투 수치(사거리·피해·등급·조합)는 한 줄도 안 건드렸다** — 사거리가 전부 '칸' 단위라
> 그림 크기를 줄여도 판정이 따라 움직이지 않기 때문이다. 가드레일이 경고한
> "캐릭터를 줄이면 소품·사거리·판정폭을 함께 재조정해야 한다" 는 경로가 아예 생기지 않는다.

### 3-7. 구역 (4종) — 5 웨이브마다 지대가 바뀐다

배경 · 경로 타일 · **지형 기믹**이 실제로 달라진다. 기믹은 경로의 특정 구간 위에서만 작동하고,
그 구간을 사거리로 덮는 지킴이에게도 영향을 준다. 현재 구역과 효과는 좌측 패널에 상시 표시된다.

| 웨이브 | 구역 | 색조 | 지형 기믹 |
|---|---|---|---|
| 1~5 | 시작 지대 | 보라 | 없음 — 지형이 방해하지 않는다 |
| 6~10 | 얼음 벌판 | 청색 | **결빙 지대**(경로 26~48%) — 지나는 어둠벌레 30% 둔화. 순수 이득 |
| 11~15 | 불의 골짜기 | 주황 | **용암 균열**(46~70%) — 초당 최대 체력 2.2% 화상, 대신 곁의 지킴이 공격속도 −15% |
| 16~20 | 어둠의 제단 | 자홍 | **침식 지대**(60~90%) — 어둠벌레 방어 +15%, 대신 곁의 지킴이 사거리 +30% |

긴 40판(21~40)은 같은 순서로 한 바퀴 더 돈다.
떠도는눈는 경로를 무시하므로 지형 기믹의 영향을 받지 않는다 — 지대가 유리할수록 비행이 무섭다.

### 3-7. 어둠벌레 (12종) · 우두머리 (4기)

어둠벌레: 어둠벌레 · 철갑벌레(중갑) · 번개발(신속) · 쌍둥이알(분열) · 회복벌레 · 방패벌레(보호막) ·
떠도는눈(비행) · 성난뿔(체력 낮을수록 가속) · 저주눈(지킴이 공속 감소 오라) · 작은떼 ·
깜빡이(주기적 위상) · 거인(미니보스급)

## 4. 우두머리 — 패턴 → 정답 → 예고 → 실패 시

우두머리는 **레인마다 「분신」를 하나씩 내려보내고 체력은 하나로 공유**한다.
모두가 동시에 같은 보스를 때리고, 분신 하나라도 방벽에 닿으면 **한 번만** 5 피해를
주고 전부 출발선으로 돌아간다(분신 수만큼 중복 피해를 주지 않는다).

예고는 **형태(도형) · 색 · 소리 3중으로 분리**하고, 도형 옆에 정답을 한 줄로 띄운다.

### 무쇠아귀 (웨이브 5 · 2페이즈)
| 패턴 | 예고(도형/색/시간) | 정답 | 실패 시 |
|---|---|---|---|
| 강철돌진 | 화살 / 주홍 / 2.2s | **적 멈춤**(정지) 또는 둔화 계열 | 3.2초간 속도 3.2배로 전진 |
| 갑주경화 | 겹육각 / 회색 / 1.8s | **방어 깎기**(망치꾼·역병사제) 또는 공격 강화 | 7초간 방어 +55% |

## 5. 밸런스 — 자동 플레이 실측으로 잡았다

측정 지표를 두 개 썼다.
- **df (death fraction)**: 처치된 어둠벌레가 **경로의 몇 %까지 살아서 갔는가**.
  낮을수록 방어가 과잉이다. 0.15~0.40 을 건강한 구간으로 봤다
- **완주 회귀**: 타이틀 → 20 웨이브 → 결과 화면까지 한 런

| 항목 | 최종 값 |
|---|---|
| 기준 체력 곡선 | `24 × 1.56^(min(w,10)−1) × 1.30^(clamp(w,10,20)−10) × 1.24^(w−20)` |
| 밀도 | 개수 `×(1 + 0.064(w−1))` · 스폰 간격 `×max(0.34, 1 − 0.030(w−1))` |
| 어둠벌레 속도 | `×(1 + 0.014(w−1))` |
| 처치 금화 | `2 + 0.9w` · 웨이브 보너스 `30 + 14w` |
| 우두머리 체력 | `목표 처치 시간(초) × 22 × 1.432^(w−1) × 슬롯 수` (40 / 42 / 46 / 56초) |
| 방벽 | 26 (해금으로 +5) · 우두머리 돌파 1회 −5 |

**두 구간 곡선을 쓰는 이유**: 10웨이브까지는 등급이 계단식으로 뛰어 화력이 웨이브당
1.5배 가까이 오르지만, 등급 상한에 걸린 뒤로는 완만해진다. 한 지수로 덮으면 전반이
너무 쉽거나 후반 웨이브가 120~160초씩 늘어진다(둘 다 실측했다).

### 실측 결과 (전 슬롯 AI, 기본 20판, 시드 무작위 · 맵 확대 후)

| 슬롯 | 방벽 | 결과 | 실플레이 | 남은 방벽 | 누출 |
|---|---|---|---|---|---|
| 1 | 18 | 승 | 10.5분 | 18 / 18 | 0 |
| 3 | 26 | 승 | 10.8분 | 19 / 26 | 7 |
| 3 | 26 | 승 | 11.5분 | 13 / 26 | 13 |
| 4 | 30 | 승 | 10.7분 | 5 / 30 | 25 |

**한 판 10.5~11.5분**(목표 11~15분 언저리). 인원이 늘수록 빡빡하다 —
혼자면 지킬 곳이 하나뿐이라 가장 무난하고, **넷이면 새는 곳이 넷이라 가장 빡빡하다**.

- **방벽은 구역 수에 비례**(14 + 4×인원)한다. 구역마다 새는 곳이 하나씩 늘기 때문이고,
  이렇게 두면 인원이 몇이든 **한 구역이 감당하는 압박**이 같아진다
- 웨이브 체력은 인원과 무관하게 같다 — **인원수로 난이도를 깎지 않는다**
- 1~10 웨이브에서는 방벽이 거의 안 깎인다. 승패는 후반 구역(불의 골짜기 ~ 어둠의 제단)에서 갈린다
- 이 AI 는 지킴이를 **재배치하지 않고** 스킬도 우두머리 예고에만 쓴다. 사람은 팔고 다시 짜기 ·
  조합표 노리기 · 무료 뽑기 타이밍을 훨씬 잘 쓴다
- 져도 **별조각**이 남아 영구 강화로 다음 판이 쉬워진다

**긴 40판**: 3슬롯 **승리 · 44.3분 · 방벽 14/26 · 우두머리 8기**.
21판부터는 열 판마다 최상위 보유 상한이 한 단계씩 풀려 화력이 계속 자란다 —
상한을 고정해 두면 30판에서 화력이 멈춘 채 웨이브만 커져 무너졌다(실측).

> **하네스 함정 하나를 여기서 잡았다** — "1슬롯이 계속 진다" 는 측정이 4회 나왔는데,
> 원인은 게임이 아니라 검증 스크립트였다. 준비 화면의 인원 수는 **순환이 아니라 클램프**라
> `3 → 오른쪽 → 오른쪽` 이 1이 아니라 **4** 가 됐다. 즉 4슬롯을 1슬롯이라고 재고 있었다.
> 고친 뒤 1슬롯은 무피격 클리어였다. **대량 실패는 코드보다 측정을 먼저 의심하라.**

### 성능

| 환경 | 전체 개체 | 화면 안 | fps | sim | draw |
|---|---|---|---|---|---|
| 헤드리스 (GPU 사용) | 105 → **480** | 27 → 102 | **120 고정** | ≤0.1ms | 1.3~1.5ms |
| 실제 GPU (headed) | 105 → 531 | 23 → 103 | **120 고정** | ≤0.1ms | 0.8~1.2ms |
| ~~헤드리스 + `--disable-gpu`~~ | 143 → 583 | — | ~~40~50~~ | ≤1.2ms | 1.0~2.0ms |

> **`--headless=new` 에 `--disable-gpu` 를 붙이지 마라.** SwiftShader(소프트웨어 래스터)로
> 떨어져 같은 조건에서 fps 가 40~50 으로 반토막 난다. 관성으로 붙이던 플래그였고,
> 빼자마자 헤드리스에서도 **120fps** 가 나왔다. 헤드리스 fps 가 낮으면 게임을 의심하기 전에
> 이 플래그부터 의심하라 (실측).

동시 개체 480 에서도 120fps 를 유지한다. 기술 도입 게이트(WebGL/WASM)의 어느 문턱에도
닿지 않으므로 **도입하지 않는다**.

프레임 페이싱은 고정 1/60 누적이 아니라 **클램프된 가변 스텝**(프레임당 1~4 서브스텝,
서브스텝 ≤20ms)이다 — 120Hz 에서 렌더 프레임의 절반이 0스텝으로 도는 스터터를 피한다.

**키 계약**: 확정 = `Z/Enter/Space/L/J/F`, 뒤로 = `Esc/Backspace/X/Q` 로 전 씬 동일.
무배정 키는 **거절음 + 화면 흔들림**으로 반드시 응답한다.

## 10. 검증

| 항목 | 결과 |
|---|---|
| 콘솔 메시지 | **0** (에러 0 · 경고 0 · 네트워크 실패 0 · favicon 은 data URI) |
| 죽은 입력 감사 | **660칸 (12씬 × 55키) 전부 반응** — 처음 3칸(도감/기록 스크롤 끝)은 끝단 피드백 추가로 해소 |
| 스모크(전 개체 실소환) | **54 개체 전부 통과** (지킴이 37 · 어둠벌레 13 · 우두머리 4 — 실제 발사·패턴 해결까지) |
| 완주 회귀 | 타이틀 → 20웨이브 → 결과 → 재시작, **3슬롯/1슬롯 모두 통과** |
| AI 승계 실측 | 사람 조작 → `Shift+1` 로 대행 전환 → AI 가 계속 소환/합성 → 복귀 시 AI 정지 → 사람 입력 재개, **전부 확인** |
| 메타 영속 | 도감 37/37 · 업적 21 · 파편 234 가 `localStorage` 에 남고 재부팅 후 복원 |
| 프레임 | 120fps 고정 · sim ≤0.2ms · draw ≤1.6ms |

검증은 전부 **실제 `KeyboardEvent` 디스패치**(CDP `Input.dispatchKeyEvent`)로 했다.
전용 포트(9502) · 전용 프로필로 격리했고, 측정 전 `document.visibilityState` 와
렌더 루프 진행을 확인하는 위생 검사를 넣었다.

### 이번 제작에서 실제로 터진 것

1. **창이 뒤로 밀리면 rAF 가 조용히 멈춘다** — `visibilityState=hidden` 이 되어 시뮬이
   얼어붙는데 예외는 안 난다. 측정 3회를 날렸다. `Emulation.setFocusEmulationEnabled` +
   `Page.setWebLifecycleState('active')` 로 고정하고, 측정 전 렌더 루프 진행을 검사하게 했다
2. **우두머리가 피해를 안 받았다** — 분신의 체력을 매 프레임 공유 풀에서 덮어써서
   그 사이 들어간 피해가 통째로 버려졌다. 보스가 죽지 않아 밸런스를 세 번 잘못 조정할 뻔했다.
   피해를 공유 풀로 직접 보내도록 고쳤다
3. **돌파 피해가 레인 수만큼 중복**됐다 — 분신 3기가 동시에 도착해 24 피해.
   "분신는 하나의 우두머리다" 로 통일했다
4. **판매가 소환보다 이득이었다** — 고정 소환 비용 + 등급 가치 기반 환급의 조합.
   판매 수입이 처치 수입의 4.5배까지 부풀었다. 소환 비용을 등급에 연동해 막았다
5. **브라우저 캐시로 스테일 스크립트를 물었다** — 고친 파일이 반영 안 돼 유령 버그를
   쫓았다. 부팅 시 `Network.clearBrowserCache` + 캐시 무효 서버로 고정
6. **검증 하네스 감도** — 키 홀드 30ms 에서 입력이 간헐적으로 씹혀 "복귀 후 입력 안 됨"
   으로 오독했다. 홀드 55ms + 폴링으로 바꾸니 정상. **대량 실패는 코드보다 측정을 먼저 의심**
7. **이펙트 풀이 가득 차면 메인 스레드가 멈췄다** — 풀이 상한(1,200)에 닿았을 때
   `live.shift()` 로 배열을 통째로 밀었다. 후반 웨이브처럼 프레임당 수백 개가 생기는 구간에서
   O(n²)가 되어 화면이 얼어붙었다. **가득 차면 가장 오래된 칸을 제자리에서 덮어쓰도록** 바꿨다.
   fps 는 120 을 유지하는데 CDP 응답만 죽는 형태라 처음엔 브라우저 문제로 오독했다
8. **120fps 캔버스를 그대로 읽으면 캡처가 40초를 넘긴다** — `Page.captureScreenshot` 도
   `canvas.toDataURL` 도 GPU 큐를 비우느라 멈춘다. **캡처 전에 렌더 루프를 세우고
   (`RTDDev.halt`) 축소 배율로 찍으면 0.2초**에 끝난다
9. **큰 배경 캔버스를 구역마다 새로 만들면 안 된다** — 3장 × 5.5M 픽셀이 계속 쌓였다.
   같은 캔버스를 지우고 다시 굽는다
