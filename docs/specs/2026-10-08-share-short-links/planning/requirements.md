# 요구사항 — 공유용 단축 링크

## 목적

공유 주소가 길다. 이력서 제출처 링크는 `https://resume.1989v.com/?k=<32자 토큰>` 이고,
글·게임 주소는 슬러그가 길다. 모든 공유 대상에 **짧은 고정 주소**를 붙인다.

## 확정 사항

### R1. 주소 형태 — apex 하나

| 접두사 | 대상 | 원래 주소 (302 목적지) |
|---|---|---|
| `/r/{code}` | 이력서 제출처 링크 | `https://resume.1989v.com/?k={token}` |
| `/p/{code}` | 관광지 상세 | `https://place.1989v.com/attractions/{id}` |
| `/g/{code}` | 게임 상세 | `https://game.1989v.com/games/{slug}` |
| `/b/{code}` | 블로그 글 | `https://blog.1989v.com/posts/{slug}` |
| `/{접두사}/list` | 각 서비스 목록 (고정 별칭) | 해당 서비스 홈 |

- 호스트는 `1989v.com` 하나. 서브도메인에는 단축 경로를 열지 않는다.
- apex 의 기존 라우트(`App.tsx`)와 `/r` `/p` `/g` `/b` 는 겹치지 않는다. 2026-10-08 에 확인했다.
- `list` 는 예약어다. 코드는 6자 이상이라 `list`(4자)와 충돌하지 않는다.

### R2. 코드는 대상에서 자동으로 정해진다 — 생성 단계 없음

사용자 답변 원문: "각각 엔드포인트별로 자동으로 식별되어 라우팅되도록, 별도 공유 버튼 없이도.
공유버튼 누르면 해당 단축 url이 보여야 함".

- **공개 콘텐츠(p·g·b)**: 코드는 대상의 숫자 `id` 를 되돌릴 수 있게 인코딩한 값이다
  (base62, 6자 이상). 매핑 테이블과 생성 API 는 없다. 모든 대상은 생기는 순간부터 단축 주소를 가진다.
  같은 대상은 언제나 같은 코드를 갖는다. 슬러그를 바꿔도 코드는 그대로다.
  - id 를 그대로 노출하지 않도록 고정 순열을 거친다. 이 순열은 비밀이 아니다.
    공개 대상의 주소는 원래 공개라서, 안전은 R4 의 공개 판정이 지킨다.
- **이력서(r)**: 토큰이 곧 열람 권한이라 코드를 추측할 수 없어야 한다.
  share link 행마다 **10자 무작위 base62 코드**를 둔다. 링크를 만들 때 자동으로 부여하고,
  기존 행에는 일괄로 채운다. 철회한 링크의 코드는 R4 처럼 무효가 된다.

### R3. 해석은 대상을 가진 도메인이 한다

- deal `/go/{slug}` 와 같은 모양이다(`DealRedirectController.kt`). 게이트웨이 경로 → 302 응답,
  헤더는 `Cache-Control: no-store` · `X-Robots-Tag: noindex, nofollow`. 클릭 기록이 실패해도
  리다이렉트는 나간다.
- `/r/**` 는 atlas 의 code-dictionary(resume)로, `/p/**` `/g/**` `/b/**` 는 content 의 place·game·blog 로 보낸다.
- 인그레스는 apex 호스트에 `/r` `/p` `/g` `/b` → gateway 규칙을 둔다.

### R4. 공개된 것만 해석한다

- 블로그: `PUBLISHED` 인 글만. 게임: 공개 목록에 나오는 상태만. 비공개 게임(ADR-0089) 판정은
  상세 API 의 노출 규칙과 같은 함수를 쓴다. 관광지: 존재하면.
- 이력서: 철회되지 않은 링크만.
- 해석에 실패하면(코드 형식 오류·대상 없음·비공개) → 열린 질문 Q1.

### R5. 공유 버튼은 단축 주소를 보여 준다

- 상세 응답(게임·글·관광지)에 `shortUrl` 을 담는다. 인코딩은 서버 한 곳에서만 한다.
  FE 에 같은 순열을 다시 구현하지 않는다.
- 블로그 `SharePanel` 은 이미 있다. 게임 상세와 관광지 상세의 공유·복사도 단축 주소를 쓴다.
  관광지 상세에는 지금 공유 버튼이 없다 → 열린 질문 Q2.
- 어드민 이력서 화면의 링크 복사 버튼(`admin/frontend/src/pages/ResumePage.tsx:281`)은 단축 주소를 복사한다.

### R6. 클릭 계측 — 누적 카운트 + 원장 90일

- 대상별 누적 클릭 수와 클릭 원장(시각·리퍼러 호스트·UA 계열, **IP 는 저장하지 않는다**)을 남긴다.
  deal `deal_offer_click` 과 같은 필드다.
- 원장은 보존기간 CronJob(`k8s/base/retention/`)이 90일로 정리한다. ADR-0077 과
  `/privacy` §6 의 숫자를 같이 맞춘다.
- 크롤러 UA 는 세지 않는다. 리다이렉트는 크롤러에게도 나간다.

## 재사용할 기존 코드

| 무엇 | 어디 |
|---|---|
| 302 리다이렉터 모양 | `deal/feature/.../presentation/controller/DealRedirectController.kt` |
| 게이트웨이가 FE 경로를 받는 선례 | `GatewayRouteConfig.kt` `deal-redirect`(463) · `blog-page`(528) |
| 이력서 토큰 생성 | `ResumeAdminService.kt:29-30,100-105` (`SecureRandom`) |
| 공유 패널 | `portal-fe/src/pages/blog/SharePanel.tsx` |
| 원장 보존기간 정리 | `k8s/base/retention/cronjob*.yaml` |

## 관측

- 단축 주소 해석 결과(성공·형식 오류·대상 없음·공개 아님·폐기)는 응답으로 구분하지 않고(모두 302), debug 로그 한 줄로 남긴다.
- 클릭 원장 행 수로 실제 유입을 본다.

## 범위 밖

- 임의 URL 단축(외부 주소). 대상은 위 네 종류만 받는다.
- 서브도메인 단축 경로. deal·rank 단축 주소.
- 만료·사용 횟수 제한. 이력서 링크는 철회로만 끈다(ADR-0064 와 같다).
- 커스텀 별칭(사람이 고른 코드).
- 짧은 주소 전용 OG 카드. 미리보기 크롤러는 302 를 따라가 원래 페이지의 meta 를 읽는다.
