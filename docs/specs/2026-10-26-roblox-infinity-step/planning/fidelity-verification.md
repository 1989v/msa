# 원작 기준 복원 검증 — 2026-10-28

> **최신 사용자 정정이 우선한다.** 아래 원본 추출/좌표/규모 항목은 연구 과정의 기록이며, 새 로블록스 맵이 원본 개수·좌표·3000높이에 일치해야 한다는 합격 기준이 아니다. spec.md의 “최우선 개정 — 게임 구성·아이디어를 유지한 로블록스 최적화”를 적용한다.

## 현재 합격 기준

- 7개 구간을 오르며 충전 점프·달리기·매달림·등반·스태미나·추락·재도전이 연결되는 게임 구성을 유지한다.
- 새 네이티브 맵의 경로 연결·점프 여유·안전 착지·구간별 장치·표시와 충돌의 일치를 검사한다.
- Part/Wedge/Truss 중심 구성과 스트리밍/객체 예산을 검증한다. 원본 경사 타일 개수나 원작 LinkArc와의 개수 일치를 검사하지 않는다.
- 일반 빌드/검증에 원작 C# 추출·Unity·.NET이 필요하지 않아야 한다. 원본 자료는 선택적 참고다.
- 저장/마지막 발판 부활/영수증·차감·전달 안전성은 회귀 검사한다.
- 실제 스튜디오 플레이·터치·화면 비교는 도구 접근이 되기 전까지 미검증이다.

## 검증 증거의 구분

1. 원작 C# 자체의 비대화형 평가: 실제 지형/경로/Leap 해를 얻었다는 증거다. 웹 직접 플레이 증거가 아니다.
2. Luau 모듈 검사: 이동·상태·저장·부활 로직의 입력과 결과를 검사한다. 로블록스 API와 물리를 실제 엔진에서 실행했다는 증거가 아니다.
3. 파일 검사: 내보낸 지형이 포함되고, 올바른 서비스에 정확한 스크립트가 들어간다는 증거다. 보기 좋은 화면이나 조작감을 입증하지 않는다.
4. 실제 스튜디오/웹 비교: 앞의 세 가지와 별도이며 도구 접근 거절 상태에서는 미검증이다.

## 아직 완료라고 할 수 없는 것

직접 스튜디오 플레이와 원작의 실제 화면/조작 비교. 날짜별 새 맵 생성, 무한 구간, 일부 표현/동적 규칙이 미지원이라면 각각 명시한다. 미지원 기능을 구간 이름이나 문서만 추가해 지원으로 표시하지 않는다.
