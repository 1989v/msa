## 이슈 (REVISE)

**R1 [#4 #2] 출처 폴백이 S1-11 매핑과 어긋남**
- 스펙: 새 필드가 없으면 「지금 고정 문구로 폴백」(spec.md:39), 회귀 주입도 이 폴백을 전제(:46).
- 입력: S1-11 은 「값 미전달·미지원이면 「출처: 정보 없음」. TourAPI로 자동 추정 금지」(s1-11-trust-field-mapping.md:80), 계획 S2-2 는 「출처·원천 갱신일·수집일은 S1-11 매핑대로」(plan:79).
- 같은 절에서 함께 빠진 것: GOCAMPING 표시명(「한국관광공사 고캠핑」 s1-11:80)과 영문 라벨, `modifiedAt` null 일 때 「원천 갱신일: 정보 없음」(s1-11:81), 수집일 처리(S1-11 은 신설 전 「수집일: 정보 없음」 s1-11:83인데 스펙은 「쓰지 않는다」 spec.md:26).
- 수정안: SR-4.2 폴백을 「출처: 정보 없음」으로 바꾼다. 배포 순서가 어긋나도 화면은 깨지지 않으니 안전성 이유는 그대로 성립한다. SR-2.5 에 source→표시명 표(TOURAPI/GOCAMPING × ko/en)와 `modifiedAt` null 문구를 적는다. 수집일 칸은 생략으로 가면 S1-11 과 다르게 가는 이유를 한 줄로 남긴다. SR-5.1 에 「SSR HTML 에 원천 갱신일 텍스트」와 「modifiedAt null」 단언을 추가한다.

**R2 [#5] `tel:` 정규화가 실제 원문에서 깨진 링크를 만든다**
- 스펙: 「숫자·하이픈만 남겨 링크로」(spec.md:27).
- 원문: 「행사장 02-319-1220운영사 02-737-6444」(s2-7-fact-check.md:28, 번호 둘이 붙어 있음), 「02-724-0274~6」(:31), 「02-2153-0310, 0311 (12:00~13:0」(:38), 「K-컬처 스퀘어 운영사무국 02-2068-1176」(:16). 숫자·하이픈만 남기면 :28 은 번호 둘이 이어진 한 줄이 되고, :38 은 시간 숫자까지 붙는다.
- 수정안: 「원문에서 처음 나오는 전화번호 패턴 하나만 링크, 패턴이 없으면 링크 없이 원문만」으로 규칙을 바꾼다. `infoCenter`·`tel` 이 둘 다 없으면(:23·:33) 전화 버튼을 내지 않는다고 적는다. 위 네 원문을 픽스처로 SR-5.1 에 넣는다.

**R3 [#5] 휴무 파서 v3 에 부정 표본이 없다**
- 파서는 `※` 앞에서 자른 뒤 `,`·`/` 로 나눈다(AttractionAttributeParser.kt:65·:81). 그래서 「매주 월요일 (단, …)」은 쉼표에서 둘로 갈려 UNKNOWN 이 된다 → 괄호 단서는 나누기 **전에** 떼야 한다.
- 부정 표본: 「매월 마지막 월요일 (단, 공휴일일 경우 …)」(s2-7:18)은 괄호를 떼도 MON 이 되면 안 된다. 서오릉 원문(s2-7:15)은 표에서 잘려 괄호가 닫히는지 보이지 않는다.
- 수정안: SR-5.1 파서 픽스처를 id 로 명시한다 — 양성 77·4811(MON), 음성 16151(UNKNOWN 유지), 닫히지 않은 괄호(끝까지 단서로 본다/UNKNOWN 중 하나를 정함).

**R4 [#4] S2-7 재측정에 기대값이 없다**
- 스펙: 「전후 표로」만 적음(spec.md:43).
- 입력은 id 단위 목록을 준다: 휴무 누락 2건(s2-7:44), 요금 반복정보 11건(:45), 무료 9건(:46). 9건 중 13354 는 11건 목록에 없어서 SR-2.3 의 입력 확장으로는 안 바뀐다. 11295 의 「무료」는 주차 원문 「가능 요금 (무료)」(s2-7:14)일 수 있다.
- 수정안: 기대값을 미리 적는다 — 휴무 누락 2→0, 요금 「정보 없음」 11건 → 0, 입장 UNKNOWN 9건 중 반복정보 행에 금액 없는 「무료」만 있는 id 만 FREE. 13354 처럼 안 바뀌는 id 는 이유와 함께 「남는 건」으로 표에 둔다.

**R5 [#2] 집계 문장·이웃 절이 기존 SSR 과 겹친다**
- 지금 `regionSection` 이 이미 「{시군구} {유형} N곳 중 {분류} M곳」(AttractionPageRenderer.kt:535-545)과 「같은 분류 가까운 곳」(:557)을 낸다. SR-3.3 의 새 문장 「{시군구}의 {분류} {N}곳 중 하나」(spec.md:32)를 대체로 쓰는지 추가로 쓰는지 적혀 있지 않다. 그대로 두면 같은 숫자가 두 문장으로 나간다.
- 수정안: 「기존 문장을 이 문구로 바꾼다(ko/en 둘 다)」 또는 「기존 문장 유지, SR-3.3 삭제」 중 하나를 고른다. 「0건이면 절 없음」은 끝난 행사를 거른 **뒤** 센다(:552)고 명시하고, FE 의 같은 절에도 같은 규칙을 적는다.

**R6 [#5] SSR `<img>` 의 `width`·`height` 를 얻을 곳이 없다**
- 스펙: https·`width`·`height`(spec.md:33), 검증 :42.
- 색인 매핑에 이미지 크기 필드가 없다(`attractions-index.json` 에 `width` 0건). og 는 고정 상수 1200×630 을 쓴다(AttractionPageRenderer.kt:725-726). 원천이 http/https 를 섞어 준다(placeView.ts:265).
- 수정안: 크기는 고정 비율 상수 + CSS `object-fit`/`aspect-ratio` 로 둔다고 정한다. http 주소는 https 로 바꿀지 그 사진을 건너뛸지 정한다(S2-5 의 「적재 시 https 치환」 plan:83 과의 관계 포함).

**R7 [#5] 영문 페이지 요금 출처 규칙이 비어 있다**
- 반복정보 행 이름이 국문 3종뿐(spec.md:23)인데, 폴드 측정은 국·영 둘 다다(:44). 영문 원천의 `infoname` 은 다른 표기라서 영문 요금 칸은 그대로 「Not provided」가 된다.
- 수정안: 영문 행 이름 목록을 넣거나 「영문은 이번 범위 밖, 요금 칸 변화 없음」을 Out of Scope 에 적는다.

**R8 [#4] S3-7 완료 조건 일부가 사용자 몫으로 넘어감**
- 계획: Schema.org 와 Google 리치 결과 테스트 **둘 다** 오류 0(plan:101). 스펙은 Google 쪽을 사용자 몫으로 넘김(spec.md:45, open-questions.yml:Q2).
- 수정안: SR-5.4 에 「Google 결과를 받기 전에는 S3-7 을 '구현 완료·검증 대기'로 둔다」를 적어 완료 판정 시점을 고정한다. creator·`sameAs` 를 뺀 것(spec.md:52)도 계획 S3-7 범위에서 줄어든 항목으로 같은 자리에 적는다.

## 요약
흐름과 테스트 매핑은 촘촘하다. 고쳐야 할 것은 셋이다. 출처 폴백이 입력 문서(S1-11)와 반대이고, 실제 원문(전화·휴무)의 예외 표본이 규칙에 반영되지 않았고, 재측정 기대값이 없다. 모두 스펙 문구로 고칠 수 있어 사람 판단이 필요한 차단 사항은 아니다.

VERDICT: REVISE
