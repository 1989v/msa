## Findings (새로 발견한 것만)

### U3-1 [보통] 행사 분류에서 분류를 풀면 숨어 있던 속성 조건이 질의에 다시 붙는다. 「모두 해제」 뒤에도 조건이 남는다 (체크 2·3·6)
- 스펙: 속성 버튼은 「행사 분류가 아닐 때만」 낸다(spec.md:43). 「모두 해제」는 「순수 함수가 낸 조건 각각」을 푼다(spec.md:47). 분류 해제의 `changed` 는 `['category','page']` 다(spec.md:49).
- 코드:
  - 행사 분류에서는 속성을 질의에서 빼지만 상태는 남긴다. 주석이 「고른 칩은 남겨 두어 행사 칩을 풀면 다시 걸린다」고 적는다(`PlacePage.tsx:351-353`).
  - 행사 상태도 상태에 남는다. 분류 칩 핸들러는 `setListEventStatus(null)` 을 부르고 `changed` 에 `listEventStatus` 를 적는다(`:1223-1225`). 스펙의 분류 해제는 이 둘을 따르지 않는다.
- 결과: 「행사 + 속성 칩 1개(숨김) + 검색어」로 0건이면 버튼은 검색어·분류 둘과 「모두 해제」다.
  - 「모두 해제」를 누르면 분류가 풀리면서 속성이 질의에 다시 붙는다. 화면에 버튼으로 보이지 않던 조건이 해제 뒤에 걸리고, `changed` 에는 `attributes` 가 없다.
  - 「조건을 조용히 바꾸지 않는다」는 Goal(spec.md:9)과 어긋난다. 해제 뒤 다시 0건이 되기 쉬운 경로다.
- 수정안(SR-5.1 에 한 문장 + SR-7.1 에 한 케이스):
  - 분류 해제는 분류 칩과 같은 규칙을 쓴다. `setListEventStatus(null)` 도 부르고 `changed` 는 `['category','listEventStatus','page']` 로 한다(`:1208,1223` 과 같은 어휘).
  - 행사 분류에서 분류를 풀 때 남아 있던 속성이 다시 걸리는 것은 칩 동작과 같다고 명시한다. 다만 「모두 해제」는 `attributes` 도 비우고 `changed` 에 `attributes` 를 넣는다. 아니면 「모두 해제」 뒤 질의에 속성이 남는 것을 의도로 적는다. 둘 중 하나로 정하면 된다.
  - 테스트: 「행사 + 숨은 속성 + 검색어」 0건에서 「모두 해제」 → 다음 질의에 속성 파라미터가 없다(또는 정한 동작).

### U3-2 [경미] 자동 시도 선택이 아직 돌지 않았으면 해제 직후 `initial` 로 시도를 다시 고른다 (체크 2·5)
- 스펙: 「해제 결과로 `pickingRegion` 이 참이 되면 지역 고르기 화면으로 바뀌는 것이 정상 동작」(spec.md:47). 계측은 `relax`(spec.md:49).
- 코드: 자동 시도 선택 effect 는 `autoPickedRef` 가 거짓이고 시도·검색어·반경이 모두 없으면 돈다(`PlacePage.tsx:582-602`). 돌면 `selectRegion(target,'initial')` 이 `triggerRef` 를 `initial` 로 덮고 시도를 다시 고른다(`:556-558`).
  - 이 effect 는 시도 자료가 오기 전에 검색어나 내 주변(`geo`)이 먼저 걸리면 건너뛰고, `autoPickedRef` 는 거짓으로 남는다(`:584`).
  - 그 뒤 해제로 검색어·반경·시도가 모두 비면 effect 가 그제야 돈다. 사용자가 푼 시도가 다시 잡히고, 위치 권한이 없으면 동기 경로(`:593-595`)라 `relax` 가 SEARCH 전에 `initial` 로 덮인다.
- 수정안: 해제 핸들러(와 「모두 해제」)에서 `autoPickedRef.current = true` 로 둔다고 한 줄 적는다. 사용자가 조건을 직접 만진 뒤에는 자동 선택이 끼어들지 않는다는 `:579` 주석의 취지와 같다. 테스트는 「시도 자료 지연 + 검색어만 있는 0건 → 검색어 해제 → 지역 고르기 화면, trigger `relax`」 한 케이스다.
