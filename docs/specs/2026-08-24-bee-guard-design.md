# 그어서 막기 — 설계

> 선을 그어 아이를 지키는 물리 퍼즐. **막을 것을 셋 중에 고른다** — 물 · 돌 · 벌.
> 폴더 이름은 `bee-guard` 그대로 두었다(주소가 이미 나가 있다). 화면에 보이는 이름만 바뀌었다.

---

## 1. 왜 고쳤나 — 진단

고치기 전의 이 게임은 **벌이 전부 같은 입자**였다. 코드에 있던 것은 `b.x += b.vx*DT` 하나뿐이고,
그린 선에 닿으면 전부 똑같이 튕겼다. 판 이름은 열 개였지만 그중 `좁은 틈` · `기둥 사이` ·
`네 방향`은 **맵을 바꾼 것**이지 위협을 바꾼 것이 아니었다. 위협 자체가 달랐던 것은
`따라온다`(homing)와 `무거운 벌`(질량) 둘뿐이다.

그래서 **테마만 갈아 끼우면 똑같이 지루하다.** 고쳐야 할 것은 껍데기가 아니라
**위협마다 다른 대응을 요구하게 만드는 것**이었다.

## 2. 성질 축 — 리스킨이 아니라는 것의 실체

이름만 다른 물체를 세 벌 만드는 것은 실패다. 그래서 **선에 닿았을 때 벌어지는 일**을
종마다 다르게 두고, 그 처리를 `world.js` 의 충돌 분기에 실제로 구현했다.

| 성질 | 코드에서 하는 일 | 이 성질을 가진 종 |
|---|---|---|
| **흐름** `settle` | 기울기 \|sin\|<0.5 인 얕은 선 위에 **고인다**. 고인 양이 그 선의 체력을 깎는다 | 물방울 · 물줄기 · 폭포 · 모래 |
| **쏟기** `pour` | 고인 것이 낮은 쪽으로 흘러 획 끝에서 **다시 떨어진다** | 모래 (물은 `wet` 로 선을 적셔 무너뜨린다) |
| **무게** `dmg`·`unsupported` | 부딪힌 충격 × 질량만큼 선이 상한다. **양 끝이 안 받쳐진 선은 2.4~3배** | 폭포 · 벽돌 · 여왕벌 |
| **부착** `stick` | 선에 **달라붙어 물길을 막는다.** 막힌 자리 앞에 고임이 생긴다 | 진흙 |
| **관통** `pierce`·`cut` | 튕기지 않고 선을 **잘라 구멍을 낸다.** 한 겹으로는 못 막는다 | 철근 · 말벌 |
| **분열** `split` | 세게 막히면(법선 속도 > 200) **둘로 갈라진다.** 막는 것만으로는 안 준다 | 벌떼 |
| **깨짐** `shatter` | 세게 부딪히면 깨져 **파편이 튄다** | 유리 |
| **밀기** `push`·`contactDps` | 튕기지 않고 밀고 들어오며 닿은 선을 계속 깎는다 | 여왕벌 |
| **반사** `rest`·`fric` | 반발계수와 접선 마찰. 물은 0.02~0.06 이라 **선을 타고 흐르고**, 벌은 0.34~0.56 이라 튕긴다 | 전 종 |

**핵심 불변식**: 같은 판을 유형만 바꿔 재탕하지 않는다. 유형마다 그 성질에 맞는 판을 따로 짰다.

### 대응이 다르면 **모양**도 달라야 한다

벌 네 종은 처음에 **색만 달랐다**(#D9752B / #E8A63A / #F2C14E — 사실상 같은 노랑 셋).
그러면 뚫는 놈과 갈라지는 놈이 같은 그림이 되고, **정답을 고를 수가 없다.**
그래서 실루엣을 갈랐다:

| 종 | 모양 | 이 모양이 말하는 것 |
|---|---|---|
| 말벌 | 몸이 가늘고 길다 + **앞에 창** · 짙은 주황 | 한 겹은 뚫린다 → 두 겹 |
| 벌떼 | **뒤에 두 마리가 붙어 다닌다** | 막으면 갈라진다 → 내보내라 |
| 정찰벌 | **뒤로 속도선** · 밝은 노랑 | 빠르다 → 틈을 남기지 마라 |
| 여왕벌 | **왕관** · 크다 | 안 튕긴다 → 흘려보내라 |

벌떼의 동료는 **뒤쪽에만** 그린다. 앞·옆으로 키우면 실제 판정보다 커 보여서
"닿을 것 같은데 안 맞는다" 가 된다.

## 3. 그린 선이 부서진다 — 이번 개편의 뼈대

전에는 그린 선이 **불멸의 벽**이었다. 그래서 "무게" 도 "관통" 도 표현할 데가 없었다.
지금은 획마다 체력이 있고, 그 크기를 **받침**이 정한다 (`js/ink.js`).

```
maxHp = 100 × 받침배율 × 길이배율
  받침배율  양 끝 다 붙음 1.7 / 한쪽 1.0 / 허공 0.55
  길이배율  clamp(300 / max(60, 길이), 0.55, 1.3)     ← 긴 다리는 가운데가 먼저 꺾인다
```

받침으로 치는 것: 판의 벽 · 바닥 · **다른 획** · 화면 가장자리 (반경 40px).
이 규칙 하나가 "지지대 없으면 부러진다" 를 말이 아니라 물리로 만든다.

- 부서지면 **고인 것과 붙은 진흙이 한꺼번에 쏟아진다** (`World.snap`)
- 관통은 획을 **두 조각으로 자른다.** 잉크는 돌려주지 않는다 — 뚫린 것이 손해여야 뚫리는 게 무섭다
- 다만 **고쳐 그리기로 돌아오면 부서진 획의 잉크는 돌려준다** (`Pad.recount`).
  없는 선의 값을 계속 물게 두면 다시 그릴 수가 없다

## 4. 두 가지 모드 — 랭킹 축을 새로 만든 이유

이 게임에는 **원래 점수 축이 없었다.** 정해진 판을 푸는 퍼즐에 점수를 붙이면
**"어떻게 막을까" 가 "잉크를 몇 픽셀 아낄까" 로 바뀐다.** 그래서 축을 나눴다.

| | 판 모드 | 끝없이 모드 |
|---|---|---|
| 내용 | 정해진 판을 푼다 | 위협이 계속 몰려온다 |
| 시간 | **그리는 동안 멈춘다** → ▶ 시작 | **안 멈춘다.** 그리면서 막는다 |
| 잉크 | 판마다 정해진 양, 회복 없음 | 초당 96~100 **회복** |
| 목숨 | 한 번 닿으면 실패 | 3 (닿으면 1.3초 무적 + 주변 정리) |
| 랭킹 | **없다.** 진행도만 저장 | **여기서만.** 유형별 보드 3개 |

**잉크를 회복시키는 것이 "아끼기 대회" 를 막는 장치다.** 아껴 봐야 시간이 돌려주므로
아끼는 것에 이득이 없고, 대신 **어디에 긋느냐**만 남는다.

> **일부러 어긴 규약 하나** — 이 장르의 규약은 "그리는 중에는 시간이 멈춘다" 이고,
> 근거는 *그리면서 동시에 피하게 만들면 손이 하나뿐인 사람에게 불가능해진다* 이다.
> **이 게임에는 피할 캐릭터가 없다.** 아이는 제자리에 있고 손이 하는 일은 그리기 하나뿐이라
> 그 근거가 성립하지 않는다. 그래서 **끝없이 모드에서만** 시간을 흐르게 두었다 —
> 시간이 멈추면 "계속 몰려온다" 가 성립하지 않기 때문이다.
> **판 모드는 규약대로 멈춘다.** 퍼즐을 푸는 쪽은 규약을 지키고, 겨루는 쪽만 열었다.

### 점수

```
점수 = floor(버틴 시간 × 10) + 막아낸 수 × 8 + 단계 보너스(40 × 단계, 단계 완료 시)
```

**오래 잘 막을수록 높다.** 막아낸 수는 화면 밖으로 내보냈거나 꿀로 보낸 것이다 —
가만히 버티는 것보다 적극적으로 흘려보내는 쪽이 점수가 높게 잡혀 있다.

### 진행자 (`js/endless.js`)

- 단계마다 **종이 하나씩 는다** (`1 + floor((단계-1)/1.34)`). 같은 그림으로는 오래 못 버틴다
- 웨이브 대본은 **유형별 고정 시드**에서 나온다. 랭킹이 있는 모드에서 운으로 순위가 갈리면 안 된다
- 첫 단계까지 4.0초, 단계 사이 3.2초. **화면을 읽을 시간만 준다** (몸풀기 판은 두지 않는다)

## 5. 랭킹 배선

런이 끝날 때 **딱 한 번** 호출한다. 어댑터가 없어도(단독 실행) 게임은 그대로 돌아간다.

```js
window.PlatformAdapter?.runEnd({
  score: 1009,
  board: 'leak' | 'rockfall' | 'bee',        // 유형별 순위표를 가르는 값 — 바꾸지 않는다
  detail: '46초 · 막음 38 · 최고 물살 4단'    // 사람이 읽는 한 줄
});
```

- 호출 지점은 `main.js` 의 `reportRun()` **하나**뿐이고 `runEnded` 플래그가 런당 1회를 보장한다
- 부르는 경우: ① 끝없이 모드에서 목숨이 다했을 때 ② 살아 있는 런을 그만뒀을 때
- **판 모드는 이기든 지든 절대 부르지 않는다**
- `detail` 의 마지막 항목은 유형마다 말이 다르다 — 물살 / 낙석 / 벌떼

## 6. 판 구성

| 유형 | 판 | 내용 |
|---|---|---|
| 물 | 7 | 새는 천장 · 물줄기 · 폭포 · 진흙 · 양쪽에서 · 폭우 · 다 샌다 |
| 돌 | 6 | 모래 · 벽돌 · 유리 · 철근 · 모래와 벽돌 · 공사장 |
| 벌 | 14 | **기존 10판 그대로** + 정찰벌 · 벌떼는 갈라진다 · 말벌은 뚫는다 · 여왕벌 |

기존 10판은 검증이 끝난 자산이라 **값을 하나도 건드리지 않았다.** 벌 유형의 판 모드로 그대로 산다.

끝없이 모드의 무대는 유형마다 하나씩, 판이 아니라 **터**다 — 위협은 무대가 아니라 진행자가 보낸다.
물은 양쪽 처마, 돌은 기둥 둘(붙여 그으면 튼튼하다), 벌은 좌우 꿀단지.

## 7. 화면 흐름

```
타이틀 ──[유형 셋이 나란히]──▶ 방식 고르기 ──▶ 플레이
        물 막기 / 돌 막기 / 벌 막기      판 모드 / 끝없이 모드
```

**유형 셋은 타이틀에 나란히 둔다.** 다음 화면에 숨기면 아무도 못 찾는다.
각 카드는 그 유형에 나오는 **네 종을 전부 그림과 이름으로** 보여 준다 — 고르기 전에
무엇과 싸우는지 알아야 셋 중 하나를 고를 이유가 생긴다.

## 9. 지킨 가드레일

| 항목 | 어떻게 |
|---|---|
| **모바일** | 터치 드로잉. **가상패드를 붙이지 않는다** — 손으로 그리는 게임이라 패드가 판을 가린다. `touch-action: none`, 캔버스 fit, 가로 스크롤 0 |
| **흔들림** | 최대 9px / 1440 = **0.63%**, 0.3초 (대형 이벤트 상한 1.5%·500ms 안). 겹치면 **더하지 않고 큰 쪽으로 대체**한다. H 로 줄이거나 끌 수 있다 |
| **2D** | 캔버스 2D 벡터. 원근·입체 과장 없음 |
| **명명** | 기능 라벨은 전부 일상어 — `막기` `되돌리기` `전부 지우기` `끝없이 모드` `막음` `단`. 한자어 직역·문어체 없음 |
| **첫 판부터** | 몸풀기 판 없음. 1판부터 모범 답안이 필요하다. 끝없이는 준비 4초뿐 |
| **결정적 실행** | 물리는 고정 1/240초 스텝. 무작위는 시드 하나에서만 — `Math.random` 은 시뮬레이션에 안 쓴다 |
| **외부 요청** | 0. 순수 정적, 빌드 스텝 없음 |

## 10. 검증

`dev.*` 훅으로 화면 없이 돌린다. **손으로 확인하면 판이 늘어나는 순간 안 하게 되고,
그때 안 풀리는 판이 섞인다.**

| 검사 | 무엇을 증명하나 | 결과 |
|---|---|---|
| `dev.verify()` | 판마다 ① 모범 답안이면 **성공** ② 아무것도 안 그리면 **실패** ③ 답안이 예산 안에 든다 | **27 / 27** |
| `dev.audit()` | 모든 화면 × 계약된 모든 키가 무언가를 한다 | **200칸 / 죽은 키 0** |
| `dev.runEndless()` | 끝없이 모드 난이도·성능 (봇 4종 × 유형 3종) | 아래 표 |
| 완주 회귀 | 타이틀부터 세 유형 27판을 실제 rAF 루프로 통과 | 예외 0 |

### 검사가 실제로 잡은 것

| 판 | 무엇이 틀렸나 |
|---|---|
| `w5 양쪽에서` | **안 그려도 통과됐다.** 두 물줄기가 곧게 떨어져 아이를 비켜 갔다 → 아이 쪽으로 모이게 고침 |

### 끝없이 모드 난이도 실측 (300초 상한, 고정 방어선)

| 방어선 | 물 | 돌 | 벌 |
|---|---|---|---|
| 안 그림 | 11초 / 113점 | 10초 / 97점 | 13초 / 168점 |
| 평평하게 한 줄 | 29초 / 407점 | 12초 / 123점 | 23초 / 311점 |
| 비스듬히 한 줄 | 33초 / 459점 | 20초 / 311점 | 36초 / 772점 |
| 천막 | **47초 / 1009점** | **34초 / 798점** | 24초 / 383점 |

**축이 의도대로 움직인다** — 잘 막을수록 오래 살고 점수가 높다. 물·돌은 비스듬히·천막이
평평한 것보다 확실히 낫고(흐름·무게), 벌은 천막이 오히려 나쁘다(막으면 갈라진다).
**유형마다 정답이 다르다**는 것이 수치로 나온다.

> 위 봇은 **한 번 그리고 가만히 있는** 봇이다. 사람은 잉크가 회복되는 동안 계속 고쳐 그으므로
> 실제 기록은 이보다 길다. 이 표는 난이도의 **하한**으로 읽어라.
