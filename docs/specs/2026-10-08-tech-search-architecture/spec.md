# Specification: `/tech/search` 검색 아키텍처·시퀀스 현황 페이지

> 2026-10-08. 1라운드 리뷰(6차원 전부 REVISE) → 심판 keep 41 / demote 3 → 개정. ADR 판단: 새 모듈·외부 의존·스키마·인증 변경 없음(fencesvg·marked 는 기존 의존성) → ADR 불요.
> 사용자 결정: ① 새 경로 `/tech/search` ② 레포 문서 원본, 빌드 때 렌더 ③ 관광지 검색 + 통합 검색 ④ (2026-10-08 추가) 렌더 단계를 **Dockerfile·CI 에도 넣는다** — OCI 비용 증가 없음 확인(렌더는 GitHub 러너, 운영은 정적 파일).
> 세션 결정: 원본 위치 `portal-fe/src/content/`(Q2, Docker 컨텍스트) · 생성물 미커밋(Q1).

## Goal

`https://1989v.com/tech/search` 한 페이지에서 관광지 검색과 통합 검색의 **아키텍처 다이어그램 1장 · 시퀀스 다이어그램 4장 · 지금 쓰는 기법/요소 표 1개**를 읽게 한다. 원본은 레포 안 마크다운 하나이고, 다이어그램은 빌드타임에 SVG 가 되어 페이지와 프리렌더 둘 다에 실린다. 검색 코드의 핵심 값 9개가 바뀌면 문서를 같이 고치지 않는 한 CI 가 빨개진다.

## User Stories

- 방문자로서, 이 사이트의 검색이 어떤 요소로 돌아가는지 첫 화면의 요약과 목차로 한눈에 파악하고, 그림과 표로 자세히 보고 싶다.
- 운영자로서, 검색 기법을 바꾼 뒤 이 페이지가 옛 값을 보여 주는 일을 막고 싶다. 게이트가 잡는 범위(9값)와 사람이 고쳐야 하는 범위를 페이지가 밝혀 주기를 바란다.
- 크롤러·LLM 독자로서, JS 없이도 표와 SVG 가 든 HTML 을 받고 싶다.

2. `## 1. 전체 구조` — flowchart 1장(`%% caption:` 필수): 브라우저 → Cloudflare·nginx(엣지 캐시, ADR-0105) → gateway `/api/search/**`(공개) → search:app → OpenSearch(`attractions`·`unified`·`regions`·`query_vectors`) · search-embed 사이드카 · Redis(미적중 ZSET) · place(원천, `attraction_embedding`) → search:batch(재색인·alias 교체) · 평가 CronJob `search-eval`(KST 07:30, `cronjob-eval.yaml` 값). 노드 12개 이하, LR 5단을 넘으면 TB, 간선 라벨은 `-->|라벨|` 파이프 표기만.
3. `## 2. 관광지 검색` — sequenceDiagram 3장. 레인은 프로세스·저장소만(브라우저 · gateway · search:app · OpenSearch · search-embed · Redis), 클래스는 `Note over`, `query_vectors` 는 OpenSearch 레인, `rect` 금지.
   - ① place 검색 허브(`place.1989v.com`) 검색: `Note over search:app` QueryIntent(잔여 검색어·패싯·상업 의도) → **키워드 레그**(BM25 × 관광/상업 분류 가중치 × ln1p(완결성 `popularityScore`) × clickBoost(꺼짐); 상업 의도면 키워드 레그는 BM25 그대로 — 분류 가중치·ln1p(완결성)·clickBoost 모두 없음) ∥ **벡터 레그**(knn, 가중치 없음, 필터 = 키워드 레그의 bool 그대로 — 구조 필터와 **검색어 일치**, 그리고 `embeddingModel` 스탬프. 그래서 검색어가 어느 검색 필드에도 안 걸린 문서는 벡터 레그에도 안 나온다. 검색어가 없으면 matchAll 이라 벡터 레그만 쓴다; `query_vectors` 적중, 미적중이면 search-embed → 캐시 저장) → RRF → 응답. 가중치는 융합 **전** 키워드 레그 안이다.
   - ② 자동완성·오타 교정: 접두×6 + 형태소×1 + 자모×0.3, 검색 필드에 없는 단어만 자모 편집거리 2 로 교정.
   - ③ 상세 주변: `/attractions/{id}/nearby` 한 요청에 4종(주변 명소·근처 숙소·근처 행사·주변 편의시설), 엣지 캐시.
4. `## 3. 통합 검색` — sequenceDiagram 1장: `/api/search/unified` → 대상 타입 결정: 요청 `type` 이 있으면 그 하나, 없고 타입 의도가 잡히면 그 타입 하나만, 둘 다 없으면 `SearchUnifiedService.ALL_TYPES` 7종(관광지 포함) 전부 → 관광지는 원문 검색어로 §2-① 하이브리드, 관광지 외 6종은 **잔여 검색어**로 `unified` BM25(`UnifiedSearchAdapter` 필드 8개 — title^3·title.en^3·titleEn^3·summary·summary.en·body·body.en·tags^2) + ln1p(인기도) → 묶음 순서(첫 결과 제목이 검색어를 담은 묶음 > `ALL_TYPES` 고정 순서) → type 하나가 실패해도 그 묶음만 빠진다.

### SR-2 빌드타임 렌더 `portal-fe/scripts/render-content.mjs`
1. 순수 함수 `renderContent(markdown, { idPrefix, gitSha }) → { html, headings, warnings }` 를 export 한다. mermaid 펜스를 직접 찾아 펜스 i(0부터)마다 fencesvg `renderDiagram(src, { idPrefix: `${idPrefix}d${i}` })` 를 부르고(기본값 `d1` 을 쓰면 그림마다 마커 id 가 `d1-arrow` 로 겹친다), `<figure class="fs-figure"><svg role="img" …/><figcaption>캡션</figcaption></figure>` 로 **스크립트가** 감싼 뒤 `marked.parse`(gfm). marked 18 은 heading id·`th scope`·table class 를 내지 않으므로 `marked.use({ renderer: { heading, table, tablerow, tablecell, link } })` 로 ① heading `id`(slug + idPrefix, 중복은 `-2`)와 `headings[]` 수집 ② `<table class="kh-table">` ③ `<th scope="col">` ④ §4 표 본문 행 `<tr id>` = idPrefix + 첫 셀(`항목`) 평문의 slug — 평문은 태그 제거·엔터티 해제·백틱 제외, slug 함수는 heading 과 같다 ⑤ md 안 `[…](#x)` 링크는 renderer 가 `<a href="#{idPrefix}x">` 를 직접 내고 기본 renderer(`encodeURI`)를 거치지 않는다. `#` 가 아닌 링크는 `false` 를 돌려 기본으로 넘긴다(md 작성자는 접두사 없이 slug 만 쓴다). 블로그 `renderMarkdown` 은 DOMPurify 가 DOM 을 요구해 쓰지 않는다.
2. 실행하면 `src/content/search-architecture.md` 를 읽어 `src/pages/tech/generated/search-architecture.json`(`{ html, headings, updated, sourceHash, gitSha }`)을 쓴다. `updated` 는 md 머리 갱신일, `sourceHash` 는 md 의 sha256 앞 12자리, `gitSha` 는 `process.env.GIT_SHA ?? 'dev'`. 출력에서 HTML 주석을 걷어낸다.
3. 실패 조건(종료 코드 1, 원인 메시지): ① `renderDiagram` 의 `warnings` 1건 이상 또는 `svg === null` ② `svg[role="img"]` 수 ≠ 펜스 수, 또는 `language-mermaid` 코드 블록 1건 이상 ③ `<script`·`<style`·`<use`·`<foreignObject`·`<iframe`·`<object`·`<embed`·`<base`·`<meta`·`<link`·`<form`·`srcdoc=` ④ 태그 안 이벤트 속성 `/<[^>]*[\s\/"']on[a-z]+\s*=/i`(속성 앞 공백·`/`·따옴표) ⑤ `href=`·`src=`·`xlink:href=` 값이 `#`·`/`·`https://` 로 시작하지 않음 ⑥ 출력에 `<!--` 잔존 ⑦ 금칙 패턴 `svc\.cluster\.local` · `\.ocir\.io` · IPv4 · 메일 주소 · `(api[_-]?key|secret|password|token)\s*[:=]` · `myrealtrip` ⑧ SVG 안 빈 줄 ⑨ 출력의 모든 `href="#x"` 에 대응하는 `id="x"` 가 같은 출력 안에 있다(없으면 죽은 앵커). 그리고 출력 안 `id="…"` 값에 중복이 0건이다. 이 검사는 sanitizer 가 아니라 **출력 계약 트립와이어**다 — 원본은 레포에 커밋된 md 뿐이다. 렌더 실패 = 이미지 빌드 실패 = Argo 가 직전 이미지를 유지한다.
4. 렌더 스텝을 **네 곳에 같은 순서로**, `tsc -b` 보다 앞에 둔다 — Docker·CI·커밋 훅은 `npm run build` 를 쓰지 않는다:
   - `package.json` build: `node scripts/render-content.mjs && tsc -b && vite build && node scripts/prerender-seo.mjs && node scripts/strip-html-comments.mjs`; dev: `node scripts/render-content.mjs && vite`.
   - `portal-fe/Dockerfile:41`: `RUN node scripts/render-content.mjs && npx tsc -b --force && …` — `ARG GIT_SHA` 선언을 이 줄 앞으로 올린다(선언 이후 줄에만 보인다).
   - `.github/workflows/ci.yml` frontend-gate: Type check 앞에 `Render content` 스텝(`working-directory: portal-fe`, `run: node scripts/render-content.mjs`).
   - `.claude/hooks/hns/compile-changed.sh:26`: `[ $fe -eq 1 ] && { (cd portal-fe && node scripts/render-content.mjs && npx tsc -b) || rc=$?; }` — 생성물이 gitignore 라 새 체크아웃에서 이 훅이 TS2307 로 무관한 portal-fe 커밋까지 거부하기 때문이다. 함께 `docs/standards/agent-behavior.md:31` 「FE 타입체크는 `npx tsc -b`」 문단 끝에 「생성물(`src/pages/tech/generated/`)은 커밋하지 않으므로 새 체크아웃에서는 `npx tsc -b`·vitest 전에 `node scripts/render-content.mjs` 를 먼저 돌린다.」 한 문장, 하네스 변경이라 `docs/changelog/harness-changelog.md` 에 한 줄.
   생성물은 `portal-fe/.gitignore` 에 `/src/pages/tech/generated/search-architecture.json` 한 줄(이 파일 기준 경로) — 아틀라스(`src/pages/atlas/generated/`)와 같은 배치 원칙으로 페이지 옆.
5. 작업 트리·CI 모두 `npm ci` 로 fencesvg 0.11.2(Q3). 표기는 파이프 라벨로 제한.
