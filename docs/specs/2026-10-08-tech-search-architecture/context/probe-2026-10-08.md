# 실측 탐침 (2026-10-08, 메인 세션, 워크트리 portal-fe — 스크래치 스크립트는 지움)

- 워크트리 `portal-fe/node_modules` 를 메인 심링크에서 `npm ci` 실설치로 바꿈 → fencesvg **0.11.2**(락과 동일, CI 와 같음). vitest 기준선 재확인(tracker 14 passed).
- fencesvg 는 Node(ESM, DOM 없음)에서 돈다. `inlineDiagrams(md)` 출력은 `<div style="overflow-x:auto"><svg …role="img" aria-label="캡션" style="min-width:…;max-width:100%;height:auto">…</svg></div>` 뒤에 **문단 「그림: 캡션」** — `<figure>`/`<figcaption>`/`.fs-figure` 래퍼는 없다(0.10.1 도 같음). 블로그의 `.fs-figure` CSS 는 블로그 쪽 후처리 몫.
- `renderDiagram(src) → { svg, caption, warnings }`. `<style>`·`<use>` 없음, 인라인 `style=` 속성은 있음(nginx CSP 는 `frame-ancestors` 뿐이라 허용), SVG 안 빈 줄 없음. `%% caption:` 이 없으면 `warnings` 에 「캡션이 없다…」 1건 → 빌드 게이트로 쓸 수 있다. 0.11 의 `-- 라벨 -->` 표기도 렌더되지만 스펙은 파이프 표기로 고정(Q3).
- marked 18.0.9: heading id 를 안 붙인다(`marked-gfm-heading-id` 미설치). → `renderContent` 가 `marked.use({ renderer: { heading } })` 로 slug id 를 직접 부여(새 의존성 없음).
- 설계 함의(스펙 개정 후보): SR-2.1 은 `inlineDiagrams` 대신 펜스를 직접 찾아 `renderDiagram` 으로 그리고 `<figure class="fs-figure"><svg/><figcaption>…</figcaption></figure>` 를 **스크립트가** 감싼다 — fencesvg 판 차이와 「그림:」 문단 형식에 묶이지 않는다. SR-3.4 의 `.fs-figure` 규칙은 그 래퍼를 대상으로 한다.
