# 작은 범위 확인 원칙

사용자 명시 요청, 2026-10-03. 후속 세션에도 적용한다.

- 초반에 보이는 문제는 시작 주둔지·첫 고지·첫 웨이브 등 재현되는 최소 구간으로 한정한다.
- 이미지 시안 요청이면 시안 1장과 핵심 설명부터 제시한다. 사용자 확인 전에 게임 구현이나 전 지역 확대를 진행하지 않는다.
- 구현 승인 후에도 해당 구간만 수정하고 사용자가 플레이해 확인한 다음 확대한다. 묶음 전체 구현으로 자동 전환하지 않는다.
- 기존 분석 결과를 재사용한다. 변경할 부분의 주변 코드만 처음 한 번 확인하며 태스크마다 전체 코드를 다시 탐색하지 않는다.
- 승인받은 작은 범위 구현이 끝나면 그 범위의 검증을 한 번 수행한다. 실패한 부분만 재검증하고 전체 캠페인 봇/전체 회귀/다중 에이전트를 습관적으로 반복하지 않는다.
- 원인이나 성공이 확인되지 않으면 그대로 보고한다. 실패한 진행 봇의 전략을 계속 조정해 통과시키는 작업을 반복하지 않는다.
- 생성 시안과 실제 구현 화면을 구분한다. 변경 내용·검증 범위·미해결 항목을 간단히 보고한다.
- 주간 잔여량50% 미만 중단 조건은 사용자가 바꾸기 전까지 유지한다. 관측 가능한 실제 수치만 사용하고 추정 잔여량을 사실처럼 말하지 않는다.

## 모델 분담과 구현 인계

사용자 명시 요청, 2026-10-03.

- 기획·디자인·PRD·이미지 시안 및 주요 설계 결정은 사용자가 직접 선택한 Astra/Medium 등 상위 모델 세션에서 진행한다. 모델 간 품질을 보장한다는 뜻이 아니라 사용자가 지정한 역할 분담이다.
- 확정된 범위의 실제 구현·버그 수정·해당 범위 검증은 Codex 서브에이전트 `gpt-6.1-sol`로 진행한다. `spawn_agent`에서 model을 명시하고 모델 지정 가능한 `fork_turns="none"` 또는 필요한 최근 턴 수를 사용한다. reasoning_effort는 별도 지정이 없으면 임의로 높이지 않는다.
- 기존 에이전트가 지정 모델인지 확인되지 않으면 구현 담당으로 재사용하지 않는다. 지정 모델이 제공되지 않으면 다른 모델로 몰래 대체하지 말고 알린다. 부모 세션 모델 변경은 사용자가 수행하며 자동 전환했다고 보고하지 않는다.
- 기본 구현 담당은 한 명이다. 단순 작업을 여러 에이전트로 쪼개거나 상위 모델이 동일 코드를 다시 분석·구현·테스트하지 않는다.
- 인계에는 승인 명세/시안 경로, 대상 파일·책임 범위, 완료 조건, 알려진 문제, 변경 금지 사항, 마지막에 실행할 국소 검증을 짧게 명시한다. 다른 작업자의 변경을 보존하도록 지시한다.
- 상위 모델은 결과·실패·범위 이탈을 확인하고 사용자에게 보고한다. 명세가 모호하거나 새로운 설계 결정이 필요하면 해당 부분을 먼저 알리고, 승인 범위 안에서 독립적으로 가능한 작업만 계속한다.
- 구현 모델도 주변 코드 확인, 실제 검증 근거, 사용자 확인 후 확대 원칙을 동일하게 지킨다. 모델 분리는 검증 생략이나 전체 재검증 반복의 이유가 아니다.

## 이번 확인 범위

언덕 위 표현과 적 주둔지 형태는 사용자 승인. 경사로는 시안보다 짧게 하되 폭과 지면 연결을 유지한다(약 1/3 단축은 제안한 구현 기준). 넓은 경사로가 저지대와 고지 윗면에 끊김 없이 연결되고, 높은 윗면/절벽 단면/유닛 접지 그림자가 같은 높이 기준을 사용해야 한다. 적 주둔지는 시안의 검은 석재·뼈 가시·붉은 천·화로 형태를 실제 고지 공격 탑과 소굴에 적용한다. 프랙탈 지형 생성은 보류하고 필요하면 추후 바위·질감 장식에만 제한한다. 현재 변경은 작업 원칙 문서화이며 게임 구현 완료를 의미하지 않는다.

시안 확인 후 조사할 초반 결함(원인 미확인):
1. 주둔지 근처 적 생성: 웨이브 집결지뿐 아니라 초기 사냥 무리·필드 보충·거점 생성 경로 각각의 실제 생성 좌표와 최소 거리를 확인한다.
2. 고지 너머 이동 직후 HP 감소 표시 없이 게임오버: 패배 사유(본진/병력·경제), 실제 HP 변화와 HUD 갱신을 같은 시점에 기록해 원인을 분리한다. 원인을 정하기 전에 난이도나 승패 규칙을 변경하지 않는다.
