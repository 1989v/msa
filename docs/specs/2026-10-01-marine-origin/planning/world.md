# World, elevation, fog

## 구현 기준과 원본 보존

사용자가 지정한 SE 지도를 확인한 뒤 지형을 구현했다. [원본 파일 조사와 추출 정정](original-map-findings.md)이 근거이며, 이전의 보류된 재구성 좌표·연결도는 이 문서로 대체한다.

원본은 96×96 megatile, 3,072×3,072 좌표다. 공식 무료 StarEdit 지형 메타데이터로 minitile 통행·고도·시야 차단·경사로를 해석하고, 원본8px minitile을 새 게임32unit 셀로 균일4배 확대했다. **세계는12,288×12,288, tile32, grid384×384**다. 좌표 원점은 좌상단, +x동/+y남이다. 원본 지형의 막힌 곳에 임의 다리나 통로를 추가하지 않았다. 원본 그래픽·사운드는 배포하지 않는다.

확대는 지형 좌표와 거리의 확대이며 작은 캐릭터의 화면 크기는 유지한다. 미니맵은 전체 영역을, 메인 뷰는 현재 지역을 보여 준다. 초기 카메라는 실제 전장 병력 생성 구역을 근거로 한 B 주둔지를 따른다. 원본의 떨어진 선택·생산 구역은 지형에 남지만 메뉴 기능은 새 UI가 담당한다.

`js/origin/map.js`의 `MAP_VERSION='origin-se-topology-1'`은 지형 버전이다. 저장 파일의 content/schema version1과는 별도 개념이다. `createWorld()`는 terrain, terrains, sites, regions, resourceNodes, base, links, openGate, restore를 제공한다.

아래 월드 좌표는 원본 좌표의 정확한4배다. 런타임 site는 해당 지점에서 가까운 통행 셀 중심으로 보정하며 `site.source`에 원본 좌표를 보관한다. 지도상의 고도와 경사로는 수기 배치가 아니라 파생 지형 배열이 결정한다.

### C2 본토 사격 접근

C2는 원본에서부터 북서쪽의 분리된 지형에 있다. 목표 중심으로 직접 걸어가는 경로를 만들지 않는다. `C2.approach=(784,784)`는 원본 `(196,196)`에 해당하는 본토 사격점이며, 본진에서 이 지점까지 보행할 수 있다. 접근점 고도1에서 목표 고도0으로 시야가 통하고, 실제 보정된 목표 중심까지 거리는 약500unit이다.

장궁 사거리 **560**으로 본토에서 목표를 공격한다. 이동 안내는 접근점을 사용하고 목표 건물의 위치는 원본 섬에 유지한다. 일반 보행 도착 여부로 이 목표의 접근 가능성을 판정하지 않는다.

### 원본 북부 왕복 전이

Z가 있는 북동 구역도 본토와 분리되어 있다. 원본 TRIG36/37의 MoveUnit 동작을 `world.links`로 표현한다. 모든 목표까지 연속 보행로가 있다고 가정하지 않는다.

| 링크 | 원본 출발→도착 | 월드 기준 출발→도착 | 조건 |
|---|---|---|---|
| north-gate | loc34 `(2960,1056)` → loc37 `(2864,832)` | `(11840,4224)` → `(11456,3328)` | 목표5개 파괴 |
| north-return | loc35 `(3024,880)` → loc38 `(2816,1232)` | `(12096,3520)` → `(11264,4928)` | 추가 목표 조건 없음 |

링크의 from/to 역시 가까운 통행 셀 중심으로 보정한다. 본토에서 north-gate 출발점, 도착점에서 Z와 north-return 출발점, 복귀 도착점에서 본진으로 가는 각 보행 구간을 확인했다. 던전2개 완료 조건은 최종보스 진행을 위한 새 게임 규칙이며 원본 북부 전이의 조건과 구분한다.

## 지형·시야·이동

- 지형은 blocked, elevation, visionBlock, ramps, buildProtected를 typed array로 가진다. surface는 렌더링 보조값이다.
- 원본 필드의 실제 고도는0/1이다. 범용 지형 함수는0/1/2를 지원하지만 원본에 없는 고도2 언덕을 추가하지 않는다.
- 보행은 상하좌우 셀 인접성으로 판정한다. 같은 고도는 통행 셀끼리 이동하고, 한 단계 높이 차이는 양쪽 셀이 같은 양수 ramp ID를 가질 때만 이동한다. 원본의 통행 가능한 고도 경계85쌍은 모두 경사로 플래그와 연결된다.
- 시야는 supercover 격자 raycast로 높은 지형과 visionBlock을 판정한다. 고지→저지 관측은 가능하지만 중간 차폐는 유지된다. 고도에 숨은 명중률 페널티를 붙이지 않는다.
- 현재 시야와 탐색 기억은 별도 bitset이다. coop은 팀 시야를 공유한다. 기억에는 지형과 정적 시설을 남기되, 가려진 적·현재 적HP·효과를 계속 표시하지 않는다.
- 이동은 예산이 있는 A*를 사용하고 초과 작업은 이어서 처리한다. 경로가 없는 목적지에 임의 직선 이동을 허용하지 않는다. 지역 간 전이는 별도 링크 또는 던전 진입으로 처리한다.
- 렌더링 고도 표현과 sprite pivot은 지면 이동 좌표를 바꾸지 않는다.
- 사이트·자원·전이 입출구 주변은 건설 보호를 적용한다. 건설은 지형, 경사로, 경계, 기존 건물과의 간격을 함께 판정한다.

## 새 경제 배치

주둔지 근처 숲2개와 광석2개는 사용자 요구에 따른 새 배치다. 원본 자원 위치를 재현했다고 주장하지 않는다. 각 위치는 원본 통행 지형 위에 놓이며 본진에서의 접근을 확인했다.

| 자원 ID | 종류 | 원본 좌표계로 표현한 배치점 | 월드 기준 중심 |
|---|---|---|---|
| wood-west | 나무 | 480,2016 | 1920,8064 |
| wood-east | 나무 | 688,2144 | 2752,8576 |
| ore-west | 광석 | 432,2096 | 1728,8384 |
| ore-east | 광석 | 752,2112 | 3008,8448 |

초기 목수는 없으며 적 처치 금화로 고용한다. 채집·금화·주둔지 방어 규칙은 gameplay.md를 따른다. 원본에 환전 안내가 있었다는 이유로 수동 환전 동선을 복원하지 않는다.

## 던전: 명시적인 판타지 각색

원본에 아래와 같은 별도 던전 인스턴스가 존재했다고 주장하지 않는다. 입구는 원본 이벤트 구역 loc27과 loc38을 위치 근거로 삼고, 내부·방 구성·보스·해금 조건은 새 판타지 게임을 위해 설계했다. 원본 북부 최종 적12기 집단을 단일 최종보스와 소환병으로 바꾼 것도 각색이다. 확보한 SE 파일과 사용자 영상 판본의 동일성은 아직 확인되지 않았다.

각 내부는 **1536×1536**, tile32다. `regions.dungeon0/1`과 `terrains.dungeon0/1`이 독립 지형을 제공한다.

| 항목 | 실제 내부 좌표·동작 |
|---|---|
| 입장 문턱 | `(768,160)` |
| 방 중심 | `(768,352)`, `(768,800)`, `(768,1280)` |
| 첫 번째 구획 벽 | y544, 두께32; x640 이상896 미만이 개방 가능한 문 |
| 두 번째 구획 벽 | y1024, 두께32; x640 이상896 미만이 개방 가능한 문 |
| 문 개방 | D1/D2의 room0 완료가 첫 문, room1 완료가 둘째 문을 개방 |
| 건설 | 내부 전역 건설 보호 |

문은 닫혀 있을 때 실제 이동·시야를 막고, 개방 때 해당 셀의 차단을 해제하며 terrain.revision을 갱신한다. 반복 openGate 호출은 멱등이다. 입구 근처 선택 원정대만 이동하고 목수·주둔 병력은 현장에 남는다. 필드 웨이브는 계속 진행한다.

### 공유 진행과 복구

캠페인당 dungeonId별 인스턴스는1개이며 coop 소유자가 공유한다. 방 진입은 encounter의 필수 스폰을 한 번 예약하고, pending·queued·alive가 모두 없어야 완료한다. 방 구성과 전투 수치는 캠페인 구현 및 gameplay.md를 따른다.

| 사건 | 상태 처리 |
|---|---|
| 첫 입장 | 첫 방 encounter와 필수 스폰 예약 |
| 동료 합류 | 기존 인스턴스 진행·적HP·보상 상태 유지 |
| 한 소유자 퇴각 | 해당 원정대만 필드 입구로 복귀 |
| 전원 이탈 | 던전 상태 보존, 휴면 처리; 필드 웨이브는 계속 |
| 재입장 | 완료된 방과 남은 적·예약·보상 상태를 이어서 진행 |
| 보스 처치 | 공유 완료 기록, 재입장으로 보상 복제 금지 |
| 저장 복구 | 새 월드 생성 후 `world.restore(state)`로 완료 거점·던전·방 문 복원 |

restore는 반복 호출해도 이미 열린 문을 다시 갱신하지 않는다. 저장 파일의 지형 배열을 복사하는 대신 현재 지형 버전에 저장된 진행도를 재적용한다.

## 확인 범위

최종 통합 중 발견한 C2/Z 경로 실패를 원본 분리 지형과 전이 근거로 해결했다. 지도 전용 테스트5개가 통과했으며 치수·목표 원본 좌표, 보행 접근과 북부 왕복 연결, C2 사격 시야, 채집 접근, 던전 문과 복원 멱등을 확인했다. 이 결과가 원본 영상 판본의 동일성이나 브라우저 시각 검증을 의미하지는 않는다.
