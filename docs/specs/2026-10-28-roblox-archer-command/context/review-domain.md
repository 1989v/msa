## Findings (심각도 순)

### 1. [HIGH] C1 주둔 병력은 2마리가 아니라 25마리, 거점 자체도 사격한다
- 스펙: `requirements.md:28` "주둔 2마리(zombie) + 20초마다 보충".
- 코드: `campaign.js:13-17` `campComposition(0)` = `CAMP_COMPOSITIONS[0]`(길이 2) × 12.5 = **25마리**(zombie 15 · plague 5 · bat 5). 초기 주둔 `campaign.js:126`, 보충 상한도 25(`campaign.js:183-184`). 배치는 거점 둘레 ring 2~24셀, 본진 800px 안 제외(`campaign.js:22-25`).
- 추가 누락: 거점(camp)은 가시 첨탑과 같은 spike 예고 사격을 한다 — 사거리 340·피해 12·1.6초(`sim.js:623-626`). 표에는 HP·보상·역습만 있다.
- 영향: "북쪽 고지 공략" 난이도가 통째로 달라진다. `spec.md:29` 의 "거점 25" 는 이 값을 알고 있으므로 표만 틀렸다.
- 수정: 표를 "주둔 25(zombie15·plague5·bat5), 20초마다 25까지 보충, 거점 spike 사격 340/12/1.6s" 로.

### 2. [HIGH] 사냥터 좀비는 F(992,11808)가 아니라 (1376,11200)에 생성되고, 문 위치가 이를 막을 수 있다
- 스펙: `requirements.md:27` "사냥터 F (992,11808) 좀비 3마리", `requirements.md:38` "x1280~1472 가 **y11328** 에서 북쪽으로 … 문으로 막고".
- 코드: `campaign.js:57` startHill 일 때 `scoutEntry = hunt.find(dist>1000) || world.waveEntry`. 본진(320,11968)→F 거리 ≈691 이라 경로 위 어느 점도 1000 을 못 넘어 **waveEntry(1376,11200)** 로 떨어진다(`map.js:132`). `campaign.js:128, 158` 이 그 점을 사냥터로 쓴다. 설령 F 를 쓰더라도 `campaign.js:223` 이 본진 900px 안 비사이트 생성을 waveEntry 로 옮긴다.
- 지형: `map.js:77` 분지 내부는 y 10688 까지, `map.js:80` 동쪽 통로 rect 는 y 9408~11328 — 즉 분지 북벽(y 10624~10688)이 x1280~1472 에서 뚫린 것이고 "y11328" 은 통로 rect 의 남단일 뿐 출구가 아니다. 문을 y11328 에 두면 (1376,11200) 과 spawnPoint ring(±8셀, `campaign.js:96`) 전체가 문 뒤에 갇혀 사냥감·전초 소멸 후 웨이브가 본진에 닿지 못한다.
- 수정: 표 "사냥터 = (1376,11200), 리시 300(`sim.js:664`)" 로 정정. SR-1 문은 **y ≤ 10688(북벽 선)** 로 명시하고, 검증(SR-5)에 "(1376,11200)→본진 격자 경로 존재" 를 넣는다.

### 3. [HIGH] 거점을 C1 하나만 옮기면 C1 파괴 직후 웨이브 구성이 6종(철갑·흡혈귀)으로 뛴다
- 스펙: `spec.md:63` C2~C5 범위 밖, `spec.md:29` "웨이브 구성 규칙" 보존.
- 코드: `campaign.js:145-147` `cleared >= s.camps.length || time>=480` → 6종, `cleared>=3 || time>=180` → 5종. 원작은 camps 5개라 C1 하나로는 4종→(180초)5종. 거점 배열이 [C1] 이면 `1 >= 1` 이 되어 **C1 파괴 즉시 armored 15%·vampire 5% 가 정상 HP 로 섞인다**.
- 수정: Luau 에서 비교 기준을 원작 거점 총수 5 로 고정(상수)하거나, 분지 범위에서는 시간 조건만 쓰도록 스펙에 명시.

### 4. [MED] 웨이브 출발지 전환 조건이 "둘 다 살아 있으면" 이 아니라 "하나라도 살아 있으면"
- 스펙: `requirements.md:26` "탑·파수꾼이 둘 다 살아 있으면 전초기지 쪽".
- 코드: `campaign.js:72-74` `openingWaveActive` = 미생성 **또는** outpost 적 하나라도 생존 **또는** 대기열에 outpost 요청. 탑만 남아도 (960,11808) 에서 온다.
- 수정: "둘 중 하나라도 살아 있으면 (960,11808), 둘 다 죽으면 (1376,11200)".

### 5. [MED] 웨이브 간격 규칙 두 가지가 빠져 실제 리듬이 표와 다르다
- 스펙: `requirements.md:25` "180초 전 15초 간격", `spec.md:49` 테스트 "웨이브 타이머".
- 코드: ① `campaign.js:189` 웨이브 요청이 대기열에 남아 있으면 다음 웨이브를 만들지 않는다. ② `campaign.js:238` 요청이 **다 방출된 시점에 타이머를 다시** `time+15/35` 로 놓는다. 80마리 행렬 방출이 약 25초 걸리므로 2차 웨이브는 23초가 아니라 ≈48초에 시작한다.
- 이식 영향: `spec.md:29` 의 상한 150(원작 1000, `enemy-limits.js:2`)은 `campaign.js:222` 에서 방출을 **멈추게** 하므로 생존 적이 150 에 닿으면 웨이브가 늘어지고 다음 웨이브도 그만큼 밀린다. "인원수는 원작 그대로" 는 맞지만 cadence 는 달라진다.
- 수정: 표에 ①②를 적고, SR-5 타이머 테스트는 "방출 완료 + 15초" 를 단언. 상한 150 의 영향은 진행 봇에서 웨이브 길이를 측정값으로 남긴다.

### 6. [MED] 리더=아바타 규칙이 원작에 없는 자동 지출과 이동 속도를 만든다
- 스펙: `spec.md:37` 리더 사망 시 금화 ≥700 이면 **자동 차감** 리스폰, 아니면 경제 패배 조건. WalkSpeed 13.75 고정.
- 코드: 원작에 자동 고용은 없다(`sim.js:118-133` 는 플레이어 명령). 경제 패배는 "금화<500 **이고** 유닛 0"(`sim.js:703`) 이라 목수만 남아도 계속 번다. 스펙은 「전투원 0 · 목수 생존 · 금화<700」 상태(원작에선 정상 생존)를 정의하지 않고, ≥700 일 때 "목수 먼저" 선택권을 빼앗는다. 원정대 속도는 추종자 최저 속도(`sim.js:509`, 장궁수 95) 인데 아바타는 110 고정이라 장궁수 고용 뒤 대열이 끊긴다. 새 리더 후보는 비주둔(`stationed`, `sim.js:57`)이어야 한다.
- Roblox 물리: 절벽 8스터드 vs 기본 점프 ≈7.2스터드, WedgePart 경사면은 어디서든 오를 수 있어 "ramp 플래그로만 고도를 넘는다"(`spec.md:30`)가 아바타에는 적용되지 않는다. `spec.md:26` 은 HRP 를 그대로 Sim 에 넣는다.
- 수정: 자동 차감 대신 원작처럼 고용 버튼(700/500) 노출 + 대기 상태 정의. WalkSpeed = 살아 있는 추종자 최저 속도 ÷8. Jump 비활성 + HRP 를 통행 셀로 클램프.

### 7. [MED] 솔로→협동 "전환" 은 원작에 없는 동작이라 정의가 비어 있다
- 스펙: `spec.md:35`, `requirements.md:47` "두 번째 입장 시 coop 으로 전환 … (원작과 같다)".
- 코드: 모드는 생성 시 고정(`sim.js:72-88`), 협동은 처음부터 소유자 2명·활잡이 2명·본진 6000 으로 만든다(`session.js:187`). 거점 HP ×1.5 도 초기화 때만(`campaign.js:115`). 중간 전환 시 본진 HP(+2000?), C1 maxHp, 이미 살아 있는 적, 둘째 소유자 시작 병력·금화를 어떻게 할지 규칙이 없다.
- 수정: 전환 규칙을 SR-2 에 명시(권장: 본진 max+2000·hp+2000, 둘째 소유자 활잡이 1·금화 0, 기존 적·거점은 그대로, 이후 생성분만 ×1.5/×1.4).

### 8. [LOW] 표에서 빠진 작은 규칙 묶음
- 길 위 무리: `campaign.js:51-53` 은 경로 24셀 이후 + 본진 1000px 밖 + 전체 지도 A* 로 놓는다. 분지 안 경로(F ≈22셀, C1 ≈37셀)는 조건을 못 채워 **분지 안 무리는 0** 이다. `spec.md:29, 49` 의 "길 위 무리 보충" 은 인스턴스가 없는 기능이다 — "없음" 으로 확정하고 테스트에서 뺀다.
- 목수 고용 시 자동 배치: `sim.js:126-129` 첫 빈 노드(wood-west (160,12064))로 바로 간다. 튜토리얼 3단계(`main.js:124`)는 이 덕에 보통 건너뛴다.
- 합성 조건에 "같은 assignment" 포함(`sim.js:151`), 영웅 cooldown·lastCombatTime 은 재료 최댓값 승계(`sim.js:156-157`).
- 전초 파수꾼은 흡혈 없음(`sim.js:696` `!enemy.guardStats`) — 표의 "vampire 외형" 으로 충분하나 명시 권장.
