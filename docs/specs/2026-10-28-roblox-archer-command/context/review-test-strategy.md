# Spec review — TEST-STRATEGY

대상: `spec.md` SR-5, `planning/test-quality.md`
근거 비교: `roblox/infinity-step/tests/run.luau` · `roblox/infinity-step/tools/verify.py` · `portal-fe/public/games/marine-command/tests/*`
프로젝트 규칙: 증거는 대상이 만든 것(검사 자신이 만든 근거 금지) · 게이트는 컴파일되는 회귀를 넣어 빨간불을 본 뒤에만 「켰다」 · CLI 검사를 Studio/런타임 검증이라 부르지 않는다

## 판정 요약
방향은 맞다. 실제 Luau 모듈을 공식 `luau` 로 실행하고(infinity-step `verify.py:14` 패턴), 미검증을 명시하며(`verify.py:58,61`), 주입 표를 둔 것은 프로젝트 규칙과 맞는다. 그러나 ① 진행 봇의 40~180초 창이 어디서도 유도되지 않은 값이고 ② 격자·파트 일치 검사가 진실 출처를 정하지 않아 자기 자신을 잴 수 있으며 ③ 원작 테스트가 못 박아 둔 규칙 중 이식에서 가장 깨지기 쉬운 것들이 SR-5 목록에 없다. 모두 스펙 문장 수정으로 풀린다.

## Findings

### F1. 진행 봇 40~180초 창은 자기충족이다 (REVISE)
- 근거: `spec.md:50` "40~180초 안에 … (원작 튜닝 기준 40~90초는 주장하지 않고 측정값을 기록한다)". 창의 하한·상한이 어느 측정에서도 오지 않았다. 원작 코드베이스에 "40~90" 은 없다(grep 0건). 봇과 Sim 이 둘 다 새 코드라, 창 안에 들어오는지는 구현자가 창을 어떻게 잡았는지에만 달린다.
- 원작에 이미 있는 오라클:
  - `tests/economy.test.mjs:46-53` — 좀비 50마리 실제 처치 → 정확히 500G → `hire carpenter` 성공 · 지갑 0.
  - `tests/outpost.test.mjs:28` — 활잡이가 쏘지 않는 상태에서 첫 웨이브가 본진에 실제 피해를 주는 시각 **15~30초** (`arrivals[0]>=15&&arrivals[0]<=30`).
  - `tests/campaign.test.mjs:32-37` — 사냥터 보충만으로 330초 안에 첫 목수 고용.
- 수정안:
  1. 창을 원작에서 유도한다: 같은 정책(리더 본진 고정 · 자동 사격만 · 500G 되는 즉시 명령 경로로 `hire carpenter`)을 `js/origin/sim.js`+`map.js` 로 시드 1~20 에 돌려 min/max 를 `verifications/` 에 남기고, Luau 창 = 그 범위 ±20%. 창의 출처가 「원작 측정」이 된다.
  2. `outpost.test.mjs:28` 의 15~30초 본진 도달 검사를 그대로 옮긴다 — 창이 좁고 출처가 있다.
  3. 봇은 금화 카운터를 읽는 게 아니라 `hire carpenter` 를 실제로 보내 ok 와 지갑 −500 을 단언한다(`economy.test.mjs:51`).
  4. 이 행의 주입을 표에 넣는다: 좀비 보상 10→5 (또는 첫 인원 80→40). **이 주입에도 창 안에 들면 창이 의미 없다는 증거**다 — 그때는 창을 좁힌다.

### F2. 격자·파트 일치 검사의 진실 출처가 정해져 있지 않다 (REVISE)
- 근거: `spec.md:21` "빌더는 Grid.luau 의 `RECTS` 를 정규식으로 읽는다", `spec.md:51` "격자 RECTS 와 빌더 파트 일치(셀 샘플링…)", `test-quality.md:16` "blocked 셀 중심 위 Y≥4 에 파트 존재 · 통행 셀 위에 절벽 없음 (XML 파싱)".
- 문제: verify.py 가 같은 정규식으로 RECTS 를 다시 읽어 blocked 를 계산하면, 빌더와 검사가 **같은 파생값**을 비교한다. 정규식 누락·px→스터드 변환(÷8, 원점 10624)·경사로 처리 버그는 양쪽에 같이 들어가 초록이 난다. 「검사가 스스로 만든 근거는 근거가 아니다」에 걸린다.
- 추가로 검사 정의가 고도를 모른다: 고지 윗면은 통행 셀인데 Y≈8 에 바닥 파트가 있고, 경사로 셀은 통행 셀인데 WedgePart 가 있다. 지금 문구대로면 그 셀들이 거짓 빨간불이거나, 그걸 피하려고 조건을 느슨하게 잡으면 검사가 사라진다.
- 수정안:
  1. blocked·elevation·ramp 의 진실은 **실행된 Grid.luau** 에서 온다 — `tools/dump_grid.luau` 가 실제 모듈을 require 해 셀마다 `(x,z,blocked,elev,ramp)` 를 찍고, verify.py 는 그 출력과 rbxlx 파트 기하를 비교한다. 정규식 재파싱 금지.
  2. 검사를 고도 기준으로 정의한다: 통행 셀(고도 e)은 보행 부피 `[8e+0.5, 8e+4]` 안에 Wedge 아닌 고형 파트가 없다 · blocked 셀은 인접 통행 셀의 보행 부피를 가로막는 고형 파트가 있다 · ramp 셀은 WedgePart 가 있다.
  3. 샘플링이 아니라 전수. 분지는 54×52 = 2,808 셀이라 XML 한 번 파싱으로 충분하다. 샘플링은 표본 밖을 놓치고 돌릴 때마다 다르다.
  4. 주입은 양방향: 절벽 파트 하나 삭제(blocked 인데 파트 없음) **그리고** 빌더의 절벽 X 를 한 셀 밀기(통행 셀에 파트 있음). `test-quality.md:16` 은 앞의 것만 있다.

### F3. 결정성·저장 왕복 검사가 약하다 (REVISE)
- 근거: `test-quality.md:14` "같은 시드 300틱 두 번 → 직렬화 동일", `spec.md:49` "저장 왕복".
- 문제: 한 프로세스 안에서 두 번 돌리면 같은 삽입 순서 → 같은 `pairs` 순서라, 순서 의존 루프(유닛·적 테이블 순회로 타겟 선택·보상 분배)가 있어도 통과한다. 그 코드는 스냅샷 복원 뒤(삽입 순서가 달라짐)나 서버 재시작 뒤에 갈라진다. 「저장 왕복」은 무엇을 비교하는지 적혀 있지 않다.
- 수정안: ① 두 **별도 `luau` 프로세스**에서 해시를 찍어 비교 ② 원작 패턴(`procession.test.mjs:12`, `outpost.test.mjs:16`)대로 `직렬화→복원→N틱` == `원본→N틱` 전체 상태 동일 ③ 손상 스냅샷(버전·범위·중복 id)은 nil 을 돌려주고 기본값으로 덮지 않는다 — infinity-step `run.luau:35-39,240` 패턴. SR-3:39 「불러오기 실패는 새 원정으로 덮지 않는다」가 CLI 에서 검사 가능한데 SR-5 에 없다.

### F4. 원작 테스트가 못 박은 규칙 중 SR-5 에 빠진 것 (REVISE)
이식에서 가장 깨지기 쉬운데 `spec.md:49` 목록에 없는 항목. 모두 Sim 순수 모듈이라 `luau` 로 검사 가능하다.

### 오라클 판정 — 원작 봇이 전부 죽는데 사망 시각 창이 충실도 검사로 성립하는가

**성립한다, 단 조건부.** 「모든 봇이 죽는다」는 오라클의 결함이 아니다. 사망 시각은 원작 밸런스가 내놓은 **측정 가능한 산출물**이고(웨이브 도달 → 교전 → 피해식·방어·회복의 합성값), 새 코드가 정한 값이 아니다. 이식판 봇이 더 오래 살면 쉬워진 것이고 그것이 이식 오류라는 `original-bot.md:34` 의 해석도 맞다. 위험은 「봇이 죽는다」가 아니라 아래 넷이다.

1. **재현 불가 (REVISE)**. `spec.md:63` 은 "원작 측정 **명령·출력**을 둔다" 고 했지만 `original-bot.md:3` 은 "스크립트는 스크래치패드(`orig_bot.mjs`)에 **있었고**" 이고, 시드별 값은 20 중 12 만 있다(`:19` "…"). 스크립트가 레포에 없으면 ① 원작이 바뀔 때 다시 잴 수 없고 ② Luau 봇이 같은 정책인지 대조할 원본이 없다. 수정: 스크립트를 `verifications/orig_bot.mjs` 로 커밋하고 20개 값 전부 + 실행 명령 + 측정 시점 원작 커밋 SHA 와 `MAP_VERSION`(`map.js` 'origin-se-southwest-4') 을 적는다.
2. **원작 밸런스가 잠정이다 (REVISE)**. 인용한 원작 상태가 `docs/specs/2026-10-01-marine-origin/status.md:217` 「…사용자 선호 질문; 답변 전 추가 밸런스 변경 없음」 — 즉 원작 작성자가 **답을 기다리는 값**에 창을 고정했다. 원작이 바뀌면 이 창은 조용히 거짓이 된다. 수정: verify.py 가 원작 `sim.js`·`campaign.js` 해시를 기록값과 비교해 다르면 오라클 행을 `STALE` 로 찍고 PASS 를 내지 않는다(「검사가 최신 대상을 재는지 먼저 확인」 규칙).
3. **정책이 산문으로만 있다 (REVISE)**. `original-bot.md:9` "공업/방업 낮은 쪽부터 1단씩(합 5까지)" 는 동률 처리가 없다. 원작 `outpost.test.mjs:25` 는 `armor<=attack ? 'armor' : 'attack'`(동률이면 방업 먼저). 같은 원작에서 정책이 조금 다른 `outpost.test.mjs:27` 의 opening(원 궤도·상한 없음·시드 1989)은 **40초에 아직 `playing`** 을 단언한다 — 정책 세부가 결과를 생존/사망으로 가른다는 뜻이다. Luau 봇 정책은 1 의 스크립트와 줄 단위로 같아야 하고, 동률 처리·상한·고용 시점을 `test-quality.md:23` 행에 적는다. 덤으로 `outpost.test.mjs:27` 의 40초 생존도 같은 방식(원작 먼저 측정)으로 옮기면 「너무 어려워진 이식」 쪽 경계가 생긴다 — 지금 창은 「너무 쉬워진 이식」 한쪽만 막는다.
4. **15~30초 검사의 하네스와 주입 (REVISE)**. 원작은 `units[0].assignment='garrison'; cooldown=1e9` 로 상태를 직접 고쳐 사격을 막는다(`outpost.test.mjs:28`). Luau 공개 면(`spec.md:34`)에는 그 손잡이가 없고 리더 garrison 은 `LEADER` 로 거부된다(§R:22). 어떻게 막을지 적어야 한다 — `snapshot → cooldown 수정 → restore` 가 공개 면만으로 가능하니 그 경로로. 또 `test-quality.md:23` 의 주입 「좀비 공격 11→4」는 사망 시각만 늦추고 **첫 피해 시각은 그대로**라(피해량 무관, 도달만 보면 됨) 15~30초 검사는 그 주입에 초록이다. 둘째 주입이 필요하다: 첫 웨이브 시각 8→20 또는 zombie 속도 123→60.

비차단 제안: 원작 타일 32px = 4 스터드(`map.js:12`)이고 LCG 를 16비트 분할로 똑같이 재현한다(`spec.md:33`, `campaign.js:39`)면 시드별 사망 시각이 **틱 단위로 같아야** 한다. 창 검사는 두되 시드 1~20 의 Luau 값을 원작 값 옆에 표로 남겨라 — 전부 일치하면 ±20% 는 필요 없고, 하나라도 다르면 그 시드가 경로·난수 소비 순서 차이를 찾는 실마리다.

### 결론
F2~F6 해소. F1 은 출처 문제는 풀렸고 재현성(스크립트·전체 값·원작 핀)·정책 정밀도·15~30초 하네스·주입 한 개가 남았다. 전부 스펙·검증 문서 문장으로 닫힌다.
