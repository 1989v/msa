# Spec Review — USECASE (첫 60분 플레이 경험 · PC/터치 · 1~2인)

대상: `spec.md`, `planning/requirements.md`. 원작 근거: `portal-fe/public/games/marine-command/js/origin/{main,sim,campaign,map}.js`, `index.html`, `README.md`, `docs/specs/2026-10-01-marine-origin/planning/unit-progression-preview.md`.

## 걸어 본 경로 (문제 없는 구간)

- **첫 8초**: 본진 (40,0.5,168) 스폰. 사거리 23.75스터드 안에 적이 없다(사냥터 F 는 86스터드, 거점·첨탑은 고지). 8초에 전초기지 쪽 (120,148) 에서 정찰 80마리(HP12)가 출발해 5~6초 뒤 도착하므로 서 있기만 해도 한 발 한 마리로 금화가 들어온다. HUD 「다음 본진 웨이브 N초」(main.js:174) 가 옮겨지면 기다릴 이유가 보인다. 다만 User Story 1 의 「근처 좀비를 자동 사격」은 틀린 문장이다 — 첫 적은 웨이브다. 문구만 고치면 된다.
- **500G → 목수 → 수입**: 80마리 × 10G 로 40초 안팎에 500G. 패널(SR-4) 에서 고용·숲 지정·반납 시 +10G 가 원작 흐름 그대로다.
- **첫 웨이브·탑·주둔·합성·2인 입장·저장**: 아래 F1~F6 이 남는다.

## Findings

### F1 · 리더(아바타)에게 garrison · combine · roll 이 들어왔을 때의 결과가 없다 — REVISE (가장 큼)
- 스펙: SR-2 「리더 위치는 Roblox 캐릭터가 정하고(서버가 HumanoidRootPart 를 읽어 틱마다 넣는다)」(spec.md:26) 와 같은 절의 명령 목록 `garrison(ids, tower)` · `combine(3 ids)` · `heroSkill(roll)`(spec.md:25). 리더 제외 규칙이 없다.
- 원작: 주둔은 유닛 좌표를 탑으로 **옮긴다**(sim.js:605 `unit.x = tower.x`), 합성은 재료 3명을 **소비**한다(preview §2 「재료 3명은 소비된다」), 구르기는 유닛 좌표를 9틱 동안 **Sim 이 쓴다**(sim.js:342, :596). 셋 다 「Sim 이 위치를 정한다」가 전제인데 리더는 그 반대다.
- 플레이어에게 보이는 결과: 병력 목록에서 자기 자신(리더)을 골라 주둔시키면 아바타는 밖에 서 있고 Sim 은 탑 안으로 친다(탑 사거리 +60 이 아바타 자리에서 적용·피격은 탑으로). 리더 포함 3명 합성이면 아바타가 영웅이 되는지 사라지는지 모른다. 리더가 영웅이면 E 구르기가 아바타를 못 움직인다(SR-4 는 Q/E 를 영웅 선택 없이 「방향」만 받으므로 어느 영웅이 구르는지도 미정 — 원작은 `eligibleHero` 로 선택 영웅 중 ID 순 1명, sim.js:322-325).
- 수정안: ① `garrison`·`combine` 에서 `leaderId` 는 거부(원작 거부 코드 형식으로 `LEADER_LOCKED` 「선두 활잡이는 주둔·합성할 수 없습니다」) 하거나, 합성은 허용하되 리더가 영웅이 되는 것으로 고정 ② `heroSkill` 의 대상 영웅 선택 규칙을 적는다(리더가 영웅이면 리더 우선, 아니면 추종 영웅 ID 순) ③ 리더 구르기는 서버가 0.3초 동안 HumanoidRootPart CFrame 을 쓰는 예외 경로를 명시(그 동안 입력 무시).

### F2 · 리더 사망 뒤 「리더 없음」 상태가 생긴다 — REVISE
- 스펙: SR-3 「살아 있는 전투 병력 → 새 리더, 없고 금화 ≥700 → 700G 차감 리스폰, 둘 다 아니면 원작 경제 패배 조건」(spec.md:37).
- 원작 패배 조건: `s.owners.every(o => o.gold < 500 && 유닛 0)`(sim.js:703) — 목수도 유닛이고, 금화 500~699 도 패배가 아니다.
- 빠지는 경우: 전투 병력 0 · 목수 1명 이상(채집 중) · 금화 < 700. 패배는 아니고 아바타도 없다. Roblox 는 `CharacterAutoLoads` 로 캐릭터를 다시 띄우므로 「Sim 에 없는 캐릭터」가 본진에 서 있게 된다. 목수 수입으로 700G 가 되면 자동 고용인지도 없다. 협동이면 상대가 계속 노는 동안 이 플레이어는 할 일이 없다.
- 또 「살아 있는 전투 병력 중 하나」가 **주둔 중**이면 탑에서 빠져나오는지, 영웅이면 F1 의 roll 문제가 따라온다.
- 수정안: 「리더 없음」을 상태로 두고 ① 캐릭터는 본진에 관전 상태로 리스폰(이동 가능·사격 없음) ② 금화 ≥700 이 되는 틱에 자동 고용·리더 승계, 토스트 「활잡이를 고용해 원정을 이어갑니다 · −700G」 ③ 새 리더 후보는 비주둔 전투 병력 우선, 없으면 주둔자를 철수시켜 승계.

### F3 · 「문구는 원작 한국어 그대로」가 제거한 기능을 가리킨다 — REVISE
- 스펙: SR-4 「문구는 원작 한국어 그대로」(spec.md:43), 「튜토리얼 단계」 전송(spec.md:36). 제거한 것: 클릭 목적지·Shift 드래그(requirements.md:41), 지역 탐색(Out of Scope).
- 원작 문구가 가리키는 것: 「본진 오른쪽 고용소에서 목수 1명을 고용하세요」(main.js:122), 「본진 왼쪽 훈련장: 공방업·합성. 건물을 클릭하거나」(main.js:65) — 빌더 산출 목록(SR-1, spec.md:18)에 고용소·훈련장 건물이 없다. 「바닥 클릭으로 이동 … Shift 드래그로 화면을 둘러보고 ◎로」(main.js:58), 「지역 탐색에서 거점과 던전 진행을」(main.js:59), 「고지·묘역·광산 순서로 진출」(main.js:125, 분지 밖). index.html:12 초기 문구 「100G를 모으세요」도 500G 와 어긋난다.
- 순서도 어긋난다: 원작 1단계는 **공업 3·방업 2 먼저**(main.js:118, 약 225G) 이고 목수는 2단계인데, User Story 2 와 SR-5 진행 봇은 목수가 첫 목표다. 어느 쪽인지 정해야 봇 측정치(40~180초)와 튜토리얼이 같은 걸 가리킨다.
- 수정안: 튜토리얼 6단계·가이드·초기 문구를 Roblox 판 표로 스펙에 싣는다(원작 문구를 기본으로, 건물·클릭·드래그·지역 탐색 언급만 바꿈). 순서는 원작(강화 → 목수)을 따르고 User Story 2 를 그에 맞춘다.

### F4 · 입력 충돌: Esc·Tab 은 Roblox 가 쓰고, 터치는 점프 버튼·탭 우선순위·배치 모드가 비어 있다 — REVISE
- 스펙: SR-4 「Tab 부대 관리, Esc 닫기」, 「Q/E 는 ContextActionService(키 + 터치 버튼), 방향은 마우스/터치 지점」, 「배치 모드(지면 커서 따라 유령 파트 …)」(spec.md:45-46).
- PC: Esc 는 Roblox 메뉴 전용이라 ContextActionService 가 못 받는다. Tab 은 기본 CoreGui 플레이어 목록 토글이라 패널과 함께 열린다.
- 터치: 기본 UI 가 왼쪽 아래 스틱 + 오른쪽 아래 점프 버튼이다. 스펙의 하단 액션바 4개 + Q/E 가 같은 자리다. 점프를 끄지 않으면(JumpPower 0 또는 점프 버튼 숨김) 절벽(8스터드) 가장자리·경사로 턱으로 올라가 리더가 blocked 셀에 서고, 추종자 A*(SR-2) 가 못 따라온다. 원작은 이 상황이 없다(squad 는 `navigate` 로만 움직인다, sim.js:513).
- Q/E 터치: 버튼을 누르는 순간의 터치 지점은 버튼 자리다. 원작은 **버튼 → 전장 탭** 2단계(`armSkill`, main.js:158-161, Esc 취소). 스펙엔 이 2단계와 취소가 없다.
- 탭 우선순위: 원작은 한 탭을 스킬 지정 → 배치 → 적 카드 → 서비스 건물 → 아군 → 탑 순으로 판정한다(main.js:199-204). 스펙엔 「선택 적 카드」와 「지면 레이캐스트」가 모두 있지만 같은 탭을 누가 먹는지 없다.
- 배치 모드: 터치엔 hover 가 없어 「커서 따라 유령 파트」가 안 움직인다. 원작은 탭으로 위치를 찍고 확인 버튼을 누른다(main.js:199 `placement.x=…` on pointerup).
- 수정안: Esc → 패널 닫기 버튼 + 오른쪽 위 X(키는 안 둔다). Tab → `StarterGui:SetCoreGuiEnabled(PlayerList,false)` 를 명시하거나 다른 키. 점프 비활성 + 액션바를 스틱·점프 영역 밖(화면 오른쪽 세로열)으로. Q/E 는 「무장 → 지면 탭/클릭 → 발동, 다시 누르면 취소」. 탭 판정 순서 한 줄. 배치는 터치에서 탭=이동, 확인 버튼=건설.

### F5 · 이어하기 · 2인 저장이 한 캠페인을 두 열쇠로 나눈다 — REVISE
- 스펙: SR-3 「소유자 키 `ArcherCommand_v1/<userId>` 에 캠페인 스냅샷」(spec.md:39), 「첫 입장 시 스냅샷이 있으면 이어하기/새 원정 선택. 두 번째 입장 시 coop 전환」(spec.md:35).
- 원작: 싱글/협동 슬롯 분리, 협동은 방장만 정본을 쓰고 손님은 복구본(README.md:26, main.js:109).
- 비는 흐름: ① 둘이 60분을 놀고 각자 나가면 같은 캠페인 사본이 두 userId 에 저장된다. 다음에 B 가 먼저 혼자 들어오면 B 사본(A 의 병력·탑 포함, 본진 6000)으로 「이어하기」가 뜨고, 나중에 A 가 들어오면 A 의 사본은 묻지도 않고 버려진다 — 둘이 각자 다른 서버에서 이어가면 같은 캠페인이 둘로 갈라진다. ② 둘째 플레이어가 자기 솔로 스냅샷을 갖고 있어도 선택지가 없다. ③ 「이어하기」시 캐릭터는 SpawnLocation 에 서고 저장된 리더 좌표는 다른 곳이다 — 추종자가 그리로 달려오는지, 캐릭터를 옮기는지 없다. ④ 선택 다이얼로그가 떠 있는 동안 Sim 이 돌면 첫 웨이브 8초가 메뉴 뒤에서 지나간다.
- 수정안: 캠페인 열쇠를 「첫 소유자 userId」 하나로 하고 둘째는 참가 기록만(원작 방장/손님). 둘째 입장 시 「내 원정 이어하기」는 없음을 명시. 이어하기 확정 틱에 캐릭터를 리더 좌표로 PivotTo. 선택이 끝나기 전까지 Sim.step 을 시작하지 않는다.

### F6 · 본진 귀환(R)이 추종자를 떼어 놓고, 다시 붙는 규칙이 없다 — REVISE
- 스펙: SR-4 「R 본진 귀환은 『따라오기 해제 + 본진으로 걷기』 표시만(아바타는 플레이어가 걷는다)」(spec.md:45).
- 원작: recall 은 squad.target = base 로 **부대 전체**가 함께 걷고 skillHold 도 푼다(sim.js:363-370). 추종자가 리더에서 떨어지는 명령이 아니다.
- 플레이어에게 보이는 결과: R 을 누르면 추종자 11명이 본진으로 가고 플레이어는 그 자리에 혼자 남는다(원작 튜토리얼 「R 귀환은 순간이동이 아닌 복귀 이동」, main.js:59, 과 의미가 다르다). 플레이어가 나중에 본진에 오면 추종자가 다시 붙는 조건(거리? 입력?)이 없다. 영웅이 구르기로 떨어진 뒤(skillHold) 복귀 조건도 「리더가 입력으로 움직이면」(spec.md:26) 뿐이라, HumanoidRootPart 좌표만 읽는 서버가 「입력」을 어떻게 아는지(MoveDirection 읽기?)가 빠져 있다.
- 수정안: R 을 「추종자가 본진으로 먼저 걷고, 리더가 본진 반경 96px(12스터드) 안에 들어오면 follow 로 복귀」로 적거나, 아바타 중심이므로 R 자체를 없애고 「본진 방향 표시」만 남긴다. skillHold 해제는 `Humanoid.MoveDirection.Magnitude > 0` 으로 명시.

## 체크리스트
- Actor-goal: 1인·2인 소유자 목표는 있음. 리더 없음 상태의 행위자 목표 없음(F2).
- Main/Alt/Exception: 주 흐름은 원작 표로 충분. 예외 흐름(리더 주둔·합성·사망 한계·저장 충돌)이 빔(F1·F2·F5).
- Pre/Post: 이어하기 선택 중 Sim 정지 여부, 리더 좌표 복원 없음(F5).
- AC 추적: SR-5 가 Sim 규칙은 덮지만 F1~F6 은 전부 「Studio 미검증」 영역이라 수동 확인 목록에 넣어야 한다.
- Edge: 터치 점프·blocked 셀(F4).
- Test mapping: 리더 제외 규칙·리더 없음 전이·저장 열쇠 단일화는 `tests/run.luau` 에 넣을 수 있다(Roblox API 불필요).

VERDICT: REVISE

### 남는 것 (비차단 · 문구 한 줄씩)
- **R1 리더 승계 시 캐릭터 이동**: 리더가 죽고 추종자가 승계하거나(spec.md:21) 리더 없음에서 고용으로 리더가 생길 때, 캐릭터가 새 리더 유닛 좌표로 옮겨지는지가 없다. 역방향 쓰기 넷(spec.md:19) 의 「리스폰」이 이것을 뜻한다면 「리스폰 = 리더 승계·고용 시 새 리더 좌표로 PivotTo」 한 줄로 못 박는다. 안 적으면 관전 중 본진 밖으로 걸어간 캐릭터와 본진에서 생성된 새 리더가 떨어져 서서, 다음 틱 위치 검사(속도×dt×2+0.5)가 캐릭터를 끌어오는 모양이 「되돌림」으로 로그에 찍힌다.
- **R2 손님에게 보이는 저장 안내**: 둘째 소유자가 다음에 혼자 들어오면 자기 키엔 스냅샷이 없어 「새 원정」만 뜬다. 결정은 명확하나(spec.md:24, 77) 플레이어는 60분이 사라졌다고 느낀다. 수락 시 HUD 토스트 「이 원정은 OO(호스트) 님 계정에 저장됩니다」 한 줄을 안내 표에 더한다.
- **R3 이어하기 뒤 부재 손님 병력**: coop 저장본을 호스트 혼자 이어하면 둘째 소유자 병력은 리더 없이 본진에 남고 웨이브는 ×1.4 그대로다(원작과 같다, requirements.md:51). 원작 동작이므로 수용하되 UNVERIFIED 목록(spec.md:66)의 「2인 접속」 항목에 「호스트 단독 이어하기」를 함께 적는다.
- **R4 WalkSpeed 하한**: 「살아 있는 추종 전투 병력 중 최저 속도」(spec.md:19) 는 원작 `Math.min(...followers)`(sim.js:509) 과 같다. 장궁수 1명이 섞이면 리더도 95 로 걷는다 — 의도된 원작 동작이지만 플레이어는 느려진 이유를 모른다. 병력 패널 속도 열 하나면 충분하다(선택).
