# 마지막 한 사람 (last-one) — PRD

- 일자: 2026-09-02
- 형태: 유니티 WebGL · **공용 프레임워크 `com.kgd.webgame`** 위의 세 번째 게임 · **첫 실시간 다인 대전**
- 상태: **구현됨** (2026-09-03) — 네트워크는 ADR-0088(호스트 권위 + 릴레이 N석), 구현 판단과
  게이트 실측은 `portal-fe/public/games/_src/last-one/DESIGN.md`. §10 선행 작업 넷은 전부 끝났다
  (`KgdMountain` 추출 · 릴레이 N석 · 20체 실측 · ADR)
- 선행 결정: 네트워크 방식은 **ADR 이 필요하다**(§6). 이 PRD 는 후보와 판정 기준까지만 적는다

## 0. 한 줄 정의

**아홉 종의 산 하나에 스무 명이 떨어져, 마지막 한 사람이 남을 때까지 싸운다.**
사람이 모자라면 AI 가 스무 자리를 채우고, 넘치면 줄을 선다. 죽으면 그 판에서 나간다.

## 1. 왜 지금인가

| 근거 | 내용 |
|---|---|
| 프레임워크의 전투 축 검증 | 아홉 종에서 올린 무기(`KgdWeapon`)·막기(`KgdGuard`)·원거리(`KgdShots`)·추격 AI(`KgdChase`)가 **사람 대 사람**에서도 서는지 — PvE 에서는 안 드러나는 균형 문제가 여기서 나온다 |
| 플랫폼의 첫 실시간 다인 | 릴레이(`/ws/games/{slug}`)는 2인 무권위다. 20인은 그것의 확장이 아니라 **다른 물건**이고, 그 물건이 생기면 다른 게임도 쓴다 |
| AI 대체가 이미 검증됨 | 인피니티 타워(캔버스)가 「사람이 나가면 AI 가 잇는다」를 **의도(intent) 단일 통로**로 풀었다. 같은 구조를 3D 로 옮긴다 |

## 2. 벤치마크 하한

기준작: 배틀로얄(2000, 영화)의 규칙 · Fall Guys / Rumbleverse 의 라운드 길이.

| 축 | 하한 | 잰다 |
|---|---|---|
| 한 판 인원 | **정확히 20** (사람 + AI). 19명이 죽어야 끝난다 | 서버 방 상한 · 봇 충원 게이트 |
| 한 판 길이 | **4~7분**. 좁혀 오는 경계가 시간을 정한다 | `PaceGate` — 봇 20명 판 100회 평균·분산 |
| 지도 | 아홉 종 챕터 1(지름 620, 7층)을 **그대로** — 새 지도를 만들지 않는다 | — |
| 무기 종류 | **5** (맨손·검·도끼·창·활) + 방패. 지도에 흩어져 있어 **줍는다** | `KgdScatter` |
| 공격·회피 변주 | 무기 5 × (약공·강공) + 구르기·막기·점프 + 등반·활공 = **위치 선점이 곧 기술**이다 | 균형 게이트(§7) |
| 커스터마이징 | 색 3곳(옷·머리·띠) + 이름. **능력치 차이는 없다** | 스킨 베이크(`tools/bake-skin.py` 를 런타임 팔레트로) |
| 대기 | 20 초과 시 대기열, 사람이 20 미만이면 AI 충원, **대기 최대 30초** 뒤 무조건 시작 | 서버 |
| 조작 | 모바일 1순위 — 아홉 종 패드 그대로 (버튼 5 + 스틱) | 세로/가로 CDP |

**첫 판부터 어렵다.** AI 는 봐주지 않는다 — 아홉 종 지킴이 수준의 판단으로 싸운다. 난이도는
사람 수가 정한다(사람이 많을수록 어렵다).

## 3. 플레이어 경험

### 한 판의 흐름

```
로비(≤30초) → 낙하(활공으로 착지점 선택, 15초) → 줍기·탐색(1~2분)
→ 경계가 좁혀짐(3단계, 각 60~90초) → 마지막 셋이 정상에서 만난다 → 한 사람
```

- **낙하**: 산 위 300 유닛에서 활공으로 내려온다. 어디에 내리느냐가 첫 선택이다 — 정상 근처는 좋은 무기, 기슭은 안전.
- **경계**: 원이 아니라 **고도**다. 시간이 지나면 낮은 층부터 「무너진다」(안개가 차오르고 그 안에서는 초당 피해). 결국 정상에서 만난다 — 산의 구조가 곧 규칙이다.
- **죽음**: 관전으로 넘어간다(남은 사람 시점). 나가면 자리는 비고, **충원하지 않는다** — 판 중간 충원은 죽은 사람의 값을 없앤다.
- **승리**: 마지막 한 사람. 2~5위도 기록한다(랭킹은 승률이 아니라 **평균 순위**).

### 전투가 PvE 와 다른 점

| PvE(아홉 종) | PvP(이 게임) |
|---|---|
| 적은 예고하고 후딜이 길다 | 사람은 예고를 안 한다 → **예비 동작이 화면에 크게** 보여야 한다(무기 자국·팔 자세가 이미 있다) |
| 막기는 정면만 | 같다 — 그래서 둘러싸면 진다 (여럿 대 하나가 이기는 구조) |
| 활은 한 방향 | **화살이 사람도 맞는다** — 원거리 견제가 생기고, 등반 중인 사람이 표적이 된다 |
| 스태미나 | 같다. 도망도 스태미나를 먹는다 — 끝없이 도망칠 수 없다 |

### AI 대체 (인피니티 타워의 구조를 3D 로)

- 시뮬레이션은 **의도(intent)** 만 소비한다: 이동 벡터 · 버튼 5 · 시선. 사람이든 AI 든 같은 통로.
- AI 정책은 `KgdChase` 의 5 양식(돌진·거리 유지·측면·수비·등반)을 **무기별로 고른다** — 활이면 거리 유지, 도끼면 돌진.
- 사람이 도중에 나가면 그 자리는 **AI 가 잇지 않는다**(죽은 것으로 친다). 인피니티 타워와 다른 점이고, 이유는 위 「죽음」 항목.

## 4. 프레임워크에서 가져오는 것 / 새로 만드는 것

| 필요 | 있는가 | 비고 |
|---|---|---|
| 이동·등반·활공·구르기 | `KgdTraverse` | 그대로 |
| 무기 5 · 팔 자세 · 자국 | `KgdWeapon` · `KgdLimbs` · `KgdTrail` | 그대로. **약공·강공**은 `KgdWeapon` 에 `Heavy` 변형이 필요 — 패키지 |
| 막기 · 원거리 | `KgdGuard` · `KgdShots` | 화살이 **사람**을 맞히는 판정은 게임 |
| AI | `KgdChase` | 표적이 「주인공」에서 「가장 가까운 산 사람」으로 — `Tick(target)` 이 이미 외부에서 표적을 받으므로 게임이 고른다 |
| 지형 | 아홉 종 `Peak` + `KgdPlateau` | **아홉 종 코드를 가져오지 않는다** — `Peak` 를 패키지로 올리는 것이 선행 작업 |
| 경계(고도 안개) | **없음** | `KgdStorm` — 고도 문턱 + 안개 + 피해. 패키지 |
| 낙하 착지 선택 | `KgdTraverse.Glide` | 시작 상태를 Glide 로 |
| 스무 명 | **없음** | 화면에 20체 — 아홉 종은 15체 상한이었다. 애니메이션 컬링 + 먼 개체 저프레임 갱신 필요 |
| 색 커스터마이징 | `tools/bake-skin.py` (오프라인) | **런타임** 팔레트 스왑으로 — `KgdKit.MaterialForSkin` 의 `tint` 로는 한 색뿐이라 부위별 3색은 셰이더 마스크가 필요 |
| 관전 카메라 | `KgdOrbitCam` | 대상 교체만 |
| 네트워크 | 릴레이 2인 | **§6** — 별도 ADR |
| 로비·대기열·충원 | **없음** | 서버 (`game` 도메인) |

## 5. 범위

### 들어가는 것
- 20인 한 판(사람 + AI), 대기열, 30초 강제 시작
- 아홉 종 챕터 1 지도 · 무기 5 + 방패 줍기 · 고도 경계
- 색 3곳 커스터마이징 · 이름
- 관전 · 순위 기록 · 평균 순위 랭킹
- 모바일 세로/가로

### 안 들어가는 것 (이유)
- 팀전 — 「마지막 한 사람」이 정체성. 팀은 후속
- 새 지도 · 새 무기 — 프레임워크 검증이 목적. 콘텐츠는 아홉 종 것으로 충분한지 먼저 본다
- 음성·채팅 — 게스트 허용 플랫폼에서 채팅은 운영 부담이 먼저 온다. 이모트 6종으로 대신
- 매치메이킹 등급 — 20명 채우기도 어려운 규모에서 등급을 나누면 판이 안 선다
- 관전 이외의 사후 참여(재입장·부활) — §3 「죽음」

## 6. 네트워크 — ADR 로 정할 것 (이 PRD 는 후보와 기준만)

**제약**: OCI 무료 티어(4 OCPU · 24GB · 단일 노드), WebGL 단일 스레드, 게스트 허용, 릴레이는 in-memory 단일 레플리카.

| 후보 | 방식 | 서버 비용 | 부정행위 | 지연 체감 | 판정 근거 |
|---|---|---|---|---|---|
| A. 호스트 권위 | 좌석 0 이 시뮬레이션을 돌리고 10Hz 스냅샷을 릴레이로 뿌린다. 나머지는 의도만 보낸다 | 릴레이 그대로(20석으로만 넓힘) | 호스트가 치팅 가능 | 호스트 외 ~100ms + 예측 필요 | **가장 싸다.** 호스트 이탈 시 승계 필요 |
| B. 결정론 락스텝 | 모두 같은 시뮬을 돌리고 의도만 교환. 시드 공유 | 릴레이 그대로 | 어렵다(같은 계산) | 입력 지연 = 가장 느린 사람 | 20명 중 한 명만 끊겨도 전원이 멈춘다 — **탈락** |
| C. 서버 권위 | 서버가 시뮬 (JVM 에 C# 규칙을 옮기거나 headless Unity) | 방 하나에 코어 1 이상 | 없다 | 가장 좋다 | 무료 티어에서 **동시 2~3판**이 상한. 규칙 이중 구현 |

**PRD 의 권고**: A 로 시작한다. 판정 기준 세 가지를 ADR 이 재야 한다 —
① 20인 스냅샷 10Hz 의 릴레이 대역(20 × 19 × 10 × ~600B ≈ 2.3MB/s/판)이 노드 하나에서 몇 판인가
② 호스트 승계(호스트 이탈 시 다음 좌석이 마지막 스냅샷에서 잇는다)가 2초 안에 되는가
③ 모바일 WebGL 이 스냅샷 수신 + 자기 예측 + 20체 렌더를 45fps 로 버티는가

릴레이 변경: 2석 → N석(상한 20) · `start` 에 좌석 전원 · `move` 를 방 전체 팬아웃(발신자 제외) ·
메시지 상한 20 msg/s 는 **스냅샷 10Hz + 의도 20Hz** 에 맞춰 재산정.

## 7. 완성 판정 — 게이트

| 게이트 | 잰다 |
|---|---|
| `PaceGate` | 봇 20명 판 100회 — 평균 4~7분, 표준편차 ≤ 90초 |
| `BalanceGate` | 무기별 봇 승률이 **12~28%** 안 (5종 균등 20% ± 8). 한 무기가 30% 를 넘으면 실패 |
| `FillGate` | 사람 0~20 어느 수에서도 정확히 20으로 시작 · 대기 30초 초과 0 |
| `StormGate` | 경계가 닫힌 뒤 어느 지점도 「도달 불가 안전지대」가 없다(고도 문턱 위에 서 있을 자리가 반드시 있다) |
| `NetGate` | ADR 의 세 판정(§6)을 수치로 |
| 실기 | 20체 화면에서 모바일 ≥ 45fps · 세로/가로 CDP 4조합 · 폰 발열 10분 |

## 8. 예산 · 제약

| 항목 | 상한 |
|---|---|
| 총 전송량 | ≤ 15MB — 아홉 종과 **번들을 공유**하면 지도 부분은 0 |
| 화면 삼각형 | ≤ 30k (20체 × 캐릭터 ≤ 1,500 = 30k 가 이미 상한 — **지형 20k 와 합치면 50k**) → 먼 캐릭터를 낮은 폴리곤 또는 빌보드(기법 카탈로그 A4)로 |
| 서버 | 무료 티어 안. 동시 판 수는 `NetGate` 가 정한다 — **용량이 모자라면 증설이 아니라 동시 판 수를 줄인다** |
| 게스트 | 로그인 없이 참가. 이름은 임시. 랭킹은 로그인 사용자만 |

## 9. 위험

| 위험 | 대응 |
|---|---|
| 사람이 20명이 안 모인다 | 설계 전제 — AI 충원이 기본값이고, **사람 1명 + AI 19 도 정상 판**이다. 그래서 AI 품질이 곧 제품이다 |
| 호스트 치팅 | 게스트 랭킹이 없으므로 이득이 작다. 랭킹 등록은 로그인 + 사후 검증(판 기록 재생) 후보 |
| 20체 성능 | §8. 안 되면 **16 명**으로 줄인다 — 인원은 조정 가능한 숫자이고 원칙(마지막 한 사람)은 아니다 |
| 균형 붕괴 | `BalanceGate`. PvE 값(검 22·도끼 40·창 26·활 17)은 PvP 에서 다시 잰다 |
| 릴레이 단일 레플리카 | 판이 in-memory 라 재배포 = 전 판 종료. 배포 창을 새벽으로 |

## 10. 선행 작업 (이 PRD 가 착수 조건으로 요구하는 것)

1. **`Peak` 를 패키지로** — 지도를 아홉 종 코드에서 떼어낸다 (`KgdMountain`)
2. **릴레이 N석** — `game` 도메인. ADR
3. **20체 성능 실측** — 아홉 종에서 적을 20으로 늘려 fps 를 잰다. 안 되면 §8 대응
4. **네트워크 ADR** — §6 의 세 판정

## 11. 미결정

- 강공(`Heavy`)의 규칙 — 스태미나를 더 먹고 막기를 뚫는가, 아니면 후딜이 긴가
- 경계 3단계의 고도 문턱과 시간 — `PaceGate` 로 정한다
- 게스트의 커스터마이징 저장 — 로컬인가, 서버인가
