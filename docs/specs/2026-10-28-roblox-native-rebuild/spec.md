# 인피니티 스탭 — 로블록스 경험으로 전면 재개발

## 승인과 범위

사용자가 웹 UI/키 설명/클릭 점프 버튼의 복제를 지적하고 “이거 기준으로 전체 다시 개발해 다 날리고”라고 명시했다. `roblox/infinity-step/`의 기존38개 추적 파일과 산출물을 폐기하고 새로 구현한다. 웹 원작·`roblox/archer-command/`·다른 게임·기존 작업자의 변경은 삭제/변경하지 않는다. 이전 구현은 git 이력에만 남긴다. 메모리와 개발 정리는 [로블록스 작업 원칙](../../../roblox/AGENTS.md)을 통해 이후 작업에 적용한다.

## 게임의 핵심

도시에서 상공·블랙홀까지 오르며, 도약의 힘과 착지 위치를 판단하고 실패하면 아래로 떨어져 다시 도전한다. 높이별 구간·위험 변화, 등반·힘 관리, 현재 진행 저장, 선택적 마지막 안전 발판 부활이라는 구성을 유지한다. 원본 좌표·개수·수치·버튼·카메라 구현을 복제하지 않는다.

## 기본 조작 — 웹 컨트롤을 만들지 않는다

- Roblox 기본 PlayerModule·Humanoid·아바타·기기별 이동/점프·기본 카메라를 유지한다. 별도 터치 스틱/Jump 버튼/고정 C·X·Z·WASD 안내/웹 오빗 카메라를 작성하지 않는다. Shift Lock·기본 줌·게임패드 등 엔진 UX를 가로채지 않는다.
- 충전 규칙은 **착지 후 힘이 차오르고 평소 점프로 사용하는 방식**으로 각색한다. 기본 점프의 누름/놓음을 기기별로 억지로 가로채지 않는다. Humanoid 점프 상태를 정상 유지하며 JumpPower는 항상 양수다. 충전량은 작은 비클릭 피드백으로만 표시한다. 이 방식은 부모의 명시한 플랫폼 적응 설계이며 원작의 버튼 홀드와 다르다.
- 이동을 일정 시간 유지하면 자연스럽게 달리기로 전환하는 방식 등 기본 이동과 결합한다. 별도 Run/Grab 터치 버튼은 만들지 않는다. 기기별 고정 키 설명 대신 필요한 안내는 ProximityPrompt 같은 엔진 상호작용에 맡긴다.
- 등반은 실제 Truss/사다리·기본 Humanoid Climbing을 우선한다. 매달림을 추가하면 자동 감지와 기본 점프/이동으로 연결하고 전용 웹식 버튼을 요구하지 않는다. 체력/소모/이탈·재진입 방지와 접속/사망 상태를 검증한다.
- 기본 카메라를 Scriptable로 바꾸지 않는다. UI는 기기와 상태에 적합한 최소 고도/구간/힘 피드백, 필요 시 부활 선택만 제공한다.

## 월드와 에셋 — 실제 로블록스 공간

- 시작 광장/골목, 외벽/주거 옥상, 마천루, 공사장, 통신 상공, 우주/블랙홀의7구간을 갖는다. 반복 직선 발판을 장식 없이 늘리는 결과물은 기준 미달이다.
- 네이티브 Terrain(지형·물·잔디 등), 내장 재질, Sky/Atmosphere/Clouds, 적절한 조명/후처리, 기본 아바타/애니메이션을 실제로 활용한다. Clouds는 Terrain 자식이어야 한다.
- 재사용 가능한 Model/프리팹 자산으로 건물 외관·창·문·비상계단·가로등·물탱크·실외기·환기구·비계·곤돌라·안테나 등 구조를 구성한다. 발판은 가능하면 이 구조의 실제 지붕/빔/테라스로 보이게 한다. 역할과 시각적 실루엣이 구간마다 다르다.
- 외부 Creator Store 자산을 쓰는 경우 제공자/가격·사용 조건·의존성을 확인하고 불필요한 스크립트를 실행하지 않는다. 유료 구매와 계정 권한 확대는 별도 승인이다. 현재는 내장 리소스와 직접 만든 모듈형 Model을 기본으로 하며, 외부 에셋을 쓰지 않았다면 썼다고 주장하지 않는다.
- 에셋 목록에는 실제 사용한 내장 재질/스카이/클라우드/Model의 출처와 역할을 기록한다. 단순 부품 수나 생성 그림을 “풍부한 배경 검증”으로 삼지 않는다.
- 스트리밍과 충돌 그룹을 사용하고, 장식에는 필요한 경우 충돌/쿼리를 끈다. 서버의 진행 충돌 지형은 추락 시에도 보존한다. 부품·광원·파일 크기를 측정하되 특정 개수를 원본과 맞추지 않는다.

## 구현 경계

- 기존 Roblox 코드/맵/자료/내보내기 도구/테스트를 복사하지 않는다. 게임 아이디어와 출처가 확인된 공식 API만 새 설계에 사용한다. 원작 C# 추출/SDK/경사 타일/수동 키맵을 기본 구성에서 제외한다.
- 공유 순수 규칙과 서버 권한(진행·저장·부활·영수증) 및 네이티브 클라이언트 피드백을 분리한다. 네트워크 입력은 타입·유한수·상태·빈도를 검증하고 점수/재고/부활 좌표는 서버가 결정한다.
- 서버·클라이언트가 경쟁하여 기본 점프를 두 번 실행하지 않게 한다. 일반 점프를 가로채는 대신 기본 캐릭터의 점프 힘을 제어하며, 실제 네이티브 입력과 물리 연결은 별도 엔진 검사 대상이다.
- 진행은 현재와 최고를 구분하며, 재접속이 무료 최고 지점 복귀가 되지 않게 한다. 접속별 소유권/순서로 오래된 저장을 거부한다.
- 부활은 추락 직전 마지막 안정 착지 대상, 명시 선택과 단일 차감, 재시도/사망/끊김 시 권리 보존을 구현한다. 실판매ID0·별도 Studio 테스트 재고, 라이브 상품·구매·게시 없음. 새 개발 저장소 이름을 사용하며 기존 배포/실판매 이력이 없다는 전제와 호환 한계를 기록한다.
- 결정적 빌더와 편집 가능한 Luau·프로젝트 매핑·`.rbxlx`·한글 README를 제공한다. 월드 프리팹과 환경은 편집 화면에서도 확인 가능하고 Terrain 등 시작 시 생성 요소는 구분한다.

## 검사

1. 실제 새 순수 모듈로 충전/착지/일반 점프·등반·진행·부활·실패 복구를 검사한다.
2. 기본 PlayerModule/카메라를 대체하는 코드, 고정 키 안내, 추가 Jump/Run/Grab GUI, 낡은 SDK/원작 좌표 스냅샷이 없음을 구조 검사한다.
3. 네이티브 환경/Model/재질·Clouds의 서비스 배치, 실제 스크립트와 빌드 포함, 스폰·충돌·경로·착지 여유·결정적 재생성·예산을 검사한다.
4. 독립 코드 리뷰를 받는다. CLI·구문 검사는 실제 Studio API/물리/기기 입력·화면 검증을 대신하지 않는다.
5. 이전 브라우저/Studio 도구 거절을 다른 경로로 우회하지 않는다. 현재 실제 화면 검증은 미검증이다. 이 상태에서 플레이/이식 완료라고 보고하지 않는다.
