## 0. 수직 슬라이스 — 이번에 100% 로 만들 것

**고을 1 · 1판 방어 하나.** 방어 한 판이 처음부터 끝까지 완성품 품질로 돈다.

슬라이스에 **반드시** 들어가는 것:

|---|---|---|
| 판 | 1판 방어 1 | 54 (고을 18 × 3판) |
| 영웅 | **2** (광개토대왕 전투형 · 양만춘 수성형) | 12 |
| 슬롯 건물 | **3** (궁방·노대·마름쇠) | 6 |
| 적 | **3** (기병·방패병·궁수) | 24 |

그 외에 슬라이스가 갖춰야 하는 것 — **원근 카메라 · 실시간 조명과 그림자 ·

## 1. 화면 축척 — 원근이라 재는 법이 다르다

아이소메트릭의 「시야 폭」이 없다. 카메라 파라미터와 **화면에 찍히는 픽셀**로 잰다.

| 항목 | 값 | 어떻게 재나 |
|---|---|---|
| 카메라 | **직교(orthographic)** — 원근 없음 | 프로젝트 설정 |
| 내려다보는 각 | **60°** | 지면 법선과 카메라 전방의 각 |
| 줌 3단 | **긴 변이 담는 월드 길이 48 / 65.5 / 95** | 거리가 아니라 길이다 (직교) |
| **원근이 벌어지는 정도** | **1.00 배** (참조작 실측 0.97) | 지면 위 같은 길이를 화면 위·아래에서 잰다 (ScaleGate) |
| **주인공 화면 비율** | **1/30.9** (화면 **긴 변** 기준) | 참조작 실제 플레이 화면 픽셀 실측 |
| **주인공 CSS px** | 가로 844×390 → **27.3 px** · 세로 390×844 → **27.3 px** | 긴 변이 844 로 같다 |
| 화면 중앙 지면이 담는 가로 | **65.6 유닛** (가로 844×390) | 짧은 변이 담는 길이 × 화면비 — 상수로 적지 않고 줌에서 뽑는다 |

- **참조작 실측 = 1/14.3** — `_ref/ks-세로-01.png` (실제 플레이 화면), 영웅 crop
  `x 402~469 · y 914~997` → 세로 **84px** / 짧은 변 **1200**
- 같은 프레임의 일반 유닛은 **1/18 안팎**이라 영웅이 유닛의 약 **2.4배**다 — 우리 비율과 같다
- **앞선 1/8.3 은 광고 프레임을 잰 값이었다** (`ks-가로-01.png`, 하단 「적을 물리쳐라」 배너 +
  전경에 과장된 거인). 광고 프레임은 인물이 크게 그려져 있어 축척의 근거가 못 된다.
  그 한 줄 때문에 카메라가 처음부터 **1.5배 가까웠고**, 지형·아트를 아무리 손봐도
  「확대된 느낌」이 안 없어졌다 (파이프라인 §8.0.2 신설의 계기)
- **주인공 키는 3.59 유닛**이고 손으로 정하지 않는다 — 위 세 값에서 역산한다(`Spec.HeightForFraction`).
  눌려 보이는 것(cos)만 넣으면 11% 크게 나온다: 부각이 있으면 세운 것의 윗끝이 카메라에 더 가깝다
- 「한 화면이 담는 길」은 처음 42 로 어림했고 실측이 47.7 이었다. **2026-09-09 에 65.6 으로 넓혔다** —
  줌 거리를 32 → 44 로 늘렸다. 영웅은 여전히 짧은 변의 1/14.3 이고, 넓어진 것은 **지형 쪽**이다
  (「카메라가 가깝다」는 영웅 크기가 아니라 이 값이 만든다).
  굽이진 길이라 시작 화면에 실제로 들어오는 길은 **31 유닛**이다
- **41 CSS px 는 조작 대상 하한 28 을 넘긴다.** 캔버스 판본이 19.5px 로 겨우 버티던 자리가 풀린다
- 줌 3단은 유지한다. 최대 축소(210)에서 길의 굽이가 한눈에 읽혀야 한다

### 영웅 로스터 둘 — 데이터로 (2026-09-13 네 번째)

설계 5장 「슬라이스에 영웅 2명(전투형·수성형 각 1)」·「영웅은 데이터 파일 하나로 정의되고 코드 분기를
만들지 않는다」를 붙였다. `Heroes.Roster`(`HeroDef`) 한 배열이 이름·배분·사거리·발사·관통·스킬 둘·
손에 든 것·수성 오라를 갖고, 사격(`Battle`)·스킬(`Skills`)·표식(`HeroMark`)·고르기 화면(`Hud.ShowPick`)이
전부 그 정의로 조립된다. 영웅이 늘면 한 줄이 늘고 게이트(`SkillGate`)도 로스터를 돈다.

| | 광개토대왕 · 전투형 | 양만춘 · 수성형 |
|---|---|---|
| 사격 | 18 · 0.55초 · 7 · 2기 관통 | 18 · 0.63초 · 7 · 2기 관통, **성문 30 유닛 안에서 사거리·피해 +30%** |
| 스킬 1 | 돌격 (12초) | **보수** — 성문 +180, 문에서 26 유닛 안에서만 (25초) |
| 스킬 2 | 화살비 (18초) | **철벽** — 6초 동안 성문이 안 깎이고 문 앞 반경 8 을 6 유닛 뒤로 (20초) |
| 표식 | 두 갈래 깃 + 창 | 낮은 투구·면갑 + **눕혀 든 활**(세우면 부각 60° 에서 막대로 보인다) |

- 이름이 사서에 없다는 사실은 양만춘 설명문에 그대로 적는다(「안시성주」).
- 고르기 화면은 판이 서기 전 한 번 — 카드 둘(유니티 UI 버튼 + EventSystem) 또는 1·2번 키. 고르기 전에는
  웨이브가 안 나온다. 화면 버튼 4·5번 이름은 「스킬1·2」로 두고 실제 이름은 HUD 칩이 보여 준다 —
  터치 버튼은 HTML 이라 영웅마다 못 바꾼다.
- 화살비 과녁은 **화면 안**에서만 고른다(`OnScreen`) — 안 보이는 데 떨어지면 뭘 눌렀는지 모른다.
- 궁수 활을 앞으로 기울여 키우고 화살깃을 어깨 위로 냈다(재굽기). 죽은 `KitCrowd`·`Gear` 를 지우고 `Blobs` 만 남겼다.
- 영웅 시안 캔버스(광개토대왕·양만춘, 프라이빗): 볼트 `claude/artifact/jeonran-heroes`. 확인되면 적처럼 치비 리그로 옮겨 굽는다.
- 승급(4단계)은 재료가 소탕 판에서만 나오므로 소탕 판과 함께 온다 — §9 그대로.

`SkillGate` 36 항목: 로스터 둘·배분 갈림·버튼 배선 + 영웅마다 스킬 둘의 효과(돌격 12→0·화살비 11 기·보수 892→991·
철벽 동안 성문 유지·10→0)·쿨다운·거절(적 없음·성문 멀리)·오라 배율(1.30/1.00). 보수·철벽 배선을 끊으면 다섯 줄 빨간불.

### 합류점·병종 키·영웅 스킬 (2026-09-13 세 번째)

**합류점 픽셀 깨짐** — 본줄기와 진입로 띠가 같은 높이(0.06)에 겹쳐 z-fighting 이 줄무늬로
났다. 길마다 높이를 갈라(본줄기 0.04 · 진입로 0.08 · 띠마다 +0.012) 겹치는 자리에서 늘 한쪽이
이기게 하고, 그림자 바이어스를 0.02 → 0.05 로. 합류점 크롭에서 세로 급변 픽셀 8.04% → 1.96%
(남은 것은 병사 창).

**병종 키** — 기병 1.00 · 궁수 0.86 · 방패병 1.20 (전 0.92/1.12). 같은 병종 안에서도 씨앗으로
±7% 어긋난다 — 전부 같은 키면 도장 찍은 무리로 보인다. 판정에는 안 들어간다.
`CrowdGate` 가 메시 사각형의 세로 변으로 잰다: 방패/궁수 평균 1.39배 · 병종 안 최대/최소 1.139배.

**영웅 스킬 둘** — 설계 5장 「스킬 버튼 1~2개(쿨다운)」. 둘 다 **정체된 덩어리**를 노린다 —
자동 사격은 한 줄씩 지우므로 문 앞에 쌓인 것을 한꺼번에 떼어 놓을 손이 따로 있어야 한다.

| | 돌격 (A · 4번) | 화살비 (S · 5번) |
|---|---|---|
| 무엇 | 가장 가까운 적 쪽으로 26 유닛/초 × 0.4초 내달리며 반경 2.4 안을 벤다 | 사거리(18) 안 **가장 빽빽한** 자리(반경 4.2)에 16발 |
| 피해 | 12 (1차 기병 한 방) + **길 뒤로 5 유닛** 밀어냄 | 10 (궁수 즉사) |
| 쿨다운 | 12초 | 18초 |
| 표시 | 발밑 흙먼지(둥근 퍼프) | 붉은 고리 0.55초 → 영웅 쪽 하늘에서 비스듬히 떨어지는 화살 |
| 거절 | 쿨다운이면 남은 초를 말한다 | 적이 없으면 「사거리에 적이 없다」, 쿨다운 안 돈다 |

- 돌격의 걸음은 `KgdTraverse` 의 구르기(Roll)다 — 벽·비탈 규칙을 새로 짜지 않는다. 시작
  프레임에 **몸 방향을 바로 돌린다**(걷기 회전은 35% 보간이라 옛 방향으로 굴렀다: 11.7 유닛 달리고 0 기)
- 한 번 휘두름에 한 기는 한 번만 — 기마다 꼬리표(`Tag`). 밀려난 기가 있으면 다음 걸음 전에 줄을 다시 세운다
- HUD **왼쪽 아래** 칩 둘이 찬 만큼 채워진다 — 터치 버튼은 HTML 이라 쿨다운을 못 보여 준다.
  오른쪽 아래에 두었더니 가로에서 터치 버튼에 가려 반만 보였다(실측). 화살비 사거리도 1.3배로
  두었다가 고리가 화면 밖에 떨어져 사거리와 같게 줄였다
- 번쩍임·흙먼지는 `Kgd/Puff`(uv 로 둥글게 깎는 가산)로 — 네모 그대로면 발밑 흙먼지가 판으로 보였다

`SkillGate`(9번째): 문 앞 3 유닛 안 12 기 → 돌격 → **0 기**(밀려남) · 벤 12 · 화살 16발 동시 비행 ·
화살비 14 기 · 고리 켜짐/꺼짐 · 쿨다운 돌고 풀림 · 적 없으면 거절 · 4·5번 버튼 배선.
베는 배선을 끊고 돌리면 세 줄 빨간불(0 기 · 12 → 12).

### 적 무리를 구운 스프라이트로 (2026-09-13 두 번째)

**아레나와 왜 다른가.** 아레나(`amp-arena/client/src/game/rig.ts`)는 「시안 캐릭터 시트의 비율을
3D 로 옮긴」 13본 치비 리그에 **뒤집은 껍질 외곽선**을 두른다. 전란은 남의 저폴리 킷에
텍스처만 갈아 끼웠다 — 사실 비율이라 위에서 보면 머리 공만 남고, 외곽선이 없어 선이 없는
그림이 된다. 킹샷 느낌은 텍스처가 아니라 **치비 비율 + 외곽선 + 단색 면**에서 온다.

**140 기라 리그를 실시간으로 못 돌린다** → 굽는다. 카메라가 직교 + 부각 60° 고정이라 유닛의
보이는 모습은 카메라 기준 yaw 와 걸음 위상으로만 갈린다. `SpriteBake` 가 게임과 같은
카메라·조명으로 방향 8 × 걸음 8 을 아틀라스(2304×768, 칸 96px)에 굽고, `SpriteCrowd` 가
병종당 메시 하나에 사각형으로 붙인다.

| | 전 (킷 스키닝) | 후 (구운 스프라이트) |
|---|---|---|
| 드로우콜 | 140 (한 기 하나) + 장비 3 | **3** (병종당 하나) |
| 스키닝 | CPU, 140 기 | **0** |
| 외곽선 | 없음 | 구워짐 (공짜) |
| 병종 구분 | 색 | 정수리 모양·색 + 무기 실루엣 |

- **`Blob` 의 삼각형 감기가 뒤집혀 있었다.** 겉면이 뒷면으로 잡혀 카메라 쪽이 잘리고
  반대편 안쪽이 보였다 — 수풀이 검고 바위가 흰 우산처럼 보이던 뿌리이고, 외곽선 껍질을
  두르니 통째로 검게 구워져 드러났다. 공용 패키지에서 고쳤다
- 굽는 장면에도 `Skin.Dress()` 가 필요하다 — 안 걸면 흰 기본 텍스처를 법선맵으로 읽는다
- 사각형은 **카메라 평면**에 세우고 굽는 카메라가 본 점(발에서 0.62 h)을 가운데로 둔다.
  직교라 화면 자리가 그대로 맞는다. 카메라 쪽으로 0.7 h 당겨 발이 땅에 안 묻히게
- 아틀라스 배치(`SpriteSheet`)는 굽는 쪽과 그리는 쪽이 **같은 상수**를 본다

`CrowdGate` 를 스프라이트 기준으로 다시 짰다: 사각형 ≥130 · 병종 메시 3 · 아틀라스 192 칸 다
참 · 병종 평균색(밝은 픽셀만) 차 ≥24 · **카메라 90° 회전 → 88/88 기 방향 칸 두 칸 이동** ·

### 바위·창 손·적 시안 개정 (2026-09-13)

**바위 — 능력에서 물건으로.** 비탈 위 아무 데서나 「밀기」를 쓰면 바위가 생기고 차수마다
다시 채워지던 것을, **판이 시작될 때 산마다 세 덩이가 놓이는** 것으로 바꿨다. 놓는 자리는

놓인 자리의 내리막**이다(지적: 「이상한 데로 굴러간다」). 쓴 덩이는 사라진다 —
**스테이지당 한정 자원**이라 차수마다 안 생긴다(`Spec.RocksPerHill = 3`).

| BattleGate | 산에 바위 6 덩이 · 길에서 7.2 유닛 · 굴린 덩이는 사라진다(5/6) · 12 기를 쓸었다 |
|---|---|

**창이 손을 따라간다.** 장비를 몸 원점에 고정하니 팔은 흔들리는데 창만 떠 있었다.
킷 리그(`RightHand`·`LeftHand`·`Head`)의 뼈 자리를 프레임마다 읽어 그 자리에 그린다.
주인공은 깃을 `Head`, 창을 `RightHand` 의 자식으로 달았다.

게이트를 짜며 **두 번 자기 근거를 쟀다**: ① 「가장 가까운 정점」으로 재니 막대는 양끝에만
정점이 있어 손 안을 지나가도 0.95 유닛 — 선분 거리로 고침 ② 정지 자세 한 번만 재니 몸
원점에 고정한 창도 손 근처(0.19)라 통과 — **걷는 두 시점의 최댓값**으로 고침. 회귀 주입
(몸 원점)에서 0.59 유닛 벌어져 빨간불을 확인했다.

**적 병종은 코드가 아니라 시안으로.** 「코드로 만들지 말고 디자인으로 받아서 하라」는 지시대로
클로드 디자인 캔버스에 기병·궁수·방패병의 정면·측면·위 세 방향과 팔레트를 올렸다
(`claude.ai/code/artifact/c26ccc60-…`, 볼트 사본 `1989v/claude/artifact/jeonran-invaders`).
가르는 기준은 정수리 모양(뿔·챙·원반) · 정수리 색(강철·가죽·검은 철) · 몸 밖으로 나온 것
(창·활·방패) 셋이고, 판정은 시안의 **20px 줄**에서 한다. 사용자 확인 뒤 구현한다.

### 능선·화살 개정 (2026-09-12 여섯 번째)

**바위 능선을 둥근 등성이로.** 납작한 마루에 수직 벽 둘이면 위에서 볼 때 두께 없는
판자로 읽힌다. 단면을 여덟 토막으로 나눠 사인 곡선으로 부풀리고, 법선을 단면 기울기에서
뽑아 정점마다 실어 마디 경계의 밝기 단을 없앴다. 마루에는 네 마디에 하나꼴로 돌을 얹는다.

- **`Mathf.Pow(Mathf.Sin(t * π), 0.55f)` 에 `Max(0)` 이 없으면 NaN 이 난다.**
  t=1 에서 sin(π) 가 −8.7e−8 이라 음수의 거듭제곱이 되고, **유니티는 NaN 정점이 하나라도
  있으면 메시를 통째로 버린다** — 정점 2016 을 넣었는데 메시는 0 이었고, 화면에서는
  「능선이 없다」로만 드러났다. 넣은 정점 수와 메시의 정점 수를 나란히 찍어 두었다
- 능선도 **그린 목록이 곧 막는 목록**이다(`Field.RidgeSolids`). `WallGate` 가 마디 63 곳 중
  셋에 하나씩, 네 방향에서 밀어 71 번 검사한다

**화살이 병사보다 길었다.** `FootHeight × 1.5` 는 주인공 키의 1.3 배(4.2 유닛)라 화면에서
흰 발광 막대가 무리 옆에 누워 있었다. 0.52 배로 줄였더니 9.1px 으로 게이트의 읽힘 하한
10px 에 못 미쳐, **0.72 배(12.6px · 주인공 키의 0.47 배)** 로 정했다.

### 적 실루엣·갈림길 개정 (2026-09-12 다섯 번째)

**「그냥 빨간색 캐릭터」의 정체 — 부각 60° 에서 보이는 것은 정수리뿐이다.**
한 기는 화면 20px 이고 그 안에서 읽히는 것은 머리 공과 어깨선이다. 킷 모델만으로는
세 병종이 「빨간 몸에 둥근 공」으로 똑같이 읽힌다.

장비를 **메시 한 장**에 몰아 그린다(`Gear`) — 발밑 표식과 같은 방법이라 병종당 드로우콜 1.

| 병종 | 얹는 것 |
|---|---|
| 기병 | 투구 덮개 + 붉은 마루 + **곧게 세운 창**(1.05 H) |
| 궁수 | 투구 덮개 + 금빛 마루 + 세워 든 각궁 + 전통 |
| 방패병 | 투구 덮개 + 쇠 마루 + **눕혀 든 둥근 방패**(면이 카메라를 보게) |

- **창은 곧게 세운다.** 비스듬히 누이면 위에서 볼 때 몸에 겹쳐 안 보인다.
  무리 위로 솟은 창 끝이 줄지어야 「행렬」이 아니라 「군대」로 읽힌다
- **방패는 눕혀 든다.** 곧게 세우면 부각 60° 에서 얇은 띠로만 남는다
- 창 각도는 자리 해시로 흔든다 — 전부 같으면 기계로 심은 것처럼 보인다

**두 번 물린 함정.**

| | 증상 | 원인 |
|---|---|---|
| 붉은 삼각형 더미 | 무리 전체가 깨진 판으로 | 궁수가 10 판을 그리는데 8 판만 잡아 다음 기 자리를 침범 |
| 형광 노란 판 | 창·방패가 스스로 빛남 | **정점 색의 알파가 자체발광**이다 — `Pal.Wood * 1.15f` 가 알파까지 1.15 로 만든다 |

둘 다 `CrowdGate` 에 넣었다: 병종 수만큼 장비 메시가 삼각형을 내놓는가 · 장비 정점의
알파가 전부 0 인가. 알파 강제를 빼 **480 개 빨간불**을 확인한 뒤 켰다.

**갈림길.** 리본 두 장이 V 로 만나 종이 두 장이 엇갈린 꼴이었다. 실제 갈림길도 만나는
자리가 부푼다 — 원판 두 겹으로 그 부풀음을 만들고, 가지는 끝 6 유닛에서 폭을 0.38 배로
좁혀 들어간다. 제 폭 그대로 끊으면 갓길이 본줄기를 가로질러 각진 단이 남는다.

### 산비탈·뚫림·축척 개정 (2026-09-12 네 번째)

**고지대를 평평한 대지에서 산비탈로 바꿨다.** 공용 패키지의 사각 대지(벼랑 + 오르막 하나)를
쓰다 접었다 — 화면에서 「흰 테 두른 팔각 접시」로 읽혔고, 비탈이 없어 바위가 길을 가로질러
스치고 나갔다(게이트 실측: 130기 중 2기만 쓸었다).

| | 전 (대지) | 후 (산비탈) |
|---|---|---|
| 모양 | 팔각 + 벼랑 + 오르막 1개 | 매끄러운 높이 함수 하나 (`Mound`) |
| 막는 것 | 둘레에 원판 여러 개 | **없음** — 어디로든 걸어 오른다 |
| 바위 | 가장자리에서만, 한 방향 | 어느 비탈에서든 아래로 |
| 치수 | 반경 6·7 · 높이 4.2·4.8 | 반경 10·12 · 높이 7.0·8.2 |

- **옆모습은 3t²−2t³ 다.** 지수형(t^1.35)으로 두면 꼭대기가 제일 가팔라 거꾸로 된 고깔이 된다
- **바위와 잔디를 면마다 갈라 칠하지 않는다** — 나눠 칠했더니 산이 회색·초록 조각보가 되고
  둘레를 흔들어 둔 탓에 소용돌이 무늬까지 생겼다. 풀로 덮고 바위는 노두로만 드러낸다
- **지형은 정점마다 법선을 싣는다**(`KgdMesh.FaceSmooth`). 면 법선 하나면 격자 칸마다 밝기가
  끊겨 동심원 띠가 보인다
- 색을 면 법선으로 고르면 꼭대기의 퇴화 사각형에서 법선이 0 이 되어 **정수리에 검은 원**이 찍힌다

**「벽을 뚫고 들어간다」의 정체 — 마을·주둔지에 막는 것이 하나도 없었다.**

새 게이트 `WallGate` 가 그리는 쪽이 내놓은 목록(`Dressing.Solids`)을 받아 사방에서 몸을
밀어 넣는다. 회귀를 주입해 빨간불을 확인했다.

| | 결과 |
|---|---|
| 처음 (막는 것 없음) | 240 번 중 **240 번 통과** |
| 막는 높이 = 벽 높이 | 215 번 중 49 번 통과 — **지붕을 밟고 넘어간다**(높이 1.89 < 오름턱 2.59) |
| 막는 높이 = 실루엣 높이 | **0 번** |
| 회귀 주입(등록 한 줄 삭제) | 238 번 중 238 번 — 게이트가 실제로 문다 |

- **보이는 것과 막는 것을 한 목록에서 낸다.** 따로 적으면 생김새를 고칠 때 한쪽만 바뀐다
- 게이트가 **끝난 자리**로 재면 뚫고 지나간 몸이 반대편에 서서 「안에 없음」이 된다 —
  지나가는 동안 **가장 가까웠던 거리**를 본다. 처음 짠 것이 그 모양으로 초록불을 냈다
- 출발점이 다른 구조물 **위**면 셈에서 뺀다 — 몸높이가 올라가면 오름턱 기준도 같이 올라간다

**축척 — 참조작보다 더 멀리 (1/30.9 → 1/36).** 「캐릭터가 커 보인다」가 다섯 번 나왔다.
참조작 실측이 1/30.9 였으므로 이건 벤치마크 초과 요구다 — 벤치마크는 하한선이지 상한이 아니다.
주인공 키를 월드에서 고정한 채 줌만 1.165 배로 넓혔다(`Zooms` 55.9·76.3·110.7).
`ScaleGate` 의 읽힘 하한을 24 → 22 px 로 내렸고, **그 예외가 사 주지 않는 것**을 함께 적었다:
이 크기에서 자세·장비는 못 읽는다. 발밑 고리·깃·창이 필수이고 줌 0 단이 가까이 보기를 받는다.

**나무를 실측에 맞췄다.** 참조작 화면에서 주인공 120px, 수관 47×75px —
수관 폭이 주인공 키의 **0.38 배**다. 우리 것은 1.27 배라 나무 한 그루가 주인공보다 컸고
위에서 보면 짙은 바위 덩이로 읽혔다. 색도 노란 초록이 아니라 **짙은 청록 rgb(7,82,67)** 에
올리브색 햇빛 자국이다.

### 병종 — 무엇으로 갈리나

킷 캐릭터 모델은 **하나뿐이다.** 그래서 병종은 **키·몸통 폭·색·걸음 속도** 넷으로 가른다.
실루엣만 다르고 안 움직이는 정적 메시 여러 벌보다 이쪽이 낫다는 것은 궁수 키우기에서
이미 확인했다.

| 병종 | 키 | 몸통 폭 | 색 | 걸음 | 읽히는 것 |
|---|---|---|---|---|---|
| 기병 | 1.00 | 0.95 | 붉은 갑주 | **1.25배** | 앞장서 밀고 들어온다 |
| 궁수 | 0.92 | 0.88 | 어두운 자주 | 1.00배 | 작고 가벼워 뒤에 붙는다 |
| 방패병 | **1.12** | **1.24** | 강철 | **0.76배** | 크고 느려 행렬을 막아 세운다 |

속도가 갈리면 행렬이 **성채로 갈수록 뭉친다** — 빠른 기병이 느린 방패병 뒤에 밀리고,
「추월하지 못한다」와 맞물려 앞쪽에 덩어리가 생긴다. 그것이 바위 한 번에 12기가 쓸리는 자리다.

> 실측: 걸음 차이만으로는 행군 **중간**에 덩어리가 거의 안 생긴다(첫 도착 무렵에야 몇 기).
> 기병이 68%라 같은 줄 앞이 대개 같은 기병이어서다. 중간 정체를 원하면 걸음 차이가 아니라
> **길 굽이·좁은 목** 같은 지형이 만들어야 한다 — 후속 과제.

**병종은 구성 비율대로 고르게 섞어 내보낸다.** 「남은 수가 많은 쪽부터」로 짜면 88/28/14 가
「앞의 64기는 전부 기병」으로 나와(실측) 초반 판이 통째로 한 병종 상대가 된다.

> **기병은 아직 탈것이 없다.** 킷에 말 모델이 없어서 지금은 「빠르고 마른 보병」으로 읽힌다.
> 탈것은 별도 에셋이고, 붙기 전까지 이 표의 속도·폭이 그 자리를 대신한다.

| 성문 체력 | **1,000** | 웨이브 하나를 다 놓치면 무너지되, 두세 기가 새는 것으로는 안 무너진다 |
| 성문 피해 | 문 앞에 닿은 적 **한 기당 초당 6** | 마릿수가 그대로 시계가 된다 |
| 기병 체력 | 12 | 영웅 두 발 |
| 궁수 체력 | 8 | 한 발 |
| 방패병 체력 | 34 | 여섯 발 — 이름값을 체력으로 낸다 |
| 영웅 사거리 | **18 유닛** | 화면 짧은 변(22)의 8할. 서 있는 자리가 곧 지키는 자리다 |
| 영웅 발사 간격 | 0.55초 | |
| 영웅 한 발 | 피해 7 · **2기 관통** | 저격형이라 한 발이 무겁고 줄을 꿰뚫는다 |
| 처치 보상 | 기병 3 · 궁수 4 · 방패병 9 냥 | |

- **자동 공격이다.** 사거리 안에서 성문에 가장 가까운 것을 먼저 쏜다 — 위험한 순서와 같다
- **적은 영웅을 때리지 않는다.** 이 게임에서 죽는 것은 성문이지 영웅이 아니다.
  영웅이 죽으면 조작 대상이 사라져 판이 멈추고, 그건 수성전이 아니라 액션 게임의 실패 규칙이다
- 웨이브를 다 지우면 다음 웨이브가 온다. 성문이 0 이 되면 진다

## 5. 고지대 기믹 — 이번 전환의 이유 중 하나

**고지대에서 바위를 굴려 행렬을 쓸어버린다.**

| 항목 | 값 |
|---|---|
| 발동 | 고지대 가장자리의 바위를 영웅이 밀거나, 슬롯 건물(투석대)이 민다 |
| 굴러가는 것 | 반지름 **1.6 유닛**, 경사를 따라 가속 |
| 피해 | 닿은 적 즉사(방패병은 2회), 최대 **12기** 관통 |
| 실측 | 가장 두꺼운 차수(130기)에 한 번 굴려 **6기** — 상한 12 는 잘 맞았을 때다 |
| 길이 홈통이다 | 길에 들면 **길 방향으로 돌아선다.** 가로질러 스치고 나가면 한 줄만 맞는다(실측 1기) |
| 재사용 | 웨이브마다 고지대당 **1회** |
| 보스 | 같은 기믹을 반대로 쓴다 — **술통을 길로 굴려 내려보낸다** |

지형이 장식이 아니라 규칙에 들어가는 자리다.

## 7. 조작

| | 가로 (우선) | 세로 |
|---|---|---|
| 이동 | **바닥을 탭하면 그 자리로 걸어간다** | 같음 |
| 공격 | 자동 (사거리 안) | 같음 |
| 스킬 | 오른쪽 아래 버튼 2 | 같음 |
| 배치 | 슬롯을 탭 → 목록에서 고름 | 같음 |
| 줌 | 핀치 + 버튼 | 같음 |

- **가상 스틱을 쓰지 않는다** (`data-stick="off"`). 참조작 실측 화면에 스틱이 없고,
  세로에서 스틱은 하단 28%를 가져간다 — 수성전은 그 띠에 성문이 들어오는 화면이다
- 탭한 자리는 **표식으로 보여 준다.** 안 보이면 눌렸는지 모르고 계속 누르게 된다
- 데스크톱은 클릭과 방향키를 **둘 다** 받는다 — 키보드를 빼면 데스크톱이 불편해진다
- 터치 타깃 **≥44 CSS px**, 조작 대상 ≥28, 라벨 ≥11
- 유니티는 `data-fit="0"` 이라 **템플릿이 하단 띠를 직접 계산**한다 (비율 0.28)
- `EventSystem` + `StandaloneInputModule` 을 HUD 와 **같이** 세운다. 없으면 버튼이 조용히 안 먹는다

## 8. 완성 판정 — 이 표를 다 채워야 슬라이스가 끝난다

| 게이트 | 판정 |
|---|---|
| 화면 축척 | 1장 세 수치를 스크린샷 픽셀로 실측, 기준 대비 ±8% |
| 모바일 두 방향 | 가로 844×390 · 세로 390×844 실측 + 스크린샷 |
| 웨이브 | 7웨이브 완주. 마지막 동시 생존 **≥130** 확인 |
| 성능 | 삼각형·전송량·첫 화면 실측값을 6장 표와 나란히 |
| 조명 | 지형에 그림자가 떨어지는가. 태양 방위 ↔ 시작 시야 내적 **양수** |
| 팔레트 연동 | 소스에 하드코딩 hex 리터럴 **0건** |
| 콘솔 | 에러 0 |
| 구조물 관통 | `WallGate` — 그린 목록(마을·주둔지·능선)을 받아 사방에서 밀어 넣어 0 건 |
| 영웅 스킬 | `SkillGate` — 로스터의 모든 영웅: 돌격·철벽이 문 앞 덩어리를 절반 이하로, 화살비 4 기 이상, 보수가 성문을 채운다 |
| 게이트 자체 | **회귀를 주입해 빨간불을 본 뒤에만** 켰다고 한다 |
| 벤치마크 일치도 | 깨끗한 서브에이전트가 소스와 `_ref/` 를 보고 판정 |
