# 검색 분석기 품사 필터 — `_analyze` 확인 (SR-2)

2026-10-11. 로컬 컨테이너 `opensearch-nori:3.8.0`(운영과 같은 이미지 태그)에 **레포의 `attractions-index.json` 그대로** 색인을 만들고 `_analyze` 로 잰 값이다. 운영 색인에서 잰 값이 아니다.

| 입력 | `nori_search`(품사 필터 + 동의어) | `nori_analyzer`(색인, 변경 없음) |
|---|---|---|
| 아이랑 갈 만한 곳 | 아이·가·만·하·곳 | 아이·랑·가·ᆯ·만·하·ᆫ·곳 |
| 아이와 갈만한 곳 | 아이·갈만·하·곳 | 아이·와·갈만·하·ᆫ·곳 |
| 와우정사 | 와우·정사 | 와우·정사 |
| 의성 마늘 | 의성·마늘 | 의성·마늘 |
| 이랑 카페 | 이랑·카페 | 이랑·카페 |
| 하와이안 워터파크 | 하와이안·워터·파크 | 하와이안·워터·파크 |
| 과천과학관 | 과천·학관 | 과천·과·학관 |
| 서울 궁궐 | 서울·궁궐·고궁·왕궁·경복·창덕·덕수·창경·경희·궁×5 | 서울·궁궐 |
| 반려견과 함께 | 반려·견과·함께 | 반려·견과·함께 |

- SR-2.2 의 예시와 같다(「아이랑」의 `랑`·`ᆯ`·`ᆫ` 이 빠지고, 「와우정사」「의성 마늘」「이랑 카페」「하와이안 워터파크」는 그대로, 「과천과학관」은 `과` 만 빠짐).
- 묶음 태그는 실제로 거부된다: `stoptags: ["J"]` → 400 `No enum constant org.apache.lucene.analysis.ko.POS.Tag.J`.
- 「서울 궁궐」은 조사·어미 토큰이 없어 품사 필터 전후의 질의 토큰이 같다. 그래서 msm `_count` 도 전후가 같다. **운영 절대값(msm `2<75%` `_count`)은 아직 재지 않았다** — 운영 읽기(`ssh msa-oci`)가 필요해 TG6.0 에 넘긴다. 동의어 그래프가 토큰 수를 늘리므로(`궁궐` → 9개 이상) msm 이 이 질의에서 어떻게 계산되는지는 그 측정이 확인해야 한다.
- 「반려견과」→`반려·견과` 분절 오류는 그대로다(Out of Scope, Q7).

## msm `2<75%` 이 실제로 무엇을 거르는지 — 로컬 문서 몇 건으로 본 모양

같은 컨테이너·같은 색인 정의에 손으로 넣은 문서 몇 건이다. 건수는 운영과 무관하고, **질의 모양만** 본다. 필드는 어댑터의 `KEYWORD_FIELDS` 와 같고 `multi_match` 기본형(`best_fields`)이다.

| 질의 | msm 없음(OR) | msm `2<75%` |
|---|---|---|
| 에펠탑 (문서: 충렬탑) | 1 · 충렬탑 | 0 |
| 아이랑 갈 만한 (문서: 아이랑 캠핑장) | 1 | 0 |
| 아이랑 | 1 | 1 |
| 서울 궁궐 (문서: 경복궁 · 주소 서울특별시 종로구) | 2 | **0** |
| 서울 경복궁 (같은 문서) | — | 1 |
| 궁궐 (같은 문서) | — | 1 |

- **msm 은 필드마다 따로 센다(`best_fields`).** 「서울 궁궐」은 두 덩어리(`서울` · 동의어 그래프 `궁궐`)라 「토큰 2개 이하는 전부」에 걸린다. 경복궁 문서는 `서울` 이 주소에만, `궁궐`(동의어 경복) 이 제목에만 있어 한 필드에서 둘을 다 맞추지 못한다. 그래서 0건이다.
- 「서울 경복궁」은 제목 필드 안에서 `경복`·`궁` 두 토큰이 맞아 3토큰 중 2(75% 내림)를 채운다.
- 뜻: GATE 에서 「지역 + 분류어」처럼 **두 말이 다른 필드에만 있는 질의**는 근거 0 으로 결과가 사라질 수 있다. 「서울 궁궐」이 근사 측정의 손실 상위(.73→.09)였던 이유와 같은 모양이다. 단계 2 판정(TG6.5) 전에 운영에서 확인해야 한다 — 열린 질문으로 올렸다.
