# 그림 로직 (pixel-logic) — 설계

> 클린룸 11호 · 장르 프리셋 `picture-logic` 의 첫 산출물
> 파이프라인: `docs/standards/game-cleanroom-pipeline.md`

## 1. 무엇을 만드는가

가로세로에 붙은 숫자 힌트만 보고 칸을 칠하면 **그림이 드러나는** 논리 퍼즐.
숫자는 그 줄에 연속으로 칠해진 칸의 길이다.

이 장르는 두 가지가 동시에 성립해야만 성립한다. 하나만 빠져도 장르가 무너진다.

| 조건 | 안 지키면 |
|---|---|
| ① 완성 그림이 **알아볼 수 있는 그림**일 것 | 다 풀어도 아무것도 아니라 푸는 보람이 사라진다 |
| ② **추측 없이 논리만으로** 유일해가 나올 것 | 퍼즐이 아니라 복권이 된다 |

나머지 설계는 전부 이 둘을 지키기 위한 장치다.

## 2. ① 완성 그림 — 손으로 찍지 않고 굽는다

### 실패한 1차본

처음에는 격자에 직접 `#` 을 타이핑했다(10×10 / 15×15 고정). 결과는 사용자 반려:

> "난이도가 너무 쉬워보임. 차라리 이미지 하나 픽셀화해서 그거 기준으로."

실제로 **연필이 종, 꽃이 돋보기, 나비가 네모**로 읽혔다. 손으로 찍으면 어떤 크기에서도
계단 덩어리가 되고, 가는 부분(자루·꽃잎·돛대)을 그릴 칸이 없어 전부 뭉갠 채로 남는다.

### 채택한 방식 — 벡터 실루엣 → 판 크기에 맞춰 픽셀화

- `js/shapes.js` — 그림 24종을 **도형 대수**로 갖고 있다.
  `['e' 타원 | 'r' (둥근)사각 | 'p' 다각형 | 'l' 굵은 선분 | 'star']`, 앞에 `-` 를 붙이면 빼기.
  순서대로 칠하고 지우므로 **순서가 곧 결과**다. 좌표는 `box: [가로, 세로]` 안의 실수, 중심 기준.
- `js/raster.js` — 칸마다 4×4 로 훑어 **덮인 비율**이 기준을 넘으면 칠한 칸.
  사진을 줄여 픽셀아트로 만드는 것과 같은 방식이라 계단 덩어리가 생기지 않고,
  **한 번 그려 두면 12×18 에서도 25×25 에서도 형태가 유지된다.**

### 굵기 하한 — 실측으로 얻은 두 개의 수치

| 실패 | 원인 | 규칙 |
|---|---|---|
| 튤립 줄기가 통째로 사라짐 | 획 0.035 → 15칸에서 **0.4칸** | 상자 긴 변 기준 **0.09 미만 획 금지**. 자루·손잡이·돛대·팔은 **0.10~0.15** |
| 나비가 해골로 읽힘 | 날개와 몸통이 붙어 최소 판에서 한 칸도 안 벌어짐 | 붙은 두 부분 사이에 **빈 줄 한 칸(≥0.09)** 을 강제로 파고 그 안에 몸통을 다시 그린다 |

같은 이유로 고쳐야 했던 것들: 모자와 머리가 같은 폭이라 통짜가 된 눈사람(모자를 좁히고
챙을 두껍게), 돛대와 돛이 붙어 산으로 읽힌 돛단배(사이를 한 칸 띄움), 밑동이 작아
풍선으로 읽힌 전구, 반점이 갓 가장자리를 갉아먹어 깨져 보인 버섯(반점을 갓 안쪽으로).

### 건강 검사

`Raster.healthy()` 는 **격자 전체가 아니라 그림이 실제로 놓인 상자** 기준으로 밀도를 잰다.
전체 기준으로 재면 연필·로켓처럼 좁은 그림이 부당하게 걸린다(밀도 0.18~0.20).

## 3. ② 유일해 — 줄 단위 논리로 전부 확정되는지

`js/solver.js` 는 **백트래킹을 쓰지 않는다.** 한 줄씩 "힌트가 허용하는 모든 배치의 교집합"만
반복해서 확정한다. 이 방식으로 전부 확정되면 **사람이 논리만으로 풀 수 있다**는 뜻이다.
해가 하나뿐임을 백트래킹으로 증명하는 것으로는 부족하다 — 찍어야 도달하는 답은 답이 아니다.

- 매번 전 줄을 다시 좁히면 25×25 에서 초 단위로 늘어난다 → **바뀐 줄만** 다시 본다(dirty 큐).
- 이미 전부 정해진 줄은 배치 열거를 건너뛴다.

### 안 풀리면 그림을 버리지 않고 다시 굽는다

같은 그림도 굵기가 반 칸 달라지면 힌트가 통째로 달라져 풀림/안 풀림이 갈린다.
`js/boards.js` 는 굵기 후보 7개(0.50 → 0.42 → 0.58 → …)를 순서대로 시도한다.
0.50 이 원본에 가장 충실하므로 늘 먼저 본다.

**실측: 24그림 × 5티어 = 120조합 전부 통과** (전수 검사 78ms). 판 하나 생성은 1ms 미만이라
스테이지 시작 시점에 즉석에서 만들어도 끊김이 없다.

> **대각선 띠는 피한다.** 굵기를 바꿔도 통째로 밀 수 있어 유일해가 안 나온다 —
> 연필을 대각선으로 눕혔을 때 미확정 100칸이 남았다. 세로로 세워 해결했다.

## 4. 그림을 미리 보여주지 않는다

사용자 지시: *"도감은 안 보여줘야지, 다 완성하면 도감을 채우게. 그 전에는 물음표로만."*

- 도감의 잠긴 칸은 **물음표만**. 흐린 실루엣이라도 내보이면 그 판의 답이 새어 나가고,
  "완성해야 볼 수 있다"는 이 장르의 유일한 보상이 사라진다.
- **타이틀 데모도 수집 대상 그림을 쓰지 않는다.** 데모 전용 마름모 도형을 따로 뒀다.

## 5. 난이도 = 판 크기

정보를 숨기거나 시간을 줄이는 게 아니라 **칸 수**로 조절한다.

| 난이도 | 시작 티어 | 실수 허용 | 점수 배율 |
|---|---|---|---|
| 보통 | 15×15 | 3 | ×1.0 |
| 어려움 | 20×20 | 3 | ×1.7 |
| 전문가 | 25×25 | 2 | ×2.6 |

두 판마다 한 티어씩 커진다. 티어마다 정사각 + 가로형 + 세로형 격자를 두고,
**그림 비율에 가장 가까운 격자**를 고른다 — 억지로 정사각에 넣으면 형태가 눌린다.

```
T0  15×15 · 18×12 · 12×18
T1  18×18 · 22×14 · 14×22
T2  20×20 · 25×16 · 16×25
T3  22×22 · 25×20 · 20×25
T4  25×25
```

**1스테이지부터 제대로 된 크기다.** 5×5 튜토리얼 판을 두면 처음 몇 분이 지루하다
(파이프라인 §0 공통 원칙). 조작은 두세 칸 칠하면 저절로 익는다.

## 6. 실수와 되돌리기

- **틀린 칸은 즉시 알려준다.** 안 알려주면 어디서 틀렸는지 못 찾아 판을 통째로 버려야 한다.
- 틀린 칸은 **엑스로 확정해 남긴다** — 그 칸이 빈칸이라는 정보는 이미 준 셈이다.
- **맞게 칠한 칸도 지울 수 있다.** 되돌릴 수 없으면 실험을 못 한다.
- 칠한 칸은 엑스로 덮지 않는다(오조작 방지).

## 7. 화면·조작 실측치

| 항목 | 값 |
|---|---|
| 캔버스 | 1080×1440 세로 |
| 칸 크기 | 15×15 → 62 캔버스px (28.7 CSS px @ 500px 폭) · 25×25 → 37.5 캔버스px |
| 힌트 | 격자를 가리지 않도록 **힌트 폭을 먼저 확보**하고 남는 공간을 칸이 나눈다. 25×25 최대 힌트 개수 5 |
| 다 센 줄 | 힌트를 흐리게 — 같은 줄을 두 번 세지 않게 |
| 칠한 칸 대비 | `#4E5794` / 빈 칸 `#171A2B` — 어두운 채움은 가독성이 곧 난이도가 된다 |
| 드래그 칠하기 | 시작 칸의 상태가 이번 드래그의 모드를 정한다(칠하다 지우는 사고 방지) |
| 도구 버튼 | 268×96 캔버스px = **124.1 × 44.4 CSS px** (터치 타깃 44px 상회) |
| 5칸 밴딩 | 격자 배경 + 굵은 선 양쪽 |
| 스테이지 배너 | **판 위가 아니라 HUD 아래 띠** — 가운데에 띄우면 힌트와 격자를 가린다 |
| 완성 연출 | 전용 상자에 맞춰 다시 잰다 — 판 격자 크기를 그대로 쓰면 세로로 긴 그림이 넘쳐 이름이 잘린다 |

## 8. 검증

| 항목 | 결과 |
|---|---|
| 논리 검사 전수 | 24그림 × 5티어 = **120조합 중 120 통과** (78ms) |
| 죽은 입력 감사 | 5씬 × 19키 = **95칸 전수 통과** (모든 키가 씬 전환·상태 변화·소리 중 하나를 낸다) |
| 콘솔 | 게임 유래 오류 0 (플랫폼 save API 404 는 로컬 정적 서버라 정상) |
| fps | 119~120 |
| 봇 완주 | 정답대로 실제 `apply()` 를 호출해 스테이지 연속 클리어 확인 |
| 모바일 | 414×896 터치 에뮬레이션 — 난이도 선택 → 시작 → 드래그 칠하기 → 도구 전환 전부 확인 |

## 9. 파일

```
portal-fe/public/games/pixel-logic/
  index.html      OG/트위터 카드 포함 (og:url·canonical 은 포털 상세를 가리킨다)
  CREDITS.md      외부 에셋 0 · 상표/저작권 근거
  js/shapes.js    실루엣 24종 (도형 좌표)
  js/raster.js    픽셀화 + 건강 검사
  js/solver.js    줄 단위 논리 솔버 (dirty 큐)
  js/boards.js    티어·격자 선택 + 굵기 재시도 + 캐시 + 도감 썸네일
  js/game.js      난이도·스테이지·판정·점수·완성 연출
  js/art.js       격자/힌트/잠긴 칸/완성 그림 렌더
  js/meta.js      도감·최고점·난이도 저장 (localStorage)
  js/audio.js     WebAudio 합성
  js/fx.js        화면 흔들림/플래시
  js/main.js      씬·입력·타이틀/도감/결과 UI
```

## 10. 저작권

`CREDITS.md` 참조. 요약: 그림 24종은 사진·아이콘 팩·이모지 글리프를 축소한 것이 **아니라**
`shapes.js` 안에 좌표로 직접 정의한 자체 도형이다. 이모지나 상용 아이콘 폰트의 글리프를
1비트로 줄인 실루엣도 원본의 2차적저작물이 될 수 있어 쓰지 않았다.
제목은 한국에서 일반명사로 통용되는 "그림 로직" 이고, 이 장르의 타사 상표는 쓰지 않는다.
