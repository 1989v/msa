# Woodland Haven 공유 월드 — 첫 수직 구현

사용자 승인: “진행해 우선은 공유 월드가 맞아”. 기존 픽셀 표현을 유지하며 서버가 지속하는 협동 월드를 구현한다. ADR-0104를 따른다.

## 수용 기준
1. 전용 로컬 서버 실행 명령 하나로 게임과 API를 제공한다. 최대8개의 온라인 플레이어가 같은 월드에 중도 참여하며 서로의 위치와 행동 결과를 본다.
2. 브라우저는 의도만 전송한다. 위치 순간 이동, 임의 자원/내구도/성장값 제출은 불가능하다. 서버가 이동속도·거리·충돌·쿨다운·비용을 판정한다.
3. 같은 자원 최종 채집/같은 자리 건축/같은 닭 포획은 한 번만 성공한다. 명령 ID 재전송은 비용이나 보상을 중복 적용하지 않는다.
4. 채집, 도구 제작·수리, 건축, 보관함, 식재·회수, 파종·물주기·병충해·수확, 닭 포획·배치·먹이·달걀을 기존 규칙으로 연결한다. 온라인에서 미연결 버튼이 로컬 상태를 조용히 변경하면 안 된다.
5. 공유 성장·재생·동물 이동은 접속자 수와 무관하게 서버에서 한 번 진행한다. 메뉴/탭 숨김은 공유 시간을 멈추지 않는다. 개인 가방·도구·체력·탐험 안개는 서로 독립한다. 월드의 건물/밭/닭장은 이 단계에서 공동 사용한다.
6. 재접속 및 서버 프로세스 재시작 후 공유 상태와 개인 경제 상태가 복원된다. 서버 오프라인 동안은 성장하지 않는다. 기존 싱글플레이 저장은 그대로 보존하며 온라인으로 자동 가져오지 않는다.
7. 경제 명령은 durable 저장 후 응답한다. 쓰기 실패·손상 기록·중복 서버 실행은 명시적으로 실패하며 기록을 지우지 않는다. 끊김 때 온라인 입력을 중지하고 연결 상태를 표시한다.
8. 로컬 전용 게스트 자격, 동일 origin 제한, 신원 위조 거부, 입력 검증, body/rate/접속 상한, 정적 경로 제한을 적용한다. 데이터·자격증명은 정적 파일로 노출하지 않는다.

## 검증
기존59개 회귀 유지. 별도 실제 HTTP 클라이언트 둘로 가입·입장·상태 전파·경합·중복요청·독립가방·재접속 검증. 서버 재시작·쓰기 실패·손상 파일·origin/인증/경로 검증. 공유 시계가 두 배로 흐르지 않는 모델 테스트. 관련 구문/타입/빌드 검증. 브라우저 조작은 새 승인 전 수행하지 않는다.

## 범위 밖
공개 배포, 계정 연동, 운영 DB 마이그레이션, PvP, 거래/약탈 권한, 운영용 다중 프로세스, 오프라인 성장. 이 범위를 완료했다고 주장하지 않는다.

## 구현 경계 및 재사용
model.mjs/life.mjs의 순수 규칙, art.mjs의 픽셀 표현, life-ui.mjs의 기존 생활 UI를 재사용한다. 기존 game 플랫폼 릴레이와 계정 API는 수정하지 않는다. 온라인 스냅샷은 자신의 가방·도구·탐험만 포함하고 다른 플레이어는 공개 위치·표현만 포함한다. 이끼 생물 전투는 협동 환경에서 서버가 판정하며 다른 플레이어 공격은 없다.

입력은 방향만 받고 서버 dt로 이동한다. 연결 끊김/입력 TTL 이후 정지한다. 경제 명령의 순번·결과 기록은 월드 변경과 함께 저장되어 재시작 후 재전송도 중복 지급하지 않는다. 저장은 성공 응답의 전제이며 오류 시 변경을 공개하지 않는다.

소유권: 자원 소진/재생, 건물/보관함, 식재/밭/닭장, 야생닭 포획 원본ID, 적 위치·체력·처치 상태는 공유한다. 가방·도구·허기·체력·귀환 캠프·발견·안개·유물 획득/귀환 목표는 개인별이다. 보물은 수호자 처치 후 각 플레이어당 한 번 지급한다. 서버 틱은 공유 성장과 개인 허기/회복/발견을 분리하며 적도 한 틱에 한 번만 이동한다. 개인 메뉴를 열어도 서버 허기/위험은 진행된다. 접속하지 않은 개인의 허기는 멈춘다. 성장/배치는 모든 접속자의 위치 및 저장된 귀환 캠프를 고려해 갇힘을 방지한다.

동일 게스트의 최신 명령 순번/결과를 영속화한다. 최신 재시도는 같은 결과, 더 오래된 순번은 거부하며 다시 실행하지 않는다. 저장 실패 시 메모리 월드·개인 상태·순번도 롤백한다. 서버 발급 게스트 최대64, 동시에 활동8명으로 제한하고 입력은250ms 후 만료한다. 제한 도달 시 기록을 삭제하는 대신 명시 오류를 낸다.

## 계약 상세
- 신원은 서버 발급 HttpOnly SameSite=Strict cookie로 식별하고 서버에는 해시만 저장한다. 요청 playerId로 신원을 선택하지 않는다. 토큰은 URL/로그/스냅샷에 포함하지 않는다. 유효하지 않은 자격은 거부하며 재접속/재시작에도 동일 개인을 복원한다.
- 명령 순번은 인증된 개인 범위다. 같은 순번·다른 payload는 충돌로 거부한다. 정상 형식으로 접수된 게임 규칙 실패도 결과와 순번을 저장하며, 인증/형식/잘못된 순번 실패는 소비하지 않는다. 저장 실패는 순번을 소비하지 않는다. 명령/틱은 직렬 처리하며 staged mutation→durable write→공개/SSE→응답 순서를 지킨다.
- 응답을 잃으면 새 행동을 막고 같은 자격으로 재연결한다. 권위 스냅샷을 받아 보류 명령의 원래 순번/payload로 결과를 확인한 뒤 다음 행동을 허용한다. 입력 보류를 저장하지 않고 새로고침한 경우 서버의 최신 순번으로 재동기화한다.
- 스냅샷에 단조 revision을 포함하고 클라이언트는 오래된 스냅샷을 무시한다. 관리 명령은 안정적인 target ID를 전송하며 서버가 최신 상태에서 조회한다. 다른 플레이어가 제거한 대상은 명시 오류로 처리하고 UI는 폐기된 객체를 변경하지 않는다.
- 이동/채집 쿨다운은 요청 횟수가 아닌 서버 단조 시간으로 판정한다. 다수 유효 요청도 이동/채집 속도를 늘리지 못한다. 접속 종료 개인은 피해/허기가 멈춘다. 요리·먹기·보관함·공격·보물·휴식도 서버 권위 명령으로 연결한다.
- `모든 저장 플레이어의 captive 합 + 공동 닭장의 마릿수 = capturedWildIds 수`를 저장/복원에서 검증한다. 새 bird ID는 월드 전체에서 유일하며 비접속 소유자의 포획 개체도 유지한다.

용어: 공유 월드는 공동으로 변경하는 지형 위 상태, 개인 상태는 게스트별 진행 기록, 명령은 서버 판정 전의 행동 의도, revision은 서버가 공개한 상태 순서다.
