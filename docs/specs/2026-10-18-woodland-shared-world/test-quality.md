# 수용 기준별 검증

| 기준 | 방법과 실패 시나리오 |
|---|---|
| 1 중도참여/전파 | 실제 임시 데이터 디렉터리 서버, 독립 쿠키2개, HTTP+SSE. 두 번째 입장과 위치/월드 변경 관측 |
| 2 권위 | 명령 모델 및 HTTP: NaN/Infinity/초과 방향/좌표·dt·자원 삽입, 과속/거리/쿨다운 위반 거부. input TTL 뒤 정지 |
| 3 경제 경합 | 두 클라이언트 같은 최종자원/건축위치/닭 경합, 최신 명령 재시도 및 과거 순번 거부. 재시작 뒤 재시도 동일 보상 |
| 4 생활 | 모든 허용 명령의 성공/실패 모델 검증, HTTP 경로를 통한 채집→제작→건축 및 식재/재배/사육 계약 연동. 브라우저 로컬변경 분기 없는지 리뷰 |
| 5 분리/시간 | 두 플레이어 공유 성장1회, 개인 가방·안개 미노출, 캠프·유물 소유권, 접속종료/메뉴 구별. 포획한 닭 보존을 전체 가방 합계로 검증 |
| 6 복원 | 실제 디스크에 저장한 서버를 완전히 종료/새 인스턴스로 재시작, 같은 자격으로 개인·공유 상태 복원. 기존59개 회귀 유지 |
| 7 실패 | 주입 가능한 저장 실패에서 메모리/순번/응답/SSE 누출 없음. 손상 파일 원문 보존. 같은 경로 서버 중복실행 거부. 연결 끊김 입력 중지 |
| 8 보안/자원 | 잘못된 자격·Origin/Host, body/rate/8활성/64기록 제한, 경로 traversal 및 서버/data 파일 다운로드 거부, 공개 플레이어에 가방/자격 미포함 |

검증 결과는 모델/실제 HTTP·SSE/브라우저 UI로 구분해 보고한다. 서버 재시작은 실제 저장 재로드를 검증하며 동일 메모리 객체 재사용으로 대신하지 않는다. 공개 운영 적합성이나 부하 상한을 이 테스트만으로 보장하지 않는다.
