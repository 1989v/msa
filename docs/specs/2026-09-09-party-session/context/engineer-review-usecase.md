## 판정: **REVISE**

기능의 뼈대와 사용자 맥락은 잘 잡혔다. 다만 **정상 경로 하나가 코드와 충돌해 30초 뒤 막히고**(U1),
**기존 비참여형 게임 3종 중 1종이 SR-6 의 방식으로는 같이 볼 수 없으며**(U2),
요구사항 두 줄이 옮겨지는 과정에서 빠졌다(U3). 셋 다 스펙 수정으로 해소되므로 BLOCK 이 아니다.
U1·U2 는 **태스크 분해 전에** 답이 있어야 한다 — 태스크 경계가 달라진다.

| 체크 항목 | 결과 |
|---|---|
| Actor-goal pairs clearly defined? | △ — 방장·참가자는 뚜렷하나 **관전자의 goal 이 없다**(U8) |
| Main/Alternative/Exception flows specified? | △ — main 은 있고 alternative·exception 이 화면 흐름에 없다(U9·U10) |
| Preconditions/Postconditions explicit? | △ — 시작 전제(SR-3.7)는 있고 **판 종료 후 상태**가 일부 미정(U4·U7) |
| AC traceable? | ✗ — Story↔SR 매핑 없음, 테스트 문서는 `R` 번호·스펙은 `SR` 번호(U12) |
| Edge cases systematically expanded? | △ — 실패 의미는 잘 적혔으나 **사용자에게 보이는 모습**이 빠짐(U4·U7·U9) |
| Test strategy mapping defined? | ○ — `planning/test-quality.md` T1~T22, 크리티컬 패스 지정까지 있음 |

## 3. User Stories — 기능 나열인가, 사용 맥락인가

**맥락이다.** 7개 전부가 "왜"를 달고 있고 그 "왜"가 현장 관찰이다 — 「한 화면에 여섯 명이 목을 빼지 않으려고」,
「한 기기를 돌려 가며 하면 순서가 유불리를 만드니까」, 「목소리 큰 사람이 정하는 게 싫으니까」,
「늦게 온 사람에게 벌칙 확률을 더 주는 식으로」. 모여 앉아 내기하는 자리의 말이다.

빠진 actor 는 셋:
- **관전자** — SR-4.6·SR-5.8 에 규칙만 있고 스토리가 없다. 왜 생기나(자리 초과? 늦게 옴? 구경만?)에 따라 화면이 달라진다.
- **진 사람 / 미제출자** — SR-7.6 최하위 처리가 자리에서 어떻게 받아들여지는지(폰 잠김? 자리 비움?)가 없다.
- **그룹을 만들지 않은 사람** — 처음 온 방장이 그룹 없이 바로 방을 열 수 있는지, 이름을 그 자리에서 치는 경로가 없다.

## 4. 화면 흐름 (Visual Design) — 빠진 경로 · 막다른 길

다이어그램의 main path 는 완결돼 있다. 아래가 빠졌다.

- **관전자 레인이 없다.** 「자리 픽」 괄호 안 한 줄뿐이고, 관전자가 로비·선정·판·결과에서 무엇을 보는지, 자리가 비면 참가자로 올라탈 수 있는지가 없다.
- **자리 픽 거절(SR-4.5) 후 복귀 화살표가 없다.** 「사유와 함께 거절」까지만 있다.
- **판 무효(SR-7.7) 후 복귀 지점이 없다.** 「다시 한다」의 주체(자동/방장 버튼)와 **반복 실패 시 탈출구**가 없다 — 채점기가 계속 실패하면 자리가 멈춘다.
- **`[랜덤]`(SR-5.3)은 되돌릴 수 없다.** 「방장 클릭 한 번으로 바로 시작」이라 확인 단계가 없다. 의도라면 그렇게 적어야 한다.
- **판 진행 중 입장자의 순서가 없다.** SR-6.5 는 「빨리 감아 따라붙는다」인데, 그 사람이 자리를 아직 안 골랐다면 자리 픽 화면이 먼저인가 빨리감기가 먼저인가.
- **판 중 이탈이 없다.** SR-1.5 는 방장 승계만 다룬다. 참여형 판 중 이탈자는 SR-7.6 미제출로 유추되지만 명시가 없다.
- **참가자 2명 미만(SR-3.7)이 화면에서 무엇으로 보이는지** 없다(비활성 버튼? 문구?).

## 5. 실패 경로가 사용자에게 무엇으로 보이는가

| 실패 | 스펙이 정한 것 | 사용자에게 보이는 것 |
|---|---|---|
| SR-7.6 미제출 최하위 | 「제한 시간이 지나면 마감」 | **시간 값이 없다**(OQ 에도 없음). 카운트다운 노출 여부 없음. **미제출 2명 이상일 때 순위 미정** → U7 |
| SR-7.7 판 무효 | 「무효로 하고 다시 한다」 | 무효 고지 · 재시작 주체 · 반복 실패 탈출구 전부 없음 |
| SR-4.5 자리 경합 거절 | 「사유와 함께 거절」 | 사유 문구도 복귀 경로도 없음 |
| SR-6.8 결과 해시 불일치 | 「방 전체에 경고가 뜬다」 | **어느 결과가 유효한지 없다** → U4 |
| SR-2.3 옵트인 끄기 | 「즉시 하드 삭제」 | 확인 절차·되돌릴 수 없다는 고지 없음. 그룹 전체가 한 번에 사라진다 |

## 이슈 목록

### U1 (최우선) — 릴레이 로비 30초 자동 마감이 파티 방을 잠근다

SR-1.4 는 「로비 30초 강제 마감은 파티 방에서 **쓰지 않는다**」고 정하지만, 릴레이는 그것을
**슬러그와 무관하게 2석 초과 방 전부에** 적용한다:

- `game/feature/src/main/kotlin/com/kgd/game/infrastructure/ws/GameRelayRegistry.kt:168-171`
  — `startDueLobbies` 의 필터는 `!it.legacy && !it.started && nowMs - it.createdMs >= LOBBY_MAX_WAIT_MS` 뿐이다. `gameSlug` 조건이 없다.
- 같은 파일 `:165-166` — `@Scheduled(fixedDelay = 1_000L) tickLobbies()` 가 1초마다 돈다.
- 같은 파일 `:230-233` — 시작된 다인 방은 잠긴다: `if (room.started && !room.legacy) send(peer, error("ROOM_STARTED"))`.

**결과**: 방장이 방을 열고 카톡에 링크를 붙여 넣는 데 30초가 넘으면 방이 자동 시작되고,
그 뒤 링크로 들어오는 사람은 전부 `ROOM_STARTED` 로 거절된다 — **사용자 원문 ②의 정상 경로가 통째로 막힌다.**
덤으로 `:264` 주석대로 빈 좌석은 호스트가 봇으로 채우므로, 내기 자리에 **봇이 벌칙 후보로 들어온다.**

이는 SR-1.1·「Existing Code」의 「`/ws/games/party` 가 **서버 변경 0**으로 열린다」와도 모순된다.
서버 변경은 최소 1건(파티 슬러그를 로비 자동 마감 대상에서 제외) 필요하다.

**제안**: SR-1.1 의 「서버 변경 0」을 내리고, SR-1.4 를 「릴레이에 파티 슬러그 예외를 넣는다(서버 변경 1건)」로 고쳐 태스크로 세운다. OQ-1(유휴 90초)과 같은 곳을 건드리므로 한 태스크로 묶인다.

### U2 (최우선) — `card-flip` 은 SR-6 의 결정적 재생으로 「같은 판」이 되지 않는다

`requirements.md` 온톨로지는 「비참여형 게임 = 다 같이 지켜보는 것, **조작이 없다**(구슬·사다리·카드)」로 정의한다.
`card-flip` 은 그 정의에 맞지 않는다:

- `portal-fe/public/games/card-flip/js/main.js:198-206` — 판 진행 중 `pointerdown` → `Art.hitTest(...)` → `tryFlip(i)`. 사람이 카드를 고른다.
- `game/CLAUDE.md:290` — 「엎어 놓은 카드를 **한 명씩 뒤집어** 정한다」, 「**재현은 배치를 정해 두는 것이지 결과를 정해 두는 게 아니다** — 어느 카드를 뽑느냐가 결과를 바꾼다」.

SR-6.2(시드 한 번 뿌리고 각 기기가 같은 판을 그린다)와 SR-6.4(진행 중 스냅샷을 보내지 않는다)로는
**누가 어느 카드를 뒤집었는지가 전달되지 않아** 기기마다 다른 판이 된다. SR-6.5 의 「빨리 감기」도
사람 입력을 기다리는 게임에는 의미가 없다.

(`ladder-draw`·`marble-race` 는 안전하다 — 결과는 시드가 정하고 판 중 조작은 카메라·배속·한 줄 먼저 보기처럼
그림만 바꾼다: `ladder-draw/js/main.js:190-212`, `game/CLAUDE.md:288`. SR-6.7 이 허용한 프레임 어긋남 범위 안이다.)

**제안**: SR-6 에 「입력이 결과를 바꾸는 비참여형 게임」 항을 추가하고 경로를 하나 고른다 —
(a) 뒤집기 입력을 릴레이로 중계(판당 메시지 수가 늘지만 사람 수만큼뿐), (b) card-flip 을 1차에서 제외,
(c) 온톨로지를 고쳐 card-flip 을 참여형으로 재분류. 셋 다 태스크 범위가 다르다.

### U3 — 요구사항 두 줄이 spec.md 로 안 옮겨졌다

`requirements.md` R7 의 여섯 줄 중 넷은 대응이 있다(R7.2→SR-7.5, R7.3→SR-7.6, R7.4→SR-5.7, R7.5→SR-7.7).
**R7.1·R7.6 은 대응 SR 이 없다** — `spec.md` 전문에 「유실/사라지/다시 열/재접속」·「저장 실패」가 한 번도 안 나온다.

- **R7.1 방 유실은 판 유실이 아니다** — 릴레이는 in-memory 단일 노드(`GameRelayRegistry.kt:24-30`)라 재배포·재기동에 방이 사라진다. 그때 사람들이 무엇을 해야 하는지(같은 코드로 다시 열고 명부 재인계)가 스펙에 없다. **운영 중 가장 자주 볼 실패**인데 화면 흐름에도 없다.
- **R7.6 그룹 계정 저장이 실패해도 판은 진행된다** — 저장 실패가 시작을 막지 않는다는 판정이 사라졌다.

**제안**: SR-1 에 R7.1, SR-2 에 R7.6 을 항으로 복원.

### U4 — 결과 해시 불일치(SR-6.8) 후 판정 규칙이 없다

SR-6.6 은 「각 기기가 스스로 계산」, SR-6.7 은 「순위가 다른 것은 허용하지 않는다」, SR-6.8 은 「경고가 뜬다」까지다.
**갈렸을 때 어느 결과가 유효한지가 없다.** 내기 자리에서 서로 다른 결과를 보고 있는 상태에 경고만 띄우면,
사람들은 무엇을 해야 할지 모른 채 화면 둘을 비교하게 된다 — 이 기능이 실패하는 가장 아픈 모습이다.

**제안**: SR-6 에 「불일치 시 판 무효 + 같은 시드로 다시」처럼 한 줄로 판정을 정한다(SR-7.7 과 같은 형태).

### U5 — 투표의 전송·집계 경로와 1인 1표 근거가 없다

SR-5.6 은 「누가 무엇을 골랐는지 어떤 응답에도 실리지 않는다」인데, 전송 경로가 정해져 있지 않다.
**릴레이로 보내면 이 요구가 즉시 깨진다** — 릴레이는 페이로드를 열어보지 않고 그대로 중계한다
(`GameRelayRegistry.kt:15-16`: 「`move` 의 `d` 는 열어보지 않고 상대에게 그대로 전달한다」).
따라서 투표는 서버 집계(HTTP)여야 하는데 스펙이 그렇게 말하지 않는다.

1표의 주체로 든 `X-Visitor-Id` 는 실재하지만(`gateway/src/main/kotlin/com/kgd/gateway/filter/VisitorIdFilter.kt:18`)
쿠키 `vid` 에서 파생되고 없으면 새로 발행한다(같은 파일 `:24-25`) — 쿠키를 지우거나 시크릿 창을 열면 새 표가 된다.
채점은 좌석 토큰으로 좌석을 확인하는데(SR-7.4) **투표는 아무 확인이 없다.** 내기 자리에서 투표를 조작할 동기는 채점과 같은 크기다.

> KB: [[anonymous-identity-headers]] (1989v 볼트, updated 2026-08-28) — 「**어느 쪽도 어뷰징 방어가 아니다.** 저장소를 비우면 전부 새 표가 된다」. 그 페이지는 방어를 포기한 대신 **표 수를 함께 노출**하는 것으로 해소했다(블로그 평점). 파티 투표는 표 수 노출로는 해소되지 않는다 — 참가자 수가 이미 알려져 있어서, 표 수가 참가자 수를 넘으면 그때 이미 판이 오염된 뒤다.

**제안**: SR-5 에 ① 투표는 HTTP 집계 엔드포인트 ② 1표의 주체는 **좌석 토큰**(SR-7.4 를 재사용) 두 줄을 추가.
식별자를 늘리지 않는다는 원칙도 함께 지켜진다.

### U6 — 「걸리는 인원 수 k」를 기존 게임 3종 중 1종만 갖고 있다

SR-3.3 은 k 를 1~(참가자−1)로 정하게 하고 SR-3.6 은 「실현 방식은 게임이 정한다」로 넘긴다.
그런데 현재:

- `card-flip` — `hits`(여러 명 뽑기) 있음: `portal-fe/public/games/card-flip/js/meta.js:19,36,43`
- `marble-race` — `rank` 는 「**몇 등을 지목할까**」이지 몇 명이 걸리나가 아니다: `portal-fe/public/games/marble-race/js/setup.js:161-164`
- `ladder-draw` — k 입력 없음: `portal-fe/public/games/ladder-draw/js/meta.js:19-20`(`mode`·`items` 뿐)

또 현행 인계 규약이 나르는 것은 `mode: 'last' | 'order'` 뿐이라(`portal-fe/src/pages/games/party.ts:16`)
k 도 비율도 지금은 넘어가지 않는다. SR-8.2 가 v2 에서 늘리기로 했지만, **기존 게임 3종을 고쳐 그것을 받게 하는 일**이
스펙 어디에도 태스크로 서 있지 않다. 비율에 대해서는 OQ-3(사다리)이 있는데 **k 에 대해서는 같은 질문이 없다.**

**제안**: OQ-3 을 「비율·인원 수를 DECIDER 3종이 각각 어떻게 실현하나」로 넓히고, 3종 개작을 SR 또는 태스크로 명시.

### U7 — 참여형 마감 규칙이 결과를 못 만든다

SR-7.6 은 「제한 시간이 지나면 마감, 미제출자는 최하위」까지다. 남은 것:
- **제한 시간 값이 없다** (OQ 에도 없다). 사용자에게 카운트다운이 보이는지도 없다.
- **미제출자가 둘 이상이면** 그들 사이 순위가 없다. SR-3.3 의 k=1 과 만나면 **누가 걸렸는지 정해지지 않는다** — 자리가 멈춘다.
- 전원 미제출이면? SR-5.7 은 투표에 대해 「전원 기권이면 무작위」를 정해 뒀는데, 채점에는 같은 줄이 없다.

**제안**: SR-7.6 에 제한 시간 기본값·동률 처리(무작위 또는 재시도)·전원 미제출 처리 세 줄 추가.

### U8 — 관전자 actor 의 goal 과 경로가 없다

SR-4.6·SR-5.8 에 「표가 없다·참가자 수에 안 들어간다」는 **제약만** 있고, 왜 존재하는지·무엇을 보는지·
자리가 비면 참가자로 전환되는지가 없다. User Story 도 없다. 테스트 T11 이 제약만 검사하므로,
관전자 화면이 통째로 비어 있어도 초록불이 난다.

### U9 — 막다른 길 3곳

자리 픽 거절(SR-4.5) · 판 무효(SR-7.7) · `[랜덤]` 즉시 시작(SR-5.3) 뒤의 복귀 경로가 Visual Design 에 없다.
특히 판 무효는 **반복 실패 시 탈출구가 없어** 자리가 멈출 수 있다.

### U10 — 판 진행 중 입·퇴장 순서 미정

SR-6.5 의 늦은 입장자가 자리 픽을 먼저 하는지 빨리감기를 먼저 하는지, 판 중 이탈자가 참여형에서 미제출로 처리되는지.

### U11 — 옵트인 끄기(SR-2.3)의 하드 삭제에 확인 절차가 없다

그룹 여러 개가 한 번에 사라지고 되돌릴 수 없다. 삭제 자체는 D2 상 옳지만, 그 앞에 확인 한 단계가 필요하다.

### U12 — AC 추적성이 끊겨 있다

- User Story ↔ SR 매핑 표가 없다. Story 7개 중 「관전」·「미제출」에 대응하는 Story 가 없는 것도 이 표가 없어 안 드러난다.
- `planning/test-quality.md` 는 **`R` 번호**(R5.5·R7.2·R4.5…)를 근거로 적는데 `spec.md` 는 **`SR` 번호**를 쓴다.
  두 체계가 연결되지 않아, 스펙이 바뀌어도 테스트 표가 따라 바뀌었는지 확인할 방법이 없다.

**제안**: test-quality.md 의 근거 열을 SR 번호로 갱신하거나 spec.md 에 R↔SR 대응 한 줄을 둔다.

### U13 (경미) — 「핀볼」의 정체가 스펙에 없다

원문 ⑤가 이름을 댄 유일한 게임인데, 그것이 `marble-race` 의 코스 이름임(`portal-fe/public/games/marble-race/js/courses.js:25`)과
SR-6 의 대상이 DECIDER 3종(`marble-race`·`ladder-draw`·`card-flip`,
`game/feature/src/main/resources/gamedb/migration/V52__genre_decider.sql:13` · `V53__seed_card_flip.sql:31`)임을 스펙이 적지 않는다.
읽는 사람이 원문 ⑤가 충족됐는지 판단할 수 없다.

### U14 (경미) — 「숏링크」가 일반 링크로 대체된 기록이 없다

원문은 「숏링크 or QR」이고 SR-4.3 은 「파티 경로 + 방 코드」다. 6자리 코드면 충분히 짧아 실질 충족이지만,
대체했다는 한 줄이 없으면 다음 사람이 다시 묻는다.

### U15 (경미) — D10(다섯 개 전부 1차)이 spec.md 에 진술되지 않았다

SR 구성상 전부 들어 있으나, 릴리스 경계 문장이 없어 태스크 분해 때 잘라 낼 여지가 남는다.
