# 테스트 전략

## 판정 원칙 셋

1. **검사는 대상의 산출물을 본다.** 검사가 로직 사본을 들고 비교하면 대상을 지워도 초록불이 난다.
2. **원칙을 문장으로 적는 것과 지켜지게 배선하는 것은 다른 일이다.** 초판은 앞엣것만 했다 — 게임 JS를
   부를 수 있는 경로를 지정하지 않아 「테스트 파일에 시뮬을 다시 적는 것」이 가장 쉬운 길이었다.
   그래서 §0 이 먼저 온다.
3. **회귀를 주입해 빨간불을 본 뒤에만 「켰다」고 말한다.** ★ 표시가 그 대상이다.

## §0 배선 — 이것부터 만들지 않으면 아래 표가 성립하지 않는다

### W1. 게임 JS 를 테스트에서 부르는 경로

게임은 `portal-fe/public/games/**` 에 있어 현재 어떤 러너에도 수집되지 않고(`vitest.config.ts:11` 의
`include` 는 `src/**` 뿐), ESM 이 아니라 IIFE 라 `import` 할 심이 없다(`global.Rng = {...}`).

**막을 수 있는 형태는 코드에 이미 있다** — `marble-race/js/game.js` 는 캔버스·DOM 을 만지지 않고
(렌더는 `art.js`·`main.js`) `start()` · `state()` · `fastForward()` 를 `global.Game` 으로 낸다.

정할 것 셋:
1. **로딩 방식** — 가짜 `window` 에 `rng.js` + `physics.js` + `courses.js` + `parts.js` + `game.js` 를 순서대로 올려 실행한다
2. **위치와 수집 범위** — 테스트 파일 위치를 정하고 `vitest.config.ts` 의 `include` 를 그만큼 넓힌다
3. **비교 대상** — `Game.state().order` 다. 게임이 내놓은 순위이지 검사가 계산한 순위가 아니다

`fastForward` 는 T18 의 대상이기도 하므로 심을 한 번 뚫으면 둘이 산다.

### W2. 좌석 토큰 검사는 실제 서명자를 배선한다

이 레포의 유일한 토큰 테스트 선례(`SubmitScoreServiceTest.kt:42-46`)는 `FakeTokens` 로 **서명 의미를
테스트가 다시 구현**한다. 실제 서명자(`HmacSessionTokenService`)는 **레포 전체에서 정의부 말고 참조가 없다.**
그 선례대로 쓰면 `verify` 를 `return true` 로 바꿔도 검사가 통과한다.

토큰 검사는 **실제 HMAC 컴포넌트를 배선한 채로** 돈다.

### W3. 릴레이 시간 검사는 시간을 인자로 준다

`startDueLobbies(nowMs)` · `sweepIdle(nowMs)` 가 둘 다 시간을 인자로 받는다. 90초를 실제로 기다리지 않는다.

### W4. 명명 · mock 경계 · 픽스처

- 서버 테스트는 Kotest BehaviorSpec + MockK, 기존 `game/feature/src/test` 규약을 따른다
- **mock 하지 않는 것**: 좌석 토큰 서명자(W2), 릴레이 레지스트리(순수 인메모리라 진짜를 쓴다), 채점 산식
- **mock 하는 것**: 저장소 포트, 시계
- 별칭 픽스처는 실명처럼 보이는 값을 쓴다 — 「테스트1」로 두면 SR-9.9 유출 검사가 무의미해진다

## 크리티컬 패스

T41 이 기능의 존재 이유다. **두 번째 판까지 밟는 것**이 T41 의 핵심이다 — 거기서 멈추면 방이
판과 함께 죽어도 나머지가 전부 통과한다.

그 아래로 넷이 무너지면 다른 게 다 통과해도 기능이 성립하지 않는다.

| | 무너지면 |
|---|---|
| **T9·T62·T63·T64·T65** (방장이 결과에 못 닿는다) | 방장이 결과를 고른다 — 내기가 성립하지 않는다. 문이 넷이라 검사도 넷이다: 시드 발급 · 판마다 재발급 · 원자적 발급 · 종료·무효 선언 |
| **T1·T3** (결과가 안 갈린다) | 아이폰과 안드로이드가 다른 결과를 본다 |
| **T10·T11** (토큰이 실제로 문다) | 아무나 남 대신 제출한다 |
| **T27** (제외가 그룹을 안 건드린다) | 매번 명부를 다시 적게 된다 — 기능의 동기가 사라진다 |

## SR → 테스트 매핑

T42~T59 가 2차·3차 패치로 생긴 SR 과 초판의 미매핑을 채웠다. 매핑이 얇은 곳을 밝혀 둔다:

- **SR-1.9**(방·좌석 상한) — 릴레이 기존 상한이라 새 검사를 두지 않는다
- **SR-4.7**(방 코드가 유일한 접근 통제) — 속도 제한은 릴레이 기존 검사가 덮는다
- **SR-5.10**(소수 인원에서 표가 드러남) — 성질이라 검사 대상이 아니다. 문서에만 남긴다
- **SR-8.13**(장르 표준 개정) — 문서 작업이라 `hns:validate --docs` 가 잡는다

## 안 하는 것

- 릴레이 다중 노드 시나리오 (범위 밖)
- 부하 테스트 — 방 상한 200 · 좌석 20 이 이미 상한이고 무료 티어 제약이 그 위에 있다
- **크로스 브라우저 실기 대조** — T3 의 **소스 단정**이 「엔진 표준 함수를 안 쓴다」를 잰다(값 표만으로는
  못 잰다 — T3 행 참조). 실기 확인은 배포 후 결과 해시 불일치 카운터(SR-9.8)가 관측한다.
  T3 이 통과하는데 실기가 갈리면 그때는 다른 원인이다
