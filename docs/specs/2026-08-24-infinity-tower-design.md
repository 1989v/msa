# 인피니티 타워 (InfinityTower) — 설계 문서

> slug: `infinity-tower` · 순수 정적 웹(HTML+JS+Canvas) · 빌드 스텝 없음 · 런타임 외부 요청 0

## 0. 한 줄 정의

**직업 4종을 골라 넷이서 첨탑을 지키거나 적 첨탑을 부수는 협동 전략 액션.**
누가 중간에 나가도 그 자리를 **AI(AI)** 이 즉시 이어받아 판이 끝까지 굴러간다.

## 1. 최우선 제약 — 이탈 내성이 이 게임의 정체성

| 제약 | 설계 반영 |
|---|---|
| 1판 10~15분 | 미션 1개 = 웨이브 12 + 보스. 웨이브 40~55초 + 준비 10초. 목표 11~13분 |
| 슬롯 4개가 `human \| ai` 런타임 전환 | `slot.control` 한 필드. 시뮬은 **의도(intent)** 만 소비하므로 전환에 상태 리셋이 없다 |
| AI 승계가 봐줄 만할 것 | 직업별 전용 정책(탱커=도발/몸빵, 사수=카이팅, 술사=밀집 조준, 치유사=최저체력 추적·부활) |
| 승계가 화면에 보일 것 | 슬롯 카드 배지 「AI」 + 캐릭터 위 태그 + 발밑 링 색 변화 + 인계 토스트 |
| 네트워크 계층 없음 | **host authority 전제**로 시뮬 1곳. 입력은 intent 로만 주입 — `InfinityTower.net.applyIntent(slotId, intent)` 훅만 열어두고 전송은 하지 않는다 |

### 1-1. 인게임 설명 (서사와 시스템이 같은 말을 한다)
네 서약자는 첨탑에 **서약**을 맺었다. 서약자가 자리를 비우면 그 서약이 남긴
**AI**이 몸을 이어받는다. → "AI가 대신 조작 중" 이 세계관 안에서 자연스럽다.

## 2. 아키텍처 — 의도(intent) 단일 통로

```
[사람 좌석 키보드]  ─┐
                     ├→  intent  →  [권위 시뮬레이션 1곳]  →  월드 상태  →  렌더
[AI 정책(직업별)]    ─┤              (고정 스텝, 시드 RNG)
[원격 피어(미구현)]  ─┘
```

- `intent = { mx, my, attack, attackDown, skill1, skill2, guard, guardDown, interact, menuL, menuR, menuOk, menuBack }`
- 사람/AI/원격 어디서 왔든 **시뮬은 구분하지 않는다.** 그래서 전환이 안전하다.
- 시뮬은 `sim.step(dt, intents[4])` 하나뿐 — 렌더/입력이 시뮬 상태를 직접 쓰지 않는다.
- 난수는 전부 시드 RNG(`world.rng`). `Math.random` 은 시뮬 안에서 호출하지 않는다(연출 파티클만 예외).

### 2-1. 통합(네트워크) 세션이 쓸 계약 — 이 게임이 여는 유일한 구멍

```js
InfinityTower.net.applyIntent(slotId, intent)   // 원격 피어의 의도를 그 슬롯에 주입
InfinityTower.net.setControl(slotId, mode, seat) // 'human' | 'ai'
InfinityTower.net.snapshot()                     // 권위 상태 요약(디버깅·재동기화 참고용)
InfinityTower.net.newIntent()                    // 빈 의도 (심장박동용)
```

- `applyIntent` 는 호출 시각을 기록한다. **1.2초 동안 의도가 끊기면 이탈로 보고
  AI이 자동 승계**한다 — 릴레이가 죽어도 판은 굴러간다.
- 전송·직렬화·지연 보상은 **이 게임 안에 없다.** 권위는 호스트 한 곳이라는 전제만 지킨다.
- 슬롯 이름은 `intent.name` 으로 함께 넘길 수 있고, 화면의 이름표에 그대로 뜬다.

## 3. 직업 4종 — 역할이 실제로 다르고, 혼자서는 못 이긴다

| 직업 | 정체성 | 기본공격 | 스킬1 | 스킬2 | 방어기(성격) |
|---|---|---|---|---|---|
| **파수기사** | 탱커·통제 | 근접 광역 3연타 | **도발** — 범위 내 적 어그로 강제 고정 | **방벽 전개** — 시간제 물리 차단벽 | **가드**(지속형) 게이지 소모·정면 90% 경감 |
| **주문술사** | 광역 딜 | 마력탄 3점사 | **낙뢰 폭발** — 예고 후 착탄 대폭발 | **서리 장판** — 감속 + 지속 피해 | **점멸**(타이밍형) 0.22초 무적 순간이동 |
| **사수** | 단일 딜·처형 | 속사 화살 | **관통 저격** — 차지 후 직선 관통(방어 무시) | **덫 설치** — 밟은 적 속박 | **회피 구르기**(타이밍형) 0.30초 무적 |
| **치유사** | 유지·부활 | 성흔 파동(약함) | **치유** — 최저 체력 아군/첨탑 회복 | **축복의 원** — 범위 아군 공격·이속 증가 | **수호 결계**(자원 흡수형) 흡수 실드, 자원 소모 |

**조합 강제 장치** — 각 위협은 특정 역할이 없으면 답이 없다.
- `잿껍질`(공성형)은 플레이어를 무시하고 첨탑만 친다 → **도발/방벽** 없으면 첨탑이 녹는다
- `잿송곳니` 군집 웨이브는 처리량 싸움 → **광역** 없으면 밀린다
- `잿무당`은 주변 적에게 보호막을 씌운다 → 먼저 끊을 **단일 폭딜** 필요
- 지속 피해·자폭 누적 → **치유/부활** 없으면 인원이 마른다

## 4. 조작 — 가상패드로 옮길 수 있는 형태 (방향 + 액션 5개)

| 액션 | 좌석1 (기본) | 좌석2 (2인 로컬) |
|---|---|---|
| 이동 | 방향키 **또는** WASD | WASD |
| 공격 | `Z` **또는** `J` | `J` |
| 스킬1 | `X` **또는** `K` | `K` |
| 스킬2 | `C` **또는** `L` | `L` |
| 방어기 | `V` **또는** `I` | `I` |
| 상호작용/건설/확정 | `Space` **또는** `U` | `U` |

- **1인 모드에서는 두 배열을 모두 받는다.** 좌석2가 참가하는 순간 좌석1은
  방향키+ZXCV+Space 로 좁혀지고, **양쪽 배열표를 화면에 안내**한다.
- 메뉴(건설·특성 카드)는 방향키 좌우 + 상호작용 확정 + 방어키 취소 → **패드로 완결**된다.
- 마우스 조준 없음. 기본공격은 **바라보는 방향 우선 + 조준 보정**(전방 부채꼴 내 최적 대상).
- `Enter` 는 어느 씬에서든 **확정**(Space·U 와 동일). `Esc`/`V`/`I`/`BkSp` 는 **취소**.
- 전역: `Esc` 일시정지 · `Tab` 자리 배정(슬롯 human/ai 전환) · `1~4` 패널에서 슬롯 지정 ·
  `M` 음소거 · `F` 전체화면.
- **조기 개시**: 준비 시간에 첨탑 곁에서 확정을 누르면 남은 시간이 **자원로 환산**되고
  웨이브가 바로 시작한다 (숙련자가 준비 시간을 버리지 않게).
- **어떤 씬의 어떤 키도 무반응이 아니다.** 배정되지 않은 키는 거절음 + 화면 흔들림으로
  돌려주고, 조건에 걸려 못 쓰는 행동(경직·조준 중·쿨다운·자원 부족)은 사유를 띄운다.

## 4-b. 맵 스케일 — 이 장르의 전제

같은 계열 커스텀맵의 규모를 하한으로 잡는다. **한 화면은 월드의 일부만 본다.**

| 항목 | 값 |
|---|---|
| 월드 | **128 × 128 타일 × 48px = 6144 × 6144** |
| 한 화면(줌 1.0) | 1920×1080 = **월드의 5.49%** |
| 전술 줌(0.62) | **14.3%** |
| 레인 | **6갈래** — 북·남·동·서(처음부터) + 북동·남서(웨이브 7부터) |
| 레인 길이 | 2588 ~ 3040px = 잿송곳니 도보 **15~18초** |
| 건설 받침 | **22개** (레인당 탑 2 + 길목 1, 첨탑 앞 4) |
| 동시 개체 | 목표 100+ (§15-10 실측) |

**구조**: 첨탑이 월드 정중앙, 여섯 관문이 사방에서 들어온다. 입구가 하나면 넷이 뭉쳐 서 있으면
끝나므로 갈래를 나눠 **역할과 위치를 분담**하게 했다. 이 구조 때문에 이탈 시 AI 승계가 더
중요해진다 — 빈 방어선이 그대로 뚫리기 때문이다.

**이동 비용 흡수** (맵이 커도 판이 늘어지지 않게):
- 직업 기본 이동 속도 **+25%** (376~440 px/s)
- **길 위에서 +35%** — 도로가 장식이 아니라 실제 기능을 한다 (64px 격자 도로 마스크로 O(1) 판정)
- 보스는 관문이 아니라 **레인 중반**에서 등장한다 (3000px 를 걸어오게 두지 않는다)

**카메라 / 미니맵** (이 규모에서는 선택이 아니다):
- 카메라: 내 캐릭터 소프트박스 추종 · 드래그 팬 · 미니맵 클릭 점프 · `Q` 줌 2단 · 휠 줌 ·
  월드 밖으로 나가지 않도록 클램프
- 미니맵(288px): 전체 맵 축소도 · 아군(내 것은 흰 테두리) · 적(정예/보스는 크게) · 건설물 ·
  첨탑 피격 경보 링 · **현재 시야 사각형**
- 컬링: 화면 밖 개체는 **렌더에서 제외하고 시뮬은 계속 돈다**
- 지형: 월드 전체 베이크가 불가능한 크기라 **512px 이음매 없는 패턴 + 절차 장식 버킷**으로
  바꿔 메모리·비용을 맵 크기와 무관하게 만들었다

## 5. 모드 — 같은 조작, 목표만 다르다

| | 방어전 「여명 관문」 | **타워 등반** |
|---|---|---|
| 목표 | 첨탑을 지킨 채 웨이브 12 + 보스 격파 | **한 층씩 격파하며 999층까지** |
| 한 판 | 14분 06초 (10~15분) | **한 층 1~1.5분** — 여러 층 오르다 그만두는 구조 |
| 실패 | 첨탑 HP 0 | 전멸 (도달 층은 남는다) |
| 지도 | 10240² · 첨탑 정중앙 · 여섯 갈래 | **8192² 층 아레나** · 진입구 3~6곳 · 중앙에 계단 |
| 압박 | 적이 온다 | **층이 오를수록 강해진다** |
| 이어하기 | 없음 (한 판 완결) | **10층마다 체크포인트** — 다음엔 거기서 시작 |

### 5-b. 타워 등반 — 999층을 손으로 만들지 않는다

**층 번호가 곧 시드다.** `towerFloor(n)` 은 순수 함수라 같은 층은 언제 들어가도 똑같이 나온다 —
그래야 공략이 성립하고 남과 이야기가 된다. 실측으로 확인했다(7층을 두 번 생성 → 진입구·적 구성·수 동일).

**구간(밴드)마다 규칙이 새로 열린다.** 선형 증가는 지루하다.

| 밴드 | 층 | 등장 적 |
|---|---|---|
| 기슭 | 1~50 | 잿송곳니 · 불씨화살 · 잿나방 |
| 본탑 | 51~200 | + 잿껍질 · 잿수호자 |
| 심층 | 201~500 | + 잿꼬투리 · 잿추적자 |
| 심연 | 501~999 | + 잿거인 (약한 적은 빠진다) |

**한 층의 리듬 — 3진.** 한 번에 쏟으면 30초에 끝난다. 적을 3진으로 나눠 밀려오게 해
층마다 기승전결을 만든다(실측: 1진에 몰아주면 30초, 3진으로 나누면 60~90초).

**10층마다 층지기 + 체크포인트.** 층지기는 그 층 잡몹보다 확실히 무겁고(체력 ×1.15),
잡으면 체크포인트가 저장돼 다음 세션은 그 다음 층에서 시작한다.

**층을 넘어 남는 것**: 레벨·특성·정수를 그대로 이월한다(`captureCarry`/`applyCarry`).
매 층 리셋되면 999층이 무의미하다. 층을 깰 때마다 최고 기록이 갱신되고,
체크포인트마다 해금 점수가 쌓인다.

## 6. 성장

**판 안 (in-run)**
- 개인 경험치 → 레벨 1~8. 레벨업마다 **특성 카드 3장 중 1택**(직업 전용 + 공용 풀).
  비차단 오버레이 · 8초 후 자동 선택 · AI 슬롯은 즉시 가중치 선택.
- 공용 자원 **자원**: 처치·웨이브 클리어로 획득 → 건설/업그레이드/수리.

**판을 넘겨 (meta, localStorage `infinity-tower.save.v1`)**
- **해금 점수** 획득 → 직업별 영구 특성, 시작 자원, 첨탑 강화, 신규 건물, 난이도 티어 해금.
- 미션별 최고 기록(도달 웨이브·점수·시간).

## 7. 난이도 — 첫 판부터 제대로 (§0 공통 원칙)

- 몸풀기 웨이브·튜토리얼 판 없음. 웨이브 1부터 2게이트 동시 + 원거리 적 포함.
- 여유는 준비 시간 10초뿐이며 그건 난이도가 아니라 화면을 읽을 시간이다.
- 상향은 **밀도·동시 공격 토큰·신종 추가**로. 예고(텔레그래프)는 무슨 일이 있어도 유지.
- 합격선: 자동 플레이 봇이 무피격 클리어하면 너무 쉽다 / 규칙을 몰라 지면 너무 어렵다.

## 8. 보스 — 패턴마다 다른 정답

### 중간보스(웨이브 6) 「잿뿔 파쇄자」
| 패턴 | 예고(형태·색·소리) | 정답 |
|---|---|---|
| 돌진 | 바닥에 **긴 직선 띠**·주황·저음 경적 | 옆으로 비켜서기 |
| 지면 강타 | **원형 파문**·붉은색·둔탁한 저음 | 사거리 밖으로 |

### 층 보스(웨이브 12) 「잿불 공성귀」
| 패턴 | 예고 | 정답 | 실패 시 |
|---|---|---|---|
| 분쇄 강타 | **전방 쐐기**·주황·쇳소리 | **가드/패링** 또는 측면 회전 | 대미지 + 넉백 |
| 낮은 휩쓸기 | **낮게 깔린 띠**·노랑·바람소리 | **회피 무적으로 통과** 또는 사거리 밖 | 넘어짐 |
| 잿불 폭격 | **도넛(안쪽 초록)**·보라·휘파람 | **붙기** — 보스 근처가 안전 | 다중 장판 피해 |
| 잿송곳니 소환 | 바닥 **균열 십자**·회색·울음 | 광역으로 정리(동시 상한 6) | 누적 압사 |
| 응축 파열(P2) | 보스로 **수축하는 고리**·흰색·고음 | **지금 때려라** — 약점 타격 시 스턴 + 큰 딜 | 광역 대미지 |

- 페이즈: 100~70% / 70~35% / 35~0%. P2 에서 분쇄 강타가 2연타가 되어 **정답이 바뀐다**
  (가드 후 반격 → 회피 2회).
- **정답 성립 3조건**을 프레임 데이터로 검증하고 수치를 이 문서에 남긴다.
  ① 정답 창 ≥ 예고 시간 ② 정답 직후 안전 프레임 존재 ③ 정답이 필요한 거리에서 발동.

## 9. 아트 디렉션

- **팔레트**: 심야 인디고/보라 배경 + **여명 금빛**(아군·첨탑) vs **잿불 주황·재빛**(적).
  아군은 차가운 금빛 테두리, 적은 뜨거운 주황 테두리 — 난전에서 소속이 즉시 갈린다.
- **개체 렌더 최저선**: 3톤 명암 + 외곽선 + 림라이트 + 접지 그림자. 단색 도형 금지.
- **배경 3층**: 원경(안개 산·성벽 실루엣) / 중경(석재 광장·길·균열, 오프스크린 1회 베이크) /
  근경(잔해·전경 그림자) + 비네트 + 첨탑 광원 + 잿가루 파티클.
- **캐릭터 존재감**: 화면 높이의 1/12~1/13 (탑다운 전략의 시야 우선). 그 대신
  **발밑 소속 링 + 실루엣 차별화 + 이름표 + 발광**으로 어떤 순간에도 즉시 식별.
- 실루엣 규약: 파수기사=가장 넓은 어깨+원형 대형 방패 / 주문술사=뾰족 후드+부유 룬고리 /
  사수=낮은 자세+긴 활+망토 / 치유사=등불+짧은 케이프+부유 오브.
- 애니메이션은 **파라메트릭 리그**(뼈대 파라미터 곡선) — 60fps 연속 보간이라 끊김이 구조적으로 없다.
  클립: 대기 / 이동 / 공격 / 시전 / 피격 / 쓰러짐 / 기상.

### 15-1. 프레임

**fps 는 두 환경을 반드시 갈라서 읽어야 한다.** 검증은 대부분 헤드리스에서 도는데,
헤드리스는 `--disable-gpu` 소프트웨어 래스터라 fps 가 실제보다 낮게 나온다. 게임의 성능이 아니라 측정 환경의 상한이다.

| 항목 | **GPU (headed, 실제 사용자 환경)** | 헤드리스 (소프트웨어 래스터) |
|---|---|---|
| 백버퍼 | 2667×1500 (스케일 1.389) | 1920×1080 (스케일 1.0) |
| 전투 초반 | **120 fps** · frame **0.70ms** | 24~38 fps |
| 적 160기 동시 | **120 fps** · frame **0.69ms** (그린 개체 8 — 컬링 동작) | — |
| 283기를 **전부 화면 안에** | — | frame **4.73ms** (§15-10 표) |

GPU 쪽 120 fps 는 모니터 상한(120Hz)에 걸린 값이고 frame cost 가 **0.70ms** 다.
**예산 16.7ms 대비 4%** — 2D 두 패스로 캐릭터 비용이 2배가 된 뒤에도 여유가 크다.

> 기술 도입 게이트: `draw+composite < 8ms`, `sim < 8ms` → **WebGL·WASM 도입 조건 미달.**
> 순수 Canvas 2D 를 유지한다 (빌드 스텝 0 유지).

### 15-5b. 보스 정답 효과 A/B (정답봇 vs 오답봇, 각 45초 × 6배속)

지표는 **패턴 인스턴스 단위 적중 수**다(보스 단위 비율이 아니다). 4인 파티이므로
인스턴스당 최대 4.00. 오답봇은 `dev.dumbBot(true)` 로 예고 판정만 끄고 교전은 유지한다.

| 보스 | 패턴 | 정답봇 (발동/적중/인스턴스당) | 오답봇 (발동/적중/인스턴스당) | 적중 감소 | 피해 감소 |
|---|---|---|---|---|---|
| 층 보스 | 분쇄 강타 | 14 / 0 / **0.00** | 32 / 53 / 1.66 | **100%** | **100%** |
| 층 보스 | 낮은 휩쓸기 | 16 / 9 / **0.56** | 27 / 78 / 2.89 | **81%** | **88%** |
| 층 보스 | 잿불 폭격 | 25 / 25 / **1.00** | (0 발동) | 대조 불가 | — |
| 층 보스 | 소환 | 18 / 0 / 0.00 | 15 / 0 / 0.00 | 설계상 무피해 | — |
| 중간보스 | 지면 강타 | 37 / 26 / **0.70** | 32 / 56 / 1.75 | **60%** | **59%** |
| 중간보스 | 돌진 | 43 / 2 / 0.05 | 51 / 3 / 0.06 | 21% | 57% |

**읽는 법과 한계**
- 분쇄·휩쓸기·지면 강타는 감소율 60~100% — 정답이 실재한다.
- **잿불 폭격은 대조군이 성립하지 않는다.** 이 패턴은 「평균 거리 300 초과」에서만 발동하는데,
  오답봇은 도망치지 않아 **애초에 이 패턴을 한 번도 뽑지 않았다**(우연히 안전 지대 안에 서 있는 사례).
  그래서 절대값으로 읽는다: **인스턴스당 1.00 / 최대 4.00 = 4명 중 3명이 정답으로 피한다.**
- **돌진은 1차 측정에서 양쪽 다 거의 안 맞았다**(0.05 vs 0.06) — 정답이 좋아서가 아니라
  **판정이 예고 띠보다 좁아 아무나 안 맞았기 때문**이다. 예고 띠(폭 140)와 판정(반경 94)의
  불일치를 찾아 판정을 띠에 맞추고(반경 133) 띠를 200 으로 넓혔다.
  → 「보고 피할 수 있는데 어려운」 쪽으로 이동.

### 15-10. 큰 맵 실측 (전역 가드레일 G1 반영 후)

**G1 — 주인공 높이 / 화면 높이.** "캐릭터가 커서 맵이 작아 보인다" 의 정체는 맵 크기가 아니라
**카메라 거리**였다. stats 값이 아니라 *실제로 그려지는* 높이로 재야 한다.

| 항목 | 이전 | **이후** | 목표(전략·디펜스) |
|---|---|---|---|
| 주인공 그려지는 높이 | 96px | **55.8px** | — |
| **주인공 / 화면 높이** | 1/11.2 ✗ | **1/19.4** ✔ | 1/16 ~ 1/24 |
| 4직업 범위 | 1/11.2 ~ 1/13.2 | **1/19.4 ~ 1/22.8** ✔ | 전부 표 안 |
| 적 범위 | 1/9.2 ~ 1/14.2 ✗ | **1/15.8 ~ 1/24.5** | 대형 정예만 1/15.8 |
| 한 화면이 보는 월드 | 5.49% | **5.88%** ✔ | 10% 이하 (권장 5%) |
| 월드 | 6144² | **10240 × 10240** (160×160 타일 × 64px) | — |
| 줌 | 2단 | **3단** 0.70 / **0.58 (기본)** / 0.47 | 대형 맵 3단 |

세 줌 단계가 각각 **1/16.1 · 1/19.4 · 1/23.9** 로 전부 표 안이고, 세 단계 모두 시야가 10% 를 넘지 않는다.

> **두 조건은 서로 당긴다.** 줌아웃하면 캐릭터 비율은 맞지만 시야 %가 커진다.
> 6144² 를 유지한 채 1/19 를 맞추면 시야가 **17.4%** 로 상한을 넘는다 — 그래서 월드를 키웠다.
> **캐릭터·사거리·판정폭은 하나도 바꾸지 않았다.** 늘린 것은 지도 배치 좌표뿐이라
> "닿는데 안 맞는다" 가 생길 여지가 없다 (G1 의 재조정 경고가 적용되지 않는 경로).

### 15-7. 죽은 입력 감사 (전 씬 × 전 키 매트릭스)

19 씬 × 34 키 = **646 칸**을 실제 KeyboardEvent 로 눌러 측정했다.
누르는 동안 폴링하고, 칸마다 씬을 다시 세팅한다.

| 분류 | 수 | 뜻 |
|---|---|---|
| 게임이 소비 (handled) | **485** | 실제 동작 또는 사유가 있는 거절(쿨다운·자원 부족·경직) |
| 배정되지 않은 키 (fallback) | **161** | 전역 거절음 + 화면 흔들림으로 되돌려줌 |
| **피드백 0 (dead)** | **0** | 485 + 161 = 646, 남는 칸이 없다 |

감사 대상 씬: 타이틀 · 도움말 · 기록 · 해금 · **미션 선택** · 직업선택 · 준비 · 전투 · **대시 중** ·
**게이지/쿨다운 소진** · **쓰러짐** · **오펜스 플레이** · 레벨업 카드 · 건설 메뉴 · **디펜스 복귀** ·
일시정지 · 자리 배정 · 승리 결과 · 패배 결과.

**소리가 나지 않은 칸 11개**(소비는 됐지만 sfx 증가 없음)는 따로 확인했다.
- 8개는 전부 `KeyM`(음소거) — **음소거는 원리상 소리로 확인할 수 없다.** 화면 표시(🔇/🔊)로 대신한다.
- 나머지 3개(`play-air:V`, `play-air:I`, `play-offense:K`)는 격리 재현에서 전부 소리가 났다
  (`last=guard` / `cd1=11.52`). 배치 안에서 대시가 이미 끝난 뒤 눌린 타이밍 문제였다.

**감사가 잡아낸 실제 결함 3종**
1. 쓰러진 동안 공격·스킬·상호작용이 **소리도 상태도 없이 사라짐** → 「쓰러짐 · N초」 표시 + 거절음.
2. 대시(점멸/구르기) 중 방어기 재입력이 무반응 → 「불가」 표시 + 거절음.
3. **음소거(M)는 원리상 소리로 확인할 수 없다** → 화면 표시(🔇/🔊) + 토스트 + 미세 흔들림 추가.

**하네스 결함도 함께 잡혔다.** 1차 측정에서 `Escape` 가 10개 씬에서 「무음」으로 나왔지만,
같은 조작을 격리해 다시 재니 6개 씬 전부 `sfxDelta=1 / last=uiBack` 이었다.
1차는 시간을 0.001배로 얼려 재느라 **쿨다운형 피드백 게이트가 붙박이가 된** 배치 드리프트였다.
(대량 실패가 나오면 코드보다 측정을 먼저 의심한다 — 이번에도 그대로 믿었으면 멀쩡한 코드를 뜯을 뻔했다.)

| 21 | 그리는 동안 누른 키가 **소리 없이 사라짐** | `input.endFrame()` 이 draw **뒤**에 있어, 그 프레임의 update 가 이미 지나간 뒤 도착한 이벤트까지 함께 삭제됐다. 그리기는 프레임의 대부분이라 유실 창이 컸다 | 입력 정산을 **update 직후**로 옮겨, 모든 이벤트가 정확히 한 번의 update 를 거치게 했다 |
| 22 | 자리 배정에서 **넷 다 AI**으로 만들 수 있었다 — 조종할 캐릭터가 0 이 된다 | 마지막 사람 자리를 넘길 때 아무 제약이 없었다 | 마지막 자리 전환을 막고, 카드에 「마지막 자리 — 비울 수 없다」 + 상단에 이유 문구. **탈락 내성이 이 게임의 정체성인데 정반대로 동작했다** |
| 23 | 잔흔들림이 **보스 흔들림 세기로 고착** | `shakeAmt` 를 `Math.max` 로만 갱신해 한 번 커지면 내려오지 않았다 | 흔들림이 끝난 뒤 새로 시작하면 진폭을 새 값으로 잡는다 |
| 24 | **화면 흔들림이 상한을 넘었다** (G3) — 보스 20~24px, 도발 8px | 호출부 29곳이 제각각 진폭을 정했다 | 상한을 **`FX.shake` 한 곳에서 강제**한다. 일반 ≤화면 높이 0.6%(6.5px)·180ms / 대형 ≤1.5%(16.2px)·500ms. 실측 `shake(24,0.9)`→**15.64px**, `shake(11,0.3)`→**3.67px**. 일시정지에 「화면 흔들림 · 켜짐/줄임/끄기」 추가 |
| 25 | **부품이 따로 노는 어중간한 3D 룩** (G4) — 사용자가 "차라리 2D 가 낫다" 고 했다 | 리그가 부품마다 외곽선 + 부품별 입체 하이라이트를 그려 형태가 하나로 안 읽혔다 | **2D 로 확정하고 두 패스로 바꿨다** — ① 실루엣 패스로 모든 부품을 외곽선 색으로 부풀려 그려 윤곽을 한 줄로 잇고 ② 색면 패스로 평면 색을 채운다. 내부 분리선은 바깥 윤곽의 40% 굵기로만 남긴다. 영웅 4종·적 전종이 같은 원시함수를 쓰므로 한 번에 적용된다 |

| 27b | 개명 1차에서 고른 **`자동`** 이 여전히 안 읽혔다 | 배지 `자동` 이 캐릭터 머리 위에 홀로 뜨는데, 그것만 보면 "자동 공격 켜짐" 같은 토글로도 읽힌다. 뜻이 확실한 `자동 조종 (AI)` 는 **Tab 패널 안에만** 있어서 처음 온 사람은 볼 일이 없다 | 가장 많이 보이는 자리부터 확실하게 — 배지·이름표·결과표는 **`AI`**, 패널은 문장으로 **`AI 가 조종 중`**. 이 게임의 정체성을 설명하는 단어라 한 번 더 갈았다 |
| 26 | 시야가 3배 넓어지자 바닥 장식이 **점 무늬처럼 어지러웠다** | 장식 밀도가 면적 비례라 한 화면에 들어오는 수가 3배가 됐다 | 간격을 250 → 430px 로 넓혀 **화면당 개수를 유지**하고, 큰 맵에서 존재감이 남도록 크기를 키웠다 |

### 검증 하네스 자체의 결함 (게임 버그로 오인했던 것들)

| 증상 | 원인 | 조치 |
|---|---|---|
| 큰 PNG 스크린샷 2회째부터 응답 없음 | 같은 WebSocket 으로 대용량 응답을 연속 수신 | 캡처마다 새 연결 |
| **사람 조작 검증이 매번 "게임이 멈춤"으로 끝남** | `Input.dispatchKeyEvent` 에 `nativeVirtualKeyCode` 로 **윈도 VK 코드**를 넘겼다. macOS 에서 크롬은 이 값을 *맥 네이티브 키코드*로 읽는다 — 49=Space, 51=Backspace | `nativeVirtualKeyCode` 제거, `code` + `windowsVirtualKeyCode` 만 전달 |

두 번째 것 하나가 아래를 전부 만들어냈다.
- `Digit1` 을 보내면 게임은 `Space` 를, `Digit3` 은 `Backspace` 를 받았고 `Digit2`/`Digit4` 는 아예 도착하지 않았다 (게임의 입력 큐를 계측해 확인)
- `Escape` 도 어긋나 "Esc 를 눌렀는데 일시정지가 안 된다" 같은 **가짜 실패**가 났다
- 어긋난 이벤트가 입력 파이프라인을 막아 `Runtime.evaluate` 가 **12~27초 지연 → 30초 타임아웃**. 이걸 "게임이 멈췄다"로 오판했다
- 고친 뒤: 입력 60회 폭주 중에도 evaluate **15~28ms**

멈춤이 아니라는 증거를 먼저 잡은 방법도 기록해 둔다 — rAF 프레임 번호를 `document.title` 에 실어
브라우저 프로세스에서 HTTP(`/json/list`)로 읽었다. **렌더러가 막혀도 읽히는 경로**라서
"evaluate 무응답"과 "게임 정지"를 분리할 수 있다. 사람 조작 30스텝 내내 프레임은 F34 → F1088 로 계속 올라갔다.

(대량 실패가 나오면 코드보다 측정을 먼저 의심하라 — 이번엔 그 규칙이 두 번 다 맞았다.)
