# 랜덤 카드 디펜스 (random-card-defense) — 설계 문서

> 포커 족보 타워 디펜스. 7~A 32장 덱에서 카드를 뽑아 족보를 만들고, 그 족보가
> 타워를 짓는다. 자리(슬롯)마다 사람과 AI 가 런타임으로 교대한다.

- 산출물: `portal-fe/public/games/random-card-defense/`
- 순수 정적 웹 (HTML + JS + Canvas). 빌드 스텝 없음, 런타임 외부 요청 0.
- 캔버스 2560×1440 고정, CSS 로 화면에 맞춤 (16:9 유지).
- **월드는 화면보다 훨씬 크다: 192×192 타일 × 48px = 9,216 × 9,216 px.**
  기본 줌에서 한 화면이 담는 면적은 월드의 **4.3%** 뿐이다 — 플레이어는 미니맵을 보며
  카메라를 옮겨 다닌다. "한 화면에 다 들어오는 판" 이 아니다.

---

## 1. 이 장르의 정체성 — 덱 구성이 곧 밸런스다

원류(카드 족보로 유닛을 소환하는 디펜스 계열)의 핵심은 **32장 덱**이다.
8랭크 × 4문양이라 확률 지형이 표준 52장과 완전히 다르다. 5장 기준 실제 확률:

| 족보 | 32장 덱 조합 수 (C(32,5)=201,376) | 비율 |
|---|---|---|
| 원페어 | 107,520 | 53.4% |
| 하이카드 | 53,040 | 26.3% |
| 투페어 | 24,192 | 12.0% |
| 트리플 | 10,752 | 5.34% |
| 스트레이트 | 4,080 | 2.03% |
| 풀하우스 | 1,344 | 0.67% |
| 포카드 | 224 | 0.111% |
| **플러시** | **208** | **0.103%** |
| 스트레이트 플러시 | 16 | 0.008% |

**페어는 흔하고 플러시는 포카드보다도 귀하다.** 그래서 이 게임에서 플러시로 가는
길은 운이 아니라 **덱을 깎는 것**이다 — 정비 상점의 `문양 각인`(카드 3장을 한 문양으로),
`정제`(낮은 카드 제거로 덱을 얇게), `승급`(끗수 상승)이 확률 지형 자체를 바꾼다.

표기 순서는 익숙한 표준 포커 순서를 그대로 쓴다(플러시 > 스트레이트). 실제 희소성과
순서가 어긋나는 구간이 있지만, 낯선 순서를 강요하는 것보다 **성능으로 보정**하는 쪽을 골랐다 —
플러시(장판)는 보스의 반사막을 통과하는 유일한 계열 중 하나라 순위표보다 실전 가치가 높다.

### 시드 운 제거 장치 (독립 확률로 굴리지 않는다)

| 장치 | 내용 |
|---|---|
| 비복원 뽑기 | 실제 덱에서 뽑고 쓴 카드는 버림 더미로. 더미가 마르면 버림을 다시 섞는다 |
| 첫 손패 보장 | 시작 손패에 페어 이상이 나올 때까지 최대 6회 교체 (`makeSlot`) |
| 천장(보정 드로우) | 원페어 이하 소환이 3연속이면 다음 뽑기는 **남은 더미를 훑어 손패를 가장 크게 올리는 카드**를 가져온다 |
| 버리기(Q) | 고른 카드를 태우면 그 자리를 **즉시 보정 드로우**로 채운다 (5초 대기) |
| 시드 단일화 | 모든 무작위는 슬롯별 mulberry32 시드에서 나온다. `Math.random` 은 화면 흔들림에만 쓴다 |

## 2. 족보 10단계 → 병기 10종 (성격이 전부 다르다)

카드는 **2~5장**을 골라 낸다. 장수가 적으면 낮은 족보만 성립하므로, "지금 싸게 세울까 /
모아서 크게 갈까" 가 매 순간의 선택이 된다.

| # | 족보 | 병기 | 사격 방식 | 성격 |
|---|---|---|---|---|
| 1 | 하이카드 | 파수 발리스타 | 단발 | 가장 싸다. 2장이면 나온다 |
| 2 | 원페어 | 쌍신 포탑 | 고속 단발 | 초당 화력 2배 |
| 3 | 투페어 | 교차 포대 | 동시 2표적 | 몰려올 때 강하다 |
| 4 | 트리플 | 삼각 작렬포 | 3점사 + 소폭발 | 첫 광역 |
| 5 | 스트레이트 | 연쇄 사슬탑 | 4회 연쇄 | 줄지어 오는 무리를 훑는다 |
| 6 | 플러시 | 문양 분출탑 | 지속 장판 | **방어막·반사막 관통** |
| 7 | 풀하우스 | 성채 대포 | 고폭발 + 오라 | 인접 병기 공속 +22% |
| 8 | 포카드 | 사방 폭풍탑 | 전방위 회전 빔 | 사거리 안 전부를 계속 벤다 |
| 9 | 스트레이트 플러시 | 혜성 소환탑 | 광역 낙하 폭격 | 반경 전체 소거 |
| 10 | 로열 스트레이트 플러시 | 왕관의 심판 | 초광역 + 처형 | 체력 16% 이하 즉사 |

### 문양(슈트) = 속성

| 문양 | 이름 | 효과 |
|---|---|---|
| ♠ | 강철 | 방어 관통 · 피해 +18% |
| ♥ | 선혈 | 20처치마다 성심 +1 · 금화 +25% |
| ♦ | 광휘 | 폭발/장판 반경 +40% · 연쇄 +2 |
| ♣ | 가시 | 둔화 38% 2.4초 · 맹독 3초 |

**대표 문양은 "가장 많이 고른 문양", 동수면 "먼저 고른 카드"의 문양이다.**
같은 페어라도 어느 쪽 카드를 먼저 누르느냐로 속성이 갈린다 — 선택 순서가 조작의 일부다.

### 자리 규칙 (진행이 막히지 않게)

| 상황 | 결과 |
|---|---|
| 빈 자리 | 새로 세운다 |
| 같은 족보 + 같은 문양, Lv<3 | **합성** — 레벨업 (피해 ×1.62 / ×2.45, 사거리 +6%/+13%) |
| 더 높은 족보 | **교체** — 기존 병기를 녹이고 새로 세운다. 회수가의 50% 환급 |

교체 규칙이 없으면 자리가 다 찬 뒤 "정확히 맞는 패"만 기다리게 되어 진행이 정지한다
(1차 실측에서 실제로 발생 — 자리 22개가 차자 AI 소환이 9초당 1회로 떨어졌다).

## 3. 자리(슬롯) 배열과 AI 승계 — 이탈 내성

- 슬롯은 **배열**이고 각 슬롯은 `human | ai` 다. 단일 플레이어 하드코딩 없음.
- **상태를 바꾸는 유일한 통로는 intent** 다. 사람 입력도 AI 도 같은 큐에 같은 모양으로 들어간다:
  `select · clearSel · summon · mulligan · gift · sell · buy · reroll · ready · mode`
- 시뮬레이션은 **권위 1곳**(`js/sim.js`)에서만 돈다. 렌더/UI 는 읽기만 한다.
- **네트워크 계층은 없다** — 통합 단계에서 릴레이가 intent 를 실어 나르면 그대로 동작하는 형태로 끊어 두었다.

### 승계 표시

| 장치 | 위치 |
|---|---|
| 슬롯 칩의 `사람 / AI` 배지 | 상단 우측. 전환 순간 2.4초 흰색 점멸 |
| 화면 배너 | "○○ — AI 승계 / 사람 복귀" |
| 로그 | 좌하단 진행 로그에 기록 |
| 전환 방법 | `F1~F4` 키, 또는 슬롯 칩을 직접 누르기(마우스/터치) |

혼자 남아도 판은 성립한다 — 비활성 갈래는 성문이 **봉쇄**되어 적이 나오지 않고,
그 갈래의 자리도 닫힌다. 인원수에 따라 성심 최대치(30 + 8×추가인원)와 적 물량이 스케일된다.

### 협동

- **보스 웨이브는 공유**: 보스는 성심 광장에 자리 잡고, 패턴은 전 슬롯에 걸린다
  (문양 봉인 · 패 강탈 · 덱 봉인은 모든 슬롯의 손패/덱을 동시에 잠근다).
- **공용 자리 8곳**이 광장 주변에 있다 — 보스 사거리 안이라 여기 지은 사람이 보스 딜을 낸다.
- **카드 건네기(E)**: 손패의 카드를 옆자리에 넘긴다. 카드는 물리적으로 상대 덱으로 옮겨간다.
  AI 도 동료 손패가 마르면 알아서 넘긴다.

## 4. 월드 스케일 · 카메라 · 미니맵

### 수치 (전부 실측)

| 항목 | 값 | 요구 최저선 |
|---|---|---|
| 월드 크기 | **192 × 192 타일** | 128×128 |
| 타일 픽셀 | **48px** | 40~64 |
| 월드 픽셀 | **9,216 × 9,216** | 5,000 이상 |
| 한 화면이 보는 면적 | **4.3%** (기본 줌) · 8.4% (광각) · 2.2% (근접) | 10% 이하 |
| 구역 | 슬롯별 사분면 4 + 성심 광장/회랑 = **8구역** | 4~8 |
| 갈래 길이 | **11,806px** (한 갈래) — 화면 폭의 4.6배 | — |
| 자리 | 갈래당 14 + 공용 12 = **68** | — |
| 동시 개체 실측 | **최대 198** (2인) · 4인은 그 이상 | 100+ |

- 성벽 = 월드 경계 안쪽 300px 라운드 사각형. 네 성문은 사분면 바깥 모서리에 있다.
- 네 갈래는 **하나의 형판을 x·y 로 뒤집어** 만든다 → 길이가 모두 같다.
- 슬롯 배정 순서 `[북서, 남동, 북동, 남서]` — 2인이면 대각선으로 앉아 월드 전체를 쓴다.
- 성심 광장 = 반경 700 원, 월드 정중앙. 보스는 여기서 싸운다.
- 자리 개방: 자기 갈래 `min(14, 6+⌊0.6w⌋)`, 공용 `min(12, 3+⌊0.6w⌋)` → 1웨이브 9자리에서 시작.

### 카메라

| 조작 | 방법 |
|---|---|
| 이동 | 방향키·WASD · **필드 드래그** · 미니맵 탭/드래그 점프 |
| 줌 | `−` `=` · 마우스 휠 · **두 손가락 핀치** · 화면 버튼 (3단: 0.72 / 1.0 / 1.42) |
| 바로가기 | `G` 내 구역 · `V` 성심 광장 · 보스 등장 시 자동으로 광장으로 이동 |
| 조준 중 | 방향키로 자리를 옮기면 **카메라가 따라간다** |

탭과 드래그는 **이동 거리 16px** 로 가른다 — 끌면 카메라 팬, 짧게 누르면 배치/선택.

### 미니맵 (이 규모에서는 없으면 플레이가 불가능하다)

우하단 336×336. 성벽·구역 경계·네 갈래(슬롯 색, 봉쇄는 회색)·성문·광장·자리·병기(소유자 색)·
**적 전부**·보스(점멸 링)·**현재 뷰포트 사각형**을 그린다. 누르면 그 지점으로 카메라가 간다.
상단 바에는 `줌 ×n · 화면 n%` 와 `현재 ○○ 구역` 이 상시 표시된다.

### 성능 (월드가 커지면 반드시 붙어야 하는 것)

| 장치 | 내용 |
|---|---|
| 지형 | 9,216² 를 통째로 구우면 340MB 다 → **이음매 없는 512px 돌 타일 패턴** + 데칼 300개 + 매 프레임 벡터(성벽/길/광장) |
| 컬링 | 모든 개체가 `CAM.visible(x,y,r)` 로 걸러진다. 길·성벽은 **보이는 구간만** 스트로크 |
| 공간 해시 | 320px 격자. 조준·스플래시·연쇄·장판·주술사 보호막·역병 오라가 전부 해시 조회 |
| 스프라이트화 | 적 발광·병기 그림자·총구 섬광·투사체를 **매 프레임 그라디언트 생성** 하지 않고 구워 둔 이미지로 |

**실측 (헤드리스 + GPU, 4인 · 병기 56 · 보스 포함):** `fps 120 · sim 0.10~0.14ms · draw 0.67~0.70ms`
= 프레임 예산의 **약 10%(120Hz 기준) / 5%(60Hz 기준)**.

> [!warning] 측정 함정 — `--disable-gpu` 는 fps 를 10~30 으로 만든다
> 헤드리스에 `--disable-gpu` 를 붙이면 SwiftShader 소프트웨어 래스터라이저로 떨어져
> **fps 10~30** 이 나오고, 오래 돌리면 렌더러가 굳어 CDP `Runtime.evaluate` 까지 멈춘다.
> 이때도 `sim + draw` 는 0.5ms 였다 — **JS 는 무죄였고 래스터가 병목이었다.**
> `--disable-gpu` 를 빼자 같은 장면이 **120fps** 로 돌았다. 헤드리스로 fps 를 잴 때는
> 이 플래그를 반드시 빼고, 프레임 코스트(sim/draw 분리)를 함께 보고할 것.

## 5. 보스 — 패턴 / 정답 / 예고 / 실패

TD 에서 "공략"은 회피가 아니라 **체계에 대한 요구**다. 패턴마다 다른 대응을 요구하고,
예고는 **형태 · 색 · 소리 3중**으로 갈라 둔다(같은 붉은 링이 다섯 번 나오지 않는다).

### 웨이브 5 — 무패의 심판관 (2페이즈)

| 패턴 | 예고(형태/색/소리) | 정답 대응 | 어기면 |
|---|---|---|---|
| 문양 봉인 | 거대 문양 도장 / 보라 / 상승 2음 | 문양을 분산해 지어 둔다. 봉인 밖 병기로 딜을 잇는다 | 한 문양에 몰빵했으면 6초간 화력 0 |
| 패 강탈 | 갈퀴 3줄 / 주황 / 긁는 노이즈 | 예고 2.2초 동안 손패를 소환으로 비운다 | 남은 카드 2장이 6초 잠긴다 |
| 무패의 종자 | 이중 확산 링 / 초록 / 하강 2음 | 광역 병기(트리플·플러시)로 즉시 정리 | 잡몹이 누적돼 성심이 깎인다 |
| 심판 광선 | 갈래 방향 쐐기 / 적색 / 상승 스윕 | 한 갈래에 몰아 짓지 않는다 | 지목된 갈래 병기 전부 3초 정지 |

- **성심 잠식**: 살아 있는 동안 7초마다 성심 −1. 무한정 버틸 수 없다(= DPS 검사).
- 페이즈 2(50%)에서 쿨다운 ×0.74.

### 웨이브 10 — 패단절자 (2페이즈)

| 패턴 | 예고 | 정답 |
|---|---|---|
| 덱 봉인 | 모래시계 / 노랑 | 드로우 4초 정지 — 예고 전에 손패를 채워 둔다 |
| 반사막 | 오각별 / 하늘색 | **직격은 80% 튕긴다. 장판(플러시)·맹독(가시)·연쇄만 통과** |
| 분열 소환 | 확산 링 / 초록 | 광역으로 조각까지 함께 지운다 |
| 절단 돌진 | 방향 화살 / 적색 | 가시(♣) 둔화가 걸려 있으면 돌진 거리가 줄어든다 |

`mirror` 는 가중치 1.6 으로 뽑아 **반드시 나오게** 했다 — 안 나오면 플러시/가시를
세워 둘 이유가 사라진다.

### 웨이브 15 — 공허의 왕 (3페이즈)

| 패턴 | 예고 | 정답 |
|---|---|---|

## 6. 밸런스 — 실측 (AI 2슬롯, 8배속 자동 완주 프로브)

| 축 | 값 |
|---|---|
| 웨이브 | 15 (보스 5 / 10 / 15) |
| 한 판 길이 | AI 최적 플레이 **약 8~9분** / 사람 조작 실측 약 10~12분 |
| 적 체력 | `1.28 × (1 + 0.30×(w−1))` — w15 = 6.66배 |
| 적 방어력 | `+⌊(w−1)/2.2⌋` — 낮은 족보 병기만으로는 후반이 안 뚫린다 |
| 밀도 | `1 + 0.05×max(0, w−5)` — 개수와 간격을 함께 스케일 (웨이브 길이는 유지) |
| 성심 | 30 + 8×(추가 인원) |
| 금화 | 처치당 `기본×(1+0.03w)×0.08` + 웨이브 보너스 `2+⌊w/2⌋`. 3웨이브 상점까지 약 110~150G |

프로브 이력 (수치가 바뀐 이유):

| 회차 | 설정 | 결과 | 판단 |
|---|---|---|---|
| 1 | 초기값 | 15웨이브 완주, 성심 25/25 무손실 | **너무 쉽다** |
| 2 | 자리 게이팅 + 물량↑ | 웨이브 14 패배, 단 12웨이브까지 무손실 | 절벽형 곡선 |
| 3 | 교체 규칙 추가 | 완주(성심 23/25) | 진행 정지는 해결, 여전히 쉽다 |
| 4 | 체력·방어력 스케일 | 웨이브 13 패배 | 중반이 여전히 무손실 |
| 5 | 밀도 램프 0.11 | 웨이브 11 패배 | **너무 어렵다** |
| 6 | 밀도 0.05 + 체력 1.28 | 웨이브 13~14 패배, 중반부터 꾸준히 누출 | 착지 |

> **1차에서 잡힌 진짜 문제는 난이도가 아니라 "진행 정지"였다.** 자리가 다 차면
> 정확히 같은 족보·같은 문양만 기다리게 되어 AI 소환 간격이 9초까지 벌어졌다.
> 교체 규칙(더 높은 족보면 갈아엎기)을 넣고서야 후반 곡선이 성립했다.
### 월드 확장(2,560px 단일 화면 → 9,216px 대형 월드) 이후 재밸런싱

월드를 3.6배로 키우면 밸런스가 통째로 다시 짜여야 한다. 실측으로 잡은 것:

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 병기가 거의 아무것도 못 죽인다 (40초에 누적 피해 2,029) | **자리를 주머니 한가운데(길에서 440px)에 놓았는데 사거리는 476** — 사거리 원이 길에 겨우 스쳤다 | 자리를 **길에서 190px** 로 붙이고 사거리를 1.6배로 |
| 2 | 웨이브 1에 성심 38이 통째로 날아감 | 물량을 2.2배로 올렸는데 개방된 자리는 4개뿐 | 물량 환원 + 개방 곡선 `6+⌊0.6w⌋` 로 상향 |
| 3 | 보스전이 3분씩 걸림 | **공용 자리를 반경 1,080 에 두어 사거리 762 로 중앙의 보스에 닿지 않았다** | 공용 자리를 반경 850 으로 당기고 보스 체력 −28% |
| 4 | 부유령(비행)이 한 웨이브에 18기 누출 | 직선 비행이 미로를 통째로 건너뛰는데 초반엔 중앙 자리가 3개뿐 | 부유령 속도 −28%·체력 +32%, 초반 물량 축소 |
| 5 | 조커 2장을 든 채 보정 드로우가 걸리면 **446ms 정지** | `pileDrawBest` 가 후보 24장마다 조커 치환 전수 탐색(32²)을 돌렸다 | 보정 판단에서 **조커를 제외**하고 후보를 12장으로 (446ms → 1.6ms) |

체력 계수는 마지막에 **매우 예민**했다: `1.28` 이면 성심 무손실 완주, `1.50` 이면 웨이브 9 패배.
`1.45` 로 착지 — AI 최적 플레이가 **15웨이브 완주(성심 31/54)**, 마지막 보스전에서 23을 잃는다.

## 12. 사용자 피드백 반영 (2026-08-24)

### F1. ★ "카드별 의미나 속성 식별이 안 됨" — 핵심 상호작용이 안 읽혔다

네 층으로 답했다. **아무것도 외우게 하지 않는다**가 원칙.

| 장치 | 내용 |
|---|---|
| **카드가 스스로 말한다** | 카드 하단에 무늬색 배지 + 무늬 기호 + 속성 두 글자(`관통` `회복` `광역` `독·둔화`). 작은 설명문이 아니라 카드 위에 직접 |
| **족보 치트시트 상시 노출** | 손패 위 가로 띠에 **족보 10단계 × 그 족보가 짓는 타워 이름**을 항상 띄운다. 지금 만들 수 있는 것 = 초록 점등, **한 장만 더 있으면 되는 것 = 점선 + 「한 장」 표시**, 나머지 = 흐림 |
| **추천 조합 표시** | 아무것도 안 고른 상태면 지금 최선의 조합을 이루는 카드에 금색 점선 테두리가 깜빡인다. 좌측 패널엔 `지금 최선: 투페어 → 두 갈래 포탑` |
| **칩을 눌러 바로 고르기** | 치트시트 칩을 누르면 그 족보를 만드는 카드가 자동 선택된다. 못 만드는 족보면 그 타워가 뭘 하는지 배너로 알려준다 |
| **전장과 같은 시각 언어** | 타워의 받침·포신 금속색이 무늬색으로 물들고, 받침에 **족보 번호(1~10)** 가 찍힌다 — 치트시트의 순서와 같은 번호다 |

계산은 `CC.handInsight(hand)` 한 곳에서 나온다(손패 서명 캐시, **2.7ms**):
지금 만들 수 있는 족보 전부 · 한 장만 더면 되는 족보 전부 · 최선 조합의 카드 인덱스.

## 13. 검증 하네스 — `nativeVirtualKeyCode` 함정 (중요)

내 CDP 하네스는 `Input.dispatchKeyEvent` 에 `nativeVirtualKeyCode: <윈도 VK>` 를 넘기고 있었다.
**macOS 에서 크롬은 그 값을 맥 네이티브 키코드로 해석한다** — `49`=Space, `51`=Backspace.
그래서 `Digit1` 을 보내면 게임은 Space 를 받고, `Digit2`/`Digit4` 는 이벤트 자체가 오지 않았다.
어긋난 이벤트가 입력 파이프라인을 막아 `Runtime.evaluate` 가 12~30초 지연되고,
그게 **"게임이 멈췄다"** 로 보였다. 나는 이 가짜 증상을 오래 쫓았다.

**해법**: `code` + `windowsVirtualKeyCode` 만 넘기고 `nativeVirtualKeyCode` 는 넘기지 않는다.

| | 수정 전 | 수정 후 |
|---|---|---|
| 20키 전송 → 게임이 받은 키 | 어긋남 · 일부 미수신 | **20/20 정확, 누락 0, 엉뚱한 키 0** |
| 입력 100회 폭주 중 evaluate 지연 | 12~30초 (타임아웃) | **0~1ms** |

게임 쪽에 `CC.input.rx`(받은 키 로그)를 두어 **"보낸 키 = 받은 키"** 를 검증 전에 항상 확인한다.

추가로 **헤드리스에 `--disable-gpu` 를 붙이면** SwiftShader 소프트웨어 래스터로 떨어져
fps 10~30 이 나오고 오래 돌리면 렌더러가 굳는다. 빼면 같은 장면이 **120fps**.
"좀비 크롬이 포트를 물고 있어 새 인스턴스가 CDP 포트를 못 여는" 사고도 있었다 —
검증 실패가 나면 **게임보다 하네스를 먼저 의심**해야 한다는 사례가 이 게임에서만 셋 나왔다.

## 15. 대전 공정성 — 시드만으로는 부족했다 (2026-08-24)

전개가 나오는지 기계로 대조해서 찾아냈다 (AI 대 AI 로 돌리면 두 자리가 **완전히 겹쳐야** 정상이다).

| # | 구멍 | 왜 불공정한가 | 고친 방법 |

| 1 | 소환 굴림이 공용 난수 | 두 전장이 번갈아 뽑아 쓰므로 방패 재사용 시간·진입 위치가 자리마다 달랐다 | 자리마다 난수 스트림을 나누고 **대전은 같은 시드**로 준다 (`s.rng`) |

## 16. 한 키보드 · 두 사람 (2026-08-24)

3~4인은 각자 자기 기기에서 붙는 전제라 지금의 화면 탭 · `Tab` · `F1~F4` 전환을 그대로 둔다.
**한 키보드에 두 사람**만 배열을 가른다 — 한 키보드에 넷은 물리적으로 불가능하다.

| 기능 | 1P (오른손) | 2P (왼손) |
|---|---|---|
| 이동 · 조준 | 방향키 | `W A S D` |
| 고르기 · 확정 | `J` (`'` 같은 기능) | `F` |
| 소환 · 취소 | `K` | `G` |
| 카드 커서 | `L` `;` | `V` `B` |
| 태우기 · 건네기 · 되팔기 | `U` `I` `O` | `Q` `E` `R` |

`ZXC` 는 `WASD` 바로 아래라 2P 액션 키로 쓰지 않는다. 자리 2개가 **모두 사람**일 때만 갈리고,
한 명이 빠지면(AI 승계) 곧바로 한 사람 배열(방향키·숫자·Space)로 돌아온다 — 참가·이탈 때마다
배너와 배열표를 띄운다. 도움말(H)·인원 설정 화면에도 같은 표가 있다.

### 이 배열을 넣으면서 같이 고친 것

- **조준 상태를 자리마다 분리**했다 (`RCD.viewOf(i)`). 하나였을 때는 두 사람이 동시에 조준하면
  서로의 커서를 덮어썼다. 기존 코드가 쓰는 `RCD.view.targeting` 은 "지금 보고 있는 자리" 로
  이어 주는 접근자로 남겨 두어, 한 사람 경로는 한 줄도 바뀌지 않았다.
- **숫자키·Space 를 두 사람 배열에서 막았다.** 공용 키를 남기면 초점을 쥔 쪽만 빠른 길이 생겨
  대전이 성립하지 않는다 (같은 이유로 상점도 자리마다 커서·준비를 따로 둔다).
- **화면 흔들림 토글을 `K` → `N`** 으로 옮겼다. `K` 는 원래 "뒤로" 로 계약된 키인데 전역
  토글이 먼저 먹고 있었고, 두 사람 배열에서는 1P 의 소환·취소 키다.
- 하단 HUD 를 **두 벌**로 나눴다 — 각자 자기 손패·자기 족보표·자기 이름표(돈·지금 최선)를
  본다. 미니맵은 가운데로 내려 두 손패 사이에 둔다. 한 사람일 때 배치는 그대로다.

### 실측

| 항목 | 결과 |
|---|---|
| 두 사람 배열 인식 · 배열표 | O (자리 2개가 사람일 때만) |
| 1P 키가 1P 에만 (`선택 [2,0]`) | O |
| 2P 키가 2P 에만 (`선택 [2,2]`) | O |
| 보낸 키 = 받은 키 | 8/8 |
| **동시 조준** (`[true,true]`, 자리 `L0-3` / `L1-3`) | O |
| 방향키·WASD 가 각자 커서를 옮김 | O |
| 각자 자기 타워를 세움 | O |
| 숫자·Space 차단 | O |
| `N` 흔들림 토글 | O |
| 이탈 → 한 사람 배열 복귀 → 숫자키 부활 | O |
| 죽은 입력 감사 (`playDuo` 장면 추가) | **840칸 중 0** |
| 5개 구성 부팅 · fps · 콘솔 | 전부 정상 · 120fps · 0건 |

두 배열만으로 한 판을 끝까지 돌린 회귀도 있다 — 키 284회, 자리별 소환 17/15, 웨이브 5,
4분 32초, 결과 화면 정상. (스크립트가 굴리는 조잡한 플레이어라 웨이브 3~9 사이로 흔들린다.
**밸런스 판정은 AI 완주(웨이브 15)가 맡고**, 이 회귀가 보는 것은 두 사람 입력 경로다)
