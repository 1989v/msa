# 구슬 레이스 (marble-race) — 설계

> 클린룸 12호 · 장르 프리셋 `party-decider` 의 첫 산출물
> 파이프라인: `docs/standards/game-cleanroom-pipeline.md`

## 1. 무엇을 만드는가

커피 사는 사람 정하기처럼 **여럿이 모여 뭔가를 정할 때** 켜는 물건. 이름을 넣고 출발하면
구슬이 실제로 굴러 내려가고, 결승선을 넘는 순서가 그대로 결과가 된다.

**실력 게임이 아니라 도구다.** 그래서 설계의 1급 목표가 재미가 아니라 **공정성과 그 증명**이고,
재미는 "결과가 나오기까지 지켜보게 만드는 연출" 로 만든다.

벤치마크는 사용자가 지정한 [lazygyu Marble Roulette](https://lazygyu.github.io/roulette/)
(Box2D WASM · 다중 맵 · 카메라 추적 · 1등/꼴찌/N등 · 이름 가중치)이고, 이건 **하한선**이다.
같은 규칙 세트를 이식하지 않고 전 축을 자체 설계로 채운 뒤, 그쪽에 없는 축
(**검증 가능한 공정성** · **미니맵 병행 표시**)을 더했다.

## 2. 사행성 가드레일 — 협상 대상이 아니다

| 규칙 | 구현 |
|---|---|
| 돈·포인트·베팅 금액을 넣을 곳을 만들지 않는다 | 그런 입력란 자체가 없다 |
| "당첨금·배당·베팅·환전" 을 쓰지 않는다 | 결과는 **걸린 사람 / 뽑힌 사람 / 순서** |
| 결과를 미리 정하고 애니메이션만 재생하지 않는다 | 물리를 실제로 돌린 결과가 순위다. 씨앗 공개 + 재현으로 증명 |
| 참가자 이름은 기기 밖으로 안 나간다 | `localStorage` 만. **`PlatformAdapter` 미부착**(랭킹도 없음) |

`x3` 가중치는 **그 사람의 구슬 개수**이고 확률이 그만큼 올라간다는 뜻이다. 배당률이 아니다.

## 3. 공정성 — 주장하지 않고 증명한다

| 장치 | 왜 |
|---|---|
| 무작위는 **씨앗 하나**에서만 (`mulberry32`, 씨앗은 `crypto.getRandomValues`) | 시뮬레이션에서 `Math.random` 을 부르면 재현이 불가능해진다 |
| 물리는 **고정 1/240초** | 60Hz 든 120Hz 든 결과가 같아야 같은 씨앗이 같은 결과를 낸다 |
| 씨앗을 화면에 띄우고 **"같은 씨앗으로 다시"** 제공 | "미리 정해 둔 게 아니다" 를 사용자가 직접 확인하는 유일한 방법 |
| 구슬은 **물리적으로 동일** (반지름 22 · 질량 · 반발계수 · 마찰) | 다른 건 색과 번호뿐 |
| 맵은 고정·좌우대칭, **출발 자리만 매 판 셔플** | 자리마다 유불리가 있어도 배정이 균등하면 사람별 확률은 같아진다 |
| **레이스 중 조작 없음** | 손댈 수 있으면 결과에 손댈 수 있다는 뜻. 방향키는 거절하고 이유를 말한다 |

### 실측

| 검사 | 결과 |
|---|---|
| 같은 씨앗 재현 (3씨앗 × 3맵 × 2회) | **불일치 0** |
| 균등성 (6명 · 240판 · 3맵 순환) | 꼴찌 χ²=**2.75**, 1등 χ²=**3.15** (df=5, α=.05 임계 **11.07**) → 편향 근거 없음 |
| 미완주 | 240판 중 **0** |
| 한 판 길이 | 평균 22.3초 · 최대 37.4초 (12구슬) |

## 4. 물리 — 외부 엔진 없이 자체 구현

`js/physics.js`: 반암시적 오일러 + 고정 스텝 위에 원/캡슐 충돌, **구름 마찰**, 회전체,
시소(접촉 토크로 기움), 컨베이어(표면 속도).

### 구름 마찰의 부호 — 여기서 판이 통째로 멈췄다

접촉점 속도는 접선 `t=(-ny,nx)` 기준으로 **`vt − ω·r`** 이다. 이 부호를 뒤집으면
5° 비탈에서 구슬이 **굴러가지 않고 그 자리에 선다**(실측: 단일 구슬이 12초 동안 정지).
부호가 맞으면 `v ≈ ω·r` 로 수렴한다 — 실제로 비탈에서 `w=23.8, r=22 → 523` vs `vx=517`.

### 반발계수 > 1 로 범퍼를 만들지 마라

`e=1.14` 짜리 범퍼에 낀 구슬이 매 스텝 에너지를 벌어 **y = −2,700,000, 속도 34,000** 으로
화면 밖으로 날아갔다. 범퍼는 **나가는 속도의 하한(kick=640)** 으로 만들고, 별개로
**전역 속도 상한(2600)** 과 각속도 상한을 뒀다.

## 5. 코스 — 통로는 눈으로 못 본다

트랙은 **4~5화면 길이**(5.1~5.7K px). 한 화면에 다 넣으면 장애물을 몇 개 못 놓아
출발 순서가 그대로 도착 순서가 된다.

조각 9종: 못밭 · 지그재그 · 회전 십자 · 시소 · 범퍼 · 컨베이어 · 관문 · 슬라롬 · **마지막 관문**
맵 3종: **핀볼**(범퍼+십자) · **폭포**(비탈+벨트) · **회전목마**(돌아가는 것들)

### 마지막 관문 — 결과가 확정되는 유일한 지점

1차본은 한 판이 11~20초로 짧고 결승이 밋밋해 사용자가 반려했다
("너무 빨리 끝나는 느낌 · 마지막 입구에도 튕겨내는 요소가 있으면 좋겠다 · 아슬아슬한 넓이").

- 트랙 길이를 **2배**로 (3.1~3.4K → 5.1~5.7K px)
- 결승 직전에 **범퍼 7개**로 한 번 흩는다
- 그 아래 **구슬 지름 + 8 (= 52px)** 짜리 구멍 세 개로만 통과시킨다.
  통과 시험으로 확인한 가장 좁은 통과 가능 폭이고, 여기서 줄을 서고 튕겨 나가는 게
  이 게임의 마지막 긴장이다
- 결과: 12구슬 기준 한 판 **17~33초**(평균 22.3초)

### 통과 시험 — 이 장르에서 가장 중요한 검증 도구

구슬 하나를 **34개 x 지점**에서 떨어뜨려 결승까지 가는지 세는 자동 시험을 만들었다.
정적 간격 검사로는 아래를 하나도 못 잡는다.

| 잡은 결함 | 증상 | 규칙 |
|---|---|---|
| 비탈에 파묻힌 장식 못 | 넘을 수 없는 턱 — 구슬이 60초 정지 | 비탈 위 장애물은 비탈면에서 `2R+12` 띄워 **매단다** |
| 수평 칸막이 | 구슬이 그 위에 서 버림 (18/37 정지) | 구멍 쪽으로 기운 **⋀** 로 |
| 레일 쪽으로 기운 면 | 레일과의 사이가 빠져나올 수 없는 주머니 | 양쪽에 통로가 남는 자리에만 놓는다 |
| 비탈 간격 < 낙차 + 구슬 지름 | 위 비탈 끝과 아래 비탈 사이 V 주머니 (37/37 정지) | `dy ≥ drop + 2R + 52` |
| 꼭대기가 평평한 기둥 | 구슬이 얹힘 | ⋀ 로 |
| 고정 길이 회전 날개 | 개수를 늘리면 통로가 구슬보다 좁아짐 | 날개 길이를 **개수에서 역산** |

최종: **3맵 모두 34/34 통과** (핀볼 1건은 못 꼭대기 정중앙 낙하라는 칼날 케이스 —
실제 게임은 출발 위치에 미세 흔들림이 있어 발생하지 않고, 구제 장치가 받는다).

### 구제 장치 2종

그래도 끼는 경우가 남는다. 흔드는 값도 **씨앗에서 뽑아** 재현성을 지킨다.

1. **속도가 0.8초 이상 낮으면** 흔든다
2. **빠른데 앞으로 못 나가면**(벨트·회전체를 도는 중) 흔든다 — 속도만 보면 이걸 못 잡는다

## 6. 화면·조작

| 항목 | 값 |
|---|---|
| 캔버스 | 1080×1440 세로. 트랙 폭 40~972, 오른쪽 108px 은 미니맵 몫 |
| 카메라 | 선두 추종 + 결승 근처 1.34배 줌. 프레임 독립 지수 추종 |
| **미니맵** | 전체 트랙 · 모든 구슬 · 현재 화면 범위 · 구간 눈금 상시 표시 |
| 준비 화면 | **DOM 폼** — 캔버스에 가짜 입력창을 만들면 모바일 키보드·한글 조합·붙여넣기가 반쪽이 된다 |
| 모드 | 꼴찌가 걸린다 / 1등이 뽑힌다 / 몇 등 지정 / 순서 정하기 |
| 가중치 | 이름 뒤 `x3` → 구슬 3개 (최대 9, 전체 20개 상한) |
| 버튼 | 135.2 × **44.4 CSS px** (모바일 실측) |
| 한 판 | 17~33초 (12구슬 기준 실측) |
| 색 구분 | 색 + **번호** — 색만으로는 색각 이상에서 못 가른다 |

## 7. 검증

| 항목 | 결과 |
|---|---|
| 통과 시험 | 3맵 × 34지점 = **102/102** (구제 포함) · 마지막 관문 52px 포함 |
| 재현성 | 씨앗 3개 × 3맵 × 2회 **불일치 0** |
| 균등성 | χ²=2.75 / 3.15 (df=5, 임계 11.07) · 240판 |
| 미완주 | 240판 중 0 |
| 죽은 입력 감사 | 3씬 × 18키 **전수 통과** |
| fps | 120 |
| 모바일 | 414×896 터치 — 준비→출발→빨리 감기 확인, 버튼 44.4 CSS px |
| 콘솔 | 게임 유래 오류 0 |

## 8. 파일

```
portal-fe/public/games/marble-race/
  index.html      준비 화면 CSS + OG/트위터 카드
  CREDITS.md      외부 에셋 0 · 개인정보 · 사행성 · 상표 근거
  js/rng.js       씨앗 난수 (mulberry32) + 셔플 + 씨앗 표기
  js/physics.js   고정 스텝 물리 (충돌·구름 마찰·회전체·시소·컨베이어·속도 상한)
  js/parts.js     코스 조각 9종(마지막 관문 포함) + 통로 치수 규약
  js/courses.js   맵 3종
  js/camera.js    선두 추종 + 결승 줌 + 화면 범위
  js/game.js      참가자→구슬, 자리 셔플, 진행, 모드별 지목, 구제 장치
  js/art.js       트랙·장애물·구슬·미니맵 렌더
  js/meta.js      로컬 저장 (이름·모드·맵·등수·음소거)
  js/setup.js     준비 화면 DOM 폼
  js/main.js      씬·입력·HUD·결과 + 검증 훅(profile/determinism/fairness)
```

## 9. 저작권 / 개인정보

`CREDITS.md` 참조. 요약:
- 물리 엔진은 Box2D·matter.js·planck.js 등 **외부 라이브러리를 쓰지 않고** 직접 구현했다.
- 맵 구성·조각 치수·모드·미니맵 병행 표시·씨앗 재현은 전부 이 프로젝트 설계다.
- 참가자 이름은 **서버로 전송하지 않는다** — 그래서 플랫폼 저장 동기화와 랭킹을 붙이지 않았다.
