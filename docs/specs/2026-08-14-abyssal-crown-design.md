# DESIGN.md — 심연의 왕관 (Abyssal Crown)

탑다운 로그라이크 액션 RPG. 순수 정적 웹(HTML + ES Modules + Canvas 2D), 빌드 스텝 없음.
**클린룸 구현** — 이 저장소의 다른 게임 코드나 공용 라이브러리를 일절 참조하지 않고
백지에서 작성했습니다.

- 규모: JS 9,947줄 / 16개 모듈 + `index.html` 135줄
- 에셋: 폰트 4종 1.6MB (OFL-1.1). 이미지·오디오 파일 **0개**
- 해상도: 1280×720 논리 캔버스, DPR 대응, 레터박스 피트

---

## 1. 세계관

가라앉은 왕국 **아비살라**. 왕은 심연의 왕관을 쓴 채 바다 밑으로 끌려 내려갔고,
왕관은 세 층 아래 옥좌에서 여전히 무언가를 부르고 있다.
마지막 창기사 **레비아**가 삼지창 하나를 들고 매번 다시 잠수한다.

| 지역 | 이름 | 성격 |
|---|---|---|
| 1 | **산호 묘지** | 가라앉은 자들의 정원. 청록 석판 + 산호 침식 |
| 2 | **침몰 성채** | 녹슨 방벽의 심장. 회청 석재 + 금속 이음새 |
| 3 | **심연 옥좌** | 왕관이 잠든 자리. 흑요석 + 금 세공 |

죽으면 **침묵의 영묘**로 돌아온다. 죽음은 실패가 아니라 루프의 문이다.

| `art.js` | 593 | 팔레트·신/희귀도 정의·바닥 타일 베이크·코스틱·문장·공용 드로잉 헬퍼 |

## 3. 전투 설계

### 3.1 조작 (마우스 조준 없음)

| 키 | 동작 |
|---|---|
| WASD / 방향키 | 이동. **바라보는 방향이 곧 공격 방향** |
| J / Z | 기본 공격 — 3연격 (15 / 15 / 27, 3타는 광범위 강타) |
| K / X | 특수 — 회전 베기, 반경 128, 쿨 1.0s |
| L / C | 주문 — 원거리 작살, 탄약 3발 자동 충전 |
| Space / Shift | **대시 — 무적 프레임 0.26s, 모든 후딜 취소** |
| E / Enter | 문 진입 · 상점 구매 · 결정 |
| Esc / P · M · R | 일시정지 · 음소거 · (영묘에서) 전액 환급 |

**조준 보정** (`player.js: assistAim`): 공격 입력 시 정면 ±66° / 300px 내에서
`각도편차 × 220 + 거리` 를 최소화하는 적을 찾아 시선을 스냅합니다.
정지 중이면 100% 스냅, 이동 중이면 65% — **플레이어 의도가 항상 보정보다 우선**입니다.

**입력 버퍼링** (`input.js: buffered`): 누른 뒤 160ms 동안 요청이 유지되어
공격 후딜 중에 미리 눌러둔 대시가 그대로 나갑니다. 콤보·대시·특수 전부 취소 우선순위가 있습니다.

### 3.2 게임 필

| 요소 | 구현 |
|---|---|
| 히트스톱 | 피해량 비례 22~70ms, 치명타 85ms, 보스 처치 500ms. `max()` 로 갱신 — 절대 누적되지 않음 |
| 화면 흔들림 | trauma² 감쇠 + value noise 오프셋 + 미세 회전. 타격/폭발/페이즈 전환마다 주입 |
| 데미지 숫자 | 팝 스케일 + 상승 + 페이드. 같은 지점 160ms 내 틱은 **합산**되어 DoT 스팸 방지 |
| 피격 플래시 | 엔티티 밝기 필터 + 화면 색 워시 (알파 상한 0.3) |
| 임팩트 | 스파크 버스트 + 충격파 링 + 이코르 파티클 + 확률적 바닥 얼룩 |

### 3.3 상태 이상

| 이름 | 효과 |
|---|---|
| 젖음 | 중첩당 받는 피해 +8% (최대 5) |
| 화상 | 0.45초마다 중첩×3.2 도트 |
| 한기 | 중첩당 이동 -11%, **6중첩 시 결빙으로 전환** |
| 결빙 | 완전 정지 1.6초. `frozenBonus`/`shatter` 축복과 연계 |
| 공명 | 만중첩 시 광역 폭발 (에코스 특수 축복 보유 시) |
| 표식 | 받는 피해 +20% |

모든 피해는 `entities.js: applyDamage()` **한 곳**을 통과합니다.
치명타 → 취약 배수 → 피드백 → 상태 부여 → 연쇄 → 사망 처리가 한 자리에 모여 있어
축복이 늘어도 규칙이 갈라지지 않습니다.

## 4. 축복 (Boon) 시스템

**26종 / 5신 / 4희귀도.**

| 신 | 색 | 정체성 |
|---|---|---|
| 넵투나 | 파랑 | 조류 — 젖음, 넉백, 이동 |
| 볼카르 | 주황 | 열수구 — 화상, 폭발 |
| 글라시아 | 보라 | 한류 — 한기/결빙, 파쇄 |
| 에코스 | 초록 | 음파 — 연쇄, 공명, 치명타 |
| 왕관 | 금 | 전설 — 축복 3개 이상 보유 시에만 등장하는 유니크 7종 |

희귀도: 일반 ×1.00 / 희귀 ×1.45 / 서사 ×1.95 / 전설 ×2.60 (모든 수치에 곱연산)

### 슬롯 규칙 (선택에 무게를 주는 장치)

`기본공격 / 특수공격 / 주문 / 대시` 는 **각각 하나만** 가질 수 있습니다.
넵투나의 기본공격 축복을 받으면 볼카르의 기본공격 축복은 그 런에서 사라집니다.
`가호(passive)` 는 무제한 중첩.

네 슬롯이 다 차도 오퍼가 무의미해지지 않도록, 이미 가진 축복은
**한 단계 높은 희귀도의 강화판**으로 다시 제안됩니다 (카드에 "강화" 리본).

### 오퍼 롤 (`boons.js: rollBoonOffer`)

1. 후보 필터 — 슬롯 점유 / 전설 도달 / `minBoons` 조건
2. **신 중복 회피** — 풀이 충분하면 카드 3장을 서로 다른 신에서 뽑음
3. 희귀도 롤 — `luck` (영묘 강화 + 지역 깊이 ×0.12) 이 가중치 꼬리를 밀어올림

## 5. 방 구조와 보상 미리보기

한 런은 **17개 방** (5+1, 6+1, 6+1).

런 시작 시 전체 방 계획을 미리 확정합니다 (`rooms.js: planRun`).
지역마다 축복방 2개 + 상점 1개를 보장하고 나머지를 가중 추첨합니다.

방을 클리어하면 문 1~3개가 열리고, 각 문 위에 **다음 방에서 받을 보상**이
신 문장 / 아이콘으로 떠오릅니다. 문에 다가가면 이름과 설명이 라벨로 뜹니다.
문을 고르면 그 방의 보상이 선택한 것으로 **덮어써집니다** — 미리보기가 거짓말을 하지 않습니다.

보상 종류: 축복 · 금화 · 심연 결정 · 회복 · 최대 체력 · 상점 · 수호자

**상점**: 좌대 3개에 무작위 3종 (회복/최대체력/봉인된 축복/결정/주문 증폭기).
가까이 가면 하단 프롬프트에 이름·효과·가격이 뜨고 E로 구매.

## 6. 적 설계 — "예고 없는 공격은 없다"

모든 적 공격은 **바닥/공중에 도형이 먼저 그려집니다.** 도형은 4종:
`cone`(부채꼴) / `line`(직선) / `circle`(원) / `ring`(집중 링).

예고는 시간에 따라 **채워지고**, 마지막 14% 구간에서 **점멸**합니다.
가득 차기 전에 대시로 빠져나가는 것이 이 게임의 기본 문법입니다.

| 지역 | 적 | 패턴 |
|---|---|---|
| 산호 묘지 | 산호게 | 직선 예고 후 돌진 (예고 중 약하게 추적) |
| | 포자충 | 링 예고 후 3방향 포자 |
| | 뼈산호 술사 | 플레이어 이동을 0.34초 예측한 지점에 원형 지연 폭발 |
| 침몰 성채 | 성채 파수병 | 정면 100° 방패 (피해 65% 감소) + 부채꼴 대검 스윕 |
| | 작살병 | 장거리 직선 예고 후 초고속 작살 |
| | 부유 포탑 | 링 예고 후 9발 방사 × 3연사 |
| | 심해 사냥개 (엘리트) | 3연속 돌진, 2번째부터 예고 시간 단축 |
| 심연 옥좌 | 공허 사제 | 순간이동 + 12스텝 나선 탄막 |
| | 심연 촉수 | 지하 잠행으로 추격 → 원형 예고 → 융기 슬램 |
| | 왕관 파편 (엘리트) | 궤도 칼날 3개를 두르고 돌진 |

난이도는 `tierFor(biome, room)` 으로 체력 +8.5%/방, 피해 +5%/방 스케일.
방은 1~3 웨이브로 구성되고, 예산(`planWaves`)이 적 조합을 뽑습니다.

## 7. 보스

공통 기반(`bosses.js: Boss`): 가중 패턴 추첨 + **직전 패턴 반복 금지**,
체력 임계값 기반 페이즈, 페이즈 전환 시 무적 정지 + 포효 + 화면 플래시 + 배너.

### 티데우스, 산호의 왕 (산호 묘지) — 2페이즈
- P1: 집게 내려찍기 → **확장 충격파 링 2~3연** / 산호 가시 벽 (부채꼴 3~5줄) / 돌진 (벽 충돌 시 경직)
- P2 (55%): 회전 스윕 추가, 잡몹 소환, 이동속도 +28%, 링 3연, 가시 5줄

### 오르카스, 심연의 감시자 (침몰 성채) — 2페이즈
- P1: 회전 레이저 스윕 / 유도 구체 3발 / 돌진
- P2 (50%): 십자 4중 레이저 회전, 구체 5발, 돌진 경로에 지뢰, 격자 폭격, 부안(副眼) 개안

### 네레이드, 심연의 왕관 (심연 옥좌) — **3페이즈**
- P1: 방사형 탄막 (파도마다 각도 오프셋 → 안전 통로가 엇갈림) / 촉수 다중 슬램
- P2 (66%): 순간이동 3연 + 추격 탄, 궤도 왕관 소환, 왕관 파편 호출
- P3 (33%): **아레나 외곽 110px 가 피해 지대로 전환**, 심연 노바(광역 + 탈출 링), 6중 왕관 광선

보스전 카메라는 플레이어-보스 **중점을 추적하고 필요한 만큼 줌아웃**해서
보스가 화면 밖으로 나가지 않도록 보장합니다 (`game.js: updateCamera`).

## 8. 메타 진행 (침묵의 영묘)

죽든 이기든 **심연 결정**이 남습니다 (도달 깊이 + 처치 드랍 + 승리 보너스 40).

강화 10종 (localStorage `abyssal-crown.save.v1`):

| 강화 | 최대 | 효과 |
|---|---|---|
| 심연의 심장 | 5 | 최대 체력 +12/레벨 |
| 삼지창 연마 | 5 | 모든 피해 +6%/레벨 |
| 조류의 발 | 4 | 이동 속도 +4%/레벨 |
| 이중 조류 | 2 | 대시 충전 +1 (최대 연속 3회) |
| 심연의 총애 | 3 | 축복 희귀도 가중치 상승 |
| 귀환의 맹세 | 2 | 치명적 피해 무효화 (방마다 재충전) |
| 파편 자석 | 4 | 결정 획득 +20%/레벨 |
| 주문 각인 | 3 | 주문 탄약 +1, 주문 피해 +8%/레벨 |
| 예리한 감각 | 4 | 치명타 확률 +3%/레벨 |
| 심연의 계약 | 3 | 금화 +15%, 시작 금화 +25 |

`R` 로 **전액 환급** — 빌드 실험 비용을 0으로 만들어 메타 강화가 잠금이 아니라
선택지로 기능하게 합니다.

저장 데이터는 로드 시 전 필드를 검증·클램프합니다. 손상되거나 구버전이면
예외를 던지지 않고 기본값으로 강등되고, 시크릿 모드처럼 스토리지가 막히면
메모리 세이브로 계속 플레이됩니다.

## 9. 렌더 파이프라인

고정 60Hz 시뮬레이션 (최대 5스텝 캐치업) + 가변 렌더.

```
배경(그라디언트 · 광선 · 마린스노우 3중 시차)
  └ 카메라 변환 [흔들림 오프셋 · 회전 · 줌]
      바깥 장식 → 아레나 바닥(베이크) → 데칼 → 장판 → 예고 →
      링/가시 → 아레나 테두리 → 문/좌대 →
      액터(Y정렬) → 투사체 → 빔 →
      파티클(일반) → 파티클(발광, lighter) → 충격파 → 연쇄 아크 → 숫자
  └ 화면공간: 코스틱 → 비네트 → 플래시 → 보스 인트로 → 배너 → HUD → 화면밖 마커 → 필름 그레인
```

**줌**: 평상시 1.5배(가시 영역 853×480), 보스전은 두 대상이 항상 담기도록 0.82~1.28 동적.

**화면 밖 마커**: 열린 문 · 미구매 좌대 · 잔존 적 3마리 이하일 때 화면 가장자리에
방향 화살표 + 문장 배지를 그립니다. 줌인된 카메라에서 목표를 잃지 않게 하는 장치입니다.

## 10. 벤치마크작에서 무엇을, 어떻게 옮겼는가

| 벤치마크작 | 이 게임 | 옮긴 방식 / 의도적 차이 |
|---|---|---|
| Boon (올림포스 신) | 축복 (심연의 신) | **슬롯 배타성**을 그대로 계승 — 하나를 고르면 그 자리가 닫힌다는 선택의 무게가 핵심. 신을 4+1로 줄이고 각 신이 상태이상 1종을 소유하게 해 빌드 방향이 즉시 읽히도록 함 |
| Boon 희귀도 (Common~Heroic) | 4단계 + 강화 재제안 | 후반 오퍼가 죽는 문제를 "같은 축복의 상위 희귀도" 로 해결 |
| Duo/Legendary Boon | 왕관 축복 7종 | 복잡한 전제 조건 대신 **축복 3개 이상 보유** 라는 단일 게이트로 단순화 (KISS) |
| 문 위 보상 아이콘 | 동일 | 문 선택 = 빌드 계획. 선택한 문이 실제 보상을 덮어써 미리보기가 항상 참 |
| Dash(Dodge) | 대시 | i-frame + 후딜 취소 + 버퍼링까지 동일. 충전식(메타로 최대 3회)으로 확장 |
| Cast (블러드스톤) | 주문 | 회수형 대신 **시간 자동 충전**으로 단순화. 회수 이동이 없어 조작 부하가 낮음 |
| 히트스톱 / 셰이크 / 숫자 | 동일 | 피해량 비례 스케일, 치명타 별도 티어 |
| 적 공격 예고 | 동일 | 4가지 도형 + 채움 진행 + 임박 점멸 |
| 보스 페이즈 전환 | 동일 | 무적 정지 + 포효 + 플래시 + 패턴 추가. 네레이드는 3페이즈 + 아레나 변형 |
| 메타 통화 / 영구 강화 | 심연 결정 / 영묘 | **무료 전액 환급**을 추가해 빌드 실험 비용 제거 |
| 무기 4종 + 각인 | 삼지창 1종 | **의도적 축소.** 무기 4종을 얕게 만드는 것보다 1종을 깊게 튜닝하는 쪽을 택함 |
| 서사 · 대화 · 관계 | 없음 | 벤치마크작의 절반은 대화 시스템이지만, 이번 과제의 축은 전투/빌드/진행이라 범위에서 제외 |
| Call (신의 부름 게이지) | 없음 | 축복 슬롯 설계가 이미 성립해 추가 자원 축을 넣지 않음 (YAGNI) |
| 거울(Mirror) 양자택일 | 단일 라인 강화 | 10종 × 다단계로 충분한 선택폭을 확보 |

## 11. 검증

`python3 -m http.server 8094` + chrome-devtools 자동 조작으로 검증했습니다.
하네스는 실제 키보드 이벤트(`KeyboardEvent`)를 디스패치해 게임의 입력 계층을 그대로 통과합니다.

확인 항목: 전투/처치/드랍, 웨이브 진행, 방 클리어→보상→문 개방, 문 선택→다음 방,
축복 카드 선택 및 빌드 반영, 상점 구매, 보스 3종 전 페이즈 전환, 사망→결산→영묘,
영묘 강화 구매의 localStorage 영속, 그리고 **3지역 17방 완주 승리**.

**콘솔 에러 0** (favicon 404 포함 0). FPS 100~120 유지.

### 검증 중 발견해 고친 실제 버그

1. **고빈도 디스플레이에서 입력 유실** — 120Hz에서는 렌더 프레임의 절반이 고정스텝을
   0회 실행하는데, `endFrame()` 이 매 렌더 프레임마다 edge-trigger 입력을 비웠습니다.
   그 프레임에 들어온 키 입력은 시뮬레이션이 보기 전에 사라졌습니다.
   → 스텝이 1회 이상 돈 프레임에서만 입력을 회수하도록 수정 (`game.js: loop`).
2. **보스가 화면 밖으로 이탈** — 고정 줌 + 방 클램프 조합에서 보스가 완전히 시야를
   벗어났습니다. → 중점 추적 + 동적 줌아웃.
3. **캔버스 blur 필터로 인한 프레임 저하** — 액터별 그림자와 아레나 그림자에
   `ctx.filter = 'blur()'` 를 쓰면서 33fps. → 그라디언트/다중 스트로크로 대체, 87→120fps.

## 12. 남은 한계

- **무기 1종.** 삼지창 외 선택지가 없어 런 간 전투 리듬 변화는 축복에만 의존합니다.
- **서사 부재.** 지역 이름과 축복 플레이버 텍스트가 세계관의 전부입니다. NPC·대화·해금 서사가 없습니다.
- **1루프 종결.** 클리어 후 난이도 상승 재도전(벤치마크작의 Heat/Pact)이 없습니다.
  `tierFor()` 에 `loop` 인자는 뚫어뒀지만 UI가 없습니다.
- **적 경로 탐색 없음.** 아레나를 의도적으로 개방형으로 만들어 회피했습니다.
  장애물을 넣으려면 별도 시스템이 필요합니다.
- **밸런스는 자동 플레이 기준.** 스크립트 플레이어로 완주까지 확인했지만
  사람 기준 난이도 곡선은 조정되지 않았습니다. 특히 3지역 보스 체력(약 6,800)은
  축복 5~7개 빌드를 전제로 한 수치입니다.
- **키보드 전용.** 게임패드·터치 미지원 (좁은 화면에서는 안내 문구 표시).
- **오디오 미세 조정.** 생성 BGM은 4마디 코드 진행 1개를 순환합니다. 곡의 전개는 없습니다.
