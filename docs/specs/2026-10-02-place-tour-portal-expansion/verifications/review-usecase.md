# Usecase 리뷰 — place 관광 포털 확장

대상: `spec.md` · `planning/requirements.md` · `planning/test-quality.md` · `context/open-questions.yml` · `docs/adr/ADR-0104-place-tour-portal-expansion.md`
관점: 여행자가 실제로 얻는 것 — 행사 찾기(진행 중·이번 주말), 근처 행사·숙소, 여행코스, 끝난 행사, 영문 사용자, 모바일. 얇은 페이지 위험과 빠진 흐름.

## 체크리스트 판정

|---|---|---|---|
| 1 | 행위자-목표 짝 | 부분 | 여행자·검색엔진·운영자는 있다(spec.md:7-11). 영문 사용자는 따로 없다 → U6 |
| 2 | 주/대안/예외 흐름 | 부분 | 주 흐름(칩→상태 칩, 상세 절, 지역 허브)은 있다. 키워드 검색, 기존 상세 절로 끝난 행사가 새는 경로, 허브 카드·모바일 시트가 빠졌다 → U2·U3·U4 |

## 이슈

### U1 [AC] 기본 필터와 정렬을 API 계약으로 나타낼 수 없다 — 차단 아님, 착수 전 수정
- spec.md:52 의 `eventStatus` 는 `ONGOING · WEEKEND · UPCOMING · THIS_MONTH` 네 값이다. 그런데 spec.md:54 는 상태 칩 기본을 「진행 중+예정(종료 제외)」으로 두고, spec.md:70 「근처 행사」도 「종료 제외」를 요구한다. 네 값 중 어느 것도 이 둘을 나타내지 못한다(`THIS_MONTH` 는 이번 달로 잘린다).
- 정렬도 비어 있다. spec.md:68·70 은 「진행 중 먼저 · 시작일 오름차순」을 요구하지만 SR-4 에 정렬 값이 없다. 행사 칩 목록(spec.md:54)은 정렬 자체가 정해지지 않았다.
- 수정안: `eventStatus` 에 `NOT_ENDED`(= 종료일 ≥ 오늘)를 더하거나 쉼표 다중값을 허용한다. `sort=eventStart` 를 정의하고, 「진행 중 먼저」는 「`NOT_ENDED` + 시작일 오름차순」이면 자연히 만족되는지 확인해 한 줄로 적는다. 진행 중 행사는 시작일이 오늘 이전이라 먼저 온다. T10 에 두 값의 요청 JSON 을 더한다.

### U2 [대안 흐름] 기존 상세 절로 끝난 행사가 계속 노출된다
- 행사 상세에 기존 「같은 분류 가까운 곳」과 지역 문구가 그대로 붙는다. 그런데 이 값은 재색인 시점에 날짜를 보지 않고 계산된다. `RegionAggregator` 는 같은 시군구·유형·분류를 모두 묶고(search/domain/.../RegionAggregator.kt:55-61), 서버 렌더(AttractionPageRenderer.kt:372)와 화면(placeAttributes.ts:158-163)이 그 값을 그린다.
- 「비슷한 곳」도 같은 문제다. `similar.py` 가 `(lang, content_type_id)` 로 묶으므로(tools/embed/src/embed/similar.py:64-65) 행사의 비슷한 곳은 다른 행사이고, 그 안에 종료된 것이 섞인다.
- 행은 지우지 않으므로(spec.md:38) 끝난 행사는 해마다 쌓인다. 그러면 「종로구 축제 n곳」의 n 이 계속 커지고, 가까운 곳 링크는 점점 종료·noindex 페이지로 채워진다.
- spec.md:14 「유지」는 이 절들을 그대로 두라고만 하고, 새 유형에서 어떻게 보일지는 정하지 않았다.
- 수정안: SR-5 에 유형별 기존 절 처리를 한 줄로 정한다. 예를 들어 「행사 문서는 같은 분류 가까운 곳·비슷한 곳·지역 문구를 그리지 않고 SR-6 근처 행사(종료 제외)로 대신한다」. T11 골든에 행사 문서의 해당 절 부재를 넣는다.

### U3 [대안 흐름] 키워드로는 행사를 찾을 수 없다
- 「전체」는 관광 분류만 보낸다(portal-fe/src/pages/place/PlacePage.tsx:272). spec.md:55 도 그대로 둔다.
- 그래서 「보령 머드축제」를 검색창에 친 사용자는 0건을 받는다. 행사 칩을 눌러야만 나온다. 「행사 찾기」의 가장 흔한 진입로가 빠졌다.
- 수정안: 둘 중 하나를 고른다. ① 키워드가 있을 때 「전체」에 `festival` 을 `NOT_ENDED` 조건으로 합친다. ② 0건일 때 「행사에서 n건」 안내 칩을 띄운다. 어느 쪽이든 SR-4 에 적고 T16 에 넣는다. 자동완성(`suggestPlaces`)이 종료 행사를 내는지도 같은 절에서 정한다.

### U4 [주 흐름] 허브 목록 카드와 모바일 상세 시트에 기간·상태가 없다
- 허브 목록은 `PlaceCard` 가 그린다(PlacePage.tsx:1149). 데스크톱 열과 모바일 바텀시트는 `AttractionDetailBody` 를 함께 쓴다(PlacePage.tsx:1241-1258). 이 본문은 분류·주소·전화·개요만 보여 준다.
- SR-5 는 상세 페이지·서버 렌더만, SR-6 은 근처·지역 허브만 기간을 다룬다. 정작 행사 칩으로 고른 목록에서는 기간이 안 보인다. 모바일에서 행사를 고르는 화면이 바로 이 카드와 시트다.
- 수정안: SR-4 또는 SR-5 에 「행사 카드·상세 본문(시트)에 기간 + 상태 문구(SR-5 와 같은 TS 판정)」를 더한다. T16·T17 에 카드·시트를 넣는다.

### U5 [사전 조건] 행사 개요가 늦게 채워지면 짧은 행사는 색인되지 못하고 끝난다
- 행사가 색인되고 sitemap 에 실리려면 개요가 있어야 한다(AttractionPageRenderer.kt:54, AttractionPage.tsx:158, spec.md:80).
- 그런데 개요 보강 `pick` 은 관광 분류를 앞에 두고 나머지를 한 묶음으로 미룬다(place/ingest/src/backfill_overview.py:65-66). 그래서 `festival` 은 음식·쇼핑·숙박 수천 건과 같은 순위에 선다. ADR-0104:55 도 「며칠에 걸쳐 채워진다」고 적었다.
- 2-3일짜리 행사는 개요가 채워지기 전에 끝날 수 있다. spec.md:28 은 반복정보에서만 코스 우선순위를 정했다.
- 수정안: SR-1 에 「개요·이용정보 보강은 `festival` 중 종료되지 않은 것을 시작일이 가까운 순으로 가장 앞에 둔다」를 더한다. T6 옆에 `pick` 순서 검사를 하나 둔다.

### U6 [경계·영문] 영문 허브에 「여행코스」 칩이 뜨면 항상 0건이다
- 코스는 국문만 있다(spec.md:21). 그런데 spec.md:54 는 칩 추가를 언어 구분 없이 적었다.
- 영문 상태 문구(「진행 중」「D-n 시작」「종료된 행사」, spec.md:60)와 상태 칩 라벨의 영문 표기도 정하지 않았다.
- 수정안: 「`/en` 은 여행코스 칩을 그리지 않는다」를 넣고, 영문 문구 셋(예: Ongoing / Starts in n days / Ended)을 SR-5 에 고정한다. 그러면 서버와 화면이 같은 문자열을 쓴다(T11·T12 골든 대상). 영문 숙박은 211건이라 5km 근처 숙소가 대부분 0건이다. 이 경우 절이 숨는 것(spec.md:72)이 정상 동작임을 T16 에 명시한다.

### U7 [경계·얇은 페이지] noindex 두 조건의 합성과 숙박 페이지의 가치가 정해지지 않았다
- 기존 noindex 는 「개요 없음」이다(AttractionPageRenderer.kt:54). SR-7 은 「종료 + 31일」을 더하지만(spec.md:76) 둘이 OR 인지 적지 않았다. T3(test-quality.md:10)에도 「개요 없음 + 진행 중」 조합이 없다. 수정안: SR-7 에 `noindex = 개요 없음 OR 종료 + 31일 이후` 를 적고 T3 에 조합 두 줄을 더한다.
- AdSense 는 2026-08-31 에 「가치가 별로 없는 콘텐츠」로 반려됐다. 사유는 TourAPI 개요를 그대로 쓴 관광지 상세였고(ADR-0076:4, :63-65), 그래서 `attraction-end` 지면이 꺼져 있다(:51).
- 이 스펙은 같은 성격의 페이지를 약 4,600개 더한다(ADR-0104:55). 그중 숙박 2,990건은 본문이 개요와 입·퇴실 원문 키뿐이다(spec.md:61). 행사(상태 판정·근처 행사)와 코스(구성 연결)에는 자체 가공이 붙지만, 숙박에는 없다. 그리고 근처 절은 서버 렌더에 들어가지 않는다(spec.md:71).
- 수정안: SR-5 또는 SR-7 에 두 가지를 적는다. ① 새 유형에서도 `attraction-end` 지면은 꺼 둔다(재심사 기준과 같다). ② 숙박을 정적 sitemap 에 넣는 조건을 정한다. 예를 들어 「개요 + 서버 렌더에 지역 문구·근처 관광지 요약 같은 자체 가공 절이 하나 이상」을 조건으로 하고, 조건이 서기 전까지는 sitemap 에서 뺀다. 결정 근거는 ADR-0104 「결과」에 한 줄 남긴다.

## 잘된 점
- 상태를 저장하지 않고 판정 함수 하나로 모았다(spec.md:46). KST 자정·일요일·당일 경계가 테스트까지 이어진다(T1·T2).
- 끝난 행사를 200 으로 두고 30일 유예 뒤 noindex 하는 흐름(spec.md:76)은 지난 행사를 찾아온 사용자를 끊지 않는다. 「근처 행사(종료 제외)」가 다음 갈 곳을 준다.
- 숙박에서 예약 링크를 뺀 경계(spec.md:61)는 deal 규칙과 충돌하지 않는다.

## 남는 위험(범위 밖으로 명시됨)
- 통합 검색(ADR-0090)은 행사 상태를 반영하지 않는다(spec.md:119). `/search` 에서 끝난 행사가 날짜 없이 나온다. 사람 트래픽이 거의 없어 지금은 수용 가능하다.

VERDICT: REVISE
