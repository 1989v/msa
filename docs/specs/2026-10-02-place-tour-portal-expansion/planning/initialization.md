# 초기화 — place 관광 포털 확장 (행사·숙박·여행코스 + 공공데이터 2단계)

## 요청 (2026-10-02)

사용자와 확정된 범위를 그대로 옮긴다. 인터뷰는 생략했다 — 아래 항목이 이미 결정된 답이다.

- 1단계(운영 키로 호출 확인됨): 축제·공연·행사(`searchFestival2`) · 숙박(`searchStay2`, 정보만) · 여행코스(유형 25, 구성은 `detailInfo2` subcontent).
  노출은 상세 서버 렌더(ADR-0103 경로, 유형별 본문 절) · 지역 허브 「이번 달 행사」 · 상세 「근처 행사·근처 숙소」 · 검색 필터 「진행 중 / 이번 주말 / 예정」 · 코스 구성 순서.
- 행사 만료(결정됨): 상태는 저장 플래그가 아니라 시작일·종료일을 두고 조회·렌더 시점에 KST 로 판정. 수집은 별도 CronJob 매일, 재색인과 합치지 않는다.
  종료 페이지는 200 + 「종료된 행사」, 종료 30일 뒤부터 noindex + sitemap 제외. 서버 렌더가 붙이는 noindex 가 정본.
- 2단계(data.go.kr 활용신청 필요, 지금 `SERVICE_KEY_IS_NOT_REGISTERED`): 무장애 여행 · 관광지 집중률 · 연관 관광지 · 두루누비 · 고캠핑 · 관광사진 · 웰니스 · 빅데이터 방문자수 · 기상청 단기·중기예보 · 에어코리아 · 반려동물 동반여행.
  응답 필드를 아직 실호출로 못 봤다 — 승인 뒤 첫 호출 표본으로 적재·화면을 정한다.

## 코드에서 확인한 사실

- `sync_tour.CONTENT_TYPES` 는 5개 유형(12·14·28·38·39 / 76·78·75·79·82)뿐이고, 정기 목록 동기화 CronJob 은 없다(`--job=sync` 는 수동).
- 행사의 신분류 `EV` 는 `LCLS1_MAP` 에서 `culture` 로 접힌다 — 그대로 넣으면 문화시설 목록·지역 건수에 행사가 섞인다.
- `attractions` 에 행사 날짜 컬럼이 없고 최신 마이그레이션은 V22 다. bulk 는 전체 동기화이고 보강 필드만 `syncFrom` 의 `?:` 로 보존된다.
- place sitemap 은 portal-fe 빌드 시점에 시도 조각(10,000건 창)으로 훑어 만든다 — 빌드 사이에 행사 상태가 낡는다.
- 외부 :443 egress 는 라벨로 place-ingest 파드에 이미 열려 있다(`11-allow-egress-https-public.yaml`).
