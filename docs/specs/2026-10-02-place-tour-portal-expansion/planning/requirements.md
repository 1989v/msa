# 요구사항 — place 관광 포털 확장

## 목표

1. place 에 행사·숙박·여행코스를 더해 관광지 탐색에 시간(언제 열리나)·숙소·동선을 붙인다.
2. 행사 페이지는 날짜가 지나도 낡지 않는다 — 상태는 조회·렌더 시점 KST 판정, 만료는 noindex·sitemap 으로.
3. 승인이 필요한 공공데이터 12종을 같은 틀에 API 마다 독립적으로 붙인다.

## 범위

### R1 수집 (1단계)
- `CONTENT_TYPES` 확장: 행사 15/85 · 숙박 32/80 · 여행코스 25(국문만). 행 정규화를 목록 호출에서 분리해 세 오퍼레이션이 함께 쓴다.
- 행사 `searchFestival2`, 숙박 `searchStay2`, 코스 `areaBasedList2`. 별도 CronJob 매일 KST 03:10(구글 보강 03:20 과 안 겹치게), 재색인과 분리.
- 행사 날짜 `yyyyMMdd` → ISO, 실패는 값만 None + 건수(한 행이 bulk 전체를 깨지 않게). 좌표 없는 행 제외는 §0 ① 명시 예외 + 건수.
- 개요·이용정보 보강은 종료 아닌 행사를 먼저(시작일 순).
- 수용 기준: 옛 행 4건(2775576 · 1891566 · 2948191 · 3112217)의 유형·지역이 채워진다.

### R2 저장
- 행사 시작일·종료일 · 목록 행 원문을 새 컬럼으로(V23). 왕복 경로 전부(도메인·엔티티·커맨드·View·DTO·`UPSERT_FIELDS`·search-batch `PlaceApiClient`)를 함께 갱신.
- 파생 분류에 `festival` · `stay` · `course`. 「숙소」 = `category=stay`(캠핑장 포함). 관광 분류(`SIGHT_CATEGORIES`)와 지역 건수 정의는 그대로.

### R3 일정 규칙과 만료
- 유효 기간 정규화 · 상태(진행 중 · 예정 · 종료 · 날짜 없음) · 필터 범위(진행 중 · 이번 주말 · 예정 · 이번 달 · 종료 아님)를 search:domain 한 객체가 갖는다. 오늘은 호출자가 `Clock` 으로 계산해 넘긴다.
- 색인은 유효 시작일·유효 종료일을 싣는다(종료일 없는 행사가 범위 질의에서 빠지지 않게).
- 종료 페이지 200 + 「종료된 행사」, `noindex = 개요 없음 OR 종료 + 31일`(서버 렌더 정본), 정적 sitemap 에서 행사 제외, 동적 행사 sitemap(호스트 제한 · 폴백 없음 · 503 그대로).

### R4 노출
- 서버 렌더 유형별 본문(행사 기간·장소·상태 문구 국/영 · 숙박 정보 · 코스 구성 순서), JSON-LD(`Event` · `LodgingBusiness` · `TouristTrip`), 서버 렌더 출처 문구.
- 지역 허브 「이번 달 행사」, 상세 「근처 행사 · 근처 숙소」(기존 편의시설 캐로셀의 숙박 몫을 옮김), 검색 필터, 키워드 「전체」의 행사 합류, 카드·바텀시트의 기간·상태.
- 기존 「같은 분류 가까운 곳」·지역 문구·비슷한 곳에서 종료 행사 제외.
- 숙박은 정보만 — 예약·제휴·여행 상품 딥링크 없음(ADR-0069 와 분리). 새 유형에 광고 지면 없음. 숙박 sitemap 은 개요+사진.

### R5 2단계 API
- 승인 순서대로 각각 독립 배포. 승인 뒤 첫 호출 표본을 `implementation/` 에 남기고 3규칙대로 전부 적재, 화면은 표본 확인 뒤 확정.
- 날씨·대기는 CronJob 선수집, 요청 경로 외부 호출 없음.

## 범위 밖
- TourAPI 에 없는 옛 행 53건 삭제(사용자 확인 대기) · 숙박 예약·가격 · 기존 5개 유형의 정기 목록 동기화 · 통합 검색 색인 반영

## 제약
- OCI 무료 단일 노드(4 OCPU/24GB) · 운영 MySQL 버퍼 풀 128MB → 큰 OFFSET 금지(키셋) · 재색인 기한 30분 · 배치 힙 약 256MB
- 외부 데이터 3규칙(원천 전부 적재 · 파생 컬럼 · 전체 동기화 필드 목록 함께 갱신) · 원천 대장 갱신 필수 · 공공누리 유형별 출처 표시
- 요청 경로에 외부 호출 없음 · 새 외부 egress 가 생기면 네트워크 정책 · Flyway 커밋 후 수정 금지
- 이미지: content(JVM, place 폴드 호스트) + place-ingest, search·search-batch(`search/domain` 변경은 search-batch 를 수동 재빌드) · 단계별 배포와 운영 확인 · 운영 계정 키의 일일 호출 한도 관리
- 첫 운영 호출 표본(Q1·Q3) 전에는 수집 코드를 머지하지 않는다.

## 재사용
`sync_tour.fetch_area_based`·`_ldong`·`categorize`·`parse_modified` · `sync_pet_tour` 실패 격리 · `backfill_media` `infoRaw` · `Attraction.syncFrom` ·
`AttractionApiReindexTasklet` 키셋 훑기·`RegionProjection` · `SearchAttractionService` 의 `Clock` · `AttractionPageRenderer` · 속성 패싯 파라미터 패턴 · nginx 렌더 프록시와 네트워크 정책 19·20 · `prerender-seo.mjs` sitemap 분할.

## 실패 의미 · 관측
- 수집: 유형·언어 하나가 실패해도 나머지는 받는다. 유형·언어별 호출 수·적재·좌표 제외·날짜 변환 실패 건수 로그.
- 재색인: 코스 구성 해석 실패는 그 필드만 비우고 진행 + 경고 건수. 코스 매칭 실패 · S>E · 날짜 없음 건수.
- 행사 sitemap: 조회 실패는 503(빈 200·SPA 셸 200 금지). URL 수·생성 시간 로그.
- 롤백: 수집 잡을 먼저 멈추고 이미지를 되돌린다(V23 은 nullable 추가뿐).
