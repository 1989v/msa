# 웹 베타 공개 준비

사용자 요청: 전체 게임 완성 전이라도 충분히 플레이 가능해지면 웹에서 베타로 공개한다. 이번 단계는 배포 산출물을 준비하며 외부 공개는 아직 하지 않는다.

## 첫 베타 범위

- 나루로 섬 탐색, 이동·점프·시야 조작.
- 상승 기류 → 활공 → 두 착지대 경로.
- 프리즘 집기·회전·배치 → 받침 퍼즐 완료 → 초기화 후 재도전.
- PC 키보드/마우스와 터치 조작. 진행 저장은 없으며 새로고침하면 초기화됨을 안내.

전투·세 유적·엔딩·최종 아트·게임 저장은 후속 버전이다. 전체 PRD의 완료율과 베타 공개 준비도를 구분한다.

## 공개 전 필수 조건

- [x] 독립 배포 폴더를 HTTP로 열어 게임 로딩·로컬 GLB 로딩 확인.
- [x] PC 키/마우스 및 390px 터치로 퍼즐 완료·reset 재시작.
- [x] 배포 패키지에서 비행 경로 완주·reset (고정 시간 스텝 입력 검사).
- [ ] 비행 경로의 실제 키/터치 연속 완주 및 실기기 성능 점검.
- [ ] 운반 중 pause/취소/벽 경계·배치 거부 및 복귀를 한 번의 플레이 패스로 확인.
- [x] 390×844 모바일 에뮬레이션에서 퍼즐 터치 조작, 버튼 최소44px, 가로 넘침 없음.
- [ ] 작은 가로 화면 및 운반 취소/벽 경계 추가 점검.
- [ ] 실제 공개 주소와 호스팅 연결 방식 확정, 공개할 산출물 검토 후 배포.

검증 비용을 줄이기 위해 위 항목은 통합 플레이 한 번으로 모아 확인한다. 이미 통과한 전체 단위 검사는 변경 사유 없이 반복하지 않는다. 실기기 성능은 확인한 기기만 명시하고 미확인 기기를 지원 완료로 표시하지 않는다.

## 배포 방식

백엔드 없이 정적 호스팅 가능한 폴더로 만든다. 외부 CDN 없이 JS/CSS/GLB를 함께 제공하며 하위 경로에서도 동작해야 한다. 후보 공개 경로는 `/games/skybound/`이지만 현재 기존 게임 카탈로그·다른 게임 소스·인프라는 수정하지 않는다. 호스팅이 정해지면 이 산출물만 연결한다.

첫 공개 전에는 HTML/JS/CSS를 장기 immutable 캐시로 두지 않는다. 원자적으로 폴더/호스팅 버전을 교체하고 문제가 있으면 이전 산출물로 되돌린다. 공개할 폴더에는 소스맵/개발 문서/다른 게임이 포함되지 않는다.

## 이어서 할 일

패키징 → 패키지 기준 통합 플레이 및 필요한 수정 → 공개 주소/산출물 확정 → 배포 → 해당 URL 로딩 확인. 전투 개발보다 첫 베타 공개 경로를 우선한다.
