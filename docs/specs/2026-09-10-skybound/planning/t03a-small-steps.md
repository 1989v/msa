# T03A · 남은 한도에 맞춘 활공 작업 분할

사용자 최신 한도 안내: 5h 12%. 잔여량 직접 조회 도구 없음. 작은 단위마다 검사·저장한다.

## T03A-1 · 순수 규칙 (이번 단위)

- SR-2의 펼침/접힘, 기력 소진, 착지 시 접힘, 원통형 기류 판정과 상승·회복 규칙.
- 기존 simulation·입력·뷰어는 변경하지 않는다. 이번 결과는 실제 데모에 아직 연결되지 않는다.
- 렌더러/DOM 의존 없는 함수와 node:test, 수치·경계·호출 책임을 README에 저장.

### 규칙 모듈의 연결 원칙

`stepGliding(state, frame, volumes)`는 전달된 공유 기력·돛 상태·수직속도를 읽고 새 결과를 반환한다.
별도 내부 기력 저장소를 만들지 않는다. `frame`은 fixed dt, 접지 여부, 현재 위치와 1회 액션을 제공한다.
접힌 상태의 수직속도는 호출부 중력 계산에 맡긴다. 펼친 상태에서는 낙하/상승 목표 속도로 제한된 가속만 적용한다.
기류가 겹쳐도 상승 효과를 무제한 합산하지 않는다. 지상 회복/달리기 소비/공중 활공 소비는 하나만 선택한다.

## T03A-2 · 이동 코어 연결

- stamina는 T02A simulation의 단일 값이다. 달리기/활공이 같은 프레임에 이중 소비하지 않게 한다.
- 고정 1/120초 step에서만 규칙을 적용한다. 프레임마다 입력 pulse를 여러 step에 반복하지 않는다.
- 지상 점프 press와 공중 돛 toggle을 press 직전 접지 상태로 구분한다. 한 press로 점프와 펼침을 동시에 하지 않는다.
- coyote·착지 직전 jump buffer의 우선순위를 테스트로 확정하고 기존 이동11개 검사를 유지한다.
- 활공 수직 결과에 기존 gravity를 다시 더하지 않는다. 착지 판정 후 접힘을 같은 snapshot에 반영한다.
- water respawn은 돛·기류 상태와 입력을 초기화하면서 quest progress는 보존한다.

## T03A-3 · 돛 표현과 조작 연결

- 기존 AnimationBridge는 gliding mode를 거부한다. 새 상태에 맞는 pose/표현을 함께 추가한다.
- PC Space·터치 점프 액션을 공통 입력 명령으로 연결한다. pause/blur/reset 회귀 유지.
- 외부 게임 참고 없이 원화의 돛 방향을 기준으로 자체 표현한다.
- 실제 브라우저에서 펼침/접힘·착지·소진·취소를 확인한다.

## T03B · 필수 경로

- 눈에 보이는 기류 하나와 중간 착지점 둘을 만든다.
- 기본 기력으로 완주 가능, 실패 시 안전 지점 재도전 및 진행 보존을 확인한다.

최종 아트·실기기 성능·필수 경로 완주는 T03A-1의 통과 기준에 포함하지 않는다.
