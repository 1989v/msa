# 검증 전략

현재는 설계만 검증한다. 아래 명령/시나리오는 향후 구현 계약이며 아직 통과하지 않았다.

| 계층 | 필수 행동 | 시점 |
|---|---|---|
| Unit | 고정 timestep, 지면/경사/낙하, 기력 상하한, 활공 전이 | T02/T03 |
| Unit | 집기 거리/관통 배치/놓기/재설정, 프리즘 안정 판정 | T04 |
| Unit | 공격 쿨다운/무적 시간/적 복귀/사망 복구 | T05 |
| Integration | 세 유적 완료 순서 6가지, 중복 보상 없음, 최종 문 조건 | T06 |
| Unit | 정상/손상/미지원 버전/범위 밖/비유한 값 저장 검증 | T07 |
| Integration | 새로고침 복원, 저장 거부, 공중 위치 안전 복원 | T07 |
| Browser | 시작/이동/점프/돛/집기/전투/완료/계속 탐험 | 각 기능 + T08 |
| Browser | blur/visibility/pointercancel 후 멈춤, 메뉴에서 이동 금지 | T02/T07 |
| Browser | 390×844·844×390·1440×900의 HUD/터치/카메라 | T01부터 |
| Performance | 고정 장면 FPS/p95, 10분 메모리·발열, 전송량 | T01 기준선 + T08 |
| Visual | 원화와 실루엣/팔레트/깊이/재질/빛 비교 | T01/T02/T08 |

게임 상태를 DOM/렌더러와 분리해 `node:test`로 규칙을 검사한다. 테스트를
숫자로 채우지 않는다. 필수 경로/실패 전이마다 의미 있는 사례를 둔다.
브라우저 자동화로 확인한 것과 실제 손으로 플레이한 것을 구분한다.

공개 전에는 고정 브라우저의 정상 플레이뿐 아니라 WebGL 초기화 실패,
context loss, 저장 비활성화, 장시간 탭 이탈을 검사한다. 실제 모바일 기기가
없으면 데스크톱 에뮬레이션만 했다고 명시하고 모바일 검증 완료로 표시하지 않는다.

독립 리뷰어에는 현재 PRD·해당 작업 diff·공통 계약만 전달한다. 기존 게임을
비교 대상으로 주지 않는다. 발견 사항은 수정 후 재검증하거나 미해결로 남긴다.
