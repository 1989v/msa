# 작은 단위 실행 계획

**현재 T03A-1 활공 순수 규칙 저장. 다음 T03A-2 이동 코어 연결. 전체 구축 추정 약 30%, 최종 아트 품질 미통과.**
실제 검증 후 체크한다. 큰 작업은 A/B로 분리하며 기능을 임의로 줄이지 않는다.

## 공통 실행 계약

- 창작 세션은 이 디렉터리의 해당 문서와 자신의 게임 소스만 읽는다.
  다른 게임 소스/문서/아트는 열지 않는다.
- 시작: progress.md → key-decisions.md → 아래 실행 단위와 해당 그룹 문단 → 필요한 PRD SR.
- 기본 스킬: `hns:implement-tasks`, 검증은 `hns:verify`. 이미지 작업에는
  `imagegen`, UI에는 `frontend-design`을 필요한 경우만 적용한다.
- T01/T02에서 게임 디렉터리의 `node build.mjs`와
  `node --test tests/*.test.mjs`가 동작하도록 만든다. 현재 T01B에 빌드/테스트,
  T02A에 순수 규칙 테스트가 존재하며 나머지 작업 명령은 향후 계약이다.
- 핵심 행동 테스트부터 작성한다. 정적 스타일에 억지 테스트를 추가하지 않는다.
- 종료: 파일/실행 명령/결과/문제/다음 작업을 progress.md에 기록하고 커밋한다.
- 이미지·번들·전체 로그를 대화에 반복 출력하지 않는다. 좁은 작업 입력만 전달한다.
