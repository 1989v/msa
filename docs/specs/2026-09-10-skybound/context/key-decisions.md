# Decisions

## 2026-09-10 · 클린룸 창작

- 사용자 요구: 기존 게임이 발전 가능성을 제한하지 않도록 다른 게임 참고 금지.
- 메인 에이전트는 요청 전 기존 구조/일부 게임을 열람했으므로 창작 구현을 분리했다.
- `/root/cleanroom_game`은 `fork_turns=none`으로 생성, 기존 게임은 읽지 않았다.
- 기존 설치 라이브러리와 통합 계약만 재사용 가능. 다른 게임 코드/아트/레벨은 금지.
- 독립 디자인 에이전트도 외부/기존 이미지 없이 원화 2장을 생성했다.

## 2026-09-10 · PRD·에셋 우선, 단계별 인계

- 사용자 최신 요구에 따라 구현을 멈추고 P0 산출물을 먼저 준비했다.
- 클린룸 폴더와 빈 src만 존재하며 소스/번들/테스트는 없다.
- 다음 구현은 T01A만 수행한다. 전체 월드 구현을 한 세션에 재시작하지 않는다.
- 새로운 결정/검증은 파일에 남겨 다음 세션의 반복 탐색을 줄인다.

## 2026-09-10 · 제품 제안의 정본

- PRD가 범위/수치의 정본이다. 아이디어 단계의 에이전트 제안은 그대로 병합하지 않는다.
- 가칭 나루/바람섬 군도, 세 유적, 중앙 바람문, 600m급 슬라이스는 기획 제안이다.
- 기력 있는 활공을 현재 제안으로 채택하되 기류 내 회복과 중간 발판을 둔다.
  기력 없는 활공 대안은 P2의 조작감 측정 후 판단한다.
- 모델 제작은 원화 품질을 기준으로 결정한다. 절차적 단순 도형만 쓰도록 제한하지 않는다.
- 새 서버/스키마 없이 정적 게임 경계 사용; 공개는 검증된 결과를 만든 뒤 별도 승인.

## 2026-09-10 · 설계 리뷰 반영

- 9개 그룹을 24개 실행 패킷으로 분할; 패킷 하나가 한 세션의 종료 경계다.
- 모델 제작 방식 결정은 T01A의 작은 소품 실험으로 앞당겨 순환 의존을 없앴다.
- 물체 운반은 메뉴에서 정지, 저장에서 제외; 미완료 퍼즐 초기 배치/완료 받침 고정 복원.
- 달리기 유지와 회피 누름 분리, 우클릭 시야와 좌클릭 공격 분리, 도구 모드 우선 규칙 명시.

## 2026-09-10 · T01A 검증과 재개 경계

- 사용자의 계속 진행/저장 요청으로 T01A까지 수행했다. 다음은 T01B다.
- 정적 소품은 독창적 Three 기하→제한된 GLB exporter→GLTFLoader로 검증했다.
  텍스처/리깅/애니메이션에는 이 exporter를 확장 사용하지 말고 표준 도구 경로를 검토한다.
- 색상은 CSS 공백 HSL 파서에 의존하지 않는다. 명시적 색 공간 API로 변환한다.
- export 전후 경계는 실제 world-space 꼭짓점으로 비교한다. AABB의 과대평가를 오차로 오인하지 않는다.
- 소품의 기술 경로는 통과, 원화 수준의 최종 아트 판정은 아직 아니다.
- 창작 에이전트 크레딧 제한으로 중단. 추가 창작은 복구 후 독립 컨텍스트에서 이어간다.

## 후속 지시 · 태스크 순차 실행

- 사용자: “순차로 진행해”. 한 태스크 종료 후 무조건 턴을 끝내는 제한을 해제한다.
- 태스크별 구현 → 직접 검증 → 저장/커밋 → 다음 태스크 순서를 지킨다.
- T01B를 새 클린룸 에이전트로 재시도했다. 기존 T01A 빌드와 테스트 5개는 재통과했다.
- 크레딧 제한이 반복되면 새 태스크를 완료로 표시하지 않고 재시도 결과를 보존한다.

## T01C / T02A · 재개 결과

- 카메라는 현재 장면의 고정 타깃/전면 궤도로 제한한다. 게임 추적 카메라·충돌 해결과 구분한다.
- 터치 DPR 1.5 / 일반 DPR 2 상한, 숨김 탭 렌더 중단, reduced-motion 물결 정지.
- WebGL 손실/복구를 실제 확장으로 시험했고 재시도 동작을 남겼다.
- 이동 지형은 topHeight 식을 복제하지 않고 렌더된 초원/길의 실제 삼각형을 읽는다.
- 수면 기본 -18과 높은 단차 거부를 회귀 테스트로 고정했다.
- T01B 최종 아트는 미통과. T02B의 캐릭터 제작 방식(Q05)을 검증하되 월드를 확대하지 않는다.

## T02B-1 · 리깅 경로와 작은 저장 경계

- 사용자 잔여 한도 15% 지시에 따라 T02B를 리깅/텍스처/모델/동작 연결로 분할했다.
- 새 클린룸 에이전트가 만든 진단 스트립으로 표준 Three GLTFExporter/GLTFLoader를 검증했다.
- 뼈대·가중치·애니메이션 보존 및 CPU 정점 변형은 4/4 통과. 제한된 정적 exporter를 확장하지 않았다.
- 이 경로는 리깅 기술 가능성만 확정한다. 텍스처/실제 모델/아트 품질은 미검증이며 Q05는 open이다.

## T02B-2 · 텍스처 제작 경로

- 자체 기하/UV/뼈대와 Canvas 1K 아틀라스 → 표준 GLTFExporter → GLTFLoader를 기술 경로로 확정한다.
- basecolor는 sRGB, 입력 flipY=false, GLB 안에 PNG를 포함한다. 코드 원본과 파생 PNG/GLB를 함께 저장한다.
- 실제 브라우저에서 12/12 통과했다. 이미지 전체 픽셀, UV, 내장 참조, 기존 skin/animation을 확인했다.
- Q05는 기술 경로만 해소. 원화 품질·실제 GPU 색상·복잡한 rig는 미검증이며 모델 품질이 미달하면 제작 도구를 재검토한다.

## T02B-3a · 모델 초안과 시각 검수

- 두 LOD는 같은 19본 skeleton과 한 1K basecolor atlas를 사용한다. GLB 표준 재로드만 렌더한다.
- 기술 검증과 아트 판정을 분리했다. 단위 4/4·브라우저27/27이나 얼굴/헤어/옷 형태가 원화 대비 미달이므로 T02B-3 전체는 미완료다.
- 앞/뒤/측면 캡처 후 어깨 이음·목깃·망토 외곽·바지 볼륨을 한 차례 개선했다. 다음 T02B-3b는 남은 아트 보완이다.
- 큰 Base64를 한 CDP 응답으로 읽는 시간 초과는 32KiB 분할 수집으로 해결했다. 모델 로드 실패로 오인하지 않는다.

## T02B-3b · 얼굴/헤어/튜닉 보완

- 얼굴의 실제 삼각형 앞에 눈이 놓이는지 양 LOD raycast 회귀 검사 추가. 테스트 5/5.
- 옆가르마 lock과 두피의 틈을 줄이고, 원통 튜닉을 열린 천 패널로 바꿨다.
- 확대 보기와 전신 복귀 검사 추가. 브라우저 30/30. 이전 캡처를 덮지 않도록 artifact 인자로 분리한다.
- 전체 아트 REVISE 유지. 스카프를 넓히기만 하면 판형 실루엣과 스트랩 관통이 생기므로 다음은 접촉/앞뒤 순서를 먼저 검토한다.

## T02B-3c · 접촉부와 동작 검증 경계

- 스카프·소매·스트랩 5개 위치를 양 LOD의 rest/inspection 포즈에서 실제 변형 삼각형 raycast로 검사한다. 전신 관통 보장은 아니다.
- 대칭 둘레 loft는 패드처럼 보여 폐기하고 브로치에서 대각선으로 내려가는 앞천으로 교체했다.
- 아트 최종 기준은 유지하되 검증된 rig의 걷기/달리기 동작 실험은 독립적으로 진행한다. 아트 미달을 통과로 바꾸지 않는다.
- 새 창작 에이전트가 보고 종료 중 크레딧 오류를 냈지만 파일/검증 결과는 저장돼 메인 에이전트가 직접 재검증했다.

## T02B-4a · 제자리 보행 검증

- offline two-link 발 목표 계산을 quaternion track으로 저장한다. 런타임 IK/새 의존성 없이 표준 GLB에 포함한다.
- 1.12초 walk / .68초 run은 기술 초안이다. run 비행구간·heel/toe roll·실제 이동 동기화는 후속이며 최종 달리기 품질로 표현하지 않는다.
- 발바닥 높이 통과 후 실제 캡처에서 발목 wrap/boot 단절 발견. 하단 두 부위의 가중치를 공유 전이로 바꾸고 bind 대비 이음새 거리 증가2mm이내 회귀 검사를 추가했다.
- 동작 로그와 일반 뷰어 로그를 각각 motion-browser.json/browser.json으로 분리해 덮어쓰지 않는다.

## T02B-4b-1 · 공중 자세와 물리 이동 분리

- jump .7초 / fall 1.2초 / land .9초는 root 이동 없는 표현용 클립이다. 실제 포물선/접지는 T02A 연결에서 담당한다.
- jump/land는 LoopOnce+clamp, fall은 반복. 일회재생 endpoint를 modulo로0에 되돌리지 않고 종료 상태를 보존한다.
- 랜딩 말미 모든 피부 정점 bind복귀와 발 접지, 실제 GLB의 종료·재재생을 검증했다.
- 사용자가 잔여16% 안내. 조회 도구 부재로 수치 직접확인은 불가. 새 에이전트 크레딧 오류 후 사용자 재개 지시에 재시도해 성공했다.

## T02B-4b-2 · 기존 구현 연결

- 새 traversal/만 추가해 기존 world 실제삼각형→terrain/simulation→GLB 위치와 동작으로 연결했다. root 위치는 simulation 발 위치를 그대로 따른다.
- 착지는 falling→grounded에서 1회, 이동 재개는 즉시 walk/run, respawn은 착지생략/시간초기화. point heightfield이며 경사발IK나 prop/camera충돌이 아니다.
- 키보드는 검증용 WASD/Shift/Space이며 blur/숨김시 일시정지. T02C의 정식 시야·touch 입력은 후속.
- 수십 프레임 GPU렌더를 한 CDP 평가로 몰면 시간초과. 검증을 작게 나누고 키입력은 고정시간 대신 위치변화 조건으로 확인했다.

## T02C · PC·터치 입력을 작은 단위로 분리

- T02C-1 우클릭 orbit·휠 줌·yaw 상대 이동을 완료했다. 최종 카메라 충돌은 별도 미완료다.
- T02C-2는 왼쪽 이동 패드·오른쪽 시야와 점프/달리기 버튼을 독립 pointer 소유권으로 다룬다.
- 한 손가락 해제는 다른 손가락 입력을 유지하고, blur/일시정지/reset은 전체 입력과 capture를 해제한다.
- 터치 에뮬레이션과 실제 모바일 성능은 구분한다. 이번 단계에 활공·pinch zoom·새 아트를 섞지 않는다.

## T03A-1 · 순수 활공 규칙 경계

- 남은12% 안내에 따라 활공 규칙/이동 연결/돛 표현/공중 경로를 나눴다.
- stateless stepGliding은 공유 stamina를 입력/반환하며, 지상·달리기·활공·기류 중 한 예산만 계산한다.
- 소진이 틱 중간에 일어나면 glidingTime을 반환한다. 호출부는 나머지 시간에만 중력을 적용해야 한다.
- 원통 기류 경계와 겹침 최대값 정책은 규칙으로 고정했으며 수치는 초기 조정값이다.
- 기존 데모/모델은 수정하지 않았다. T03A-2에서 jump pulse·coyote·착지buffer 우선순위를 검증한다.

## T03A-2 · 활공 선택 활성화와 입력 우선순위

- createSimulation flight 옵션은 기본 비활성이다. 현재 viewer bridge에 gliding 대응이 없으므로 표현과 함께 후속 활성화한다.
- 지상/coyote 점프, 접힌 돛의 .12초 이내 예상 착지 버퍼, 나머지 공중 toggle 순서로 단발 입력 소비자를 정한다.
- 기류 설정은 생성 시 복사·검증하고 외부 변경을 차단한다.
- 공중 틱에 기력·중력 분배를 처리했으면 착지 후 다시 회복하지 않는다. 다음 접지 틱부터 회복한다.
- 기본 데모 브라우저19개 회귀 통과는 브라우저 활공 검증과 구분한다.

## T03A-3 · 데모 활공 기술 초안

- 7% 한도에서 기존 GLB를 재생성하지 않고 자체146tri 돛과 임시 fall 포즈로 데모를 연결했다.
- 손과 횡봉이 떨어져 보이므로 전용 포즈·접촉 검증을 T03A-4로 분리했다. 아트 통과로 표시하지 않는다.
- 기류·새 경로는 추가하지 않았다. 이번 실제 활공 입력 검사는 PC이며 터치 재누름 검사는 후속이다.

## T03A-4 · 실제 리깅 기반 손 접촉

- GLB 재생성 없이 팔 길이와 공통 횡봉 목표점으로 양팔을 계산한다. 손바닥 중심/실제 변형 정점으로 접촉을 검사한다.
- 보정 전 quaternion을 매 프레임 복원한 뒤 mixer→활공 보정을 적용한다. 비활공 자세로 보정이 새지 않게 한다.
- 터치 최초 실패 후 로그 추가 재실행 통과는 원인 해결이 아니다. 다음 단계 재확인 항목으로 유지한다.

## T03B-1 · 기류 표시와 판정 데이터

- 실제 초원 경사 표본을 포함하는 원통 하나를 만들고 동일 정의를 시각/물리에 전달한다.
- 48개 화살표는 tick 절대시간으로 갱신해 pause 때 멈추고 reset 때 재현한다. 매 프레임 객체/버퍼 재할당은 없다.
- 기류 원거리 가독성·바람 표현과 필수 공중 경로는 다음 품질 단계다.

## T03B-2a · 공중 발판의 지지면 질의

- 최고 높이만 반환하는 기존 heightfield에 공중 상판을 합치면 아래 초원 이동이 막힌다. 선택 supportHeightAt으로 이전 발 높이 아래의 상판만 조회한다.
- 상판 렌더 정점을 충돌에 사용하며 밑면/측면 충돌은 제공하지 않는다. heightAt은 기존 초원·체크포인트 계약을 유지한다.
- 첫 착지 기록은 진단 진행값이며 water respawn에서 보존한다. 전체reset에서 지우고 자동 체크포인트는 바꾸지 않는다.

## T03B-2b · 순서 있는 진단 경로

- 두 번째 지지면을 합성할 때 첫 지지면 조회를 유지한다. base heightAt 계약은 바꾸지 않는다.
- route reducer는 첫 발판 이후의 둘째 착지만 완료로 처리한다. 물 리스폰은 진행을 보존하고 전체reset은 지운다.
- 기본 기력 경로 완주를 확인해 다음 물체 조작으로 진행한다. 최종 아트·바람 음향·실기기 안정성은 후속이다.

## T04A-1 · 운반과 확정 배치 분리

- 사전 등록 stone/prism만 한 개씩 조작하며 초기 회전은90도 단위다. 끝점 AABB와 보수적 회전 경로를 사용한다.
- 유효하지 않은 preview는 held/committed pose를 바꾸지 않는다. grab/drop은 현재 문맥을 다시 검증한다.
- 취소/reset은 복구 재배치이며 actor 겹침 해소 후 재개하는 후속 연결이 필요하다. 이 예외를 일반 안전 배치로 표현하지 않는다.
- committedSnapshot은 진단 데이터이며 실제 게임 저장 계약으로 재사용하지 않는다.

## 2026-09-13 · T04A-2a 운반 연결

초기 운반은 지상에서만 시작하고 이동/점프 입력을 비워 잠근다. 시야로 위치 조정, 실제 지면 중심 높이에 배치한다. 보이는 회색 상자와 같은 AABB를 운반 벽으로 사용한다. 원위치와 actor 겹침 시 취소를 거부하고 전체 reset은 actor와 프리즘 모두 복구한다. 지면이 없는 목표는 무효 표시하며 다시 지면을 겨누면 목표를 재검사한다. 넓은 지지와 모바일 작은 화면은 T04A-2b에 남긴다.

## 2026-09-13 · T04A-2b 지면 지지

선택적 순수 `resolvePlacement`가 높이 보정 또는 거부 사유를 반환하고, 코어는 보정된 pose에 사거리/벽/겹침/sweep를 검사한 뒤에만 상태를 변경한다. 기본 resolver는 기존 동작을 유지한다. 화면의 실제 지형을 사용하는 어댑터는 회전 바닥 9개 표본/최대 높이 차이 0.2m로 근사한다. 초기 프리즘도 같은 지지를 적용한다. 전체 면적의 연속 지지·자유 기울기 물리는 범위 밖이다.

## 2026-09-13 · T04B-1 받침 퍼즐

받침은 실제 지형을 따르는 표시이며 충돌 플랫폼을 추가하지 않는다. 전체 프리즘 바닥/방향90·270/높이 .05m 허용오차를 committed pose에서 판정한다. 운반/무효 예고/정지 중에는 새 완료하지 않는다. 완료 latch와 조작 잠금을 화면 어댑터가 연결하고 전체 reset으로 함께 해제한다. 보상·세이브 계약은 아직 적용하지 않는다.
