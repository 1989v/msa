# 좀비 행군 (zombie-march) — 설계

**한 줄**: 좀비 군단을 손가락으로 몰아 사람의 전열을 뚫고, 쓰러진 사람이 몇 초 뒤 일어나 내 편이 되는 영지 전략 게임.

## 0. 엔진 판정 — 캔버스

유니티가 값을 하는 조건은 **골격 애니메이션이 붙은 무리 + 스트리밍이 필요한 큰 3D 맵**이 둘 다 필요할 때다.
이 게임은 둘 다 아니다.

- 무리는 많지만(최대 300+) **2D 스프라이트**로 충분하다 — 절차 생성 리그를 구워 쓰므로 골격 런타임이 필요 없다.
- 지도는 33×33 아이소 격자 하나이고 전투는 판 하나다. 스트리밍이 필요한 규모가 아니다.
- 빌드 스텝 0 · 산출물 252KB · 첫 로딩 즉시. 유니티였다면 10~50MB.

결론: **캔버스 2D**. 새 런타임 기술(WASM/WebGL/Worker)은 도입하지 않았다 — 측정한 프레임 코스트가 예산 안이다(§7).

## 1. 벤치마크와 그 규모

벤치마크는 모바일 세로 전략 **「탑 로드」(GAME SPARK, 2026)**. 품질·규모의 하한선으로만 쓴다.
가져온 것은 **장르 문법**이고, 세계관·캐릭터·이름·UI 는 전부 창작이다(§8).

| 규모 축 | 벤치마크 | 이 게임 | 판정 |
|---|---|---|---|
| 맵 범위 | 타일 단위 영지 확장, 성 레벨로 잠금 해제 | **33×33 = 1089 타일**, 지역 4개(죽은 들판·가시 숲·돌 요새·왕도), 지역마다 성채 보스 | 동급 |
| 해상도 | 3D 세로 화면 | 논리 세로 캔버스(전장 폭 1080 / 가로에선 1560), 기기 픽셀 그대로(DPR 2 상한) | 동급 |
| 플레이타임 | 캠페인 60단계 이상 | **1회차 8~14시간 추정**(§6 근거) | 동급 |
| 진행 깊이 | 성 레벨 · 병종 · 영웅 · 연구 | 본진 5단계 · 좀비 4종 · 사람 8종 · 영웅 2 · 건물 4종×3단계 · 지역 4 · 보스 4 | 동급 |

**원작에 있는데 뺀 것**: 연맹(온라인 소셜), 일일 임무·기간 이벤트, 과금·스피드업, 그리핀 탈것.
전부 **라이브 서비스 운영 장치**라 정적 웹 단판 게임에 옮길 근거가 없다. 뺀 자리는 「죽인 사람이 내 편이 된다」는
이 게임 고유의 축으로 채웠다.

## 2. 화면 축척 (전역 가드레일 G1-2)

기준 방향은 **세로**다. 세 수치를 실측했다 (390×844, 기본 줌).

| | 목표(전략·RTS 대역) | 실측 |
|---|---|---|
| 시야 폭 (짧은 변이 담는 월드 유닛) | — | **1080** |
| 주인공(개체) 화면 비율 | 1/16 ~ 1/24 | **1/18.0** |
| 개체 CSS px | 하한 참고 | **21.7** |

- **줌 3단**: 가깝게 1.5 / 보통 1.0 / 넓게 0.7 (`RenderBattle.zoomLevels`). 지도도 3단(0.55/1/1.6).
- **가로(844×390)에서는 전장 폭을 1560 으로 넓히고 배율을 다시 뽑는다** — 세로용 1080 을 그대로 쓰면
  화면 폭의 절반만 차고 양옆이 빈다. 가로 실측: 개체 32.5 CSS px, 비율 1/12.0.
  기준 방향이 세로이므로 대역 판정은 세로 값으로 한다.

**예외 선언 — RTS 축척과 모바일 하한의 충돌 (G5-2)**
세로에서 개체가 21.7 CSS px 라 「구분해야 하는 적 ≥16」은 넘지만 「조작 대상 ≥28」에는 못 미친다.
이 게임에서 **개체는 조작 대상이 아니다** — 조작하는 것은 집결 표식(해골) 하나이고 그것은 **52 CSS px** 이다.
그리고 이 예외가 사 주지 않는 것: **버튼·타일 시트 같은 실제 터치 대상은 여전히 44 CSS px 이상을 지킨다**
(스킬 66 · 일시정지 48 · 지도 버튼 44~48 · 출정 60×44).

## 3. 조작 — 네이티브 터치 (G5-3)

**가상패드를 붙이지 않는다.** 근거: 조작이 ① 화면 드래그로 집결 지점 옮기기 ② 탭으로 타일·건물·스킬 고르기
두 가지뿐이라, 방향 입력이 연속값이 아니다. 패드를 깔면 전장의 아래 1/4 를 가려 무리가 안 보인다.

| 행동 | 터치 | 키보드 |
|---|---|---|
| 군단 몰기 | 화면 드래그 / 탭한 자리로 | 방향키 · WASD |
| 일으키기(스킬 1) | 버튼 | Z |
| 독안개(스킬 2) | 버튼 | X |
| 집결 | 버튼 | C · Space |
| 멈춤·메뉴 | ⏸ 버튼 | Esc |
| 전투 줌 | 핀치 | Q · E |
| 지도: 이동/줌/선택 | 드래그·핀치·탭 | 방향키 · Q/E · Tab(전선 순회) · Enter |
| 지도: 군단·영웅·본진 | 버튼 | Z · X · C |

**모달 키 계약**: 확정 = Enter·Space·Z / 뒤로 = Esc·X / 이동 = Tab·방향키 / 나머지 = 거절음.
승리·패배 연출 중에는 **아무 키나** 눌러 결과창으로 건너뛴다.

## 4. 두 층 구조

### 영지 (`05-world.js` · `09-render-map.js`)
- 33×33 아이소 격자. 가운데 3×3 이 묘지성, 거리 고리(d)가 지역을 가른다.
- **안개 4단계**: 0 내 땅 · 1 전선(깃발+전력 표시) · 2 그 뒤(흐릿) · 3 어둠. 전선만 고를 수 있다.
- 건물 4종 × 3단계: 무덤(시체→좀비) · 뼈 채굴장(뼈밭 전용) · 역병 우물 · 제단(폐허 전용, 영웅 소환).
- 본진 5단계가 **출정 상한 · 건물 자리 · 영웅 자리 · 좀비 해금**을 동시에 잠근다.
- 자리를 비운 동안의 생산은 **8시간까지** 정산한다(`D.OFFLINE_CAP`).

### 전투 (`06-battle.js` · `08-render-battle.js`)
- 세로 전장. 아군은 아래에서 시작해 **적 전열 2~3줄**을 뚫고 진영까지 간다.
- 조작은 **집결 지점 하나**. 군단은 그리로 가되 사거리 안의 사람을 문다. 집결 지점은 무리에서
  340 유닛 넘게 못 떨어진다(줄이 끊기면 조작이 아니라 방치가 된다).
- **시체 → 좀비**: 죽은 사람은 3.4~4.3초 뒤 일어난다. 기사는 **좀비 기사**(갑옷 유지)가 된다.
  사제는 그 전에 시체를 태운다 — 사제가 있는 판은 시체가 재원이 아니다.

## 5. 사람 8종 — 각자 다른 답을 요구한다

| 병종 | 하는 짓 | 답 |
|---|---|---|
| 주민 | 도망만 친다. 죽으면 좀비 | 마을 타일의 금 보너스 |
| 민병 | 평범한 근접 | 수로 민다 |
| 궁수 | 사거리 430, 짧게 뒷걸음 | 뛰는 좀비로 파고든다 |
| 창병 | **앞 ±0.95rad 을 0.55초마다 찌른다**(관통) | 옆·뒤로 돈다. 정면은 갈린다 |
| 척후병 | 빠르고 약하다 | 무시하고 진행 |
| 기사 | 갑옷 30%, **붉은 띠 예고 후 돌진** | 띠를 피하고 돌진 끝의 회복 창을 친다 |
| 사제 | 공격 없음. **시체를 태우고 아군을 회복** | 최우선 제거 — 안 잡으면 군단이 안 는다 |
| 기사 대장(보스) | 광역 휘두르기 + 돌진, 절반에서 **2페이즈**(종을 쳐 민병 소환·2.5초 무적) | 돌진 뒤 **「빈틈」** 표시 2.2초 동안 피해 1.6배·갑옷 0 |

## 6. 플레이타임 추정 (코드 수치 기준)

- 전투 1회 40~130초(실측, 헤드리스 시뮬 3판×여러 시드).
- 타일 1089칸 중 실제로 먹는 것은 진행 경로 위주로 **150~250칸** 추정.
- 건설: 1단계 12초 · 2단계 30초 · 3단계 60초. 본진 5단계 누적 비용 뼈 2,660 · 금 1,560.
- 뼈 수급은 채굴장 1단계 10/분 → 3단계 30/분. 본진 4단계(뼈 700·금 420)만 해도
  채굴장 2기 2단계(36/분)로 **약 20분**.
- 지역 4개 × (고리 3~4개 × 8~12칸) + 보스 4 → **1회차 8~14시간**.
- 그래서 **이어하기가 필수**다: `localStorage` 단일 슬롯 + `PlatformAdapter` 서버 동기화.

## 7. 성능

- **실측**(rAF 간격 180표본의 중앙값·p95, 개체 300~350 · 파티클 100+ · 데칼 90):

  | 조건 | 개체 | 프레임 중앙값 | p95 | fps |
  |---|---|---|---|---|
  | 데스크톱 1440×900 | 350 | 16.7ms | 16.8ms | 59.9 |
  | 데스크톱 교전 중 | 310 | 16.7ms | 16.8ms | 59.9 (p95 59.5) |
  | 세로 390×844 (lowFx) | 349 | 16.7ms | 16.7ms | 59.9 |
  | 세로 교전 중 | 300 | 16.7ms | 16.7ms | 59.9 |

  프레임 시간이 16.7ms 에 붙어 있다 = rAF 상한에 걸린 것이지 일이 모자라 그런 것이 아니다. 여유가 있다.
- **폰은 프레임이 아니라 일의 양을 깎는다**(G7 변형): rAF 는 16.7ms 격자라 45fps 를 만들 수 없고
  30fps 는 끌기가 끊겨 보인다. 그래서 60fps 를 유지하되 `V.lowFx`(coarse 포인터)에서
  **안개 2겹 → 1겹 · 파티클 상한 700 → 340 · 광원 4개 상한 · DPR 2 상한**.
- **멈춤·모달·타이틀은 20fps** 로 내린다 — 멈춘 화면을 60fps 로 다시 그리는 것이 발열의 흔한 모양이다.
- 개체 300+ 를 위해 **공간 해시**(셀 72)와 스프라이트 캐시(배율별 버킷 6개, LRU).
- **실기 발열은 확인하지 못했다** — 헤드리스는 소프트웨어 렌더링이라 GPU 비용이 재현되지 않는다(G7).
  위 수치는 프레임 시간이지 온도가 아니다. 폰 30분 플레이 확인은 남은 항목이다.

## 8. IP

벤치마크는 **품질·규모의 기준**일 뿐이다. 서빙되는 파일(코드·주석·UI 문구·메타태그)에 타사 게임 이름이 없다.
- 세계관·지명·인명·병종명·영웅명 전부 창작(베일·그림 박사·죽은 들판·가시 숲…).
- 원작의 로고·캐릭터·고유 디자인을 재현하지 않는다. 좀비/중세 병종은 장르 공유 소재다.
- 메커니즘(타일 확장·스와이프 유도 전투·본진 레벨 게이트)은 **아이디어이므로 자유**다.

## 9. 실측 함정 (이 게임에서 실제로 터진 것)

1. **좀비의 `rising` 상태를 사람에게 쓰면 무적이 된다** — `hurt()` 가 그 상태를 무시한다.
   보스 2페이즈 소환 8기가 불사가 되어 **전투가 영영 안 끝났다**. 지금은 사람에게 그 상태가 붙으면 즉시 해제한다.
2. **패치가 메서드를 통째로 복제할 수 있다** — `onKey` 가 두 벌이 되어 **뒤엣것(옛 코드)이 이겼다**.
   키가 안 먹는데 파일에는 새 코드가 보였다. 죽은 입력 감사가 잡았다.
3. **궁수가 자기 전열을 넘어 전진**해 혼자 물렸다. 지금은 자기 줄 앞 150 까지만 나간다.
4. **가로 화면에서 카드 마지막 줄이 접힌 아래로 내려가** 확인 버튼이 안 눌렸다. 마지막 줄을 sticky 로 고정.
5. **바닥 패턴 이음매**가 격자로 읽혔다 — 얼룩을 9방향으로 둘러 그려 타일을 잇는다.

## 10. 검증 (전부 같은 세션에서 실측)

- 죽은 입력 감사: **7개 씬 × 19키 = 133칸, 죽은 칸 0**.
- 모바일 두 방향: 세로 390×844 · 가로 844×390 각각 부팅→지도→타일 시트→출정→전투까지 **탭·드래그만으로** 도달.
- `scripts/lint-game-mobile.py zombie-march --strict` 경고 0 (회귀 주입으로 F1·F2·W5 빨간불 확인).
- 저장·복원 일치, `runEnd` POST 본문 확인(`score`·`detail` 문자열).
- 콘솔 에러 0.
