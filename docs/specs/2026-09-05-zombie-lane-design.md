# 좀비 레인 (zombie-lane) — 설계

**한 줄**: 세 줄로 갈린 길에서 숫자 문을 골라 지나가며 조선 군사 부대를 불리고, 역병에 걸린 무리와 부딪혀 뚫는다.

## 0. 이 게임이 왜 이 모양인가

처음에 「탑 로드」를 벤치마크로 받고 **실제 앱**(영지 건설 전략)을 조사해 그쪽으로 만들었다.
그런데 사용자가 원한 것은 그 앱의 **광고에 나오는 게임**이었다 — 좌우로 움직이며 숫자 게이트를
지나 군중을 불리는 러너. 리뷰에도 "광고와 본편이 다르다"가 있었고, 그 광고 쪽이 독립된 장르다
(**게이트 러너** · 군중 클래시 러너).

**교훈**: 벤치마크가 앱 이름으로 주어지면 **그 앱과 그 앱의 광고가 다른 게임일 수 있다.**
어느 쪽인지 먼저 맞춰야 한다. 이 건은 한 번 만들고 나서야 갈렸다.
(먼저 만든 「좀비 행군」은 지우지 않고 그대로 서비스한다 — 다른 장르의 다른 게임이다.)

## 1. 엔진 판정 — 캔버스

유니티가 값을 하는 조건은 **골격 애니메이션 무리 + 스트리밍이 필요한 큰 3D 맵**이 둘 다일 때다.
이 게임은 둘 다 아니다. 원근은 **직선 도로 하나**뿐이라 투영 한 줄(`V.proj`)이면 되고,
무리는 절차 생성 2D 스프라이트를 굽는다. 빌드 스텝 0 · 폴더 136KB · 첫 로딩 즉시.

## 2. 코어 루프

```
달린다(자동) → 세 줄 중 하나에 선다 → 숫자 문 통과 → 부대 수가 바뀐다
            → 좀비 무리와 충돌 → 서로 깎임 → 뚫으면 계속, 모자라면 끝
            → 구간 끝 → 엽전으로 강화 → 다음 구간
```

조작은 **좌우 하나**다. 화면을 끌거나(연속) 아래 세 칸을 탭한다(레인 스냅). PC 는 ←→.

## 3. 숫자 규칙 — 이 게임의 전부

세 가지를 지켜야 「지금 몇 명인가」가 판단의 기준이 된다.

| 규칙 | 왜 |
|---|---|
| **덧셈은 구간 기준, 곱셈은 부대 기준** | 덧셈을 부대에 비례시키면 언제나 ×2 와 같아져 물어볼 것이 없어지고 수만 폭주한다. 고정 사다리(`addBase` = 시작 부대 ×1.6)로 두면 초반엔 +가 세고 커질수록 ×로 갈아타게 된다 |
| **곱셈은 세 줄에 한 번, 한 장만** | 무작위로 뿌리면 곱셈이 몇 번 더 나온 판이 복리로 튄다. 실측: 같은 실력에 결과가 **350명 ~ 550만명**으로 벌어졌다 |
| **카드는 부대를 0으로 만들지 않는다**(하한 1) | 좀비를 만나기도 전에 산수로 죽으면 게임이 아니다. 0은 좀비만 만들 수 있다 |

줄의 성격은 셋이다 — **보통**(좋은 것 섞임) · **함정**(하나만 좋다, 진행할수록 늘어난다) ·
**잭팟**(하나가 ×4, 나머지는 나쁘다). 첫 줄은 셋 다 좋게 두어 **첫 1초가 「어느 쪽이 더 좋은가」**를
가르친다. 난이도를 낮추는 워밍업이 아니라 문법을 보여 주는 자리다.

## 4. 병종 — 수를 어떻게 쓰는가

부대 전체가 한 병종이다(수 하나가 진실이어야 한다). 병종 문을 지나면 통째로 바뀐다.

| 병종 | 공격 | 받는 피해 | 사거리 | 성격 |
|---|---|---|---|---|
| 창병 | 1.00 | 1.00 | — | 기본 |
| 궁수 | 0.78 | 1.15 | 420 | **붙기 전에 미리 깎는다.** 대신 붙으면 약하다 |
| 방패병 | 0.72 | 0.50 | — | 덜 죽는다. 대신 느리게 깎는다 |

## 5. 충돌 — 란체스터 제곱 법칙

```
부대 감소 = 좀비hp × 2.6 × 0.30 × (병종 피해계수)
좀비 감소 = 부대수 × 2.6 × 무예 × (병종 공격계수)
```

이기는 조건은 `부대 > 0.55 × 좀비hp` 안팎이고, 남는 수는 `√(부대² − 0.3×좀비hp²)` 다.
**수가 조금만 커도 손실이 급격히 준다** — 그래서 문을 잘 고르는 것이 곧 병사를 살리는 것이 된다.

## 6. 규모와 페이싱

| 축 | 값 | 근거 |
|---|---|---|
| 구간 | 12개 (들판 3 · 솔숲 3 · 산성 3 · 도성 3) | 각 구역이 하늘·땅·길·나무 팔레트를 바꾼다 |
| 한 판 | **25~54초** | 길이 7,200~16,200 ÷ 속도 300 |
| 결정 간격 | **2.2초** (문 간격 660) | 처음 205 로 뒀더니 **0.68초**였다 — 세 장을 읽을 수 없어 선택이 아니었다 |
| 한 판의 결정 | 8~20회 | 구간 길이에 비례 |
| 좀비 무리 | 3~5회 | 사이에 네댓 줄이 들어가야 성장이 성립한다 |
| 무리 크기 | **지수**(뒤로 갈수록 ×3) | 균등하게 나누면 첫 무리가 시작 부대보다 산더미다 |
| 1회차 | **12구간 · 25~35분** + 강화 반복 | |

## 7. 화면 축척 (전역 가드레일 G1-2)

기준 방향은 **세로**. 390×844 실측:

| | 값 |
|---|---|
| 선두 병사 | **39.5 CSS px** |
| 짧은 변 대비 | **1/9.9** (탑다운 액션 대역 1/8~1/12) |
| 터치 타깃 최소 | 44 CSS px (멈춤 버튼) · 칩 42 |
| 레인 탭 영역 높이 | 287 CSS px (화면의 34%) |
| HUD 가림 | **4.4%** |

**주인공은 한 명이 아니라 무리다.** 선두는 39.5px 이고 원근으로 뒤로 갈수록 작아진다.
대형 전체 깊이는 **90 월드 유닛으로 고정**한다 — 넘기면 뒷줄이 카메라보다 가까워져
화면 밖으로 흘러나가고 잘린 병사가 거대하게 찍힌다(실측). 좌우로도 도로 밖(±0.94)을 넘지 않는다.

가로(844×390)에서는 도로 폭 비율과 지평선을 다시 잡는다(`V.roadHalf` 0.46 → 0.34, 지평선 0.34 → 0.30).

## 8. 조작 (G5-3)

**가상패드를 붙이지 않는다.** 조작이 좌우 하나뿐이고 그 입력을 화면 전체 드래그와
아래 세 칸 탭으로 받는다. 패드를 깔면 달려오는 길을 가린다.

| 행동 | 터치 | 키보드 |
|---|---|---|
| 줄 옮기기 | 좌우 드래그(연속) · 아래 세 칸 탭(스냅) | ← → · A D |
| 멈춤 | ⏸ | Esc · Space |
| 다시 시작 | 결과창 | R |

모달 키 계약: 확정 = Enter·Space·Z / 뒤로 = Esc·X(한 단계 위로) / 이동 = Tab·방향키 / 나머지 = 거절음.

## 9. IP

벤치마크는 장르 문법의 출처일 뿐이다. 서빙되는 파일에 타사 게임 이름이 없다.
숫자 게이트·군중 성장·최종 충돌은 이 장르 수십 종이 공유하는 **메커니즘**이고,
조선 군사 대 좀비라는 소재·이름·그림·수치·병종 규칙은 전부 창작이다.
군사 차림은 조선 후기 도상의 인상을 단순화한 것으로 특정 유물·일러스트를 베끼지 않았다(`CREDITS.md`).

## 10. 검증 (같은 세션 실측)

- **밸런스**: 헤드리스 봇 3실력(최선 1.0 / 좋음 0.7 / 대충 0.45) × 12구간 × 5시드.
  잘 고르면 이기고(5/5), 대충 고르면 진다(0~2/5).
- **죽은 입력**: 6개 씬 × 18키 = 108칸, **죽은 칸 0**.
- **두 방향**: 세로 390×844 · 가로 844×390 모두 탭·드래그만으로 부팅→달리기→줄 옮기기 도달.
- `scripts/lint-game-mobile.py zombie-lane --strict` 경고 0.
- 콘솔 오류 0 (테스트 서버의 저장 동기화 501 제외 — 운영엔 그 엔드포인트가 있다).
- 60fps (세로·가로 모두).

## 11. 남은 것

- 실기 발열 미확인 — 헤드리스는 소프트웨어 렌더링이라 GPU 비용이 재현되지 않는다.
- 무한 모드(12구간 이후) 없음. 지금은 구간 반복으로 엽전을 모은다.
