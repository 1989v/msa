# PRD — 전통시장 구역·가게 지도와 시장 데이터 어드민

작성 2026-10-15 · 상태 초안(사용자 검토 대기) · 도메인 place · 선행 분석 아티팩트 「시장 골목 지도 샘플」(https://claude.ai/artifact/2Xr2HPNwqo9ubhS86A6Hj3)

## 결론 요약

| 항목 | 결정 |
|---|---|
| 무엇 | 관광지 중 **전통시장**에 시장 기본정보 + **구역별 가게 지도**(골목·건물·층) + 가게별 취급품목을 붙인다 |
| 왜 어드민이 필요한가 | 공공데이터는 가게의 25~35% 에만 좌표를 주고, 노점·미등록 가게·구역 이름·건물형 평면 배치는 어느 원천에도 없다. 이건 "사람이 아는 것"이라 입력 도구 없이는 영영 안 채워진다 |
| 모양 | 공공데이터를 손대지 않는 **원천 층** 위에 **판정 층**(자동 + 덮어쓰기)과 **추가 층**(수동 행)을 얹는다. 화면은 셋을 합쳐 보이되 출처 배지를 유지한다 |
| 권한 | 전역 Role 이 아니라 **시장별 행** `market_steward`. 상인회가 신청하고 운영자가 승인하면 그 시장만 편집한다. 운영자(ROLE_ADMIN)는 전 시장 |
| 단계 | P1 자동 생성(어드민 없음) → P2 운영자 편집·이력 → P3 상인회 신청·승인·"상인회 제공" 배지 |
| 새 파드 | 없음. place 도메인 안(`place/feature`), 어드민 API 는 `/api/v1/admin/**`, FE 는 `admin/frontend` + `portal-fe` AttractionPage |
| 선행 문서 | 새 스키마(시장·구역·가게·권한) → **ADR 필요**. 원천 3종 추가 → `docs/architecture/data-sources.md` 대장 갱신 필수 |

## 1. 배경

place 관광지 중 시장 이름을 가진 행은 국문 482 · 영문 187 이다(`title LIKE '%시장%'`, 분류 SH04/SH06 · A04010100/A04010200). 지금 상세 화면은 TourAPI 개요·주변 명소·편의시설뿐이라 "그 시장에 뭐가 있나"에는 답하지 못한다. `pois` 테이블은 적재 도구만 있고 운영 DB 는 0건이다.

2026-10-14 광장·망원·광명시장 샘플로 공공데이터의 경계를 실측했다.

| 공공데이터로 안 되는 것 | 실측 사례 |
|---|---|
| 노점·미등록 가게 | 광명시장 추억의 국화빵·홍두깨칼국수 — 가맹점·상가정보·상권 712곳 모두 없음 |
| 가맹점의 시장 소속 오류 | 광명시장 온누리 가맹점 692 중 약 절반이 시장 밖(26개 골목 97곳이 170m~1.4km 밖, 광명새마을시장 159곳은 870m 떨어진 별개 시장) |
| 구역 이름 | 골목별 품목 비율로는 "먹거리 골목" 같은 이름이 나오지 않는다 |
| 건물형 시장의 평면 배치 | 상가정보 좌표가 **필지 중심**이라 광장시장 본관 200곳·남대문 264곳·경동 160곳이 한 점에 겹친다 |
| 커버리지 | 가맹점 × 상가정보 매칭으로 좌표를 얻는 비율은 시장 점포의 25~35%(광장 701→403, 남대문 1,833→906, 통인 61→42, 광명 692→421) |

구역 단위 데이터는 어디에도 없다. 구역을 유도할 근거는 셋뿐이다: 도로명(=골목), 건물명·동·층, 취급품목 군집.

## 2. 목표 · 비목표

**목표**
- 여행자가 시장 상세에서 **구역(골목·동·층)별로 어떤 가게가 있는지** 보고, 가게 이름으로 찾고, 출처를 안다.
- 공공데이터가 못 채우는 것을 운영자·상인회가 **원천을 덮지 않고** 보탤 수 있다.
- 공공데이터 재적재가 수동 입력을 지우지 않는다.

**비목표(이번 범위 밖)**
- 가게 단위 가격·메뉴판 입력. 가게 단위 가격 원천은 착한가격업소뿐이라 P1~P3 에는 넣지 않았고, P6(§12)에서 그 원천만 붙인다. 시장별 품목 시세는 원천이 없다(§12).
- 전통시장 경계 폴리곤 자동 생성. 전국 데이터가 없고 지역 SHP(부산·천안·서울 상권영역)는 범위가 다르다.
- 상인회 신원의 시스템 검증(사업자번호 조회 등). 승인은 사람이 한다.
- 건물형 시장의 배치도 이미지 위 좌표 찍기. 수요가 보이면 P4.
- 시장 밖 반경 검색. 사용자 결정: "시장 내 가게만".

## 3. 사용자와 역할

| 역할 | 누구 | 하는 일 | 권한 근거 |
|---|---|---|---|
| 여행자 | 비로그인 포함 | 시장 상세에서 구역·가게 열람, 찾기 | 없음 |
| 운영자 | ROLE_ADMIN | 전 시장 편집, 상인회 신청 승인·정지, 이력 되돌리기 | 게이트웨이 admin 경로 필터(기존) |
| 상인회 담당자 | 로그인 회원 + 승인된 `market_steward` 행 | 자기 시장만 편집 | place 가 행을 확인(블로그 `blog_profile` 과 같은 방식) |

권한을 JWT 역할에 넣지 않는 이유: 역할 하나로는 "어느 시장"을 담지 못하고, 정지 처분이 토큰 만료 전까지 먹지 않는다(ADR-0072 블로그 작성 권한과 같은 판단).

### 4.3 시장 소속 판정 (P1 자동)

1. 관광지 행 중 시장 유형을 고른다: 분류코드(A04010100/A04010200, SH04/SH06) 또는 제목 `시장`.
2. 전통시장표준데이터와 이름·주소(시군구)로 붙여 `market` 행을 만든다. 못 붙으면 관광지 좌표·제목만으로 만들고 `market_info_matched = false`.
3. 온누리 가맹점을 시장명으로 모아 소속 **후보**로 둔다.
4. 상가정보 벌크에서 같은 법정동 안 점포를 지번+상호 / 지번 / 상호 순으로 매칭해 좌표·건물·층을 얻는다.
5. 바깥을 걸러낸다: 시장 중심에서 거리형 300m · 건물형 150m 를 1차 반경으로 두고, 반경 안 골목(도로명)의 가맹점 밀도가 임계 아래면 그 골목은 `OUTSIDE` 로 판정한다. 임계값은 광명(골목 4개 안 · 26개 밖)·광장·망원 실측으로 정하고 상수로 둔다.
6. 비가맹 가게를 `storeListInPolygon`(구역 폴리곤이 있을 때) 또는 반경 호출로 보강한다. 일 10,000 한도 안에서 시장 482곳이면 하루 분량이다.

## 5. 기능 요구사항

### P1 — 자동 생성 (어드민 없음)

**FR-1 시장 식별**: 4.3 의 1~2 로 `market` 행을 만든다. 관광지 상세는 `market` 이 있으면 "시장" 섹션을 보인다.

**FR-2 가게·구역 자동 생성**: 4.3 의 3~6 과 4.4 로 `market_zone`·`market_store` 를 채운다. 매일 ingest CronJob(`place/ingest`) 에 잡 하나를 더한다. 벌크 zip 352MB 는 시도별 CSV 를 스트리밍으로 읽고 대상 법정동만 남긴다(무료 티어 메모리 제약).

**FR-3 시장 섹션 화면** (portal-fe `AttractionPage`): 샘플 아티팩트의 운영판.
- 상단: 시장 기본정보(유형·점포수·개설주기·편의시설, 출처 표시).
- 지도: 가게 점 + 구역 색. 거리형은 골목 칩 필터, 건물형은 건물·동·층 목록. 지도 라이브러리는 기존 place 지도 방식을 따른다.
- 가게 목록 패널: 점 클릭 → 같은 필지 가게 목록. 이름 찾기 입력 → 찾은 가게 강조 + 목록 상단 배지, 없으면 "없음" 안내.
- 출처 배지(4.1). `membership = OUT` 가게는 기본 숨김, "시장 밖도 보기" 토글.
- 영문 관광지(en 187) 는 가게 이름이 국문뿐이므로 국문 그대로 보이고 품목만 영문 분류로 바꾼다(후속에서 번역 검토).
- 모바일 1순위. 목록 패널은 모바일에서 지도 아래 시트.

**FR-4 검색 색인**: 시장 가게 이름을 attractions 색인의 보조 필드로 넣을지는 비목표. P1 은 상세 안 찾기만.

### P2 — 운영자 편집 (ROLE_ADMIN)

**FR-5 어드민 시장 편집 화면** (`admin/frontend`): 시장 목록 → 시장 상세.
- 가게 표: 소속 판정(IN/OUT) 토글, 구역 재배정, 이름·품목 수정. 모든 수정은 `market_store_override` 로 들어가고 이유를 받는다.
- 가게 추가: `source = MANUAL`. 위치는 정확 핀 또는 **참고 위치 핀**(이웃 가게를 고르고 "옆·맞은편·앞" 상대 위치 + 메모). 참고 핀은 화면에서 점선 링으로 구분한다.
- 지도 편집 셋만: 구역 폴리곤 그리기(클릭으로 꼭짓점), 가게 핀 옮기기·추가, 가게↔구역 배정. 건물형은 폴리곤 대신 동·층 목록 편집.
- 구역 이름 짓기, 구역 순서.

**FR-6 변경 이력**: 모든 편집이 `market_change_log` 에 전후 값으로 남고, 어드민에서 행 단위 되돌리기가 된다.

**FR-7 재적재 보호**: ingest 가 원천 행을 갱신해도 override·MANUAL 행·폴리곤·구역 이름은 유지된다. 검증: 재적재 전후 수동 행 수와 override 행 수가 같다.

### P3 — 상인회 신청·승인

**FR-8 신청**: 로그인 회원이 시장 상세의 "상인회 담당자 신청"에서 시장을 고르고 단체명·연락처를 적는다. `market_steward(PENDING)` 행이 생긴다. 한 회원이 여러 시장을 신청할 수 있다.

**FR-9 승인**: 어드민에서 PENDING 목록 → 운영자가 메일·전화로 확인한 뒤 승인·반려. 정지(SUSPENDED)는 즉시 효력 — 다음 요청부터 막힌다.

**FR-10 상인회 편집**: ACTIVE 행이 있는 회원은 그 시장에 한해 FR-5 와 같은 편집을 한다. 경로는 admin 필터 밖의 로그인 경로(`/api/v1/place/markets/{id}/manage/**`)이고 place 가 행을 확인한다. 가게 입력에는 "상인회 제공" 배지가 붙는다. 가격 필드는 없다.

**FR-11 상인회 범위 제한**: 다른 시장 편집 시도는 403. 운영자 전용 동작(승인·정지·되돌리기·폴리곤 삭제)은 상인회에게 없다.

## 6. API 초안

| 경로 | 권한 | 용도 |
|---|---|---|
| `GET /api/v1/place/markets/{contentId}` | 공개 | 시장 정보 + 구역 + 가게(IN 기본, `includeOutside`) |
| `GET /api/v1/admin/place/markets`, `GET …/{id}` | ADMIN | 목록·상세(OUT·override·이력 포함) |

## 8. 제약과 지켜야 할 규칙

- 외부 데이터 3규칙(원천 전부 적재 · 파생 분리 · 전체 동기화 경로 갱신)과 `data-sources.md` 대장. 공공누리 1유형은 화면에 출처 표시.
- 새 도메인 체크리스트: 새 파드 없음(place:feature 안), 레이어 표준(UseCase 인터페이스 + Port + Adapter), Kotest BehaviorSpec.
- 무료 티어: ingest 메모리 256~512Mi 안에서 352MB zip 스트리밍. 상가정보 API 일 10,000 안에서 시장당 호출 수 상한.
- 이미지 둘: place(JVM) + place-ingest(파이썬) 둘 다 바뀐다.
- 재색인·배치의 저하 경로에는 실패 비율 상한을 둔다(전부 실패해도 성공으로 끝나지 않게).
- 시간은 KST.

## 11. P4 — 골목 구조 보강 (2026-10-15 추가)

근거: 「시장 지도 화면 샘플」 v2 의 「골목 구조 개선안」. P1 판정은 도로명 + 반경이라 엮인 골목 구조가 보이지 않고, 큰길가 가게가 비율 기준 하나에 통째로 들어오거나 빠진다(광명 오리로 141/486 = 0.29, 기준 0.30).

### 11.1 판정 순서 (P1 §4.3 위에 얹는다)

1. 가게별 보정(`market_store_override` MEMBERSHIP)
2. 시장 경계가 있으면 경계 안 = IN, 밖 = OUT
3. 경계가 없으면 도로 단위 규칙(도로명, 건물번호 구간 선택) — 일치하는 규칙의 IN/OUT
4. 그 밖에는 적재 잡의 도로명 + 반경 판정(지금 값)

판정 결과는 파생 값이다. 원천 행의 적재 판정(`membership`)은 덮지 않고, 재판정 결과를 별도 컬럼으로 둔다(외부 데이터 3규칙 ②).

### 11.2 골목 배정

- 가게에서 25m 안에 주소 도로명과 같은 이름의 골목 선이 있으면 그 골목.
- 없으면 가장 가까운 골목 선, 그리고 `needs_review = true`("확인 필요" 목록, 공개 화면에는 안 보임).
- 골목 선이 없으면 P1 의 도로명 구역을 그대로 쓴다.
- 광명 표본 기대값: 경계 안 가맹점 153곳, 큰길 가게 중 경계 안 29곳(오리로 12·광명로 17), 자동 배정 104곳, 확인 필요 49곳, 골목 선 14개, 출입구 후보 9곳.

### 11.3 데이터

| 테이블 | 핵심 컬럼 | 비고 |
|---|---|---|
| `market_boundary` | market_id(1:1), polygon(위경도 배열 JSON), source(OSM/DERIVED/MANUAL), osm_type·osm_id, fetched_at | OSM 원본은 `market_osm_raw` 에 그대로 둔다 |
| `market_path` | id, market_id, name(null 허용), named, geometry(선 JSON), source(OSM/MANUAL), osm_way_id, sort | 골목 선 |
| `market_entrance` | id, market_id, lat/lng, via_path_id, label, source | 경계를 지나는 자리 |
| `market_road_rule` | id, market_id, road_name, building_no_from/to(null 허용), membership(IN/OUT), reason | 경계가 없는 시장의 안전망 |
| `market_osm_raw` | market_id, kind(BOUNDARY/PATHS/ROADS), payload JSON, fetched_at | 원천 전체 보존, 배경 큰길 선 포함 |
| `market` 추가 컬럼 | center_override lat/lng, radius_override_m | 관광지 좌표 고정 문제 |
| `market_store` 추가 컬럼 | judged_membership, judged_by(OVERRIDE/BOUNDARY/ROAD_RULE/INGEST), path_id, needs_review | 파생 컬럼 |

모든 편집은 기존 `market_change_log` 로 전후 값을 남기고 되돌릴 수 있다(target 에 BOUNDARY·PATH·ENTRANCE·ROAD_RULE·MARKET_GEO 추가).

### 11.4 원천 — OpenStreetMap (ODbL 1.0)

- Overpass API 로 시장 중심 반경 안의 `amenity=marketplace` 폴리곤, `highway=footway|pedestrian|service|living_street|residential` 선, 배경용 큰길 선을 받는다. 출입구 후보는 경계와 골목 선의 교차점으로 계산한다.
- 화면(공개·어드민 지도)에 "© OpenStreetMap contributors" 를 표시한다.
- 고친 경계·골목 선은 OSM 파생 데이터베이스다. 내려받기·API 로 **데이터 자체를 공개 배포하지 않는다**(지도 표시만). 공개 배포가 필요해지면 ODbL share-alike 로 공개해야 하므로 별도 결정한다. ADR-0110 과 원천 대장에 적는다.
- Overpass 사용 정책: User-Agent·`Accept` 지정, 시장 하나에 한 요청, 요청 사이 간격, 실패율 상한(5%) 초과 시 잡 실패·쓰기 없음. OSM 폴리곤이 없으면 IN 가게 좌표의 둘레(볼록 껍질 + 20m 여유)를 `DERIVED` 초안으로 만든다.
- 운영자·상인회가 고친 경계(`MANUAL`)는 재적재가 덮지 않는다. OSM 원본이 바뀌면 `market_osm_raw` 만 갱신한다.

### 11.5 기능

- 어드민: 지도 배경에 OSM 큰길·골목 선, 경계 꼭짓점 끌기·추가·삭제, 경계를 OSM/둘레 초안으로 되돌리기, 골목 선 그리기·이름 붙이기·삭제, 출입구 찍기, 도로 규칙 표(도로명·건물번호 구간·IN/OUT·이유), 시장 중심 핀 이동·반경 입력, "확인 필요" 목록(가게 → 골목 선택), 저장하면 그 시장을 바로 재판정해 바뀐 가게 수를 보여 준다.
- 공개 시장 섹션: 경계 선, 골목 선(이름 라벨), 출입구 표시, 가게 색은 배정된 골목, OSM 출처 표시. 경계가 없으면 지금 화면 그대로.
- 상인회: 경계·골목 선·도로 규칙은 직접 고치지 않는다. **변경 요청**(그림 + 설명)을 올리고 운영자가 승인하면 반영된다.

### 11.6 수용 기준

- AC-P4-1: 광명 표본(OSM 2026-10-15)으로 재판정하면 §11.2 기대값이 나온다.
- AC-P4-2: 경계를 고친 뒤 재적재해도 `MANUAL` 경계·골목 선·출입구·도로 규칙이 그대로다.
- AC-P4-3: 경계 저장 → 같은 요청 안에서 재판정, 응답에 바뀐 가게 수. 되돌리기로 이전 판정이 복원된다.
- AC-P4-4: 경계가 없는 시장은 도로 규칙 → 반경 판정 순서로 간다(규칙 하나로 큰길 141곳을 한 번에 IN/OUT).
- AC-P4-5: 공개·어드민 지도에 OSM 출처 표시가 있다. 공개 API 는 확인 필요 플래그와 OSM 원본 payload 를 내지 않는다.
- AC-P4-6: 상인회 변경 요청은 승인 전까지 판정에 영향이 없고, 승인하면 운영자 편집과 같은 경로로 반영·이력이 남는다.

## 12. P6 — 가게 가격대 (2026-10-15 추가)

정본: `p6-contract.md`.

- 원천은 행정안전부 「착한가격업소 현황」(#3045247, 파일·키 없음·분기 갱신, 이용허락범위 제한 없음) 하나다. 대표 메뉴 최대 4개와 가격을 준다.
- 시장 가게와는 이름+시군구, 없으면 도로명·건물번호+이름 포함 관계로 맞춘다. 모호하면 붙이지 않는다. 실측 약 105곳·80여 개 시장(2026-10-15).
- 화면은 착한가격 배지·메뉴·가격, 시장별 「착한가격업소 N곳 · 가격 범위」, 메뉴 이름 검색이다.
- 시장별 품목 시세는 넣지 않는다. 한국소비자원 참가격 월간 파일(#15083256, 2026-09)에는 전통시장 판매점이 없고(이름에 「시장」이 든 2곳은 마트 지점), 품목도 포장 상품이다. 서울시 생필품 시세(OA-23055)는 서울 열린데이터 키가 없어 확인하지 못했다.
