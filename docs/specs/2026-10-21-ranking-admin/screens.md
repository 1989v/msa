### 1280px 기준 배치

- 1280×800 우선. 사이드바 240px + 콘텐츠 1040px이며 콘텐츠 좌우 여백은 spacing.6(24px)이다. 본문 실사용 폭은 992px이다.
- 상단 Header는 기존 셸을 따른다. 화면 제목→탭→상태 요약→필터→표→페이지 순으로 둔다.
- 목록은 행 높이 최소 52px, 본문 14px, 보조 라벨 12px, 제목 24px를 사용한다. 숫자는 우측 정렬·tabular-nums다.
- 표는 행 전체를 링크로 만들지 않고 메뉴명·상세 버튼을 분리한다. 긴 메뉴명은 2줄까지 표시하고 전체 이름은 상세에서 읽는다.
- S2는 전용 상세 페이지다. 992px 안에서 원천과 교정 두 패널을 나란히 두며 목록 표와 동시에 좁은 드로어를 띄우지 않는다.
- DESIGN.md의 dark-trading 토큰·기존 UI 컴포넌트를 우선 사용한다. colors.surface_1·surface_2·text_primary·primary와 spacing·radius 토큰만 참조하며 hex를 새로 입력하지 않는다.
- 위험·충돌은 배지·아이콘·설명 문구를 병기한다. 색만으로 구별하지 않는다. 한 화면의 주 액션은 하나다.
- 1024px 미만은 셸을 접고 필터를 줄바꿈한다. 768px 미만 상세는 원천→교정 순으로 쌓으며 필드 이름을 반복한다. 200% 확대에서도 입력·버튼이 겹치지 않는다.

### 필터·페이지·선택

- 기본 size=50, 선택지 20/50/100/200, page=0부터다. 필터 적용 시 첫 페이지로 돌아간다. 전체 수·필터 결과 수·선택 수를 구분한다.
- q는 원천 메뉴명과 교정 표시명을 검색한다. Enter·검색 버튼으로 제출한다. 필터는 적용 시 한 번 요청하며 입력 중 목록을 흔들지 않는다.
- 유형 기준은 ‘유효값’이 기본이며 ‘기본 분류’를 선택해 원래 기타였던 행을 재검토할 수 있다. 상태는 원천만/교정/충돌/소멸을 지원한다.
- 소멸 필터는 원천이 없는 교정 레코드도 반환한다. 영양값 자리에 ‘원천 행 없음’, 상세에는 읽기 전용 원천 기준 스냅샷을 표시한다.
- 기본 정렬은 브랜드→원천 메뉴명→온도→사이즈→카페인 상태다. 같은 이름의 일반/디카페인을 합치지 않는다.
- 행의 변형 셀은 온도·사이즈·카페인 상태를 표시한다. null은 ‘미표시’다. 전체 자연키는 상세에서 확인한다.
- 페이지 이동은 선택을 유지한다. q·필터·정렬이 바뀌면 선택을 비우고 알린다. URL에 필터·정렬·페이지를 남기며 선택 키·근거 메모는 URL에 넣지 않는다.
- 헤더 체크는 현재 페이지 선택이다. ‘필터 결과 157행 선택’은 서버가 고정한 157개 키를 가져와 명시적으로 선택한다. 200행 초과면 조건을 좁히도록 안내한다.
- 충돌은 필드 수와 행 수를 혼용하지 않는다. 한 행에 2필드 충돌이면 요약에 ‘1행·2필드’를 표시한다.

### 필드와 저장

- 좌측 원천 25필드·notes·raw 영양표는 열람 전용이다. 영양 원문 탭은 문자열로 안전하게 표시하며 외부 HTML을 실행하지 않는다.
- 좌측 유형·컵용량·농도에는 ‘기본 파생’을 명시한다. 우측에는 원천 사용/교정값 사용/미확정 세 상태와 현재 유효값을 보인다.
- 용량 ‘미확정’은 자동 용량 추론을 중지한다. 유효 컵용량은 ‘운영 검토로 미확정’, 모든 100ml 값은 ‘산출 불가’로 표시한다. ‘해제’ 후에만 원천/사이즈표 추론을 재개한다.
- P1 자연키 5요소는 잠금 표시한다. 잘못된 키·카페인 상태는 ‘원천 재적재 검토’ 안내를 제공하고 저장 대상에서 제외한다.
- 원천 사용은 RESET, 미확정 체크는 SET_UNKNOWN이다. 입력칸을 비운 상태는 검증 오류이며 자동 0·null 저장을 하지 않는다.
- 숨겨진 필드와 원천 전체 값을 다시 조립해 보내지 않는다. 변경된 allowlist 필드만 PATCH한다. 정밀도·양수 용량·카페인 상태 제약은 plan §3을 따른다.
- 저장 전 차이·공개 유효값·영향 유형을 보여 준다. 수정 사유·근거 URL·확인일이 없으면 저장 불가다. 브랜드 검증일 수정과 행 확인일 수정을 혼용하지 않는다.
- 저장 중 버튼 중복 클릭을 막고 입력값을 유지한다. 성공 시 operationId·서버 저장 시각을 표시하고 상세·목록·유형 수를 재조회한다.
- 409는 ‘다른 수정 또는 새 적재가 반영됨’ 안내와 최신값 재조회 버튼을 제공한다. 초안을 보존하고 자동 덮어쓰지 않는다.
- CONFLICT 필드에는 ‘현재 원천을 임시 사용 중’을 표시하며 S5로 이동한다. 일반 저장으로 충돌을 우회 해제하지 않는다.
- ORPHANED 상세는 이전 기준값·교정·감사만 보이며 일반 저장을 잠근다. 키 재연결은 P2다.

## 4. S3 — 유형 일괄 교정

```text
+------------------------------------------------------------------------------+
| 유형 일괄 교정 / 선택 157행                                                  |
| 1. 대상 확인  ->  2. 변경 미리보기  ->  3. 반영 결과                          |
+------------------------------------------------------------------------------+
| 출발: 기본 분류=기타 / 브랜드=전체 / 선택 당시 157행                         |
| 선택 키 고정. 이후 새로 들어온 행은 이번 대상에 포함하지 않음                |
| 변경할 유형 [티 v]  근거 URL [https://...]  확인일 [2026-10-21]               |
| 사유* [공식 메뉴명·카테고리 대조 후 유형 교정                              ] |
| [미리보기 생성]                                                            |
+------------------------------------------------------------------------------+
| 브랜드/메뉴       변형          원천 분류    기존 유효 유형 -> 변경 유형     |
| A / 메뉴 예시     ICE/M/ZERO    차           기타          -> 티              |
| B / 메뉴 예시     HOT/L/DECAF   음료         기타          -> 티              |
| ... 페이지 1/4 (선택 157행 전체 대상)                                       |
| 변경 150행 / 이미 동일 7행 / 차단 0행 | 미리보기 만료까지 04:59              |
+------------------------------------------------------------------------------+
| [취소] [대상 다시 선택]                                  [150행 교정 반영] |
+------------------------------------------------------------------------------+
```

- ‘기타’ 전체를 하나의 유형으로 자동 확정하지 않는다. 운영자가 후보를 확인한 뒤 같은 유형인 행만 선택한다. 157행 전량 선택은 동질 fixture의 수용 시나리오다.
- 선택 단계에서 행을 제외할 수 있다. 메뉴명·원문 카테고리·변형·기존 유효 유형을 비교한다. 세부 근거는 S2로 새 탭 없이 이동 후 복귀한다.
- 미리보기에는 명시적 키≤200개와 각 revision·generation을 고정한다. 브라우저의 현재 필터 문자열만으로 적용하지 않는다.
- 같은 유형인 행은 ‘변경 없음’으로 제외한다. 차단 행이 하나라도 있으면 반영 버튼을 잠그고 재선택·미리보기 재생성을 요구한다.
- 이미 교정된 행은 기존 교정을 바꾸는 사실을 강조한다. 충돌·소멸 행은 일반 일괄 교정에서 차단한다.
- 근거가 다른 행은 분리 작업으로 처리한다. 공통 URL과 사유만으로 실제 검토하지 않은 메뉴를 일괄 확인 처리하지 않는다.
- 미리보기 5분 만료, 세대/revision 변경, 허용 유형 변경은 409다. 일부 성공은 없다. 실패 시 전체 변경 0행과 원인을 표시한다.
- 성공 화면에 ‘변경 150행·변경 없음 7행’, operationId, 감사 연결, [되돌리기 검토]를 표시한다. 화면의 성공 수는 서버 결과만 사용한다.

```text
| 실행/시작(KST)   대상      상태       입력  반영  제거  재적용  충돌  소요   |
| run-104 / 14:00  A 브랜드  성공        198   198   198    12      2    3초   |
| run-103 / 13:55  B 브랜드  실패        120     0     0     0      0    1초   |
| run-102 / 13:40  A 브랜드  중단 의심    --     0    --    --     --   20분   |
| [이전] 1 [다음]                                                             |
+------------------------------------------------------------------------------+
| run-104 상세 | source checkedAt 범위 10-19~10-20 / 서버 적재 10-21 14:00      |
| parentRunId ... | 브랜드 세대 41 -> 42 | 원천 교체 성공                      |
| 재적용 12필드 / 충돌 1행·2필드 / 소멸 0키 [연결 충돌 보기]                 |
| 오류 요약: 없음 / 실행 주체: 수집 잡                                         |
+------------------------------------------------------------------------------+
```

- ‘제거’는 브랜드 전체 교체로 지운 기존 원천 행 수다. 원천의 사업상 단종 수와 동일하지 않음을 설명한다.
- parent 실행이 일부 브랜드만 성공하면 PARTIAL을 표시하고 브랜드 하위 실행으로 분해한다. 성공 브랜드까지 실패로 표현하지 않는다.
- RUNNING에는 진행 중, 15분 초과 INTERRUPTED에는 ‘완료 확인 안 됨’을 표시한다. 접속 실패 등 서버 수신 전 오류는 미보고일 수 있다는 범위를 명시한다.
- 이력 도입 전 데이터는 ‘이력 수집 이전’이다. checkedAt로 적재일을 채우지 않는다. 목록 0건은 ‘저장된 적재 이력이 없음’이다.
- 오류는 오류 코드·단계·요약만 보여 주며 원문 파일·키·stacktrace를 노출하지 않는다. 재수집·재실행·업로드 버튼은 P1에 없다.

## 6. S5 — 충돌 목록과 검토

```text
+------------------------------------------------------------------------------+
| 충돌 검토 / 검토 필요 3행·4필드                                              |
| 브랜드[전체 v] 필드[전체 v] 상태[충돌 v] 적재 runId[       ] [조회]           |
+------------------------------------------------------------------------------+
| 선택 대상             필드     이전 원천  새 원천    교정값  현재 유효값     |
| A / 메뉴 ICE/L/DECAF   당류     18.0g      12.0g      16.0g   12.0g          |
| B / 메뉴 HOT/M/ZERO    유형     기타       티         라떼    티             |
| C / 메뉴 ICE/M/ZERO    원천키   존재       없음       유형교정  공개 행 없음 |
+------------------------------------------------------------------------------+
| 검토: A / 메뉴 / 당류 | 검출 2026-10-21 14:00 KST / run-104                  |
| 현재 공식 원문 [링크] | 교정 당시 근거 [링크] | 원천 변경 사유: 당류 변경   |
| (o) 새 원천 채택 — 교정 해제, 유효값 12g                                    |
| ( ) 교정 유지 — 현재 원천 기준 재승인, 유효값 16g                           |
| ( ) 새 교정값 [     ] g                                                     |
| 사유* [                   ] 근거 URL* [https://...] 확인일* [날짜]          |
| [취소]                                                     [검토 결과 저장] |
+------------------------------------------------------------------------------+
```

- 기본 정렬은 미해결·오래된 검출 순이다. 원천 변경·원천과 일치·키 소멸·키 재등장·규칙 변경을 배지로 구별한다.
- 숫자뿐 아니라 유형 의존값·규칙 버전 차이도 보여 준다. ‘현재 유효값’으로 공개 결과를 확인한다.
- 새 원천 채택·교정 유지·새 값 입력을 필드별로 결정한다. 충돌 여러 건의 일괄 ‘그대로 유지’는 P1에 넣지 않는다.
- 키 소멸 상태는 공개 행 없음과 교정 보존을 명시한다. 현재 원천이 없으므로 유지·새 값 적용은 잠근다. 교정 해제 또는 검토 대기만 가능하다.
- 키 재등장은 새 원천과 과거 교정을 비교하고 재승인할 수 있다. 다른 키로 이동하는 기능은 제공하지 않는다.
- 저장 직전 revision·generation을 검사한다. 변경되면 최신값을 보여 주고 기존 선택을 자동 제출하지 않는다.

## 7. S6 — 브랜드 출처·확인일

```text
+------------------------------------------------------------------------------+
| 브랜드 출처 / 확인                                                          |
| 브랜드      행 수  원천 확인일 범위      운영 검증일      출처·권리 확인     |
| A 브랜드     198   10-19 ~ 10-20         10-21            미확인            |
| B 브랜드     329   10-20 ~ 10-20         미검증           미확인            |
+------------------------------------------------------------------------------+
| A 브랜드 검증                                                              |
| 행별 공식 URL 집합 [목록 펼치기]  원천 최저/최신 확인일 10-19 / 10-20        |
| 운영 검증 공식 URL [https://...                    ] [행 추가]              |
| 운영 검증일 [2026-10-21] 검증 메모 [공식 영양 공지 대조                   ]  |
| 변경 사유* [                                ]                              |
| 행별 sourceUrl·checkedAt는 이 작업으로 변경되지 않음                        |
| [취소]                                                   [검증 정보 저장]   |
+------------------------------------------------------------------------------+
```

- 행별 sourceUrl·checkedAt 집계와 운영 검증 메타를 별도 제목으로 보여 준다. 최신 날짜만으로 전체 행이 최신이라고 표시하지 않는다.
- 출처·라이선스·자동수집 조건의 기준 문서는 `docs/architecture/data-sources.md` §9다. 미확인은 ‘허가됨’이 아니다.
- P1 권리 확인 정보는 대장 기준 읽기 전용이다. 권리 판단 자체를 URL 입력만으로 바꾸지 않는다.
- 링크는 사용자 클릭으로 공식 원문을 새 탭에서 연다. 서버의 URL 저장·검증은 외부 URL 요청을 만들지 않는다.
- 출처 URL 추가·삭제·날짜 수정도 사유·revision·감사와 되돌리기 대상이다. 행별 링크가 틀리면 S2에서 별도 교정한다.

## 8. S7 — 감사와 되돌리기

```text
+------------------------------------------------------------------------------+
| 변경 이력                                                                  |
| 기간[       ~       ] 행위자[회원ID] 대상[키/브랜드] 작업ID[     ] [조회]    |
| 시각(KST)    작업         행위자    대상/변경               사유    상세     |
| 14:03        유형 일괄    회원 27   150행 기타 -> 티        대조    [보기]   |
| 14:00        충돌 검출    SYSTEM    A / 당류                 적재    [보기]   |
+------------------------------------------------------------------------------+
| 작업 op-201 / 변경 150행 / 영향 필드 drinkGroup                              |
| 되돌릴 상태: 이전 교정 복구 또는 원천 사용 / 원천 데이터 복원 없음          |
| 되돌리기 검사: 150행 가능 / 후속 변경 0 / 원천 변경 0                        |
| 사유* [일괄 분류 검토 결과 수정                                             ]|
| [취소]                                           [150행 되돌리기 실행]      |
+------------------------------------------------------------------------------+
```

- operation 단위 이력에서 행별 전후 상태를 페이지로 펼친다. 회원 ID·서버 시각·근거·revision을 제공한다.
- 되돌리기에는 변경 대상 수와 결과 미리보기를 제공한다. 실행 시 서버가 다시 검사하며 하나라도 후속 변경이 있으면 전체 취소한다.
- 되돌릴 수 없으면 버튼 비활성화와 ‘이후 교정 있음’·‘원천 재적재됨’ 같은 사유를 표시한다. 현재 상태를 기준으로 새 교정 작성 링크를 제공한다.
- SYSTEM 적재·충돌 기록은 직접 역실행하지 않는다. 되돌리기 대상은 관리자 교정·해제·검증·해결 작업이다.
- 결과 불명 상태는 제출 전에 생성한 operationId로 조회한다. 결과가 없으면 같은 키·본문으로 재시도하며 새 operation으로 만들지 않는다.

## 9. S8 — 주유소 보드·스냅샷 상태

```text
+------------------------------------------------------------------------------+
| 주유소 보드 / 읽기 전용                                                     |
| 지역[전체 v] 유종[전체 v] 보드상태[전체 v] 진단[전체 v] [조회]               |
| 전국 전량이 아닌 지역·유종별 최저가 TOP20 수집 범위                          |
+------------------------------------------------------------------------------+
| 지역/유종     보드상태  진단       최신 관측(KST)  저장/실제 수  최신ID      |
| 지역 A 휘발유 OPEN      정상       10-21 05:00     20 / 20       3041        |
| 지역 A 경유   OPEN      지연       10-19 05:00     18 / 18       3002        |
| 지역 B 휘발유 OPEN      미생성     --              -- / --       없음        |
| 지역 B 경유   OPEN      정합 오류  10-21 05:00     20 / 19       3045        |
+------------------------------------------------------------------------------+
| 보드 상세 / gas-...  출처: 오피넷  단위: 원/L                                |
| 스냅샷 선택 [2026-10-21 05:00 / 최신 v] 보관 기준 30일                      |
| 순위  주유소명   subjectKey    가격      이전 순위/등락                       |
| 1     예시       gas:...       1,599     신규 진입                          |
| 2     예시       gas:...       1,602     5 / 상승 3                          |
| [payload 상세 펼치기]                                                       |
+------------------------------------------------------------------------------+
```

- OPEN 같은 도메인 상태와 정상/지연/미생성/정합 오류 진단을 분리한다. 스냅샷 갱신·원천 확인 시각은 별도다.
- 36시간 지연은 제안 운영 기준이다. 원인을 확인하지 않고 ‘수집 실패’로 단정하지 않는다.
- 20행 미만은 후보 부족일 수 있다. 저장 entryCount와 실제 수 차이, 끊긴 최신 포인터는 정합 오류다.
- prevRank=null은 ‘신규 진입’이다. 가격·순위·포인터 입력칸, 재생성·삭제·롤백 버튼은 제공하지 않는다.
- 과거 스냅샷 없음은 ‘보관기간 경과 또는 자료 없음’이다. 과거 원장 전체 보존을 약속하지 않는다. 출처: plan E1·E2·E15.

## 10. 상태·접근성·화면 검수

아래 상태 계약은 S1~S8 전체에 적용한다. 목록 0행과 요청 실패가 동시에 표시되지 않도록 한다.

| 상태 | 표시·가능 액션 | 저장·데이터 처리 |
|---|---|---|
| 최초 로딩 | 제목·열 구조 유지, ‘불러오는 중’과 skeleton | 변경 버튼 잠금, 0건 문구 미표시 |
| 조건에 맞는 결과 없음 | ‘조건에 맞는 데이터 없음’, 필터 초기화 | 전체 데이터 없음과 구별 |
| 원천·이력 없음 | ‘아직 적재된 자료 없음’ 또는 ‘이력 수집 이전’ | 생성·수집 버튼을 임의 제공하지 않음 |
| 조회 오류·시간초과 | 오류 요약·다시 시도, 기존 결과가 있으면 ‘이전 조회’ 표시 | 실패를 0건으로 바꾸지 않음, 오래된 선택 적용 잠금 |
| 저장 검증 오류 400 | 필드 아래 이유, 오류 요약에서 해당 필드로 이동 | 입력·사유 보존 |
| 동시 수정 409 | 최신 기준 변경 요약·재조회·미리보기 재생성 | 자동 덮어쓰기·부분 반영 없음 |
| 저장 5xx·네트워크 결과 불명 | ‘처리 결과 확인 중’, operation 결과 조회 | 임의 성공 알림·새 작업 재제출 금지 |
| 미인증 401 | 기존 세션 갱신 후 로그인 흐름 | 민감 초안을 URL·분석 로그에 남기지 않음 |
| 권한 없음 403 | ‘관리자 권한이 필요함’, 기존 UnauthorizedPage 연결 | 민감 값 숨김, 교정·재시도 버튼 제거 |
| 대상 없음 404 | ‘원천 행을 찾을 수 없음’, 소멸 교정/감사 조회 또는 목록 복귀 | 다른 행에 자동 연결 금지 |
| 일부 보조 조회 실패 | 행 데이터는 표시, 요약/브랜드 출처만 ‘확인 불가’ | 실패한 영역 재조회, 해당 정보를 요구하는 쓰기 잠금 |
| 교정 저장 성공 | 서버 변경 수·시각·operationId, 감사 링크 | 관련 query 갱신, 미저장 상태 해제 |

### 키보드·이탈·검수 기준

- Tab 순서는 제목·탭→검색→필터→선택→행 상세→페이지다. 표 헤더와 checkbox에 범위·대상 이름을 제공한다.
- 포커스 링을 유지하고 검증 오류 시 첫 오류 필드로 이동한다. 저장 결과·선택 건수는 aria-live로 전달한다.
- 미저장 입력이 있는 화면 이탈은 ‘편집 계속’·‘변경 버리고 이동’ 선택을 제공한다. 물음표로 된 모달 제목은 사용하지 않는다.
- 검색·목록 복귀 시 URL 조건·페이지·스크롤 위치를 복원한다. 새 데이터 때문에 페이지가 비면 이전 유효 페이지로 이동하며 안내한다.
- 1280×800과 200% 확대에서 목록/상세 잘림·버튼 겹침을 검수한다. 작은 화면은 768px 및 390px에서 입력·상태·페이지 조작 가능성을 확인한다.
- 정상·빈·조회 오류·저장 오류·403·충돌·소멸·157행 선택·일괄 409 fixture를 각각 검수한다. 이는 향후 구현 검수 계획이며 현재 렌더 결과가 아니다.

## 11. 요약과 사용자 결정 필요 항목

**[제안 요약]** 목록에서 오류 후보를 찾고 원천·교정을 나란히 비교한 뒤, 단일 또는 최대 200행의 유형 교정을 반영한다.
적재 이력과 충돌을 연결하고, 모든 관리자 변경은 감사·되돌리기 경로를 제공한다. 주유소는 읽기 전용으로 둔다.

| 사용자 결정 필요 항목 | 권고 초안 | 관련 화면 |
|---|---|---|
| 상세 표시 방식 | 전용 페이지의 원천/교정 2열 | S2 |
| 일괄 범위 | 최대 200행·5분 미리보기·전부 성공 또는 취소 | S3 |
| 충돌 시 공개값 | 새 원천 사용, 교정 재승인까지 적용 보류 | S2·S5 |
| 적재·스냅샷 실행 버튼 | P1 제외, 상태 조회만 제공 | S4·S8 |
| P1 자연키·카페인 상태 수정 | 잠금, 원천 재적재 검토로 안내 | S2 |

정책 결정의 원본은 plan §9다. 이 화면설계서 승인은 구현·배포·운영 데이터 변경 승인을 포함하지 않는다.
