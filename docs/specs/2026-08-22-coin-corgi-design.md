# 코인 코기 (coin-corgi) — 설계 문서

> 장르 프리셋: `casual-catch` (낙하물 받기·피하기 캐주얼 아케이드)
> 표준: `docs/standards/game-cleanroom-pipeline.md`

한 판 40~90초. 하늘에서 쏟아지는 돈은 받고 똥과 벌은 피한다.
짖어서 벌을 쫓고 똥을 밀어내며 배율을 쌓는 게 이 게임의 전부다.

---

## 1. 한 줄 요약

**받는 건 관대하게, 피하는 건 정확하게.** 이 비대칭이 손맛의 전부이고,
나머지 설계는 그 비대칭이 계속 성립하도록 붙어 있다.

---

## 2. 벤치마크 대비 자평 (6축)

벤치마크 = **2000년대 캐주얼 웹 아케이드 낙하물 게임 대표작군**의 완성도.
이 장르는 분량이 아니라 밀도·반응성·재시작 마찰로 평가된다.

| 축 | 벤치마크 수준 | 코인 코기 | 판정 |
|---|---|---|---|
| ①그래픽 | 단색 스프라이트 + 단일 배경 | 1080×1440 캔버스, 전 개체 3톤 명암 + 외곽선 + 접지 그림자, 배경 4레이어 | **상회** |
| ②애니메이션 | 2~3프레임 루프 | 절차 리그(대기/이동/대시/피격/웅크림/공중) + 스쿼시&스트레치 + 귀·꼬리 2차 모션 | **상회** |
| ③해상도·화면 활용 | 640×480급 고정 | 1440p급 세로 캔버스, 존별 파랄랙스·비네트 | **상회** |
| ④이펙트 밀도 | 획득 시 점수 텍스트만 | 파티클 3종(dot/shard/star) 420풀 · 링 · 히트스톱 · 화면 흔들림 · 전체 플래시 | **상회** |
| ⑤조작감 | 좌우 이동만, 가속 없음 | 이동·점프·웅크림·대시·짖기 5액션, 입력→이동 ≤2프레임, 정지→최고속 0.09초 | **상회** |
| ⑥연출 | 없음 | 존 3종 크로스페이드 + 존별 BGM 교체 + 이벤트 배너 + 최고기록 갱신 전용 연출 | **상회** |

**못 따라잡은 것**: 없음. 다만 이 벤치마크는 대작이 아니라 팝콘 장르의 하한선이므로,
"상회" 는 자랑이 아니라 **최소 조건 충족**으로 읽어야 한다.

## 3. 판정 비대칭 (실측)

| 항목 | 값 |
|---|---|
| 스프라이트 반폭 | 95px |
| 보상 판정 도달거리 | **153px** |
| 코인 시각 접촉 거리 | 133px |
| → 보상은 시각 접촉보다 | **20px 먼저 먹힌다** (관대) |
| 피해 판정 도달거리 | **115px** |
| 똥 시각 접촉 거리 | 137px |
| → 피해는 시각 접촉보다 | **22px 더 겹쳐야 맞는다** (정확) |

합격 기준 충족: "닿을 것 같은데 안 먹힌" 0 · "안 닿았는데 맞은" 0.

**웅크리기**는 이 비대칭을 플레이어가 직접 조절하는 장치다 —
피해 판정이 줄지만 보상 판정도 같이 줄고 이동속도가 42%로 떨어진다.

## 4. 응답성 (프리셋 목표 대비 실측)

| 항목 | 목표 | 실제 |
|---|---|---|
| 방향 입력 → 이동 시작 | ≤2프레임 | 1프레임 (엣지를 시뮬 전에 수집) |
| 화면 폭 횡단 (보행) | 1.1~1.5초 | **1.23초** (880px/s) |
| 정지 → 최고속 | ≤0.1초 | **0.09초** (가속 9800px/s²) |
| 대시 발동 / 지속 | ≤2프레임 / 0.12~0.18초 | 1프레임 / **0.15초** (2400px/s, 쿨 0.9초) |
| 사망 → 재시작 입력 수용 | ≤0.6초 | **0.35초** |
| 재시작 → 첫 낙하물 | ≤1.0초 | **0.9초** |
| 프레임 | 60fps 이상 | **119~125fps** (120Hz 디스플레이, 148초 완주 회귀 중) |

프레임 페이싱은 고정 1/60 누적이 아니라 **클램프된 가변 스텝**(프레임당 1~4 서브스텝,
서브스텝 ≤20ms, 프레임 dt 상한 80ms). 120Hz 에서 렌더 프레임의 절반이 0스텝으로
도는 미세 스터터를 막는다.

## 5. 낙하물 8종

| 종류 | 반지름 | 낙하속도 | 효과 | 등장 |
|---|---|---|---|---|
| 동전 | 38 | 520 | +10 × 배율 | 티어 0~ |
| 지폐 | 40 | 470 | +45 × 배율 | 티어 0~ |
| **금괴** | 46 | **800** | **+180 × 배율** | 티어 1~ · **항상 똥 2개와 세트**(±132px) |
| 똥 | 42 | 560 | 하트 −1, 콤보 리셋 | 티어 0~ |
| 벌 | 40 | 300 + 수평 유도 | 하트 −1 · **짖기로 격퇴** | 티어 2~ |
| 뼈다귀 | 42 | 430 | 자석 5초 (반경 420) | 티어 0~ |
| 우산 | 44 | 430 | 실드 1회 | 티어 0~ |
| 하트 | 40 | 420 | 하트 +1 (최대 5) | 티어 3~ |

**리스크-리워드의 실체**: 금괴는 단독으로 내려오지 않는다. 실측 확인 — 관측된 금괴 스폰
전부가 좌우 132px 에 똥을 대동했다. 먹으려면 두 위험 사이의 좁은 통로에 들어가야 한다.

**벌의 텔레그래프**: 스폰 시 소리(저음 경보) + 화면 상단에 **삼각형 경고 마커**로 0.9초
예고하고, 그동안 내려오지 않는다. 색이 아니라 **형태**로 구분된다.

## 6. 진행

- **티어**: 15초마다 상승, 최대 8. 낙하 속도 ×1.0→×1.9, 스폰 간격 0.22→0.13초.
  **점수가 아니라 시간 기준**이다 (점수 기준이면 잘하는 사람만 어려워져 곡선이 뒤집힌다).
- **존**: 34초마다 순환(2.6초 크로스페이드) — 햇살 공원 / 노을 골목 / 네온 옥상.
  배경·팔레트·**BGM 이 전부 바뀐다**.
- **초반 8초**는 스폰 간격에 warmup 계수(최대 ×2.28)를 걸어 확실히 쉽다.
  튜토리얼 모달 대신 난이도로 가르친다.

### 이벤트 웨이브 2종 (26초 간격 교대)

| 이벤트 | 지속 | 내용 |
|---|---|---|
| **돈벼락** | 6초 | 동전·지폐만 0.17초 간격. **시작 시 화면의 위험물을 전부 날린다** — 배너가 "똥은 잠시 멈춘다" 고 약속했으면 실제로 지켜야 한다 |
| **비둘기 습격** | 5.5초 | 비둘기 최대 4마리가 사선으로 가로지르며 똥을 투하. 평소와 다른 각도의 위협 |

## 7. 중독 구조 (프리셋 4대 요소)

1. **콤보 배율** — 보상 4개마다 ×1 상승, 최대 ×8. 피격 시 리셋.
   HUD 중앙에 76px 로 크게. **획득음의 음정도 배율을 따라 올라간다**(8단계).
2. **리스크-리워드** — 금괴 세트 (§5)
3. **갱신 피드백** — 최고 기록 갱신 시 전용 아르페지오 + 금색 플래시 + 결과 화면 문구 변화
4. **메타 진행** — 누적 획득액으로 해금: 4,000원 하얀 시바 / 15,000원 닥스훈트 /
   30,000원 시작 하트 +1. 세 견종은 색만 다른 게 아니라 **몸 길이·다리 길이·귀 모양·꼬리가
   전부 다른 리그**를 쓴다.

## 9. 아트

- 외곽선 `#2A1A2E` 를 전 개체가 공유한다 — 이게 팔레트 통일의 축이다

- 화면 흔들림 시 가장자리가 비지 않도록 배경을 **화면 밖 60px 까지** 칠한다

## 10. 사운드

WebAudio 자체 신스. **외부 오디오 파일 0**. 첫 사용자 입력 후 AudioContext 활성화.
BGM 은 존별 16스텝 시퀀서(베이스/아르페지오/하이햇/킥)를 게임 루프에서 0.18초 룩어헤드로 스케줄.

## 11. 검증 결과

| 항목 | 결과 |
|---|---|
| 콘솔 메시지 | **0** (148초 완주 회귀 후 포함) |
| 죽은 입력 감사 | **120칸(4씬 × 30키) 중 0칸 죽음** |
| 전 낙하물 스모크 | 8/8 스폰·렌더 성공 |
| 파워업 실발동 | 자석·실드·하트 3/3 |
| 실드 흡수 | 하트 유지 + 실드 소모 확인 |
| 피격→무적→게임오버 | 무적 중 재피격 차단 확인, 결과 화면 도달 확인 |
| 금괴 세트 스폰 | 관측 전부 똥 2개 대동 |
| 이벤트 2종 | 돈벼락(위험물 소거 확인) · 비둘기 습격(4마리 스폰) 확인 |
| 존·티어 진행 | 존 0→1→2→0→1 순환, 티어 0→8 도달 |
| localStorage 영속 | 새로고침 후 최고점·누적·해금 유지 |
| fps | 119~125 |
| 자동 플레이 봇 | 무보정 55.7초 생존 / 피격 4회 — 프리셋의 "3분 무사고면 너무 쉽다" 기준 통과 |

### 죽은 입력 감사에서 실제로 잡힌 결함 2종

1. **음소거(M)가 4개 씬 전부에서 소리도 화면도 안 바꿨다** — 토스트만 떠서 "고장" 으로 읽혔다.
   → 확인음 + 화면 플래시 추가.
2. **플레이 중 R(재시작)이 소리 없이 판을 리셋했다** — 눌렸는지 알 수 없었다. → 확인음 추가.

둘 다 자동 검증이 아니었으면 놓쳤을 부류다.

### 측정이 틀렸던 사례 (기록 의무)

피해 판정 도달거리 1차 측정이 **0px** 로 나와 "똥이 아예 안 맞는다" 로 읽혔다.
원인은 게임이 아니라 하네스 — 테스트가 똥을 피해 판정 밴드(y 1130~1260) **위쪽**에
놓고 220ms 만 기다려 밴드에 도달하지 못했다. 밴드 한가운데에 놓고 재측정하니 115px.
같은 원인으로 "실드가 피격을 안 먹는다" 도 거짓 양성이었다.
**대량 실패가 한꺼번에 나오면 코드보다 측정을 먼저 의심하라**(파이프라인 실측 함정 그대로).

## 12. 기술

순수 정적 웹 — HTML + JS + Canvas 2D. **빌드 스텝 없음, 런타임 외부 요청 0.**
WASM/WebGL/Worker 미도입 (기술 도입 게이트: 프레임 예산의 일부만 쓰고 있어 병목 없음).

```
coin-corgi/
  index.html
  js/audio.js   WebAudio 신스 + 존별 BGM 시퀀서
  js/input.js   키 계약 · 엣지/홀드 분리
  js/fx.js      파티클·텍스트·링 풀 / 흔들림 / 히트스톱
  js/art.js     팔레트 · 배경 4레이어 · 강아지 리그 3종 · 낙하물 8종
  js/meta.js    localStorage 메타 진행 (실패해도 게임은 돈다)
  js/game.js    시뮬 코어 · 판정 · 스폰 · 이벤트
  js/main.js    루프 · 씬 · HUD · 검증 훅(dev.*)
```

### 검증 훅

`dev.scene(name)` · `dev.stats()` · `dev.smoke()` · `dev.bot(true)` · `dev.fps(true)`
— 씬 도달 비용을 상수로 낮추기 위한 것. 봇은 실제 입력 상태와 공개 액션 API 만 쓰며
쿨다운을 우회하지 않는다.

## 13. IP

메커닉(낙하물 받기·피하기, 콤보 배율)은 장르 문법이라 자유롭게 쓰되,
**특정 작품의 규칙 조합·진행 구조·화면 배치를 이식하지 않았다.**
캐릭터·명칭·팔레트·UI 는 전부 이 프로젝트에서 창작했다.
견종명(웰시 코기·시바·닥스훈트)은 일반 명사다.
