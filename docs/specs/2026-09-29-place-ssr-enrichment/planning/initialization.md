## 직전 맥락

- 「1번」 = 관광지 상세를 크롤러가 본문과 함께 받게 하는 일. 처음 제안은 sitemap 축소였으나 사용자는
  **전부 노출**을 원한다 → 블로그 전례(ADR-0072 §6)대로 요청 시 서버가 HTML 을 만드는 방향.
- 「2번」 = 관광지 페이지의 자체 가치. 후보 A(속성 추출·정규화) · B(지역 안 위치 집계) ·
  C(임베딩 유사 관광지) · D(이용 기반 인기도). 사용자는 A~D 를 **검색 필터(패싯) 보강** 방향으로 확장하길 원한다.
- 「이미 있는 것은 두고」 = 주변 관광지 섹션 · 편의시설 섹션 · 링크 섹션 · 인기 집계 원장 · 임베딩은 유지.
