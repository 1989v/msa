# 아홉 종 — 플레이 시뮬레이션 · 그래픽 재판정 (2026-09-02)

CDP 키 이벤트로 게임을 직접 몰면서(걷기·달리기·점프·벽 붙기·공격·구르기·막기) 스크린샷과
fps 를 모았다. 조작 **버튼**은 웹 오버레이가 쏘는 키라 합성 입력이 안 들어가고, **키보드**는
들어간다 — 그래서 키보드로 몬다. 상자 앞에 붙이는 것은 화면 색으로 상자를 찾아 조향하는
드라이버(`scratchpad/aim/run.mjs`)까지 만들었는데 붙는 순간 미끄러져 지나가 여섯 번 실패했다.
그 장면만은 사람이 봐야 한다.

## 1. 시뮬레이션에서 나온 것

| # | 발견 | 원인 | 조치 |
|---|---|---|---|
| 1 | 벽 가까이서 화면 반이 **검정** | 빛 반대편 면 = 환경광뿐인데 환경광 0.55 배 → 명암비 6:1. 게다가 빌더가 구운 음영(0.66)과 실시간 조명이 **곱해져** 이중으로 어두웠다 | 환경광 3색(하늘·지평선·땅) 0.85/0.92 배 · 구운 음영 0.86~1.06 · 반램버트(wrap 0.35) |
| 2 | 절벽·옆벽이 무늬 없는 **단색 판** | 절차 메시 면 하나 = 색 하나 | 월드 해시 노이즈 두 옥타브 ±3.5% (픽셀당 해시 2번) |
| 3 | 하늘 **단색** — 3인칭에서 화면의 30~40% | `clearFlags = SolidColor` | `Kgd/Sky` 그라디언트 + 해 + 구름(값 노이즈 2옥타브, 하늘 픽셀에만) |
| 4 | 막기 때 「막아 냈다」 배너와 「막힘」 숫자가 **겹쳐** 안 읽힘 | 같은 사건에 표시 둘 | 배너 제거 |
| 5 | 적의 예고 부채꼴이 **타격 순간**에만 뜸 | `State.Strike` 에만 켬 | `Windup` 부터 (카탈로그 D4 「예고 후 활성」) |
| 6 | 벽타기에서 팔이 **등 뒤로** 꺾임 | 뼈 로컬 축을 짐작한 오일러 각 | `KgdLimbs` — 월드 방향 조준(축 무관). 자세 게이트: 팔꿈치·무릎 접힘 ≤150°, 손·무릎이 몸 앞 |
| 7 | 림라이트가 **초록** (야간 궁수용 값) | 팔레트 상속 | 하늘색으로 (`KgdSky.TintRim`) |
| 8 | 비탈 옆벽과 절벽 사이 **막다른 주머니** | 지형 형태 | 결함은 아님. 등반 진입점으로 쓸 수 있는지 다음에 |

| 시작 | 60.1 | 60.2 |

## 4. 검증 경로의 한계 (기록)

- 화면 버튼은 CDP 로 못 누른다 → 키보드로 몬다
- 캐릭터를 **특정 소품 앞에 정확히** 세우는 것은 색 기반 조향으로도 실패했다 — 붙는 순간 미끄러진다.
  다음 시도는 `Runtime.evaluate` 로 게임 안 디버그 훅(`GateTeleport`)을 열어 위치를 직접 놓는 것
- fps 는 소프트웨어 렌더러 값이라 **절대값은 무의미**, 전후 비교만 쓴다
