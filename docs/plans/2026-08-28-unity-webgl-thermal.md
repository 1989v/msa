# 유니티 WebGL 모바일 발열 — 원인과 개선 플랜

<!-- source: portal-fe/public/games/_src/archer-outbreak/Assets/Scripts/GameEntry.cs, Core/PostFx.cs, Core/Kenney.cs, unity/template/WebGLTemplates/Kgd/index.html -->

`archer-outbreak` 을 폰에서 돌렸더니 발열이 심하다는 보고. "그래픽이 화려하지도 몹이 많지도 않은데"
심하다는 것이 핵심 단서다 — **보이는 것의 양이 아니라 매 프레임 쉬지 않고 도는 일의 양**이 문제였다.

## 0. 판정 방법

프로파일러 대신 **코드에서 프레임당 반복되는 일**을 세었다. WebGL 은 단일 스레드라 CPU 쪽은
스크립트·스킨 계산이, GPU 쪽은 화면을 몇 번 다시 칠하는가가 곧 비용이다.

## 1. 원인 — 값이 큰 순서

| # | 원인 | 프레임당 비용 | 근거 |
|---|---|---|---|
| 1 | **60fps 고정** | GPU·CPU 가 쉬는 구간이 없다 | `Application.targetFrameRate = 60` |
| 2 | **메뉴에서도 60fps** | 타이틀·일시정지·기지 화면에서 세상이 멈췄는데 같은 속도로 다시 그렸다 | 프레임 예산 분기 없음 |
| 3 | **그림자 거리 92 · High · 2 cascade** | 화면 밖까지 그림자 맵을 그린다. 카메라 시야는 25×39 유닛인데 92 를 덮었다 | `shadowDistance = 92f` |
| 4 | **MSAA 4x** | 폰에서 프레임버퍼 대역폭이 배로 든다 | `antiAliasing = 4` |
| 5 | **포스트 전체화면 6패스** | 임계 1 + 번짐 4 + 합성 1. 화면을 매 프레임 여섯 번 다시 칠한다 | `PostFx.OnRenderImage` |
| 6 | **스킨드 메시 바운드 매 프레임 재계산** | `updateWhenOffscreen=true` 가 최대 240마리에 걸려 있었다. 스킨을 다시 풀어 AABB 를 뽑는 일이 개체 수만큼 | `Kenney.SpawnCharacter` |
| 7 | **실시간 광원 6개 한도** | 화톳불·랜턴·유물 광원이 겹치면 픽셀당 조명 패스가 그만큼 곱해진다 | `pixelLightCount = 6` |
| 8 | **DPR 2 고정** | 390×844 폰이 780×1688 = 131만 픽셀. 위 5·6 이 이 픽셀 수에 곱해진다 | 템플릿 `devicePixelRatio` |

**4·5·8 이 서로 곱해진다**는 것이 이 게임에서 발열이 유난한 이유다. 픽셀 수 × 패스 수 × MSAA
샘플 수가 한꺼번에 커져서, 화면에 보이는 물체가 적어도 GPU 는 계속 최대로 돈다.

## 2. 적용한 개선과 **게임성 변화**

기기로 가른다. 데스크톱은 그대로 두고 폰만 깎는다.

| 항목 | 데스크톱 | 폰 | 게임성 변화 |
|---|---|---|---|
| 목표 프레임 | 60 | **45** | 자동 사격이라 조준 정밀도와 무관. 회피 구르기(0.34초)는 45fps 에서 15프레임이라 입력 판정에 영향 없음. **체감 변화 거의 없음** |
| 메뉴 프레임 | **20** | **20** | 타이틀·일시정지·기지 화면. 애니메이션이 없는 화면이라 **변화 없음** |
| 그림자 | 62 · Medium | **46 · Low** | 발밑 그림자는 그대로 남는다(카메라가 45 유닛). 먼 건물 그림자가 흐려지고 일찍 사라진다. **밤 화면이라 티가 적음** |
| MSAA | 4 → **2** | 4 → **0** | 폰에서 각진 모서리에 계단이 보인다. **눈에 띄는 유일한 화질 손해** |
| 포스트 | 6패스 · 1/2 해상도 | **4패스 · 1/4 해상도** | 네온 번짐이 약해지고 뭉툭해진다. 야간 습격 분위기는 유지 |
| 실시간 광원 | 6 → 4 | 6 → **2** | 광원이 겹치는 기지 한복판에서 먼 광원이 꺼진다. **주인공 랜턴과 화톳불은 유지** |
| 스킨 바운드 | 매 프레임 | **생성 시 1회 고정** | 없음. 실제 자세를 재서 2.2배로 굳히므로 컬링 정확도 유지 |
| 뼈 가중치 | 4본 | **2본** | 관절이 미세하게 각져진다. 21 CSS px 에서 **식별 불가** |
| 동시 생존 상한 | 170 | **90** | **가장 큰 게임성 변화.** 폰에서 무리가 절반. 화면 안 밀도는 들판 배회 로직이 최소 10마리를 보장하므로 **눈앞은 그대로**, 줄어드는 것은 멀리 있는 개체 |

## 3. 남은 것 (미적용 — 판단 필요)

| 항목 | 기대 효과 | 게임성 변화 |
|---|---|---|
| **DPR 2 → 1.5** | 픽셀 수 44% 감소. 위 항목 전체에 곱해지므로 **단일 항목 중 최대** | 화면이 부드럽게 뭉개진다. 한글 UI 가독성이 떨어질 수 있어 실측 필요 |
| **적응형 프레임** — 온도 대신 프레임 시간으로 45↔30 전환 | 약한 기기에서 추가 절감 | 프레임이 눈에 띄게 바뀌는 순간이 생긴다 |
| **그림자 완전 제거(폰)** | 그림자 패스 전체 제거 | 인물이 지면에서 뜬다. 발밑 표식이 있어 위치는 알지만 입체감 손해가 큼 |
| **포스트 제거(폰)** | 전체화면 패스 4개 제거 | 야간 습격 룩이 사라진다. 게임이 다른 게임처럼 보임 |

## 4. 검증

- 폰에서 30분 플레이 후 손등 체감 + 배터리 소모율
- `chrome://tracing` 대신 브라우저 FPS 계측(`requestAnimationFrame` 카운트)
- 헤드리스는 소프트웨어 렌더링이라 **이 항목의 검증에 쓸 수 없다**
