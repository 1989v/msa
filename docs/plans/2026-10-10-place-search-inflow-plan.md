> 2·3단계 코드 몫 배포(2026-10-09) 다음 날의 운영 실측을 기준선으로, 검색 유입을 늘리는 순서를 정한다.

**해석**
- 병목은 콘텐츠 품질보다 **발견과 측정**이다. 6.3만 상세를 하루 17건 크롤하면 한 바퀴에 10년이 걸린다. 크롤이 적은 것은 대개 「사이트 신뢰(외부 링크)가 낮고, 제출 신호가 없다」는 뜻이다.
- 네이버·Bing 은 거의 오지 않는다. 둘 다 **IndexNow 와 웹마스터 도구 제출을 받는** 엔진이라, 등록과 IndexNow 만으로 발견이 크게 바뀔 수 있다(가설).
- 우리 원장은 유입을 못 센다. 계획의 첫 코드 작업은 「어디서 왔나」를 기록하는 것이다.

## 3. 지표 (선행 → 후행)
1. **크롤**: Googlebot `/attractions` 일 요청(지금 ~17) · Yeti·Bingbot place 요청(지금 ~0) — I0-6
2. **색인**: GSC 색인 페이지 수, 「크롤링됨-미색인」 비율(템플릿별) — I0-1 이후
3. **노출·클릭**: GSC·서치어드바이저 노출/클릭, 질의 유형(관광지명 vs 조건형)
4. **유입**: 검색엔진 리퍼러 세션(지금 0/일) — I0-5 이후
5. **행동**: 유입 세션의 상세 탐색·찜·길찾기 — 기존 계측(S1-12b·F)

가설 목표(8주): Googlebot 상세 일 요청 100+, Bing·Yeti 상세 크롤 시작, 검색 유입 세션 일 10+. 근거가 생기면 고친다.

## 4. 하지 않는 것
- 상세 URL 을 더 만들기(크롤이 병목인데 URL 을 늘리면 희석). 랜딩은 20장으로 시작.
- 자동 생성 문장으로 상세를 「길게」 만들기(가치 추가 없는 재게시 위험).
- 링크 구매·교환 네트워크·대량 디렉터리 등록.
- AI 크롤러 차단(지금 열어 둔 방침 유지).

## 5. 세션이 바로 할 수 있는 순서
I0-5(유입 기록) → I0-6(봇 일 집계) → I1-1(핵심 사이트맵) → I1-3(내부 링크 깊이) → I2-2(데이터 스토리 초안) → I2-6(서비스 간 링크). 사용자 몫 I0-1~I0-4 가 가장 먼저이고 효과가 가장 크다(가설).
