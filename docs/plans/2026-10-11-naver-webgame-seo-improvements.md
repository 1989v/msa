# 네이버 웹게임 검색 보완 작업

- 근거: [검색 진단](../research/2026-10-11-naver-webgame-seo.md), [ADR-0062](../adr/ADR-0062-seo-and-organic-discovery.md)
- 승인: 2026-10-11 사용자의 “보완작업 진행” 요청. 기존 SEO 설계 내 FE 수정(L2).
- 범위: 홈페이지 메타의 카탈로그 수 오류, 게임 안내 콘텐츠, 상세 DOM 읽기 순서 보완.

## 요구사항

1. 홈페이지 메타의 게임 수는 목록 응답의 전체 건수를 사용한다. 48개 페이지 제한이나 태그 필터가
   전체 카탈로그 수로 표현되지 않아야 한다. 로딩·실패·빠른 필터 전환 중 잘못된 메타를 쓰지 않는다.
   장르 페이지도 목록 길이로 전체 장르 수를 단정하지 않도록 정리한다.
2. 홈페이지 하단에 게임 선택과 시작 방법을 안내한다. 한국어·영어를 지원하고 초기 HTML과
   실제 화면이 같은 원본을 사용한다. 장르 링크와 실제 기능에 근거한 설치·계정·모바일 안내를
   제공한다. 모든 게임의 모바일·저장·멀티플레이 지원을 보장하는 표현은 쓰지 않는다.
3. 상세 페이지에서 게임 소개가 내 기록·평가보다 DOM 순서상 먼저 읽히도록 정리한다.
   플레이 버튼·탭·반응형 배치를 보존한다. 사용자에게 보이지 않는 SEO 전용 키워드를 추가하지 않는다.
4. 상세 초기 HTML에 기존 설명과 실제 상세 응답의 인원·모바일 정보가 일관되게 제공되는지 확인하고
   필요한 경우 보완한다. 근거 없는 조작법·공략을 생성하지 않는다.
5. 과거 주석의 “네이버는 JS를 실행하지 않는다” 단정을 공식 가이드에 맞게 고친다.

## 검증

- 48개 목록·82개 전체 건수에서 홈페이지 메타가 82종을 유지하는 회귀 검증.
- 태그 필터·로딩·요청 실패·비동기 응답 역전으로 전체 수 메타가 오염되지 않는지 검증.
- 한국어·영어 안내가 런타임과 프리렌더에 존재하고 링크·텍스트 이스케이프가 정상인지 검증.
- 게임 소개와 공통 안내의 DOM 순서, 기존 상세 회귀 테스트 확인.
- 관련 Vitest, TypeScript/Vite 빌드, 변경 파일 lint. 운영 API를 호출하는 전체 SEO 빌드 결과는
   번들 빌드 성공과 구분해 보고한다.

## 경계 및 후속 작업

- 게임 본체·백엔드·관광지 변경은 이 작업에 포함하지 않는다.
- 이미 진행 중인 `prerender-seo.mjs`의 관광지 변경을 보존한다.
- 서치어드바이저 소유확인·사이트맵 제출·재수집·실제 Yeti 로그 확인은 계정/서버 접근이 필요한
   운영 작업으로 남긴다. 이번 코드 보완으로 실행됐다고 기록하지 않는다.
- 배포·외부 게시·재수집 제출은 검증된 변경을 사용자에게 보여준 뒤 승인받는다.
- 사이트맵 `lastmod`를 빌드 시각으로 채우지 않는다. 정확한 홈페이지 변경일 정책은 별도 검토한다.
- 검색 순위나 스니펫 선택 개선을 보장하지 않는다.

## 실행 결과 (2026-10-11)

- 구현·관련 검증: 지정된 `gpt-6.1-sol` 서브에이전트. 부모 세션이 변경사항과 검증 증거를 검토했다.
- 홈페이지·장르 메타는 별도 무태그 건수 조회의 `totalElements`를 사용한다. 목록 48개 제한,
  태그·정렬, 응답 역전과 실패에 의해 전체 수가 잘못 표시되지 않도록 처리했다.
- 건수를 모르는 새 주소에서는 숫자 없는 설명을 제공하고 canonical 을 갱신한다.
  같은 주소의 정상 초기 HTML 메타는 건수 조회 중 유지한다.
- 한국어·영어의 홈페이지 이용 안내 원본을 런타임과 프리렌더가 공유한다.
- 상세 DOM 에서 소개를 기록·평가보다 먼저 두고, CSS 로 기존 화면 배치를 유지했다.
  프리렌더에는 상세 응답에 있는 인원·모바일·플레이 시간 정보를 추가했다.
- 과거의 네이버 JS 미지원·등록 필수 단정은 공식 안내에 맞게 정정했다.

브라우저 실행 후 메타가 일치하는지, 그 뒤 네이버 설명이 갱신되는지는 배포 후 확인해야 한다.
