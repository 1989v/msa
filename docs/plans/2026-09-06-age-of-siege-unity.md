# 전란 (age-of-siege) — 유니티 전환 계획

> 캔버스 2D 판본을 접고 **유니티로 다시 짓는다.** 이유는 하나다 — 목표 퀄리티가
> 실시간 조명·그림자·원근 카메라를 요구하고, 그건 캔버스가 흉내만 낼 수 있다.
>
> 설계(게임성)는 `docs/specs/2026-09-05-age-of-siege-design.md` 가 원본이고,
> 이 문서는 **엔진 전환·요구사항 확정·Claude Design 연동**만 다룬다.

---

## 1. 결정과 그 대가 — 표준 예외를 이름 불러 선언한다

`docs/standards/unity-game-pipeline.md` §0 은 유니티 조건을 이렇게 못 박는다.

> 유니티가 값을 하는 것은 **골격 애니메이션이 붙은 무리 + 스트리밍이 필요한 큰 3D 맵**
> 둘이 동시에 필요할 때다. **3D 로 보이는 것만으로는 부족하다.**

전란은 **절반만** 해당한다.

| 조건 | 전란 |
|---|---|
| 골격 애니메이션 무리 | **해당** — 이중 행렬 100기 이상이 각자 걷는다 |
| 스트리밍이 필요한 큰 3D 맵 | **미해당** — 한 스테이지가 한 화면 안팎이다 |

**그래서 이건 예외다.** 근거는 퀄리티 기준이 바뀐 것이고, 캔버스 아트 스파이크로
도달 한계를 실제로 재 본 뒤의 판단이다(스파이크: 원근 지면·리본 길·100기 행렬까지는
캔버스로 됐고, 실시간 조명·지형 그림자에서 멈췄다 — 체감 70%).

**이 예외가 사 주지 않는 것**을 함께 적는다.

- 전송량 ~8MB · 첫 화면 5.7초 (`archer-outbreak` 실측). 첫 화면 예산 5초를 **이미 넘긴 전례**다
- 발열 관리가 붙는다. 그 게임이 폰 발열 신고를 받아 G7 가드레일이 생겼다
- 빌드 한 번에 8~10분. 고칠 때마다 빌드하면 하루가 간다
- 캔버스 판본 코드 대부분을 버린다 (수치·밸런스·상태기계 설계는 살린다)

이 넷을 감수하고 간다.

## 2. 이미 있는 것 — 새로 만들지 않는다

| | 어디 | 이 게임이 쓰는 법 |
|---|---|---|
| 프레임워크 | `unity/packages/com.kgd.webgame` | 이동·충돌·시점·적·타격감·챕터·소리·플랫폼이 이미 있다 |
| **고지대 지형** | `Runtime/Terrain/` — `KgdPlateau` · `KgdPlateauBuilder` | **언덕을 새로 만들지 않는다.** `IKgdTerrainSink` 하나만 구현해 꽂는다 |
| 견본 게임 | `portal-fe/public/games/_src/nine-bells` | 게이트 구조·`Chapter`·`GameEntry` 배선을 베낀다 |
| 시작 골격 | `Kgd.Editor.Scaffold.CreateStarter` | 평지·기둥·쫓아오는 것 하나가 처음부터 돈다 |
| 빌드 | `scripts/unity-build-web.sh <slug>` | **레포 루트에서** — 하위 폴더에서 돌리면 조용히 아무것도 안 한다 |

새로 만드는 것은 **규칙 · 레벨 배치 · UI 배치 · 아트** 넷뿐이다.

## 3. 요구사항 — 대화에서 확정된 것

### 3-1. 전장 구조 (참조작 실물 스크린샷 12장 근거)

- **길이 전장이다.** 굵은 길이 굽이치고 적은 그 위를 **이중 행렬**로 온다
- **진입로는 스테이지마다 다르다.** 초반 1~2, 뒤로 갈수록 3 이상. 갈라진 길이 **본줄기에 합류**한다
- **길 옆 고정 슬롯**에 값을 치르고 놓는다. 자유 배치가 아니다. 슬롯마다 가격표가 떠 있다
- **화폐는 냥 하나.** 적을 잡으면 떨어진다. 채집하러 걸어다니지 않는다
- **바위 능선이 길과 아군 구역을 가른다.** 타워가 능선 너머로 쏜다
- **성채는 길 끝 한 곳**이고 판이 진행되면 자란다(오두막 → 석조)

### 3-2. 이번 전환의 이유가 된 것들

- **실시간 조명과 지형에 떨어지는 그림자**
- **기울어진 원근 카메라** (아이소메트릭 아님)
- **언덕** — 보는 것이 아니라 **기믹**이다. 고지대에서 바위·술통을 굴려 행렬을 쓸어버린다
- **적 100기 이상**이 화면을 채운다. 지금 캔버스 판본은 6~20이라 화면이 비어 보였다
- **보스가 화면을 압도한다.** 술통을 굴려 길로 내려보낸다

### 3-3. 살리는 설계 (캔버스 판본에서 그대로)

- **고을 = 세 판** (방어 2 + 소탕 1). 고을 안에는 세운 것이 남고, 고을 사이에는 설계도 등급만
- **영웅 조작 + 발밑 오라 + 스킬 둘.** 한국사 영웅 12인, 배분 다섯(전투·통솔·수성·저격·유격)
- **승급 4단계** — 색과 장식이 바뀐다
- 봉수대가 웨이브 신호

### 3-4. 제약

| | 값 | 근거 |
|---|---|---|
| 총 전송량 | ≤ 15MB | 파이프라인 §6 |
| 첫 화면 | ≤ 5초 | 같음. `archer-outbreak` 이 5.66초로 넘겼다 |
| 방향 | **가로 우선, 세로도 지원** (2026-09-06 결정) | 참조작 인게임이 가로다. 길이 길게 뻗는 화면이라 가로가 유리하다 |
| 모바일 | **1순위.** 세로 390×844 · 가로 844×390 둘 다 실측 | G5 |
| 프레임 | 폰 45 · 멈춤 20 · MSAA 0 · 포스트 ≤4 | G7 |
| 첫 판 | 튜토리얼 구간 없음 | 전 게임 공통 |

## 4. Claude Design 연동 — 무엇을 만들고 어떻게 흘러가나

### 4-1. 경계선부터

Claude Design은 **3D 모델·텍스처·애니메이션 클립을 만들지 못한다.** 그걸 기대하면
어긋난다. 대신 **값을 정하는 단일 원본**이 된다.

| Claude Design 이 만든다 | 유니티가 만든다 |
|---|---|
| 팔레트 (hex) · 조명 톤 기준판 | 머티리얼 · 라이트 · 포스트 |
| UI 화면 전부 (HUD · 건설 시트 · 결과 · 영웅 선택) | 그 화면을 옮긴 UI 프리팹 |
| 영웅 초상 · 아이콘 세트 | 인게임 3D 모델 |
| 스테이지 레이아웃 판 (길·슬롯·고지대 배치) | 그 배치를 읽는 레벨 데이터 |
| 이펙트 스펙 (색·모양·타이밍) | 파티클·셰이더 |

### 4-2. 흐름 — 값이 한 방향으로만 흐른다

```
Claude Design 아트보드          →   값 추출          →   유니티
 (팔레트·UI·초상·레이아웃)          (hex · px · 비율)     ScriptableObject / 프리팹
```

**색을 유니티에서 직접 찍지 않는다.** 아트보드가 원본이고 유니티는 그 값을 읽는다.
두 군데서 색을 정하면 반드시 어긋나고, 어긋난 걸 아무도 못 잡는다.

구체적으로:

1. **팔레트 아트보드** → `KgdPalette` ScriptableObject 하나. 잔디·모래·바위·적·아군·금색·
   태양 방위·환경광 배수까지 **한 자산에** 넣는다
2. **UI 아트보드** → 화면마다 프리팹 하나. 아트보드의 px 를 그대로 쓰지 않고 **비율**로 옮긴다
   (세로·가로 둘 다 살아야 한다)
3. **영웅 초상** → 이미 12인 로스터 시안이 있다(`claude.ai/code/artifact/a12432f7…`).
   그걸 확장해 승급 4단계까지 뽑고, 텍스처로 굽는다
4. **스테이지 레이아웃 판** → 길 스플라인 점·슬롯 좌표·고지대 반경을 **판에서 읽어** JSON 으로

### 4-3. 인게임 3D 에셋 — 절차 생성 메시 (2026-09-06 결정)

**Claude Design 은 3D 모델을 못 만든다.** `.fbx`·`.glb`·메시를 내보내지 못한다.
그래서 「디자인으로 3D 에셋을 만든다」는 문자 그대로는 성립하지 않는다.
대신 이렇게 나눈다.

| | 무엇 |
|---|---|
| Claude Design | **형태 규격** — 비율(머리:몸:다리), 실루엣, 팔레트, 파트 목록, 승급 단계별 색·장식 |
| 유니티 C# | 그 규격대로 **상자·원기둥·구를 코드로 조립**한 계층 메시 |

애니메이션은 **스킨드 메시가 아니라 파트 Transform** 을 움직인다 —
몸통·머리·팔·다리·무기를 각각 자식으로 두고 사인파로 흔든다.

이 선택이 사 주는 것이 크다. 파이프라인 §9 함정 목록의 **절반이 아예 안 생긴다** —
T 자세 바인딩(`Animation` 을 `Root` 에), 클립 이름 충돌(`Resources.Load` 가 바인드
자세를 집는 것), 루트 커브가 배율을 지우는 것, 스킨드 메시 컬링 바운드. 전부 리그가
있어야 나는 문제다.

**대가**: 캐릭터가 참조작의 모델링된 것보다 단순해진다. 다만 화면에 100기가 있는
게임이라 **모델 디테일보다 실루엣과 색이 판정을 지배한다** — 캔버스 스파이크에서
이미 확인한 바다. 주역(영웅·보스)만 파트를 늘려 밀도를 준다.

**용량 이득도 있다.** 절차 메시는 코드라 `.data` 에 실리지 않는다. 첫 화면 5초 예산에서
`archer-outbreak` 이 5.66초로 넘긴 전례가 있어, 이쪽이 예산에 유리하다.

### 4-4. 게이트 — 연동이 끊겼는지 검사한다

디자인과 코드가 갈리는 것이 이 방식의 유일한 실패 모드다. 그래서 검사를 붙인다.

- 팔레트 자산의 hex 가 아트보드에서 뽑은 값 목록과 **한 글자라도 다르면 빨간불**
- 유니티 소스에 **하드코딩된 hex 리터럴이 있으면 빨간불** (팔레트를 우회한 것)
- 회귀를 주입해 빨간불을 본 뒤에만 「켰다」고 한다

## 5. 순서

| # | 하는 일 | 끝났다는 근거 |
|---|---|---|
| 1 | **PRD 확정** — 맵 범위·플레이타임·진행 깊이를 숫자로 | `docs/specs/*-prd.md`. 숫자가 없으면 완성 판정이 없다 |
| 2 | **디자인 판** — 팔레트·조명 톤·UI 4화면·스테이지 레이아웃 1개 | 아트보드 게시, 값 추출 목록 |
| 3 | **스캐폴드** — `_src/age-of-siege/`, 패키지 경로는 nine-bells 것 그대로 | 스타터가 브라우저에서 돈다 |
| 4 | **수직 슬라이스** — 고을 1 · 1판 방어 하나 | 길·행렬 100기·슬롯·보스·고지대·조명이 다 있는 한 판 |
| 5 | **게이트** — 이 게임의 질문으로 바꾼 게이트, 회귀 주입 확인 | 빨간불을 본 기록 |
| 6 | **빌드·실측** — 전송량·첫 화면·삼각형·세로/가로 | 표의 값과 나란히 |
| 7 | **통합** — 카탈로그 시드(DRAFT→BETA→PUBLISHED)·프리렌더·배포 | 운영 해시 = 로컬 빌드 해시 |

**빌드는 게이트를 다 돌린 뒤 한 번.** 한 번에 8~10분이라 고칠 때마다 빌드하면 하루가 간다.
그림 문제는 **에디터 배치모드 오프스크린 렌더**로 1분에 본다 (`MeshProbe.cs` 요령).

## 6. 이 게임에 걸릴 함정 — 파이프라인 §9 에서 추린 것

전부 **오류 없이 조용히 실패**한다. 눈으로 보이는 것을 근거로 삼지 않는다.

| 이 게임에서 터질 자리 | 조치 |
|---|---|
| **행렬 100기가 T 자세로 미끄러진다** | `Animation` 을 모델 최상위가 아니라 `Root` 에 단다. 클립은 `LoadAll` 로 **이름으로** 고른다 |
| **무리가 통째로 안 보인다** | 스킨드 메시 컬링 바운드. 주역은 `updateWhenOffscreen`, 무리는 생성 시 실제 자세를 재서 넣는다 |
| **고지대가 프레임을 3분의 1로 만든다** | `KgdPlateau.TopCell` 이 2.2 유닛 고정이면 큰 반경에서 삼각형이 225배. 반경에 비례시킨다 |
| **지형이 검거나 흰 원판이 된다** | 태양 방위 ↔ 시작 시야, 그리고 노출 포화. 팔레트의 `ToLight` 와 씬 `Light` 를 **같이** 고친다 |
| **건설 슬롯 버튼이 안 눌린다** | `EventSystem` + `StandaloneInputModule` 을 HUD 와 함께 세운다. CDP 로 좌표를 눌러 화면이 바뀌는지로 검증 |
| **한글이 네모** | 정적 SDF 아틀라스. 보간식 안의 문자열은 못 읽으니 변수로 뺀다 |
| **세로에서 가상패드가 화면을 덮는다** | 유니티는 `data-fit="0"` 이라 템플릿이 하단 띠를 직접 계산한다 (비율 0.28) |
| **고쳤는데 스크린샷이 그대로** | 빌드가 조용히 실패했다. 재기 전에 `Build/*.wasm.gz` mtime·해시를 본다 |
| **프로젝트가 통째로 사라진다** | 빌드 출력 폴더 안에 프로젝트를 두지 않는다 |
