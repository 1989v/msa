# 이력서 어드민 작성 가이드

`admin.1989v.com` 에서 `resume.1989v.com` 의 내용을 채우는 절차. 설계 근거는 ADR-0064.

> **원본은 여기다.** 이력서 볼트에서 초기 데이터만 가져왔고, 그 뒤로 사이트 콘텐츠의 원본은
> 이 DB다. 여기서 고친 내용이 곧 사이트 내용이고, 볼트를 다시 뽑아도 덮어쓰지 않는다.
> 대신 **경력 사실이 바뀌면 볼트와 사이트를 각각 고쳐야 한다.**

---

## 화면 두 개

| 메뉴 | 담당 |
|---|---|
| **이력서** | 문서(마크다운) · 공개 토글 · 제출처별 링크 · 열람 기록 |
| **이력서 경력데이터** | 회사 · 카테고리 · 프로젝트 · 기술 스택 |

서술은 왼쪽, 계산·반복되는 항목은 오른쪽이 담당한다.

---

## 작성 순서

**참조 관계가 있어 순서가 중요하다.** 거꾸로 하면 프로젝트에서 고를 회사·카테고리가 없다.

```
① 카테고리  →  ② 회사  →  ③ 프로젝트  →  ④ 기술 스택  →  ⑤ 문서
                                                          (자리표시자 사용)
```

①④는 V8 마이그레이션이 이미 넣어 뒀다. 확인만 하면 된다.

---

## ① 카테고리 (시드 완료)

프로젝트를 묶는 축이자 공개 화면의 드릴다운 단위.

| 코드 | 이름 |
|---|---|
| `search` | 검색 |
| `display` | 전시 |
| `commerce` | 커머스 |
| `platform` | 인프라·플랫폼 |
| `ai-engineering` | AI 엔지니어링 |

- **코드는 소문자·숫자·하이픈만.** 대문자나 한글을 넣으면 저장이 거절된다
- 이름·설명은 자유롭게 다듬어도 된다 — 재배포가 되돌리지 않는다(`INSERT IGNORE`)
- 칩을 누르면 편집, `×` 를 누르면 삭제. 삭제해도 그 카테고리를 쓰던 프로젝트는 남고
  분류만 비워진다

---

## ② 회사

**여기 입력한 기간에서 총 경력과 연차가 자동으로 계산된다.** 저장 즉시 화면 상단 값이 바뀐다.

| 필드 | 형식 | 비고 |
|---|---|---|
| 회사명 | 텍스트 | |
| 시작 | `YYYY-MM` | 일자는 받지 않는다 |
| 종료 | `YYYY-MM` | **비우면 재직 중** |
| 직급 | 텍스트 | 선택 |
| 팀 | 텍스트 | 선택 |
| 순서 | 숫자 | 표에 나오는 차례 |

입력 예:

```
이파트          2015-09  ~  2017-12   웹 개발
에듀윌          2018-03  ~  2022-07   백엔드
마이리얼트립     2022-08  ~  (비움)     매니저 / Product Strategy팀
```

넣고 나면 상단에 이렇게 떠야 한다:

```
총 경력  10년 9개월      연차  11년차      합산 개월  129개월
```

**계산 규칙** — 종료된 재직은 종료월을 포함해 세고(2015.09~2017.12 = 28개월), 진행 중인
재직은 완료된 달까지만 센다. 이직 공백은 빠진다. 연차는 만 연차 + 1.

> 값이 다르게 나오면 기간 입력이 틀렸다는 뜻이다. 저장하면서 바로 확인할 수 있는 게 이 화면의 목적이다.

---

## ③ 프로젝트

카테고리별로 묶여 공개 화면에 카드로 나온다.

| 필드 | 비고 |
|---|---|
| 제목 | 필수 |
| 회사 | 비우면 **개인 프로젝트** |
| 카테고리 | 비우면 분류 없이 맨 아래 묶음에 나온다 |
| 시작 / 종료 | `YYYY-MM`, 둘 다 선택. 종료를 비우면 진행 중 |
| 한 줄 요약 | 카드 본문 |
| 성과 지표 | **한 줄에 하나** (예: `CTR +3.4%`) — 불릿으로 렌더된다 |
| 상세 문서 slug | 지정하면 카드 제목이 그 상세 화면으로 이어진다 |
| 순서 | 카테고리 안에서의 차례 |
| 공개 | 끄면 사이트에서 사라진다(초안용). 어드민에는 남는다 |

**드릴다운은 `상세 문서 slug` 로 완성된다.** 예를 들어 `검색` 카테고리의 프로젝트에
`search-platform` 을 걸어두면:

```
메인 → 검색 카테고리 → 프로젝트 카드 클릭 → /d/search-platform 상세
```

slug 가 실제로 존재하지 않아도 저장은 된다(FK 로 묶지 않았다). 링크가 죽으면 404 가 뜨므로
문서를 먼저 만들거나, 만든 뒤 다시 와서 채우면 된다.

## ④ 기술 스택 (시드 완료)

그룹 9개가 이미 들어가 있다 — Language / Framework / Search / Persistence / Messaging /
AI / Infra / Architecture / Test · 관측.

- **항목은 쉼표로 구분**해 한 칸에 넣는다 (`Java (8~25), Kotlin, TypeScript`)
- 목록만으로 무엇을 했는지 안 드러나는 그룹은 설명을 덧붙인다.
  Search 그룹이 그 예다 — 도구 이름 옆에 "색인 설계, 매칭·스코어 조정, 쿼리 이해…"

## ⑤ 문서 (마크다운)

**"이력서" 메뉴**에서 등록한다.

| 필드 | 의미 |
|---|---|
| slug | **URL 경로**(`/d/<slug>`) 겸 **저장 키**. 같은 slug 로 저장하면 덮어쓴다 |
| 제목 | 메인 하단 링크에 표시되는 글자. 상세 화면의 큰 제목은 본문 첫 줄(`#`)이 그린다 |
| 종류 | `MAIN` = 루트 화면(**하나만**), `DETAIL` = 상세 + 링크 목록에 자동 등장 |
| 순서 | DETAIL 목록의 차례 |
| 공개 | 끄면 사이트에서 사라진다 |

slug 는 **소문자·숫자·하이픈만**. 한 번 정하면 바꾸지 않는다 — 이미 뿌린 링크가 깨진다.

### MAIN 본문에 자리표시자를 쓴다

구조화 데이터가 들어갈 자리를 마크다운에 표시한다. 배치와 제목은 마크다운이 정하고
내용만 데이터가 채우므로, 순서를 바꾸려고 코드를 고칠 일이 없다.

| 자리표시자 | 들어가는 것 |
|---|---|
| `{{career}}` | 회사 표 + "총 경력 N년 M개월 · K년차" |
| `{{projects}}` | 카테고리별 프로젝트 카드 |
| `{{skills}}` | 기술 스택 목록 |

작성 예:

```markdown
# 권기덕

1989v@naver.com · [github.com/1989v](https://github.com/1989v) · [1989v.com](https://1989v.com)

11년차 백엔드 개발자입니다. …

## 경력
{{career}}

## 이런 일을 해왔습니다
- **검색 품질** — …

> **기여 범위를 먼저 밝힙니다.** …

## 프로젝트
{{projects}}

## 기술 스택
{{skills}}

## 함께 일할 때
- …
```

**자리표시자를 안 써도 된다.** 쓰지 않으면 그 섹션이 안 나올 뿐, 기존 마크다운을 그대로
붙여넣어도 동작한다. 손으로 적은 표를 자리표시자로 하나씩 옮겨가면 된다.

### 주의: 상세 링크 목록은 빼야 한다

MAIN 본문 아래쪽의 "## 프로젝트 상세" 텍스트 목록은 **지운다.** 사이트가 등록된 DETAIL 문서로
클릭 가능한 링크 목록을 자동 생성하므로, 남겨두면 같은 목록이 두 번 나온다.

## 검증

넣고 나서 확인할 것:

- [ ] 어드민 문서 표에 **MAIN 이 정확히 하나** (둘이면 어느 쪽이 뜰지 보장되지 않는다)
- [ ] 경력데이터 상단 값이 예상과 일치
- [ ] 제출처 링크를 하나 발급해 `?k=...` 로 **시크릿 창**에서 열기
- [ ] 메인 하단에 상세 링크가 순서대로
- [ ] 프로젝트 카드 제목이 상세로 이어지는지
- [ ] 모바일 폭(375px)에서 표가 **자기 안에서만** 가로 스크롤 — 페이지는 안 밀려야 한다
- [ ] "전체 인쇄 (상세 포함)" → 메인 + 상세가 한 문서로, 상세마다 새 장
- [ ] 인쇄 미리보기가 흰 배경·검은 글자로 뒤집히는지
- [ ] 링크를 폐기하고 같은 URL 재접속 → **404**

여기까지 통과하면 **전체 공개** 토글. 그 순간 `1989v.com` 의 GNB 이력서 링크와
OPEN TO WORK 배지가 함께 켜진다.

---

## 저장이 안 될 때

| 증상 | 원인 |
|---|---|
| 문서 저장 거절 | slug 에 대문자·한글·언더스코어. 소문자·숫자·하이픈만 |
| 카테고리 저장 거절 | 코드에 대문자·한글 |
| 회사/프로젝트 저장 거절 | 기간이 `YYYY-MM` 형식이 아님 (`2022.08`, `2022-8` 모두 거절) |
| 화면이 통째로 안 뜸 | `code-dictionary` 가 내려간 상태. 이력서는 이 서비스에 의존한다 |
