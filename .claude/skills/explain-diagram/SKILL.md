# Explain with Diagram

설명은 **대상에 맞추고**, 산출물은 **그림이 끌고 가는 아티팩트 한 장**이다.
글은 그림과 그림을 잇는 접착제이지 본체가 아니다.

## 1. 대상 판정

요청에서 대상을 고른다. 없으면 **5살**(ELI5 기본값). 설명 언어는 요청 언어를 따른다.

| 대상 | 어휘·톤 | 비유의 재료 | **주 그림이 그리는 것** |
|---|---|---|---|
| 5살 · 어린이 | 짧은 문장, 용어 0 | 장난감·동물·놀이터·그림책 | **비유 장면** — 비유 자체를 그린다 (책과 목차, 식당과 웨이터) |
| 10~15살 · 초중고 | 기본 용어는 정의와 함께 | 학교·게임·SNS | 비유 장면 + 단계 하나 |
| 부모 · 배우자 · 친구 | 따뜻하고 대등하게, 내려다보지 않음 | 집안일·그들이 쓰는 기기 | 비유 장면 |
| 매니저 · 디렉터 · PM | 영향·일정·비용·리스크로 | 사업 결과 | **영향과 갈림길** — 무엇이 깨지고, 선택지가 어떻게 갈리며, 각각 무엇을 치르는지 |
| 동료 · 디자이너 | 그들의 작업에 닿는 부분 | 협업 지점·사용자 흐름 | 그들과 맞닿는 경계 |
| 엔지니어 · 대학원생 | 정확한 용어, 트레이드오프 | 이미 아는 구조와 비교 | **메커니즘** — 데이터 흐름·컴포넌트·상태 전이 |

## 2. 원문 읽기

- 코드: 파일을 읽고 **목적**부터 잡는다. 문법은 나중이다.
- 에러: 표면 문구가 아니라 원인을 찾는다.
- 개념: 핵심 부품으로 쪼갠다.

## 3. 산출물 계약

순서대로 한다.

1. `artifact-design` 로드 → `artifact-diagramming` 로드 (작법·팔레트는 거기 있다 — 여기 반복하지 않는다. 프로젝트 `DESIGN.md` 는 그 프로젝트 화면의 규칙이고 설명 페이지에는 적용하지 않는다)
2. HTML 을 스크래치패드에 쓴다
3. **한 번 렌더해 본다** — 그림이 겹치거나 잘리는 것은 코드로 안 보인다. 원샷 `chrome --headless=new --screenshot=<png> file://<html>` 로 찍고, 명령이 끝나면 그 프로필로 뜬 프로세스가 남았는지 확인해 닫는다(캡처 뒤에도 안 죽는 경우가 있다). 프로젝트 훅이 다른 도구를 지정하면 그 도구를 따른다. 캡처 한 장 보고 겹침만 고친다 — 재캡처 반복은 하지 않는다
4. Artifact 로 발행한다. 사용자가 `/explain-diagram` 으로 직접 불렀거나 "아티팩트로·페이지로" 라고 말했으면 **그 말이 발행 승인**이다. 자동 트리거로 들어왔으면 발행 직전 한 줄로 묻는다
5. 터미널에는 **링크 + 한 줄**만. 본문을 터미널에 다시 쓰지 않는다. 사용자가 채워야 할 빈칸이 있으면 그 한 줄에서 말한다

페이지는 이 순서로 구성된다:

| 순서 | 요소 | 규칙 |
|---|---|---|
| ① | 제목 | 2~4 단어 |
| ② | 한 줄 "what" | 대상 어휘로 한 문장 |
| ③ | **주 그림 + 캡션** | 필수. §1 표의 "주 그림이 그리는 것". 캡션은 그림이 주장하는 바 한 문장 |
| ④ | 단계·비교 그림 0~2장 | 순서가 있으면 단계, 선택지가 있으면 **나란히 그린 두 그림 또는 갈림길** — 표로 대신하지 않는다. 각 그림 아래 그 선택지가 치르는 값(기간·비용·체감)을 라벨로 단다 |
| ⑤ | 그림 사이의 글 | 그림 한 장당 **3문장 이내** |
| ⑥ | "so what" | 이 대상에게 왜 중요한지 한 단락. 비즈니스 대상이면 **내려야 할 결정** 목록 |
| ⑦ | 용어 상자 | 기술 대상에게만. 단순 대상 페이지에는 없다 |

글 총량: 단순 대상 150단어 이내, 비즈니스 300단어 이내, 기술 대상은 그림이 요구하는 만큼.
화살표에는 라벨(`writes`, `분당 100`, `거부됨`)을 단다.

**`--text` 이거나 사용자가 "텍스트로·터미널로·아티팩트 말고"라고 하면**: 같은 대상 보정으로 터미널 프로즈. 이때만 그림을 생략한다.

## 4. 언어 보정

- **단순 대상**: 용어 0. 불가피하면 그 자리에서 정의. 한 문장 한 생각. "너·당신"으로 개인화.
- **비즈니스 대상**: 영향부터. 요청·코드·로그에 **있는** 수치는 쓰고, 없는 수치는 지어내지 않고 `[ ]` 빈칸으로 둔다. 구현 세부는 묻기 전엔 생략. "그러니 우리는 …해야 한다"로 결정 프레임.
- **기술 대상**: 용어를 피하면 무시당한다고 느낀다. 트레이드오프·엣지케이스·설계 이유에 집중. 간결하게.

## 5. 예시 — "외부 API 분당 100회 제한에 걸려 피크에 실패, 매니저에게"

- 주 그림: 요청들이 `분당 100` 이라 적힌 문을 지나가고, 101번째부터 튕겨 `사용자에게 실패로 보임` 으로 빠지는 흐름. 캡션: "피크에는 한도를 넘는 만큼이 그대로 실패가 된다."
- 갈림길 그림: 왼쪽 `보내는 양 줄이기(캐시·대기열)` / 오른쪽 `한도 올리기(제공사 협의)`. 각 그림 아래 기간 `[ ]`·비용·사용자 체감.
- 글: what 한 문장 → 그림 → "바로 다시 보내도 같은 1분 안이라 또 막힌다" 한 문장 → 갈림길 → 결정 3개.
- 없는 것: HTTP 429 같은 용어, 방안 4개 표, 구현 세부, 요청에 없던 "실패율 N%".

## 6. 흔한 실수

| 실수 | 고침 |
|---|---|
| 프로즈를 다 쓰고 그림을 삽화로 끼움 | 그림을 먼저 정하고 글을 그림 사이에 채운다 |
| 비교를 표로 함 | 나란히 그린 두 그림 또는 갈림길 그림 |
| 5살에게 아키텍처, 매니저에게 시퀀스 다이어그램 | §1 표의 "주 그림이 그리는 것"을 따른다 |
| 터미널에 본문을 한 번 더 씀 | 링크 + 한 줄 |
| 라벨 없는 화살표 | 관계를 화살표 위에 적는다 |
| "429", "B-tree" 같은 용어가 단순 대상 페이지에 남음 | 지우거나 그 자리에서 정의 |
| 요청에 없는 기간·건수를 그럴듯하게 지어냄 | `[ ]` 빈칸 + 터미널 한 줄에서 채울 자리를 말한다 |
| 발행 전에 렌더를 안 보고 넘김 | 한 번 캡처 — 겹침·잘림은 코드로 안 보인다 |

발행 뒤 볼트 사본은 글로벌 규칙(Session Wrapup)이 정한다 — 여기서 반복하지 않는다.
